## 摘要——"环境注意力发布"

**v0.5.5 让舰队自行注意、重试、升级上报、诊断与完成上手**。别再手工照看在途工作：`rig parked` 带着置信度与讲授内容诊断静默卡滞；常驻卡滞巡检无须你操持；接力棒唤醒自行重试、聚合与升级上报；搁置条目自带唤醒并显示 HEALTHY；`rig ps` 增加一列来自单一事实源的类型化 `ACTIVITY`；Slack 人类层端到端上线；全新安装自行完成上手。

**v0.5.5 完整包含 v0.5.4**。同一条对账归一的血脉。

**迁移**：新增两个。头从 `071` 推进到 `073`：
- `072_thread_seat_map.ts`
- `073_queue_transition_wakes.ts`

**新增动词**：`rig parked [seat]`、`rig seat handover --source fork:|rebuild`（执行路径）、`queue block --on <blocker>`（带唤醒的搁置）、`rig gateway human` 片段生命周期动词、`rig view show escalations`。`rig ps` 新增类型化的 `ACTIVITY` 列。

## 发布内容

### `rig parked [seat]`——推导式的静默卡滞诊断

活动数 × 未决待办义务，逐项输入给出置信度并在行内讲授补救方法。当某个席位看似空闲而你怀疑工作被弄丢时使用它——在任何 `claimedAt` 算术或窗格截屏之前。行表示以前掩盖了搁置（park）与搁浅（strand）的区别；这个动词终结了这一点。

### 自重试唤醒阶梯 + 升级上报视图

失败的接力棒唤醒自行重试、聚合、升级上报。流转记录本身就是阶梯状态（重启安全）；按目的地逐个聚合；每一级先送达再推进；未确认且无人接手就升级上报，而不重发。用 `rig view show escalations` 监看聚合结果。把这一行交接出去，别再追着 nudge 跑。

### 常驻卡滞巡检无须你操持

逾期 + 未送达变成路由化的发现项，推导证据内联展示。别再靠定时器手工跑 `queue overdue` / `undelivered`——直接消费巡检产出的发现项即可。

**注意事项（5.6 待办）**：跨主机继任者可见性是一类已证实的误报——普查时有 39 个活跃发现项（20 个证实为误报，19 个未核实）。已全舰队范围内按"每个条件一个"加以遏制；在 5.6 检测器修复落地前，跨主机谱系的发现项一律按未核实对待。这个增量的输出本身就会讲授该注意事项。

### `queue block --on <blocker>`——带唤醒的搁置（park-with-wake）

一次搁置可以自带唤醒并显示 HEALTHY。`queue block --on <blocker-qitem>` 记录唤醒条件；"持有且唤醒活跃"的条目不会被标记为卡滞；被自动解除搁置的负责人会得到一次诚实的唤醒。仅用于迫近但被挡住的工作；不迫近的工作属于 mission 工作区——队列是一条传送带。

### `rig ps` 从单一事实源（oracle）获得真实的 `ACTIVITY` 列

类型化的分类：working / idle-at-prompt / needs-input-as-count+reason / unknown。证据阶梯以自我上报居顶，阶梯降级可见。以席位为键，跨换任保持。TUI 读取的是同一份真相。对任何"它在思考还是卡住了"的问题——这个事实源比截屏更可靠。

### `rig seat handover --source fork:|rebuild`——真执行（EXECUTE）

`fork:` 直取实时上下文；`rebuild` 从持久链预热（prime）并逐一点名其预热工件。换任中途失败会如实记录。用于更换占用者——不再只有干跑式的规划呈现面。

### Slack 人类层端到端上线

网关运行中、每席位一线程、入站恰好一次对账、升级上报的响度（mention）区别于日常消息。人类是可寻址的成员；`rig gateway human` 拥有完整的片段生命周期动词。任何智能体都可以直接升级上报；升级上报类的发送会在目标人的手机上响亮抵达。

### 全新安装自行完成上手

全新安装默认获得聚焦的上手包（默认关闭该配置；既有 rig 不受影响）。在搭建新 rig 或新席位时——别再手工走完那八件套。

### Refocus 只在应触发时触发

在上下文阈值或按需触发——绝不在会话开始时触发。压缩后两种运行时都会触发；用量阈值仅限 Claude。一个全新席位收到 refocus 现在应当作为缺陷提报，而不是被当成可忽略的噪音。

### 单文件 scope 约定

`scope mission create` → `NOTES.md` + 承载意图的 `SPEC`；`slice create` → 仅 `SPEC`（无 `IMPLEMENTATION-PRD`）+ 验收用 `PROGRESS`；发布 mission 会得到一个能力增量脚手架。`repair` 是增量式的——戳记只追加，绝不重写作者 frontmatter。戳记核验重新变成机械式剥离。

### 守护进程绑定意图有来源可查

继承来的 `OPENRIG_HOST` 绝不会再次选中单绑定；收养门会测试全部必需的监听器。守护进程维护可从任何托管环境执行——不再需要 `env -u` 仪式。

## 应停用的做法（每一条在 0.5.4 下都正确，如今错误）

1. **停止每把锁都跑一遍作者重构协议**。戳记现在只做追加（APPEND）；剥离重构是机械的。
2. **停止用 `claimedAt` 算术加截屏来诊断搁置**。`rig parked` 会推导诊断，附置信度与讲授；截屏只是备用的顺手一瞥。
3. **停止把延期工作存成队列行**。队列是迫近的顺序工作的传送带；延期工作住在 mission 工作区里。
4. **停止在新工作中撰写 `IMPLEMENTATION-PRD.md` 与 `MISSION_NOTES.md`**。`SPEC.md` 是唯一的规格文件；`NOTES.md` 是链名。
5. **停止默认经协调器路由联络**。任何智能体都可直接升级上报。
