## 摘要

OpenRig v0.3.0 把 0.2 的协作底座打磨成一个更成熟的面向操作者的产品。它交付了重新设计的 shell、通用的工作流预置模板、任务（mission）形态的工作区支持、项目可观测性、精选的内置技能、运行时图形、上下文遥测，以及让全新安装更干净的发版强化工作。

本次发布保留了队列交接、工作流运行时、看门狗监管、工件/证据呈现面以及智能体协作等方面的可复用原语，同时公开的预置内容有意保持通用。

## 本版包含内容

- V1 shell 重新设计，采用 vellum 视觉系统、两个桌面 chrome 区域、拓扑的图形/表格/终端模式、抽屉式查看器，以及 Project、For You、Queue、Library、Settings 等面向证据的详情呈现面。
- 通用的工作流预置规格：
  - `conveyor`：适用于站位式工作，多个数据包可同时在拓扑中处于活跃状态。
  - `basic-loop`：适用于一次只处理一个数据包的演示流程。
- `conveyor` 预置 rig 及配套的智能体规格，覆盖接收/规划/构建与评审导向的工作。
- 任务形态的工作区默认值，以及只读的嵌套任务/切片（slice）索引。
- 项目可观测性升级，覆盖 For You、Story、Queue、Tests、Project 汇总、证据截图与队列条目（qitem）抽屉。
- 运行时/工具图形包，应用于拓扑、队列、项目元数据、证据行、终端预览与智能体身份标识。
- 终端预览改进、活动指示器、交接边动画，以及拓扑表格/终端视图中的上下文用量遥测。
- 在配置档案解析期间从文件系统技能根目录发现运行时技能。
- 发布前 CLI/守护进程清理：有界会话记录轮转、`rig send` 消息信封、OpenRig install/init 标记命名，以及面向公开发布的术语清理。

## 用户可感知的变化

### 重新设计的 Shell

UI 现在使用 V1 shell 模型：窄边栏（rail）、按目的地切换的 Explorer 区域、中央工作区，以及具名触发器的抽屉。拓扑页面在同一个稳定 URL 下提供图形、表格与终端三种模式。抽屉式查看器负责处理队列条目、文件、子规格预览、终端预览与证据资产，不会让每次引用点击都变成整页跳转。

### 预置工作流与预置 rig

本次发布包含的是通用的工作流示例，而非特定项目的自动化配方。`conveyor` 演示带有自然队列背压的站位式流程。`basic-loop` 演示简单的逐个令牌（token）循环。`conveyor` rig 是公开的工作流预置模板。`product-team` 仍是更高级的、由人类操作者驱动的预置拓扑。

### 项目与证据可见性

项目呈现面现在会区分进行中与已归档的工作，展示任务/切片层级，把任务标签路由到任务页面，并暴露 story/tests/proof 汇总。For You 与 Queue 卡片会填充 qitem 正文、证据图片、审计结果与下一步动作状态。Tests 证据截图可在页内查看器中打开。

### 拓扑与运行时可见性

拓扑现在提供混合多 rig 图、展开/折叠控件、活动圆环、动画交接边、运行时/工具标识、上下文百分比/令牌显示，以及终端回退视图。智能体详情呈现面现在使用规范的存活节点详情视图。

### 技能与预置指导

内置技能经过筛选，以保证预置模板的一致性。运行时技能发现现在会在运行时与工作区技能根目录中查找有效的 `SKILL.md` 文件，rig 本地资源优先于更大范围的用户库。

## 运维/安装注意项

- 全新工作区默认为任务形态，并从 `workspace.root` 派生。使用 `rig config init-workspace` 创建默认工作区结构。
- 本仓库使用 npm workspaces 与纳入版本跟踪的根目录 `package-lock.json`。`pnpm-lock.yaml` 文件不是发布工件。
- 诸如 `CLAUDE.md` 这类根级运行时投影文件有意不纳入产品仓库跟踪。
- 已弃用的 `RIGGED_*` 别名仅为原始运行时环境键保留：`daemon.port`、`daemon.host`、`db.path`、`transcripts.enabled` 与 `transcripts.path`。新的强类型配置键只使用 `OPENRIG_*`。
- 既有的本地工作流规格仍可从工作区/规格位置安装；产品源码只打包通用的工作流预置模板。

## 已知限制

- 插件支持不属于 0.3.0。插件打包的技能与外部插件分发计划在后续版本推出。
- 公开的预置工作流只是示例，不是一套完整的打包自动化方法论。
- 部分大范围 CLI 测试对本地守护进程端口/配置状态敏感。最终推送门槛使用了聚焦发布路径的测试以及构建/lint 门槛。

## 已执行的验证

- `npm run lint`
- `npm run build`
- `npm run test:repo`
- 针对发布卫生、配置边界、预置技能发现、shell/拓扑行为与项目可观测性的聚焦 CLI、守护进程与 UI 测试。
- 针对个人路径、内部署名措辞、默认回退假设以及新强类型键上不应遗留的旧环境变量别名的源码扫描。
