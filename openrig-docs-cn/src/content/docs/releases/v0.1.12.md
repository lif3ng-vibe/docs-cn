title: "OpenRig v0.1.12"
---

## 摘要

本次发布强化了启动状态的真实性，改进了会话记录（transcript）清理，并让 Claude 与 Codex 托管会话的恢复行为更加可靠。

## 本版包含内容

- 将用户可自行清除的启动阻塞项规范化，使其不再伪装成硬性故障。
- 更激进地清理过期的 Claude 启动/报错残留。
- 改进 Codex 恢复连续性检测和恢复元数据捕获。
- 修复会话记录重绘与状态噪声的清理。
- 强化 Claude 托管会话启动环节对 MCP 相关阻塞项的处理。
- 提升 tmux 健康与实例化（instantiate）时机方面的运维可靠性。

## 用户可感知的变化

- 卡在交互式启动提示上的节点，现在会被规范化为用户可自行清除的启动阻塞项，而不是停留在具有误导性的过期故障状态。
- 一旦当前运行时证据证明旧的故障残留已过期，就会更激进地清理 Claude 启动状态。
- 在恢复被包装（wrapped）的进程以及 TUI 已滚动或渲染出额外页脚/页眉噪声时，Codex 的恢复行为更加稳健。
- 会话记录清理的噪声更小，能更好地移除重绘/状态工件（artifact），而不会让终端输出停留在令人困惑的状态。

## 运维/安装注意项

- 升级后请重启守护进程（daemon），使新的启动与恢复行为生效：

  ```bash
  rig daemon stop
  rig daemon start
  ```

- 本次发布改进了分类与恢复行为，但并不能把每一次被中断的运行时都变成有保障的原生连续性。操作者仍应如实看待恢复结果，并在产品表示无法证明连续性时改用手动恢复路径。

## 已知限制

- 生命周期/状态处理比以前更真实，但 OpenRig 仍没有一套完全显式的、基础设施级的状态机。
- 恢复仍然依赖具体运行时并以证据为驱动；部分恢复路径仍依赖启发式方法，而非完善的提供商原生原语。

## 已执行的验证

- 发布工作期间针对守护进程与 CLI 的测试覆盖。
- 对会话记录清理变更集的重点审查与验证。
- 在全新虚拟机（VM）上对已发布的 `@openrig/cli` 包进行 npm 安装验证，包括守护进程启动、健康路由、doctor 检查、`rig ps --nodes` 以及 UI 加载。
