## 摘要——工作流、多主机协作与工厂基础

OpenRig v0.4.6 落地确定性工作流引擎，以及运行其上的多主机协作模型。工作流成为一等产品呈现面：一个坚如磐石的引擎、一门特性齐备的规格语言、一个工作流 CLI、一个工作流 Web UI，以及一套异常 + 人工门成熟度模型，让健康运转保持零打扰。在该引擎之上，自动驾驶工厂 starter 以已随版的 MVP starter（`rig up factory-rsi`）落地——一个 rig、七个席位、一条自动驾驶的 `plan → implement → qa_check → review → release` 内环，dogfood 与之解耦、对随版产品带外运行，把记录到的发现喂给下一轮 plan。

多主机协作落地完整的 happy path。主机通过仪表盘可见的卡片注册与选择；本地操作者可读取远程主机的工作区呈现面；队列条目与 hot-potato 交接经已注册传输显式跨主机（绝不发生静默的选择改家）；直连协作动词（`rig send`、`rig capture`、`rig transcript`、`rig broadcast`）经随版的 http 传输分支 CLI 直连跨主机，ssh 行为字节级原样保留；一个舰队层级的关注带汇总全部已注册舰队的 needs-attention。

基础层补完本版本：新的智能体运行时适配器（Pi）以一等运行时的身份加入 Claude/Codex 之列；终端提供商在各终端相关呈现面上获得一等处理；守护进程读取路径为多主机 + 工作流负载硬化，无任何功能行为变化。

两个新的捆绑技能以 canonical + 插件双形态随版，带字节一致性守卫：`openrig-herdr`（rig 终端 open/views/status 模型）与 `openrig-cmux`（与提供商无关的增量差异）。

迁移仅增量：`049_workflow_instance_version`、`050_workflow_spec_json`、`051_workflow_resume`、`052_workflow_instance_bound_rig`、`053_sessions_node_id_index`、`054_queue_transitions_archive`。现有 v0.4.4 数据库在新守护进程上运行 `rig daemon start` 即可升级。（v0.4.5 被跳过；v0.4.4 与 v0.4.6 之间没有切版。）

## 随版内容

### 工作流

- **坚如磐石的确定性引擎**——严格规格校验（未知键拒绝；不可达步骤与无守卫的环失败）；`loop_guards.max_hops` 在投影处强制执行；等待式出口的重放吸收；逐实例 keepalive 看门狗（watchdog）在路由事务内自动架设；启动清扫重新架设并暴露卡住的实例；`rig workflow continue` 更名为只读检查器语义。
- **特性齐备的规格语言**——步骤带 role / target.rig / preferred_targets / next_hop.on / invariants / loop_guards / exception_routing / closure / gates / skill_refs / spawn_budget；严格键集校验；随版规格的兼容性由夹具往返（fixture round-trip）钉定。
- **工作流 CLI**——新动词 `rig workflow run`（实例化 + 跟随到终点；退出码 3 = 工作流失败，区别于传输 1/2）、`rig workflow watch`（中途接入）、`rig workflow status`（needs-attention 汇总）、`rig workflow route`（一次事务内重定向前沿）。格式化的 `trace` / `list` / `show` 人类输出；`--json` 与此前字节一致。新守卫拒绝带外关闭一个存活工作流前沿数据包。
- **工作流 Web UI**——新增 Workflows/Instance/InstancesBand/TopologyGraph/InstanceTrailTimeline 页面；SSE 流不再按 rig 限定范围；纯 `buildLauncherViews` + `suggestLayout` + 边柄分配导出。UI 验收由逐切版的真实截图 + 两主机集成证明承载；孪生夹具回填被转为一项非阻塞的 0.4.7 卫生快速跟进。
- **异常 + 人工门模型**——`rig workflow resume` 动词（从一个失败实例的失败步骤重新驱动（redrive），重新绑定、全新能力感知的重新解析、一个全新的 `max_hops` 窗口）；异常在同一事务内与失败一起成为持久的关注条目；成熟度拨盘 `orchestrator-first | human_only` 按类别 / 按工作流 / 按主机设定；关注带具备工作流感知；happy-path 保证不变。

### 多主机协作

- **添加 / 选择主机 + 仪表盘**——`HostConfigCard` + `HostIndicator` 呈现于仪表盘；`rig host select` 持久化一个粘性选择，供 observe/interactive 动词消费；新增 `useHosts` / `useFleet` hooks。
- **查看远程工作区**——工作区可观测标签页获得 `--host <id>` 范围；registry + bearer 逐主机扇出读取。只读。
- **跨主机队列路由**——`rig queue create / handoff / handoff-and-complete` 获得 `--host <id>` 与主机限定的目标形态 `member@rig@<host>`。仅显式路由。至少一次送达 + 经确定性继任者 id 实现幂等；交接先创建继任者、后关闭本地条目；重试在主键上吸收。逐主机结果的失败诚实。
- **跨主机智能体协同**——`rig send` + `rig capture` 获得一条 http 传输分支，CLI 直连远程守护进程既有的 `/api/transport/send|capture` 路由；`rig transcript` + `rig broadcast` 以同样的方式获得其首个跨主机入口。`agent@rig@host` 目标形态是会话目标动词的 CLI 边缘糖。对以 ssh 注册的主机，ssh 行为字节级原样保留；优先级为显式 `--host` > 目标糖 > 选择；经 http 的 `send --verify` 原样打印 REMOTE 路由的判定。
- **舰队关注层级**——经 `FleetBand` + `FleetPage` 的全舰队关注汇总；逐主机状态 + 下钻。

### 工厂

- **工作流到 rig 的绑定层**——实例化时经 `--rig` 把工作流绑定到一个 rig；角色按能力解析到席位；有能力席位的解析遵循仅托管（managed-only）、感知 harness 钉定的运行时匹配、最少 pending 积压、确定性平手裁决；解析一次、记录进数据包；角色绑定到稳定的席位坐标 `{pod}-{member}@{rig}`（席位背后的智能体交接绝不会困死工作流）。
- **自动驾驶工厂 starter（`factory-rsi`）**——新的 `rig up factory-rsi` starter；新的 `factory-rsi` 内置工作流，带一条经 `loop_guards.max_hops` 批准的 `plan → implement → qa_check → review → release` 内环；dogfood 解耦并带外对随版产品运行，其发现喂给下一轮 plan（RSI 边，在 MVP 中不加门——在后续版本中打磨）；publish 仍经 `release_signoff` 门保持为人的动作。
- **member-exists 建议 + 跨 rig 包装**——误路由的工作流目的地在实例化时被大声抓住；跨 rig 包装工作流经跨主机队列路由路径传递。

### 运行时、终端与读取路径

- **Pi 智能体运行时适配器**——新的头等运行时，加入 Claude/Codex 之列；参与全部工作流 / 角色 / 队列 / send / capture 呈现面，与已随版运行时完全一致。
- **终端提供商一等处理**——终端提供商在终端启动器、send/capture/broadcast，以及新的 `openrig-cmux` 技能的 `--provider cmux` 接缝上获得一等处理，带尽力而为的回退。
- **守护进程读取路径硬化**——SSE 流背压守卫、投影缓存、面向读取侧查询性能的增量索引。无功能行为变化；同样的读取返回同样的结果，只是更快。

### 新的捆绑技能

- **`openrig-herdr`**——完整的 rig 终端 open/views/status 模型（动词、视图语法、诚实的不完整读取、只读策略、terminal-views.yaml schema）。AGPL 净室（clean-room）轨道——不 vendor 任何 herdr 源文本。
- **`openrig-cmux`**——与提供商无关 versus cmux 专属的增量差异，带随版集成的 open-or-focus 规则。

两者都以 canonical + 捆绑 openrig-core 插件双形态随版，并有字节一致性守卫。

## 迁移

仅增量：

- `049_workflow_instance_version`——`workflow_instances` 上的乐观并发控制。
- `050_workflow_spec_json`——完整解析后的 spec 缓存于 `workflow_specs`；旧行在下一次读取时自愈。
- `051_workflow_resume`——`workflow_instances` 上的 `resume_count` + `hops_baseline`。
- `052_workflow_instance_bound_rig`——`workflow_instances` 上可空的 `bound_rig` TEXT。
- `053_sessions_node_id_index`——增量索引。
- `054_queue_transitions_archive`——面向读取侧查询性能的归档表。

现有 v0.4.4 数据库在新守护进程上运行 `rig daemon start` 即可升级。
