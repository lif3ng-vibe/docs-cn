> **UI 姿态（与 v0.4.7 保持不变）**：Web UI 仍处于**维护模式**——照常发布、照常运行，但不做新功能开发。**CLI/TUI 是首要呈现面**。v0.5.0 将 TUI（`rig` / `rig tui`）作为新的任务控制主页落地。

## 摘要——终端任务控制 + 上下文库 + 权限策略 + 提供商用量 + 诚实的 CLI

**终端任务控制**：输入 `rig`（或 `rig tui`）即可打开全新 TUI——文件树导航器、信息密集的智能体详情（工作目录、运行时、上下文占用百分比）、在一屏内呈现整个舰队的拓扑图、诚实的状态/活动文案、动效设计、真正可用的滚动，以及贯穿全局的诚实宽度裁切指示。

**v0.5.0 包含 v0.4.8 的全部内容**。两个发布之间没有任何分歧——v0.4.8 的权限姿态工作与已随附技能在 v0.5.0 中全部在场。

迁移仅做增量（additive）。既有 v0.4.8 数据库只需在新守护进程上运行 `rig daemon start` 即可完成升级。

## 发布内容

### 权限策略内置模板 + 智能体驱动的翻译

在 v0.4.8 权限策略基础之上，v0.5.0 发布了**内置策略模板，外加把模板翻译成目标运行框架实时配置的智能体驱动技能**。

- **四个内置策略模板**——`locked`、`standard`、`open`、`yolo`。对包内内容只读；复制后即可自定义。另有 `none` 作为刻意的"无策略"选项。
- **`rig setup --policy <name>`**——把所选策略记录进 rig 规格（spec）。接受内置名称（`locked | standard | open | yolo | none`），或自定义策略文件的路径（自定义策略以你亲手撰写的 `.policy.md` 文件形式存放）。
- **`applying-a-permission-policy`——负责翻译的随附技能**。在 rig setup / 预检时，该技能读取策略规格，检查席位当前的运行框架版本，写入前先展示具体 diff，再把配置落到 Claude 的 `~/.claude/settings.json` 和/或 Codex 的 `config.toml`。绝不盲目写入。翻译之所以刻意由智能体驱动，是因为运行框架的权限格式会随版本频繁变化——一个确定性的写入器会在运行框架呈现面一变时就失效。
- **两个呈现面**——**启动旗标**（launch-flag）呈现面（Claude `--permission-mode`、Codex sandbox/bypass、Pi `--approve` / `--no-approve`）保持稳定，由 OpenRig 替你设置：包括下限基线（Claude `acceptEdits`、Codex workspace-write）与完全绕过的 YOLO 模式。**配置文件**呈现面（Claude `~/.claude/settings.json`、Codex `config.toml`）则是 allow/ask/deny 规则所在之处，也是技能套用你所选策略的地方。
- **哪些是确定性的、哪些是尽力而为**——启动旗标下限与 YOLO 是确定性的。精细的配置文件规则属于尽力而为，因为各运行框架的规则语法各异；技能会通过"写入前先看 diff"的流程向你提示这些注意事项（前缀冲突、target-first 泄漏、Claude 缺少原生网络门）。若某次翻译结果不确定，你随时可以退回手工编辑运行框架自己的设置文件，或退到 YOLO／下限基线这类钝器。

### 权限写入保证，现已用测试钉死

v0.5.0 信守 v0.4.8 的承诺——**OpenRig 绝不向你的 Claude `settings.json` 写入权限条目**——并以一条常驻守卫测试加一次空写入扫描将其钉死。唯一获准的例外，是 v0.4.8 自身定义的项目级 `acceptEdits` 下限基线。权限策略发现过程中的告警排序更清爽（先输出既有的主下限基线告警，再输出策略挂载告警）；这只是呈现层面的改动，语义围栏不变。

### 上下文库

`rig context` 负责存储与组合上下文；`rig walk` 按节奏送达；`--context` / `--body-context` 把一份已存储的上下文（按引用）附加到 `rig send` / `rig broadcast` / `rig queue create`。语法很严格：**名词负责存储与组合**（`rig context` 自己绝不送达）；**动词负责送达**（`rig send`、`rig broadcast`、`rig walk`，或通过 `--context` / `--body-context` 使用 `rig queue create`）。v0.4.x 的旧上下文窗口用量查看器已移除；`rig context` 这个名字现在属于这个库。

### 行为变化（v0.4.8 → v0.5.0）

`rig.yaml` 中的启动 `context_pack` 条目不再在 rig 实例化时自动送达。**它们会被拒绝并返回一条教学式报错，指引你改用 `rig context compose` 加一条送达命令**。在 v0.4.8 上采用过 `rig.yaml` `context_pack` 的用户（该版本数天前才发布，时间窗口很小）应先用 `rig context compose` 组合该包，再用送达命令送达——`rig send --context`、`rig broadcast --context`、`rig walk`，或在 `rig queue create` 上使用 `--context` / `--body-context`。捆绑路由器仍会存储该包，只是不再在启动时自动送达。

### 提供商用量可观测

守护进程按主机跟踪账户级用量——回答"我是不是快用完额度了"这个问题——并通过 `GET /api/provider/usage` 与 `rig provider status` 暴露。提供商不上报时明确标记未知；多个信号相互矛盾时同时展示两个事实。Codex 的账户切换流程保持不变。

### 计划修订的正确做法

`rig scope slice approve --re-approve --reason "..."` 会为已锁定的计划重新盖章并留下只增不改的审计轨迹——取代了此前"已批准状态只能强制改成 `Status` 备注"的变通办法。

### 诚实的 CLI 输出

- `rig ps` 会在显示的是多台 rig 中的某一台时如实说明，而不是默默截断。
- `rig send --json` 把结构化错误以 `{fact, consequence, action}` 形式返回。
- 活动钩子修复终结了此前每次发送都会在全舰队触发的 "producer link stale" 提醒。面向操作者的质量改进。

### 构建纪律

贡献者门禁与车道（lanes）的唯一事实来源是 `docs/reference/developing.md`。

### UI 状态（与 v0.4.7 相同）

Web UI 维持 v0.4.7 引入的维护模式不变——照常发布、照常运行、不做新功能开发。CLI/TUI 是首要呈现面，v0.5.0 的 TUI（`rig` / `rig tui`）是今后任务控制投入的落点。UI 未被弃用，也未移除；既有部署继续可用。

### 随附技能

两个新的随附技能加入已发布技能集，与 v0.4.8 的技能并列：

- `applying-a-permission-policy`——权限策略的智能体驱动翻译（见上文权限策略一节）。
- `delegating-work`——面向每个席位的分派指引。

`openrig-user` 技能已随 v0.5.0 的上下文库语法更新（`rig context compose`、`rig walk`、`--context` / `--body-context`）。

## 已知问题

- **Codex `HOME` 修复未进入 v0.5.0**——一项确保守护进程与 Codex 席位对 `HOME` 环境达成一致（使权限姿态写入能抵达席位）的权限姿态修复已获准进入 v0.5.0，却在构建时被意外遗漏。它将作为早期缺陷修复随 v0.5.1 发布。在此之前，v0.4.8 的部署注意项仍然适用：**权限姿态写入要抵达 Codex 席位，守护进程的 `HOME` 必须与席位的 tmux `HOME` 相等**——任何远程主机升级都请核实这一点。

## 升级注意事项

- 迁移仅增量；在新守护进程上运行 `rig daemon start`。
- 任何仍在声明启动 `context_pack` 的 `rig.yaml` 都会遇到上述教学式报错拒绝；请迁移到 `rig context compose` + 送达命令。

## 行为与兼容性

- **迁移**——仅增量。
- **`rig.yaml` 启动 `context_pack`**——实例化时被教学式报错拒绝。请迁移到 `rig context compose` + 送达命令。
- **上下文查看器移除**——v0.4.x 的上下文窗口用量查看器已移除；`rig context` 这个名字归属上下文库。
- **权限写入呈现面**——由常驻守卫测试钉死：除获准的项目级 `acceptEdits` 下限基线外，OpenRig 写入 `~/.claude/settings.json` 的权限条目为零。
