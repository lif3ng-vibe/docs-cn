## 摘要——"诚实发布"

**v0.5.4 让命令输出描述实际发生的效果**。传输解析区分"会话缺失"、"会话存在"与"无法确定"。送达核验区分"输入仍在暂存"与"已被智能体消费为一个回合"。队列、refocus、生命周期、导入与预览呈现面保留真实状态与拒绝语义，而不是把它们塌缩成一个看似合理的成功。

**v0.5.4 完整包含 v0.5.3**。VM 切线已通过 32/32 有序稳定补丁 ID 匹配，与已发布线对账一致。

无新增迁移。迁移头保持在 071（与 v0.5.3 一致）。Node 引擎要求不变。既有 CLI 命令全部保留；本发布新增 `rig seat set-model`、`rig seat stop` 与 `rig seat clean`。

## 发布内容

### 一条经分类的会话解析路径

send、capture、nudge 与 walk 消费同一个探测结果：found、absent 或 indeterminate。tmux 或传输层的瞬时抖动不再变成假的 `Session not found`，恢复输出会如实说明检查了什么。

### 按效果核验送达

`rig send --verify` 检查输入是仍处于暂存状态，还是已被消费为一个回合。单目标、扇出与 JSON 输出使用同一套分类，因此"已键入"与"已送达"不再是同义词。

### 诚实的未知发送者送达

没有可归属发送者身份的消息会以"未知发送者"标签送达，而不是被拒绝。在可能的情况下，发送者会收到一条请其补充归属说明的提示。

### 受支持的单席位生命周期控制

- `rig seat set-model` 变更规范模型绑定，并附带一条可审计的理由。
- `rig seat stop` 停止一个运行中的席位，而不惊扰同级席位。
- `rig seat clean` 清除死会话残留，让逻辑席位可以重新启动。

安全是整类的：生命周期操作可能变动的每个会话都会被探测，任何"存活"或"不确定"的结果都会拒绝该操作。模型变更已经由一个真实的托管继任者演练过。

### 保持状态的队列与 Refocus 行为

队列备注保留该行的状态。无身份的 owned 列表会拒绝执行，而不是静默放宽或变更范围。Refocus 会保留到期状态，直到送达变得可见。预览与交接输出会说明内容何时有界、何时可选。

### 跨创建与导入的运行中名称守卫

一个运行中的 rig 名称无法通过其他实例化器或导入路径被重新创建。每条路径都在 CLI 边界上保持同一个 `409 rig_name_running` 代码与教学信息。

### 密封启动与插件授权

草稿/测试启动边界是密封的。随附的 `openrig-core` 插件在显式版本授权下推进，防止较旧的运行时把已安装的引导内容悄悄回滚。过期的实验室 refocus 注册已被退役。

## 行为与兼容性

- **迁移**——无；模式（schema）头保持在 071。
- **API 兼容性**——既有命令继续可用；三个席位生命周期动词为增量新增。
- **血脉**——0.5.4 的产品增量已按补丁身份与已发布的 0.5.3 线对账归一。
- **发布边界**——打标签、npm 发布、主机安装与守护进程切换仍是各自独立的授权行为；本文档并不表示这些行为已经发生。

## 已知限制（0.5.5 待办清单）

- **写入层磁盘上限**——清理只是临时控制手段；永久性的写入层上限尚未完成。
- **修复/批准时的 frontmatter 重写**——已知的重写缺陷仍未关闭。
- **观测管道性能**——更大的窗格/进程轮询重构仍在以测量数据把关，本发布对此不做任何宣称。
