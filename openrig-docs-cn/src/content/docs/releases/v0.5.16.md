版本 **0.5.16** 的变更内容。发布状态与日期记录在 [GitHub release](https://github.com/mvschwarz/openrig/releases/tag/v0.5.16) 与 npm 上。

OpenRig 0.5.16 让 rig 可以把托管的 Claude Code 指令与纳入版本管理的 `CLAUDE.md` 分开存放，并为拉取请求新增一份参考性的可移植性报告。

## 保持已纳入版本管理的 CLAUDE.md 不变

OpenRig 会把给 Claude Code 成员的指令写入各成员工作目录中的托管块（managed blocks）。默认文件是 `CLAUDE.md`。如果你的仓库正在跟踪 `CLAUDE.md`，可以在 rig spec 中选择 `CLAUDE.local.md`：

```yaml
managed_blocks:
  claude-code: CLAUDE.local.md
```

Claude Code 同样会从工作目录加载 `CLAUDE.local.md`；请将其排除在 git 之外，例如加入一条 `.gitignore` 条目。该选择在成员启动、恢复、重启或新增时生效，并由 `rig export` 与 rig bundle 保留。`rig down` 只会从所选文件中移除 OpenRig 的块。OpenRig 从不编辑、移动或删除另一个文件中的块。

只接受 `claude-code` 这一个键，取值只能是 `CLAUDE.md` 或 `CLAUDE.local.md`；其他任何键或取值都会在成员启动之前被拒绝。没有该字段时行为不变。Codex 成员始终使用 `AGENTS.md`。

**切换已有的 rig**：OpenRig 已写进 `CLAUDE.md` 的块会留在原地。在你删除它们之前，该文件一直处于被修改状态，且 Claude Code 会同时加载两份副本。请手工删除每一对 `<!-- BEGIN OpenRig MANAGED BLOCK: … -->` … `<!-- END OpenRig MANAGED BLOCK: … -->` 段落，保留文件其余部分。如果 `CLAUDE.md` 里没有你还需要保留的其他未提交修改，也可以改用 `git restore CLAUDE.md`；该命令会丢弃该文件的所有未暂存修改，而不仅是 OpenRig 的块。参见 [RigSpec 参考](/reference/rig-spec/#选择-claude-指令文件)。

## 面向拉取请求的可移植性报告

新的拉取请求工作流会列出新增行中与特定机器、网络或账户绑定的取值：凭据、家目录与临时路径、网络地址以及电子邮件地址。疑似凭据不会出现在报告中。发现项永远不会让检查失败；改什么由作者决定。它基于模式匹配，并不保证没有隐私信息残留。在本地运行：

```sh
node scripts/portability-report.mjs
```
