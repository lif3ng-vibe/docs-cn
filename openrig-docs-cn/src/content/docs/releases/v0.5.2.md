## 摘要——测试系统投入实战；急救车指挥器；可靠性修复

**v0.5.2 让 v0.5.1 的测试系统投入实战**。本发布中的可靠性修复由场景发现并验证——场景通过"人使用的同一批命令"驱动真实产品。主打功能落地：急救车（crash cart）舰队恢复指挥器，一次按键就能带你从死掉的守护进程走到如实反映的座舱，再回到活跃的舰队。

**v0.5.2 完整包含 v0.5.1**。同一条血脉，毫无分歧。

本发布没有新增迁移。v0.5.1 已随附迁移 068-071（其中 068 与 071 是一对配对的 create / drop-if-exists，对任何 v0.5.0→v0.5.1 升级而言净效果为零操作）。v0.5.2 停留在迁移 071。相较 v0.5.1，没有任何 CLI 命令或旗标被移除或更名。

## 发布内容

### 急救车舰队恢复指挥器（主打）

在死掉的守护进程面前输入裸命令 `rig`，就能抵达如实反映的座舱——没有晦涩报错，没有静默失败。一次回车即按"内核优先"恢复舰队，收养（adopt）所有幸存的 tmux 窗格（绝不覆盖它们），并呈现一份精确到每个席位的修复路径，一次按键即可逐步走完。取消是诚实的。只有当收养确实无法成功时，才会提供破坏性恢复。十轮构建、四道独立关卡、由非作者完成的 QA 门测试（door test）。

### 守护进程事件循环在负载下不再挂起

一类守护进程事件循环在负载下冻结的问题已被修复并量化。如果你的守护进程曾在全舰队活动下失去响应，那就是这一类问题。

### Claude 席位无人值守交接

当 Claude 席位需要交接（压缩、会话边界、显式交接请求）时，即将离场的席位现在会自动撰写复盘摘要（recap）并提交自己的交接包——接手的席位带着复盘摘要开工，而不是冷启动。已通过门测试端到端验证。

### `rig policy` 诚实应对恶意输入

畸形或有敌意的策略输入现在会产生诚实的结构化报错，而不是静默失败或意外行为。三轮评审。

### 跨主机消息携带来源机器

跨主机发送的消息现在带上来源机器信息，多主机协作在接收端读起来是正确的。已通过门测试端到端强制保证。

### Codex 模型配置漂移检测器

一个新的检测器，针对一类此前会悄然溜过的 Codex 模型配置漂移。上线当天就抓到了真实案例。

### 测试可信度工作

- 测试运行器拒绝在脏树上运行——一次绿色的跑通现在意味着源码本身是绿的，而不是意外未提交的状态。
- 密封的测试根目录（hermetic test roots）。
- 隔离不稳定的夹具（fixture）。

### 治理写进代码

计划锁定是显式的（在你要求时才选择），不再从环境状态继承。唤醒（wake）改为自愿开启（opt-in）。

### 容器 tar 文件挂起在接缝处根除

一类容器 tar 文件挂起问题已被构造性根除——不是绕过了事，而是把使之成为可能的接缝封死。

## 已知限制（5.3 待办清单）

已如实登记到下一个发布周期。点名列出，让你知道哪些尚未修复：

- **回复提示（reply-hint）自指认**——部分跨主机消息上的回复提示用机器 ID 而非已注册主机名指认自己；直接使用该回复提示可能失败，报 "no registered host X"。请从 `rig host list` 取得已注册主机名替换之。5.3 修复。
- **`rig queue handoff --summary`** 会告警，但字段在其自身输出上不可设置。5.3 修复。
- **`rig send --verify` 检测不到"已暂存未发送"**——对发往 Claude 席位的多行发送无效。多行发送可能被静默暂存。
- **全屏促销（fullscreen upsell）下 Claude 会话记录变薄**——上游的全屏促销会写入 `"tui":"fullscreen"`；一次被接受的提示就可能把整个舰队翻回去。5.3 中修复 + 钉死 + 预防。
- **测试运行器可能在未构建的树上静默跳过**——终局关卡规则（先构建 CLI + 断言零跳过）已被采纳为发布仪式的一部分；产品侧修复 5.3 落地。
- **`seat-handover` 模型忠实度 real-Codex 端到端**在 main 上同样失败（环境与产品的区分尚未查明根因）。隔离修复 5.3 落地。

另有少量内部债务事项已登记进维护计划。
