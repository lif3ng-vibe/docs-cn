---
title: "OpenRig 0.5.12 — 连贯的工作、安静的等待与一个正常的 TUI 前门"
---

**状态：** 发布候选版（release candidate）。精确裁剪的实质评审、最终发布验证与发布仍是分开的步骤。

OpenRig 0.5.12 把日常的工作流操作接到有用的进度视图、可恢复的归属与可读的 TUI 上。目标是让操作者或智能体开始、理解、调整并回到工作，而无须维护状态副本，也无须知道某个私藏的恢复偏方。

## 判断只记录一次

一个经过授权、有证据支撑的证明判断会推导受影响的证明、切片（slice）、任务（mission）与项目就绪状态。修正该判断会更新其依赖视图，同时保留无关工作与原始证据。代码、带署名的等价补丁工作与非代码工件都可以携带真实的来源（provenance）。勾选框、上传的文件或已关闭的队列条目不会成为语义上的验收，就绪也不等于发布。

## 分清正在运行的是哪张图

普通的工作流检视会区分撰写的 scope 与绑定的运行图、建议性的次序与可执行的依赖、规划波次与运行时步骤。`rig workflow revise` 在应用之前预览受支持的变更，保留已完成的工作与当前的托管关系。不兼容的编辑会指出需要重新考虑的决策。操作身份与 `rig workflow operation` 可以恢复一个含糊的创建/修订结果，而不重复其效果。选定的开发方法指引随工作流延续一同返回，包括原始故事与有用的下一步操作；守护进程不评判智能体撰写文字的含义。

## 让故障有归属、有恢复路径

异常就绪状态在故障发生前就解释选定的负责人，并让缺失的配置、真正的无匹配与不可得的路由证据彼此区分。路由使用撰写的智能体身份或已登记的人工回退。未被处理的依赖分支故障会同时记录其发生、所属任务与唤醒，即使另一分支仍在运行。一次失败的提醒不会抹掉任务。修正原因之后，用 `rig workflow resume` 加 `--occurrence <failed-qitem-id>` 选中该故障：其过期的异常在重驱（redrive）事务中关闭，而其他未解决的故障与已完成的工作保持可见。

## 安静等待而不丢工作

健康且无变化的等待避免重复下发完整上下文包。同一可操作回合的重叠通知共享呈现并保留来源。变化的阻塞、错过的投递与被搁置的工作保留有界的恢复或升级路径。普通读取优先暴露当前负责人、阻塞点与下一个有用的决策，完整证据则需显式展开。未知的活动仍是未知；提醒不是进度。

## 从同一个 TUI 开始并返回

不带参数的交互式 `rig` 是正常的前门，涵盖首次安装、守护进程未启动时的启动以及重启后的返回。TUI 显示预期的实例与观察到的前置条件，提供守护进程启动，并支持选择要回去继续工作的 rig 与席位。推荐先选内核（kernel）；未选中的 rig 保留各自的历史。Resume 在可用时恢复所选席位已录制的会话。不可用的 resume 会提供具名的修复，或一个显式确认后的全新、重新引导（re-primed）的会话；绝不会被悄然替换。启动器与原生启动修复在运行框架或依赖不可用时保留有用的报错。

## 在 CONFIG 中浏览通用实例设置

CONFIG 将实例、工作区/上下文、显示/时区、等待、快照与恢复设置整理成可读的类别，并带有来源与覆盖来源（override provenance）。高级设置与完整的取值仍可查到。Slack 与人工连接是 CONFIG 的一个子项。打开或刷新浏览器是被动的且不接触密钥；已配置的取值与观察到的应用、连通性与投递状态仍彼此区分。用户可以不开配置文件就回到普通的 scope 与工作视图。

## 运维/安装注意项

Root、CLI、守护进程与 Web UI 包版本为 0.5.12。终端 TUI 保持其独立的 0.1.0 版本。Node 要求与有序迁移头 `079_workflow_lifecycle_parallel` 与 0.5.11 相比不变；本发布不新增数据库迁移。

在被授权采纳时，请使用受支持的升级与延续性流程。准备该候选版不会重启守护进程或续约既有席位。配置检视不是编辑器，不是凭证迁移、自动修复，也不是"每个设置都可热加载"的承诺。只编辑撰写的图并不会将其采纳进一个已有进度的运行工作流。异常修复不会为更早代码已提交的故障追溯性创建任务；请检视留存的故障发生记录，并刻意走受支持的恢复路线。

## 验证范围与已知限制

获接受的开发成果包括一次较少引导、返回/辅助型的智能体旅程，穿越两个相互依赖的切片：记录并修正证明、修订图、等待并返回、恢复一次真实失败的下发检查，以及在 CONFIG 中导航回到工作。聚焦的机制评审与已安装控制支撑该旅程。原生启动、resume 与唤醒的观察保留其原始的源码裁剪与时间；它们是以署名方式复用，并非作为该纯版本候选上的新运行来呈现。候选包与生成版本检查单独记录，与那些开发判断分开。

- 这不是对陌生人类用户的研究、无辅助的绿地可用性试验或全平台验证。安装与一次性的原生审批仍属于已记录旅程的一部分。
- 最终的异常任务在其占位目的地无法接收提醒之后，经公开的读取/认领/操作路径被消费。它不确立原生的异常投递或对外的人工接收。
- 安静等待的度量确立的是受测工作负载的注意力与恢复行为，不是全局延迟保证，也不是提供商计费 token 的节省。一个留存的启动期"目录不可用"对照组在其未变的父级上同样失败；该证据不是全绿测试套件声明。
- 整包实质评审、精确发布验证与发布仍须绑定这个已备好的候选版。这些说明不宣告某个可用的 npm 版本，也不授权运行时采纳。
