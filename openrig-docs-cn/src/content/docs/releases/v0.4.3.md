## 摘要——"能存活的 rig"

OpenRig v0.4.3 让 rig 真正能够存活。把守护进程乃至整台机器弄崩——直接断电，而不是体面停机——重启之后席位会回到它们**原来**的会话，带着崩溃前的恢复标记，零次 fresh-prime。证明是一次真实的硬关机收尾演练（硬断电 → 重启 → `rig start` → Claude 与 Codex 席位双双恢复到各自的发起会话）。这就是承重的"能存活的 rig"主张。

在存续主干之外，本版本发布了**默认拒绝的 `rig send` 反转**：`needs_input`（真实的交互式选择器）现在是唯一的硬性发送拒绝；unknown / stale / missing / busy 一律 advise-and-send。0.4.1 的 3 层守卫在实践中过严——0.4.2 热修复了 daemon-status 探测，0.4.3 则纠正 send 守卫的姿态，例行的队友协同不再需要 `--dangerously-interact` 作桥。真实的提示符阻塞仍然有效。

Wave-2 UI 在工作区落地 rig-status + 启动控制、一次 switch-client 的视图重定向，以及一套真正的主题系统（Vellum Dark 选择性开启；light 主题字节级不变）。席位交接全周期 + 席位分叉收尾补全恢复故事。教义（Doctrine）也有随版：mission-slice-sop 技能。

现有的 v0.4.2 数据库在新守护进程上运行 `rig daemon start` 即可升级。迁移 045、046 与 047 均为增量式。

## 存续——承重集合

- **崩溃恢复 resume-token 台账（FR-3 → FR-7）**——席位的 resume 标记在收养（adoption）时采集（FR-3）、快照时刷新（FR-4）、钉定到一个恢复目标（FR-5）、以 1 小时的建议性阈值 + `--fresh` 复核做新鲜度门控（FR-6 + FR-6.1 周期性重盖戳），而——关键地——恢复路径绝不把一个本有 resume 标记的席位静默降级为 fresh-prime（FR-7）。在 FR-7 之前，一次够不到 token 的恢复会退化为 fresh-prime，丢掉原会话身份；这一静默降级如今被消除。
- **夹具目录（fixture-home）隔离守卫**——一个会清掉存活 rig 主目录的 fresh-prime 会被大声拒绝，而非静默吞掉。
- **存活 PID 校验**——守护进程通过先确认进程真实存在再给席位贴上 running 标签，来区分存活席位与死 PID 幽灵。
- **守护进程事件循环健康 + 终端代理韧性**——守护进程发布一个事件循环延迟健康信号；`TerminalSessionBroker` 在守护进程重启间干净恢复。
- **启动证明**——席位须证明它真的读过了自己的 orientation 材料，而不是跳过；一条经挑战验证的读取路径。
- **席位交接全周期**——卸任席位可以把自己的已采集上下文交给一位全新继任者；resume 标记经 FR-3 自动携带；交接失败时两条通道都会触发大声回退（loud-unwind）路径。
- **席位分叉收尾**——分叉生命周期在共享检查点上干净终止；前任与继任者都被命名并接线。

## 默认拒绝的反转（`rig send`）

0.4.1 的 3 层守卫在舰队层面过于激进：unknown / stale / missing / busy 活动信号全部默认拦截，例行的队友协同因此不得不反复使用 `--dangerously-interact --reason "..."` 覆盖。0.4.3 纠正了这一点：

- **`needs_input`（目标 pane 上渲染出的真实交互式选择器）是唯一的硬性发送拒绝**。守卫行为在真正的陷阱点上保持不变。
- **Unknown / stale / missing / busy** 现在改为 **advise-and-send** 而非拦截。队友发送照常送达；操作者在发送输出中看到建议。
- **`--dangerously-interact --reason "..."`** 覆盖仍然存在，用于刻意驱动一个停在提示符的席位，行为不变。

同样改进的还有：**Codex 活动信号硬化**——空闲的 Codex 席位现在接受正常发送；真实的提示符阻塞仍然保持；hook 信任自动清除（hook-trust autoclear）作为快速跟进落地，让恢复出的 Codex 席位在恢复时清掉自己的关注门。

## `rig send` 统一寻址

`rig send` 增加显式的多收件人寻址——一个收件人列表 + `--pod` + `--rig`——复用既有的广播扇出 + 逐收件人守卫。向后兼容：单收件人发送不变。

## Wave-2 UI 与主题

- **Rig-status + 启动控制 UI**——用于启动 / 停止 / 恢复一个 rig 的工作区呈现面落地。将拓扑视图与一个面向混合方案 rig 的启动弹窗结合。
- **switch-client 视图重定向**——点击 switch-client 动作后，操作者会落到正确的目标视图，不再挂着过期面包屑。
- **Dashboard 主题——Vellum Dark 选择性开启**——一个真正的主题原语：`light` 即现有 `:root` 主题（字节级一致），`dark` 是首个随版备选，底座经 token block + registry 条目可扩展到 N 套主题。使用 Tailwind `darkMode: 'selector'`。light 主题不变。

## 恢复与操作者 UX

- **空闲门看门狗（watchdog）**——一个持有可认领门口队列条目的空闲席位会被唤醒，并做有界的跳过记录，免得队列积压在一个沉睡席位之后。
- **会话管理变更的认证守卫**——管理员变更呈现面不再能在没有正确认证姿态的情况下触达。
- **`rig queue show` 有界 body 预览**——过长的队列条目 body 在 show 视图中截断；完整 body 仍可在队列条目抽屉中查看。
- **手动可配置的压缩触发 + 同席位守卫**——可以从席位之外提示 Claude Code 席位执行压缩；该触发拒绝同席位变更。
- **密钥边界 B1 硬化（`rig auth`）**——`rig auth` 的密钥边界现在先打开 fd、再始终作用于 fd，从不重新解析路径，封死 check-then-use 在中断 / 并发合法 rig 进程场景下的缺口（TOCTOU 一类随之关闭）。`rig auth` 文件是真实凭据；泄漏追查是真正的安全工作，不是表演。

## 教义与快速跟进

- **`mission-slice-sop` 技能**随版——涵盖 `PROGRESS.md` / `PROOF.md` / `MISSION_NOTES.md` / `MISSION_BRIEF.md` / `README.md` 的逐文件规则、SCAFFOLD/POPULATE/PROJECT/VERIFY 生命周期、hot-potato 队列交接，以及 `rig scope audit` 兜底。
- **Hook 信任自动清除（快速跟进）**——一个恢复后的 Codex 席位若撞上 attention_required 的 VM 本地 hook 信任门，现在会在恢复路径上自动清除关注，与切片 10 镜像一致，实现完全无值守的 Codex 恢复。

## 行为与兼容性

- **迁移**——仅增量。`045_resume_verification`、`046_seat_identity_verdicts`、`047_events_node_type_index` 随本版本落地。现有 v0.4.2 数据库在新守护进程上运行 `rig daemon start` 即可升级。
- **`rig send` 默认姿态变更**——unknown / stale / missing / busy 活动信号不再默认拦截；只有 `needs_input` 会。如果你此前依赖 0.4.1 的默认拦截姿态，请在调用点自行加显式守卫；队友协同的意图信号现在走舰队标准的 advise-and-send 路径。
- **`rig send` 语法**——多收件人列表 + `--pod` + `--rig` 为增量；单收件人调用不变。
- **纯视觉的 Project 呈现面**——Dashboard 主题经 UI 开关选择性开启；light 主题字节级一致。
