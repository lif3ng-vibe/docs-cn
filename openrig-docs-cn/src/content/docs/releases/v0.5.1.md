## 摘要——一套面向产品的测试系统，外加经由它发布的可靠性修复

**v0.5.1 为产品带来一套测试系统**。场景通过"人使用的同一批命令"驱动真实产品，因此产品能在无需人工逐项核对的情况下证明自己的行为。这一窗口期的可靠性修复经由测试系统发布——在第一个周期就证明了它的价值。

**v0.5.1 完整包含 v0.5.0**。同一条血脉，毫无分歧。

迁移仅做增量（additive）。既有 v0.5.0 数据库只需在新守护进程上运行 `rig daemon start` 即可升级。相较 v0.5.0，没有任何 CLI 命令或旗标被移除或更名。

## 发布内容

### 测试系统

- **供测试用的桩（stub）运行时**——一个可被场景驱动的假智能体运行时。让场景能端到端地驱动守护进程，而无需真实的 Claude 或 Codex 进程。
- **场景格式 + 运行器**——一种基于文本的场景格式，以及一个针对真实产品执行场景的执行器。其中包含一个源自编写运行器的真实修复：针对窗格（pane）或会话记录做文本匹配，原本永远匹配不到它本应命中的两个呈现面；现在可以了。
- **种子场景**——三个种子场景对真实产品端到端运行全绿。无法建成的那个见下文"已知限制"。

### 容器试验床——脚手架

**容器模式的脚手架**已发布：参数构建器、镜像身份打标、运行手册（runbook），外加一个单元测试套件。**运行器还不能在容器中执行**——它是你会在目录树里看到、但目前没有任何测试驱动的脚手架。容器模式执行已列入后续规划（scoped forward）。

### 可靠性修复（经由测试系统发布）

- **守护进程传输失败的诚实呈现**——操作者看到的是真实失败，而不是静默的空操作或笼统报错。
- **队列持久化**——两处修复，确保队列记录写入之后仍如实反映实际发生的事。
- **跨机器发送回归**——验证期间发现并修复。这正是测试系统在履行职责：跨机器验证产品行为，并在发布前拦下一个回归。

### 小功能

- **来自 spec 的每智能体模型**——每个智能体的模型来自其自身 spec，而非全舰队统一默认值，因此不同智能体可以运行在不同提供商或模型上。
- **Token 用量随时间跟踪**——守护进程记录 token 使用量，操作者可以看到趋势并预测席位何时接近用量上限。
- **消息携带来源机器**——消息带上来源机器信息，多主机协作因此清晰可读。

### 其他

- **UI 时序加固**——UI 测试不再因加载时序的偶发抖动而失败。
- **队列记录写入后说真话**——收束了一类"写了却没生效"的问题。
- **未送达消息可见性**——展示从未抵达智能体的消息。落地当天就暴露出九个自 8 月 8 日起被静默丢失的真实交接。

## 已知限制

- **容器模式已搭好脚手架，但尚未被驱动**。你会在目录树中看到接缝（seam）、参数构建器、镜像打标、运行手册与一个单元测试套件，但目前没有任何测试在容器中执行。已列入后续规划（scoped forward）。
- **种子场景：计划集合中三个已运行全绿**。第十个场景无法建成，原因是缺少产品尚不具备的两项能力（场景不能改变正在运行系统的形态；终端界面暴露的是导航状态而非舰队清单）。这两项能力均已列入后续规划（scoped forward）。

## 行为与兼容性

- **迁移**——仅增量。既有 v0.5.0 数据库在新守护进程上运行 `rig daemon start` 即可升级。
- **API 呈现面保持不变**——相较 v0.5.0，没有任何 CLI 命令或旗标被移除或更名。
- **v0.5.1 完整包含 v0.5.0**——同一条血脉，毫无分歧。
