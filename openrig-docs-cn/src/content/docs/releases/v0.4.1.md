## 摘要

OpenRig v0.4.1 是一次可观测性 + 操作者 UI 的大改版：工作区成为开发者的 mission 驾驶舱。在 Project UI 上，层级投影（工作区 → mission → 切片）与一套连贯的标签页取代了 v0.4.0 那些半成品的 Project 页面。mission 落地标签页展示引导（steering）与面向人的 mission 简介。Story 标签页把某个 mission 上实际发生的事，重构成一条基于队列谱系的、可滚动的 git-graph。Workflow 标签页将已配置的工作流规格可视化。Artifacts 导航器 + Proof 标签页 + Progress 热力图为工作区层级带来了自己的原生呈现面。Dashboard 路由作为启动器主页也迎来一次干净的焕新。

底层方面：一个 UI 数字孪生从带类型的夹具（fixture）出发，无须守护进程地 1:1 渲染全部六个真实 Project 呈现面，使视觉意图能够在任何 UI 切片动工之前先获得确认，并在收尾时用真实截图加以证明。拓扑边流动动画在拓扑图上呈现真实的队列/交接移动（信号驱动，绝不是装饰）。For-You 信息流换上对手机友好的新样式，并保持真实数据忠实度。

新 CLI：`rig auth` 落地为一个产品原生的、CLI 本地的 Codex 认证配置（auth-profile）管理器，带有硬化的密钥边界，拒绝逃出 CODEX_HOME 的 symlink + 硬链接路径。`rig send` 带上一套 3 层交互式提示守卫（目标 pane 处于提示符时默认拦截；`--raw` 按键仍受守卫；`--dangerously-interact --reason` 为经审计的覆盖）——队友消息再也不能在另一个智能体的终端里误选一个选项。

可靠性修复：全新执行 `npm install -g @openrig/cli` 后接 `rig daemon start` 现在能干净解析（缺失的 `@hono/node-ws` 运行时依赖此前被开发主机上的 monorepo 提升所掩盖，但在全新安装上会失败；CLI 现在镜像守护进程的完整运行时依赖集合，并由一个打包完整性测试把关）。表格视图 + hybrid 终端动作的错误以可见告警呈现，而非静默失败，且表格终端能正常打开。队列条目新增一个人类可读的 `summary` 字段（增量迁移 044；对撰写者分阶段 WARN）。

现有的 v0.4.0 数据库在新守护进程上运行 `rig daemon start` 即可升级。迁移均为增量式（044 新增可空的 `queue_items.summary` 列；0.4.1 之前的条目可干净降级为 body 回退标签）。

## 本版包含内容

### 新增顶级 CLI 呈现面

- **`rig auth`**——产品原生的、CLI 本地的 Codex 认证配置管理。在 CLI 自有的 `~/.openrig/codex-auth/` 下列出 / 查看 / 切换 / 采集 / 遗忘 Codex 配置，绝不越出 CODEX_HOME。对抗性路径已被封死：被 symlink 的 active 认证会被拒绝，硬链接与 symlink 的父目录无法逃出 CODEX_HOME，且密钥边界经集成测试。取代此前产品外的临时 Codex 认证切换，成为唯一的头等呈现面。

### `rig send`——交互式提示守卫

队友消息再也无法在另一个智能体的终端里误选某个选项或误批某项权限。共三层：

- **L0（默认）**——当目标 pane 停在交互式提示或权限块时，`rig send` 会被**拦截**。检测以 hook 为主（Codex `PermissionRequest`），并配有硬化的 capture-pane 回退（12 行尾部内容扫描 + 15 秒的发送就绪新鲜度）。
- **L1——`--raw`**——精确按键；L0 守卫仍然生效。
- **L2——`--dangerously-interact --reason "..."`**——显式覆盖，隐含 `--raw`，要求 `--reason`，写入一行审计记录。

长年存在的"一条 stand-down 消息误提交了 authorize-publish 默认项"的陷阱就此关闭。

### 工作区可观测标签页（主打）

- **引导（Steering）标签页（mission 落地页）**——Panel 1 投影 `STEERING.md`（智能体当前被要求去做什么）；Panel 2 投影 mission 面向人的 `MISSION_BRIEF.md`，它派生自新的已锁定 7 节 schema。点进一个 mission 时首先落在此标签页；Overview 仍然可用。
- **Mission 简介文档类型 + 投影**——一个真正的 canonical 面向人文档类型，与 `README.md` / `PROGRESS.md` / `MISSION_NOTES.md` 并列。`rig scope init-workspace` / `rig scope mission create` 从 7 节模板（Brief / What & why / Building / Progress / Proven / Needs you / Pointers）生成根级 `MISSION_BRIEF.md`；可按需把同一模板回填到既有 mission。Mission 的 Steering 标签页将其以 markdown → UI 渲染。
- **Story 标签页——队列条目 DAG git-graph**——从 `chain_of_record` + 交接谱系重构出一片 DAG 森林，呈一条向上生长、可滚动的 git-graph。仅单父边（不虚构合并状态）；曲线装订线上方的一行式条目；全宽展开行；Tier-3 抽屉复用队列条目查看器，展示完整的智能体语言 body + chain。mission 与切片两个层级皆可用；基于既有的 `/api/queue` 只读 API 在客户端实现（无新呈现面）。Queue 标签页并入 Story。
- **Workflow 标签页——规格可视化器**——把半成品的 Project Topology 标签页补完为已配置工作流规格的真正只读可视化器：点阵网格画布、深色表头步骤卡、每步骤状态点、dagre LR 布局、琥珀色 reject → rework 回环。标签更名 Topology → Workflow（test-id 保持 `project-tab-topology`，id 稳定）。mission 与切片两个层级皆可用。仅工作区内；独立的 Topology 页面（NOC）不变。
- **Proof 标签页**——逐切片证明画廊 + 已脚手架但未填充切片的空状态。读取切片的 `proof/` 目录 + 若存在则读取 `PROOF.md` 摘要。
- **Progress 热力图**——Project Progress 标签页收敛为热力图（逐切片汇总卡退役）；热力图一眼呈现状态，没有重复卡的噪音。
- **Artifacts 导航器**——切片层级的 `ArtifactsNavigator` 取代先前的 `SliceArtifactsTab` 卡墙；文件与文档经由同一 `/api/files/*` 呈现面解析；证明工件归 Proof 标签页所有；决策呈现面经由 Story 路由（记录中的决策项本就是 Story 节点）。
- **工作区组合视图（portfolio）**——工作区父层级渲染一个跨 mission 的组合面板：mission 列表，展开时附带引导一眼概览、惰性 `MISSION_BRIEF.md` 抓取，汇总指标计数采用 *proven*（取自 `hasProofPacket`）而非 `done`。

### UI 数字孪生与视觉意图→证明约定

- **UI 数字孪生（harness）**——一个按源派生的孪生体，从带类型的夹具（cache-seed + 一层薄的 fetch 覆盖 + 一个种子化的 SSE 流；**不是** MSW）出发，无须守护进程地 1:1 渲染全部六个真实 Project UI 呈现面。每个呈现面一个自包含的 `intent.html`；tsc 编译期漂移守卫（真实的接口变更会打断孪生构建）；约 2 步的逐切片编写环；与生产隔离的仅开发目标。用 `TWIN_ROUTE=<route> npm run twin:build` 构建任意呈现面。
- **`rig scope` intent-visual 插槽**——`rig scope slice create` 生成的切片 `README.md` 内含一个 `## Intent visual` 插槽，附 `[change.diff]` 与 `TWIN_ROUTE=<route> npm run twin:build` 重建命令。非视觉切片会得到一行显式 `N/A`，因此每个切片上该插槽*要么存在要么 N/A*。
- **视觉意图→证明约定**——随 harness 一同采纳：视觉意图在建前先以孪生样机确认，收尾时再用真实截图证明。该约定的孪生数据新鲜度条件（每个全新 UI 呈现面都有孪生夹具；数据形状与真实一致）并入发布收尾门。

### 拓扑与 For-You

- **拓扑边流动动画**——当真实的队列交接或 `rig send` 经过一条边（source → destination）时，该边沿交接方向动画，存活期间变亮，TTL 之后归于静态。诚实契约得到坚持：**仅**在真实的 queue / send 信号上动画（没有工作流 DAG，没有环境常动）；无信号的边保持静态；reduced-motion 下省略流动。仅限拓扑图形呈现面。
- **For-You 手机焕新 + 真实数据忠实度**——Dashboard 的焕新延伸到 For-You，成为对手机友好的卡片布局，附层级拨盘筛选（All activity → Highlights → Needs you，每档卡片集不同）。信息流卡片不再渲染内部 `source.type` 包装字符串；筛选信息流上方残留的 storytelling 预览带已移除（它无视层级筛选，还在视觉上遮蔽了焕新）。

### 可靠性与正确性

- **全新安装的守护进程启动修复**——`@hono/node-ws` 现在声明在 CLI 包中（CLI 内置（vendor）了构建好的守护进程、不依赖 `@openrig/daemon`，因此其 `package.json` 必须镜像守护进程的运行时依赖，全局 `npm install -g @openrig/cli` 才能解析它们）。monorepo 提升的盲区造成开发主机能跑、全新安装却失败；如今若守护进程运行时依赖未镜像进 CLI，打包完整性门会让测试套件失败。
- **表格 / hybrid 终端动作可靠性**——终端动作错误在拓扑 Table 视图 + hybrid 呈现面上以可见的 cmux/认证告警呈现，而非静默失败；Table 终端现在能干净打开。
- **队列条目人类可读摘要**——队列条目上的增量可空字段 `summary`（迁移 044）。`rig queue create` + `rig queue handoff` 获得 `--summary`，并带 WARN-on-author（缺失即告警；**不会**硬性打断既有调用方——分阶段强制）。智能体语言的 body 仍是事实来源，且可在队列条目抽屉中查看。Story 行标签优先采用人工撰写的摘要，对 0.4.1 之前的条目干净降级为 body 回退。
- **席位范围的压缩后恢复**——Claude Code 席位获得一个从 JSONL 会话记录派生的、有范围的、幂等的恢复包；压缩后的智能体从持久证据重建其工作心理模型，而非含糊的回忆。
- **表格视图崩溃修复**——null 安全的 TanStack 过滤 + 三个拓扑 Table 挂载点（host / rig / 工作舱）上的 `ErrorBoundary`，单个坏行不再拖垮整页；已加回归测试。
- **Dashboard 路由焕新**——欢迎 / 主页启动器路由的纯视觉翻新（paper-draft 启动器网格 + 六张卡 + Field Environment + 起草页脚）。纯视觉层面；六个启动器路由与卡片 test-id 均保留。

### 已采纳的约定

- **视觉意图→证明**——数字孪生约定以三个已批准的组成部分采纳：按源派生的孪生（不用 MSW）、每个呈现面一个 `intent.html`，以及作为残余发布收尾检查的孪生数据新鲜度。
- **发布耐久性收尾——AC-9（技能级联完整性）**——`rig skill audit` 对随版集合干净，每条漂移边全绿，捆绑插件除已声明的变换外与 canonical 对齐一致。条件 2（漂移边）在随版级联检查器落地前保持建议性；条件 1 与 3 自本版本起为硬性。
- **发布耐久性收尾——AC-10（孪生数据新鲜度）**——孪生的组件观感在构造上即为 1:1；把关仅覆盖构造覆盖不到的两个残余——虚构数据集的代表性（由孪生构建机械地抓住）与全新路由的夹具覆盖。

## 行为与兼容性

- **迁移**——仅增量。迁移 044 新增可空的 `queue_items.summary` 列；0.4.1 之前的条目降级为 body 回退标签。省略 044 的 0.4.1 之前守护进程也经由一条 `detectQueueColumn` 守护的读取路径干净降级。现有 v0.4.0 数据库在新守护进程上运行 `rig daemon start` 即可升级。
- **`rig queue create` / `rig queue handoff`——`--summary`**——可选；缺失摘要发出 WARN，绝非硬错误（优雅迁移）。硬性必填是未来的硬化方向。
- **`rig send` 默认行为**——目标 pane 停在提示符时拒绝发送。`--dangerously-interact --reason "..."` 是显式覆盖路径。
- **纯视觉的 Project 标签页更名**——Topology → Workflow（test-id 稳定）；Queue 并入 Story。
- **For-You 信息流**——`/for-you` 上的 storytelling 预览带已移除（其 mission 进度汇总保留在 Dashboard / Project 上）。

## 已知限制与后续跟进

- **技能层切分深度（slice 04 家族）**——canonical 技能层切分仍待对承重技能集合的决定；本次并不执行该切分。04.3 的随版级联漂移检查器不在此切分内。
- **约定漂移控制（slice 28）**——部分交付；约定已批准并并入发布收尾门，但随版产品技能 + 审计代码仍在进行中。
- **孪生采集工具（slice 11.2）**——孪生 harness 已随版；一键采集包装器仍在进行中。
- **工作区 UX 架构（slice 15）**——设计发现范围已批准；其余样机仍在进行中（它们把关的是未来的 UI 切片，而非 0.4.1 已随版的呈现面）。
- **For-You 终端手机 UX（slice 27）**——For-You 焕新与真实数据忠实度已随版；内嵌终端的手机 UX（键盘 / 触控 / 宽度 / 性能）是非阻塞的打磨检查，尚未经手机验证。
- **`rig send` 交互式提示守卫——hook 主路径**——回退 capture-pane 守卫已被完整证明；hook 主导的 `PermissionRequest` 路径随本版本落地，其完整证明留待下一轮迭代。
- **`rig auth` 后续（B1 密钥边界）**——已并入 `rig auth` 的对抗性硬化关闭了 symlink + 硬链接逃逸；更深层结构化的后续项另行跟踪，不在此切分内。
- **继承的级联元数据卫生**——0.4.0 的顺延项（技能层 `missing_provenance` + `missing_verified` 审计发现）仍是文档化的残留；批量修复归入 0.4.0 之后单独的技能卫生工作项。
