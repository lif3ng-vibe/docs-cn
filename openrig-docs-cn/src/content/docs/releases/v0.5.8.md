---
title: "OpenRig 0.5.8 — 可恢复的运维与可见的工作"
---

OpenRig 0.5.8 让长时间运行的 rig 更容易恢复、理解和操作。它新增了突发中断后对所选 rig 的精确恢复，让当前任务（mission）及其执行脉络对智能体和操作者可见，并收紧了维持实时状态诚实的诊断与防护栏。

## 恢复与拓扑生命周期

- **中断后恢复所选 rig。** Restore 现在会拒绝过期的原生身份，使用真实的提供商会话证据，避免代之以全新的或错误的占用者，也不会启动无关的兄弟 rig。
- **统一拓扑创建路径。** 公开的创建与扩展收敛到相同的守护进程效果，同时保留成员的工作目录覆盖。
- **让拓扑声明保持实用。** rig 如实呈现自身描述，工作区声明在导出后得以保留，且经过验证的工作区声明可以应用到既有的 rig 而不改变其拓扑。

## 任务与上下文可见性

- **从 SCOPES 打开任务执行。** 选中的任务现在呈现可读的 `DONE` / `NOW` / `NEXT` / `ATTENTION` 故事线、真实的工作车道与证据缺口计数、有界溢出，以及稳定的任务切换。
- **安装真正处于当前的工作。** Work-install 解析完整文件与点式切片（slice）ID，而 refocus 会推导该席位带类型的当前任务与切片，不再要求智能体凭记忆重建它们。
- **发现随附的能力。** 公开能力世界及其可寻址的上下文可通过已安装的上下文路由获得。

## 运维诚实与更安全的安装

- **只对需要关注的状态唤醒一次。** 搁置（park）计时器在每条退出路径上都会退役，新的搁置回合取代旧计时器，空闲门控看门狗（watchdog）与系统其余部分使用同一个经仲裁的活动判定源。
- **诊断真正在运行的机制。** 生产者链路健康从实际生效的端点推导，拓扑新鲜度有界，合成模型记录不再制造虚假的模型分歧发现。
- **保护用户自有的 Codex 配置。** 托管 TOML 投影在写入前拒绝格式错误或根作用域的片段，并在合法冲突时保留用户自己的表。
- **升级保持由智能体主导。** 随附的升级技能提供有界检查、经过验证的数据库备份以及受控的托管插件刷新辅助，而切换决策仍交由执行操作的智能体判断。
- **信任干净检出结果。** 文档化的守护进程测试门禁与同 SHA 长期门禁现在就确定性源码真相达成一致。

## 运维/安装注意项

- Root、CLI、守护进程与 Web UI 包版本升至 `0.5.8`。终端 TUI 保持独立的 `0.1.0` 版本。
- 数据库迁移头从 `077_node_session_source` 升到 `078_idle_gate_fired_condition`；守护进程正常启动会自动应用，无需手动迁移步骤。
- 既有 rig 无需重写拓扑。新的仅工作区（workspace-only）apply 路径刻意不动成员、工作舱（pod）、边与运行中的会话。

## 已知限制

- 所选 rig 的恢复不覆盖数据库与文件系统同时全损，也不覆盖全集群自动重启。
- 既有 rig 的工作区故事不校验 `target_repo`；这一独立关注点仍在本发布契约之外。
- 后端预存的 `attention_required` 状态不属于有界 TUI 拓扑新鲜度工作的范围。

## 已执行的验证

- 独立 QA 与评审在 110 与 160 列宽度下演练了最终的 SCOPES 执行旅程，包括任务选择、可读的证据缺口、有界溢出、切片下钻与 Escape 导航。
- 恢复测试在当前、过期、缺失与证据不足等状态下使用真实的 Claude 与 Codex 占用者，也覆盖了同一 OpenRig 占用者记录内原生会话身份变化的情况。
- 获接受的产品树被重放为以 0.5.7 为根的线性公开谱系。每位作者与提交者都使用项目 noreply 身份，重放的产品树与获接受的本地 main 树逐字节一致。
- 发布验收包括包组装、逐文件的哈希绑定实质评审，以及针对该精确私有裁剪的已安装运行时 QA 与评审。
