**状态：** 发布候选版（release candidate），未发布。精确裁剪的实质评审、发布验证与发布仍在待办中。该候选版尚未被采纳进任何实际安装。

OpenRig 0.5.13 把人类用户的 TUI 旅程连成一线：进入实例、选择项目、阅读其当前指令、理解哪些事情需要你决策，然后有意地打开你需要的终端。scoped 级的监督与显式的 Git 上下文更新帮助智能体依据正确的指令工作，同时让权限、证据与本地撰写内容保持可见。

## 从有用的东西开始

裸的交互式 `rig` 在启动检查运行中、守护进程宕机或其状态未经校验时，暴露 Help、Skip 与本地阅读。所选项目、任务（mission）与切片（slice）意图可以从磁盘读取，但不假装它是实时的队列、执行或拓扑数据。读取失败与来源保持可见。启动守护进程或让席位回到工作仍然是有意的动作；阅读与跳过并不意味着同意。

## 阅读当前源码并找到回去的路

PROJECTS 让所选项目的身份与根目录贯穿任务、切片与源码视图，包括显示名相同的项目。某项目源码不可用时，如实报给该项目，而不是替换成另一个项目的工作。Refresh 读取当前文件。

共享阅读器显示源码路径、修改/哈希信息与有界的内容，支持滚动、本地链接、标题链接与 Back。HTTP(S) 链接显示一个可选中以便复制的目的地；不会打开浏览器。缺失、不可读、二进制或超出根目录的文件保持为具名报错。大文件显示 1 MiB 返回内容上限；被截断前缀中缺席的标题不会宣称在整个文件中缺席。Back 恢复之前的阅读内容与导航位置。

## 分清哪些需要你决策

ATTENTION 将 **Action required** 与 **Updates** 分开。人工请求与显式阻塞会显示请求内容、紧急度、scope 以及它能解锁的工作。成果与健康更新保留各自的来源与历史。打开详情或关联的证据来理解它；查看请求不等于批准或投递，关闭一个队列条目也不是产品成果完成的证明。缺失或不完整的读取保持可见。

## 打开终端之前先预览

TERMINALS 列出已保存与派生出来的视图，连同其成员与解析出的布局。预览是被动的。有意的 Open 使用被检视的方案，并上报已打开、缺失或降级的成员，包括部分失败。Help 与旁路之后会回到同一个预览与页面。已观察到的原生提供商旅程使用 Herdr；更广的提供商限制见下文。

CONFIG 保证完整取值、默认值与来源/覆盖来源可读。Help 提供命令描述、语法与示例，在启动失败期间同样可用。窄视图保留滚动与返回控件。Health 让 INFO 严重级与 Unknown 评估分开，暴露过期与不可得的读取，并解释一个空的发现列表**不是健康判定**。完整的空健康解释在 80 列下即可读全。

## 为眼前的工作选择监督

人类主导的工作在仅进程诊断时默认安静。显式的委派可在规划与执行两个阶段同样启用该监督，前提是既有诊断策略与投递前置条件得到满足。普通工作提醒与运维健康保持原行为。scope、阶段与姿态来自显式来源；未决的身份保持未知。

用 `rig mode effective` 加显式 scope 来检视结果。[scoped operating posture 参考](/reference/scoped-operating-posture/)描述选择与优先级。姿态偏好不授予任何执行权限。纠正记录可以保留选定的当前指引，并区分一次评估、实际采取的一次动作与后来观察到的效果。这些是受支持的机制，而不是判断力得到改进的证据：自然的行为效果仍为 **UNOBSERVED**，人工时间成本仍为 **UNMEASURED**。不声称治愈或复发率降低。

## 更新上下文而不丢弃本地撰写

`rig context add <repository-path-or-URL> --git` 保留 Git 来源、其检出与所选上下文包（context pack）之间的关系。在仓库内选择包时用 `--pack`。既有的 Git 凭证照样适用。

用 `rig context source inspect <ref>` 在不抓取的情况下检视本地变更、冲突、版本与选择。`rig context source update <ref>` 在选择干净内容之前显式抓取并合并上游。已提交的本地工作在普通合并中幸存。脏工作树、冲突变更、不可得的上游或对所投递选择的编辑都会导致具名拒绝，而不是重置或覆盖。在留存的检出中解决并提交，或中止合并，然后再重试；冲突期间，之前的所投递选择仍然可用。更新不会 push。

检出历史、所选投递字节与智能体的实际消费是三个不同的事实。用 `rig context get <ref>` 读取所选字节，并核对预期的消费者。这不会自动同步每一个上下文库，也不会把指引采纳进正在运行的智能体。

## 运维/安装注意项与验证限制

Root、CLI、守护进程与 Web UI 包版本为 0.5.13。终端 TUI 保持其独立的 0.1.0 版本。Node 要求不变。有序迁移头从 079 升至 `080_scoped_operating_posture`，在既有 mode 绑定存储中扩展 scoped 的人类主导/委派选择，同时保留旧行。在被授权采纳时，请使用受支持的升级与延续性流程；准备该候选版不执行任何实际迁移或重启。

获接受的开发证据把该旅程连在 140×42 与 80×24 之下，包括不可用/Unknown 控件、双项目隔离、当前源码阅读、有意的原生终端打开与 Git 冲突保留。那些观察保留其原始的开发裁剪与署名。版本、发布说明与包检查与那些旅程分开；它们不是一次全新整版可用性研究。

- 并发打开的默认 TUI 客户端可能互相替换对方的程序化控件套接字地址。这仍是已知的、未修复的限制，对所示范的单客户端人类旅程判定为不阻塞。唯一的测试套接字不能证明产品级的多客户端隔离；历史上丢失的请求仍未核实。
- 原生终端证明覆盖 Herdr。SSH 登录、cmux 的端到端行为以及对父宿主机的影响仍未核实。既有的原生延续证据仅复用于未变的路径，不构成新的提供商覆盖。
- 一次私密关停在关闭连接时超时；干净完成与挂起的效果仍未核实。更早在沙箱中公开启动的失败仍是已记录的失败，尽管之后有成功的托管私密启动。
- 合成的发现与请求演练的是机制，不是自然的行为改善或真实的人工审批/投递。未确立陌生人类研究、真实主机重启、全平台运行或 0.5.13 的实际采纳。
- 最终的精确裁剪验证与发布仍需各自的证据与授权。这些说明不宣告某个可用的 npm 版本，也不授权采纳。
