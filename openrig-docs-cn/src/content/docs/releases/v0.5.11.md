---
title: "OpenRig 0.5.11 — 更清晰的首用、工作流与日常操作"
---

**状态：** 发布候选版（release candidate）。发布与最终发布验证是分开的步骤。

OpenRig 0.5.11 让在普通仓库中开始有用的工作更容易，让团队及其工作流在 TUI 中一目了然，并能诊断配置或生命周期故障而不把不确定的状态误当作成功。

## 首次有用工作与共享视图

- `first-project` 预置模板（starter）为一个仓库提供专注的 Codex 负责人/检查者组合。README 沿着这条路走完从启动、做出一次有用的变更、独立检查到回到工作的全程。
- 新的内核（kernel）包含一个共享的 TUI 终端。`rig tui --shared` 接入该既有视图；不带参数的 `rig tui` 打开独立视图。加入共享视图不会悄然启动缺失的终端或智能体。
- Herdr 用户也可以走同样的仓库与终端旅程。这是无插件可用运维的准备；Herdr 插件或社区采用的结果不属于本发布。

## 在普通 TUI 中理解工作

- 任务（mission）视图暴露工作流、其当前步骤与负责人、等待，以及一次流转背后的工作包。源码导航将视图与撰写的工作及 specs 连接起来。
- Specs 呈现已声明的目的，包括 rig 的 `summary`，并区分内容缺失与读取失败。
- Connections 显示正在运行的守护进程与 CLI 身份、生效的实例设置、已配置与已应用的网关状态，以及已登记的人工路由。它是被动的检视呈现面；已配置的连接器并不证明有人收到了消息。
- 命令补全、可读的 Recent 活动与持久可配置的时区让日常导航更容易。默认显示时区为 America/Los_Angeles。
- 超时的守护进程探测在整个 TUI 界面中保持未经验证状态，而不是被标注为已确认的宕机。

## 更可靠的协同与生命周期

- 项目自有的发布档案（profile）提供可复用的仪式与发布后边界步骤。当前版本的收尾不再依赖凭空发明一个后续任务。智能体仍要对每项待办义务（obligation）背后的证据作出判断。
- 工作流异常恢复会保留正确的负责人并清除已解决的异常状态。卡住工作的发现保留如实路由所需的来源证据。
- 终端投递保留撰写好的长上下文；分步走查验证会检查目标片段与适用的运行框架/代际记录。投递与原生回合完成仍然不同于理解。
- Context profile 与 work-install 命令在 `codex` 之外接受一致的 Claude 运行框架写法（`claude-code` 与 `claude`），无效的显式取值在投影前被拒绝。
- 启动使用选定的撰写证明。它不会增加未被要求的演练，仅终端成员也不会收到智能体证明挑战。
- 守护进程关闭有有界的预算与带署名的结果回执。失败或缺失的回执在受支持的停止路径上仍然可见。
- 守护进程启动把成功与状态发布绑定到其真实的子进程，处理竞争启动，并在无法确立子进程存活时保留不确定性。跨主机请求归因独立于所选目的地识别来源。

## 运维/安装注意项

Root、CLI、守护进程与 Web UI 包版本为 0.5.11。终端 TUI 保持其独立的 0.1.0 包版本。Node 要求不变。有序数据库迁移头仍为 `079_workflow_lifecycle_parallel`；本发布在 0.5.10 源码基线之外不新增迁移。

诊断 `show` 与 `list` 现在返回摘要深度的 `--json`，保留当前状态与决策并同时指明被省略的证据。需要完整记录的消费者必须使用 `--full --json`，或执行打印出的展开命令。队列 `show` 保留其 512 码点正文预览，并新增显式的大小、完整性与展开元数据。HTTP 响应与 mutation JSON 保持完整。这些默认值不是全局输出大小上限。

请使用受支持的升级流程，带数据库备份与延续性检查。守护进程重启与 rig 关停效果不同：后者会停止席位。既有内核不会自动重建以获得新的共享终端。

## 验证范围与限制

该候选版保留了更早的隔离已安装包证据，覆盖连通的 first-project/工作流/TUI 旅程，以及对用途与未验证状态修正的聚焦验证。那些更早的运行归为既往证据，并非本裁剪的全新端到端或提供商接入测试。包身份与有界的已安装渲染检查随候选版准备进行；精确裁剪的实质验证与最终发布验证仍需在发布前完成。

- 首用证据包含全新重入；它不确立同会话 resume 或完整的混合运行框架接入。
- 受控的 Connections 证据与被动检视不确立对外的人工投递。瞬态探测延迟与视图延迟填充仍是已观察到的限定条件，不构成全面响应性声明。
- 撰写完成度、遗留来源与证明配对是各自独立的读取方。更新一份声明不会凭空补出缺失的来源或执行波次历史。
- 一项有界的健康分析概念验证产出了带署名的诊断并正常退出。它是研究证据，不是随附的冷智能体/运行 API、提供商抽象，也不证明对常驻方式有成本或延迟优势。
