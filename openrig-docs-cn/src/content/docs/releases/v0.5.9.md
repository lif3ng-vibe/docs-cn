OpenRig 0.5.9 把终端 UI 变成真正的任务控制台呈现面，并为其背后的实例带来更干净、更耐久的运维模型。TUI 在普通终端尺寸下更容易扫读、导航与驾驭；System World、项目上下文与托管技能现在显式组合；而 restore、全新启动、定时唤醒与项目工作流都会上报它们实际作用于的状态。

## 开发者视角的精致终端 UI

- **一眼读全实例。** 拓扑视图现在在多个 rig 之间呈现一张连续的智能体表格，保持工作舱（pod）分隔线可见，并从真实的队列流转记录中显示有界的 `RECENT` 工作，既不重复已归档的 rig，也不凭空编造缺失的摘要。
- **从总览到行动不丢上下文。** 实例、rig、任务（mission）、切片（slice）、智能体与 Explorer 页面共享同一响应式视觉语法，滚动时保持 rig 身份可见，并且在 160、120 与 84 列宽度下生命周期证据与操作都触手可及。
- **把终端当作一等界面。** 语义状态配色、紧凑字形、克制的动效、窗口尺寸变化重绘、过滤、指针局部滚动、终端原生选择/复制、接入操作与基于套接字的命令，都经由同一个生产呈现面生效。

## 连贯的实例、上下文与技能模型

- **从一个增量的实例布局开始。** CLI 与守护进程启动会对齐同一规范的 `$OPENRIG_HOME` 结构，保留既有内容，并在写入前拒绝类型错误的托管路径。
- **将 System World 与当前项目组合。** `context.root` 是可寻址的上下文库，`context.system_world` 选择实例级基线，而 `rig context work-install` 一次性上报 System World、拓扑与项目输入。
- **把技能当作独立资源管理。** `skills.root` 指定一个可版本化的目录。`rig skill loadout` 组合系统、拓扑与项目选择器；其 apply 模式只拥有 manifest 列出的投影，并拒绝抹除本地或已修改的内容。
- **以合适的宽度为每个运行框架备好入门。** 按提供商形态定制的上手内容为 Codex 提供紧凑的引导加可寻址的覆盖地图，同时为确实受益的运行框架保留更完整的引导路线。

## 生命周期与恢复诚实

- **为一个席位刻意创建空白占用者。** `rig seat launch <seat> --fresh --reason <why>` 是显式的无延续路径；它会保留兄弟席位与持久化工作，并拒绝不被托管语义支持的含糊用法。
- **把撰写的工作编译成可执行的生命周期。** `rig workflow compile` 将 `project.yaml`、`mission.yaml` 与 `slice.yaml` 读取为一张图；`instantiate-lifecycle` 以不透明的重放密钥启动符合条件的图，而带类型的验收证据可以防止工作流的推进冒充发布验收。
- **了解一次 restore 到底尝试了什么。** 快照选择可以是显式的，快照可以保留预期的席位名册，而 `rig restore status` 会推导当前预期集合的结果，同时不把历史节点与未经校验的 resume 谱系算作虚假的成功。
- **让自动化可归因。** 看门狗（watchdog）提醒以显式调度器身份投递撰写好的消息，有效模型检测会跟随经身份校验的当前占用者，而非留存的前任会话。
- **只在值得的地方引入判断。** 随附的 `agent-operated-workflows` 技能区分了 AI 赋能的软件、智能体操作的工作流与智能体操作的软件。0.5.9 实例迁移是该技能的第一个参考实现。

## 运维/安装注意项

- Root、CLI、守护进程与 Web UI 包版本升至 `0.5.9`。终端 TUI 保持独立的 `0.1.0` 版本。
- 数据库迁移头从 `078_idle_gate_fired_condition` 升到 `079_workflow_lifecycle_parallel`；守护进程正常启动会自动应用。
- 既有实例存在一个刻意安排的布局边界：上下文遥测移至 `state/context-usage`，提供商遥测位于 `state/provider-usage`，可寻址库移至 `context/`，默认 System World 位于 `context/system/system-world.yaml`。
- 不要在旧采集器仍在写入时把上述变化当作目录重命名来执行。请加载随附的 `openrig-upgrade` 技能并遵循其 0.5.9 Agent-Operated Migration：检查，以留存迁移前镜像的方式准备，分别激活精确的目标运行框架，校验成对的规范样本，然后携带该精确回执调用非破坏性的库定稿器。完整的命令序列与回滚契约见顶层 README。

## 已知限制

- 迁移辅助工具刻意不停止或启动守护进程、不改写数据库、不重启席位、也不删除遗留遥测/库状态。这些生命周期与最终退役决策仍是操作者的显式工作。
- 一次 restore 尝试的回执只推导持久化事件与当前进程证据能够证明的内容；缺失或含糊的原生身份保持未决，而不是靠猜测。
- TUI 仍是终端呈现面。字体选择与终端颜色渲染由用户的终端模拟器决定，而非 OpenRig。
