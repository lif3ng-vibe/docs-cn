版本 **0.5.15** 的变更内容。发布状态与日期记录在 [GitHub release](https://github.com/mvschwarz/openrig/releases/tag/v0.5.15) 与 npm 上。

OpenRig 0.5.15 改进了启动与恢复，新增了面向持续运转软件团队及用户自选命令权限的公开指引，并修复了 Pi 回复可见性、shell 上下文与终端输入处理。

## 启动与返回的清晰指引

启动之前，请先阅读 [OpenRig 会在你的机器上改动什么](https://github.com/mvschwarz/openrig/blob/main/README/#what-openrig-changes-on-your-machine)。提供商集成可以配置可执行钩子与工作区信任；仅修改 `OPENRIG_HOME` 并不能隔离提供商配置。[入门指南](/reference/getting-started/)会带你走完第一个任务，并解释这些安装影响。

检查你的安装中可用的命令：

```sh
rig --version
rig --help
rig up --help
```

启动与恢复通过 shell 和 Node 启动器识别原生 Codex，并在无法确认进程身份时报告不确定。识别到的更新提示会被跳过，不会安装提供商更新。认证与信任的选择仍由你决定。

启动错误现在会描述问题与恢复动作。如果一个名称同时匹配某个预置模板（starter）和某个已停止的 rig，`rig up <name> --existing` 会选择已存在的 rig。在指派更多工作之前，先查看其报告的状态。

## 继续推进有效的已评审工作

为你的智能体提供一个真实仓库、一个成果，以及你希望保留的决策。捆绑的 OpenRig Software Factory 配方（recipe）支持直接团队协作、队列支撑的编排，或可选的显式 Workflow。

```sh
rig context show skills/core/openrig-software-factory --json
rig context get skills/core/openrig-software-factory/SKILL.md
rig context get skills/core/openrig-software-factory/references/worked-example.md
```

从两席位团队开始。当工作因职责分开而受益时，用 `rig grow` 增加一到两个席位。示例涵盖角色、上下文、工作归属、独立评审、并发与成本，并区分对运行中团队的修改与保存更新后的 RigSpec。请使用与你所装版本相匹配的指引。

## 选择命令权限

让智能体检查目标运行框架（harness），解释可用的 scope，并在保留既有规则的前提下应用你的选择：

```sh
rig context get skills/applying-a-permission-policy/SKILL.md
```

允许全部 `rig` 命令族，同时意味着放行生命周期与配置变更，而不只是读取。必要时选择更窄的命令或保留审批提示。仅项目级设置要求受支持、处于启用且受信任的项目配置；若不可用，智能体应当说明该限制，而不是改用用户级权限。备份被改动的文件，并在实际对话中验证所选规则。随版本发布的沙箱、审批与权限默认值均未改变。

## 已知的兼容性限制

在 macOS arm64 搭配 Node 24 时，若无合适的预编译二进制且无法编译，安装 SQLite 依赖可能失败。编译构建的 SQLite 也曾在运行时的数据库清理阶段失败。**当前请在 macOS arm64 上使用 Node 22**。此建议不改变已声明的 Node 支持范围，本版也不更新 SQLite。

## Pi 的回复、输入与恢复

在受支持的 RPC 事件形态下，Pi 的回复与工具进度可见。Shell 工具保留身份与路由所需的托管 OpenRig 上下文。提供商错误以限定长度的文本显示，重试耗尽后不会反复打印同一条错误。

粘贴的消息会等待显式提交。终端运行器可接受超出终端规范缓冲上限的输入，保留编辑与取消能力，并在拒绝超大分帧消息后恢复。这并非一般性的延迟保证，也不是不设上限的输入长度承诺。

在资源投影阶段首次启动失败、且启动上下文尚未保存的新增席位，可在修正安装问题后使用受保护的重试。保留完整的原始成员片段及其来源根目录；仅凭快照无法重建缺失的启动配置。每次只用一次重试。普通会话恢复（resume）保持独立。

**Pi 的支持状态为验收合格且受监督**。已用 Pi 0.87.1 配合 OpenRouter 的 `z-ai/glm-5.3-flash` 验证了受控的编程、追问、汇报与会话连续性；普通席位的身份识别、工具使用与回复也正常。完成一个普通的有用任务与无人值守的团队运行仍未验证。Context profile 选择与钩子生成的覆盖有限；不要假设它与其他 Codex 或 Claude 集成对等。Software Factory 指南同样未确立完全无人值守的运行。
