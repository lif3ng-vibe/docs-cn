## 摘要

OpenRig v0.3.1 在 v0.3.0 的基础上继续推进：面向操作者的 UX 工作、重磅的 Claude 自动压缩（auto-compaction）策略、Dashboard 与 For You 的视觉刷新、插件原语 v0（Plugin Primitive v0）呈现面（`rig plugin`）、Library Explorer 收尾（技能 + 插件 + 规格，支持真实的文件夹浏览）、Settings 目的地 Explorer、动作结果 + 内联错误 UX，以及一次全面的隐私清理。

没有破坏模式（schema）的迁移。既有的 v0.3.0 数据库会在首次 `rig daemon start` 时完成升级（新增迁移 `040_workflow_specs_diagnostic`——在 `workflow_specs` 缓存上增加两个诊断列，采用带安全默认值的 `ALTER TABLE ADD COLUMN`）。

## 本版包含内容

- **Claude 自动压缩策略**——操作者可配置的会话自动 `/compact`，带安全默认值（默认关闭、自愿启用；不显式启用则行为不变）。新增 7 个 ConfigStore 键；守护进程到 LLM 的六阶段生命周期（预准备提示 → 压缩 → 握手 → 恢复 → 合规审计 → 冷却）；PreCompact 钩子 + SessionStart/UserPromptSubmit 桥接。
- **插件原语 v0**（Plugin Primitive v0）——`rig plugin` 命令呈现面（v0 为只读：`list`、`show`、`used-by`、`validate`）。从 `$OPENRIG_HOME/plugins/` 发现插件，采用 vendored 加来源标注（provenance）模式。v0 没有 `install` 动词；推迟到 0.3.2。
- **Library Explorer 收尾**——技能 + 插件 + 规格成为完全面向操作者的呈现面，支持真实的文件夹浏览。新增守护进程自有的库发现 API（`/api/skills/library`、`/api/skills/:id/files/...`、`/api/plugins/:id/files/...`）。
- **Settings 目的地 Explorer**——设置成为与 Topology / Project / Library / For-You 同构的四项 Explorer 目的地，带有 `/settings`、`/settings/policies`、`/settings/log`、`/settings/status` 子路由。
- **Dashboard 与 For You 视觉刷新**——两条路由采用统一的 "vellum" 呈现面语言（半透明石色卡片、纸纹网格背景、环境阴影、mono+dot 类型指示、L 形角括号对位标记）。生产环境与 `/lab/vellum-lab` 之间单一事实来源。
- **For You 叙事适配器**——Progress / Shipped / Incident / Approval 卡片类型接入真实数据（任务、切片、活动流、队列条目）。ApprovalCard 呈现等待审批的真实队列条目。
- **动作结果 + 内联错误呈现面**——队列条目动词操作（Approve/Deny/Route/Hold/Drop/Annotate/Handoff）在成功时立即渲染结果，失败时内联呈现而不静默回退。修复了一个阻塞演示的静默回退缺陷。
- **移动端抽屉行为**——375px 下 Settings / Project / Library / For-You 的 Explorer 抽屉现在会层叠在边栏托盘之上。Topology 移动端抽屉在 0.3.1 中有意隐藏；计划在 0.3.2 完整恢复。
- **Vendored 技能来源标注**——vendored 技能通过 `metadata.openrig` frontmatter 声明上游谱系，修改过的技能还附带一个 `OPENRIG.md` 伴生文件。已应用于全部 10 个流程技能呈现面。
- **工作流规格诊断呈现面**——迁移 `040` 为 `workflow_specs` 缓存添加 `status` + `error_message` 列，Library UI 可将解析/校验错误渲染为诊断行而不是隐藏。
- **隐私清理专项**——三次 filter-repo 处理从历史中清除了个人数据、内部引用与历史版本；提交标题与正文已为公开呈现面润色。保留备份仓库用于回滚。

## 用户可感知的变化

### Claude 自动压缩策略

面向 Claude 会话的操作者可配置自动 `/compact`，带安全默认值：

- **默认关闭、自愿启用**：不显式启用该策略就什么都不会改变。未配置策略时，守护进程绝不会发送自动 `/compact`。
- **7 个新 ConfigStore 键**，位于 `policies.claude_compaction.*` 命名空间：`enabled`、`threshold_percent`（严格整数 1-100）、`compact_instruction`（由操作者提供；设置后会附加到 `/compact` 参数）、`message_inline`、`message_file_path`、`pre_compact_instruction`、`post_restore_audit_instruction`。在所有来源层（`set`/`POST`/env/file）上严格校验。无效的环境变量取值会回退到默认值并在 stderr 上告警，而不是静默强转。
- **5 个操作者可编辑的提示词呈现面**，位于 Settings → Policies UI：压缩前准备、压缩指令、压缩后恢复（内联）、恢复文件路径、恢复后审计。守护进程自有的包装层（用量/阈值框架、信任通道保留、标记路径、读取深度限制、轮次边界握手、去重 + 冷却）不可编辑。
- **六阶段生命周期**：压缩前准备提示（先存档再退出的心智模型恢复图）→ 带操作者指令的 `/compact` → 压缩后轮次边界握手 → 带纵深防御回退链的恢复提示 → 合规审计（强制输出 FULL/PARTIAL/NOT_READ 表格）→ 10 分钟冷却。
- **安全强化**：正在输入的提示词草稿会被归类为注意（attention）状态，自动 `/compact` 会稍后重试而不是覆盖人工输入。发送失败不会推进去重状态。重新武装需要再次越过阈值。

### 新增 `rig plugin` 命令（v0 为只读）

```
rig plugin list                   # 跨 vendored 与运行时缓存的可发现插件
rig plugin show <id>              # 插件 manifest + 技能 + hooks + mcp 服务器
rig plugin used-by <id>           # 引用此插件的智能体
rig plugin validate <path>        # 校验插件 manifest 与技能 frontmatter
```

v0 没有 `install` 动词——安装即由操作者显式复制或符号链接到 `$OPENRIG_HOME/plugins/<plugin-id>/`。各插件记录在案的复制/符号链接工作流见其 `OPENRIG-INSTALL.md`。`rig plugin install <substrate-path>` 动词推迟到 0.3.2。

### Library Explorer 收尾

Library 目的地（技能 + 插件 + 规格）现在完全面向操作者：

- 顶级条目不再重复（从 `SpecsTreeView` 移除了 `> SKILLS` / `> PLUGINS` 行；点击底行即可导航 + 展开树）。
- 树中插件位于技能之上。
- 32 个 OpenRig 托管的共享技能现在可在生产虚拟机环境中被发现（此前因相对工作区的路径查找而为空）。
- 守护进程自有的库发现 API：`GET /api/skills/library`、`GET /api/skills/:id/files/list?path=...` + `/files/read?path=...`，`/api/plugins/:id/` 下有对等的路由。
- 插件与技能详情页提供真实的文件浏览器 + 文档浏览器。Markdown 自动渲染；非 markdown 文件按文本渲染。文件夹导航可用。
- `/specs/skills` 与 `/specs/plugins` 提供汇总索引页，含平铺行列表、来源标签、文件计数与入口链接。

### Settings 目的地 Explorer

设置现在是与 Topology / Project / Library / For-You 同构的顶级 Explorer 目的地：

- `/settings`（通用配置键表单）
- `/settings/policies`（Claude 自动压缩策略表单在此）
- `/settings/log`
- `/settings/status`

旧的顶行标签页导航已移除。4 个子路由共用 `SettingsPageShell` chrome。

### Dashboard 与 For You 视觉刷新

一次协调一致的视觉刷新，统一到共享的 "vellum" 呈现面语言：

- **Dashboard `/`**——基于新的 `dashboard/vellum/` 原语完全重写。主视觉排版（"WELCOME BACK"）使用 display-lg + headline-bold。带等宽数字排版的战术仪表盘式统计行。六张目的地卡片（Topology / Project / For You / Library / Search / Settings）共用同一套数字布局处理。真实数据 hooks：`useRigSummary`、`usePsEntries`、`useSpecLibrary`。
- **For You `/for-you`**——两套卡片系统统一到 vellum 配方：叙事横带（`CardShell` 以 bg-stone-100/45 + backdrop-blur + 环境阴影 + 角括号重写）与队列条目 `FeedCard.tsx`（同样的外层 chrome；vellum 描边无填充操作按钮，带悬停反色与 44px 触摸目标）。
- **单一事实来源**：`/dashboard` 与 `/lab/vellum-lab` 之间通过 `packages/ui/src/components/dashboard/vellum/` 共享。
- **Lab 路由**——`/lab/card-previews`、`/lab/vellum-lab`、`/lab/vellum-bg/{a-large,b-small,c-allover}` 是纳入版本控制的实验呈现面，供设计师迭代。生产环境中可通过直接 URL 访问；主导航不提供链接。

### For You 叙事适配器

`/for-you` 顶部的叙事横带现在把四种卡片类型接入真实数据：

- **Progress**——前 2 个活跃任务（`useMissionDiscovery`）
- **Shipped**——状态为 shipped/complete/done 的切片（上限 3 个；来自 `useSlices`）
- **Incident**——状态为 blocked/failed/danger 的切片（上限 3 个）
- **Approval**——等待审批的队列条目，来自 `useActivityFeed` + `classifyFeed`（上限 2 个）

`ConceptCard` 组件保留在源码中，但生产适配器不再输出；0.3.2 将做一个明确的数据源决策。

### 动作结果与内联错误呈现面

队列条目动词操作（Approve/Deny/Route/Hold/Drop/Annotate/Handoff）：

- 成功时，`ActionOutcomePanel` 立即渲染（"Approved by X"、"Routed by X to Y"）——无需等待审计日志往返。
- 出错时，动词按钮下方会渲染一个三级边框的错误块，显示守护进程的错误消息；动词选择状态会保留，操作者可以修正后重试。
- 取代了此前的静默回退 UX。回归测试对该类做了显式守护。

## 运维/安装注意项

升级已发布的 CLI 之后：

```bash
npm install -g @openrig/cli@0.3.1
rig --version    # 预期输出 0.3.1
rig daemon stop
rig daemon start
```

迁移 `040_workflow_specs_diagnostic` 会在升级后首次启动守护进程时自动应用。它是无破坏性的 `ALTER TABLE ADD COLUMN`，带安全默认值（既有行会追溯获得 `status: 'valid'`）。无需手动操作。

Claude 自动压缩策略：默认关闭、自愿启用。访问 `/settings/policies` 进行配置。适用于上下文耗尽反复成为运维问题的会话。启用前请先阅读 Settings UI 中的文档章节。

新的 `rig plugin` 呈现面：不安装插件就没有行为变化。内置的 `openrig-core` 插件随守护进程一同发布（11 个技能）。操作者可以按照各插件的 `OPENRIG-INSTALL.md` 工作流安装 `gstack`（45 个技能）或 `obra-superpowers`（14 个技能）。

## 已知限制

- **`rig down <name>` 仍返回 HTTP 404**——v0.3.1 中按名称拆除仍无法通过守护进程 down 路由解析。请改用 `rig down <rigId> --delete`。作为已知问题顺延至 v0.3.2。
- **`rig queue list --json --limit` 与 `rig view list/show --json` 标志不一致**——标志已搭好骨架但未完全接通。现阶段请使用人类可读输出。顺延至 v0.3.2。
- **Topology 移动端抽屉隐藏**——0.3.1 在 375px 视口下有意如此（点击汉堡按钮会触发一个既有的 `TopologyTableView` 渲染器级联）。计划在 0.3.2 通过专门的渲染路径切片完整恢复。
- **`ConceptCard` 组件保留在源码中**，但生产 For You 适配器不输出它。0.3.2 将做一个明确的数据源决策。
- **`/lab/*` 路由随生产构建发布**是遵创始人指示的有意行为；0.3.2 将加入索引页 + 每个 lab 的横幅 + manifest 模式。
- **插件安装人机工学**——v0 的插件安装由操作者复制或符号链接完成；一等公民的 `rig plugin install <substrate-path>` 推迟到 0.3.2。
- **生命周期分类**保持真实，但在部分恢复路径上仍依赖启发式方法，而非完善的提供商原生原语。
