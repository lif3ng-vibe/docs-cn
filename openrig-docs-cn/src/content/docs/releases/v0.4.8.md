## 摘要——权限姿态的快速跟进

启动姿态可配置，拒绝集合写在一个项目本地审批无法覆盖的层级，而危险操作由在当前运行框架（harness）下真正生效的显式前缀规则把关。

迁移仅增量。现有 v0.4.7 数据库在新守护进程上运行 `rig daemon start` 即可升级。

## 随版内容

### 可配置的启动姿态

硬编码的 `--permission-mode acceptEdits` 启动标志被一个可配置的姿态取代，默认为 `dontAsk`。这关闭了一类冻结场景：自治席位可能卡在一个模态权限提示上，而没有人代点。`dontAsk` 是默认值，因为它匹配自治席位实际能响应的东西；席位需要先前行为时仍可选 `acceptEdits`；刻意的 `bypassPermissions` 值在写入时原样保留。

### 项目本地审批覆盖不了的拒绝集合

姿态写入用户层的 `~/.claude/settings.json`，而非项目本地审批文件。其结果是：**拒绝在项目本地审批之上获胜**。写入是增量的（绝不对同级键做破坏），并把遗留的 `acceptEdits` 值前向迁移进新 schema。刻意的 `bypassPermissions` 值会被保留。

### 有界危险操作的拒绝集合

四个危险操作默认被把关：`git push`、`gh pr create`、`npm publish` 与 `rig down`。其中 `rig down` 尤其经由前缀规则 `Bash(rig down:*)` 把关——当前的 Claude 运行框架（2.1.220）只支持 Bash 规则上的前缀匹配，而仅含标志的模式被证明管不住 `rig down <rig> --force` 这类目标在前的形态，因此前缀规则是唯一真正成立的形态。裸 `rig down` 在 v0.4.8 中被把关；选择性许可（例如针对特定目标的 `rig down <rig>`）顺延到 v0.5.0 的服务器端强制。

### `rig up` 解除门控

上个版本对 `rig up` 的询问门被移除——`rig up` 是可逆操作，不值得设交互门。

### 权限策略基础（内置集随 v0.5.0 落地）

- **运行框架中立的策略 schema**。权限策略规格是一个运行框架中立的呈现面，`default_posture`、`floor` 与 `allow` / `ask` / `deny` 表达为**语义动作**（`push_to_remote`、`force_push`、`delete_files`、`read_secrets`、`create_pr`、`publish_package` 等），而非原始 shell 命令模式。
- **`rig setup --policy <name>`**——`rig setup` 上的一个新标志，把权限策略选择记录进既有的 rig 规格。接受内置名称或自定义策略文件的路径。**内置策略文件本身随 v0.5.0 落地**；v0.4.8 随版的是消费它们的框架。
- **两个呈现面**。**启动标志**呈现面（Claude `--permission-mode`、Codex 沙箱 / bypass 标志、Pi `--approve` / `--no-approve`）是稳定的，且由 OpenRig 代你设置——floor 与全绕过 YOLO 就住在这里。**配置文件**呈现面（Claude `~/.claude/settings.json`、Codex `config.toml`）是 allow/ask/deny 规则的居所；由于运行框架的规则语法跨版本频繁变化，该呈现面由一个智能体驱动的技能交互式施加（该技能随 v0.5.0 以 `applying-a-permission-policy` 落地）。

## 部署须知（操作者必读）

要让姿态写入触及席位，**守护进程的 `HOME` 必须等于席位的 tmux `HOME`**。这是 Claude 2.1.220 的 settings 路径不变量，对任何升级的远程主机环节至关重要：

- 在纯本地主机上，这通常自动满足。
- 在远程主机升级上，先把守护进程与 tmux 席位进程之间的 HOME 对等校验过，再认定升级完成。

（v0.5.0 将此作为 Codex `HOME` 分歧的已知问题记录；产品修复随 v0.5.1 发布。）

## 已作废方案

v0.4.8 的初次尝试（把 `dontAsk` 烘成**平台默认**而非 OpenRig 侧默认）在终审时被撤回；随版的 v0.4.8 是一个重定范围为 permission-agnostic 的基础，外加一套策略规格系统。被撤回尝试中的任何内容都没有随版。

## 行为与兼容性

- **迁移**——仅增量。现有 v0.4.7 数据库在新守护进程上运行 `rig daemon start` 即可升级。
- **默认启动姿态**——从硬编码的 `acceptEdits` 变为可配置、默认 `dontAsk`。席位需要先前行为时，显式选择 `acceptEdits`。
- **拒绝集合写入位置**——用户层 `~/.claude/settings.json`；拒绝集合在项目本地审批之上获胜。写入为增量式。
- **`rig up`**——不再被询问门把关；可逆操作不值得设交互门。
