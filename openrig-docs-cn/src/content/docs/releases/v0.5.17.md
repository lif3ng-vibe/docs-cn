版本 **0.5.17** 的变更内容。发布状态与日期记录在 [GitHub release](https://github.com/mvschwarz/openrig/releases/tag/v0.5.17) 与 npm 上。

OpenRig 0.5.17 现在既可以用 npm 安装，也可以用 Bun 安装。

## 使用 Bun 安装

```sh
bun add -g @openrig/cli
```

此前版本把尚未发布的 `@openrig/daemon` 包列为依赖。npm 会使用包内自带的副本，但 Bun 会到注册表中查找该依赖并以 404 失败。现在这个包改为导入它本就自带的守护进程副本，不再依赖 `@openrig/daemon`，这也让它变得更小。npm 安装方式不变。

OpenRig 仍然运行在 Node.js 上，因此也需要安装 Node.js 22。Bun 可能会阻止本包的 postinstall 脚本。此时 Node.js 版本与 SQLite 检查不会在安装时运行。参见 [OpenRig 会在你的机器上改动什么](https://github.com/mvschwarz/openrig/blob/main/README/#what-openrig-changes-on-your-machine)。

安装修复已用 Bun 1.4.0 与 npm 在 macOS arm64 搭配 Node.js 22 下验证。其他组合未经验证。

## 贡献者与收录的拉取请求

感谢 [@drewpayment](https://github.com/drewpayment) 在 [#66](https://github.com/mvschwarz/openrig/issues/66) 中报告 Bun 安装失败问题，该问题已在 [#68](https://github.com/mvschwarz/openrig/pull/68) 中修复。

Node 支持范围与 SQLite 版本不变。0.5.15 中提到的 macOS arm64 搭配 Node 24 的 SQLite 安装限制仍然适用；请在 macOS arm64 上使用 Node 22。
