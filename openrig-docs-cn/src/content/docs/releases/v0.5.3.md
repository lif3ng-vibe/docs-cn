## 摘要——"上下文发布"

**v0.5.3 让上下文上轨道**。按地址抽取已发布技能与库条目的精确小节，而不是通读整个文件。靠提问发现上下文，而不是靠猜路径。Refocus 自动解析 ref。交接会写入持久、带"被取代链"的席位复盘摘要，并随每一次恢复包（restore packet）送达。组合是按引用进行的，因此不存在会漂移的第二份副本。

**v0.5.3 完整包含 v0.5.2**。同一条血脉，毫无分歧。

无新增迁移。迁移头保持在 071（与 v0.5.2 一致）。v0.5.2→v0.5.3 升级无须应用任何内容。相较 v0.5.2，没有 CLI 命令或旗标被移除或更名。

## 发布内容

### 上下文的地址语法：`rig context get`（主打）

按地址抽取一个小节的精确字节：

```
rig context get <pack-ref>/<file>#<H2-slug>[/<H3-slug>]
```

`/<file>` 组件是必需的，即便包里只有一个文件。ref 是规范化的完整路径（如 `skills/<namespace>/<name>`）。错误的 slug 会响亮失败，并列出所有可寻址的小节。`rig context list` 枚举每个已发布条目的 ref 与名称；`rig context show` 查看其中一个。跨源访问（`seat:` / `mission:` 原子）是一种**撰写时**（authoring）的能力——在包清单中声明、并在组合期间通过 `rig context profile --rig/--seat/--mission` 授权——而不是传给 `get` 的临时参数。

### `openrig-skills` 路由器——提问 → ref → 装载

路由器传授这三步：先提问，再拿到一个 ref，然后按 ref 装载。当你不知道哪个技能或上下文适用，或冷启动后什么都没有投射出来时，就用它。

### 持久的席位复盘摘要——`rig context recap-write`

交接时刻、压缩边界，或任何继任者本会从滚动缓冲里重新推导你状态的时刻：`rig context recap-write` 会在 `LEARNED` 旁维护一个席位级的 `RECAP.md`，并带一条防碰撞的被取代链。恢复包现在携带一个指向已撰写复盘摘要的指针。

### Refocus 自动解析 ref

Refocus 钩子自动解析库 ref（ref 优先于文件），响亮失败但不阻塞，并送达指针。这是把运行中的席位指向新内容的正式发布通道。

### 按需取用有界的专长包

`rig context get` 按类路径的 ref 送达专长包，如 `skills/process/context-engineering`。旧的 `context-pack:` 冒号形式已被移除，CLI 也会明说。

**该包有一条注意事项**——它的标题"Traditional Context Engineering — 2024-2025 Snapshot"是有原因的：按创始人裁定，它属临时性、历史性、非规范性内容。一旦冲突，当前的 OpenRig 技能、明确的用户裁定与经过测量的实践都优先于它。

## 应停用的做法（0.5.2 下正确，如今错误）

1. **停止把库内容复制进席位或任务文件来组合上下文**。用 ref 组合：可寻址意味着不存在会漂移的第二份副本。没有任何机制能自动抓住复制件；按规则它仍是缺陷。
2. **停止把 `MODEL DIVERGENCE` 宣告当作别名噪音**。先规范化再比较的修复终结了 pinned=fable / effective=claude-fable-5 这一误报类，监视器现在按下抛出的席位逐个隔离。这一运行时上的宣告是一次真实的升级上报——请立即处理。
3. **停止把工具报错里的 "founder-gated" 解读成一堵权限墙**。夸大的措辞已从脚本中退役；这些守卫要求的是显式路径（如 `OPENRIG_SKILL_CANON_ROOT`），而不是许可。真正的创始人边界只有一条：push 与 PR。本地提交与普通的套用工作从不需要创始人点头。
4. **停止手工摆放证据，或把一份占位 PRD 当作证明契约**。`rig proof add` 把证据与契约配对，而一份原封未动的脚手架 PRD 永远不会静默变成那份契约：已撰写的 SPEC 即可充当契约，回显中的 `contractSource` 会告诉你绑定的是哪个来源。

## 已落地但尚不可驱动

Eval CASES 已随附（14 个选择/装载用例），但今天尚不存在可运行的评分通过。`--provider rig` 是实时的证明契约之门，且**尚未被驱动**——它自己会说明这一点，并重定向到 fake（把接线接通的工作属于进行中的收敛测试驱动器）。`--provider fake` 只回放通过 `--transcripts <map.json>` 提供的会话记录；未提供会话记录时每个用例都报错。当实时之门被驱动以后，下一个发布将把它提升为一项能力。

- **Eval 评分通过**——CASES 已随附；尚无可运行的评分通过。被驱动的 `--provider rig` 5.4 落地。
