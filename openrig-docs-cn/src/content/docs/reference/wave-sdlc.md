---
title: "wave SDLC——并行构建、wave 级评审、以组成作为用心拨盘"
---

这是 `sdlc-conventions.md` 组件菜单中一个可选的构建与评审模型。它是否适合这项工作，由 mission 归属人决定。该模型中的锁定戳是增量的（ADDITIVE）：批准只追加元数据，绝不改写成文的字节，因此候选版本的身份在其自己的批准之后依然成立。

## 模型一段话概述

切片在所有构建类席位上并行（IN PARALLEL）构建，各自处于一个不相交的文件领地（DISJOINT FILE TERRITORY），在候选版本带着构建者证明的回执冻结的那一刻，由唯一一名集成者串行合并。独立评审每个 wave 进行一次（ONCE PER WAVE），覆盖该 wave 累积的全部范围——两名视角不同的评审者（理想情况下运行时也不同），绝不是作者本人——他们的发现驱动修复轮，修复轮在当轮最终修订上重新赢得两项裁决。检查保持逐切片（失败测试优先的证明、按效果验证、诚实的回执）；轮次按 wave 进行。

## 机制

1. **PLAN（计划）**：wave 条目写入记录在案的计划；规划者塑造规格；计划权威锁定它们。每个切片都要有一个真实的工作区，否则证明无处安放。
2. **DISPATCH（派发）**：接力棒带着独占的文件领地展开。简报就是单位：每份指派都携带目标、验收标准、完整的上下文路由（确切路径）、领地——以及这项常设授权："自己驾驭实现：推导你需要的，做调研，派出读者，自行决定构建顺序。卡住就问；编排者在这里提供帮助。"默认范围是整份规格，在一次持续的运行中构建到唯一一个冻结的候选。派发任何更小的块，都必须在简报本身上写明理由（一个未决的决策、一个活跃的领地冲突、一个真正的岔路风险）——没有解释的小块是派发缺陷。
   领地重叠 = 串行化。构建中途发现冲突 = 停下来裁决。
   为什么：构建者握着规格与代码；关于如何构建的决策属于构建上下文所在之处。详细的顺序指令在模型弱小的年代是脚手架；今天它们是牢笼，逐命令路由是失败模式，不是勤奋。
   简报是地图，不是领地。蒸馏是受欢迎的——对一个极小切片，简报确实可能比规格更丰富——但它绝不是接收者的唯一上下文：构建者的第一个动作是按路由出的阅读清单自我上手（slice 尺度的 mission-install 模式），然后对照自己实际立足的地面检查地图。没有人比构建者更了解一楼；广角镜在上一层。当地面与地图不一致时，那是一个要提出来的发现——而不是跟着地图走向悬崖的理由。
3. **BUILD（构建）**：针对一个洁净基线、以已提交的最终测试字节做失败测试优先；冻结单一候选修订；回执引用最终修订（任何 rebase 之后重新赢得）。
4. **MERGE（合并）**：仅限集成者，串行进行，每次都在源头验证（候选的父提交等于合并前顶端；变更文件等于声明的领地）。合并公告是每个未结候选的 REBASE 触发器。
5. **WAVE REVIEW（wave 评审）**：wave 的构建完成时触发。两名独立评审者，以顶端为基（base-scoped 的评审范围），作者被排除在评审自己的工作之外。两道门问的是不同的问题——结构是否站得住，对比每项主张是否经得起与源头的接触。这是设计，不是冗余。
   评审者还要评审漂移（DRIFT），而不只是缺陷：构建出的东西是否仍符合简报所述的验收标准——这还是归属人要的那个狗窝吗，还是每一步都情有可原的小让步累积出了一座月球基地？剧情丢失（plot-loss）是与逻辑缺陷同级的一等发现。
   评审还要按成因处置每一个失手：CONTEXT-GAP——规格或其路由缺少当时所需的东西（规划发现；修复落进规格）——对比 JUDGMENT-GAP——上下文就在那里而判断错了（构建者发现；修复是一道检查）。在裁决工件里写一个词即可。这样产生的比率，就是派发形态据以调校的校准。
6. **FIX ROUNDS（修复轮）**：发现变成前向修复候选（合并成立；已合并不等于在运行）。每轮一次复审，在最终修订上重新赢得两条腿。窄修复用窄复检。
7. **SEAL（封存）**：两条腿在同一修订上清白 = wave 封存；下一个槽位开启。

## wave 就是用心拨盘

wave 的组成（COMPOSITION）是一件工作被多用心对待的控制面：一个大而复杂或承重的切片独享一个 wave（它的评审仪式只为它触发）；一件大工作甚至可以拆分到多个 wave。这解耦了旧模型混为一谈的东西：mission 与 slice 工作区保持为灵活的组织容器；wave 是单独的一层，负责排序工作、指派工作，并为它的处理用心程度定价。用心是逐件工作的属性，绝不是逐 mission 的属性。

## 何时使用

许多中小型、找到根因、有证据支撑的切片；足以并行化的席位；能干净划分的领地；一名能串行合并并快速验证的集成者。

## 何时不使用

设计不确定或共享区域的工作（单切片、经典两腿评审、或先开一场设计会）。一小时内不可逆的任何事情（发布、切换、破坏性操作）——那是重流程。以及在没有独立的非写入评审者时：任何事情都不自我评审；没有他们，wave 门就是演戏。

## 失败模式与缓解

- **冻结-合并竞态**：候选在合并移动顶端之前几秒冻结。缓解：在隔离 worktree 中以内容身份证明（稳定 patch-id）做零重叠重堆叠；构建者侧在合并公告时自行捕获。
- **证据表演**：因错误原因而失败的测试，读起来与真实失败一模一样。缓解：评审者独立重新推导失败；错误的定性退入更正历史，绝不静默改写。
- **只测存在不测缺席的测试**：断言真行存在，而假行仍在打印。规则：在每一种编码中都钉死假主张的缺席。
- **幽灵检出状态**：按引用合并会让共享检出的索引过时。绝不从共享检出构建或提交；在围栏处同步其索引。
