---
title: "发布边界——每次围栏执行一次的整理工作"
---

这是一份判断指南清单，而非门禁清单：每一项都写明缘由，多数项只是一个动作，凡属情境性的内容在下一次边界即告失效。每次发布围栏运行一次，在上一次发布的仪式完成之后进行。由项目归属人与席位归属人挑选适用的动作，并在边界记录中保存其理由。

## 1. 席位——重置或重新灌注，视各席位的连续性需要

- **逐席位与其归属人商定连续性方案**。全新启动、托管压缩加重新灌注（re-prime）、或保留当前会话，三者各服务于不同需要。仅凭角色名称不足以做出选择。记录所选方案、理由以及未竟工作的保管安排；选定某个流程本身并不授权任何生命周期操作。
- **全新启动**可以清空累积的上下文，并载入当前的启动引导。在获授权退出之前，先保存该席位积累的知识与延续材料（凡预置了 recap 之处，先做 recap）；再核实新占用者的真实身份与安装情况。
- **托管压缩加重新灌注**可以在恢复下一阶段所需上下文的同时保留规划上的连续性。**保留当前会话**则可以延续进行中的保管。无论哪种情况，都要检查哪些引导已经过时，并交付所选定的当前上下文；在磁盘上修改并不等于把内容交付到会话。
- **重新灌注 = 世界走读 + 当前能力增量 + 任务安装**，遵循任务安装（mission install）约定（`docs/reference/mission-install.md`）：世界这一半恢复"你身在何处"；项目这一半（五个层次、两种深度档位、有节奏的指针走读）恢复"你在做什么"。由具名工件组合而成，来源优先级因此保持可见。
- **仪式本身就是实验**。上述每个动作都运行在产品自身的原语之上，因此仪式同时也是对它们的实测。被动观察：每个重新灌注过的席位在最初几个自然回合里用到了什么，什么坏了？发现写入边界记录旁一份带日期的观察文件。

## 2. 记忆——只蒸馏，绝不累积

- 逐席位的学习文件：过一遍蒸馏。取舍检验："它最近是否改变过某个决策？"改变过的留下；其余移入同一文件内带日期的归档章节。学习文件一旦上量，便不再起约束作用，而是开始充当辩解。
- 任何共享的智能体记忆：同样过一遍、同样检验；被本版发布证伪的条目即行退役。
- 已完结发布的任务笔记：封存为记录，不带分毫。新任务从轻起步。规则不迁移；需求经由计划迁移。

## 3. 队列——按目的地清扫，每条都有处置

- 每个席位都清扫自己 DESTINATION 里的未结行（唤醒并不可靠；清扫本身就是读取）。已完结发布留下的每一条未结行，必须且只能归入三者之一：done-with-receipt · carried-to-the-new-mission（按新计划重新归档，绝不原样硬拖）· closed-superseded。清扫能暴露出被漏掉的唤醒或记忆中过时的工作清单所掩盖的待办义务。
- 核实每一份结项文书（closing paper）的继承都有一个在册的接收行并有归属人。零孤儿。

## 4. 基座——把拆除当作独立的原子

- 保留当前发布与紧邻的上一个发布。在发布 N 的边界上，N-2 及更早的 worktree 与其他按发布划定范围的基座进入可清理范围。可清理不等于可以丢弃仅存的脏字节：先归档或以其他方式处置。辨识在用的 `main` 与运行时状态时，依据其真实的 ref 与身份，绝不依据过时的目录名。
- 修剪 worktree；移除会话级临时树；核实已合并的分支确已删除（合并回执即授权）。
- 临时目录中的暂存主目录（scratch homes）与场景根目录（scenario roots）：一律清扫。
- 运行时安装：保留 LIVE 与 LAST-KNOWN-GOOD；归档热修复链；处置启动器备份。
- 发布中途的 vendored 文件备份，待包含真正修复的发布上线后移除。
- 已拆除拓扑的快照：每条一行编入索引，或删除。

## 5. 仪器与看板

- 已完结发布的跟踪与规划看板：作为记录冻结，并如此加注标签。新任务启用全新看板——markdown 为唯一事实来源，看板由其派生。
- 冻结的评审标准：与其证据一并归档，标注"可用、未削弱、非门禁"。
- 在任务开始时采集一份干净环境（clean-box）基线回执（负载、进程数、健康检查尾延迟）——下一个性能问题值得有一份"之前"作对照。

## 6. 能力增量的生命周期（常设法则）

每个发布的能力增量都在围栏处撰写并绑定到确切的候选版本，随后与已发布的定版（cut）对账。其基线是正典（canon）实际吸收的最后一个标记，而不是假定紧邻的上一个 semver 已被吸收。当正典落后时，新增量是对其间每个增量的累积综合，保留取代与转向关系，而不是把旧文段串接起来。

正典吸收经保留的公共产品事实。增量过期要求两个条件同时成立：正典头部点名了那个确切的增量，并且确实存在一个不同的后继增量文件。仅有头部不会使其过期；缺失或不可读的输入保持未知/在效。在真正的边界上，先核实事件再记录过期，然后停止引用已过期的增量。不要为了让条件成真而制造后继。候选版本被吸收并不能证明已发布，也不能证明生产侧已经采用。

私有项目拓扑、宿主实践与发布归属进入版本化的项目世界，而不泄漏进公共包。新发布的增量义务从它自己的定版开始。

## 7. 世界吸收与可发现性

- 每一个变化的能力都配一张小地图：**用户情境 · 当前能力 · 权威来源 · 自然的首次产品相遇 · 耐久的上下文归所 · 干净智能体探测**。已经好用的路线，记录下来后就不再去动。
- 优先从现成的 `--help`、报错、命令输出、实时状态、上下文目录、工作安装或技能路由器获取随需即得的事实。世界安装提供广度与本体（ontology）；它不应去复制实时呈现面自己就能推导出的确切事实。
- 发布任务在可能时应在其定版之前主持这项评审，使公共世界/帮助的变化随能力一同发布。本边界核实打包后的确切结果，把任何遗漏的吸收作为显式欠账修复，吸收私有项目事实，重新灌注，并观察一个只装了世界、未经点名的干净智能体能否从自身情境出发找到该能力。
- 路线缺失本身就是一个发布发现。要么修复既存的最小接缝，要么把有证据的缺口存入可推导上下文任务；不要在边界上再造第二套能力注册表、搜索服务或世界存储。

## 8. 边界上刻意不做的事

- 不做流程迁移：情境性规则在围栏处即已过期。常备语料只有那四条检查原则——以效果验证 · 证据取自源头 · 诚实的裁决，包括对自己也不例外 · 绝不捏造。
- 不重新争讼已完结发布的裁决；封存的文书即是记录。
- 本清单不加条目，除非附有一个真实发生过的样本。
