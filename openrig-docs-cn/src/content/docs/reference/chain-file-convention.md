title: "链文件约定（CE-v2）"

**本文件是链文件的单一事实来源**（SSOT）：链文件如何命名、每个层级承载什么、叶到根的追溯如何解析，均以此为准。两棵树的遍历器（walker）都消费此处定义的路径。若遍历器与本文件相悖，则二者之一必有缺陷——上报它；不要分叉这套约定。

## 唯一的规则

**文件名唯一，在树的每个层级完全相同**。读者通过从自己站立之处向根方向行走来定位，逐层读取同名文件。没有需要追随的指针，没有分支，也没有逐层各异的命名。发明一个层级专属的名字会破坏每一个遍历器。

链文件位于**节点**上——实例、rig、工作舱（pod）、席位；任务（mission）、切片——绝不位于架子上（`rigs/`、`seats/`、`missions/` 是容纳关系而非节点，不承载链文件）。

## 两棵树，两个问题

| 树 | 路径形态 | 承载内容 | 是否随附分发 |
|---|---|---|---|
| **拓扑树** | instance → rig → pod → seat | 这里的事情怎么做 | **是**——普遍适用的默认值随源码分发 |
| **项目树** | project → mission → slice | 正在构建什么 | **否**——取决于用户构建什么；见下文 |

### 拓扑树

根植于带类型的配置键 **`topology.root`**（解析顺序：`env OPENRIG_TOPOLOGY_ROOT > config file > derived default $OPENRIG_HOME/topology`）。永远不要硬编码这条路径——`rig config get topology.root` 在任何机器上都是标准答案。实例层级**就是根的顶端**（没有可供寻找的实例目录；根即实例）：

```
<topology.root>/<NAME>.md                         # instance altitude
<topology.root>/rigs/<rig>/<NAME>.md              # rig altitude
<topology.root>/rigs/<rig>/pods/<pod>/<NAME>.md   # pod altitude
<topology.root>/rigs/<rig>/seats/<seat>/<NAME>.md # seat altitude
```

引擎在物化拓扑时会创建实例根、rig 目录以及每个已声明的工作舱目录，即使尚不存在任何手写的链文件默认值。工作舱上下文仍是可选的：只有单一上下文域内共享的知识才使用该层级。跨工作舱的指引仍属于 rig 层级。

拓扑树上已确立的链文件名：

- `LEARNED.md`——一个位置（POSITION）学到的东西；绝不按原样共享或随附分发。一个席位的 LEARNED 由其路径（PATH）标识：两个 rig 中的同名席位是两个不同的文件。
- `CULTURE.md`——启动时分层注入成员的规范。

### 项目树

根植于工作区配置键（`workspace.root`、`workspace.slices_root`）。此处的链文件名：`SPEC.md`（frontmatter 中的意图沿链向上组合；规格说明是叶子属性）、`PROOF.md`、`PROGRESS.md`。

**项目树上下文无法随附分发**。它描述的是*你*正在构建什么——任务意图、切片规格、证明契约。任何厂商都无法预先代写，而分发一份默认值等于把别人的项目安装成你的上下文。演示项目附带一个可供抄写的完整示例；真实项目则自己编写。（拓扑树上下文正相反：一支智能体团队如何良好运转，很大程度上是普遍的，这正是内置 rig 随附默认值的原因。）

## 旧位置与提示性告警（advisory）

在此约定之前，拓扑树位于 `~/.openrig/shared-docs/rigs/`（2026-08-14 的设计决定：某台机器上的一个任意文件夹，不是产品路径）。该位置**仍保持可读**，作为逐层回退，让现有 rig 得以迁移而非崩坏——但每一次解析到该处的读取都会发出一条具名提示性告警（`legacy-topology-read: …`），说明旧来源、`topology.root` 下的规范目的地以及配置键。一次静默的旧位置读取即是缺陷。旧路径字面量在每个 settings twin 中只存在于一个辅助函数里（`resolveLegacyTopologyRigsRoot`）；遍历器导入它，自身不携带任何路径字面量。

## 追溯（trace）

`rig context trace --rig <rig> [--pod <pod>] [--seat <seat>] --name <NAME>.md` 执行这次行走：按根在前的顺序（一般 → 具体）打印每个被选中的层级，标注内容来自 `topology.root`、旧树（提示性告警走 stderr）抑或不存在，且不需要守护进程在运行——需要定位方向之时，恰恰可能是守护进程宕掉之时。既有的 rig/席位追溯仍然有效；选择 `--pod` 会在其间加入该上下文域。`--json` 返回结构化结果。

你的读取本身就是这次行走：凭记忆拼出的追溯是一场复述，恰好复现它本要捕获的漂移。去运行它，不要凭回忆。

## 随附默认值与策展路径

内置 rig（产品团队优先）在适用的实例、rig、工作舱与席位层级随附合理默认值的链文件，在 rig-up 时安装到 `topology.root` 之下。
随附默认值是一个**起点**，由占用团队在其上追加——后续的 rig-up 绝不会覆盖它（已有文件获胜）。

把发现的最佳实践加入随附默认值被刻意设计得很轻量：

1. **发现**——实践出现在它被验证之处：某个席位的 `LEARNED.md`、一条现场笔记、一条评审观察。
2. **策展**——由人判断它是否*普遍适用*（换一台陌生机器、换一个项目，它还成立吗？）。若它是项目特定的，就留在赢得它的那个层级。
3. **分发**——把它加进源代码中该 rig 的默认链文件（`packages/daemon/specs/rigs/…/topology/`），并用一行写明促成此事的事故。它在下个发布抵达新安装；运行中的 rig 只能通过显式交付获得（见 refocus 通道）——**编辑文件不等于交付到运行中的席位**。

## 本文件不覆盖的内容

链文件如何抵达一个运行中（RUNNING）的席位（即 refocus 通道）由 refocus 文档规定；工作本身的质量标准存放在该 rig 的 operating-model skill 与文化文件中。
