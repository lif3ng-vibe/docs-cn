# Next.js App Router 快速上手

AI SDK 是一个功能强大的 TypeScript 库，旨在帮助开发者构建 AI 驱动的应用。

在这个快速上手教程中，你将构建一个带有流式聊天界面的简单智能体（agent）。在此过程中，你会学到在自己的项目中使用 AI SDK 所需的关键概念与技术。

如果你不熟悉[提示词工程（Prompt Engineering）](/docs/advanced/prompt-engineering)和 [HTTP 流式传输](/docs/foundations/streaming)的概念，可以选择先阅读这两篇文档。

## 前置条件

要跟随本快速上手教程，你需要：

- 本地开发机器上安装了 Node.js 22+ 和 pnpm。
- 一个 [ Vercel AI Gateway ](https://vercel.com/ai-gateway) API 密钥。

如果你还没有获取 Vercel AI Gateway API 密钥，可以在 Vercel 网站上[注册](https://vercel.com/d?to=%2F%5Bteam%5D%2F%7E%2Fai&title=Go+to+AI+Gateway)获取。

## 创建 Route Handler

创建一个 Route Handler `app/api/chat/route.ts`，并添加以下代码：

```tsx filename="app/api/chat/route.ts"
import {
  streamText,
  UIMessage,
  convertToModelMessages,
  createUIMessageStreamResponse,
  toUIMessageStream,
} from 'ai';
__PROVIDER_IMPORT__;

export async function POST(req: Request) {
  const { messages }: { messages: UIMessage[] } = await req.json();

  const result = streamText({
    model: __MODEL__,
    messages: await convertToModelMessages(messages),
  });

  return createUIMessageStreamResponse({
    stream: toUIMessageStream({ stream: result.stream }),
  });
}
```

我们来看看这段代码中发生了什么：

1. 定义一个异步的 `POST` 请求处理器，并从请求体中提取 `messages`。`messages` 变量包含你与聊天机器人之间的对话历史，为聊天机器人提供进行下一次生成所需的上下文。`messages` 是 UIMessage 类型，专为应用 UI 设计——它们包含完整的消息历史以及时间戳等相关元数据。
2. 调用从 `ai` 软件包导入的 [`streamText`](/docs/reference/ai-sdk-core/stream-text)。该函数接受一个配置对象，其中包含 `model` 提供商和 `messages`（在步骤 1 中定义）。你还可以传入其他[设置](/docs/ai-sdk-core/settings)来进一步自定义模型的行为。`messages` 键期望一个 `ModelMessage[]` 数组。该类型与 `UIMessage` 的不同之处在于，它不包含时间戳、发送方信息等元数据。为了在这两种类型之间进行转换，我们使用 `convertToModelMessages` 函数，它会剥离 UI 特有的元数据，将 `UIMessage[]` 数组转换为模型期望的 `ModelMessage[]` 格式。
3. `streamText` 函数返回一个 [`StreamTextResult`](/docs/reference/ai-sdk-core/stream-text#result-object)。将其 `stream` 传给 `toUIMessageStream`，并用 `createUIMessageStreamResponse` 返回它，以创建一个流式响应对象。
4. 最后，将结果返回给客户端，以流式传输响应。

这个 Route Handler 会在 `/api/chat` 处创建一个 POST 请求端点。

## 构建 UI

现在你已经有了一个可以查询 LLM 的 Route Handler，接下来搭建前端。AI SDK 的 [ UI ](/docs/ai-sdk-ui) 软件包将聊天界面的复杂性抽象为一个 Hook：[`useChat`](/docs/reference/ai-sdk-ui/use-chat)。

用以下代码更新你的根页面（`app/page.tsx`），以显示聊天消息列表并提供用户消息输入框：

```tsx filename="app/page.tsx"
'use client';

import { useChat } from '@ai-sdk/react';
import { useState } from 'react';

export default function Chat() {
  const [input, setInput] = useState('');
  const { messages, sendMessage } = useChat();
  return (
    <div className="flex flex-col w-full max-w-md py-24 mx-auto stretch">
      {messages.map(message => (
        <div key={message.id} className="whitespace-pre-wrap">
          {message.role === 'user' ? 'User: ' : 'AI: '}
          {message.parts.map((part, i) => {
            switch (part.type) {
              case 'text':
                return <div key={`${message.id}-${i}`}>{part.text}</div>;
            }
          })}
        </div>
      ))}

      <form
        onSubmit={e => {
          e.preventDefault();
          sendMessage({ text: input });
          setInput('');
        }}
      >
        <input
          className="fixed dark:bg-zinc-900 bottom-0 w-full max-w-md p-2 mb-8 border border-zinc-300 dark:border-zinc-800 rounded shadow-xl"
          value={input}
          placeholder="Say something..."
          onChange={e => setInput(e.currentTarget.value)}
        />
      </form>
    </div>
  );
}
```

<Note>
  确保在文件顶部添加 `"use client"` 指令。
  这样你才能使用 JavaScript 添加交互性。
</Note>

这个页面使用了 `useChat` Hook，默认会调用你之前创建的 `POST` API 路由（`/api/chat`）。该 Hook 提供了处理用户输入和表单提交的函数与状态。`useChat` Hook 提供了多个工具函数和状态变量：

- `messages` - 当前的聊天消息（一个包含 `id`、`role` 和 `parts` 属性的对象数组）。
- `sendMessage` - 一个用于向聊天 API 发送消息的函数。

该组件使用本地状态（`useState`）管理输入框的值，并通过调用 `sendMessage` 传入输入文本来处理表单提交，随后清空输入框。

LLM 的响应通过消息的 `parts` 数组访问。每条消息包含一个有序的 `parts` 数组，表示模型在响应中生成的一切内容。这些部分可以包括纯文本、推理（reasoning）token 以及你稍后会看到的更多内容。`parts` 数组保留了模型输出的先后顺序，让你可以按生成顺序显示或处理每个部分。

## 用工具增强聊天机器人

虽然大语言模型（LLM）拥有强大的生成能力，但它们在离散任务（例如数学运算）和与外部世界交互（例如获取天气信息）方面表现不佳。这正是[工具](/docs/ai-sdk-core/tools-and-tool-calling)的用武之地。

工具是 LLM 可以调用的操作。这些操作的结果可以反馈给 LLM，供其在下一个响应中加以考虑。

例如，如果用户询问当前天气，在没有工具的情况下，模型只能基于训练数据提供一般性信息。但有了天气工具，它就可以获取并提供最新的、针对特定位置的天气信息。

让我们通过添加一个简单的天气工具来增强你的聊天机器人。

### 更新你的 Route Handler

修改你的 `app/api/chat/route.ts` 文件，加入新的天气工具：

```tsx filename="app/api/chat/route.ts" highlight="1-8,18-32"
import {
  streamText,
  UIMessage,
  convertToModelMessages,
  tool,
  createUIMessageStreamResponse,
  toUIMessageStream,
} from 'ai';
__PROVIDER_IMPORT__;
import { z } from 'zod';

export async function POST(req: Request) {
  const { messages }: { messages: UIMessage[] } = await req.json();

  const result = streamText({
    model: __MODEL__,
    messages: await convertToModelMessages(messages),
    tools: {
      weather: tool({
        description: 'Get the weather in a location (fahrenheit)',
        inputSchema: z.object({
          location: z.string().describe('The location to get the weather for'),
        }),
        execute: async ({ location }) => {
          const temperature = Math.round(Math.random() * (90 - 32) + 32);
          return {
            location,
            temperature,
          };
        },
      }),
    },
  });

  return createUIMessageStreamResponse({
    stream: toUIMessageStream({ stream: result.stream }),
  });
}
```

在这段更新后的代码中：

1. 你从 `ai` 软件包导入了 `tool` 函数，并从 `zod` 导入了 `z`，用于 schema 校验。
2. 你定义了一个包含 `weather` 工具的 `tools` 对象。该工具：
   - 具有描述信息，帮助模型理解何时使用它。
   - 使用 Zod schema 定义了 `inputSchema`，指定执行该工具需要一个 `location` 字符串。模型会尝试从对话上下文中提取该输入；如果无法提取，它会向用户询问缺失的信息。
   - 定义了一个 `execute` 函数，用于模拟获取天气数据（这里返回一个随机温度）。这是一个在服务器上运行的异步函数，因此你可以从外部 API 获取真实数据。

现在你的聊天机器人可以"获取"用户所询问的任何位置的天气信息了。当模型判断需要使用天气工具时，它会生成一个包含必要输入的工具调用。随后 `execute` 函数会自动运行，工具输出将作为 `tool` 消息添加到 `messages` 中。

试着输入类似"纽约的天气怎么样？"的问题，看看模型如何使用这个新工具。

注意到 UI 中的空白响应了吗？这是因为模型没有生成文本响应，而是生成了一个工具调用。你可以通过 `message.parts` 数组中的 `tool-weather` 部分，在客户端访问该工具调用及随后的工具结果。

<Note>
  工具部分的名称始终为 `tool-{toolName}`，其中 `{toolName}` 是你定义
  工具时使用的键。在本例中，由于我们把工具定义为 `weather`，
  因此该部分的类型是 `tool-weather`。
</Note>

## 启用多步工具调用

你可能已经注意到，虽然工具现在已在聊天界面中可见，但模型并没有使用这些信息来回答你最初的问题。这是因为模型一旦生成了工具调用，从技术上讲它就已经完成了本次生成。

为了解决这个问题，你可以使用 `stopWhen` 启用多步工具调用。默认情况下，`stopWhen` 被设置为 `isStepCount(1)`，即在有工具结果时，第一步之后生成就停止。通过修改这个条件，你可以让模型自动将工具结果回传给自己，以触发后续生成，直到满足你指定的停止条件。在本例中，你希望模型继续生成，以便利用天气工具的结果来回答你最初的问题。

### 更新你的 Route Handler

修改你的 `app/api/chat/route.ts` 文件，加入 `stopWhen` 条件：

```tsx filename="app/api/chat/route.ts" highlight="19"
import {
  streamText,
  UIMessage,
  convertToModelMessages,
  tool,
  isStepCount,
  createUIMessageStreamResponse,
  toUIMessageStream,
} from 'ai';
__PROVIDER_IMPORT__;
import { z } from 'zod';

export async function POST(req: Request) {
  const { messages }: { messages: UIMessage[] } = await req.json();

  const result = streamText({
    model: __MODEL__,
    messages: await convertToModelMessages(messages),
    stopWhen: isStepCount(5),
    tools: {
      weather: tool({
        description: 'Get the weather in a location (fahrenheit)',
        inputSchema: z.object({
          location: z.string().describe('The location to get the weather for'),
        }),
        execute: async ({ location }) => {
          const temperature = Math.round(Math.random() * (90 - 32) + 32);
          return {
            location,
            temperature,
          };
        },
      }),
    },
    onStepEnd: ({ toolResults }) => {
      console.log(toolResults);
    },
  });

  return createUIMessageStreamResponse({
    stream: toUIMessageStream({ stream: result.stream }),
  });
}
```

在这段更新后的代码中：

1. 你将 `stopWhen` 设置为 `isStepCount` 达到 5 时停止，允许模型在一次生成中最多使用 5 个"步骤"。
2. 你添加了一个 `onStepEnd` 回调，用于记录交互中每个步骤产生的 `toolResults`，帮助你了解模型的工具使用情况。

回到浏览器，询问某个位置的天气。你现在应该会看到模型使用天气工具的结果来回答你的问题。

通过设置 `stopWhen: isStepCount(5)`，你允许模型在一次生成中最多使用 5 个"步骤"。这支持更复杂的交互，并允许模型在需要时跨多个步骤收集和处理信息。你可以通过添加另一个将温度从摄氏度转换为华氏度的工具来实际看看这一机制。

### 添加另一个工具

更新你的 `app/api/chat/route.ts` 文件，添加一个将温度从华氏度转换为摄氏度的新工具：

```tsx filename="app/api/chat/route.ts" highlight="34-47"
import {
  streamText,
  UIMessage,
  convertToModelMessages,
  tool,
  isStepCount,
  createUIMessageStreamResponse,
  toUIMessageStream,
} from 'ai';
__PROVIDER_IMPORT__;
import { z } from 'zod';

export async function POST(req: Request) {
  const { messages }: { messages: UIMessage[] } = await req.json();

  const result = streamText({
    model: __MODEL__,
    messages: await convertToModelMessages(messages),
    stopWhen: isStepCount(5),
    tools: {
      weather: tool({
        description: 'Get the weather in a location (fahrenheit)',
        inputSchema: z.object({
          location: z.string().describe('The location to get the weather for'),
        }),
        execute: async ({ location }) => {
          const temperature = Math.round(Math.random() * (90 - 32) + 32);
          return {
            location,
            temperature,
          };
        },
      }),
      convertFahrenheitToCelsius: tool({
        description: 'Convert a temperature in fahrenheit to celsius',
        inputSchema: z.object({
          temperature: z
            .number()
            .describe('The temperature in fahrenheit to convert'),
        }),
        execute: async ({ temperature }) => {
          const celsius = Math.round((temperature - 32) * (5 / 9));
          return {
            celsius,
          };
        },
      }),
    },
  });

  return createUIMessageStreamResponse({
    stream: toUIMessageStream({ stream: result.stream }),
  });
}
```

现在，当你询问"纽约的气温是多少摄氏度？"时，你应该会看到一个更完整的交互过程：

1. 模型将调用天气工具查询纽约。
2. 工具输出会显示出来。
3. 然后，它会调用温度转换工具，将温度从华氏度转换为摄氏度。
4. 模型随后会利用这些信息，给出关于纽约天气的自然语言回复。

这种多步方式让模型能够收集信息并用它提供更准确、更贴合上下文的回复，使你的聊天机器人更加实用。

这个简单的例子展示了工具如何扩展模型的能力。你可以创建更复杂的工具，与真实 API、数据库或任何其他外部系统集成，让模型能够实时访问和处理现实世界的数据。工具弥合了模型知识截止时间与最新信息之间的差距。
