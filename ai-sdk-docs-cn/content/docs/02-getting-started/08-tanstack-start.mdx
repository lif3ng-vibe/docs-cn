# TanStack Start 快速上手

AI SDK 是一个功能强大的 TypeScript 库，旨在帮助开发者构建 AI 驱动的应用程序。

在这个快速上手教程中，你将构建一个带有流式聊天界面的简单智能体（agent）。在此过程中，你将学习在自己的项目中使用 AI SDK 的一系列关键概念与技术。

如果你不熟悉[提示词工程（Prompt Engineering）](/docs/advanced/prompt-engineering)和 [HTTP 流式传输](/docs/foundations/streaming)的概念，可以先选择阅读这两篇文档。

## 前置条件

要完成本快速上手教程，你需要：

- 本地开发机器上已安装 Node.js 22+ 和 pnpm。
- 一个 [ Vercel AI Gateway ](https://vercel.com/ai-gateway) API 密钥。

如果你尚未获取 Vercel AI Gateway API 密钥，可以在 Vercel 网站上[注册](https://vercel.com/d?to=%2F%5Bteam%5D%2F%7E%2Fai&title=Go+to+AI+Gateway)获取。

## 创建 Route Handler

创建一个 Route Handler `src/routes/api/chat.ts`，并添加以下代码：

```tsx filename="src/routes/api/chat.ts"
import {
  streamText,
  UIMessage,
  convertToModelMessages,
  createUIMessageStreamResponse,
  toUIMessageStream,
} from 'ai';
__PROVIDER_IMPORT__;
import { createFileRoute } from '@tanstack/react-router';

export const Route = createFileRoute('/api/chat')({
  server: {
    handlers: {
      POST: async ({ request }) => {
        const { messages }: { messages: UIMessage[] } = await request.json();

        const result = streamText({
          model: __MODEL__,
          messages: await convertToModelMessages(messages),
        });

        return createUIMessageStreamResponse({
          stream: toUIMessageStream({ stream: result.stream }),
        });
      },
    },
  },
});
```

我们来看看这段代码中发生了什么：

1. 使用 TanStack Start 的服务器路由定义一个异步 `POST` 请求处理器，并从请求体中提取 `messages`。`messages` 变量包含你与聊天机器人之间的对话历史，为聊天机器人的下一次生成提供必要的上下文。`messages` 的类型是 UIMessage，专为应用 UI 设计——它们包含完整的消息历史以及时间戳等相关元数据。
2. 调用从 `ai` 包导入的 [`streamText`](/docs/reference/ai-sdk-core/stream-text)。该函数接受一个配置对象，其中包含 `model` 提供商和 `messages`（在第 1 步中定义）。你可以传入更多[设置](/docs/ai-sdk-core/settings)来进一步自定义模型的行为。`messages` 键期望一个 `ModelMessage[]` 数组。该类型与 `UIMessage` 的区别在于它不包含时间戳或发送者信息等元数据。为了在这两种类型之间转换，我们使用 `convertToModelMessages` 函数，它会剥离 UI 特有的元数据，并将 `UIMessage[]` 数组转换为模型期望的 `ModelMessage[]` 格式。
3. `streamText` 函数返回一个 [`StreamTextResult`](/docs/reference/ai-sdk-core/stream-text#result-object)。将其 `stream` 传给 `toUIMessageStream`，并用 `createUIMessageStreamResponse` 返回它，以创建一个流式响应对象。
4. 最后，将结果返回给客户端以流式传输响应。

该 Route Handler 在 `/api/chat` 处创建了一个 POST 请求端点。

## 搭建 UI

既然你已经拥有一个可以查询 LLM 的 Route Handler，现在该搭建前端了。AI SDK 的 [UI](/docs/ai-sdk-ui) 包将聊天界面的复杂性抽象为一个 Hook——[`useChat`](/docs/reference/ai-sdk-ui/use-chat)。

用以下代码更新你的 index 路由（`src/routes/index.tsx`），以显示聊天消息列表并提供用户消息输入框：

```tsx filename="src/routes/index.tsx"
import { createFileRoute } from '@tanstack/react-router';
import { useChat } from '@ai-sdk/react';
import { useState } from 'react';

export const Route = createFileRoute('/')({
  component: Chat,
});

function Chat() {
  const [input, setInput] = useState('');
  const { messages, sendMessage } = useChat();
  return (
    <div className="flex flex-col w-full max-w-md py-24 mx-auto stretch">
      {messages.map(message => (
        <div key={message.id} className="whitespace-pre-wrap">
          {message.role === 'user' ? 'User: ' : 'AI: '}
          {message.parts.map((part, i) => {
            switch (part.type) {
              case 'text':
                return <div key={`${message.id}-${i}`}>{part.text}</div>;
            }
          })}
        </div>
      ))}

      <form
        onSubmit={e => {
          e.preventDefault();
          sendMessage({ text: input });
          setInput('');
        }}
      >
        <input
          className="fixed dark:bg-zinc-900 bottom-0 w-full max-w-md p-2 mb-8 border border-zinc-300 dark:border-zinc-800 rounded shadow-xl"
          value={input}
          placeholder="Say something..."
          onChange={e => setInput(e.currentTarget.value)}
        />
      </form>
    </div>
  );
}
```

这个页面使用了 `useChat` Hook，默认会使用你之前创建的 `POST` API 路由（`/api/chat`）。该 Hook 提供了处理用户输入和表单提交所需的函数与状态。`useChat` Hook 提供多个实用函数和状态变量：

- `messages` - 当前的聊天消息（一个包含 `id`、`role` 和 `parts` 属性的对象数组）。
- `sendMessage` - 向聊天 API 发送消息的函数。

该组件使用本地状态（`useState`）管理输入框的值，并通过调用带输入文本的 `sendMessage` 然后清空输入框的方式来处理表单提交。

LLM 的响应通过消息的 `parts` 数组访问。每条消息都包含一个有序的 `parts` 数组，代表模型在其响应中生成的所有内容。这些 parts 可以包含纯文本、推理 token，以及你稍后会看到的更多内容。`parts` 数组保留了模型输出的先后顺序，让你可以按生成顺序显示或处理每个组件。

## 用工具增强你的聊天机器人

虽然大型语言模型（LLM）拥有出色的生成能力，但它们在处理离散任务（如数学）和与外部世界交互（如获取天气）方面并不擅长。这正是[工具](/docs/ai-sdk-core/tools-and-tool-calling)的用武之地。

工具是 LLM 可以调用的操作。这些操作的结果可以汇报给 LLM，供其在下一次响应中参考。

例如，如果用户询问当前天气，没有工具时，模型只能根据训练数据提供一般性信息。但有了天气工具，它就能获取并提供最新的、针对具体地点的天气信息。

让我们通过添加一个简单的天气工具来增强你的聊天机器人。

### 更新你的 Route Handler

修改你的 `src/routes/api/chat.ts` 文件，加入新的天气工具：

```tsx filename="src/routes/api/chat.ts" highlight="9,22-38"
import {
  streamText,
  UIMessage,
  convertToModelMessages,
  tool,
  createUIMessageStreamResponse,
  toUIMessageStream,
} from 'ai';
__PROVIDER_IMPORT__;
import { createFileRoute } from '@tanstack/react-router';
import { z } from 'zod';

export const Route = createFileRoute('/api/chat')({
  server: {
    handlers: {
      POST: async ({ request }) => {
        const { messages }: { messages: UIMessage[] } = await request.json();

        const result = streamText({
          model: __MODEL__,
          messages: await convertToModelMessages(messages),
          tools: {
            weather: tool({
              description: 'Get the weather in a location (fahrenheit)',
              inputSchema: z.object({
                location: z
                  .string()
                  .describe('The location to get the weather for'),
              }),
              execute: async ({ location }) => {
                const temperature = Math.round(Math.random() * (90 - 32) + 32);
                return {
                  location,
                  temperature,
                };
              },
            }),
          },
        });

        return createUIMessageStreamResponse({
          stream: toUIMessageStream({ stream: result.stream }),
        });
      },
    },
  },
});
```

在这段更新后的代码中：

1. 你从 `ai` 包导入了 `tool` 函数，并从 `zod` 导入 `z` 用于 schema 验证。
2. 你定义了一个包含 `weather` 工具的 `tools` 对象。该工具：
   - 具有一个描述（description），帮助模型理解何时使用它。
   - 使用一个 Zod schema 定义 `inputSchema`，指定执行此工具需要一个 `location` 字符串。模型会尝试从对话上下文中提取该输入；如果无法提取，它会向用户询问缺失的信息。
   - 定义了一个 `execute` 函数，模拟获取天气数据（此处返回一个随机温度）。这是一个在服务器上运行的异步函数，因此你可以从外部 API 获取真实数据。

现在你的聊天机器人可以"获取"用户询问的任何地点的天气信息了。当模型判断需要使用天气工具时，它会生成一个带必要输入的工具调用。随后 `execute` 函数会被自动运行，工具输出将作为 `tool` 消息添加到 `messages` 中。

试着问一句"纽约的天气怎么样？"，看看模型如何使用这个新工具。

注意到 UI 中的空白回复了吗？这是因为模型没有生成文本响应，而是生成了一个工具调用。你可以在客户端通过 `message.parts` 数组中的 `tool-weather` part 访问该工具调用及其后续的工具结果。

<Note>
  工具 part 始终命名为 `tool-{toolName}`，其中 `{toolName}` 是你定义工具时
  使用的键。在这个例子中，由于我们将工具定义为 `weather`，因此该 part 的
  类型是 `tool-weather`。
</Note>

## 启用多步工具调用

你可能已经注意到，虽然工具现在已在聊天界面中可见，但模型并没有使用这些信息来回答你最初的问题。这是因为模型一旦生成了工具调用，严格来说它的生成工作就已经完成了。

要解决这个问题，你可以使用 `stopWhen` 启用多步工具调用。默认情况下，`stopWhen` 被设置为 `isStepCount(1)`，这意味着在有工具结果的情况下，第一步之后生成就会停止。通过更改此条件，你可以让模型自动将工具结果发回给自己以触发额外的生成，直到满足你指定的停止条件。在这个场景中，你希望模型继续生成，以便它能使用天气工具的结果来回答你最初的问题。

### 更新你的 Route Handler

修改你的 `src/routes/api/chat.ts` 文件，加入 `stopWhen` 条件：

```tsx filename="src/routes/api/chat.ts"
import {
  streamText,
  UIMessage,
  convertToModelMessages,
  tool,
  isStepCount,
  createUIMessageStreamResponse,
  toUIMessageStream,
} from 'ai';
__PROVIDER_IMPORT__;
import { createFileRoute } from '@tanstack/react-router';
import { z } from 'zod';

export const Route = createFileRoute('/api/chat')({
  server: {
    handlers: {
      POST: async ({ request }) => {
        const { messages }: { messages: UIMessage[] } = await request.json();

        const result = streamText({
          model: __MODEL__,
          messages: await convertToModelMessages(messages),
          stopWhen: isStepCount(5),
          tools: {
            weather: tool({
              description: 'Get the weather in a location (fahrenheit)',
              inputSchema: z.object({
                location: z
                  .string()
                  .describe('The location to get the weather for'),
              }),
              execute: async ({ location }) => {
                const temperature = Math.round(Math.random() * (90 - 32) + 32);
                return {
                  location,
                  temperature,
                };
              },
            }),
          },
        });

        return createUIMessageStreamResponse({
          stream: toUIMessageStream({ stream: result.stream }),
        });
      },
    },
  },
});
```

在这段更新后的代码中，你将 `stopWhen` 设置为 `isStepCount(5)`，允许模型在任意一次生成中使用最多 5 个"步骤"。

回到浏览器，询问某个地点的天气。现在你应该能看到模型使用天气工具的结果来回答你的问题。

通过设置 `stopWhen: isStepCount(5)`，你允许模型在任意一次生成中使用最多 5 个"步骤"。这使更复杂的交互成为可能，并允许模型在需要时跨多个步骤收集和处理信息。你可以通过添加另一个将温度从华氏度转换为摄氏度的工具来实际观察这一机制。

3. 然后它会调用温度转换工具，将温度从华氏度转换为摄氏度。
4. 模型随后会利用这些信息，用自然语言回答关于纽约天气的问题。

这种多步方式让模型能够收集信息并用它提供更准确、更贴合上下文的响应，使你的聊天机器人实用得多。

这个简单示例展示了工具如何扩展模型的能力。你可以创建更复杂的工具，与真实 API、数据库或任何其他外部系统集成，让模型实时访问和处理真实世界的数据。工具弥合了模型知识截止时间与当前信息之间的差距。
