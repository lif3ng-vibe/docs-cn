# Prompt Engineering

## 什么是大语言模型（LLM）？

大语言模型（LLM）本质上是一个预测引擎：它以一个词序列作为输入，目标是预测接下来最可能出现的序列。它通过为潜在的后续序列分配概率，然后从中选择一个来实现这一点。模型会持续生成序列，直到满足指定的停止条件。

这些模型通过在海量文本语料上训练来学习，这意味着它们对某些用例的适配程度会高于其他用例。例如，在 GitHub 数据上训练的模型会特别擅长理解源代码中序列的概率。然而，必须理解的是，生成的序列虽然常常看似合理，但有时可能是随机的、并非基于现实。随着这些模型变得越来越精确，许多令人惊喜的能力和应用也随之涌现。

## 什么是提示词（prompt）？

提示词（prompt）是 LLM 的起点，是触发模型生成文本的输入。提示词工程的范畴不仅包括精心编写这些提示词，还包括理解相关概念，例如隐藏提示词、token、token 限制，以及提示词攻击（prompt hacking）的可能性——其中包括越狱（jailbreak）和信息泄露等现象。

## 为什么需要提示词工程？

提示词工程目前在塑造 LLM 的响应方面发挥着关键作用。它让我们能够调整模型，使其更有效地响应更广泛的查询，其中包括语义搜索、命令语法和 ReActive 模型架构等技术的运用。不同模型和模型提供商的 LLM 在性能、上下文窗口和成本上各不相同，这又为整体增加了更多约束。例如，GPT-4 模型比 GPT-3.5-turbo 更昂贵且明显更慢，但在某些任务上也可能更有效。因此，与软件工程中的许多事情一样，成本与性能之间存在权衡。

为了帮助比较和调整 LLM，我们构建了一个 AI playground，让你可以在线并排比较不同模型的性能。当你准备好后，甚至可以使用 AI SDK 生成代码，快速将你的提示词和所选模型应用到自己的应用中。

## 示例：构建一个口号生成器

### 从一条指令开始

想象一下，你想为营销活动构建一个口号生成器。创作朗朗上口的口号并非总是那么容易！

首先，你需要一个能清楚表达你需求的提示词。让我们从一条指令开始。提交这个提示词来生成你的第一次补全。

<InlinePrompt initialInput="为一家咖啡店创作一个口号。" />

还不错！现在，试着让你的指令更具体一些。

<InlinePrompt initialInput="为一家有机咖啡店创作一个口号。" />

在提示词中引入一个描述性词语就会影响补全结果。从本质上讲，编写提示词就是你"指示"或"编程"模型的方式。

### 提供示例

清晰的指令是获得高质量结果的关键，但这可能并不总是足够。让我们尝试进一步增强你的指令。

<InlinePrompt initialInput="为一家有现场音乐的咖啡店创作三个口号。" />

这些口号尚可，但还可以更好。模型似乎忽略了我们提示词中"现场音乐"的部分。让我们稍作修改，以生成更贴切的建议。

通常，向模型既展示又说明你的需求会更有帮助。在提示词中加入示例有助于传达模式或细微差别。测试这个带有几个示例的提示词。

<InlinePrompt
  initialInput={`为一家有独特特色的商家创作三个口号。

商家：有猫的书店
口号："完美书页"、"书本与胡须"、"小说与依偎"
商家：带攀岩墙的健身房
口号："巅峰表现"、"再攀高峰"、"攀出好身材"
商家：有现场音乐的咖啡店
口号：`}
/>

很好！针对特定输入加入预期输出的示例，促使模型生成了我们想要的那种名字。

### 调整你的设置

除了设计提示词之外，你还可以通过调整模型设置来影响补全结果。一个关键的设置是 **temperature**（温度）。

你可能已经注意到，同一个提示词在重复提交时会产生相同或几乎相同的补全。这发生在你的 temperature 为 0 时。

尝试在 temperature 设为 1 的情况下重新提交相同的提示词几次。

<InlinePrompt
  initialInput={`为一家有独特特色的商家创作三个口号。

商家：有猫的书店
口号："完美书页"、"书本与胡须"、"小说与依偎"
商家：带攀岩墙的健身房
口号："巅峰表现"、"再攀高峰"、"攀出好身材"
商家：有现场音乐的咖啡店
口号：`}
  showTemp={true}
  initialTemperature={1}
/>

注意到区别了吗？当 temperature 高于 0 时，同一个提示词每次都会给出不同的补全。

请记住，模型预测的是最可能跟随前文出现的文本。temperature 是一个介于 0 到 1 之间的值，本质上控制着模型在进行这些预测时的置信水平。较低的 temperature 意味着更小的风险，会产生更精确、更确定的补全；较高的 temperature 则会带来更广泛的补全结果。

对于你的口号生成器，你可能想要一个大的名称建议池。适中的 temperature（0.6）应该就够用了。
