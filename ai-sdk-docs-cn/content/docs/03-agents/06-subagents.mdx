# Subagents

子智能体（subagent）是父智能体可以调用的智能体。父智能体通过一个工具委派工作，子智能体自主执行后返回结果。

## 工作原理

1. **定义一个子智能体**，为其配置专属的模型、指令和工具
2. **创建一个调用它的工具**，供主智能体使用
3. **子智能体在自己的上下文窗口中独立运行**
4. **返回一个结果**（可选地向 UI 流式传输进度）
5. **控制模型看到的内容**，使用 `toModelOutput` 进行摘要

## 何时使用子智能体

子智能体会增加延迟与复杂度。只有当收益大于成本时才使用它们：

| 适合使用子智能体的场景          | 避免使用子智能体的场景   |
| ------------------------------- | ------------------------ |
| 任务需要探索大量 token          | 任务简单且聚焦           |
| 需要并行处理相互独立的研究      | 顺序处理即可满足         |
| 上下文将超出模型限制            | 上下文仍然可控           |
| 希望按能力隔离工具访问权限      | 所有工具可以安全共存     |

## 为什么使用子智能体？

### 卸载上下文繁重的任务

有些任务需要探索大量信息——读取文件、搜索代码库或研究某个主题。在主智能体中执行这些任务会迅速消耗上下文，使智能体随时间推移变得不那么连贯。

使用子智能体后，你可以：

- 启动一个专门的子智能体，让它消耗数十万个 token
- 让它只返回一段聚焦的摘要（大约 1,000 token）
- 保持主智能体的上下文干净而连贯

子智能体负责繁重的工作，主智能体则专注于编排。

### 并行化独立工作

对于诸如探索代码库之类的任务，你可以生成多个子智能体，同时研究不同的领域。每个子智能体返回一份摘要，由主智能体整合各项发现——无需为所有这些探索支付上下文成本。

### 专业化编排

一种较少见但同样有效的模式，是让主智能体纯粹负责编排，将不同类型的工作委派给专门的子智能体。例如：

- 一个带有只读工具、用于研究代码库的探索子智能体
- 一个带有文件编辑工具的编码子智能体
- 一个带有特定平台或 API 专属工具的集成子智能体

这带来了清晰的职责分离，不过上下文卸载与并行化才是使用子智能体更常见的动机。

## 不带流式的基本子智能体

最简单的子智能体模式不需要任何特殊机制。你的主智能体拥有一个工具，在其 `execute` 函数中调用另一个智能体：

```ts
import { ToolLoopAgent, tool } from 'ai';
__PROVIDER_IMPORT__;
import { z } from 'zod';

// Define a subagent for research tasks
const researchSubagent = new ToolLoopAgent({
  model: __MODEL__,
  instructions: `You are a research agent.
Summarize your findings in your final response.`,
  tools: {
    read: readFileTool, // defined elsewhere
    search: searchTool, // defined elsewhere
  },
});

// Create a tool that delegates to the subagent
const researchTool = tool({
  description: 'Research a topic or question in depth.',
  inputSchema: z.object({
    task: z.string().describe('The research task to complete'),
  }),
  execute: async ({ task }, { abortSignal }) => {
    const result = await researchSubagent.generate({
      prompt: task,
      abortSignal,
    });
    return result.text;
  },
});

// Main agent uses the research tool
const mainAgent = new ToolLoopAgent({
  model: __MODEL__,
  instructions: 'You are a helpful assistant that can delegate research tasks.',
  tools: {
    research: researchTool,
  },
});
```

当你无需在 UI 中展示子智能体的进度时，这种方式效果很好。工具调用会阻塞直到子智能体完成，然后返回最终的文本响应。

### 处理取消

当用户取消请求时，`abortSignal` 会传播到子智能体。务必将它透传下去，以确保清理得以执行：

```ts
execute: async ({ task }, { abortSignal }) => {
  const result = await researchSubagent.generate({
    prompt: task,
    abortSignal, // Cancels subagent if main request is aborted
  });
  return result.text;
},
```

如果你中止该信号，子智能体会停止执行并抛出 `AbortError`。主智能体的工具执行失败，从而终止主循环。

为了避免后续消息中出现关于不完整工具调用的错误，请结合 `ignoreIncompleteToolCalls` 使用 `convertToModelMessages`：

```ts
import { convertToModelMessages } from 'ai';

const modelMessages = await convertToModelMessages(messages, {
  ignoreIncompleteToolCalls: true,
});
```

它会过滤掉没有对应结果的工具调用。更多信息请参阅 [convertToModelMessages](/docs/reference/ai-sdk-ui/convert-to-model-messages) 参考文档。

## 流式传输子智能体进度

当你想在子智能体工作期间展示增量进度时，可以使用[**初步工具结果**](/docs/ai-sdk-core/tools-and-tool-calling#初步工具结果)。这种模式使用一个生成器函数，向 UI 持续产出部分更新。

### 初步工具结果的工作原理

将你的 `execute` 函数从普通函数改为异步生成器（`async function*`）。每次 `yield` 都会向前端发送一个初步结果：

```ts
execute: async function* ({ /* input */ }) {
  // ... do work ...
  yield partialResult;
  // ... do more work ...
  yield updatedResult;
}
```

### 构建完整消息

每次 `yield` 都会**完全替换**上一次的输出（而不是追加）。这意味着你需要一种方式，把子智能体的响应累积成一条随时间不断增长的完整消息。

`readUIMessageStream` 工具函数可以处理这件事。它从流中读取每个分块，构建一个不断增长的 `UIMessage`，其中包含目前为止已接收的所有部分：

```ts
import { readUIMessageStream, toUIMessageStream, tool } from 'ai';
import { z } from 'zod';

const researchTool = tool({
  description: 'Research a topic or question in depth.',
  inputSchema: z.object({
    task: z.string().describe('The research task to complete'),
  }),
  execute: async function* ({ task }, { abortSignal }) {
    // Start the subagent with streaming
    const result = await researchSubagent.stream({
      prompt: task,
      abortSignal,
    });

    // Each iteration yields a complete, accumulated UIMessage
    for await (const message of readUIMessageStream({
      stream: toUIMessageStream({ stream: result.stream }),
    })) {
      yield message;
    }
  },
});
```

每个产出的 `message` 都是一条完整的 `UIMessage`，包含子智能体到该时刻为止的所有部分（文本、工具调用和工具结果）。前端只需用每条新消息替换其显示内容即可。

## 控制模型看到的内容

这正是子智能体在上下文管理上大显身手之处。包含子智能体全部工作内容的完整 `UIMessage` 会存储在消息历史中，并显示在 UI 里。但你可以通过 `toModelOutput` 控制主智能体的模型实际看到的内容。

### 工作原理

`toModelOutput` 函数将工具的输出映射为发送给模型的 token：

```ts
const researchTool = tool({
  description: 'Research a topic or question in depth.',
  inputSchema: z.object({
    task: z.string().describe('The research task to complete'),
  }),
  execute: async function* ({ task }, { abortSignal }) {
    const result = await researchSubagent.stream({
      prompt: task,
      abortSignal,
    });

    for await (const message of readUIMessageStream({
      stream: toUIMessageStream({ stream: result.stream }),
    })) {
      yield message;
    }
  },
  toModelOutput: ({ output: message }) => {
    // Extract just the final text as a summary
    const lastTextPart = message?.parts.findLast(p => p.type === 'text');
    return {
      type: 'text',
      value: lastTextPart?.text ?? 'Task completed.',
    };
  },
});
```

在此配置下：

- **用户看到的是**：子智能体的完整执行过程——每一次工具调用、每一个中间步骤
- **模型看到的是**：仅最终的摘要文本

子智能体可能消耗 100,000 个 token 来探索和推理，但主智能体只会消耗摘要文本。这让主智能体保持连贯与专注。

### 为总结而编写子智能体指令

为了让 `toModelOutput` 能提取出有用的摘要，你的子智能体必须产出摘要。请添加类似这样的明确指令：

```ts
const researchSubagent = new ToolLoopAgent({
  model: __MODEL__,
  instructions: `You are a research agent. Complete the task autonomously.

IMPORTANT: When you have finished, write a clear summary of your findings as your final response.
This summary will be returned to the main agent, so include all relevant information.`,
  tools: {
    read: readFileTool,
    search: searchTool,
  },
});
```

如果没有这条指令，子智能体可能不会给出全面的摘要。它可能只说一句 "Done"，让 `toModelOutput` 提取不到有用的内容。

## 在 UI 中渲染子智能体（配合 useChat）

要展示流式进度，请检查工具部分的 `state` 与 `preliminary` 标志。

### 工具部分的状态

| State              | 描述                             |
| ------------------ | -------------------------------- |
| `input-streaming`  | 正在生成工具输入                 |
| `input-available`  | 工具已就绪，可执行               |
| `output-available` | 工具已产出输出（检查 `preliminary`） |
| `output-error`     | 工具执行失败                     |

### 检测流式中还是已完成

```tsx
const hasOutput = part.state === 'output-available';
const isStreaming = hasOutput && part.preliminary === true;
const isComplete = hasOutput && !part.preliminary;
```

### 子智能体输出的类型安全

随你的智能体一起导出类型，供 UI 组件使用：

```ts filename="lib/agents.ts"
import { ToolLoopAgent, InferAgentUIMessage } from 'ai';

export const mainAgent = new ToolLoopAgent({
  // ... configuration with researchTool
});

// Export the main agent message type for the chat UI
export type MainAgentMessage = InferAgentUIMessage<typeof mainAgent>;
```

### 渲染消息与子智能体输出

此示例使用上面定义的类型，同时渲染主智能体的消息与子智能体的流式输出：

```tsx
'use client';

import { useChat } from '@ai-sdk/react';
import type { MainAgentMessage } from '@/lib/agents';

export function Chat() {
  const { messages } = useChat<MainAgentMessage>();

  return (
    <div>
      {messages.map(message =>
        message.parts.map((part, i) => {
          switch (part.type) {
            case 'text':
              return <p key={i}>{part.text}</p>;
            case 'tool-research':
              return (
                <div>
                  {part.state !== 'input-streaming' && (
                    <div>Research: {part.input.task}</div>
                  )}
                  {part.state === 'output-available' && (
                    <div>
                      {part.output.parts.map((nestedPart, i) => {
                        switch (nestedPart.type) {
                          case 'text':
                            return <p key={i}>{nestedPart.text}</p>;
                          default:
                            return null;
                        }
                      })}
                    </div>
                  )}
                </div>
              );
            default:
              return null;
          }
        }),
      )}
    </div>
  );
}
```

## 注意事项

### 子智能体不支持工具审批

子智能体的工具无法使用审批流程，例如 `toolApproval`（或已弃用的 `needsApproval`）。所有工具都必须在没有用户确认的情况下自动执行。

### 子智能体上下文相互隔离

每次子智能体调用都从一个全新的上下文窗口开始。这是子智能体的关键优势之一：它们不会继承主智能体累积的上下文，正因如此，它们才能进行重度探索而不使主对话膨胀。

如果你需要让子智能体访问对话历史，工具的 `execute` 函数会在接收 `abortSignal` 的同时接收 `messages`：

```ts
execute: async ({ task }, { abortSignal, messages }) => {
  const result = await researchSubagent.generate({
    messages: [
      ...messages, // The main agent's conversation history
      { role: 'user', content: task }, // The specific task for this invocation
    ],
    abortSignal,
  });
  return result.text;
},
```

请谨慎使用，因为传入完整历史会削弱上下文隔离的部分优势。

### 流式增加复杂度

基本模式（无流式）更易于实现和调试。只有当你需要在 UI 中展示实时进度时，才添加流式。
