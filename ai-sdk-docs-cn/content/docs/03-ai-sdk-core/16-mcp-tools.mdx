# Model Context Protocol (MCP)

AI SDK 支持连接到 [Model Context Protocol (MCP)](https://modelcontextprotocol.io/) 服务器，以访问其工具、资源和提示词。
这让你的 AI 应用能够通过标准化接口发现并使用各种服务提供的能力。

<Note>
  如果你使用的是 OpenAI 的 Responses API，也可以使用内置的
  `openai.tools.mcp` 工具，它无需转换工具即可直接集成 MCP 服务器。
  详情请参阅 [OpenAI 提供商文档](/providers/ai-sdk-providers/openai#mcp-工具)。
</Note>

## 初始化 MCP 客户端

对于生产部署，我们建议使用 HTTP 传输（如 `StreamableHTTPClientTransport`）。stdio 传输只能用于连接本地服务器，因为它无法部署到生产环境。

使用以下任一传输选项创建 MCP 客户端：

- **HTTP 传输**（推荐）：可以通过客户端直接配置 HTTP（使用 `transport: { type: 'http', ... }`），或使用 MCP 官方 TypeScript SDK 的 `StreamableHTTPClientTransport`
- **SSE**（Server-Sent Events，服务器推送事件）：另一种基于 HTTP 的传输
- `stdio`：仅用于本地开发。对本地 MCP 服务器使用标准输入/输出流

AI SDK 的 MCP 客户端同时支持旧版基于初始化（initialize）协商的协议版本，以及无状态的 MCP `2026-07-28` 协议版本。内置的 stdio 传输会先用 `server/discover` 探测，若为旧版服务器则自动回退（fallback）到旧版 `initialize` 握手。自定义传输可通过 `supportsProtocolVersionDiscovery: true` 选择加入此协商。

### HTTP 传输（推荐）

对于生产部署，我们建议使用 HTTP 传输。你可以直接在客户端上进行配置：

```typescript
import { createMCPClient } from '@ai-sdk/mcp';

const mcpClient = await createMCPClient({
  transport: {
    type: 'http',
    url: 'https://your-server.com/mcp',

    // optional: configure HTTP headers
    headers: { Authorization: 'Bearer my-api-key' },

    // optional: provide an OAuth client provider for automatic authorization
    authProvider: myOAuthClientProvider,

    // optional: allow redirect responses (default is 'error' to prevent SSRF)
    redirect: 'follow',
  },
});
```

如果旧版 MCP 服务器使用 Streamable HTTP 会话，你可以通过恢复之前的会话 id 和 initialize 结果，重新附加到已保存的会话。MCP `2026-07-28` 是无状态的，不使用这些选项：

```typescript
import { createMCPClient } from '@ai-sdk/mcp';

const savedSession = await loadMcpSession();
let currentSessionId = savedSession?.sessionId;

const mcpClient = await createMCPClient({
  transport: {
    type: 'http',
    url: 'https://your-server.com/mcp',
    initialSessionId: savedSession?.sessionId,
    initialProtocolVersion: savedSession?.initializeResult.protocolVersion,
    terminateSessionOnClose: false,

    onSessionIdChange: sessionId => {
      currentSessionId = sessionId;
    },

    onSessionExpired: sessionId => {
      if (currentSessionId === sessionId) {
        currentSessionId = undefined;
        void clearMcpSession();
      }
    },
  },
  initialInitializeResult: savedSession?.initializeResult,
});

if (currentSessionId) {
  await saveMcpSession({
    sessionId: currentSessionId,
    initializeResult: mcpClient.initializeResult,
  });
}
```

提供 `initialInitializeResult` 时，`createMCPClient` 会复用缓存的 initialize 元数据，不会再次发送 `initialize` 请求。当 `onSessionExpired` 被调用时，传输已经清除了会话 id，请求仍会以底层 HTTP 错误失败。此时应重新创建一个不带 `initialSessionId` 或 `initialInitializeResult` 的全新客户端进行重试。当你只想关闭本地客户端、同时保留 MCP 会话以便稍后重新附加时，请将 `terminateSessionOnClose` 设为 `false`。

你也可以使用 MCP 官方 TypeScript SDK 中的 `StreamableHTTPClientTransport`：

```typescript
import { createMCPClient } from '@ai-sdk/mcp';
import { StreamableHTTPClientTransport } from '@modelcontextprotocol/sdk/client/streamableHttp.js';

const url = new URL('https://your-server.com/mcp');
const mcpClient = await createMCPClient({
  transport: new StreamableHTTPClientTransport(url, {
    sessionId: 'session_123',
  }),
});
```

### SSE 传输

SSE 提供了另一种基于 HTTP 的传输选项。通过 `type` 和 `url` 属性进行配置。还可以提供 `authProvider` 以支持 OAuth：

```typescript
import { createMCPClient } from '@ai-sdk/mcp';

const mcpClient = await createMCPClient({
  transport: {
    type: 'sse',
    url: 'https://my-server.com/sse',

    // optional: configure HTTP headers
    headers: { Authorization: 'Bearer my-api-key' },

    // optional: provide an OAuth client provider for automatic authorization
    authProvider: myOAuthClientProvider,

    // optional: allow redirect responses (default is 'error' to prevent SSRF)
    redirect: 'follow',
  },
});
```

### Stdio 传输（本地服务器）

<Note type="warning">
  stdio 传输只应用于本地服务器。
</Note>

Stdio 传输可以从 MCP SDK 或 AI SDK 中导入：

```typescript
import { createMCPClient } from '@ai-sdk/mcp';
import { StdioClientTransport } from '@modelcontextprotocol/sdk/client/stdio.js';
// Or use the AI SDK's stdio transport:
// import { Experimental_StdioMCPTransport as StdioClientTransport } from '@ai-sdk/mcp/mcp-stdio';

const mcpClient = await createMCPClient({
  transport: new StdioClientTransport({
    command: 'node',
    args: ['src/stdio/dist/server.js'],
  }),
});
```

### 自定义传输

如果标准传输无法满足特定需求，你也可以通过实现 `MCPTransport` 接口来自带传输实现。

<Note>
  `createMCPClient` 函数返回的是一个轻量级客户端，专用于工具转换场景。它目前不支持完整 MCP 客户端的所有功能，例如自动会话持久化、可恢复流以及接收通知。

使用 AI SDK 的 MCP HTTP 或 SSE 传输时，可以通过提供 `authProvider` 来支持 OAuth 授权。

</Note>

### 共享 OAuth 凭据存储

当多个 MCP 客户端或副本共享 OAuth 凭据时，轮换中的刷新令牌（refresh token）可能被并发使用。一次刷新可能保存了新令牌，而另一次刷新却因旧刷新令牌而收到 `invalid_grant`。

可选的 `OAuthClientProvider.invalidateCredentials` 方法会接收第二个参数，用于标识失败刷新所使用的令牌：

```typescript
invalidateCredentials(
  scope: 'all' | 'client' | 'tokens' | 'verifier',
  context?: { tokens: OAuthTokens },
): void | Promise<void>;
```

当 `scope === 'tokens'` 且带有 context 时，只有在存储的访问令牌和刷新令牌仍与 `context.tokens` 匹配时才删除该凭据。比较和删除必须是原子操作，可使用条件数据库操作或事务。如果已不再匹配，则将较新的令牌保留在存储中。SDK 会重试授权并重新读取存储的令牌。

在使缺少授权服务器固定（pin）的已存储令牌失效时，SDK 也会提供该 context。其他失效场景可以省略 context。

如果授权码（authorization code）交换返回 `invalid_grant`，SDK 会直接传播该错误，不会使已存储的凭据失效，也不会重试被拒绝的授权码。被拒绝的授权码并不意味着现有的访问令牌或刷新令牌已失效。

### OAuth 授权服务器验证

在服务器端应用中使用 MCP OAuth 时，MCP 服务器可以声明要使用的 OAuth 授权服务器。如果你连接的 MCP 服务器不在你的控制范围内，请在 `authProvider` 上实现 `validateAuthorizationServerURL`，只允许你信任的授权服务器来源（origin）：

```typescript
const allowedAuthorizationServerOrigins = new Set([
  'https://accounts.example.com',
  'https://tenant.auth0.com',
]);

const myOAuthClientProvider = {
  // ...other OAuthClientProvider methods

  validateAuthorizationServerURL(serverUrl, authorizationServerUrl) {
    const origin = new URL(authorizationServerUrl).origin;

    if (!allowedAuthorizationServerOrigins.has(origin)) {
      throw new Error(
        `Unexpected OAuth authorization server for ${serverUrl}: ${origin}`,
      );
    }
  },
};
```

此钩子会在 SDK 获取授权服务器元数据之前调用，因此被拒绝的 URL 不会被请求。该方法是可选的，除非你实现它，否则不会改变现有的 OAuth 流程。

### OAuth 回调签发方验证

在完成 OAuth 授权回调时，将回调的 `iss` 参数作为 `callbackIssuer` 传递给 `auth`：

```typescript
import { auth } from '@ai-sdk/mcp';

const callbackUrl = new URL(request.url);

await auth(myOAuthClientProvider, {
  serverUrl: 'https://mcp.example.com',
  authorizationCode: callbackUrl.searchParams.get('code')!,
  callbackState: callbackUrl.searchParams.get('state') ?? undefined,
  callbackIssuer: callbackUrl.searchParams.get('iss') ?? undefined,
});
```

当 `iss` 存在时，它必须与发现的授权服务器签发方完全匹配。不匹配时不会交换授权码。

动态客户端注册请求包含 OAuth `application_type`。客户端会为回环地址、localhost 和自定义 scheme 重定向推断 `native`，为远程 HTTP(S) 重定向推断 `web`。你可以在提供商的 `clientMetadata` 中设置 `application_type` 来覆盖此行为。

### 动态客户端凭据恢复

为了让 SDK 能够替换通过动态客户端注册创建的失效凭据，请在 OAuth 客户端提供商上实现 `isClientInformationDynamicallyRegistered`。仅当当前客户端信息来自动态注册响应时才返回 `true`。当提供商在请求之间被重新创建时，请将这一来源信息与凭据一同持久化。

```typescript
const myOAuthClientProvider = {
  // ...other OAuthClientProvider methods

  async saveClientInformation(clientInformation) {
    await saveClientRecord({
      clientInformation,
      dynamicallyRegistered: true,
    });
  },

  async isClientInformationDynamicallyRegistered() {
    return (await loadClientRecord())?.dynamicallyRegistered === true;
  },
};
```

当此方法被省略或返回 `false` 时，客户端信息将被视为预注册的，并在 `invalid_client` 和 `unauthorized_client` 错误后予以保留。SDK 不会从 `redirect_uris` 等字段推断来源，因为预注册客户端可以包含与动态注册客户端相同的元数据。

### 重试瞬时工具失败

MCP 工具调用可能因瞬时的传输原因而失败，例如速率限制、临时过载或网关超时。你可以在创建客户端时传入 `maxRetries`，为 `tools/call` 请求启用自动重试：

```typescript
const mcpClient = await createMCPClient({
  transport: {
    type: 'http',
    url: 'https://your-server.com/mcp',
  },
  maxRetries: 2,
});
```

重试默认关闭。内置的重试匹配仅针对瞬时的 HTTP 与网络故障。JSON-RPC 应用层错误（例如无效的工具参数）会立即抛出，不会重试。带有 `isError: true` 的成功 MCP 工具响应同样会直接返回给模型，不做重试。

`maxRetries` 适用于 `tools/call` 请求，不适用于客户端初始化。下面的示例使用导出的 `MCPClientError` 类型守卫来识别可能是瞬时的 HTTP 初始化失败：

```typescript
import { createMCPClient, MCPClientError } from '@ai-sdk/mcp';

try {
  await createMCPClient({
    transport: {
      type: 'http',
      url: 'https://your-server.com/mcp',
    },
  });
} catch (error) {
  if (
    !MCPClientError.isInstance(error) ||
    error.code != null ||
    error.statusCode == null ||
    !(
      error.statusCode === 408 ||
      error.statusCode === 409 ||
      error.statusCode === 429 ||
      error.statusCode >= 500
    )
  ) {
    throw error;
  }

  // Retry according to your application's backoff policy.
}
```

此示例只考虑了 HTTP 状态码。缺少 `statusCode` 并不能说明失败是瞬时的：配置错误、协议错误和被取消的请求同样可能没有 HTTP 状态。网络与超时的重试需要应用层另行制定策略。`UnauthorizedError` 和 `MCPClientOAuthError` 等 OAuth 错误在此示例中会被原样重新抛出。

<Note type="warning">
  只应在重试安全的 MCP 工具上启用重试。重试非幂等工具（例如发送邮件或创建记录的工具）可能导致副作用重复发生。
</Note>

### 关闭 MCP 客户端

初始化之后，应根据你的使用模式关闭 MCP 客户端：

- 短期使用（例如单次请求）：在响应结束后关闭客户端
- 长期运行的客户端（例如命令行应用）：保持客户端打开，但确保应用终止时将其关闭

流式响应时，可以在 LLM 响应结束后关闭客户端。例如使用 `streamText` 时，应使用 `onEnd` 回调：

```typescript
const mcpClient = await createMCPClient({
  // ...
});

const tools = await mcpClient.tools();

const result = await streamText({
  model: __MODEL__,
  tools,
  prompt: 'What is the weather in Brooklyn, New York?',
  onEnd: async () => {
    await mcpClient.close();
  },
});
```

非流式生成响应时，可以使用 try/finally 或框架中的清理函数：

```typescript
import { createMCPClient, type MCPClient } from '@ai-sdk/mcp';

let mcpClient: MCPClient | undefined;

try {
  mcpClient = await createMCPClient({
    // ...
  });
} finally {
  await mcpClient?.close();
}
```

## 使用 MCP 工具

客户端的 `tools` 方法充当 MCP 工具与 AI SDK 工具之间的适配器。它支持两种处理工具 schema 的方式：

### schema 发现

通过 schema 发现，服务器提供的所有工具会被自动列出，输入参数类型根据服务器提供的 schema 推断：

```typescript
const tools = await mcpClient.tools();
```

这种方式实现起来更简单，并且会自动与服务器变更保持同步。不过，你在开发阶段将无法获得 TypeScript 类型安全，而且服务器上的所有工具都会被加载。

### 工具批注与审批

MCP 服务器可以通过 `readOnlyHint`、`destructiveHint`、`idempotentHint`、`openWorldHint` 等批注（annotation）描述工具行为。MCP 客户端会将这些批注暴露在每个工具的 `metadata.annotations` 以及产生的工具调用的 `toolMetadata.annotations` 上。

批注是不可信的服务器端提示。MCP 客户端不会自动将其转换为审批策略。应用应将它们与确定性控制手段结合使用，例如工具白名单、最小化权限的凭据，以及自身的 [`toolApproval`](/docs/agents/tool-approvals) 策略。

下面的保守策略只在服务器明确将工具标记为只读时才允许其自动运行。`readOnlyHint: false` 或没有 `readOnlyHint` 的工具都需要用户审批：

```typescript
import { type McpProviderMetadata } from '@ai-sdk/mcp';

const result = streamText({
  model: __MODEL__,
  tools,
  toolApproval: ({ toolCall }) => {
    const annotations = (
      toolCall.toolMetadata as McpProviderMetadata | undefined
    )?.annotations;

    return annotations?.readOnlyHint === true
      ? 'not-applicable'
      : {
          type: 'user-approval',
          reason:
            annotations?.destructiveHint === true
              ? 'The MCP server marks this tool as destructive.'
              : 'The MCP server does not mark this tool as read-only.',
        };
  },
  prompt,
});
```

完整带批注的 MCP 服务器与应用层审批配置，请参阅[本地工具批注示例](https://github.com/vercel/ai/tree/main/examples/mcp/src/tool-annotations)。在两个终端中分别启动服务器和客户端：

```bash
cd examples/mcp
pnpm server:tool-annotations
```

```bash
cd examples/mcp
pnpm client:tool-annotations
```

让客户端读取、删除或创建一条笔记。只读工具会立即执行。破坏性工具和未标注批注的工具会提示审批；输入 `y` 或 `n` 后，客户端会把决定发回并打印模型的响应。

### 定义 schema

为了获得更好的类型安全与控制力，你可以在客户端代码中显式定义工具及其输入 schema：

```typescript
import { z } from 'zod';

const tools = await mcpClient.tools({
  schemas: {
    'get-data': {
      inputSchema: z.object({
        query: z.string().describe('The data query'),
        format: z.enum(['json', 'text']).optional(),
      }),
    },
    // For tools with zero inputs, you should use an empty object:
    'tool-with-no-args': {
      inputSchema: z.object({}),
    },
  },
});
```

这种方式提供完整的 TypeScript 类型安全和 IDE 自动补全，让你在开发阶段就能发现参数不匹配。定义 `schemas` 后，客户端只会拉取显式定义的工具，让应用聚焦于所需的工具。

### 类型化工具输出

当 MCP 服务器返回 `structuredContent` 时（依据 [MCP 规范](https://modelcontextprotocol.io/specification/2026-07-28/server/tools#structured-content)），你可以定义 `outputSchema` 来获得类型化的工具结果：

```typescript
import { z } from 'zod';

const tools = await mcpClient.tools({
  schemas: {
    'get-weather': {
      inputSchema: z.object({
        location: z.string(),
      }),
      // Define outputSchema for typed results
      outputSchema: z.object({
        temperature: z.number(),
        conditions: z.string(),
        humidity: z.number(),
      }),
    },
  },
});

const result = await tools['get-weather'].execute(
  { location: 'New York' },
  { messages: [], toolCallId: 'weather-1' },
);

console.log(`Temperature: ${result.temperature}°C`);
```

提供 `outputSchema` 时：

- 客户端会从工具结果中提取 `structuredContent`
- 输出会在运行时依据你的 schema 进行校验
- 结果获得完整的 TypeScript 类型安全

如果服务器没有返回 `structuredContent`，客户端会回退到从文本内容解析 JSON。若两者都不可用或校验失败，则抛出错误。

如果服务器返回了 `structuredContent` 但缺少向后兼容的 `content` 字段，客户端会在返回结果前添加一个包含序列化 JSON 的文本内容块。这一兼容行为用于处理那些省略了 MCP 规范所建议的文本镜像的服务器。

<Note>
  不提供 `outputSchema` 时，工具会返回原始的 `CallToolResult` 对象，其中包含 `content` 和可选的 `isError` 字段。
</Note>

## 使用 MCP 资源

根据 [MCP 规范](https://modelcontextprotocol.io/docs/learn/server-concepts#resources)，资源是**由应用驱动**的数据源，为模型提供上下文。与工具（由模型控制）不同，何时获取资源并作为上下文传入由你的应用决定。

MCP 客户端提供了三个处理资源的方法：

### 列出资源

列出 MCP 服务器上所有可用的资源：

```typescript
const resources = await mcpClient.listResources();
```

### 读取资源内容

按 URI 读取特定资源的内容：

```typescript
const resourceData = await mcpClient.readResource({
  uri: 'file:///example/document.txt',
});
```

### 列出资源模板

资源模板是支持灵活查询的动态 URI 模式。列出所有可用的模板：

```typescript
const templates = await mcpClient.listResourceTemplates();
```

## 使用 MCP 补全

当 MCP 服务器声明 `completions` 能力时，可以为提示词参数和资源模板变量提供自动补全建议。使用 `complete` 基于当前的部分参数值向服务器请求建议：

```typescript
const completion = await mcpClient.complete({
  ref: {
    type: 'ref/resource',
    uri: 'file:///{path}',
  },
  argument: {
    name: 'path',
    value: 'doc',
  },
});

console.log(completion.completion.values);
```

对于有多个参数的资源模板或提示词，通过 `context.arguments` 传入已解析的值：

```typescript
const completion = await mcpClient.complete({
  ref: {
    type: 'ref/resource',
    uri: 'kubernetes://namespaced/{plural}/{namespace}',
  },
  argument: {
    name: 'namespace',
    value: 'auth',
  },
  context: {
    arguments: {
      plural: 'deployments',
    },
  },
});
```

如果连接的服务器未声明 `capabilities.completions`，客户端会抛出 `MCPClientError`。

## 使用 MCP 提示词

<Note type="warning">
  MCP Prompts 是实验性功能，未来可能变更。
</Note>

根据 MCP 规范，提示词是由用户控制的模板，由服务器暴露给客户端，客户端可带可选参数列出并获取它们。

### 列出提示词

```typescript
const prompts = await mcpClient.experimental_listPrompts();
```

### 获取提示词

获取提示词消息，可选地传入服务器定义的参数：

```typescript
const prompt = await mcpClient.experimental_getPrompt({
  name: 'code_review',
  arguments: { code: 'function add(a, b) { return a + b; }' },
});
```

## 处理引导请求（elicitation）

引导（elicitation）是 MCP 服务器在工具执行期间向客户端请求额外信息的机制。例如，服务器可能需要用户输入来完成注册表单，或需要对敏感操作进行确认。

<Note type="warning">
  妥善处理引导请求是客户端应用自己的责任。MCP 客户端只是把这些请求从服务器透传给你的应用代码。
</Note>

### 启用引导支持

要启用引导，需要在创建 MCP 客户端时声明该能力：

```typescript
const mcpClient = await createMCPClient({
  transport: {
    type: 'sse',
    url: 'https://your-server.com/sse',
  },
  capabilities: {
    elicitation: {},
  },
});
```

### 注册引导处理器

使用 `onElicitationRequest` 方法注册一个处理器，当服务器请求输入时它会被调用：

```typescript
import { ElicitationRequestSchema } from '@ai-sdk/mcp';

mcpClient.onElicitationRequest(ElicitationRequestSchema, async request => {
  // request.params.message: A message describing what input is needed
  // request.params.requestedSchema: JSON schema defining the expected input structure

  // Get input from the user (implement according to your application's needs)
  const userInput = await getInputFromUser(
    request.params.message,
    request.params.requestedSchema,
  );

  // Return the result with one of three actions:
  return {
    action: 'accept', // or 'decline' or 'cancel'
    content: userInput, // only required when action is 'accept'
  };
});
```

### 引导响应动作

你的处理器必须返回一个带有 `action` 字段的对象，取值可以为：

- `'accept'`：用户提供了所请求的信息。必须包含带有数据的 `content`。
- `'decline'`：用户选择不提供该信息。
- `'cancel'`：用户完全取消了该操作。

## 检测工具定义漂移（"rug pull"）

MCP 服务器会在你的应用首次连接时发送工具定义（名称、描述、输入 schema），通常你会在此刻审查并批准它们。协议中没有任何机制阻止服务器在之后为同一工具名提供*不同*的定义——例如描述中携带注入指令，或输入 schema 被额外字段拓宽。由于 SDK 在每次调用时使用的都是你传入的工具，后续 `mcpClient.tools()` 获取到的被篡改定义会被直接使用，不会与已批准的内容做任何比对。这就是 MCP 的 ["rug pull"](https://invariantlabs.ai/blog/mcp-security-notification-tool-poisoning-attacks) 类攻击。

AI SDK 提供两个函数来固定已批准的定义并检测变更。`fingerprintTools` 将每个工具中由服务器控制的、与安全相关的字段（字符串 `description`、解析后的输入 schema 和 `title`）摘要为稳定的"工具名 → 摘要"映射。`detectToolDrift` 对两个这样的映射做差分。基线的存储与对漂移的响应（阻断、强制重新审批或告警）由你的应用负责：

```typescript
import { fingerprintTools, detectToolDrift } from 'ai';

// Trust time (first connect, human-reviewed): capture and persist the baseline.
const baseline = await fingerprintTools(await mcpClient.tools());

// Every later fetch, before handing tools to generateText:
const tools = await mcpClient.tools();
const drift = detectToolDrift(await fingerprintTools(tools), baseline);

if (drift.changed.length || drift.added.length) {
  // A pinned definition changed, or a new tool appeared. Block, re-approve,
  // or alert per your policy — do not silently pass `tools` to the model.
}
```

<Note>
  这能检测出工具描述、输入 schema 或标题被篡改的情况——即提示词注入与 schema 拓宽这两类攻击面。它无法检测名称、描述和 schema 均未改变的行为/端点调包，因为工具在 MCP 服务器上远程运行，这种变更对客户端不可见。Core 保持中立：它不持久化基线，也不阻断调用——这些是你的应用的责任。
</Note>
