# Language Model Middleware

语言模型中间件（middleware）是一种通过拦截并修改对语言模型的调用来增强语言模型行为的方式。

它可用于以与具体语言模型无关的方式添加护栏（guardrails）、RAG、缓存和日志记录等特性。这类中间件可以独立于其所应用的语言模型进行开发和分发。

## 使用语言模型中间件

你可以通过 `wrapLanguageModel` 函数使用语言模型中间件。它接收一个语言模型和一个语言模型中间件，并返回一个融合了该中间件的新语言模型。

```ts
import { wrapLanguageModel, streamText } from 'ai';

const wrappedLanguageModel = wrapLanguageModel({
  model: yourModel,
  middleware: yourLanguageModelMiddleware,
});
```

包装后的语言模型可以像任何其他语言模型一样使用，例如在 `streamText` 中：

```ts highlight="2"
const result = streamText({
  model: wrappedLanguageModel,
  prompt: 'What cities are in the United States?',
});
```

## 多个中间件

你可以向 `wrapLanguageModel` 函数提供多个中间件。这些中间件会按照提供的顺序依次应用。

```ts
const wrappedLanguageModel = wrapLanguageModel({
  model: yourModel,
  middleware: [firstMiddleware, secondMiddleware],
});

// applied as: firstMiddleware(secondMiddleware(yourModel))
```

## 内置中间件

AI SDK 自带多个内置中间件，可用于配置语言模型：

- `extractReasoningMiddleware`：从生成的文本中提取推理（reasoning）信息，并将其作为 `reasoning` 属性暴露在结果上。
- `extractJsonMiddleware`：通过剥离 markdown 代码围栏从文本内容中提取 JSON。在将 `Output.object()` 与会把 JSON 响应包裹在代码块中的模型搭配使用时很有用。
- `simulateStreamingMiddleware`：用非流式语言模型的响应模拟流式行为。
- `defaultInstructionsMiddleware`：在调用未提供自身指令时应用默认指令。
- `defaultSettingsMiddleware`：为语言模型应用默认设置。
- `addToolInputExamplesMiddleware`：将工具输入示例添加到工具描述中，适用于原生不支持 `inputExamples` 属性的提供商。

### 提取推理

一些提供商和模型会使用特殊标签（如 &lt;think&gt; 和 &lt;/think&gt;）在生成的文本中暴露推理信息。

`extractReasoningMiddleware` 函数可用于提取这些推理信息，并将其作为 `reasoning` 属性暴露在结果上。

```ts
import { wrapLanguageModel, extractReasoningMiddleware } from 'ai';

const model = wrapLanguageModel({
  model: yourModel,
  middleware: extractReasoningMiddleware({ tagName: 'think' }),
});
```

然后你就可以在 `generateText` 和 `streamText` 等函数中使用这个增强后的模型。

`extractReasoningMiddleware` 函数还包含一个 `startWithReasoning` 选项。当设置为 `true` 时，推理标签会被前置到生成的文本之前。这对于响应开头不包含推理标签的模型很有用。更多细节请参阅 [DeepSeek R1 指南](/cookbook/guides/r1#deepseek-r1-middleware)。

### 提取 JSON

有些模型即使在你请求结构化输出时，也会把 JSON 响应包裹在 markdown 代码围栏（例如 ` ```json ... ``` `）中。

`extractJsonMiddleware` 函数会从响应中剥离这些代码围栏，使其与 `Output.object()` 兼容。

```ts
import {
  wrapLanguageModel,
  extractJsonMiddleware,
  Output,
  generateText,
} from 'ai';
import { z } from 'zod';

const model = wrapLanguageModel({
  model: yourModel,
  middleware: extractJsonMiddleware(),
});

const result = await generateText({
  model,
  output: Output.object({
    schema: z.object({
      name: z.string(),
      ingredients: z.array(z.string()),
    }),
  }),
  prompt: 'Generate a recipe.',
});
```

对于使用不同格式的模型，你还可以提供自定义的 transform 函数：

```ts
const model = wrapLanguageModel({
  model: yourModel,
  middleware: extractJsonMiddleware({
    transform: text => text.replace(/^PREFIX/, '').replace(/SUFFIX$/, ''),
  }),
});
```

### 模拟流式

`simulateStreamingMiddleware` 函数可用于用非流式语言模型的响应来模拟流式行为。当你希望在使用只提供完整响应的模型时仍保持一致的流式接口，这会很有用。

```ts
import { wrapLanguageModel, simulateStreamingMiddleware } from 'ai';

const model = wrapLanguageModel({
  model: yourModel,
  middleware: simulateStreamingMiddleware(),
});
```

### 默认设置

`defaultSettingsMiddleware` 函数可用于为语言模型应用默认设置。

```ts
import { wrapLanguageModel, defaultSettingsMiddleware } from 'ai';

const model = wrapLanguageModel({
  model: yourModel,
  middleware: defaultSettingsMiddleware({
    settings: {
      temperature: 0.5,
      maxOutputTokens: 800,
      providerOptions: { openai: { store: false } },
    },
  }),
});
```

### 默认指令

`defaultInstructionsMiddleware` 函数会为尚不包含系统消息的调用应用指令。直接在调用上提供的指令优先于默认值。

```ts
import { wrapLanguageModel, defaultInstructionsMiddleware } from 'ai';

const model = wrapLanguageModel({
  model: yourModel,
  middleware: defaultInstructionsMiddleware({
    instructions: 'You are a concise technical assistant.',
  }),
});
```

当你需要在指令上附带提供商选项（provider options）时，`instructions` 选项也接受一个 `SystemModelMessage` 或 `SystemModelMessage` 对象数组。

<Note>
  该中间件会把归一化提示词（prompt）中的任何系统消息视为调用级指令，并且不会添加默认值。只应在可信的消息历史中启用 `allowSystemInMessages`，因为该历史中的系统消息可能会覆盖这些默认值。
</Note>

### 添加工具输入示例

`addToolInputExamplesMiddleware` 函数会将工具输入示例添加到工具描述中。这对于原生不支持工具上 `inputExamples` 属性的提供商很有用。该中间件会将示例序列化进工具的描述文本，使模型仍然能从示例输入中获益。

```ts
import { wrapLanguageModel, addToolInputExamplesMiddleware } from 'ai';

const model = wrapLanguageModel({
  model: yourModel,
  middleware: addToolInputExamplesMiddleware({
    prefix: 'Input Examples:',
  }),
});
```

当你使用 `inputExamples` 定义工具时，中间件会把这些示例追加到工具的描述中：

```ts
import { generateText, tool } from 'ai';
import { z } from 'zod';

const result = await generateText({
  model, // wrapped model from above
  tools: {
    weather: tool({
      description: 'Get the weather in a location',
      inputSchema: z.object({
        location: z.string(),
      }),
      inputExamples: [
        { input: { location: 'San Francisco' } },
        { input: { location: 'London' } },
      ],
    }),
  },
  prompt: 'What is the weather in Tokyo?',
});
```

工具描述将被转换为：

```
Get the weather in a location

Input Examples:
{"location":"San Francisco"}
{"location":"London"}
```

#### 选项

- `prefix`（可选）：前置在示例之前的文本。默认值：`'Input Examples:'`。
- `format`（可选）：每个示例的自定义格式化函数。接收示例对象及其索引。默认值：`JSON.stringify(example.input)`。
- `remove`（可选）：是否在把示例添加到描述之后从工具中移除 `inputExamples` 属性。默认值：`true`。

```ts
const model = wrapLanguageModel({
  model: yourModel,
  middleware: addToolInputExamplesMiddleware({
    prefix: 'Input Examples:',
    format: (example, index) =>
      `${index + 1}. ${JSON.stringify(example.input)}`,
    remove: true,
  }),
});
```

## 社区中间件

AI SDK 提供了一份语言模型中间件规范。社区成员可以开发遵循该规范的中间件，使其与 AI SDK 生态系统兼容。

以下是一些值得探索的社区中间件：

### 自定义工具调用解析器

[自定义工具调用解析器](https://github.com/minpeter/ai-sdk-tool-call-middleware)中间件为原生不支持 OpenAI 风格 `tools` 参数的模型扩展了工具调用能力。这包括许多缺乏原生函数调用（function calling）特性的自托管模型和第三方模型。

<Note>
  在已支持原生函数调用的模型上使用此中间件可能导致意外的性能下降，因此在决定使用之前，请先确认你的模型是否支持原生函数调用。
</Note>

该中间件通过将函数 schema 转换为提示词指令，并把模型的响应解析为结构化的函数调用来实现函数调用能力。其工作方式是：先将 JSON 函数定义转换成模型能够理解的自然语言指令，再分析生成的文本以提取函数调用尝试。这种方式让开发者能够在不同的模型提供商之间使用相同的函数调用 API，即使是原生不支持 OpenAI 风格函数调用格式的模型也不例外，从而无论底层模型实现如何，都能提供一致的函数调用体验。

`@ai-sdk-tool/parser` 包提供了三种中间件变体：

- `createToolMiddleware`：一个灵活的函数，用于创建针对特定模型定制的自定义工具调用中间件
- `hermesToolMiddleware`：面向 Hermes 和 Qwen 格式函数调用的开箱即用中间件
- `gemmaToolMiddleware`：为 Gemma 3 模型系列的函数调用格式预先配置好的中间件

下面展示了如何为原生不支持函数调用的 Gemma 模型启用函数调用：

```ts
import { wrapLanguageModel } from 'ai';
import { gemmaToolMiddleware } from '@ai-sdk-tool/parser';

const model = wrapLanguageModel({
  model: openrouter('google/gemma-3-27b-it'),
  middleware: gemmaToolMiddleware,
});
```

更多示例请访问此[链接](https://github.com/minpeter/ai-sdk-tool-call-middleware/tree/main/examples/core/src)。

## 实现语言模型中间件

<Note>
  实现语言模型中间件属于高级功能，需要对[语言模型规范](https://github.com/vercel/ai/blob/main/packages/provider/src/language-model/v4/language-model-v4.ts)有扎实的理解。
</Note>

你可以实现以下三个函数中的任意一个来修改语言模型的行为：

1. `transformParams`：在参数传递给语言模型之前对其进行转换，对 `doGenerate` 和 `doStream` 均生效。
2. `wrapGenerate`：包装[语言模型](https://github.com/vercel/ai/blob/main/packages/provider/src/language-model/v4/language-model-v4.ts)的 `doGenerate` 方法。
   你可以修改参数、调用语言模型并修改结果。
3. `wrapStream`：包装[语言模型](https://github.com/vercel/ai/blob/main/packages/provider/src/language-model/v4/language-model-v4.ts)的 `doStream` 方法。
   你可以修改参数、调用语言模型并修改结果。

每个 `LanguageModelV4Middleware` 对象都必须设置 `specificationVersion: 'v4'`。

以下是一些实现语言模型中间件的示例：

## 示例

<Note>
  这些示例并非用于生产环境。它们只是展示如何使用中间件来增强语言模型的行为。
</Note>

### 日志记录

此示例展示如何记录语言模型调用的参数与生成的文本。

```ts
import type {
  LanguageModelV4Middleware,
  LanguageModelV4StreamPart,
} from '@ai-sdk/provider';

export const yourLogMiddleware: LanguageModelV4Middleware = {
  specificationVersion: 'v4',

  wrapGenerate: async ({ doGenerate, params }) => {
    console.log('doGenerate called');
    console.log(`params: ${JSON.stringify(params, null, 2)}`);

    const result = await doGenerate();
    const generatedText = result.content
      .filter(part => part.type === 'text')
      .map(part => part.text)
      .join('');

    console.log('doGenerate finished');
    console.log(`generated text: ${generatedText}`);

    return result;
  },

  wrapStream: async ({ doStream, params }) => {
    console.log('doStream called');
    console.log(`params: ${JSON.stringify(params, null, 2)}`);

    const { stream, ...rest } = await doStream();

    let generatedText = '';
    const textBlocks = new Map<string, string>();

    const transformStream = new TransformStream<
      LanguageModelV4StreamPart,
      LanguageModelV4StreamPart
    >({
      transform(chunk, controller) {
        switch (chunk.type) {
          case 'text-start': {
            textBlocks.set(chunk.id, '');
            break;
          }
          case 'text-delta': {
            const existing = textBlocks.get(chunk.id) || '';
            textBlocks.set(chunk.id, existing + chunk.delta);
            generatedText += chunk.delta;
            break;
          }
          case 'text-end': {
            console.log(
              `Text block ${chunk.id} completed:`,
              textBlocks.get(chunk.id),
            );
            break;
          }
        }

        controller.enqueue(chunk);
      },

      flush() {
        console.log('doStream finished');
        console.log(`generated text: ${generatedText}`);
      },
    });

    return {
      stream: stream.pipeThrough(transformStream),
      ...rest,
    };
  },
};
```

### 缓存

此示例展示如何为语言模型调用生成的文本构建一个简单的缓存。

```ts
import type { LanguageModelV4Middleware } from '@ai-sdk/provider';

const cache = new Map<string, any>();

export const yourCacheMiddleware: LanguageModelV4Middleware = {
  specificationVersion: 'v4',

  wrapGenerate: async ({ doGenerate, params }) => {
    const cacheKey = JSON.stringify(params);

    if (cache.has(cacheKey)) {
      return cache.get(cacheKey);
    }

    const result = await doGenerate();

    cache.set(cacheKey, result);

    return result;
  },

  // here you would implement the caching logic for streaming
};
```

### 检索增强生成（RAG）

此示例展示如何将 RAG 用作中间件。

<Note>
  `getLastUserMessageText` 和 `findSources` 等辅助函数并不属于 AI SDK。它们只是在本示例中用来阐述 RAG 的概念。
</Note>

```ts
import type { LanguageModelV4Middleware } from '@ai-sdk/provider';

export const yourRagMiddleware: LanguageModelV4Middleware = {
  specificationVersion: 'v4',

  transformParams: async ({ params }) => {
    const lastUserMessageText = getLastUserMessageText({
      prompt: params.prompt,
    });

    if (lastUserMessageText == null) {
      return params; // do not use RAG (send unmodified parameters)
    }

    const instruction =
      'Use the following information to answer the question:\n' +
      findSources({ text: lastUserMessageText })
        .map(chunk => JSON.stringify(chunk))
        .join('\n');

    return addToLastUserMessage({ params, text: instruction });
  },
};
```

### 护栏

护栏（guardrails）是一种确保语言模型调用所生成的文本安全且得体的方式。此示例展示如何将护栏用作中间件。

```ts
import type {
  LanguageModelV4Middleware,
  LanguageModelV4StreamPart,
} from '@ai-sdk/provider';

const redactText = (text: string) => text.replace(/badword/g, '<REDACTED>');

export const yourGuardrailMiddleware: LanguageModelV4Middleware = {
  specificationVersion: 'v4',

  wrapGenerate: async ({ doGenerate }) => {
    const result = await doGenerate();

    // filtering approach, e.g. for PII or other sensitive information:
    const content = result.content.map(part =>
      part.type === 'text' ? { ...part, text: redactText(part.text) } : part,
    );

    return { ...result, content };
  },

  wrapStream: async ({ doStream }) => {
    const { stream, ...rest } = await doStream();

    // Keep a separate buffer for each text block in the stream.
    const buffers = new Map<string, string>();

    const transformStream = new TransformStream<
      LanguageModelV4StreamPart,
      LanguageModelV4StreamPart
    >({
      transform(chunk, controller) {
        if (chunk.type === 'text-start') {
          buffers.set(chunk.id, '');
          controller.enqueue(chunk);
          return;
        }

        if (chunk.type === 'text-delta') {
          buffers.set(chunk.id, (buffers.get(chunk.id) ?? '') + chunk.delta);
          return;
        }

        if (chunk.type === 'text-end') {
          const bufferedText = buffers.get(chunk.id);

          if (bufferedText != null) {
            const redactedText = redactText(bufferedText);

            if (redactedText) {
              controller.enqueue({
                type: 'text-delta',
                id: chunk.id,
                delta: redactedText,
              });
            }

            buffers.delete(chunk.id);
          }
        }

        controller.enqueue(chunk);
      },

      flush(controller) {
        for (const [id, bufferedText] of buffers) {
          const redactedText = redactText(bufferedText);

          if (redactedText) {
            controller.enqueue({
              type: 'text-delta',
              id,
              delta: redactedText,
            });
          }
        }
      },
    });

    return {
      stream: stream.pipeThrough(transformStream),
      ...rest,
    };
  },
};
```

<Note>
  该流式示例会把每个文本块一直缓冲到 `text-end`，这样跨 `text-delta` 分块拆分的匹配内容就不会泄漏出去。这会延迟输出，且内存占用与文本块大小成正比。不要对每个增量（delta）独立进行脱敏。增量式实现必须保留所有可能的不完整匹配，仅靠固定大小的缓冲区对于无界变长模式并不安全。
</Note>

## 配置每次请求的自定义元数据

要在中间件中发送和访问自定义元数据，可以使用 `providerOptions`。在构建日志中间件时这很有用：你可能希望传递诸如用户 ID、时间戳或其他有助于跟踪与调试的上下文数据等附加信息。

```ts
import { generateText, wrapLanguageModel } from 'ai';
__PROVIDER_IMPORT__;
import type { LanguageModelV4Middleware } from '@ai-sdk/provider';

export const yourLogMiddleware: LanguageModelV4Middleware = {
  specificationVersion: 'v4',

  wrapGenerate: async ({ doGenerate, params }) => {
    console.log('METADATA', params?.providerMetadata?.yourLogMiddleware);
    const result = await doGenerate();
    return result;
  },
};

const { text } = await generateText({
  model: wrapLanguageModel({
    model: __MODEL__,
    middleware: yourLogMiddleware,
  }),
  prompt: 'Invent a new holiday and describe its traditions.',
  providerOptions: {
    yourLogMiddleware: {
      hello: 'world',
    },
  },
});

console.log(text);
```
