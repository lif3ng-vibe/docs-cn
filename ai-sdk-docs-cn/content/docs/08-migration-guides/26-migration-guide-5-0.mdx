# Migrate AI SDK 4.x to 5.0

## 推荐的迁移流程

1. 备份你的项目。如果你使用版本控制系统，请确保此前所有版本均已提交。
1. 升级到 AI SDK 5.0。
1. 使用以下任一方式自动迁移代码：
   - 使用 [AI SDK 5 迁移 MCP 服务器](#ai-sdk-5-迁移-mcp-服务器) 在 Cursor 或其他支持 MCP 的编码智能体（agent）中进行 AI 辅助迁移
   - 使用 [Codemods](#codemods) 自动转换代码
1. 按照下方的破坏性变更指南操作。
1. 验证项目按预期工作。
1. 提交你的变更。

## AI SDK 5 迁移 MCP 服务器

[AI SDK 5 迁移模型上下文协议（MCP）服务器](https://github.com/vercel-labs/ai-sdk-5-migration-mcp-server)提供了一种借助编码智能体自动迁移项目的方式。该服务器为 Cursor 设计，但应可在任何支持 MCP 的编码智能体中使用。

开始使用：在项目中创建或编辑 `.cursor/mcp.json`：

```json
{
  "mcpServers": {
    "ai-sdk-5-migration": {
      "url": "https://ai-sdk-5-migration-mcp-server.vercel.app/api/mcp"
    }
  }
}
```

保存后，打开命令面板（macOS 上为 Cmd+Shift+P，Windows/Linux 上为 Ctrl+Shift+P），搜索"View: Open MCP Settings"。确认新服务器已出现并处于开启状态。

然后使用以下提示词（prompt）：

```
Please migrate this project to AI SDK 5 using the ai-sdk-5-migration mcp server. Start by creating a checklist.
```

更多信息请参阅 [AI SDK 5 迁移 MCP 服务器仓库](https://github.com/vercel-labs/ai-sdk-5-migration-mcp-server)。

## AI SDK 5.0 包版本

你需要在 `package.json` 文件中将以下包更新到相应版本：

- `ai` 包：`5.0.0`
- `@ai-sdk/provider` 包：`2.0.0`
- `@ai-sdk/provider-utils` 包：`3.0.0`
- `@ai-sdk/*` 包：`2.0.0`（其他 `@ai-sdk` 包）

此外，还需要更新以下 peer 依赖：

- `zod` 包：`4.1.8` 或更高版本（推荐，以避免 TypeScript 性能问题）

升级命令示例：

```
npm install ai @ai-sdk/react @ai-sdk/openai zod@^4.1.8
```

<Note>
  如果升级后遇到 TypeScript 性能问题，请确保使用 Zod 4.1.8 或更高版本。如果问题仍然存在，请更新 `tsconfig.json`，使用 `moduleResolution: "nodenext"`。更多详情请参阅 [TypeScript 性能故障排查指南](/docs/troubleshooting/typescript-performance-zod)。
</Note>

## Codemods

当某个功能被弃用、移除或发生其他变更时，AI SDK 提供 Codemod 转换来帮助你升级代码库。

Codemod 是自动在代码库上运行的转换。它们让你无需手动遍历每个文件，即可轻松应用大量变更。

<Note>
  Codemod 旨在辅助你完成升级过程。它们可能无法覆盖你需要做出的所有变更，你可能还需要手动进行额外修改。
</Note>

从项目根目录运行以下命令，即可执行 5.0 升级流程提供的全部 codemod：

```sh
npx @ai-sdk/codemod upgrade
```

仅运行 v5 codemod（v4 → v5 迁移）：

```sh
npx @ai-sdk/codemod v5
```

也可以指定 codemod 名称单独运行：

```sh
npx @ai-sdk/codemod <codemod-name> <path>
```

例如，运行某个特定的 v5 codemod：

```sh
npx @ai-sdk/codemod v5/rename-format-stream-part src/
```

另请参阅 [codemod 对照表](#codemod-对照表)。此外，最新的一批 codemod 可在 [`@ai-sdk/codemod`](https://github.com/vercel/ai/tree/main/packages/codemod/src/codemods) 仓库中找到。

## AI SDK Core 变更

### generateText 与 streamText 变更

#### 最大输出 token 数

为清晰起见，`maxTokens` 参数已更名为 `maxOutputTokens`。

```tsx filename="AI SDK 4.0"
const result = await generateText({
  model: __MODEL__,
  maxTokens: 1024,
  prompt: 'Hello, world!',
});
```

```tsx filename="AI SDK 5.0"
const result = await generateText({
  model: __MODEL__,
  maxOutputTokens: 1024,
  prompt: 'Hello, world!',
});
```

### 消息与类型系统变更

#### 核心类型重命名

##### `CoreMessage` → `ModelMessage`

```tsx filename="AI SDK 4.0"
import { CoreMessage } from 'ai';
```

```tsx filename="AI SDK 5.0"
import { ModelMessage } from 'ai';
```

##### `Message` → `UIMessage`

```tsx filename="AI SDK 4.0"
import { Message, CreateMessage } from 'ai';
```

```tsx filename="AI SDK 5.0"
import { UIMessage, CreateUIMessage } from 'ai';
```

##### `convertToCoreMessages` → `convertToModelMessages`

```tsx filename="AI SDK 4.0"
import { convertToCoreMessages, streamText } from 'ai';

const result = await streamText({
  model: __MODEL__,
  messages: convertToCoreMessages(messages),
});
```

```tsx filename="AI SDK 5.0"
import { convertToModelMessages, streamText } from 'ai';

const result = await streamText({
  model: __MODEL__,
  messages: convertToModelMessages(messages),
});
```

<Note>
  有关模型消息的更多信息，请参阅 [Model Message 参考](/docs/reference/ai-sdk-core/model-message)。
</Note>

### UIMessage 变更

#### content → parts 数组

对于 `UIMessage`（此前称为 `Message`），`.content` 属性已被 `parts` 数组结构取代。

```tsx filename="AI SDK 4.0"
import { type Message } from 'ai'; // v4 Message type

// Messages (useChat) - had content property
const message: Message = {
  id: '1',
  role: 'user',
  content: 'Bonjour!',
};
```

```tsx filename="AI SDK 5.0"
import { type UIMessage, type ModelMessage } from 'ai';

// UIMessages (useChat) - now use parts array
const uiMessage: UIMessage = {
  id: '1',
  role: 'user',
  parts: [{ type: 'text', text: 'Bonjour!' }],
};
```

#### data 角色已移除

`data` 角色已从 UI 消息中移除。

```tsx filename="AI SDK 4.0"
const message = {
  role: 'data',
  content: 'Some content',
  data: { customField: 'value' },
};
```

```tsx filename="AI SDK 5.0"
// V5: Use UI message streams with custom data parts
const stream = createUIMessageStream({
  execute({ writer }) {
    // Write custom data instead of message annotations
    writer.write({
      type: 'data-custom',
      id: 'custom-1',
      data: { customField: 'value' },
    });
  },
});
```

#### UIMessage 推理结构

UI 消息上的 reasoning 属性已移至 parts 中。

```tsx filename="AI SDK 4.0"
const message: Message = {
  role: 'assistant',
  content: 'Hello',
  reasoning: 'I will greet the user',
};
```

```tsx filename="AI SDK 5.0"
const message: UIMessage = {
  role: 'assistant',
  parts: [
    {
      type: 'reasoning',
      text: 'I will greet the user',
    },
    {
      type: 'text',
      text: 'Hello',
    },
  ],
};
```

#### 推理部分属性重命名

推理 UI 部分上的 `reasoning` 属性已更名为 `text`。

```tsx filename="AI SDK 4.0"
{
  message.parts.map((part, index) => {
    if (part.type === 'reasoning') {
      return (
        <div key={index} className="reasoning-display">
          {part.reasoning}
        </div>
      );
    }
  });
}
```

```tsx filename="AI SDK 5.0"
{
  message.parts.map((part, index) => {
    if (part.type === 'reasoning') {
      return (
        <div key={index} className="reasoning-display">
          {part.text}
        </div>
      );
    }
  });
}
```

### 文件部分（file part）变更

文件部分现在使用 `.url`，取代原先的 `.data` 和 `.mimeType`。

```tsx filename="AI SDK 4.0"
{
  messages.map(message => (
    <div key={message.id}>
      {message.parts.map((part, index) => {
        if (part.type === 'text') {
          return <div key={index}>{part.text}</div>;
        } else if (part.type === 'file' && part.mimeType.startsWith('image/')) {
          return (
            <img
              key={index}
              src={`data:${part.mimeType};base64,${part.data}`}
            />
          );
        }
      })}
    </div>
  ));
}
```

```tsx filename="AI SDK 5.0"
{
  messages.map(message => (
    <div key={message.id}>
      {message.parts.map((part, index) => {
        if (part.type === 'text') {
          return <div key={index}>{part.text}</div>;
        } else if (
          part.type === 'file' &&
          part.mediaType.startsWith('image/')
        ) {
          return <img key={index} src={part.url} />;
        }
      })}
    </div>
  ));
}
```

### Stream Data 移除

`StreamData` 类已被完全移除，由用于自定义数据的 UI 消息流取代。

```tsx filename="AI SDK 4.0"
import { StreamData } from 'ai';

const streamData = new StreamData();
streamData.append('custom-data');
streamData.close();
```

```tsx filename="AI SDK 5.0"
import { createUIMessageStream, createUIMessageStreamResponse } from 'ai';

const stream = createUIMessageStream({
  execute({ writer }) {
    // Write custom data parts
    writer.write({
      type: 'data-custom',
      id: 'custom-1',
      data: 'custom-data',
    });

    // Can merge with LLM streams
    const result = streamText({
      model: __MODEL__,
      messages,
    });

    writer.merge(result.toUIMessageStream());
  },
});

return createUIMessageStreamResponse({ stream });
```

### 自定义数据流式传输：writeMessageAnnotation/writeData 已移除

`DataStreamWriter` 中的 `writeMessageAnnotation` 和 `writeData` 方法已被移除。请改为在新的 `UIMessage` 流架构中使用自定义数据部分（data part）。

```tsx filename="AI SDK 4.0"
import { createDataStreamResponse, streamText } from 'ai';

export async function POST(req: Request) {
  const { messages } = await req.json();

  return createDataStreamResponse({
    execute: dataStream => {
      // Write general data
      dataStream.writeData('call started');

      const result = streamText({
        model: __MODEL__,
        messages,
        onChunk() {
          // Write message annotations
          dataStream.writeMessageAnnotation({
            status: 'streaming',
            timestamp: Date.now(),
          });
        },
        onFinish() {
          // Write final annotations
          dataStream.writeMessageAnnotation({
            id: generateId(),
            completed: true,
          });

          dataStream.writeData('call completed');
        },
      });

      result.mergeIntoDataStream(dataStream);
    },
  });
}
```

```tsx filename="AI SDK 5.0"
import {
  createUIMessageStream,
  createUIMessageStreamResponse,
  streamText,
  generateId,
} from 'ai';

export async function POST(req: Request) {
  const { messages } = await req.json();

  const stream = createUIMessageStream({
    execute: ({ writer }) => {
      const statusId = generateId();

      // Write general data (transient - not added to message history)
      writer.write({
        type: 'data-status',
        id: statusId,
        data: { status: 'call started' },
      });

      const result = streamText({
        model: __MODEL__,
        messages,
        onChunk() {
          // Write data parts that update during streaming
          writer.write({
            type: 'data-status',
            id: statusId,
            data: {
              status: 'streaming',
              timestamp: Date.now(),
            },
          });
        },
        onFinish() {
          // Write final data parts
          writer.write({
            type: 'data-status',
            id: statusId,
            data: {
              status: 'completed',
            },
          });
        },
      });

      writer.merge(result.toUIMessageStream());
    },
  });

  return createUIMessageStreamResponse({ stream });
}
```

<Note>
  有关 v5 中流式传输自定义数据的更多详细信息，请参阅[流式数据指南](/docs/ai-sdk-ui/streaming-data)。
</Note>

##### providerMetadata → providerOptions

输入参数 `providerMetadata` 已更名为 `providerOptions`。注意，结果中返回的元数据仍称为 `providerMetadata`。

```tsx filename="AI SDK 4.0"
const result = await generateText({
  model: 'openai/gpt-5',
  prompt: 'Hello',
  providerMetadata: {
    openai: { store: false },
  },
});
```

```tsx filename="AI SDK 5.0"
const result = await generateText({
  model: 'openai/gpt-5',
  prompt: 'Hello',
  providerOptions: {
    // Input parameter renamed
    openai: { store: false },
  },
});

// Returned metadata still uses providerMetadata:
console.log(result.providerMetadata?.openai);
```

#### 工具定义变更（parameters → inputSchema）

工具定义已更新为使用 `inputSchema` 取代 `parameters`，错误类也已更名。

```tsx filename="AI SDK 4.0"
import { tool } from 'ai';

const weatherTool = tool({
  description: 'Get the weather for a city',
  parameters: z.object({
    city: z.string(),
  }),
  execute: async ({ city }) => {
    return `Weather in ${city}`;
  },
});
```

```tsx filename="AI SDK 5.0"
import { tool } from 'ai';

const weatherTool = tool({
  description: 'Get the weather for a city',
  inputSchema: z.object({
    city: z.string(),
  }),
  execute: async ({ city }) => {
    return `Weather in ${city}`;
  },
});
```

#### 工具结果内容：experimental_toToolResultContent → toModelOutput

`experimental_toToolResultContent` 选项已更名为 `toModelOutput`，不再是实验性功能。

```tsx filename="AI SDK 4.0"
const screenshotTool = tool({
  description: 'Take a screenshot',
  parameters: z.object({}),
  execute: async () => {
    const imageData = await takeScreenshot();
    return imageData; // base64 string
  },
  experimental_toToolResultContent: result => [{ type: 'image', data: result }],
});
```

```tsx filename="AI SDK 5.0"
const screenshotTool = tool({
  description: 'Take a screenshot',
  inputSchema: z.object({}),
  execute: async () => {
    const imageData = await takeScreenshot();
    return imageData;
  },
  toModelOutput: result => ({
    type: 'content',
    value: [{ type: 'media', mediaType: 'image/png', data: result }],
  }),
});
```

### 工具属性变更（args/result → input/output）

工具调用与结果的属性已更名，以便与 schema 保持更好的一致性。

```tsx filename="AI SDK 4.0"
// Tool calls used "args" and "result"
for await (const part of result.fullStream) {
  switch (part.type) {
    case 'tool-call':
      console.log('Tool args:', part.args);
      break;
    case 'tool-result':
      console.log('Tool result:', part.result);
      break;
  }
}
```

```tsx filename="AI SDK 5.0"
// Tool calls now use "input" and "output"
for await (const part of result.fullStream) {
  switch (part.type) {
    case 'tool-call':
      console.log('Tool input:', part.input);
      break;
    case 'tool-result':
      console.log('Tool output:', part.output);
      break;
  }
}
```

### 工具执行错误处理

`ToolExecutionError` 类已被移除。工具执行错误现在会作为 `tool-error` 内容部分出现在结果步骤中，从而在多步场景中支持自动化的 LLM 往返。

```tsx filename="AI SDK 4.0"
import { ToolExecutionError } from 'ai';

try {
  const result = await generateText({
    // ...
  });
} catch (error) {
  if (error instanceof ToolExecutionError) {
    console.log('Tool execution failed:', error.message);
    console.log('Tool name:', error.toolName);
    console.log('Tool input:', error.toolInput);
  }
}
```

```tsx filename="AI SDK 5.0"
// Tool execution errors now appear in result steps
const { steps } = await generateText({
  // ...
});

// check for tool errors in the steps
const toolErrors = steps.flatMap(step =>
  step.content.filter(part => part.type === 'tool-error'),
);

toolErrors.forEach(toolError => {
  console.log('Tool error:', toolError.error);
  console.log('Tool name:', toolError.toolName);
  console.log('Tool input:', toolError.input);
});
```

在流式场景中，工具执行错误会以 `tool-error` 部分的形式出现在流中，而其他错误则以 `error` 部分的形式出现。

### 工具调用流式传输默认开启（toolCallStreaming 已移除）

`toolCallStreaming` 选项在 AI SDK 5.0 中已被移除。工具调用流式传输现在默认始终启用。

```tsx filename="AI SDK 4.0"
const result = streamText({
  model: __MODEL__,
  messages,
  toolCallStreaming: true, // Optional parameter to enable streaming
  tools: {
    weatherTool,
    searchTool,
  },
});
```

```tsx filename="AI SDK 5.0"
const result = streamText({
  model: __MODEL__,
  messages: convertToModelMessages(messages),
  // toolCallStreaming removed - streaming is always enabled
  tools: {
    weatherTool,
    searchTool,
  },
});
```

### 工具部分类型变更（UIMessage）

在 v5 中，UI 工具部分使用类型化命名：`tool-${toolName}`，取代通用类型。

```tsx filename="AI SDK 4.0"
// Generic tool-invocation type
{
  message.parts.map(part => {
    if (part.type === 'tool-invocation') {
      return <div>{part.toolInvocation.toolName}</div>;
    }
  });
}
```

```tsx filename="AI SDK 5.0"
// Type-safe tool parts with specific names
{
  message.parts.map(part => {
    switch (part.type) {
      case 'tool-getWeatherInformation':
        return <div>Getting weather...</div>;
      case 'tool-askForConfirmation':
        return <div>Asking for confirmation...</div>;
    }
  });
}
```

### 动态工具支持

AI SDK 5.0 引入动态工具，用于处理在开发时类型未知的工具，例如没有 schema 的 MCP 工具或运行时由用户定义的函数。

#### 新增 dynamicTool 辅助函数

新增的 `dynamicTool` 辅助函数允许你定义输入与输出类型在编译期未知的工具。

```tsx filename="AI SDK 5.0"
import { dynamicTool } from 'ai';
import { z } from 'zod';

// Define a dynamic tool
const runtimeTool = dynamicTool({
  description: 'A tool defined at runtime',
  inputSchema: z.object({}),
  execute: async input => {
    // Input and output are typed as 'unknown'
    const { query } = input as { query: string };
    return { result: `Processed: ${query}` };
  },
});
```

#### 无 schema 的 MCP 工具

未提供 schema 的 MCP 工具现在会自动被视为动态工具：

```tsx filename="AI SDK 5.0"
import { MCPClient } from 'ai';

const client = new MCPClient({
  /* ... */
});
const tools = await client.getTools();

// Tools without schemas are now 'dynamic' type
// and won't break type inference when mixed with static tools
```

#### 混合使用工具时的类型安全处理

同时使用静态工具和动态工具时，请使用 `dynamic` 标志进行类型收窄：

```tsx filename="AI SDK 5.0"
const result = await generateText({
  model: __MODEL__,
  tools: {
    // Static tool with known types
    weather: weatherTool,
    // Dynamic tool with unknown types
    customDynamicTool: dynamicTool({
      /* ... */
    }),
  },
  onStepFinish: step => {
    // Handle tool calls with type safety
    for (const toolCall of step.toolCalls) {
      if (toolCall.dynamic) {
        // Dynamic tool: input/output are 'unknown'
        console.log('Dynamic tool called:', toolCall.toolName);
        continue;
      }

      // Static tools have full type inference
      switch (toolCall.toolName) {
        case 'weather':
          // TypeScript knows the exact types
          console.log(toolCall.input.location); // string
          break;
      }
    }
  },
});
```

#### 新增 dynamic-tool UI 部分

UI 消息现在包含 `dynamic-tool` 部分类型，用于渲染动态工具调用：

```tsx filename="AI SDK 5.0"
{
  message.parts.map((part, index) => {
    switch (part.type) {
      // Static tools use specific types
      case 'tool-weather':
        return <div>Weather: {part.input.city}</div>;

      // Dynamic tools use the generic dynamic-tool type
      case 'dynamic-tool':
        return (
          <div>
            Dynamic tool: {part.toolName}
            <pre>{JSON.stringify(part.input, null, 2)}</pre>
          </div>
        );
    }
  });
}
```

#### 破坏性变更：工具调用与结果需要进行类型收窄

在遍历 `toolCalls` 和 `toolResults` 时，现在需要先检查 `dynamic` 标志才能正确进行类型收窄：

```tsx filename="AI SDK 4.0"
// Direct type checking worked without dynamic flag
onStepFinish: step => {
  for (const toolCall of step.toolCalls) {
    switch (toolCall.toolName) {
      case 'weather':
        console.log(toolCall.input.location); // typed as string
        break;
      case 'search':
        console.log(toolCall.input.query); // typed as string
        break;
    }
  }
};
```

```tsx filename="AI SDK 5.0"
// Must check dynamic flag first for type narrowing
onStepFinish: step => {
  for (const toolCall of step.toolCalls) {
    // Check if it's a dynamic tool first
    if (toolCall.dynamic) {
      console.log('Dynamic tool:', toolCall.toolName);
      console.log('Input:', toolCall.input); // typed as unknown
      continue;
    }

    // Now TypeScript knows it's a static tool
    switch (toolCall.toolName) {
      case 'weather':
        console.log(toolCall.input.location); // typed as string
        break;
      case 'search':
        console.log(toolCall.input.query); // typed as string
        break;
    }
  }
};
```

### 工具 UI 部分状态变更

工具 UI 部分现在使用更细粒度的状态，以更好地表达流式生命周期和错误处理。

```tsx filename="AI SDK 4.0"
// Old states
{
  message.parts.map(part => {
    if (part.type === 'tool-invocation') {
      switch (part.toolInvocation.state) {
        case 'partial-call':
          return <div>Loading...</div>;
        case 'call':
          return (
            <div>
              Tool called with {JSON.stringify(part.toolInvocation.args)}
            </div>
          );
        case 'result':
          return <div>Result: {part.toolInvocation.result}</div>;
      }
    }
  });
}
```

```tsx filename="AI SDK 5.0"
// New granular states
{
  message.parts.map(part => {
    switch (part.type) {
      case 'tool-getWeatherInformation':
        switch (part.state) {
          case 'input-streaming':
            return <pre>{JSON.stringify(part.input, null, 2)}</pre>;
          case 'input-available':
            return <div>Getting weather for {part.input.city}...</div>;
          case 'output-available':
            return <div>Weather: {part.output}</div>;
          case 'output-error':
            return <div>Error: {part.errorText}</div>;
        }
    }
  });
}
```

**状态变更**：

- `partial-call` → `input-streaming`（工具输入正在流式传输）
- `call` → `input-available`（工具输入已完成，准备执行）
- `result` → `output-available`（工具执行成功）
- 新增：`output-error`（工具执行失败）

### 步骤控制：maxSteps → stopWhen

对于 `generateText` 和 `streamText` 等核心函数，`maxSteps` 参数已被 `stopWhen` 取代，后者对多步执行提供更灵活的控制。`stopWhen` 参数定义**在最后一个步骤包含工具结果时**停止生成的条件。当以数组形式提供多个条件时，只要满足其中任一条件生成即停止。

```tsx filename="AI SDK 4.0"
// V4: Simple numeric limit
const result = await generateText({
  model: __MODEL__,
  messages,
  maxSteps: 5, // Stop after a maximum of 5 steps
});

// useChat with maxSteps
const { messages } = useChat({
  maxSteps: 3, // Stop after a maximum of 3 steps
});
```

```tsx filename="AI SDK 5.0"
import { isStepCount, hasToolCall } from 'ai';

// V5: Server-side - flexible stopping conditions with stopWhen
const result = await generateText({
  model: __MODEL__,
  messages,
  // Only triggers when last step has tool results
  stopWhen: isStepCount(5), // Stop at step 5 if tools were called
});

// Server-side - stop when a specific tool is called
const result = await generateText({
  model: __MODEL__,
  messages,
  stopWhen: hasToolCall('finalizeTask'), // Stop when finalizeTask tool is called
});
```

**常用停止模式**：

```tsx filename="AI SDK 5.0"
// Stop after N steps (equivalent to old maxSteps)
// Note: Only applies when the last step has tool results
stopWhen: isStepCount(5);

// Stop when a specific tool is called
stopWhen: hasToolCall('finalizeTask');

// Stop when either tool is called
stopWhen: hasToolCall('submitOrder', 'finalizeTask');

// Multiple conditions (stops if ANY condition is met)
stopWhen: [
  isStepCount(10), // Maximum 10 steps
  hasToolCall('submitOrder'), // Or when order is submitted
];

// Custom condition based on step content
stopWhen: ({ steps }) => {
  const lastStep = steps[steps.length - 1];
  // Custom logic - only triggers if last step has tool results
  return lastStep?.text?.includes('COMPLETE');
};
```

**重要提示**：`stopWhen` 条件仅在最后一个步骤包含工具结果时才会被评估。

#### maxSteps 移除

`maxSteps` 参数已从 `useChat` 中移除。现在你应使用服务端 `stopWhen` 条件控制多步工具执行，并在客户端工具调用时手动提交工具结果、触发新消息。


```tsx filename="AI SDK 5.0"

import { streamText, convertToModelMessages, isStepCount } from 'ai';
__PROVIDER_IMPORT__;

  model: __MODEL__,
  messages: convertToModelMessages(messages),
  stopWhen: isStepCount(5), // Stop after 5 steps with tool calls
});

// Client-side: Configure automatic submission

  DefaultChatTransport,
  lastAssistantMessageIsCompleteWithToolCalls,
} from 'ai';

  // Automatically submit when all tool results are available
  sendAutomaticallyWhen: lastAssistantMessageIsCompleteWithToolCalls,

  async onToolCall({ toolCall }) {
    const result = await executeToolCall(toolCall);

    // Important: Don't await addToolOutput inside onToolCall to avoid deadlocks
    addToolOutput({
      tool: toolCall.toolName,
      toolCallId: toolCall.toolCallId,
      output: result,
    });
  },
});
```

<Note>
  重要：使用 `sendAutomaticallyWhen` 时，不要在 `onToolCall` 内对 `addToolOutput` 使用 `await`，否则可能导致死锁。当你未使用自动提交、需要确保消息在手动调用 `sendMessage()` 之前已更新时，`await` 才有用。
</Note>

这一变更为处理工具调用提供了更大的灵活性，并使客户端行为与服务端多步执行模式保持一致。

有关新工具提交方式的更多细节，请参阅下方的[工具结果提交变更](#工具结果提交变更)章节。

#### 用量信息

在 v4 中，用量信息可通过 `onFinish` 回调的 options 参数直接获取。在 v5 中，用量数据通过 `toUIMessageStreamResponse` 中的 `messageMetadata` 函数以元数据形式附加到各条消息上。

```tsx filename="AI SDK 5.0"
import {
  convertToModelMessages,
  streamText,
  UIMessage,
  type LanguageModelUsage,
} from 'ai';
__PROVIDER_IMPORT__;

// Create a new metadata type (optional for type-safety)
type MyMetadata = {
  totalUsage: LanguageModelUsage;
};

// Create a new custom message type with your own metadata
export type MyUIMessage = UIMessage<MyMetadata>;

export async function POST(req: Request) {
  const { messages }: { messages: MyUIMessage[] } = await req.json();

  const result = streamText({
    model: __MODEL__,
    messages: convertToModelMessages(messages),
  });

  return result.toUIMessageStreamResponse({
    originalMessages: messages,
    messageMetadata: ({ part }) => {
      // Send total usage when generation is finished
      if (part.type === 'finish') {
        return { totalUsage: part.totalUsage };
      }
    },
  });
}
```

### 流式协议变更

#### 流式协议：单块 → start/delta/end 模式

基础流式模式已从单块变为三阶段模式，每个内容块都带有唯一 ID。


```tsx filename="AI SDK 5.0"

  switch (chunk.type) {
    case 'text-start': {
      // New: Initialize a text block with unique ID

      break;
    }
    case 'text-delta': {
      // Changed: Now includes ID and uses 'delta' property
      process.stdout.write(chunk.delta); // Changed from 'textDelta'
      break;
    }
    case 'text-end': {
      // New: Finalize the text block
      console.log(`Completed text block: ${chunk.id}`);
      break;
    }
  }
}

```


## 消息持久化变更

<Note>
  如果你已将消息持久化到数据库，请参阅[数据迁移指南](/docs/migration-guides/migration-guide-5-0-data)，获取将已存储消息数据迁移到 v5 格式的全面指引。
</Note>

在 v4 中，你通常会在 `streamText` 的 `onFinish` 回调里使用 `appendResponseMessages` 或 `appendClientMessage` 等辅助函数来格式化消息：

```tsx filename="AI SDK 4.0"
import {
  streamText,
  convertToModelMessages,
  appendClientMessage,
  appendResponseMessages,
} from 'ai';

const updatedMessages = appendClientMessage({
  messages,
  message: lastUserMessage,
});

const result = streamText({
  model: __MODEL__,
  messages: updatedMessages,
  experimental_generateMessageId: () => generateId(), // ID generation on streamText
  onFinish: async ({ responseMessages, usage }) => {
    // Use helper functions to format messages
    const finalMessages = appendResponseMessages({
      messages: updatedMessages,
      responseMessages,
    });

    // Save formatted messages to database
    await saveMessages(finalMessages);
  },
});
```

在 v5 中，消息持久化现在通过 `toUIMessageStreamResponse` 方法处理，它会自动将响应消息格式化为 `UIMessage` 格式：

```tsx filename="AI SDK 5.0"
import { streamText, convertToModelMessages, UIMessage } from 'ai';

const messages: UIMessage[] = [
  // Your existing messages in UIMessage format
];

const result = streamText({
  model: __MODEL__,
  messages: convertToModelMessages(messages),
  // experimental_generateMessageId removed from here
});

return result.toUIMessageStreamResponse({
  originalMessages: messages, // IMPORTANT: Required to prevent duplicate messages
  generateMessageId: () => generateId(), // IMPORTANT: Required for proper message ID generation
  onFinish: ({ messages, responseMessage }) => {
    // messages contains all messages (original + response) in UIMessage format
    saveChat({ chatId, messages });

    // responseMessage contains just the generated message in UIMessage format
    saveMessage({ chatId, message: responseMessage });
  },
});
```

<Note>
  **重要提示**：使用 `toUIMessageStreamResponse` 时，应始终同时提供 `originalMessages` 和 `generateMessageId` 参数。否则，UI 中可能出现重复的助手消息。更多详情请参阅[故障排查：助手消息重复](/docs/troubleshooting/repeated-assistant-messages)。
</Note>

### 消息 ID 生成

`experimental_generateMessageId` 选项已从 `streamText` 配置移至 `toUIMessageStreamResponse`，因为它面向的是 `UIMessage` 而非 `ModelMessage`。

```tsx filename="AI SDK 4.0"
const result = streamText({
  model: __MODEL__,
  messages,
  experimental_generateMessageId: () => generateId(),
});
```

```tsx filename="AI SDK 5.0"
const result = streamText({
  model: __MODEL__,
  messages: convertToModelMessages(messages),
});

return result.toUIMessageStreamResponse({
  generateMessageId: () => generateId(), // No longer experimental
  // ...
});
```

有关消息 ID 与持久化的更多细节，请参阅[聊天机器人消息持久化指南](/docs/ai-sdk-ui/chatbot-message-persistence#消息-id)。

### 使用 createUIMessageStream

对于更复杂的场景（尤其是涉及数据部分时），可以使用 `createUIMessageStream`：

```tsx filename="AI SDK 5.0 - Advanced"
import {
  createUIMessageStream,
  createUIMessageStreamResponse,
  streamText,
  convertToModelMessages,
  UIMessage,
} from 'ai';

const stream = createUIMessageStream({
  originalMessages: messages,
  generateId: generateId, // Required for proper message ID generation
  execute: ({ writer }) => {
    // Write custom data parts
    writer.write({
      type: 'data',
      data: { status: 'processing', timestamp: Date.now() },
    });

    // Stream the AI response
    const result = streamText({
      model: __MODEL__,
      messages: convertToModelMessages(messages),
    });

    writer.merge(result.toUIMessageStream());
  },
  onFinish: ({ messages }) => {
    // messages contains all messages (original + response + data parts) in UIMessage format
    saveChat({ chatId, messages });
  },
});

return createUIMessageStreamResponse({ stream });
```

在 AI SDK 5 中，默认的 OpenAI 提供商实例使用 Responses API，而 AI SDK 4 使用的是 Chat Completions API。Chat Completions API 仍受到完全支持，你可以通过 `openai.chat(...)` 使用它。

<Note>
  Responses API 与 Chat Completions API 的行为和默认值不同。如果你依赖 Chat Completions API，请将模型实例切换为 `openai.chat(...)`，并检查你的配置。
</Note>

#### Responses API 的严格 schema（strictSchemas）

在 AI SDK 4.0 中，你可以在 Responses 模型上设置 `strictSchemas` 选项（默认为 `true`）。该选项在 AI SDK 5.0 中已更名为 `strictJsonSchema`，且默认值变为 `false`。

```tsx filename="AI SDK 4.0"
import { z } from 'zod';
import { generateObject } from 'ai';
import { openai, type OpenAIResponsesProviderOptions } from '@ai-sdk/openai';

const result = await generateObject({
  model: openai.responses('gpt-4.1'),
  schema: z.object({
    // ...
  }),
  providerOptions: {
    openai: {
      strictSchemas: true, // default behavior in AI SDK 4
    } satisfies OpenAIResponsesProviderOptions,
  },
});
```

```tsx filename="AI SDK 5.0"
import { z } from 'zod';
import { generateObject } from 'ai';
import { openai, type OpenAIResponsesProviderOptions } from '@ai-sdk/openai';

const result = await generateObject({
  model: openai('gpt-4.1-2024'), // uses Responses API
  schema: z.object({
    // ...
  }),
  providerOptions: {
    openai: {
      strictJsonSchema: true, // defaults to false, opt back in to the AI SDK 4 strict behavior
    } satisfies OpenAIResponsesProviderOptions,
  },
});
```

如果你调用 `openai.chat(...)` 直接使用 Chat Completions API，可以用 `OpenAIChatLanguageModelOptions` 对其进行类型标注。AI SDK 5 同样在那里增加了相同的 `strictJsonSchema` 选项。

## 故障排查

### Zod 引发的 TypeScript 性能问题

如果在 AI SDK 5.0 中使用 Zod 时遇到 TypeScript 服务器崩溃、类型检查缓慢，或"Type instantiation is excessively deep and possibly infinite"之类的错误：

1. **首先，确保你使用的是 Zod 4.1.8 或更高版本**——该版本修复了导致 TypeScript 性能问题的模块解析问题。

2. 如果问题仍然存在，请更新 `tsconfig.json` 以使用 `moduleResolution: "nodenext"`：

```json
{
  "compilerOptions": {
    "moduleResolution": "nodenext"
    // ... other options
  }
}
```

这可以解决 TypeScript 性能问题，同时让你继续使用标准的 Zod 导入。如果问题仍未解决，你可以尝试使用带版本号的导入路径作为替代方案。详细的故障排查步骤请参阅 [Zod 引发的 TypeScript 性能问题](/docs/troubleshooting/typescript-performance-zod)。

## v5 Beta 版本之间的变更

本节记录 AI SDK 5.0 各 beta 版本之间的破坏性变更。如果你是从较早的 v5 beta 版本升级到较新的版本，请查看本节中可能影响代码的变更。

### fullStream 类型重命名：text/reasoning → text-delta/reasoning-delta

为与 UI 流和语言模型流保持一致，`fullStream` 中的 chunk 类型已更名。

```tsx filename="AI SDK 5.0 (before beta.26)"
for await (const chunk of result.fullStream) {
  switch (chunk.type) {
    case 'text-delta': {
      process.stdout.write(chunk.text);
      break;
    }
    case 'reasoning': {
      console.log('Reasoning:', chunk.text);
      break;
    }
  }
}
```

```tsx filename="AI SDK 5.0 (beta.26 and later)"
for await (const chunk of result.fullStream) {
  switch (chunk.type) {
    case 'text-delta': {
      process.stdout.write(chunk.text);
      break;
    }
    case 'reasoning-delta': {
      console.log('Reasoning:', chunk.text);
      break;
    }
  }
}
```
