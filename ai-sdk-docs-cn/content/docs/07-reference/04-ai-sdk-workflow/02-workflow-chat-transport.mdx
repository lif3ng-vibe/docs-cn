# `WorkflowChatTransport`

[`ChatTransport`](/docs/ai-sdk-ui/transport) 的一个实现，供 [`useChat`](/docs/reference/ai-sdk-ui/use-chat) 使用，为基于工作流的聊天应用提供自动流式重连能力。它将消息发送到聊天端点，提取 `x-workflow-run-id` 响应头，并在流中断（网络故障、页面刷新、函数超时）时重连到 `/{runId}/stream` 端点。

[`DefaultChatTransport`](/docs/ai-sdk-ui/transport) 假定完整响应在单个 HTTP 请求中到达，而 `WorkflowChatTransport` 则专为 [Workflow SDK](https://vercel.com/docs/workflow) 设计——在这种场景下，初始响应流可能被函数超时打断。该传输层会自动检测缺失的 `finish` 事件，并重连以从流中断的位置恢复。

```tsx
'use client';

import { useChat } from '@ai-sdk/react';
import { WorkflowChatTransport } from '@ai-sdk/workflow/client';

export default function Chat() {
  const { messages, sendMessage } = useChat({
    transport: new WorkflowChatTransport({
      api: '/api/chat',
      maxConsecutiveErrors: 5,
    }),
  });

  // ... render chat UI
}
```

## 方法

### `sendMessages()`

通过 POST 将消息发送到聊天端点并返回流式响应。如果流被中断（未收到 `finish` 事件），传输层会自动通过 GET 重连到 `{api}/{runId}/stream?startIndex={chunkIndex}`，从上次中断的位置恢复。

POST 请求以 JSON 形式携带消息，并期望响应中包含标识工作流运行的 `x-workflow-run-id` 请求头。

```ts
const stream = await transport.sendMessages({
  chatId: 'chat-123',
  trigger: 'submit-message',
  messages: [...],
  abortSignal: controller.signal,
});
```

### `reconnectToStream()`

  chatId: 'chat-123',
  startIndex: -50, // Optional: fetch last 50 chunks
});

## 重连工作原理

传输层遵循以下流程：

1. **POST**：将消息发送到 `{api}`。响应必须包含 `x-workflow-run-id` 请求头。
2. **流式**：读取 SSE 响应，并在块到达时进行计数。
3. **检测中断**：如果流在没有 `finish` 事件的情况下关闭（例如函数超时、网络错误），传输层即可判定响应不完整。
4. **重连**：通过 GET 请求 `{api}/{runId}/stream?startIndex={chunkIndex}`，从最后收到的块继续。
5. **重试**：如果重连的流再次中断，最多重试 `maxConsecutiveErrors` 次。
6. **完成**：一旦收到 `finish` 事件，调用 `onChatEnd` 并关闭流。

### 负数起始索引

当 `initialStartIndex` 为负数（例如 `-50`）时，传输层会在首次重连请求中将其原样发送。服务器应将其解析为绝对位置，并返回 `x-workflow-stream-tail-index` 响应头，以便传输层为后续重试计算出正确的位置。

如果该响应头缺失或无效，传输层会回退为从头重放（`startIndex=0`）。

负数索引要求服务器流是持久化的，且其存储对象本身就是 `UIMessageChunk` 对象。下文展示的原始 `WorkflowAgent` 转换仅支持非负索引。

## 服务器要求

要使 `WorkflowChatTransport` 正常工作，服务器必须提供两个端点：

### POST `{api}`（例如 `/api/chat`）

- 以 JSON 请求体接收消息
- 返回 `UIMessageChunk` 事件的 SSE 流
- 包含 `x-workflow-run-id` 响应头

### GET `{api}/{runId}/stream`（例如 `/api/chat/{runId}/stream`）

- 接受 `startIndex` 查询参数
- 返回从指定块索引开始的 SSE 流
- 对于负数 `startIndex`，解析到流的末尾并包含 `x-workflow-stream-tail-index` 响应头

完整端点示例参见 [WorkflowAgent 指南](/docs/agents/workflow-agent)。

## 示例

### useChat 基本用法

```tsx
'use client';

import { useChat } from '@ai-sdk/react';
import { WorkflowChatTransport } from '@ai-sdk/workflow/client';
import { useMemo } from 'react';

export default function Chat() {
  const transport = useMemo(
    () => new WorkflowChatTransport({ api: '/api/chat' }),
    [],
  );

  const { messages, sendMessage, status } = useChat({ transport });

  return (
    <div>
      {messages.map(message => (
        <div key={message.id}>
          {message.role === 'user' ? 'User: ' : 'AI: '}
          {message.parts.map((part, index) =>
            part.type === 'text' ? <span key={index}>{part.text}</span> : null,
          )}
        </div>
      ))}
      <button onClick={() => sendMessage({ text: 'Hello!' })}>Send</button>
    </div>
  );
}
```

```tsx
'use client';

import { useChat } from '@ai-sdk/react';
import { WorkflowChatTransport } from '@ai-sdk/workflow/client';
import { useMemo } from 'react';

export default function Chat() {
  const transport = useMemo(
    () =>
      new WorkflowChatTransport({
        api: '/api/chat',
        maxConsecutiveErrors: 5,
        onChatSendMessage: response => {
          const runId = response.headers.get('x-workflow-run-id');
          console.log('Workflow run started:', runId);
        },
        onChatEnd: ({ chatId, chunkIndex }) => {
          console.log(`Chat ${chatId} complete, ${chunkIndex} chunks`);
        },
      }),
    [],
  );

  const { messages, sendMessage } = useChat({ transport });

  // ... render chat UI
}
```

### 服务器端端点（Next.js）

```ts filename="app/api/chat/route.ts"
import { createModelCallToUIChunkTransform } from '@ai-sdk/workflow';
import { createUIMessageStreamResponse, type UIMessage } from 'ai';
import { start } from 'workflow/api';
import { chat } from '@/workflow/agent-chat';

export async function POST(request: Request) {
  const { messages }: { messages: UIMessage[] } = await request.json();
  const run = await start(chat, [messages]);

  return createUIMessageStreamResponse({
    stream: run.readable.pipeThrough(createModelCallToUIChunkTransform()),
    headers: {
      'x-workflow-run-id': run.runId,
    },
  });
}
```

```ts filename="app/api/chat/[runId]/stream/route.ts"
import { createModelCallToUIChunkTransform } from '@ai-sdk/workflow';
import { createUIMessageStreamResponse } from 'ai';
import type { NextRequest } from 'next/server';
import { getRun } from 'workflow/api';

export async function GET(
  request: NextRequest,
  { params }: { params: Promise<{ runId: string }> },
) {
  const { runId } = await params;
  const startIndex = Number(
    new URL(request.url).searchParams.get('startIndex') ?? '0',
  );
  if (!Number.isSafeInteger(startIndex) || startIndex < 0) {
    return Response.json(
      { error: 'startIndex must be a non-negative safe integer' },
      { status: 400 },
    );
  }

  const run = await getRun(runId);
  const readable = run
    .getReadable({ startIndex: 0 })
    .pipeThrough(
      createModelCallToUIChunkTransform({ uiStartIndex: startIndex }),
    );

  return createUIMessageStreamResponse({
    stream: readable,
    headers: {
      'x-workflow-run-id': runId,
    },
  });
}
```

该 `WorkflowAgent` 端点会从索引 `0` 重放原始 `ModelCallStreamPart` 对象，在将其转换为 `UIMessageChunk` 对象之后再应用传输层的非负游标。负数起始索引要求流是持久化的，且其存储对象本身就是 `UIMessageChunk` 对象。
