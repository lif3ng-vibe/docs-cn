# `WorkflowAgent`

创建一个持久化、可恢复的 AI 智能体（agent），用于工作流内部。`WorkflowAgent` 负责智能体循环、跨工作流步骤边界的工具 schema 序列化，以及内置的工具审批流程。

与 `ai` 包中的 [`ToolLoopAgent`](/docs/reference/ai-sdk-core/tool-loop-agent) 不同，`WorkflowAgent` 旨在经受住进程重启、暂停以等待人工审批，并与 Workflow DevKit 的步骤机制集成。

`WorkflowAgent` 支持 `runtimeContext`（共享的智能体状态）和 `toolsContext`（每个工具各自的上下文）。由于这些值可能跨越工作流与步骤边界，请保持它们为可序列化的持久化数据。与 `ToolLoopAgent` 不同，不要在上下文中放置函数、类实例、symbol、数据库客户端或 SDK 客户端；请传递标识符或配置，并在步骤函数内部重建不可序列化的资源。

```ts
import { WorkflowAgent } from '@ai-sdk/workflow';
import { tool } from 'ai';
import { z } from 'zod';

const agent = new WorkflowAgent({
  model: 'anthropic/claude-sonnet-5.5',
  instructions: 'You are a helpful assistant.',
  tools: {
    weather: tool({
      description: 'Get the weather in a location',
      inputSchema: z.object({
        location: z.string(),
      }),
      execute: async ({ location }) => ({
        location,
        temperature: 72,
      }),
    }),
  },
});

const result = await agent.stream({
  messages: [
    {
      role: 'user',
      content: [{ type: 'text', text: 'What is the weather in NYC?' }],
    },
  ],
});

console.log(result.messages);
```

要查看 `WorkflowAgent` 的实际效果，请参阅[这些示例](#示例)。

## 方法

### `generate()`

使用模型的非流式 `doGenerate()` 方法运行持久化的智能体循环。模型调用与工具执行使用与 `stream()` 相同的编排方式。

```ts
const result = await agent.generate({ prompt: 'Summarize the findings.' });
console.log(result.text);
console.log(result.usage);
```

接受 `WorkflowAgentGenerateOptions`，与 `stream()` 共享提示词/消息、指令、生成设置、工具与运行时上下文、准备、停止、输出以及生命周期选项。它不接受 `writable`、`includeRawChunks`、`experimental_transform`、`sendFinish` 或 `preventClose`。在没有配置停止条件的情况下，生成最多 20 个步骤后停止。`stream()` 保留其现有的无上限默认值。

`include` 选项接受 `requestBody`、`responseBody` 和 `requestMessages` 布尔值，默认均为 `false`。仅当需要额外的请求/响应数据时才启用它们。当模型提供时，响应 ID、时间戳、模型 ID、请求头与提供商元数据都会保留。

#### 返回值

返回 `Promise<WorkflowAgentGenerateResult>`，具有核心 [`GenerateTextResult`](/docs/reference/ai-sdk-core/generate-text#返回值) 的语义：

- `text`、`finishReason`、`rawFinishReason` 与 `finalStep` 描述最后一个步骤。
- `content`、`files`、`sources`、`warnings`、工具调用与工具结果覆盖所有步骤。
- `usage` 与 `totalUsage` 汇总所有步骤，同时保留 token 明细与未知计数。
- `responseMessages` 包含生成的消息，即使 `prepareStep` 替换了输入历史。
- `output` 默认为文本，或遵循构造函数/每次调用指定的输出规范。当输出不可用时（例如最终响应为 `tool-calls`），读取它会抛出 `NoOutputGeneratedError`。

在工作流内部，`timeout` 限定模型调用，包括重试与暂停后的派发。它不会取消工具正在等待的 Hook。请使用 Workflow 运行时的 `run.cancel()` 来停止已暂停的运行。参见[截止时间、取消与重放](/docs/agents/workflow-agent#deadlines-cancellation-and-replay)。

生成失败会导致 Promise 被 reject。结束回调在完整输出解析之前运行；因此解析失败可能在 `onEnd` 已经运行后才导致 reject。现有的 Workflow 回调形态与准备优先级仍然适用；它们并非都与核心的回调 API 完全相同。

<Note>
  请在工作流代码内部使用结果 API，并通过 `run.returnValue` 返回选定的可序列化
  字段（例如 `text` 和 `usage`）。不支持返回整个结果类。性能数据目前测量的是
  模型响应；完整的工具/步骤耗时尚未上报。
</Note>

审批请求会出现在 `content` 与 `responseMessages` 中，无需 writable。要继续执行，请将 `responseMessages` 追加到原始历史中，并添加一条包含用户 `tool-approval-response` 的工具消息。请保留请求签名与工具调用输入；在续跑时使用相同的 `experimental_toolApprovalSecret` 环境变量引用。本地审批会在执行前校验，而由提供商执行的审批响应会被转发给提供商。参见[无需流式传输的审批往返](/docs/agents/workflow-agent#approval-round-trips-without-streaming)。

### `stream()`

运行智能体循环，流式传输响应并按需执行工具调用。返回一个 resolve 为 `WorkflowAgentStreamResult` 的 Promise。

```ts
const result = await agent.stream({
  messages: [{ role: 'user', content: [{ type: 'text', text: 'Hello' }] }],
});
```

### `repairToolCall` 在工作流中

`repairToolCall` 在模型步骤内部运行。在工作流中使用它时，请将回调定义为一个
带有 `'use step'` 指令的函数。可以在构造函数上设置它，也可以传递给 `stream()`。

Workflow 会保存对已注册函数的引用，并在模型步骤内部加载其实现。请保持函数
捕获的任何值都是可序列化的。普通的内联回调在跨越此步骤边界时会引发序列化
错误。

该回调可以是异步的。返回修复后的工具调用；如果无法完成修复则返回 `null`。
修复策略请参见[工具调用修复](/docs/ai-sdk-core/tools-and-tool-calling#工具调用修复)。

### `experimental_transform` 在工作流中

将一个转换工厂或工厂数组传递给 `stream()`。
为每个工厂标记 `'use step'`，以便 Workflow 能在模型步骤内部加载它。工厂必须
同步返回一个 `TransformStream`。请保持捕获的值是可序列化的。

```ts
import type { LanguageModelV4StreamPart } from '@ai-sdk/provider';
import { WorkflowAgent } from '@ai-sdk/workflow';
import { getWritable } from 'workflow';

function uppercaseText() {
  'use step';

  return new TransformStream<
    LanguageModelV4StreamPart,
    LanguageModelV4StreamPart
  >({
    transform(part, controller) {
      controller.enqueue(
        part.type === 'text-delta'
          ? { ...part, delta: part.delta.toUpperCase() }
          : part,
      );
    },
  });
}

export async function uppercaseWorkflow() {
  'use workflow';

  const agent = new WorkflowAgent({ model: 'openai/gpt-5' });

  return agent.stream({
    messages: [{ role: 'user', content: 'Write a short greeting.' }],
    writable: getWritable(),
    experimental_transform: uppercaseText,
  });
}
```

## 工具函数

### `createModelCallToUIChunkTransform(options?)`

创建一个 `TransformStream`，将原始的 `ModelCallStreamPart` 块（由智能体写入 `writable` 流）转换为适合客户端消费的 `UIMessageChunk` 对象。

```ts
import { createModelCallToUIChunkTransform } from '@ai-sdk/workflow';

return createUIMessageStreamResponse({
  stream: run.readable.pipeThrough(createModelCallToUIChunkTransform()),
});
```

使用 `WorkflowChatTransport` 游标恢复时，从索引 `0` 开始重放原始工作流
流，并将非负的 UI 块索引传递给转换器：

```ts
const readable = run
  .getReadable({ startIndex: 0 })
  .pipeThrough(createModelCallToUIChunkTransform({ uiStartIndex: startIndex }));
```

`uiStartIndex` 必须是非负的安全整数。原始模型流部分与
UI 消息块并非一一对应，因此不要将 UI 块索引传递给
`getReadable`。负数尾部索引要求持久化流已经
存储了 `UIMessageChunk` 对象。

### `toUIMessageChunk()`

将单个 `ModelCallStreamPart` 转换为 `UIMessageChunk`。对于无法映射为 UI 块的部分返回 `undefined`。

```ts
import { toUIMessageChunk } from '@ai-sdk/workflow';

const uiChunk = toUIMessageChunk(modelCallPart);
```

## 类型

### `ActiveTools`

```ts
type ActiveTools<TTools extends ToolSet> =
  | ReadonlyArray<keyof TTools & string>
  | undefined;
```

将工作流智能体调用限制在列出的工具名称内。`undefined` 表示不应用任何工具限制。

### `InferWorkflowAgentUIMessage`

推断 `WorkflowAgent` 实例的 UI 消息类型。可选地接受第二个类型参数用于自定义消息元数据。

```ts
import { WorkflowAgent, InferWorkflowAgentUIMessage } from '@ai-sdk/workflow';

const agent = new WorkflowAgent({
  model: 'anthropic/claude-sonnet-5.5',
  tools: { weather: weatherTool },
});

type MyAgentUIMessage = InferWorkflowAgentUIMessage<typeof agent>;
```

### `InferWorkflowAgentTools`

推断 `WorkflowAgent` 实例的工具集合类型。

```ts
import { WorkflowAgent, InferWorkflowAgentTools } from '@ai-sdk/workflow';

type MyTools = InferWorkflowAgentTools<typeof myAgent>;
```

### 工作流中使用持久化工具的智能体

```ts filename="workflow/agent-chat.ts"
import { WorkflowAgent, type ModelCallStreamPart } from '@ai-sdk/workflow';
import { convertToModelMessages, tool, type UIMessage } from 'ai';
import { getWritable } from 'workflow';
import { z } from 'zod';

// Tool execute functions marked with 'use step' become durable workflow steps
// with automatic retries and persistence
async function searchFlightsStep(input: {
  origin: string;
  destination: string;
}) {
  'use step';
  const response = await fetch(`https://api.flights.example/search?...`);
  return response.json();
}

export async function chat(messages: UIMessage[]) {
  'use workflow';

  const modelMessages = await convertToModelMessages(messages);

  const agent = new WorkflowAgent({
    model: 'anthropic/claude-sonnet-5.5',
    instructions: 'You are a flight booking assistant.',
    tools: {
      searchFlights: tool({
        description: 'Search for available flights',
        inputSchema: z.object({
          origin: z.string(),
          destination: z.string(),
        }),
        execute: searchFlightsStep,
      }),
    },
  });

  const result = await agent.stream({
    messages: modelMessages,
    writable: getWritable<ModelCallStreamPart>(),
  });

  return { messages: result.messages };
}
```

import { createModelCallToUIChunkTransform } from '@ai-sdk/workflow';
import { createUIMessageStreamResponse, type UIMessage } from 'ai';

### 带工具审批的智能体

对于 `WorkflowAgent`，工具审批是在工具定义上通过
`needsApproval` 配置的。对于 `generateText`、`streamText` 和 `ToolLoopAgent`，
请改用
`toolApproval`。

```ts
import { WorkflowAgent } from '@ai-sdk/workflow';
import { tool } from 'ai';
import { z } from 'zod';

const agent = new WorkflowAgent({
  model: 'anthropic/claude-sonnet-5.5',
  experimental_toolApprovalSecret: {
    environmentVariable: 'TOOL_APPROVAL_SECRET',
  },
  tools: {
    bookFlight: tool({
      description: 'Book a flight',
      inputSchema: z.object({
        flightId: z.string(),
        passengerName: z.string(),
      }),
      needsApproval: true, // Pauses the agent until user approves
      execute: bookFlightStep,
    }),
  },
});
```

配置了 `experimental_toolApprovalSecret` 后，每个审批请求都会基于其审批 ID、
工具调用 ID、工具名称与已校验输入进行签名。缺少签名或签名无效的重放审批不会
执行该工具。签名会保留在持久化流与 UI 消息历史中，而只有环境变量名称会跨越
工作流边界。签名与校验步骤从各自的本地环境读取原始密钥，不会将其序列化。
流级别的引用会覆盖构造函数的值。

import { WorkflowAgent } from '@ai-sdk/workflow';

const agent = new WorkflowAgent({

  },

const result = await agent.stream({
  messages,

  // Per-call callbacks (both fire)
  async onStepEnd({ usage }) {
    await trackUsage(usage);
  },

  onEnd({ steps, totalUsage }) {
    console.log(
      `Done in ${steps.length} steps, ${totalUsage.totalTokens} tokens`,
    );
  },
});
