# `createProviderRegistry()`

当你同时使用多个提供商和模型时，通常希望将它们集中在一处管理，并通过简单的字符串 id 访问模型。

`createProviderRegistry` 允许你创建一个包含多个提供商的注册表，并以 `providerId:modelId` 格式的 id 访问它们。

在 TypeScript 中，注册表模型 ID 会从已注册的提供商 ID 推断得出。当提供商暴露字面量模型 ID 类型时，编辑器可以建议组合后的 `providerId:modelId` 值。

### 设置

你可以使用 `createProviderRegistry` 创建一个包含多个提供商和模型的注册表。

```ts
import { anthropic } from '@ai-sdk/anthropic';
import { createOpenAI } from '@ai-sdk/openai';
import { createProviderRegistry } from 'ai';

export const registry = createProviderRegistry({
  // register provider with prefix and default setup:
  anthropic,

  // register provider with prefix and custom setup:
  openai: createOpenAI({
    apiKey: process.env.OPENAI_API_KEY,
  }),
});
```

### 自定义分隔符

默认情况下，注册表使用 `:` 作为提供商 ID 与模型 ID 之间的分隔符。你可以通过传入 `separator` 选项来自定义该分隔符：

```ts
const registry = createProviderRegistry(
  {
    anthropic,
    openai,
  },
  { separator: ' > ' },
);

// Now you can use the custom separator
const model = registry.languageModel('anthropic > claude-3-opus-20240229');
```

### 语言模型

你可以使用注册表上的 `languageModel` 方法访问语言模型。
提供商 id 会成为模型 id 的前缀：`providerId:modelId`。

```ts highlight={"5"}
import { generateText } from 'ai';
import { registry } from './registry';

const { text } = await generateText({
  model: registry.languageModel('openai:gpt-6-astra'),
  prompt: 'Invent a new holiday and describe its traditions.',
});
```

### 文本嵌入模型

你可以使用注册表上的 `.embeddingModel` 方法访问文本嵌入模型。
提供商 id 会成为模型 id 的前缀：`providerId:modelId`。

```ts highlight={"5"}
import { embed } from 'ai';
import { registry } from './registry';

const { embedding } = await embed({
  model: registry.embeddingModel('openai:text-embedding-3-small'),
  value: 'sunny day at the beach',
});
```

### 图像模型

你可以使用注册表上的 `imageModel` 方法访问图像模型。
提供商 id 会成为模型 id 的前缀：`providerId:modelId`。

```ts highlight={"5"}
import { generateImage } from 'ai';
import { registry } from './registry';

const { image } = await generateImage({
  model: registry.imageModel('openai:dall-e-3'),
  prompt: 'A beautiful sunset over a calm ocean',
});
```

### 视频模型

你可以使用注册表上的 `videoModel` 方法访问视频模型。
提供商 id 会成为模型 id 的前缀：`providerId:modelId`。

```ts highlight={"7"}
import { fal } from '@ai-sdk/fal';
import { createProviderRegistry, experimental_generateVideo } from 'ai';

const registry = createProviderRegistry({ fal });

const { videos } = await experimental_generateVideo({
  model: registry.videoModel('fal:luma-dream-machine/ray-2'),
  prompt: 'A cat walking on a beach at sunset',
});
```

### 文件与技能

你可以通过调用 `registry.files(providerId)` 和 `registry.skills(providerId)`
访问提供商的文件与技能接口。

## 实验性决策模型

推断出的返回类型还会暴露 `decisionModel('providerId:modelId')`，
返回 `Experimental_DecisionModelV4`。提供商必须暴露
`decisionModel` 工厂。自定义分隔符与模型 ID
推断的工作方式与视频模型相同。语言与图像中间件不会
包装决策模型。`ProviderRegistryProvider` 仍是一个稳定接口；
如需保留实验性决策访问能力，请使用推断的返回类型或
`Experimental_DecisionProviderRegistry`。

当决策能力或模型不可用时，会抛出带 `modelType: 'decisionModel'` 的
`NoSuchModelError`；未知的注册表提供商则抛出
`NoSuchProviderError`。这些能力属于结构上的扩展，不会
被加入稳定的 `ProviderV4` 契约。在未配置默认提供商时，
直接的决策字符串 ID 会默认使用 Gateway。
可运行的用法示例见[决策](/docs/ai-sdk-core/decisions#模型别名与注册表)。
