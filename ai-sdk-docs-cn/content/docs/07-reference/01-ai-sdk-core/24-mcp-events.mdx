# MCP Events

本页介绍 `client.experimental_events` 上的实验性方法、webhook 处理器及其公开类型。使用
[`createMCPClient`](/docs/reference/ai-sdk-core/create-mcp-client) 创建客户端。应用流程请参阅
[MCP Events 指南](/docs/ai-sdk-core/mcp-events)。

## 设置

```ts
import { createMCPClient } from '@ai-sdk/mcp';
import { eventStore } from './event-store';

const client = await createMCPClient({
  transport: { type: 'http', url: 'https://service.example/mcp' },
  experimental_events: { store: eventStore },
});
```

`experimental_events` 接受 [`Experimental_MCPEventsConfig`](/docs/reference/ai-sdk-core/mcp-events#client-configuration)。
在直接模式（direct mode）下，subscribe、refresh 和 unsubscribe 需要提供 store。
也可以按下文所述配置托管适配器（managed adapter）。不配置任何一种模式也可以进行发现（discovery）。请在订阅之前挂载
[webhook 处理器](/docs/reference/ai-sdk-core/mcp-events#webhook-处理器)。

以下方法属于 `client.experimental_events`；它们不是独立导入的函数。

## 列出事件

### `client.experimental_events.list()`

发送 `events/list` 并返回一页事件目录。

```ts
const { events, nextCursor } = await client.experimental_events.list();
console.log(events.map(event => event.name));

if (nextCursor != null) {
  const nextPage = await client.experimental_events.list({
    params: { cursor: nextCursor },
  });
  console.log(nextPage.events);
}
```

## 托管订阅

配置 `experimental_events: { adapter }` 可以将订阅生命周期操作委托给后端。适配器实现
`@ai-sdk/mcp` 的 `Experimental_MCPEventsAdapter`；它由你的应用或集成包绑定到已授权的账户与目的地。

```ts
import { createMCPClient } from '@ai-sdk/mcp';
import { authenticatedTransport, eventsAdapter } from '@/lib/mcp';

const client = await createMCPClient({
  transport: authenticatedTransport,
  experimental_events: { adapter: eventsAdapter },
});

try {
  // Authenticated MCP discovery; this does not list saved subscriptions.
  const catalog = await client.experimental_events.list();

  const watch = await client.experimental_events.subscribe({
    name: 'comment.created',
    arguments: { document_id: 'doc_123' },
    context: { bindingId: 'saved_intent_123' },
    expiresAt: null,
    idempotencyKey: 'saved_intent_123',
  });

  const state = await client.experimental_events.getSubscription({
    id: watch.id,
  });
  const page = await client.experimental_events.listSubscriptions({
    status: 'active',
    limit: 20,
  });
  const stopped = await client.experimental_events.unsubscribe({
    id: watch.id,
  });
} finally {
  await client.close();
}
```

`authenticatedTransport` 与 `eventsAdapter` 由你的应用提供。
发现与订阅管理应使用同一个已授权账户。
绝不根据模型参数推导账户身份、目的地或授权。

### 适配器契约

```ts
import type { JSONObject } from '@ai-sdk/provider';

type ManagedSubscription = {
  id: string;
  name: string;
  arguments: JSONObject;
  status:
    | 'pending'
    | 'active'
    | 'needs_auth'
    | 'stopped'
    | 'expired'
    | 'failed';
  expiresAt: string | null;
  cleanupStatus?: 'pending' | 'complete' | 'exhausted';
};

type ManagedSubscribeInput = {
  name: string;
  arguments: JSONObject;
  context?: JSONObject;
  idempotencyKey: string;
  options?: {
    signal?: AbortSignal;
    timeout?: number;
    maxTotalTimeout?: number;
  };
} & (
  | { ttlMs: number; expiresAt?: never }
  | { expiresAt: string | null; ttlMs?: never }
);
```

这些类型以 `Experimental_ManagedSubscription` 和
`Experimental_ManagedSubscribeInput` 导出。必须恰好提供一种监控期限：
正数 `ttlMs`、`expiresAt` 中的 ISO 截止时间，或 `expiresAt: null`
表示持续监控直到停止。后端会校验这些值并执行其自身的限制。

`Experimental_MCPEventsAdapter` 有四个操作：

| 操作                | 输入                                              | 结果                               |
| ------------------- | ------------------------------------------------- | ---------------------------------- |
| `subscribe`         | `Experimental_ManagedSubscribeInput`              | `Experimental_ManagedSubscription` |
| `getSubscription`   | `{ id, options? }`                                | `Experimental_ManagedSubscription` |
| `listSubscriptions` | Optional `{ cursor?, limit?, status?, options? }` | `{ subscriptions, nextCursor? }`   |
| `unsubscribe`       | `{ id, options? }`                                | `Experimental_ManagedSubscription` |

所有操作都返回 Promise。客户端会透传输入、取消/超时
选项、结果与错误，不做重试或重新映射。适配器
必须自行实现请求选项处理，并保留可操作的后端错误，
例如需要授权同意、配额超限或暂时不可用。

托管 ID 标识后端记录。`expiresAt` 是应用的监控
截止时间，而不是上游 MCP 的 `refreshBefore` 授予。pending 结果表示
后端已持久接受；上游设置可能仍在进行。
停止操作可能返回 `cleanupStatus: 'pending'`，此时远程清理仍在继续。

回调 URL、密钥、上游订阅调用、验证、
续期与清理都由后端负责。托管的 `subscribe` 不会隐式发现目录、
生成密钥、写入本地 store 或调用上游 `events/subscribe`。
`getSubscription` 与 `listSubscriptions` 是适配器方法，不是 MCP 线上协议方法。
托管门面没有 `refresh()`；即使应用侧的 watch 没有截止时间，
后端也会续期有限的上游租约。

在创建结果不确定时，应在后端文档声明的恢复窗口内
持久化应用意图并复用其幂等键（idempotency key）。超时或
中止的请求并不能证明远程订阅已被取消。
关闭 MCP 客户端不会取消托管 watch 的订阅。

托管投递与本客户端相互独立。请使用后端的投递校验器
与接收方契约；`experimental_createMCPEventWebhook` 服务于直接模式的 MCP
webhook。应用仍需自行负责授权路由、持久化接收确认
与幂等的任务分发。适配器不会调用事件回调。

### 配置与类型

只能在 `experimental_events: { adapter }` 与 `experimental_events: { store }` 之间二选一。
混用会在 TypeScript 和运行时被拒绝。`validateArguments` 是
直接模式选项；托管模式的校验属于后端。未发布的
`events` 配置写法已被 `experimental_events` 取代。

配置适配器时，`createMCPClient` 会推断出带有
`Experimental_ManagedMCPEvents` 的 `Experimental_ManagedMCPClient`。两种模式都使用
`MCPClientConfig`，其 `experimental_events` 属性接受
`Experimental_MCPEventsConfig` 联合类型。直接模式客户端保持 `MCPClient` 与
`Experimental_MCPEvents`。两种模式的输入与结果类型保持不同。

保存配置时使用 `satisfies MCPClientConfig` 以保留所选模式的类型推断。
若配置的模式只能在运行时确定，则返回两种客户端类型的联合；
它不保证 `refresh()` 等仅直接模式可用的方法。要在没有
store 或适配器的情况下进行目录发现，可以完全省略 `experimental_events`。

接下来的 subscribe、refresh 与 unsubscribe 小节描述的都是直接模式。

## 刷新订阅

### `client.experimental_events.refresh(options)`

按 ID 或存储键加载已保存的订阅，并以
原始的名称、参数、回调 URL、密钥、请求的有效期和最近
保存的游标发送 `events/subscribe`。

订阅在续期前会被标记为 pending。在响应保存新的过期时间并恢复活跃状态之前，事件投递会返回 `503`。如果续期
失败，记录会保持 pending，因为服务器可能已经完成了续期；
你可以使用已保存的 ID 或键重试 refresh 或 unsubscribe。

对于已保存 ID 的订阅，即使续期处于 pending，经过验证的终止消息也会被处理。例如，如果访问权限被吊销，`onTerminated` 仍会运行，
处理成功后已保存的订阅会被移除。

```ts
const renewed = await client.experimental_events.refresh({
  id: subscription.id,
});
console.log(renewed.refreshBefore);
```

## 错误

客户端会拒绝向不具备 `events` 能力的服务器发起请求。
订阅生命周期方法需要 `experimental_events.store`；refresh 与 unsubscribe
还需要已知的订阅 ID 或存储键。subscribe 会拒绝未知
的事件名称、不支持的投递模式、无效的回调 URL、签名密钥
或有效期设置。这些检查使用 `MCPClientError`，但 URL 解析可能
抛出 `TypeError`。

MCP 请求错误、store 失败和应用层校验错误会传播
给调用方。事件请求不会按客户端的工具调用重试
设置进行重试。参见 [MCP 客户端错误处理](/docs/reference/ai-sdk-core/create-mcp-client#错误处理)。

## Webhook 处理器

### `experimental_createMCPEventWebhook()`

为实验性 MCP webhook 事件创建 Web Request/Response 处理器。
它使用 [`client.experimental_events.subscribe`](/docs/reference/ai-sdk-core/mcp-events#订阅事件) 保存的订阅来验证回调质询（challenge）与事件签名。

### 导入

<Snippet
  text={`import { experimental_createMCPEventWebhook } from "@ai-sdk/mcp"`}
  prompt={false}
/>

### 示例

```ts filename="app/api/mcp-events/route.ts"
import { experimental_createMCPEventWebhook } from '@ai-sdk/mcp';
import { eventStore } from '@/lib/event-store';

export const POST = experimental_createMCPEventWebhook({
  store: eventStore,
  async onEvent({ subscription, event }) {
    console.log(subscription.id, event.name, event.data);
  },
  async onGap({ subscription, gap }) {
    // Some events cannot be replayed; reconcile state or notify the agent.
    console.log('Replay gap:', subscription.id, gap.cursor, gap.truncated);
  },
  async onTerminated({ subscription, termination }) {
    // The server ended the subscription; notify the agent of the reason.
    console.log('Subscription terminated:', subscription.id, termination.error);
  },
  onError(error) {
    console.error(error);
  },
});
```

请在订阅之前挂载该路由。处理器与订阅客户端必须
访问同一个私有订阅 store。

#### 回调参数

`onEvent` 接收：

完整类型参见[订阅元数据](/docs/reference/ai-sdk-core/mcp-events#subscription-metadata)
与[事件字段](/docs/reference/ai-sdk-core/mcp-events#event)。

`onGap` 与 `onTerminated` 接收同样的安全 `subscription` 元数据，以及
来自签名 `webhook-id` 请求头的 `messageId`。每个回调只接收与其
匹配的控制负载，因此无需 `type` 检查。重试去重按
订阅 ID 与 `messageId` 进行。

- `onGap` 接收 `gap: { type: 'gap', cursor, truncated: true }`。它表示部分
  事件已无法重放。请调和应用状态或
  通知智能体。回调 resolve 后，该辅助函数会加上 `truncated: true` 并与最新
  游标一起保存。订阅保持活跃，事件
  投递继续。
- `onTerminated` 接收
  `termination: { type: 'terminated', error: { code, message, data? } }`。它表示
  服务器已结束该订阅。检查错误了解原因并
  通知智能体。回调 resolve 后，该辅助函数会删除已保存的
  订阅记录。

两者在成功处理后都返回 `204`。即使省略对应回调，状态更新也会发生。回调或存储失败会返回 `503`
以便重试。在激活或续期被持久化之前，事件与间隔（gap）都返回 `503`。
当订阅 ID 已保存时，pending 续期期间也接受终止消息；没有保存 ID 的订阅仍返回 `503`。
即使已保存的过期时间已过，控制消息也会被处理。它们绝不会
发送给 `onEvent` 或 `validatePayload`。该辅助函数不会自动运行或通知智能体。

### 返回值

```ts
(request: Request) => Promise<Response>;
```

处理器接受 `Content-Type: application/json` 的 `POST` 请求。
请传入原始请求体字节，并保留订阅客户端添加的 `mcp_event_subscription`
查询参数。在传给该处理器之前，不要解析再重新序列化请求体。

服务器必须包含 `webhook-id`、`webhook-timestamp`、`webhook-signature`
与 `X-MCP-Subscription-Id`。该辅助函数验证 Standard Webhooks v1 HMAC-SHA256
签名，并接受距当前时间五分钟以内的签名时间戳。
事件的 `eventId` 必须与 `webhook-id` 一致，其名称必须与订阅一致。

## 事件类型

以下类型从 `@ai-sdk/mcp` 导出，均为实验性。

```ts
import type {
  Experimental_MCPEvents,
  Experimental_MCPEventsConfig,
  Experimental_MCPEventDefinition,
  Experimental_ListEventsResult,
  Experimental_SubscribeEventOptions,
  Experimental_SubscribeEventResult,
  Experimental_MCPEvent,
  Experimental_MCPEventControl,
  Experimental_MCPEventSubscription,
  Experimental_MCPEventSubscriptionInfo,
  Experimental_MCPEventStore,
  Experimental_MCPEventWebhookOptions,
} from '@ai-sdk/mcp';
```

下面的类型结构使用 `@ai-sdk/provider` 的 `JSONObject` 表示 JSON 兼容的
过滤对象。请求设置为内联书写，因为 `RequestOptions`
未从 `@ai-sdk/mcp` 导出。

### Webhook 控制消息

`Experimental_MCPEventControl` 是生命周期负载的联合类型。`onGap`
接收其 `gap` 变体；`onTerminated` 以 `termination` 接收其 `terminated` 变体：

```ts
type Experimental_MCPEventControl =
  | { type: 'gap'; cursor: string; truncated: true }
  | {
      type: 'terminated';
      error: { code: number; message: string; data?: unknown };
    };
```

未知的扩展字段会被保留。验证质询会自动应答，
不会调用 `onEvent`、`onGap` 或 `onTerminated`。

### 客户端方法

`Experimental_MCPEvents` 描述 `client.experimental_events` 属性：

```ts
interface Experimental_MCPEvents {
  list(options?: {
    params?: { cursor?: string };
    options?: {
      signal?: AbortSignal;
      timeout?: number;
      maxTotalTimeout?: number;
    };
  }): Promise<Experimental_ListEventsResult>;

  subscribe(
    options: Experimental_SubscribeEventOptions,
  ): Promise<Experimental_SubscribeEventResult>;

  refresh(
    options: ({ id: string; key?: never } | { key: string; id?: never }) & {
      options?: {
        signal?: AbortSignal;
        timeout?: number;
        maxTotalTimeout?: number;
      };
    },
  ): Promise<Experimental_SubscribeEventResult>;

  unsubscribe(
    options: ({ id: string; key?: never } | { key: string; id?: never }) & {
      options?: {
        signal?: AbortSignal;
        timeout?: number;
        maxTotalTimeout?: number;
      };
    },
  ): Promise<void>;
}
```
