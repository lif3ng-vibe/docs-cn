# HarnessAgent

`HarnessAgent` 是由 harness 适配器支撑的 AI SDK `Agent` 实现。它为你提供返回 AI SDK 兼容结果的 `generate()` 和 `stream()` 方法，而这些结果由一个预先配置好的 harness 驱动。

## 安装

安装核心 harness 包、一个 harness 适配器和一个沙箱适配器：

<InstallPackages packages="@ai-sdk/harness @ai-sdk/harness-claude-code @ai-sdk/sandbox-vercel" />

Claude Code 和 Codex 这类桥接型 harness 需要使用真正的网络沙箱，例如 `@ai-sdk/sandbox-vercel`。Pi 这类宿主运行时 harness 也可以用 `@ai-sdk/sandbox-just-bash` 运行，因为它们不需要沙箱暴露的端口。

## 创建智能体

```ts
import { HarnessAgent } from '@ai-sdk/harness/agent';
import { claudeCode } from '@ai-sdk/harness-claude-code';

export const agent = new HarnessAgent({
  harness: claudeCode,
  model: 'claude-sonnet-4-6',
  instructions:
    'You are a careful coding assistant. Prefer small changes and explain tradeoffs.',
});
```

在模块作用域中构造智能体。它只持有配置，而不是活跃会话；活跃状态属于 `HarnessAgentSession`。请单独创建沙箱会话，并将其传给 `agent.createSession()`：


```ts
import { createVercelNetworkSandboxSession } from '@ai-sdk/sandbox-vercel';

const sandboxSession = await createVercelNetworkSandboxSession({
  runtime: 'node24',
  ports: [4000],
  template: await agent.getSandboxTemplate(),
});
```

设置 `model` 来选择 harness 运行时使用的模型。模型标识符因 harness 而异。省略时，harness 会使用其默认模型。模型按回合应用，因此 `prepareCall` 可以在回合之间替换它。

要使用该智能体，请确保已设置包含沙箱与 harness 凭据的环境变量。

## 运行回合

```ts
const session = await agent.createSession({ sandboxSession });

let exitCode = 0;
try {
  const result = await agent.generate({
    session,
    prompt: 'Create a short TODO.md for this repository.',
  });

  console.log(result.text);
} catch (err) {
  exitCode = 1;
  console.error(err);
} finally {
  await session.destroy();
  await sandboxSession.destroy();
  process.exit(exitCode);
}
```

`generate()` 会排空该回合并返回一个 `GenerateTextResult`。

使用 `stream()` 获取增量输出：


```ts
const session = await agent.createSession({ sandboxSession });

let exitCode = 0;
try {
  const result = await agent.stream({
    session,
    prompt: 'Create a short TODO.md for this repository.',
  });

  for await (const part of result.stream) {
    if (part.type === 'text-delta') {
      process.stdout.write(part.text);
    }
  }
} catch (err) {
  exitCode = 1;
  console.error(err);
} finally {
  await session.destroy();
  await sandboxSession.destroy();
  process.exit(exitCode);
}
```

## 生命周期回调

在 `HarnessAgent` 上配置生命周期回调，以观察智能体调用、模型步骤和工具执行：


```ts
const agent = new HarnessAgent({
  harness: claudeCode,
  tools: { weather },
  onStart: event => console.log('call started', event.callId),
  onStepStart: event => console.log('step started', event.stepNumber),
  onLanguageModelCallStart: event =>
    console.log('model call started', event.modelId),
  onLanguageModelCallEnd: event =>
    console.log('model call ended', event.finishReason),
  onToolExecutionStart: event =>
    console.log('tool started', event.toolCall.toolName),
  onToolExecutionEnd: event => console.log('tool ended', event.toolOutput.type),
  onStepEnd: step => console.log('step ended', step.stepNumber),
  onEnd: event => console.log('call ended', event.finishReason),
});
```

在单次 `generate()` 和 `stream()` 调用上配置的回调会在设置回调之外被调用，且设置回调先被调用。回调错误会被忽略，不会改变智能体的执行。

Harness 运行时会在内部执行其内置工具。对于这些工具，`onToolExecutionStart` 和 `onToolExecutionEnd` 描述的是运行时报告结果之后的逻辑工具生命周期。这些回调仍会在工具结果发布到结果流之前被递送。

## 运行时上下文

在 `HarnessAgent` 上设置 `runtimeContext`，让应用上下文对每个回合可用。使用 `prepareCall` 可以在每个新的提示词回合替换它。准备好的上下文可通过 `generate()` 和 `stream()` 获取，并在使用 `continueGenerate()` 和 `continueStream()` 进行内存中续传时保持不变。生命周期回调会收到完整上下文，它也可以在每个结果的 `finalStep.runtimeContext` 上获取。


```ts
const agent = new HarnessAgent({
  harness: claudeCode,
  runtimeContext: {
    conversationId: 'conversation-123',
    userId: 'user-456',
  },
  telemetry: {
    includeRuntimeContext: {
      conversationId: true,
    },
  },
  onEnd: ({ runtimeContext }) => {
    console.log(runtimeContext.userId);
  },
});
```

运行时上下文默认被排除在遥测之外。使用 `telemetry.includeRuntimeContext` 将各个顶层属性加入允许列表；只有设置为 `true` 的属性才会发送给遥测集成。生命周期回调与结果仍会收到完整上下文，因此请避免存储这些消费者不应访问的机密信息。

## 生成结构化输出

在构造 `HarnessAgent` 时设置 `output`，以要求每个回合都产生相同的类型化输出。智能体会把输出规范转换为 JSON Schema 交给 harness 适配器，校验完成的响应，并通过 `result.output` 返回解析后的值。


```ts
import { HarnessAgent } from '@ai-sdk/harness/agent';
import { Output } from 'ai';
import { z } from 'zod';

const agent = new HarnessAgent({
  harness: claudeCode,
  output: Output.object({
    schema: z.object({
      recipe: z.object({
        name: z.string(),
        ingredients: z.array(
          z.object({
            name: z.string(),
            amount: z.number(),
            unit: z.enum(['oz', 'fl oz', 'cup', 'gallon']),
          }),
        ),
        steps: z.array(z.string()),
      }),
    }),
  }),
});

const session = await agent.createSession({ sandboxSession });
try {
  const result = await agent.generate({
    session,
    prompt: 'Generate a lasagna recipe.',
  });
  console.dir(result.output, { depth: Infinity });
} finally {
  await session.destroy();
}
```

使用 `stream()` 时，读取 `partialOutputStream` 获取增量解析的值，并 await `result.output` 获取校验后的最终值。结构化数据也会以 JSON 形式保留在正常的文本与流式界面中；适配器不会把它加入 `finish` 部分。

Harness 结构化输出需要 schema。无 schema 的 `Output.json()`，以及无法强制执行 schema 的适配器或运行时配置，都会抛出 `HarnessCapabilityUnsupportedError`；参见[适配器能力表](/docs/ai-sdk-harnesses/harness-adapters#适配器能力)。

## 消息与历史

harness 会话拥有自己的原生对话历史。当你传入 `messages` 或消息数组形式的 `prompt` 时，`HarnessAgent` 会把最新的用户消息作为该回合的新输入，而不会把之前的完整对话重放给 harness。

末尾的工具消息的处理方式不同：工具审批响应和客户端提供的工具结果会继续那个产生了对应请求或工具调用的未完成 harness 回合。

这一点与模型调用不同——模型调用中应用通常发送完整的历史消息。在聊天路由中，请持久化并恢复 harness 会话，而不是依赖消息重放。

### 读取运行时自身的历史

运行时的对话可能会在你的进程之外增长——例如同一对话在智能体自己的 CLI 中被交互式地继续——而活跃事件流永远看不到这些交互。能够访问其运行时存储的适配器会通过 `session.readHistory()` 暴露它们：


```ts
const { messages, cursor } = await session.readHistory();
// Messages use role/content shapes. Adapter-specific details, including the
// runtime's raw record, are available under harnessMetadata.

// Later: read only what was recorded since.
const delta = await session.readHistory({ since: cursor });
```

历史读取因适配器而异；调用该方法前请先查阅适配器能力表。
当适配器未实现历史读取时，`readHistory()` 会抛出 `HarnessCapabilityUnsupportedError`；当它实现了但在当前环境中无法访问运行时的存储时（例如存储位于远程沙箱内），则抛出 `HarnessHistoryUnavailableError`。尚无任何记录消息的对话不是错误；它会解析为空的 `messages` 数组。

## 会话生命周期

请显式地结束每个会话：

- `session.destroy()` 停止运行时并放弃可恢复性。
- `session.detach()` 挂起运行时、返回恢复状态，并让传入的沙箱继续运行以便之后重新附加。如果回合未完成，恢复状态会包含续传状态。
- `session.stop()` 保存恢复状态，然后停止运行时。如果回合未完成，恢复状态会包含续传状态。
- `session.suspendTurn()` 用于跨进程边界的高级活跃回合续传。
- `session.hasUnfinishedTurn()` 报告当前回合是否必须先被继续或暂停，会话才能接受新的提示词。

一次性脚本和测试请使用 `destroy()`。需要多轮连续性的 HTTP 路由请使用 `detach()` 或 `stop()`。

## 在回合之间更改设置

使用 `callOptionsSchema` 和 `prepareCall` 为每个新回合派生 `model`、`skills`、`instructions`、`tools` 和 `runtimeContext`。这遵循与 `ToolLoopAgent` 相同的 call-options 模式：


```ts
import { HarnessAgent } from '@ai-sdk/harness/agent';
import { tool } from 'ai';
import { z } from 'zod';

const getPolicy = tool({
  description: 'Look up the active project policy.',
  inputSchema: z.object({}),
  execute: async () => 'Keep public APIs backward compatible.',
});

const agent = new HarnessAgent({
  harness: claudeCode,
  tools: { getPolicy },
  callOptionsSchema: z.object({
    area: z.enum(['frontend', 'backend']),
    enablePolicyTool: z.boolean(),
    useCheaperModel: z.boolean(),
  }),
  prepareCall: ({ options, ...call }) => ({
    ...call,
    model: options.useCheaperModel ? 'claude-haiku-4-5' : undefined,
    instructions: `Work as the ${options.area} specialist.`,
    runtimeContext: { area: options.area },
    skills: [options.area === 'frontend' ? frontendSkill : backendSkill],
    tools: options.enablePolicyTool ? { getPolicy } : undefined,
  }),
});

const session = await agent.createSession({ sandboxSession });
try {
  await agent.generate({
    session,
    prompt: 'Review the current implementation.',
    options: {
      area: 'frontend',
      enablePolicyTool: false,
      useCheaperModel: false,
    },
  });

  await agent.generate({
    session,
    prompt: 'Now review the API contract.',
    options: {
      area: 'backend',
      enablePolicyTool: true,
      useCheaperModel: true,
    },
  });
} finally {
  await session.destroy();
}
```

`prepareCall` 会在新提示词的自定义 `options` 通过校验之后运行。其设置随后在整个回合内固定下来。如果回合因等待工具结果、审批、停止条件或进程交接而暂停，其续传会复用相同的设置，不会再次调用 `prepareCall`。这防止了设置在回合中途发生变化。

更改 `model` 不会创建新的 harness 会话。每个适配器都会在下一个提示词之前切换或重新配置其运行时，同时保留会话的对话历史。

当 Codex 适配器的技能、指令或工具目录发生变化时，它会启动一个全新的原生 Codex 线程，因为 `codex exec resume` 保留了原始原生线程的引导过程。harness 会话仍然可用，但此前的原生对话上下文不会跨越这一设置变更边界。设置未变的回合会继续沿用现有的原生线程。

把 `abortSignal` 直接传给 `generate()` 或 `stream()`；它本来就是按调用设置的，不属于 `prepareCall`。`output` 也固定在智能体上，因为其响应格式与智能体的输出 schema 绑定。

当你把 `sandboxSession` 传给 `agent.createSession()` 时，调用方保留对该沙箱的所有权。`session.stop()` 和 `session.destroy()` 仍会结束 harness 运行时，但不会停止或销毁传入的沙箱会话。在这种情况下，智能体的构造函数不需要 `sandbox` 提供商。


```ts
const session = await agent.createSession({
  sessionId: chatId,
  sandboxSession,
});

try {
  const result = await agent.stream({ session, messages });

  for await (const part of result.stream) {
    if (part.type === 'text-delta') {
      process.stdout.write(part.text);
    }
  }

  const resumeState = await session.detach();
  await persistResumeState({ chatId, resumeState });
} catch (error) {
  await session.destroy();
  throw error;
}
```

## 恢复

请持久化这份不透明的恢复状态。在本例中，harness 的 `sessionId` 就是 `chatId`，沙箱 ID 也从同一个已知 ID 派生。如果你的应用无法派生沙箱 ID，请改为把 `sandboxSession.id` 与 harness `sessionId` 和恢复状态一起持久化。在让智能体恢复之前，先重新附加沙箱。创建时指定 `sandboxId` 会命名一个**新的**活跃沙箱，而绝不会去查找已存在的沙箱。如果同名的沙箱已存在，创建器复用该 ID 会失败；只有恢复函数会执行查找。


```ts
const resumeState = await loadResumeState({ chatId });
const sandboxId = `chat-${chatId}`;

const sandboxSession = resumeState
  ? await resumeVercelNetworkSandboxSession({ sandboxId })
  : await createVercelNetworkSandboxSession({
      sandboxId,
      ports: [4000],
      template: await agent.getSandboxTemplate(),
    });

const session = await agent.createSession(
  resumeState
    ? { sessionId: chatId, resumeFrom: resumeState, sandboxSession }
    : { sessionId: chatId, sandboxSession },
);
```

`HarnessAgent` 在把恢复状态交给运行时之前，会校验它确实由同一个 harness 适配器产生。如果恢复状态包含未完成的回合，请先调用 `continueStream()` 或 `continueGenerate()`，再发送新的提示词。Vercel 的恢复函数既能重新附加在 `detach()` 之后仍在运行的沙箱，也能重新附加已停止但带有可恢复快照的沙箱。在 `sandboxSession.destroy()` 将其删除之后，该 ID 便无法再被恢复。

## 继续被暂停的回合

对于必须跨进程边界交接活跃回合的高级工作流，请暂停该回合并持久化其续传状态：


```ts
if (session.hasUnfinishedTurn()) {
  const continuationState = await session.suspendTurn();
  await persistContinuationState({ chatId, continuationState });
}
```

当你只有来自 `suspendTurn()` 的原始续传状态时，使用 `continueFrom` 恢复，然后在不发送新提示词的情况下继续该回合：


```ts
const session = await agent.createSession({
  sessionId: chatId,
  continueFrom: continuationState,
  sandboxSession,
  // Rebind this when the suspended turn used host-only tool context:
  toolsContext,
  runtimeContext,
});

const result = await agent.continueStream({ session });
```

使用 `continueStream()` 获取增量输出，或使用 `continueGenerate()` 排空被继续的回合并返回 `GenerateTextResult`。

`toolsContext` 和 `runtimeContext` 被有意地不存入续传状态，因为它们可能包含凭据或不可序列化的宿主对象。当被暂停的回合使用了由 `prepareCall` 派生的上下文时，请把相同的值传给 `createSession`，在继续该回合的进程中重新绑定它们。进程恢复后若未重新绑定，续传会使用智能体构造函数级别的 `runtimeContext` 和 `toolsContext`。

## 在 Harness 步骤之后停止

使用 `stopWhen` 来启用语义化的步骤边界。谓词会在可能延续到另一个模型步骤的真实 harness 工具步骤之后运行，并收到当前调用已完成的步骤。当谓词匹配时，返回的结果即告结束，而底层回合仍未完成。终结性的纯文本步骤则会消费该回合的 `finish` 事件并自然结束。


```ts
import { isStepCount } from 'ai';

const steppedAgent = new HarnessAgent({
  harness: claudeCode,
  stopWhen: isStepCount(1),
});

const session = await steppedAgent.createSession({ sandboxSession });
const result = await steppedAgent.generate({
  session,
  prompt: 'Create a short TODO.md for this repository.',
});

if (session.hasUnfinishedTurn()) {
  const continueFrom = await session.suspendTurn();
  await persistContinuationState({ chatId, continuationState: continueFrom });
}
```

`stopWhen` 没有默认值。省略时，`HarnessAgent` 会持续运行，直到回合自然结束或因等待宿主输入而暂停，从而保留没有步骤控制的智能体的行为。可以传入单个谓词或数组；匹配任一谓词即结束当前结果切片。被停止的回合可通过 `createSession({ continueFrom })` 配合 `continueStream()` 或 `continueGenerate()` 恢复。

## 准备沙箱

使用 `sandboxConfig` 在 harness 启动之前准备沙箱。

`sandboxConfig.onBootstrap` 在沙箱模板创建期间运行，时机是 harness 适配器自身的引导之后、支持快照的提供商发布快照之前。用它执行那些应被未来会话复用的昂贵设置。提供 `onBootstrap` 时，还必须提供 `bootstrapHash`；每当引导输出应使可复用快照失效时，就更改该哈希值。

`sandboxConfig.onSession` 在每个沙箱会话被获取且其工作目录就绪之后运行，包括被恢复的会话。用它处理会话级文件或轻量配置。


```ts
const agent = new HarnessAgent({
  harness: claudeCode,
  sandboxConfig: {
    workDir: 'repo',
    bootstrapHash: 'ripgrep-v1',
    onBootstrap: async ({ session, abortSignal }) => {
      const result = await session.run({
        command:
          'command -v rg >/dev/null || (apt-get update && apt-get install -y ripgrep)',
        abortSignal,
      });
      if (result.exitCode !== 0) {
        throw new Error(`Failed to install ripgrep: ${result.stderr}`);
      }
    },
    onSession: async ({ session, sessionWorkDir, abortSignal }) => {
      await session.writeTextFile({
        path: `${sessionWorkDir}/README.md`,
        content: 'Session notes for the harness.',
        abortSignal,
      });
    },
  },
});
```

`workDir` 是可选的。提供时，它必须相对于沙箱的默认工作目录，并会被用作会话工作目录。设为 `'.'` 表示直接使用沙箱的默认工作目录本身。省略时，常规会话使用默认的 `<harnessId>-<sessionId>` 目录，而 `onBootstrap` 收到的是沙箱的默认工作目录。

## 准备可复用沙箱

使用 `agent.getSandboxTemplate()` 在创建沙箱之前解析单个 harness 的引导配置和 `sandboxConfig.onBootstrap`。模板的标识在沙箱创建之前即可确定。Vercel 会持久化准备好的快照，并基于它创建活跃沙箱；相同的调用会复用该快照：


```ts
const sandboxSession = await createVercelNetworkSandboxSession({
  runtime: 'node24',
  ports: [4000],
  template: await agent.getSandboxTemplate(),
});

const session = await agent.createSession({ sandboxSession });
try {
  await agent.generate({ session, prompt: 'Inspect this repository.' });
} finally {
  await session.destroy();
  await sandboxSession.destroy();
}
```

对于共享同一个调用方引导 Hook 的多个 harness，可以从所有适配器构建一个模板。`harnessId` 重复时以最后一个适配器为准，且配置标识在哈希前会先排序。`onSession` 不属于模板，会在每个被获取的会话上单独运行。


```ts
import { createHarnessSandboxTemplate } from '@ai-sdk/harness/agent';

const template = await createHarnessSandboxTemplate({
  harnesses: [claudeCode, codex],
  sandboxConfig,
});
console.log(template?.identity);

const sandboxSession = await createVercelNetworkSandboxSession({
  source: { type: 'snapshot', snapshotId: baseSnapshotId },
  ports: [4000],
  template,
});
```

派生的模板会在其缓存键中包含源快照 ID，因此相同源与模板的重复调用会复用准备好的快照。在依赖缓存模板时，请固定易变的 Git 修订版、镜像标签和源 URL。`sandboxId` 命名的是活跃沙箱，而不是它的可复用模板。现有的原生 `name` 选项仍然命名活跃沙箱；如果两者都提供，其值必须一致。

## 设置

`HarnessAgent` 接受以下主要设置：

- `harness`：适配器实例。
- `model`：可选的 harness 专属模型标识符。省略时，harness 使用其默认模型。
- `id`：可选的稳定智能体标识符。
- `instructions`：在受支持时附加到运行时的系统或开发者提示词，否则前置到用户提示词的指令。
- `headers`：随模型请求一起发送的额外请求头。请求头在构造时固定。不允许使用 `authorization`、`x-api-key`、`user-agent` 和 `x-client-app`。
- `callOptionsSchema` 和 `prepareCall`：校验自定义调用选项，并为每个新回合派生模型、技能、指令和工具。
- `output`：应用于每个回合的类型化输出规范。
- `stopWhen`：在可能延续到另一个模型步骤的 harness 工具步骤完成之后，结束结果切片的条件。
- `tools`：当 harness 调用时由宿主执行的 AI SDK 工具。
- `runtimeContext`：每个回合转发给生命周期回调与结果的应用上下文；`prepareCall` 可在新提示词回合替换它。
- `activeTools`：harness 可以调用的内置与宿主执行工具的允许列表。
- `inactiveTools`：harness 不能调用的内置与宿主执行工具的拒绝列表。
- `skills`：由适配器呈现的指令包。
- `permissionMode`：内置工具权限模式。
- `toolApproval`：宿主执行工具的审批状态映射。
- `sandboxConfig`：沙箱工作目录与生命周期 Hook 配置。
- `telemetry`、`debug` 和 `onLog`：可观测性与诊断。使用 `telemetry.includeRuntimeContext` 把运行时上下文属性加入遥测的允许列表。

遥测会报告每个回合解析后的模型、指令和活跃的宿主定义工具。技能属于适配器上下文，没有对应的 AI SDK 遥测字段，因此不会包含在标准遥测事件中。

适配器专属设置应放在适配器工厂上，例如 `createCodex({ reasoningEffort: 'high' })`。

## 自定义沙箱编排

当你的应用自行创建和管理沙箱时，先准备好网络沙箱会话，再把同一个会话传给 `agent.createSession()`。智能体不会创建沙箱，也不会停止或销毁调用方拥有的沙箱。


```ts
import { HarnessAgent } from '@ai-sdk/harness/agent';
import { claudeCode } from '@ai-sdk/harness-claude-code';
import { createVercelNetworkSandboxSessionFromNativeSandbox } from '@ai-sdk/sandbox-vercel';
import { Sandbox } from '@vercel/sandbox';

const sandbox = await Sandbox.create({
  runtime: 'node24',
  ports: [4000],
});
const sandboxSession =
  createVercelNetworkSandboxSessionFromNativeSandbox(sandbox);

const agent = new HarnessAgent({ harness: claudeCode });
const session = await agent.createSession({ sandboxSession });

try {
  const result = await agent.stream({
    session,
    prompt: 'Create a short TODO.md for this repository.',
  });

  for await (const part of result.stream) {
    if (part.type === 'text-delta') {
      process.stdout.write(part.text);
    }
  }
} finally {
  await session.destroy();
  await sandboxSession.destroy();
}
```

### 无网络控制的基本沙箱会话

下面的示例演示了基本会话 API 的工作方式。如果你的项目能够暴露完整的网络沙箱会话，强烈建议传入该会话。只有当项目无法暴露完整网络会话时，才传入受限的基本会话。

基本沙箱会话只暴露文件系统与进程 API。智能体仍然把沙箱生命周期留给调用方。对于桥接型 harness，需要在适配器上配置桥接端口及其外部可达的端点，因为基本会话无法解析它们。


```ts
import { HarnessAgent } from '@ai-sdk/harness/agent';
import { createClaudeCode } from '@ai-sdk/harness-claude-code';
import {
  createVercelNetworkSandboxSessionFromNativeSandbox,
  createVercelSandboxSessionFromNativeSandbox,
} from '@ai-sdk/sandbox-vercel';
import { Sandbox } from '@vercel/sandbox';

const sandbox = await Sandbox.create({
  runtime: 'node24',
  ports: [4000],
});
const sandboxSession =
  createVercelNetworkSandboxSessionFromNativeSandbox(sandbox);
const portEndpoint = await sandboxSession.getPortEndpoint({
  port: 4000,
  protocol: 'ws',
});
const restrictedSandboxSession =
  createVercelSandboxSessionFromNativeSandbox(sandbox);
const claudeCode = createClaudeCode({ port: 4000, portEndpoint });

const agent = new HarnessAgent({ harness: claudeCode });
const session = await agent.createSession({
  sandboxSession: restrictedSandboxSession,
});

try {
  const result = await agent.stream({
    session,
    prompt: 'Create a short TODO.md for this repository.',
  });

  for await (const part of result.stream) {
    if (part.type === 'text-delta') {
      process.stdout.write(part.text);
    }
  }
} finally {
  await session.destroy();
  await sandboxSession.destroy();
}
```
