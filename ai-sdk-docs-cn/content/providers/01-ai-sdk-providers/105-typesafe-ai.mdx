# TypeSafe 提供商

[TypeSafe](https://typesafe.ai) 提供商支持实验性决策（decision）API，原生提供 Choice、Score 和 Boolean 答案。它将所有问题放在同一个请求中，针对同一状态发送。

## 安装

安装该提供商：

```sh
pnpm add @ai-sdk/typesafe-ai
```

设置 `TYPESAFE_AI_API_KEY` 环境变量。导入默认提供商或配置一个实例：

```ts
import { createTypeSafeAi, typeSafeAi } from '@ai-sdk/typesafe-ai';

const customTypeSafe = createTypeSafeAi({
  apiKey: 'your-api-key',
});
```

`createTypeSafeAi` 接受：

| 设置      | 说明                                                                   |
| --------- | ---------------------------------------------------------------------- |
| `apiKey`  | API 密钥；默认取 `TYPESAFE_AI_API_KEY`。                               |
| `baseURL` | 默认取 `TYPESAFE_AI_BASE_URL`，其次 `https://api.typesafe.ai/v1`。     |
| `headers` | 附加请求头。                                                           |
| `fetch`   | 自定义 fetch 实现。                                                    |

使用 `TYPESAFE_AI_BASE_URL` 可以让默认的 `typeSafeAi` 实例经由受信任的代理或自托管的 TypeSafe 兼容服务器路由：

```sh
TYPESAFE_AI_BASE_URL=http://127.0.0.1:8766/v1
```

显式传给 `createTypeSafeAi` 的 `baseURL` 优先于环境变量。配置的服务器会接收 API 密钥和决策状态，并且必须实现 TypeSafe 的 `POST /systemone` API。

## 决策

```ts
import { typeSafeAi } from '@ai-sdk/typesafe-ai';
import { experimental_decide } from 'ai';

const result = await experimental_decide({
  model: typeSafeAi.decisionModel('jev-latest'),
  state: {
    message: 'I was charged twice. Please refund the duplicate.',
  },
  questions: {
    department: {
      type: 'choice',
      instructions: 'Which team should handle this?',
      criteria: {
        billing: { includes: ['Charges', 'Invoices', 'Refunds'] },
        technical: ['Bugs', 'Outages'],
        other: null,
      },
    },
    severity: {
      type: 'score',
      instructions: 'How severe is the issue?',
      criteria: ['Cosmetic', 'Workaround exists', 'Blocking; no workaround'],
    },
    requestsRefund: {
      type: 'boolean',
      instructions: 'Is the customer requesting money back?',
    },
  },
});

console.log(result.answers.department.choice);
console.log(result.answers.severity.score);
console.log(result.answers.requestsRefund.probability);
console.log(result.usage);
```

请使用 `jev-latest` 或其他 TypeSafe 模型 ID。响应中会包含实际的模型 ID，例如别名背后解析出的版本。可以使用模型实例、自定义别名或已注册的提供商。将 `typeSafeAi` 显式配置为 `globalThis.AI_SDK_DEFAULT_PROVIDER` 后，你可以直接传 `model: 'jev-latest'`。参见[模型别名与注册表](/docs/ai-sdk-core/decisions#模型别名与注册表)。

| 问题      | TypeSafe 原生原语         | 限制与语义                                                           |
| --------- | ------------------------- | -------------------------------------------------------------------- |
| `choice`  | Choice                    | 1–255 个选项；返回所选选项与完整概率。                               |
| `score`   | Score                     | 2–10 个有序评分等级；返回小数分值与完整概率。                        |
| `boolean` | Noul                      | 必须返回模型估计的为真概率。                                         |

状态、说明和描述除字符串外还接受 JSON 对象与数组。描述可以为 `null`。布尔 true/false 准则是可选的。SDK 使用中性的名称 `boolean`，并将其映射到 TypeSafe 的 `noul` 字段。

### 舍入值与置信度

TypeSafe 返回的分值和概率四舍五入到小数点后两位。`result.rounding` 会报告这一精度，使 SDK 在检查分布之和与加权均值时可以计入舍入影响。返回值保持原样不变；由于舍入，概率之和可能不恰好等于一。

置信度（confidence）是 TypeSafe 的另一项统计指标，对于 Choice 和 Score 答案，可在 `result.providerMetadata.typesafe.confidence[questionId]` 下获取。Boolean 的概率始终表示 P(true)，而不是对任一结果的置信度。请在应用代码中自行选择决策阈值。

### 错误与重试

提供商失败使用 `APICallError`，包括校验错误和身份验证错误。Core 会根据 `maxRetries`（默认：2）对 `429`、`529` 等瞬时失败进行重试。`abortSignal`、请求头和自定义 fetch 都会被转发。提供商侧没有重试循环。

目前没有定义提供商特有的选项。`providerOptions.typesafe` 下的未知条目会产生不支持选项的警告。语言、嵌入和图像模型工厂会抛出 `NoSuchModelError`。

决策模型支持工作流序列化。自定义 fetch 函数不会被序列化；恢复后的模型使用默认的 fetch 实现。
