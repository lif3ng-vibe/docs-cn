这是 Astryx CLI 系列的第二篇文章。第一篇讲的是 [CLI 即文档](/blog/the-astryx-cli)。

## 你大概已经注意到，AI 非常擅长模仿

可以说，LLM 最擅长的事就是模仿。众所周知，它想出原创点子的能力要差得多，而在前端代码上更是举步维艰。对任何用过主流模型的人来说，这都不是新闻，而我们构建 Astryx 时就一头撞上了这个问题。

早期我们的模板并不好。有太多纯 StyleX 代码，太多 div 和 span，真正的组件却不够多。我们让智能体（agent）去搭一个页面，然后眼看着它几乎不碰 Astryx，或者交回一个看起来就是坏掉的东西。这让我们困惑了一阵。智能体手里有文档，通过 CLI 能拿到每一个 prop 和每一个示例，它需要的一切都有。为什么它全都不用？

答案简单得近乎可笑：它在模仿我们的坏例子。垃圾进，垃圾出，老话依然成立。这也是我们为模板写了一份[评分细则](https://github.com/meta/astryx/wiki/Contributing-Templates)的原因。它每次都以同样的方式给每个模板打分，马虎的东西混不过去，一屋子设计师也能守住同一条标准线。我们修好了智能体正在模仿的东西，输出随之改善。

## 值得模仿的好范例

这解决了质量问题。我们现在有大量设计师制作的高质量模板，这一项已经达标。下一个问题是易用性。一个整页示例，只有当你的需求恰好和我们做过的类似时才有用。需求千差万别，用整页去覆盖每一种需求并不可持续。所以我们按三种尺寸提供示例：

- **页面**是完整的模板。当你的需求恰好与我们的某个成品吻合时，它就是理想之选。
- **区块**是更小的可组合单元。它满足同样的质量标准，但不是完整页面。你可以把它们组合成需要的东西。
- **组件**示例展示用好某个具体组件的一种方式。

于是从整页到最小的组件，每种尺寸我们都有高质量示例，覆盖了完整的范围。下一个问题是智能体究竟怎么用上这一切。它当然可以四处 grep，也能找到一些东西。但如果它想要的是 analytics，而我们把模板命名成了 dashboard 呢？类似这种词对不上的情况很多，纯文本搜索撑不住，我们得在暴露这些内容的方式上更聪明一些。

## 推出 `astryx build`

解决上述一切的是一个叫 `astryx build` 的单一命令。它接收一段自然语言提示，返回可能与你正在构建的东西相关的条目。这是你的智能体在当前项目中查找任何所需内容时使用的唯一命令。如果它找不到完整的页面，就可能推荐一个区块或一个组件。它不只是扔回一份结果列表，而是推荐出第一步该怎么走，让智能体清楚从哪里下手。某种意义上，它几乎就是一个交互式提示。

底层是一个朴素的排序算法。`astryx build` 先从你的组件、Hook、文档和模板中一次性收集所有候选。然后清理你的提示：丢掉填充词，把其余的词通过内置的同义词表展开，这样请求 dashboard 也能命中 analytics、KPI 和 metrics。它甚至对每个词做词干化处理，让 chart、charts 和 charting 全部归并到同一个词根。

然后每个候选都在一套固定的信号阶梯上打分：

- 精确的名称匹配优先。
- 精确的关键词次之。
- 再往下是通过编辑距离容忍错字和小拼写偏差的近似匹配。

只出现在描述里的词也算数，但干净利落的名称或关键词匹配永远排在它前面，这样你拿到的是真正对得上的东西，而不是恰好提过一次你的词的杂项。面对较长的提示，它会对每个概念单独打分，并奖励覆盖概念最多的候选，再对这些匹配的强度取平均，所以啰嗦的提示不会因为绕来绕去而被惩罚。

模板还有一个额外的妙处。每个模板不只按标题索引，还按它的构成索引。一个页面会携带它内部实际用到的组件名，所以即便标题提供不了什么信息，它也能浮现出来。最终你的智能体会拿到搭建页面所需的一切：

- 最接近的页面作为起点
- 覆盖其中部分的区块
- 填补空缺的组件
- 每个页面反正都需要的框架与地基

然后它选定一个唯一的起手式。强的页面匹配意味着"初始化这个模板"，弱的匹配意味着"把它当作布局参考，组合出其余部分"。这一切快速且确定，同样的提示每次都返回同样的结果。没有网络调用，背后也没有模型。你可以自己去读[完整的实现](https://github.com/meta/astryx/blob/main/packages/cli/src/api/search.mjs)。

最后，每次 `astryx build` 运行都会以一小段规则收尾：布局不用 div，不写内联样式，其余一切都用 token。这还是那份评分细则，只是这次指向的是你的智能体，而不是我们的设计师。智能体依然可以即兴发挥，而这些围栏只是在它发挥时把它留在体系之内。

## 这才是重点

我们用 Astryx 想抵达的目标，很大一部分就是这个：智能体应当能在几乎不需要你费力的前提下，产出真正优秀的前端。你应该能够随手搭起一个东西并信任它，而不必费心琢磨它是怎么做到的。

我们没有对抗这个模仿者，而是顺势而为。我们做好东西，把它们放在智能体找得到的地方，然后让它去模仿。好范例变成好输出，好输出又变成下一批值得模仿的东西。给模仿者一些值得模仿的东西，它看起来就很像有品味了。
