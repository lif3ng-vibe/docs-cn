# Openship 的 AI 构建是如何工作的

运行 `openship deploy` 之后，应用上线前还有很多事在发生。下面就讲讲 AI 构建系统的工作原理。

## 第 1 步：框架识别

Openship 会扫描项目中的这些信号：

- `package.json` 的 scripts 与依赖
- 配置文件（`next.config.js`、`nuxt.config.ts`、`Cargo.toml` 等）
- 是否存在 Dockerfile
- 目录结构特征

由此得到一个带置信度评分的框架匹配结果。如果 Openship 以 95% 的置信度识别出 Next.js，就会采用 Next.js 构建流水线；如果有 Dockerfile，则直接使用它。

## 第 2 步：配置生成

根据识别出的框架，Openship 会生成：

- **构建命令**——`npm run build`、`go build` 等。
- **启动命令**——`npm start`、`./server` 等。
- **端口映射**——检测应用监听哪个端口
- **环境变量**——按框架惯例建议所需的变量

以上任何一项都可以在 `openship.json` 中覆盖。

## 第 3 步：构建优化

AI 层会对构建做优化：

- **层缓存**——依赖层与源码分开缓存
- **多阶段构建**——生产镜像不含开发依赖
- **并行构建**——多服务项目并发构建

## 第 4 步：健康检查

部署完成后，Openship 会验证：

- 容器成功启动
- 健康检查端点有响应
- SSL 证书已开通且有效

任何一项检查失败，部署都会自动回滚。

## 接下来

我们正在做 AI 诊断——构建失败时，Openship 会分析报错并给出修复建议。敬请期待。
