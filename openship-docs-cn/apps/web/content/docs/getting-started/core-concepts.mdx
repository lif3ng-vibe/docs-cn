有几个词，Openship 反反复复地用。一旦掌握，其余文档读起来就会很轻松。可以用一个比喻把它们串起来：你的代码是**菜谱**（recipe），Openship 是**厨房**（kitchen），下面各节就是厨房里的不同部位。本页是一份简短词汇表——每个词一句话，全用白话。

## 组织（工作区）

*就像你和团队共用的一个文件柜。*

你在 Openship 里创建的一切都归属于一个**组织**（organization）——控制台里也称它为工作区（workspace）。你的项目、服务器和域名都属于组织，而不是你个人。团队正是因此得以共享它们。

你可以同时属于多个组织，组织里的每个人都有一个**角色**（role）：owner、admin 或 member。角色决定他能做什么。参见[权限](/docs/security/permissions)。

## 项目

*就像菜单上的一道菜——你想上线的一个应用。*

**项目**（project）是你要部署的一个应用。它记住代码来自哪里（一个 GitHub 仓库或磁盘上的文件夹）、怎么构建，以及挂在它身上的一切：部署记录、网址、环境变量、日志和设置。

其中大部分都不必手动配置——Openship 会读你的代码并填入合理的默认值。如何创建一个项目，见[快速开始](/docs/getting-started/quickstart)。

## 环境

*就像一间招待顾客的正经厨房，和一间用来试验菜谱的试做厨房。*

**环境**（environment）是项目的一份独立副本。最常见的两种是：

- **Production**（生产环境）——真实用户在用的正式版本。
- **Preview**（预览环境）——在正式上线前试验改动的临时副本。

（还有一个用于本地开发的 **development** 环境。）每个环境都保存各自的部署、环境变量和网址，因此做测试绝不会碰到线上。

## 部署

*就像一本书的一次印刷——每次部署都是新版。*

**部署**（deployment）是把你的代码构建并上线的一次尝试。每次部署——或开启自动部署（auto-deploy）后每次推送到 GitHub——Openship 都会新建一条部署记录。每次成功的发布（release）都会有一个版本号（v1、v2、v3……）以便区分。

同一时刻只有一条部署处于**线上**（live）状态，其余作为历史保留——万一新版本出了问题，可以**回滚**（roll back）到更早的一条。每条部署都会记录它构建的是哪个 commit、是否成功，以及上线的 URL。

## 服务

*就像一家有厨房、吧台和洗碗间的餐厅——各自独立的工位协同工作。*

大多数项目只是一件事。但有些应用实际上是几个部件并肩运行——一个网站、一个数据库、一个缓存。每个部件就是一个**服务**（service）。Openship 支持两种形态：

- **Compose**——服务定义在 `docker-compose` 文件里（例如 `web`、`db` 和 `redis`）。
- **Monorepo**——多个应用住在同一个仓库里，各自构建为独立的服务。

服务之间可以相互依赖，每个服务可以有自己的公开地址，也可以保持私密，而且一次部署会把整套一起拉起来。参见[多服务与 Compose](/docs/guides/compose-multi-service)。

## 域名

*就像你家门牌上的街道地址。*

**域名**（domain）是人们访问你的应用时输入的网址，例如 `app.example.com`。Openship 可以先给项目分配一个免费地址，你也可以连接自己拥有的自定义域名。

添加自定义域名时，Openship 会检查一条 DNS 记录来确认它确实属于你，然后自动为你启用 HTTPS。每个项目中有一个域名会被标记为**主域名**（primary，即主地址）。完整细节见[域名 API](/docs/api/domains)。

## 服务器

*就像在别人的厨房里租一个灶台——菜谱你带，场地他出。*

**服务器**（server）是你自己的远程计算机，Openship 通过 SSH 连上去运行你的应用。只需带着连接信息（主机、用户，以及密钥或密码）添加一次，之后 Openship 就能向它部署。一个组织可以有多台服务器。

<Callout title="只有“server”运行时才需要添加服务器" type="info">
如果本地部署或部署到 Openship Cloud，你完全不用添加服务器。服务器只用于在你自己拥有的机器上运行应用。
</Callout>

## 运行时

*就像选择在家做、去朋友家做，还是干脆点外卖。*

部署时你要选择**应用实际运行在哪**。部署页面上这个选项叫**部署目标**（deploy target），共有三种：

- **Local**（本地）——就在运行 Openship 的那台电脑上。在桌面应用里试用再合适不过。
- **Your server**（你的服务器）——在你自己的某台[服务器](/docs/getting-started/core-concepts#服务器)上，通过 SSH 连接，默认在 Docker 中运行。
- **Openship Cloud**——由 Openship 替你运行，不需要你自己的机器。

在部署页面上选好即可，之后也可以在它们之间移动项目。每种方式底层如何工作，见[运行时模型](/docs/architecture/runtime-model)。
