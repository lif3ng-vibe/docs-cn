---
title: 云边界
description: 自托管实例如何与 Openship Cloud 通话而不泄露本地身份——被代理的请求只携带所有者的云会话，别无他物。
---

当你把自己运行的这份 Openship 连接到 Openship Cloud 时，两者保持干净的隔离。不妨想成两国之间的边检口岸：你的实例是一侧，云是另一侧，每个过境的请求只出示一本护照——组织所有者的云会话——并且不带任何家里的东西。没有本地身份证，没有家门钥匙，也没有回信地址。

<Callout title="两侧各是什么">
- **自托管实例**——你跑在自己机器或服务器上的 Openship。它是唯一的**控制面**（control plane）与**权限面**（permission plane）：决定谁能做什么的那一层。每个请求都先在这里接受检查。
- **Openship Cloud**——托管服务，位于 `https://api.openship.io`。对住在云上的任何项目，它是**上游权威**（最终说了算的一方）。
- **代理**——当请求针对云所有的项目时，你的实例会把它*转发*给上游，而不是亲自作答。这个转发步骤就是边界，下面所有规则都在这里生效。
</Callout>

## 一个网关，一个身份

所有云项目流量都经过代码里**唯一**的一处，并以组织所有者的云会话身份通行。只有先通过你本地权限检查的请求才会抵达云端——代理运行在权限闸门*之后*，因此不存在绕开本地访问控制的云后门。

谁是“所有者”？只有组织所有者能关联云账号（关联操作有所有者角色检查把守），其会话成为该组织唯一的云身份。每个成员的云操作——部署、分析、域名、GitHub——都在这一个身份下运行，处处以同一方式解析，因此控制台和部署路径对“究竟是谁在操作”绝不会有分歧。

代理并不会让请求在家里隐身。转发步骤运行在你本地权限中间件*内部*，因此被代理的云操作和本地操作一样，会写入同样的本地审计记录——即使事情由云端执行，你的实例仍然记录着谁做了什么。

## 什么能过境——什么永远不能

你的实例向上游代理请求时，会从零重建这个请求。只转发：

- HTTP **方法**（`GET`、`POST` 等），
- **路径**与查询字符串，
- 请求**体**（写操作时），
- **Content-Type** 头，
- 一个装有所有者云会话令牌的 **Authorization** 头（由传输层添加，绝不取自入站请求）。

其余一切都被刻意丢弃。尤其是，代理**一概**不转发下面这些：

| 永不转发 | 原因 |
|---|---|
| 本地会话 Cookie | 浏览器登录只在本地有效；云永远看不到它。 |
| `X-Organization-Id` | 云从所有者的令牌解析组织，而不是从头里。本地组织 id 在上游毫无意义（本地组织 id ≠ 云组织 id），只会是颗地雷。 |
| `X-Project-Source` 及其他客户端提示 | 路由提示只留在本地。 |
| `Host` / 原始来源 | 请求会被重新寻址到 `api.openship.io`。 |

<Callout title="不变式" type="info">
被代理的请求**只转发方法、路径、请求体和 Content-Type**，外加所有者的云 Bearer 令牌。本地会话、本地组织 id、本地主机名，一概不过境。这条规则白纸黑字写死在唯一的代理模块里——那是把入站请求转发给云后端的唯一地方。
</Callout>

## 本地 id 走私不到上游

由于 `X-Organization-Id` 被剥掉，调用者没法把一个本地标识递给云、让它对别的组织的数据动手。云完全从所有者的 Bearer 令牌判断请求属于哪个组织：它在自己的会话表里查这个令牌，从那份可信的服务端记录推导出用户——进而推导出组织。被代理的请求里不存在任何一个字段，能让本地 bug 或本地攻击者把矛头指向别人的云数据。

## 没有混合形态

- **云项目没有本地行**。你的实例不为它保留任何数据库记录；对云项目而言，实例永远只是网关。因此本地 bug 或搞砸的迁移碰不到云所有的数据——本地根本没有什么可供损坏。
- **本地（或服务器）项目绝不在云算力上运行**。两个世界不共享执行。
- **陌生 id 一律同样的 404**。请求一个与你组织毫无关联的云项目 id，你得到的“未找到”与请求一个完全无关的 id 一模一样——你的实例甚至不会泄露它存在。这堵住了 **IDOR**（不安全的直接对象引用——猜别的租户的 id 来读他们的数据）。

## 存储的凭据

你的实例保存的唯一云机密，是所有者的云会话令牌。它：

- **静态加密**——以 AES-256-GCM（认证加密）密文存在所有者的设置行里，只在发出出站调用的那一刻于服务端解密。
- **从不暴露给浏览器**——控制台永远收不到这枚令牌。它待在服务端，只在你实例发出的那次调用上作为 Bearer 出示。云流量完全不涉及任何客户端侧的 Cookie 或令牌。
- **实时校验**——“连着吗”由询问云端来回答，而不是看令牌是否还躺在磁盘上。云在身份端点用 `401` 拒绝的令牌会被自动清除；瞬时的 `5xx` 不会被视为断连。

<Callout title="可选：把会话钉死到一台设备" type="info">
在云一侧，可以用 `CLOUD_SESSION_PINNING` 设置把已连接实例的会话**钉**在创建会话时记录的 IP 地址和 User-Agent 上。默认是 `warn`——不匹配会记日志，但请求仍然放行；`off` 完全跳过检查；`strict` 在不匹配时用 `401` 拒绝请求。严格模式能抓住从别的网络或客户端重放的被窃令牌，代价是会误伤切换运营商或 VPN 的用户。
</Callout>
