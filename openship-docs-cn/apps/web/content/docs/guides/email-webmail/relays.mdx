---
title: 第三方邮件投递
description: 把你邮件服务器的出站邮件经由外部 SMTP 中继投递。
---

SMTP 中继（relay）就是一个中间人：它接下你的服务器想发的邮件，并真正投递给全世界——而不是你的机器直连 Gmail 或 Outlook 去说。

值得配中继，因为投递成败系于 IP 信誉：全新的服务器 IP 毫无信誉，收件箱提供商标它会很快退信、或把它的邮件丢进垃圾箱。把出站邮件经由一家成熟的中继提供商路由，意味着邮件从收件方已经信任的 IP 发出。它还绕开了 25 端口——大多数云提供商默认封锁出站 25 端口——中继改走 587 端口发信，因此无需申请任何服务限制豁免。

Openship 的邮件中继原生支持这一点——前往 **Emails → Sending → “Relay via Amazon SES (or any SMTP relay)”**，对没有预设的中继选择提供商 **Custom**（自定义）。同样的主机、端口和凭据字段在 **Settings → Email**（设置 → 邮件）下也可用——如果你更想让 Openship 自己的通知邮件也经同一家提供商中继的话。

无论选哪家提供商，它大致都会向你要这些东西：

- **DNS 记录**（SPF、DKIM，有时还有 DMARC），添加在你域名的 DNS 服务商处，让收件服务器能够核实：声称来自你域名的邮件，确实来自你授权的中继。
- **发件人注册或验证**——大多数中继拒绝代表它们不认识的 From 地址发信，因此在邮件开始流通前，你要逐个注册/验证发件人（或你的整个域名）。
- **SMTP 凭据**——一个用户名和密码（或充当密码的 API 密钥），仅限发信用途。
- 填进 Openship 中继表单的**主机与端口**——几乎总是 `587` 端口。

下一份文档介绍 Oracle Cloud（OCI）Email Delivery：[OCI Email Delivery](/docs/guides/email-webmail/relay-oci)。

## 其他提供商

OCI 只是一个选项——AWS SES、Resend、Mailgun、SendGrid 等提供商全都长一个样：DNS 认证（SPF/DKIM）、发件人或域名验证、SMTP 凭据，以及填入同一个 **Emails → Sending** 表单的主机/端口。如果你配合 Openship 用过其中某一家，欢迎提 PR 在这里为该提供商补一页。
