VPS 不够用了，还是想合并机器？Openship 可以把一个**运行中**的项目——它的容器*和*卷数据——从一台已连接的服务器迁到另一台。它复用已经在跑的镜像（无需重建），并在主机之间直接流式传输数据。两台服务器只需都通过 SSH 连接到 Openship。

<Callout title="与平台导入是同一引擎">
在你自己的服务器之间迁移，与[从 Coolify / Dokploy / Dokku 导入](/docs/guides/migrate-from-coolify-dokploy-dokku)走的是同一套迁移流程——你只是选择一个**不同的目标服务器**。那一页有更深入的架构说明；本页聚焦于服务器到服务器路径。
</Callout>

## 开始之前

- **两台服务器都已连接**到 Openship（Servers → Add server），且你需要对**源和目标两者**的 `server:write` 权限。
- **本地构建的镜像无法跨主机**。镜像构建于源服务器的服务（在目标上没有可拉取的镜像仓库）会被阻止——请改为在当前服务器上*原样接管*它们。运行已发布镜像的服务（`postgres`、你 push 的应用镜像、应用目录应用）可以正常迁移。
- **跨服务器永远不是零停机**。与同服务器接管不同，迁往另一台主机会为了让数据一致复制而停止原容器，然后在目标上验证一次全新部署——存在一个真实（通常较短）的停机窗口。下文的 DNS 步骤正是把停机保持在秒级而非分钟级的关键。

<Callout type="warn" title="先调低 DNS TTL——提前一天做">
迁移会把你的应用重新指向一个**新的服务器 IP**。对**自定义域名**来说，这意味着更新其 `A` 记录——而旧记录会按其 **TTL** 设定的时长被缓存。迁移开始前几个小时（最理想是提前一天），先在 DNS 服务商那里把域名 TTL 设为 60 秒（1 分钟）。**这样，切换后把 `A` 记录翻向新服务器时，它大约一分钟内就会生效，而不是数小时**——这就是几秒停机与长尾停机之间的差别。确认迁移完成后把 TTL 调回。（免费 `.opsh.io` 域名会替你做好路由——无需碰 `A` 记录。）
</Callout>

## 迁移一个项目（分步操作）

<Steps>

<Step>
### 发起迁移并选择源服务器

打开迁移向导，选择**源服务器**（服务器 A）。Openship 以只读方式扫描并列出正在运行的内容——每个项目/服务及其端口和卷。

</Step>

<Step>
### 选择要迁移的工作负载

勾选你想要搬到新机器上的项目或服务。源上的反向代理会被自动排除——你搬的是应用，不是边缘。
</Step>

<Step>
### 选择目标服务器

设定**目标服务器**（服务器 B）——必须是一台*不同的*已连接服务器。正是这一点让它成为服务器到服务器迁移，而不是原样接管。具名卷和可移动的应用数据挂载直接以 **A → B** 流式传输（同一 Docker 守护进程：`tar → tar` 复制；跨守护进程：gzip 流）；系统路径（`/proc`、`/sys`、`/var/lib/docker`、socket）绝不复制。

<Callout type="info" title="你的数据在源端是安全的">
Openship **拒绝覆盖目标上非空的同名卷**，因此重跑不会毁掉数据，迁移过程中也绝不删除源卷。
</Callout>
</Step>

<Step>
### 迁移

Openship 为做一致的复制而停止 A 上的原容器，把卷流式传到 B，用同一镜像在彼处拉起工作负载，并轮询至**就绪**（大型首次迁移最长约 20 分钟）。可以实时观看进度。

</Step>

<Step>
### 重新指向 DNS、验证，然后切换

工作负载此刻已在服务器 B 上线，Openship 也已在彼处重新注册其路由 + 证书。对**自定义域名**，在你的 DNS 服务商处把 `A` 记录更新为**服务器 B 的 IP**（低 TTL 的作用正在于此——约一分钟内生效）。确认应用经由 B 提供服务后，执行**切换**以停止并移除 A 上遗留的容器。**切换绝不触碰你的源卷**，所以在你确信之前始终留有后备；之后把 DNS TTL 调回。

<Callout title="切换之前先验证新服务器" type="warn">
切换会**停止并移除旧工作负载**——在你确认服务器 B 完全健康之前不要执行：应用能加载并服务流量、你的**数据完好无损**（登录、打开一条记录、检查卷/上传和数据库）、每个服务都处于 `RUNNING` 状态。因为切换让**源卷在 A 上原封不动**，你可以把旧服务器留作后备，直到确信无疑。如果有任何不对劲——数据缺失、服务起不来、路由/TLS 不对——**不要切换**；让 A 继续运行，并[在 GitHub 上提 issue](https://github.com/oblien/openship/issues)，我们会帮忙。
</Callout>
</Step>

</Steps>

## 哪些会迁移，哪些不会

- **会迁移**：运行中的容器（经由其当前镜像）、具名卷和可移动的应用数据挂载——主机到主机流式传输；路由与 Let's Encrypt 会在目标上重建。
- **不迁移**：本地构建的镜像（目标上没有镜像仓库——请原样接管）、系统路径 / socket（绝不复制）。
- **停机**：卷复制和目标验证期间的一个短暂窗口。提前调低的 DNS TTL 把其中 DNS 的一半压缩到秒级。
