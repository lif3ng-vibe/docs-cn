Openship 构建你的应用前必须**先克隆你的仓库**。公开仓库是免费的——不需要任何凭据。**私有**仓库则需要某个东西证明自己有权读代码。本页按 Openship 的尝试顺序把每种方式讲清楚，并说明如何分别启用。

<Callout title="你大多数时候不必操心">
在 Openship Cloud 上，连接 GitHub App 就够了。在桌面应用上，你本地的 `gh` 登录会自动派上用场。本页针对的是构建报告**无法对克隆做认证**的情况——几乎总是私有仓库部署到你自己的服务器。
</Callout>

## 先搞清楚：克隆在哪里运行？

最要紧的一点：**在你的笔记本上好用的凭据不会自动在远程构建服务器上也好用。** Openship 可以在两个地方克隆：

- **在本主机上**（你的桌面应用，或 Openship 控制面）——然后把构建产物传输到应用运行的地方。
- **在构建服务器自身上**——由服务器直接克隆，无需上传。大仓库的最佳选择，裸机/Direct 部署时的必需项。

存在你机器上的令牌要*运送*到服务器上才能在那里克隆——而 Openship 对运送哪些凭据是刻意谨慎的。这就是为什么"私有克隆怎么做认证"取决于克隆在哪里运行。

## 凭据链（服务器构建）

对于不在本主机上运行的构建，Openship 按顺序尝试，使用**第一个**可用的。各项相互独立——不适用的环节直接跳过，所以顺序只在多项同时可用时才决定谁胜出。

| # | 凭据 | 它是什么 | 会把秘密送到服务器吗？ |
|---|---|---|---|
| 1 | **转发的 git 身份** | 你本地的 `gh` 登录，只为此克隆通过 SSH 隧道递到服务器上 | 否——按需临时发放，从不落盘 |
| 2 | **服务器自带的 git** | 机器上已有的 `gh`/credential-helper/SSH 密钥 | 否——在服务器上本地解析 |
| 3 | **按服务器配置的令牌或 SSH 密钥** | 你为该服务器保存的 GitHub 令牌或部署密钥 | 是——且只发给那一台服务器 |
| 4 | **克隆令牌 / GitHub App** | 项目级或全局克隆令牌，或 App 安装令牌 | 是——短效且限仓库范围 |
| 5 | **公开仓库** | 完全不需要凭据 | 没有可送的 |
| 6 | **在 Openship 克隆再传输** | 在这边克隆，上传源码 | 否——代码从不以令牌形式经过服务器 |

如果这些都不能为私有仓库拿到凭据，构建会以一条可行动的错误消息停止，而不是一直挂起。

<Callout title="顺序为什么这样排" type="info">
按"少运一点秘密材料"排序。转发（1）与服务器自带的 git（2）**什么都不送**——所以优先胜出。存储的令牌或密钥（3–4）确实会上服务器，因此仅在周边凭据都不管用时使用。在这边克隆再传源码（6）是所有凭据都留在本主机的最后手段。
</Callout>

## 各方式如何启用

<Steps>

<Step>
### 转发你的 git 身份（桌面端推荐）

打开 **Settings → Clone credentials → "Forward my git identity to build servers.**"当构建跑在远程服务器上时，Openship 只为这一次克隆把你的本地 `gh` 登录经 SSH 隧道转发过去。服务器上不留任何东西，克隆一完成即时消失。

这是**单个按操作者的开关**，不是每次部署的勾选框——设一次，之后所有服务器克隆都用它。它适用于桌面应用（有你的本地 `gh` 和通往服务器的 SSH 隧道）；在没有本地 git 身份可转发的场景它是空的。
</Step>

<Step>
### 使用服务器自带的 git

如果构建服务器已经登录过 GitHub，Openship 直接用它——在 Openship 里什么都不用配。在服务器上，任选其一：

```bash
gh auth login                       # 机器上的 GitHub CLI
# ——或一个凭据助手——
git config --global credential.helper store
# ——或账户上的 SSH 密钥——
ls ~/.ssh/id_ed25519
```

在依赖它之前，Openship 会先验证服务器真的够得着*你的*仓库，因此以错误账户登录的机器会被跳过，而不是构建到一半才失败。
</Step>

<Step>
### 在服务器上保存一个令牌或 SSH 密钥

在 **Servers** 页面，打开某个服务器的 **GitHub authentication**，添加一个设备流令牌、个人访问令牌，或一把 SSH 部署密钥。这份凭据用于跑在**该**服务器上的克隆。当服务器没有任何周边 git、你又不想从自己机器转发时用它——比如一台无头的 CI 机器。
</Step>

<Step>
### 设置一个克隆令牌（全局或按项目）

**Settings → Tokens → GitHub clone credentials** 存储一个个人访问令牌（经典的 `ghp_…` 或细粒度的 `github_pat_…`），在 GitHub App 未安装时用来克隆私有仓库。开启 **Use as default clone token** 把它加入凭据链。**项目级**覆盖（项目 → 克隆令牌）在该项目上优先于全局的。

经典令牌给它 `repo` 作用域，或者给细粒度令牌对你要部署的那些仓库的读权限。
</Step>

<Step>
### 公开仓库什么都不需要

公开的 GitHub 匿名克隆——没有令牌、没有转发，与任何平台上部署公开仓库完全一样。Openship 会从真正执行构建的机器上实际尝试一次克隆来确认这一点，因此被限速的 API 检查绝不会把公开仓库错判成私有。
</Step>

</Steps>

## 本地构建与服务器构建

- **本地构建**（在本机构建，传输产物）：直接用你本地 `gh` 令牌，它绝不离开这台机器。
- **服务器构建**（在目标机上构建）：宽权限的本地令牌**绝不**会被塞进克隆 URL 再运出本机。这正是转发（1）存在的原因——它经 SSH 隧道按需临时发放身份，而不是把它写到服务器上——也是为什么一个普通的 `gh` 令牌不被接受为可运送的远端凭据。

<Callout title="Openship Cloud">
Cloud 构建在 Cloud 工作区（workspace）内运行，用 **GitHub App** 安装令牌认证。从 **Settings → GitHub** 连接 App 即完成——上面的转发/服务器令牌步骤只针对自托管的服务器部署。
</Callout>
