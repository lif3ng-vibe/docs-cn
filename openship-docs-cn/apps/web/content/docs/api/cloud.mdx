Cloud 端点把一个自托管安装连接到 Openship Cloud，并支持浏览器交接、托管路由与数据传输。自托管的连接路由与 Cloud 的控制面（control-plane）路由共用 `/api/cloud`；进程运行模式决定哪些可用。

没有名为 `cloud` 的原生 SDK 组。要通过 SDK 管理 Cloud 项目，请使用 [remote client](/docs/api/sdk/client)，并传入规范的 Cloud API 与 Cloud 组织 ID。本地所有者的 Cloud 链接无法为固定的 SDK 作用域提供已验证的映射；参见
[Cloud 兼容性](/docs/api/sdk/compatibility#cloud)。

## 自托管端点

仅存在于自托管实例上（不在 `CLOUD_MODE` 中）。Cloud 连接是**组织所有的**：它归属于组织所有者，因此每个成员看到的连接状态一致。断开连接与连接最终确认需要 `owner` 角色，而不只是 `cloud:admin` 授权。


### 检查连接状态

```
GET /api/cloud/status
```

```bash
curl "$OPENSHIP_URL/api/cloud/status" \
  -H "Authorization: Bearer $OPENSHIP_TOKEN"
```

连接本身是一个从控制台发起的浏览器流程（**设置 → Cloud**）：弹窗与 Openship Cloud 完成 PKCE 握手，然后把结果提交给下方的 `connect-finalize`。没有专门的 `openship cloud connect` CLI 动词。

### 完成连接

控制台弹窗从 `localStorage` 读取其 PKCE verifier，并把返回的 code 提交到这里，以保存组织的 cloud bearer。

```
POST /api/cloud/connect-finalize
```

<TypeTable
  type={{
    code: { type: 'string', description: '由 cloud connect 流程返回的一次性交接码。', required: true },
    codeVerifier: { type: 'string', description: '与流程开始时发送的 code_challenge 匹配的 PKCE verifier。' },
  }}
/>

<Callout title="仅限所有者" type="warn">
`connect-finalize` 与 `disconnect` 会接管组织的 cloud bearer，因此在 `cloud:admin` 标签之上还受 `requireRole("owner")` 限制。仅持有 `cloud:admin` 授权的非所有者仍会收到 `403`。
</Callout>

## Cloud 控制面端点

仅在 cloud 模式下存在（`CLOUD_MODE`）——即这些端点运行在 Openship Cloud 上，而不是你的自托管机器上。所有租户级操作都通过**调用方的命名空间令牌**转发给 Oblien；Oblien 原生强制执行命名空间边界，因此没有 SaaS 侧的所有权账本。公开的交接路由通过浏览器重定向到达，并由 URL 中签名、一次性的令牌认证。


<Callout title="这些大多是内部端点">
你的自托管实例会通过其 cloud client 代为调用这些控制面端点——你无需手工接线，也没有与之逐一对应的 `openship` CLI 动词。下文记录请求形状，是为了让集成者能够理解这些流量。
</Callout>

### 交接与代码交换

连接与桌面登录流程绝不会把浏览器 cookie 交给本地实例。取而代之的是：先签发一个短时效、绑定 PKCE 的**交接码**（handoff code）（`connect-authorize`），然后将其兑换为一个专用会话（`exchange-code`）。

```
POST /api/cloud/connect-authorize
```

<TypeTable
  type={{
    redirect: { type: 'string', description: '返回使用的回调 URL。必须是 HTTPS（localhost 除外）。', required: true },
    state: { type: 'string', description: '不透明的 CSRF 值（1–256 个字符），会在回调时原样回传。', required: true },
    codeChallenge: { type: 'string', description: 'PKCE S256 challenge（40–128 个 URL 安全字符），绑定到所签发的交接码。', required: true },
  }}
/>

```
POST /api/cloud/exchange-code
```

<TypeTable
  type={{
    code: { type: 'string', description: '来自 connect/desktop 流程的一次性交接码。', required: true },
    code_verifier: { type: 'string', description: '与 code_challenge 匹配的 PKCE verifier（当交接码绑定 PKCE 时必填）。' },
  }}
/>

公开的 `GET` 交接路由取查询参数，不取请求体——`desktop-handoff` 与 `connect-handoff`
需要 `redirect`、`state` 与 `code_challenge`；`github/install-callback` 需要 `installation_id`、
`setup_action` 与 `state`；`github/oauth-bridge` 需要 `token`。

GitHub 的安装链接首先通过 `flow=select` 与 `state` 打开 Openship 的账号选择页。用户可以重新连接既有安装，或前往 GitHub 创建新的安装。这在自托管与桌面实例所用的外部浏览器中同样有效：
临时的 state 会把选择绑定到发起它的用户和工作区，而不需要 Cloud 浏览器会话。发现与选择会重新检查访问权限，安装领取使用与控制台选择器相同的验证与事务。

### 控制台产品遥测

```
POST /api/cloud/telemetry
```

这个可选的第一方端点只接受白名单中的控制台页面事件与结账导航事件。它独立于上文的客户流量分析中继，也不是 SDK 或 MCP 操作。除非显式配置了生产环境的 Cloud 遥测，否则返回 `404`。

请求必须来自已配置的控制台 Origin，已登录时使用浏览器的 cookie 会话，并且不得携带 bearer 授权。服务器在把事件关联到某个用户或组织之前会先验证当前会话。浏览器事件不得报告支付或其他业务结果；无法识别的属性与超过 4 KiB 的请求体都会被拒绝。

### GitHub App 代理

GitHub App 的私钥由 Cloud 保管；自托管实例永远不持有。本地侧把 `(userId, request)` 交接出去并拿回解析好的数据——它从不签署 JWT，也看不到 App 凭据。

```
POST /api/cloud/github/installation-token
```

<TypeTable
  type={{
    owner: { type: 'string', description: '该 installation 所属的 GitHub 账号/组织。', required: true },
    repos: { type: 'string[]', description: '可选，把令牌限定到这些仓库名。' },
  }}
/>

<Callout title="永远不会从请求体接受 installationId" type="warn">
`installation-token` 从调用方的组织解析出 installation，而不是从客户端提供的 id——传入 id 没有任何效果。这可以防止调用方为它不拥有的 installation 签发令牌。
</Callout>

## 错误

<Callout title="403 — 需要所有者（自托管的连接/断开）" type="error">
`connect-finalize` 与 `disconnect` 需要组织的 `owner` 角色。仅持有 `cloud:admin` 授权的成员会被拒绝。
</Callout>

<Callout title="409 — slug 已被占用（edge 代理 / pages）" type="warn">
请求的 slug 已由共享 cloud 区上的其他租户持有。Oblien 返回 `409`，Openship 原样转发。请改用其他 slug。
</Callout>

<Callout title="412 — 转储格式不匹配（ingest）" type="warn">
`ingest-subgraph` 会拒绝 `formatVersion` 与 SaaS 不一致的转储（`code: INGEST_FORMAT_MISMATCH`）。
请更新你的本地实例并重新导出转储。
</Callout>

<Callout title="413 — 转储过大（ingest）" type="error">
`ingest-subgraph` 在认证运行之前就把请求体限制在 50MB（`code: PAYLOAD_TOO_LARGE`）。
</Callout>

<Callout title="401 — 交接码/会话无效或过期" type="error">
交接码是一次性且有时效的；`exchange-code` 在其被消费或过期后返回 `401`。控制面的 `cloud:*` 端点在 cloud 会话 bearer 缺失或被吊销时返回 `401`——请从控制台重新连接。
</Callout>
