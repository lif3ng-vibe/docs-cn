REST 请求使用你的安装地址加 `/api`。脚本用个人访问令牌（personal access token）认证。
[创建令牌](/docs/api/tokens)，或参见 [CLI 登录指南](/docs/cli/access)。

```bash
curl "$OPENSHIP_URL/api/projects" \
  -H "Authorization: Bearer $OPENSHIP_TOKEN"
```

JSON 请求体使用 `Content-Type: application/json`。部分更新时只发送你要修改的字段。
[资源页](/docs/api)记录了请求字段与等价的 SDK 调用。

## 认证

请求只通过以下四种方式之一自证身份。Openship 先检查 `Bearer` 令牌，然后是会话 cookie，
最后是本地回环兜底（仅当该模式启用时）。

| 方式 | 发送内容 | 使用方 |
|---|---|---|
| **个人访问令牌** | `Authorization: Bearer opsh_pat_…` | CLI、脚本、服务器到服务器 |
| **会话 cookie** | 登录时设置的 httpOnly cookie | 浏览器中的控制台 |
| **MCP OAuth** | 授权同意时绑定的 OAuth 2.1 访问令牌 | 连接 `/api/mcp` 的 AI 智能体 |
| **零认证回环** | 无（来自 `127.0.0.1` 的请求） | 桌面应用/自行开启的单用户实例 |

```bash
curl https://your-host/api/projects \
  -H "Authorization: Bearer $OPENSHIP_TOKEN"
```

<Callout title="Bearer 仅限非浏览器客户端" type="info">
从浏览器可信来源出示的 `Bearer` 令牌会被拒绝（`BEARER_NOT_ALLOWED_FROM_BROWSER`），这样被窃取的
会话令牌就无法绕过 httpOnly cookie 被重放。令牌可以是**限定组织**（org-scoped）的——用
`TOKEN_ORG_SCOPE` 拒绝不匹配的 `X-Organization-Id`；也可以是**只读**（read-only）的——用
`TOKEN_READ_ONLY` 拒绝变更操作。MCP OAuth 发现服务位于源地址根路径：
`/.well-known/oauth-authorization-server` 与 `/.well-known/oauth-protected-resource`。
</Callout>


## 权限

经过认证的应用路由会声明形如 `resource:action` 的权限标签——`project:read`、`domain:write`、
`deployment:admin`——子资源会在中间加一段（`project:service:write`）。共享操作对原生 SDK 调用方
同样执行访问控制。action 通常与 HTTP 方法对应：`read`（GET 单个）、`write`
（POST/PUT/PATCH）、`admin`（DELETE 与破坏性操作）、`list`（GET 集合）。

访问按**组织**逐一判定。Openship 从 `X-Organization-Id` 请求头解析你指的组织（回退到你的
会话默认值），然后检查你在该组织中的角色——`owner`、`admin`、`member` 或
`restricted`（仅可授权）。操作表列出的是路由声明的权限。共享操作还会检查资源所有权、
当前成员资格、令牌限制以及其他管理要求。完整模型参见
[权限与角色](/docs/security/permissions)。


## 速率限制

整个 `/api` 面都受速率限制（rate limit）。未认证的请求落在按 IP 计的默认配额内；已认证的
请求获得更宽裕的按用户配额。部分路由组带有更紧或更松的具名策略。所有限制均按滚动分钟计。

| 策略 | 限制 | 计数依据 | 适用范围 |
|---|---|---|---|
| `default-anon` | 300 / 分钟 | IP | 任何未认证路由 |
| `default-authed` | 3000 / 分钟 | 用户 | 任何已认证路由 |
| `auth-tight` | 10 / 分钟 | IP | `POST /api/auth/*`（登录、注册、重置）与自托管邀请注册 |
| `mcp` | 300 / 分钟 | IP | `/api/mcp`（工具调用突发） |
| `webhook-ingress` | 120 / 分钟 | 源 IP | 入站 Webhook 投递 |
| `billing-portal` | 20 / 分钟 | 组织 | Stripe 门户/结账创建 |

每个响应都携带 `X-RateLimit-Limit`、`X-RateLimit-Remaining` 与 `X-RateLimit-Reset`。`/api/health`
永不限流（负载均衡器与 SSR 会轮询它）。对既没有设置 `TRUST_PROXY` 也没有设置
`OPENSHIP_PUBLIC_URL` 的自托管实例，经回环到达的请求跳过普通限制——但 `auth-tight` 登录闸门
始终生效。

<Callout title="429 — 请求过多" type="warn">
当配额桶用尽时，请求会得到 `429`，响应体为 `{"error":"Too many requests"}` 并附带
`Retry-After` 请求头（秒数）。退避等待窗口重置，而不要立即重试。
</Callout>


## 错误结构

错误以固定的 JSON 结构返回：一条人类可读的 `error` 消息，对于有类型的失败还有机器可读的
`code`。校验失败会附上按字段的 `details` 映射。

```json
{ "error": "This access token is read-only", "code": "TOKEN_READ_ONLY" }
```

| 状态 | 常见 `code` | 含义 |
|---|---|---|
| `400` | `VALIDATION_ERROR` | 请求体未通过 schema 校验——出错字段见 `details`。 |
| `401` | `INVALID_TOKEN`、`BEARER_NOT_ALLOWED_FROM_BROWSER` | 未认证，或令牌无效/过期（完全没有会话时为普通的 `Unauthorized`）。 |
| `403` | `TOKEN_ORG_SCOPE`、`TOKEN_READ_ONLY` | 已认证但无权操作——组织错误、令牌只读，或你的角色/授权拒绝该操作。 |
| `404` | — | 资源不存在，或不属于你的组织（防 IDOR）。 |
| `409` | — | 与当前状态冲突（例如删除正在进行中）。 |
| `429` | — | 触发速率限制（见上文）。 |
| `503` | `AUTH_UNAVAILABLE` | 认证后端不可达——请重试；绝不会被视为"无会话"。 |
| `500` | — | 未处理的服务器错误（`{"error":"Internal server error"}`，无 code）。 |


## 固定组织作用域

同时发送 `X-Organization-Id: org_123` 与 `X-Openship-Scope: fixed` 即可要求使用该确切组织。
认证与授权仍然生效。绑定到其他组织的令牌会被拒绝。
远端 SDK 配置了 `organizationId` 时会发送这些请求头；它会先检查 API 能力支持。
参见[作用域兼容性](/docs/api/sdk/compatibility#固定组织作用域)。

## 流式与重试

标记为流式的端点返回 Server-Sent Events，而非单个 JSON 对象。使用 `curl -N` 或 SSE 客户端，
用完即关闭连接。SDK 的流式方法返回异步迭代器并接受中断信号。
[部署进度](/docs/api/deployments#读取进度事件)展示了两种接口。

连接断开并不能证明变更操作失败了。重试创建、部署或恢复之前，先检查资源或运行状态。
SDK 不会自动重试变更操作。

## 可用性

自托管路由不会挂载到 Cloud API 上。某个具名 SDK 方法仍可能要求已配置的提供方、主机能力或
操作员权限。仅 HTTP 的行没有对应的具名原生操作；在认证允许的情况下，远端客户端可以使用其
[HTTP 传输](/docs/api/sdk/utilities#http-传输)。
