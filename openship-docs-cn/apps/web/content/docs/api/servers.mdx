服务器是 Openship 构建与运行应用的宿主机。注册 SSH 连接信息、
检查必需的组件，并安装目标机器所需的内容。服务器管理需要相应
权限与主机执行策略。这些操作仅限自托管。

## 注册服务器

服务器是你部署到的 SSH 目标。响应永远不包含 SSH 机密——密码与密钥口令
静态加密存储，只在 SSH 客户端内部解密。参见
[自定义服务器指南](/docs/guides/custom-servers)。

## 服务器健康检查与安装

<Tab value="SDK">

```ts
const health = await ship.servers.check("srv_123", { components: ["docker"] });
console.log(health.ready, health.missing);
```

</Tab>
<Tab value="REST API">

```bash
curl -X POST "$OPENSHIP_URL/api/system/check" \
  -H "Authorization: Bearer $OPENSHIP_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"serverId":"srv_123","components":["docker"]}'
```

</Tab>
</Tabs>

先测试连接，再检查已保存服务器装了哪些组件，然后安装或移除组件。
这些路由在**请求体**中用 `serverId`（而非 URL 参数）标识服务器，且每个
handler 都各自执行按服务器的 `server:admin`（或 `server:read`）检查。

`POST /api/system/test-connection` 用请求体里的凭据临时开启一条 SSH 连接并返回
`{ ok, message }`——不持久化任何内容。要求调用者是组织所有者/管理员。

`POST /api/system/remove` 与 `install` 对应，用于移除单个可移除组件。`POST /api/system/install/stream`
接受 `{ serverId, components: string[], config? }` 并返回一份**Server-Sent Events**（服务器推送事件）流
（`progress`、`log`、`complete`、`end`）；若已有会话在运行，则返回 **409 `install_in_progress`**。

<Callout title="是 SSE，不是 JSON" type="info">
`install/stream` 和 `monitor/stream` 是事件流。可以改为读取 `GET /api/system/install/session` 来轮询

</Callout>

磁盘、在线时长与负载均值——对应 `openship server monitor <serverId>`。

## 服务器集群与私有网络

在自托管的 OpenShip 实例上，私有网络通过既有的私有 IPv4 网络或受管的 WireGuard 网格，连接 2–16 台已注册的 Linux
服务器。读取
`ship.servers.networkCapabilities()` 了解可用的服务商配置档与你拥有的
管理权限。本地与桌面版自托管控制器支持
网络清点与手动网络检查。Oblien 托管的 Cloud 不提供
这类基础设施管理。

计算集群是另一种独立记录，把选定的服务器归组到一条既有
私有网络上。联网功能用 `*Network` 方法与 `/api/system/networks`，
这类服务器分组用 `*ComputeCluster` 方法与 `/api/system/compute-clusters`。
较旧的 `*Cluster` 方法与 `/api/system/clusters` URL 保留为私有网络的
兼容别名。

对既有的网络，create 保存配置；verify 启动一个独立的、会持久化的操作。
重试未变更的创建请求时复用同一个 `requestId`。update、
verify 与 remove 需要该网络当前的 `revision`。并发编辑
会返回冲突，而正在进行的验证会阻止配置变更。

```ts
const network = await ship.servers.createNetwork({
  requestId: crypto.randomUUID(),
  name: "Production EU",
  network: {
    mode: "native",
    cidrs: ["10.20.0.0/24"],
    mtu: 1400,
    probePort: 51821,
  },
  members: [
    { serverId: "srv_a", providerId: "hetzner-dedicated", privateIp: "10.20.0.2" },
    { serverId: "srv_b", providerId: "hetzner-dedicated", privateIp: "10.20.0.3" },
  ],
});
const verification = await ship.servers.verifyNetwork({
  networkId: network.id,
  revision: network.revision,
});
console.log(verification.id, verification.status);
```

订阅只读的 SSE 端点 `GET /api/system/networks/stream` 即可跟进
验证进度，重连后依然有效。用
`ship.servers.getNetwork({ networkId })` 读取已保存的快照。报告包含
按方向的 TCP、UDP、MTU、UDP 往返时延、丢包与抖动
结果。受管 WireGuard 的报告还包含按对端（peer）的握手观测。
主机需要 Linux、Python 3、iproute2、持久的
机器标识，以及可用的私有网卡与路由。选定的探测
端口必须在成员之间放行 TCP 与 UDP。检查器
`ship.servers.inspectNetwork(serverId)` 只读取网卡信息，不做配置。

临时授权的监听器绑定到选定的私有地址，
如果清理流程失联则本地过期。运行在四分钟后过期；
成功的观测在十五分钟后视为过期。探测程序
测试其选定的端口与包大小。加密与应用端口访问
不在验证范围内。

验证完成后，还可以用同一端点对一个选定连接做双向
测量：

```ts
const network = await ship.servers.getNetwork({ networkId: "network_id" });
const speedTest = await ship.servers.verifyNetwork({
  networkId: network.id,
  revision: network.revision,
  speedTest: { sourceServerId: "srv_a", targetServerId: "srv_b" },
});
```

测速先检查连通性，然后每个方向最多传输 32 MiB 或持续三
秒。`report.throughput` 记录接收方确认的字节数、
耗时与 Mbps，或一个具体的传输错误。普通验证
不发送大流量。两台服务器都必须属于该私有网络；验证进行中时
不能启动不同的测试。对同一对重复发起活动请求会
复用其运行。进度与最终结果走同一条 SSE 流。

网络读取需要全舰队的服务器读取权限。管理需要
全舰队的服务器管理员权限，且每个成员也须单独授权。移除一条
已被接管的私有网络只移除 OpenShip 的清点记录；服务器与
外部管理的网络保留。受管网络使用下文的受审核清理
流程。移除服务器之前必须先处理好成员关系与活动操作。私有网络负责连接主机；而一个具备就绪运行时的
[计算集群](#计算集群)可以运行[应用副本与数据库](/docs/api/projects#在集群上扩缩容无状态应用)。
[共享存储](#跨服务器共享文件)需单独启用。服务商
API/VLAN 置备仍在受管网络搭建的范围之外。

### 受管的私有网络

受管组网会创建一个加密的 WireGuard 网格，并自动
分配私有地址。启动服务器准备流程来检查基础设施、
安装缺失工具，并生成一份可审核的计划：

```ts
const preparation = await ship.servers.prepareManagedNetwork({
  requestId: crypto.randomUUID(),
  name: "Production mesh",
  members: [
    { serverId: "srv_a", providerId: "hetzner-dedicated" },
    { serverId: "srv_b", providerId: "custom" },
  ],
});
console.log(preparation.id, preparation.status, preparation.hosts);

for await (const event of ship.servers.managedNetworkPreparationEvents(preparation.id)) {
  if (event.event === "snapshot") {
    const { run } = JSON.parse(event.data);
    console.log(run.sequence, run.status, run.hosts);
  }
}
```

该订阅在连接时以及每次进度变化时发送一份完整的已保存 `snapshot`，
在尝试收尾后关闭前再发送 `complete`。控制台在连接断开后以退避方式重连。
SDK 调用者可用同一方法重新挂回；重连绝不重新开始工作。请用每份快照整体替换本地状态，
而不是往日志上追加。单调递增的 `sequence` 也能防止过晚的响应造成错乱。

`ship.servers.getManagedNetworkPreparation({ preparationId })` 仍可用于
单次读取已保存状态。当其状态为 `ready` 时，用它的 `operationId`
读取网络计划。要重试失败或中断的准备流程，用与上次相同的输入和请求 ID 调用
`prepareManagedNetwork`。已经健康的工具会被检查后复用。`listManagedNetworkPreparations()` 列出最近仍需处理或审核的工作。
准备阶段不会启动任何隧道变更。

要丢弃一个已停止的准备流程，用其最新的
进度序列调用 `discardManagedNetworkPreparation({ preparationId, sequence })`。尚未应用的计划可用
`discardManagedNetworkPlan({ operationId, planHash })` 丢弃。两者都要求舰队
管理权限。准备流程与任何未应用的计划在同一个事务中关闭，
并从待处理搭建中消失；既有的服务器、服务与已安装工具
保留。已取消的记录仍可读取用于诊断，并阻止过晚的重试复活已被丢弃的工作。活动中的准备流程必须先完成。

要从尚未完成的**初始集群搭建**中移除一台服务器，调用
`removeManagedNetworkPreparationMember({ preparationId, serverId, sequence, requestId })`。
对初始网络操作，用
`removeManagedNetworkOperationMember({ operationId, serverId, sequence, planHash, requestId })`。
至少要保留两台服务器。`requestId` 用新的 UUID，响应丢失时复用它。
不同的选择需要不同的请求。
两个方法都要求舰队管理权限并返回 `{ preparation, operation }`。
原始记录通过 `replacementPreparationId` 链接到替代记录；
设置与诊断仍然可用，且原始请求不能再恢复。

在网络应用（apply）之前，移除操作会取消旧的选择，并把余下
服务器保存到一个暂停（`pending`）状态的准备流程中。部分应用之后，它还会有一个
`cleanupOperationId`。OpenShip 复用回滚，在**所有原始主机**上恢复这次尝试的网络
变更，包括被移除服务器的 peer 条目。
该服务器、其工作负载、磁盘、其他网络与共享安装的工具保留。
清理运行期间待处理准备流保持打开；订阅该清理操作可查看按主机的进度。
失联或被外部改动过的主机会让清理与预留一直挂着。解决问题后用
`action: "rollback"` 重试该操作。一旦所有主机确认回滚，准备流程保持暂停。随后显式用替代记录保存的输入调用 `prepareManagedNetwork`
以重试；在清理完成前它会拒绝请求。移除、清理重试与流重连都不会启动准备流程。
由此产生的网络计划始终需要重新审核并应用。已建成的集群沿用其既有的、经审核的成员变更工作流。

对已满足前置条件的主机，`planManagedNetwork` 接受
同样的输入并执行只读检查，不安装任何软件包。

审核之后，把该 operation ID 与哈希传给
`ship.servers.applyManagedNetwork({ operationId, planHash, action: "apply" })`。
计划在十五分钟后过期，并拒绝任何对集群 revision、
主机标识或已检查网络信息的改动。订阅
`ship.servers.managedNetworkOperationEvents(operationId)` 可获得持久化的进度；
`getManagedNetworkOperation({ operationId })` 提供单次状态读取。
同一 operation 在中断之后还支持 `action: "resume"` 或 `action: "rollback"`。活动中的工作是幂等的，不能被启动两次。
一旦网络变更已经开始，discard 即被阻止。用 `action: "rollback"`
清理未完成的新集群，或恢复既有集群的上一个网络。每台主机都必须确认清理后，
清点信息与预留才会释放。失联的主机会让恢复一直挂着；待访问恢复后再重试回滚。恢复后的既有集群随后可以走受审核的移除流程。

`ship.servers.clusterEvents()` 流式推送包含 `clusters` 与
`preparations` 的总览快照。三个订阅方法都接受 `{ signal }`，可在不取消搭建的情况下断开某个查看端。这些流使用已保存的数据库状态，在订阅时再次校验舰队
读取权限，并每十五秒做一次对账，以发现另一个控制器的更新与过期的 worker 租约。

主机要求带 WireGuard 内核支持的 Linux、Python 3.8+、iproute2、systemd、
以及 root 或免密 sudo。准备流程会通过共享工具链自动安装缺失的
Python 3.8+、iproute2（4.15+）与 WireGuard 工具（1.0+）。
它在检查之前先验证安装。内核、init 系统与权限
问题会在某个具名步骤停下；OpenShip 不会更换内核或重启主机。
若后续的网络操作回滚，已安装的工具仍保持安装。支持的
防火墙是：无任何主机防火墙、原生 iptables，或使用标准
`inet filter input/output` 链且没有额外过滤型 IPv4 input/output
基础链的 nftables。UFW、firewalld 与不受支持的 nftables 布局会在检查时失败。
服务商防火墙必须放行经审核的传输端口（默认 51820/UDP）。
传输使用可达的 IPv4 端点，没有中继或自动 NAT 穿透。
提供了显式 IPv4 传输端点时，IPv6 SSH 管理亦可工作。
准备阶段检查本地前置条件与路由；它不证明主机之间的 UDP 可达性。应用（Apply）之后，`transport` 步骤会暂存 WireGuard 端点与
自有的主机防火墙规则。`handshake` 步骤在 `configure` 分配私有地址与路由之前测试每个对端。失败会保留按对端的端点与端口，
并恢复先前的配置。服务商防火墙或 NAT 的变更需要管理员先介入，再做一次显式重试。

私钥留在各自的主机上。每台主机会有一个持续二十分钟的
回滚计时器，因此即使控制器断连或主机重启，未完成的搭建也能恢复。OpenShip 只改动自己的网卡、peer 路由与
防火墙规则。传输阶段沿用同样的回执与回滚计时器；
成功晋升后，已验证的网卡与密钥得以保留。握手与
每一次定向的 TCP/UDP/MTU 检查都必须成功才能提交。已提交的组网可在无控制器的情况下本地重启。失联
或被外部改动过的主机保留其认领，直到恢复得到确认。

对受管集群做编辑时，在新的计划中包含 `clusterId` 与 `revision`。成员关系、
传输端点/端口、MTU 与 `rotateKeys` 可以变更；既有地址与
已分配子网保持稳定。要移除受管集群，用 `intent: "remove"` 制定计划，
并在应用前审核其主机清理。这些网络
操作不会排空工作负载或迁移其数据。

## 计算集群

通过选择已接入私有网络的服务器来创建计算集群。
网络与计算集群的成员关系相互独立。重试未变更的创建请求时复用同一个
`requestId`；更新与移除需要计算集群当前的
`revision`。

```ts
const cluster = await ship.servers.createComputeCluster({
  requestId: crypto.randomUUID(),
  name: "Production EU",
  networkId: "network_id",
  serverIds: ["srv_a", "srv_b"],
});
console.log(cluster.id, cluster.networkId, cluster.serverIds);
```

`removeComputeCluster({ clusterId, revision })` 移除这一分组并保留
其服务器与私有网络。`ship.servers.infrastructure(serverId)` 会报告
与某台服务器关联的网络和计算集群。

### 受管的 K3s 搭建

创建资源池并不会安装软件。在把选定服务器接入其私有网络之后，启动其独立的运行时操作：

```ts
const runtime = await ship.servers.setupClusterRuntime({
  clusterId: "cluster_id",
  revision: 1,
  requestId: crypto.randomUUID(),
});
console.log(runtime.status);

const abort = new AbortController();
for await (const event of ship.servers.clusterRuntimeEvents("cluster_id", { signal: abort.signal })) {
  console.log(event.data);
  abort.abort(); // Close the subscription when leaving the setup view.
  break;
}
```

搭建会安装缺失的工具、固定 K3s 版本并校验 checksum、配置私有
主机防火墙规则、把服务器加入集群，并检查真实的 Pod 流量、Services
与 DNS。一/两成员的池使用一台控制服务器；更大的池使用
三台控制服务器与更多 worker。初始支持要求 Linux
amd64/arm64、systemd、root 或免密 sudo、已禁用 swap，以及未过滤或原生 iptables 主机防火墙。服务商私有网络 ACL 仍是运维者的
责任；控制台会列出确切的私有 peer 端口。这些端口
不应暴露到公网。

用 `getClusterRuntime({ clusterId })` 读取已保存的进度；搭建开始前它返回 `null`。
用 `retryClusterRuntime({ clusterId, sequence })` 显式重试被中断或失败的操作。
重试会保留已固定的版本/配置，并对主机状态做对账。重连 SSE 绝不会
启动或重试安装。运行时流保持打开以便观察后续变化；
离开页面时取消它们。快照包含带时间戳的验证结果，
不是持续的工作负载监控。

`removeClusterRuntime({ clusterId, sequence })` 启动有归属的清理。应用
工作负载、持久卷与额外的运维组件必须先移除。
清理会保留私有网络与既有的 Docker 应用，并可在部分移除后恢复。运行时仍在安装或未完成时，
移除该池或变更其成员/网络会被阻止。

搭建就绪后，在项目的拓扑中选择该集群即可让应用跨其服务器运行，或添加受管的 PostgreSQL 与 Redis 数据库。
既有项目部署只有在你选定新目标并部署时才会迁移。

### 跨服务器共享文件

用集群上的**共享存储**（Share storage）在至少两台
服务器上准备独立副本。搭建会安装所需的工具、检查选定的空目录、
配置共享存储并验证一次跨服务器写/读。它绝不会格式化磁盘。其技术实现展示在折叠的详情中。

`setupClusterStorage` 接受经审核的磁盘、副本数与一个稳定请求 ID。
读取 `getClusterStorage` 或订阅 `clusterStorageEvents`，直到搭建就绪。
中断之后，检查已保存的错误，并用最新 sequence 显式重试。
读取状态以了解当前容量与磁盘健康状况时用 `observe: true`。

选择一个外部备份目标即可启用可恢复的文件存档。项目
随后就能创建、挂载、扩容、备份并恢复自己的共享卷。
多副本让文件在集群内保持可用；外部备份则在删除或数据损坏后提供恢复点。

移除共享存储之前，先断开并移除项目卷。空存储清理
会保留外部存档与集群的其他存储类别。移除集群运行时之前先移除共享存储。
