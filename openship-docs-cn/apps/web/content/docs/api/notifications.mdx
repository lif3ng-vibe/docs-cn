通知 API 决定由谁、以何种方式收到诸如部署失败、SSL 证书即将过期等事件的消息。你可以注册**渠道**（告警发往何处——邮件、Webhook（网络回调）、Slack、Discord、Microsoft Teams 或应用内铃铛）、开关**订阅**（哪些事件类别送达哪个渠道）、为组织新成员设置全局**默认项**，以及读取**投递记录**（铃铛图标背后的告警信息流）。在控制台中对应 **Settings → Notifications** 页面。渠道、订阅与投递记录按用户维度隔离；默认项按组织维度隔离。

<Callout title="每个实例均可用" type="info">
  该模块在自托管与云端实例上均内置提供。没有专门的 `openship` CLI 命令——请通过控制台或直接调用这些端点来管理通知。
</Callout>

## 事件类别

事件类别是稳定的、面向用户的事件分组（例如 `deploy.failed`、`backup.failed`、`domain.expiring`），订阅和默认项都以它为键。类别定义在代码里而非数据库中，因此 `GET
/api/notifications/categories` 是一个静态注册表——每一项包含 `id`、`group`、`label`、
`description` 和 `defaultEnabled`。

响应还带一个 `groups` 数组（`{ id, label }`，已按展示顺序排列），各类别的 `group` 字段指向其中的条目——`deployment`、`app_health`、`backups`、`jobs`、`domains`、`members`、`billing`。`billing` 组及其类别仅在 Openship Cloud 之外才会被省略（因为自托管实例上没有可触发它们的事件）。

<Tabs items={['SDK', 'REST API']} groupId="api-transport" persist>
<Tab value="SDK">

```ts
const result = await ship.notifications.categories();
console.log(result);
```

</Tab>
<Tab value="REST API">

```bash
curl "$OPENSHIP_URL/api/notifications/categories" \
  -H "Authorization: Bearer $OPENSHIP_TOKEN"
```

</Tab>
</Tabs>

## 创建渠道

渠道是一个投递目的地。`config` 对象会按 `kind` 做形状校验；其中的机密信息（Webhook 签名密钥、Slack URL、Telegram 机器人令牌）会加密存储，且永远不会完整返回。

<Tabs items={['SDK', 'REST API']} groupId="api-transport" persist>
<Tab value="SDK">

```ts
const result = await ship.notifications.createChannel({
  kind: "email",
  label: "On-call inbox",
  config: {
    address: "ops@example.com",
  },
});
console.log(result);
```

</Tab>
<Tab value="REST API">

```bash
curl -X POST "$OPENSHIP_URL/api/notifications/channels" \
  -H "Authorization: Bearer $OPENSHIP_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"kind":"email","label":"On-call inbox","config":{"address":"ops@example.com"}}'
```

</Tab>
</Tabs>

<Callout title="获取 Teams Webhook URL" type="info">
  在 Teams 中创建一个**工作流（Workflow）**，触发器选用 **“When a Teams webhook request is received”**，并使用其生成的 URL。旧版 `webhook.office.com` 连接器 URL 也接受。URL 会加密存储，在响应中以 `webhookUrlConfigured` 的形式出现，永远不会完整返回。
</Callout>

<Callout title="获取 Telegram 机器人令牌与 chat id" type="info">
  给 **@BotFather** 发消息 → `/newbot` 获取令牌。机器人只能向已主动开启过它的聊天写消息，所以请先给机器人发一条消息（或把它加进你的群组）。要获取 chat id，调用
  `https://api.telegram.org/bot<token>/getUpdates` 并读取 `result[].message.chat.id`——群组 id 为负数。编辑 Telegram 渠道但不重新提交 `botToken` 时，会继续沿用已存储的令牌。
</Callout>

新渠道默认 `enabled: true`。`in_app` 渠道立即就是 `verified` 状态；其他类型初始均未验证，必须先（通过一次测试发送）完成验证才能投递——用 `PATCH` 翻转 `verified`。

## 更新渠道

只发送你想修改的字段。对非 `in_app` 渠道修改 `config` 会把 `verified` 重置为 `false`，因为投递目的地可能已经变了。

```
PATCH /api/notifications/channels/:id
```

## 为渠道订阅事件类别

订阅是（用户、组织、类别、渠道）四元网格中的一个开关。`PUT` 是幂等的 upsert——再次发送同样的三元组即可翻转 `enabled`。`channelId` 必须是你拥有的渠道。

<Tabs items={['SDK', 'REST API']} groupId="api-transport" persist>
<Tab value="SDK">

```ts
const result = await ship.notifications.upsertSubscription({
  category: "deploy.failed",
  channelId: "chan_123",
  enabled: true,
});
console.log(result);
```

</Tab>
<Tab value="REST API">

```bash
curl -X PUT "$OPENSHIP_URL/api/notifications/subscriptions" \
  -H "Authorization: Bearer $OPENSHIP_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"category":"deploy.failed","channelId":"chan_123","enabled":true}'
```

</Tab>
</Tabs>

## 组织默认项

默认项为组织新成员预填订阅网格。设置默认项仅管理员可用（`notifications:admin`）；读取则不受限。

```
PUT /api/notifications/defaults
```

## 读取告警信息流

`GET /api/notifications/deliveries` 返回你在当前组织的近期投递记录——即铃铛图标背后的历史。`GET /api/notifications/deliveries/unseen-count` 驱动未读角标，`POST
/api/notifications/deliveries/:id/seen` 清除一条。

<Tabs items={['SDK', 'REST API']} groupId="api-transport" persist>
<Tab value="SDK">

```ts
const result = await ship.notifications.listDeliveries({
  unseen: true,
  limit: 20,
});
console.log(result);
```

</Tab>
<Tab value="REST API">

```bash
curl "$OPENSHIP_URL/api/notifications/deliveries?unseen=true&limit=20" \
  -H "Authorization: Bearer $OPENSHIP_TOKEN"
```

</Tab>
</Tabs>

## 错误

<Callout title="400 —— 渠道无效或字段缺失" type="warn">
  `kind` 不属于 `email`/`webhook`/`in_app`/`slack`/`discord`/`msteams`/`telegram`、`label`
  缺失，或 `config` 未通过对应 kind 的校验（邮箱格式错误、Webhook URL 不是
  `http(s)`、Slack URL 不是 `https://hooks.slack.com/...`、Discord URL 不是
  `https://discord.com/api/webhooks/...`、Teams URL 不是 https Workflow 或
  `webhook.office.com` 地址、Telegram 令牌/chat id 不符合 `<id>:<secret>` 或数字/`@name` 格式）。订阅需要 `category`、`channelId` 和布尔值 `enabled`；默认项需要 `category` 和布尔值 `defaultEnabled`。
</Callout>

<Callout title="按用户维度的路由返回 404" type="error">
  该渠道、订阅或投递的 `:id` 不属于你（或已被删除）。用对应的 `GET` 路由列出你自己的记录以获得有效 id。
</Callout>
