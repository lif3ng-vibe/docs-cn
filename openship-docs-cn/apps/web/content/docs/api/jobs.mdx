---
title: 任务
description: 创建命令任务、运行它们，并查看计划与结果。
---

任务（job）在一台或多台已授权服务器上运行命令。任务可以手动运行、按 cron 计划运行、在指定时间
运行一次，或响应已配置的事件。这一面（surface）要求自托管安装。

任务方法使用任务的 **`key`**。运行方法使用**运行 ID**（run ID）。写入命令任务还需要对每台目标
服务器的管理访问权限。

## 创建命令任务

<Tabs items={['SDK', 'REST API']} groupId="api-transport" persist>
<Tab value="SDK">

```ts
const job = await ship.jobs.create({
  label: "Check Node version",
  serverId: "srv_123",
  command: "node --version",
  scheduleType: "manual",
  timeoutMs: 10_000,
});
console.log(job.key);
```

</Tab>
<Tab value="REST API">

```bash
curl -X POST "$OPENSHIP_URL/api/jobs" \
  -H "Authorization: Bearer $OPENSHIP_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"label":"Check Node version","serverId":"srv_123","command":"node --version","scheduleType":"manual","timeoutMs":10000}'
```

</Tab>
</Tabs>

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| `label` | `string` | 必填；1–120 个字符。 |
| `command` | `string` | 必填；要执行的命令，最多 10,000 个字符。 |
| `serverId` / `serverIds` | `string` / `string[]` | 目标服务器，或多至 50 台服务器。 |
| `scheduleType` | `manual`、`recurring` 或 `once` | 选择任务的调度方式。 |
| `cronExpression` | `string` | 循环任务的 cron 表达式。 |
| `runAt` | `string` | 一次性任务用的带时区 ISO 时间戳。 |
| `timeoutMs` | `number` | 执行超时，1,000–86,400,000 ms。 |
| `retry` | `object` | `maxAttempts`（1–10）与 `backoffSeconds`（0–3,600）。 |
| `env` / `secrets` | `Record<string, string>` | 环境值；密钥会加密并在读取时打码。 |
| `dependsOn` | `string[]` | 最多 50 个前置任务 key。 |
| `triggerEvents` | `string[]` | 最多 50 个来自 `triggerEvents()` 的事件 ID。 |
| `notifyConfig` | `object` | 渠道 ID 与状态：`running`、`success` 或 `failed`。 |

`update(key, input)` 接受部分配置加 `enabled`。系统任务只接受 `cronExpression` 与 `enabled`，
且无法移除。密钥更新会整体替换所提供的密钥映射。

## 运行与查看

<Tabs items={['SDK', 'REST API']} groupId="api-transport" persist>
<Tab value="SDK">

```ts
const submitted = await ship.jobs.run("job_key");
console.log(submitted.runId, submitted.summary);
```

</Tab>
<Tab value="REST API">

```bash
curl -X POST "$OPENSHIP_URL/api/jobs/job_key/run" \
  -H "Authorization: Bearer $OPENSHIP_TOKEN"
```

</Tab>
</Tabs>

提交可能返回 `runId` 或直接的摘要。用 `getRun(runId)` 查看执行状态、尝试次数、输出、错误与
耗时。`listRuns(key, { limit })` 返回历史记录；`limit` 范围为 1–1,000。

<Tabs items={['SDK', 'REST API']} groupId="api-transport" persist>
<Tab value="SDK">

```ts
for await (const event of ship.jobs.streamRun("run_123")) {
  console.log(event);
}
```

</Tab>
<Tab value="REST API">

```bash
curl -N "$OPENSHIP_URL/api/jobs/runs/run_123/stream" \
  -H "Authorization: Bearer $OPENSHIP_TOKEN"
```

</Tab>
</Tabs>

## 原生调度

自有原生安装默认不会启动调度。仅当它应当承担那份工作时，才在其启动配置中设置
`jobs: { enabled: true }`。手动运行一个任务与启用循环调度是两个独立的动作。
参见[后台工作限制](/docs/api/sdk/compatibility#当前限制)。

## 操作

{/* api-operations:start */}

| 操作 | SDK | REST API |
| --- | --- | --- |
| 流式读取一次任务运行的实时输出。 | `jobs.streamRun(id, options?)` | `GET /api/jobs/runs/:runId/stream`<br />`job:read` · 自托管 |
| 列出可用的系统任务与自定义任务。 | `jobs.list()` | `GET /api/jobs`<br />`job:read` · 自托管 |
| 创建带调度与目标配置的自定义命令任务。 | `jobs.create(input)` | `POST /api/jobs`<br />`job:write` · 自托管 |
| 列出可触发自定义任务的事件。 | `jobs.triggerEvents()` | `GET /api/jobs/trigger-events`<br />`job:read` · 自托管 |
| 连同任务一起读取已计划的备份保留策略。 | `jobs.backupSchedules()` | `GET /api/jobs/backup-schedules`<br />`job:read` · 自托管 |
| 读取任务的配置与近期运行。 | `jobs.get(id)` | `GET /api/jobs/:key`<br />`job:read` · 自托管 |
| 修改计划或自定义任务配置。 | `jobs.update(id, input)` | `PATCH /api/jobs/:key`<br />`job:write` · 自托管 |
| 删除一个自定义任务；系统任务可以改为禁用。 | `jobs.remove(id)` | `DELETE /api/jobs/:key`<br />`job:write` · 自托管 |
| 立即触发一个任务。 | `jobs.run(id)` | `POST /api/jobs/:key/run`<br />`job:write` · 自托管 |
| 读取一个任务的运行历史。 | `jobs.listRuns(id, input?)` | `GET /api/jobs/:key/runs`<br />`job:read` · 自托管 |
| 读取一次已记录的运行、结果与捕获的输出。 | `jobs.getRun(id)` | `GET /api/jobs/runs/:runId`<br />`job:read` · 自托管 |

{/* api-operations:end */}
