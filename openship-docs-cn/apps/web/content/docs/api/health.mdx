Health API 是 Openship 外部的任何程序确认实例存活并了解其部署方式的方式——版本、认证模式、
面向哪个云端（如果有的话）。负载均衡器与 Docker 健康检查请求 `GET /api/health`；
CLI 与控制台读取 `GET /api/health/env` 来决定显示哪种登录流程。在终端里它对应
[`openship status`](/docs/cli/run) 命令。两条路由在每个实例上都可用（自托管、桌面版与云）。

## 存活探针

```
GET /api/health
```

只要进程还在响应请求，就返回 `200` 和固定的响应体。把它用作容器或负载均衡器的健康检查——
它不触碰数据库，也永远不需要认证。

```bash
curl "$OPENSHIP_URL/api/health"
# → {"status":"ok","timestamp":"2026-07-19T04:29:00.000Z"}
```

## 部署信息

对实例配置方式的静态、利于缓存的描述。客户端读取它来选择正确的登录流程并访问正确的云端端点——
控制台使用这些值而不是写死的对照表。依赖数据库的读取项（`teamMode`、迁移相关字段）会在设置表
在迁移途中不可用时回退到安全默认值，因此该路由始终保持可用。

## 错误

<Callout title="连接被拒绝/超时" type="warn">
这些路由永远不会返回认证或权限错误——失败意味着进程不可达（主机/端口错误、容器仍在启动，
或实例已宕机）。`openship status` 会把它报告为 `Cannot reach the API at <url>`。
确认实例正在运行且 URL 正确，然后重试。
</Callout>
