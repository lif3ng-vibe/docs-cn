## 包的可用性

Ship SDK 随 **`openship` 0.8.0 及更高版本**发布。使用 `npm install openship` 安装；
旧的仅 CLI 依赖使用 `npm install openship@latest` 升级。要求 Node.js 22 或更高版本。
公开导入路径与本地构建参见[安装](/docs/api/sdk/installation)。

## 固定组织作用域

带 `organizationId` 的远程客户端在发送限定作用域的应用请求之前，会通过
`/api/health` 检查这项能力：

```json
{ "sdk": { "protocol": 1, "fixedOrganizationScope": true } }
```

客户端发送 `X-Organization-Id` 和 `X-Openship-Scope: fixed`。API 会对调用者进行认证，
检查当前的成员身份和授权，并把访问限制在该组织内。请求头不能覆盖客户端已配置的
作用域。

不兼容的服务器会导致 `SDK_SCOPE_UNSUPPORTED`。请升级服务器。移除 `organizationId`
会改变作用域保证。格式错误的作用域头，或 `fixed` 却缺少组织，会以
`400 VALIDATION_ERROR` 拒绝。

## Cloud

使用规范的 Cloud API、Cloud 凭据及其组织 ID。已部署的 API 必须通过同样的能力检查；
代码检出中的 SDK 支持并不代表已部署的服务器也支持。

自托管所有者的 Cloud 账户关联目前不提供经过验证的租户映射。固定作用域会以
`CLOUD_SCOPE_UNAVAILABLE` 拒绝这种转发。Cloud 操作还需要相应的提供方和账户能力；
主机管理仍然仅限于自托管的安装。

## 当前限制

| 领域 | 状态 |
| --- | --- |
| 命名操作 | [参考文档](/docs/api)覆盖了当前全部的原生和远程操作组。提供方与权限检查仍然适用。 |
| 集群与扩缩容 | 命名操作覆盖私有网络、计算集群搭建、应用副本、PostgreSQL/Redis 数据库、共享文件及其备份/恢复流程。基础设施管理仅限自托管；需要就绪的运行时以及相应的存储/备份配置。参见[服务器](/docs/api/servers#计算集群)与[项目](/docs/api/projects#在集群上扩缩容无状态应用)。 |
| 邮件与数据传输 | 已有 HTTP 端点；完整的命名原生 SDK 操作组尚不可用。 |
| 系统与账户生命周期 | 其余的安装设置、自身应用、边缘/终端以及账户生命周期覆盖尚不完整。请使用已有文档记载的功能面。 |
| 原生 CLI | 资源命令支持原生模式；部分命令和系统操作仍需 HTTP。参见[原生 CLI 支持](/docs/cli/native#支持的命令)。 |
| 后台工作 | 原生调度默认禁用。面向全部任务/备份/扫描的受限保存主体以及分布式调度器归属仍不完整。 |
| 分发与重放 | 持久化的多 worker 分发、幂等重放以及跨重启的事件重放仍不完整。 |
| 计费 | 账户/支付功能需要配置好的托管计费。完整的 Webhook 重放与记账事务保证仍在迁移中。 |
| Cloud 迁移 | 对于固定 SDK 作用域，经过验证的租户映射、提升与对账仍不完整。 |

浏览器登录重定向、会话 Cookie、Webhook 签名和终端握手仍然是各自的传输协议。原生
导入不会取代这些协议。

## 已验证的内容

公开 tarball 在 Node 22 和 24 上有已安装包的检查，包括原生部署、持久化、资源拆除、
ESM/CommonJS、类型声明和 CLI 调用。参见[可运行的示例](/docs/api/sdk/examples)。真实
提供方的验证仍是单独的发布关卡。
