这个包包含一个可执行的示例，它使用公开导入、真实存储和共享的部署管线。

## 运行原生生命周期

在 Node 项目中[安装 `openship`](/docs/api/sdk/installation)之后：

```bash
node node_modules/openship/examples/native-lifecycle.mjs
```

把该文件复制到你的项目中加以改造。这个示例会：

1. 开通两个用户并选择其组织作用域。
2. 部署生成的 HTML 并等待发布就绪。
3. 更新配置并向同一个项目部署新文件。
4. 检查部署历史、租户隔离和会话吊销。
5. 关闭并重新打开持久化存储，然后检查已保存的配置和掩码后的密钥。
6. 删除项目、排空安装并清除其临时状态。

如果某个步骤的行为不符合预期，断言会使进程失败。这个示例会创建自己的临时目录，
不需要 API 凭据、Docker 守护进程或外部数据库。

## 它验证了什么

针对已安装包的检查会在仓库之外、Node 22 和 24 上运行这个文件，并依据公开的类型
声明进行类型检查。相关的包探测还会检查发布文件内容、重新打开、物理清理、
ESM/CommonJS 导入以及安装好的 CLI。

该示例使用 bare 运行时并设置 `routing: "none"`，因此不对外提供公开 URL。真实的
Cloud、Docker、SSH 和公开路由属于单独的集成检查。
