安装设置控制一个自托管的 Openship 实例。下文的资源操作在可用时使用共享的
SDK/HTTP 接口；初始引导、恢复与其余搭建端点仅限 HTTP。

宿主机与组件安装参见[Servers](/docs/api/servers)，既有站点参见[边缘管理](/docs/api/edge)，导入、导出与团队模式迁移参见[数据传输](/docs/api/data-transfer)。

## 初始引导与搭建

`GET /api/system/onboarding` 返回 `{ configured: boolean }`——一旦存在至少一台服务器即为 `true`。
`POST` 变体执行与内部 `/setup` 推送相同的逻辑，但仅在实例尚未配置时有效
（之后返回 **403 “Instance already configured”**），因此首启流程不需要令牌。

```
POST /api/system/onboarding
```

## 实例设置

`GET /api/system/settings` 返回实例配置（认证模式、隧道提供方、默认构建模式与
回滚窗口、邀请邮件发件源、团队模式、迁移目标）。`PATCH` 只更新你发送的
字段。`DELETE` 会清空实例设置**以及**每一条服务器记录。

<Tabs items={['SDK', 'REST API']} groupId="api-transport" persist>
<Tab value="SDK">

```ts
const result = await ship.system.updateSettings({
  defaultBuildMode: "docker",
});
console.log(result);
```

</Tab>
<Tab value="REST API">

```bash
curl -X PATCH "$OPENSHIP_URL/api/system/settings" \
  -H "Authorization: Bearer $OPENSHIP_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"defaultBuildMode":"docker"}'
```

</Tab>
</Tabs>

<Callout title="零认证有双重门控" type="warn">
在非桌面部署上设置 `authMode: "none"` 意味着任何能访问 API 的人都能以管理员身份行事。运维者必须**同时**先用 `OPENSHIP_ALLOW_ZERO_AUTH=true` 启动该流程（否则 **403**），并在请求体里发送 `confirm: "I-understand-no-auth"`（否则 **400**）。
</Callout>

## 把零认证升级为真正的登录

`POST /api/system/upgrade-to-auth` 把合成的零认证用户转换为一个邮箱/密码账号，并把
`authMode` 从 `none` 翻转为 `local`，同时保留同一用户 id，使既有的项目、部署与审计记录仍可解析。只在 `authMode === "none"` 时可调用（否则 **400**）。

```
POST /api/system/upgrade-to-auth
```

## 浏览主机文件系统

`GET /api/system/browse?path=<dir>` 列出一个路径下的子目录（默认为宿主的
home 目录），并标出哪些看起来是可部署的项目。被“部署本地文件夹”选择器使用。

返回 `{ path, directories: [{ name, path, isProject }] }`——项目在前，之后按字母排序。非目录
路径返回 **400**，路径不存在返回 **404**。

### 资源方法

| 操作 | SDK | REST API |
| --- | --- | --- |
| 浏览一个已授权的主机文件系统位置。 | `system.browse(input?)` | `GET /api/system/browse`<br />`settings:read` · 自托管 |
| 读取数据库与安装健康状况。 | `system.health()` | `GET /api/system/diagnostics`<br />`settings:read` · 自托管 |
| 读取实例设置。 | `system.getSettings()` | `GET /api/system/settings`<br />`settings:read` · 自托管 |
| 修改实例设置。 | `system.updateSettings(input)` | `PATCH /api/system/settings`<br />`settings:write` · 自托管 |
| 读取 SMTP 设置，机密打码。 | `system.getEmailSettings()` | `GET /api/system/settings/email`<br />`settings:read` · 自托管 |
| 为该安装配置 SMTP 投递。 | `system.updateEmailSettings(input)` | `PUT /api/system/settings/email`<br />`settings:write` · 自托管 |
| 用已配置的 SMTP 设置发送测试邮件。 | `system.sendTestEmail(input)` | `POST /api/system/settings/email/test`<br />`settings:write` · 自托管 |
| 重置受支持的实例设置。 | `system.resetSettings()` | `DELETE /api/system/settings`<br />`settings:admin` · 自托管 |
