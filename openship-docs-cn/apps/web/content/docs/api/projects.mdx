一个项目将源代码、构建配置、环境变量、域名与部署历史组合在一起。先创建项目记录，再[提交部署](/docs/api/deployments)。

本地文件系统与边缘管理操作需要自托管能力。使用 Cloud 时，请直接连接 Cloud API。[固定作用域不会经由所有者的 Cloud 链路转发](/docs/api/sdk/compatibility#cloud)。

## 创建项目

从 Git 仓库或本地路径创建项目，把构建配置固化进项目记录。上传文件夹请改用[源文件上传流程](/docs/api/sources)。只有 `name` 是必填的——其余字段都会自动探测或取默认值。

<Tabs items={['SDK', 'REST API']} groupId="api-transport" persist>
<Tab value="SDK">

```ts
const result = await ship.projects.create({
  name: "marketing-site",
  gitOwner: "acme",
  gitRepo: "site",
  gitBranch: "main",
  framework: "nextjs",
});
console.log(result);
```

## 在集群上扩缩容无状态应用

自托管项目可以把流量指向[就绪的服务器集群](/docs/api/servers)。
保存集群目标需要集群舰队管理权限。为源码构建选择一个镜像仓库；
集群节点使用已保存的镜像仓库凭据拉取不可变的发布镜像。
它支持单个应用或 worker，其实例可启动到任何选定的服务器上。
项目自有的共享卷可以让文件在多个实例间持久化；节点本地 bind mount 与
Compose 转换需要单独的迁移。PostgreSQL 与 Redis 使用各自受管的
数据库生命周期与复制。

```ts
const current = await ship.projects.getClusterWorkload("proj_123");
await ship.projects.setClusterTarget("proj_123", {
  clusterId: "cluster_123",
  config: { replicas: 3, imageRepository: "ghcr.io/acme/api" },
  expectedUpdatedAt: current.updatedAt,
  stateless: true,
});
// Deploy the project through the existing Deployments API.
// After that release is active, change its replicas without rebuilding:
const live = await ship.projects.getClusterWorkload("proj_123");
if (live.activeDeploymentId && live.activeClusterId === live.clusterId) {
  const scale = await ship.projects.scaleClusterWorkload("proj_123", {
    replicas: 4,
    expectedDeploymentId: live.activeDeploymentId,
    expectedUpdatedAt: live.updatedAt,
  });
  console.log(scale.deploymentId); // Follow the normal deployment progress stream.
}
```

副本数量变更属于配置式发布。它们复用当前镜像、等待 Pod 就绪，
并沿用既有的更新/回滚历史。请为新旧两套发布同时预留容量。
`status` 与 `observedAt` 描述最近一次观测结果；保存的 `config` 描述未来意图。
OpenShip Edge 目前经由第一个集群控制服务器进入。自动网关
故障转移与基于策略的自动扩缩容尚未实现。

### 共享应用文件

先在服务器集群上启用共享存储。用 `createClusterVolume` 创建项目
卷，再把它的名称与挂载路径加入集群配置并部署。每个发布都保留自己审核过的卷标识。`listClusterVolumes` 与 `streamClusterVolumeEvents` 会报告挂载健康状态、独立副本、扩容与备份情况。

共享文件备份使用集群已配置的外部备份目标。定时任务可按小时或按天运行。`listClusterVolumeBackups` 也包含原卷已被删除的存档；
先恢复到一个新卷并校验其内容，再把它挂到应用上。
删除卷之前先断开挂载并部署。外部备份在卷被移除后依然保留。

### 添加、导入或恢复数据库

通过 `createClusterDatabase` 创建 PostgreSQL 或 Redis，然后持续检查进度直到就绪。
数据库实例与 Redis 分片的扩缩容与应用副本无关。Redis 分片
变更需要一份已验证的备份和显式审核。

`listClusterDatabaseImports` 返回本项目现有 PostgreSQL 或
Redis 服务的合格备份。可用选定的备份走 `importFrom`，或对受管数据库存档走 `restoreFrom` 恢复。PostgreSQL 17 升级到 18 用 `copyFrom` 构建一个独立的数据库。
每条路径都保留源数据。你可以在改变应用的集群目标之前先准备好导入的数据库；之后目标必须选择同一个集群。

校验恢复出的数据，然后基于两个数据库的当前序列，显式保存或替换受管的应用连接。
重新部署以使用新连接。做最终切换时，暂停源库写入并生成一个新的恢复点；捕获之后的写入不会自动复制。
参见[数据库工作流](/docs/guides/mcp-clusters-and-scaling#数据库与备份工作流)。

## 环境变量

```
GET   /api/projects/:id/env
PATCH /api/projects/:id/env
```

`GET` 列出项目的变量，机密值已打码。写入走**合并**（merge）逻辑：只有你点名的
键会被改动——`upserts` 被插入/更新，`deletes` 被移除，其余变量
（包括未触及的已打码机密）原样保留。

<Tabs items={['SDK', 'REST API']} groupId="api-transport" persist>
<Tab value="SDK">

```ts
const result = await ship.projects.mergeEnvVars("proj_123", {
  environment: "production",
  upserts: [
    {
      key: "DATABASE_URL",
      value: "postgres://…",
      isSecret: true,
    },
  ],
  deletes: ["OLD_FLAG"],
});
console.log(result);
```

</Tab>
<Tab value="REST API">

```bash
curl -X PATCH "$OPENSHIP_URL/api/projects/proj_123/env" \
  -H "Authorization: Bearer $OPENSHIP_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "environment": "production",
    "upserts": [{"key":"DATABASE_URL","value":"postgres://…","isSecret":true}],
    "deletes": ["OLD_FLAG"]
  }'
```

</Tab>
</Tabs>

## 携带日志重试路由

路由修复可以包含 SSH 与证书签发。用流式操作跟进其进度，避免普通请求超时：

```ts
for await (const event of ship.projects.retryRoutingStream("proj_123")) {
  console.log(event.event, event.data);
}
```

对应的 HTTP 形式是 `POST /api/projects/:id/routing/retry/stream`，以 SSE 响应返回。日志事件
包含服务器的消息。终止性 `complete` 事件携带 `status: "completed"` 或
`status: "failed"`；仅凭流断开不能断定成功。取消流会停止日志投递，而已被接受的路由修复会在项目的运行时锁之下继续执行。

## 错误

<Callout title="400 —— 校验失败" type="warn">
某个字段缺失或超出范围（例如 `name` 为空、`cpuCores` 大于 4，或 `git/link` 缺少
`owner`/`repo`）。响应会指出违规字段。
</Callout>

<Callout title="403 —— 权限不足" type="error">
你的令牌或角色缺少该路由的标签——删除需要 `project:admin`，写入需要 `project:write`。
参见[权限模型](/docs/security/auth)。
</Callout>

<Callout title="项目维度路由返回 404" type="error">
该 `:id` 不属于你的组织（或已被删除）。仅限自托管的路由（标为 **†**）在 Openship Cloud 上调用时同样返回 `404`。用 `GET /api/projects` 列出你的项目以获取有效
ID。
</Callout>
