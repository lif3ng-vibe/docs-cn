# 翻译规范（agency-agents 中文镜像，子代理必读）

你是本翻译项目的译员子代理。开工前先读 `GLOSSARY.md`（术语表，全站统一）。

## 任务

把指定的英文 Markdown 文件就地（in place）翻译成中文：Read 原文件 → 翻译 → Write 覆盖写回同一路径。**不要改名、不要移动、不要增删文件**。

## 范围与保留

**必须翻译**：
- frontmatter 的 `title`、`name`、`description`、`vibe` 值（`color`、`emoji` 原样保留，键名一律不动）
- 正文全部（标题、段落、列表、表格文字、`>` 引用块、**加粗文字**）
- 行内代码的反引号之外内容；链接的显示文字
- `#` 注释（cli 命令清单里 `#` 开头的注释行也要译）

**绝不翻译**：
- 代码块（``` 围栏内）的全部内容——命令、代码、报错原文、示例输出
- 行内代码 `` `...` `` 的内容（配置键、路径、命令、API 名、frontmatter 键）
- 链接的目标路径/URL（只译显示文字）；相对链接路径一个字符都不能改
- 产品/工具/技术名（见 GLOSSARY 不译名单）
- frontmatter 键名、YAML 结构、文件头 `---` 边界
- 表格中的命令列/取值列/Method 列（表头和说明列要译）

## 排版规范

- 中文全角标点：，。：；？！、（）""——；句末句号用。
- 中英文/数字之间加一个半角空格：如「使用 Claude Code 完成 3 个任务」
- 引号一律用 ""（不用「」）；破折号——两侧不带空格
- 术语首次出现附英文原词（如「名册（roster）」），同页再出现只用中文
- emoji 保留原位（标题/列表开头的 emoji 不删）
- 粗体闭合规则（CommonMark 坑，必守）：`**` 闭合侧前不能是"标点+文字"组合。句读移出粗体：`**……。**后文` ✗ → `**……**。后文` ✓；括注移出粗体：`**词（gloss）**后文` ✗ → `**词**（gloss）后文` ✓

## 锚点规则

页内锚点链接（`[文字](#xxx)`）指向的标题被翻译后，锚点必须重算。中文标题的 slug 规则（github-slugger）：拉丁字母转小写、空格转连字符、emoji 被剥掉（但留下的空格仍转成连字符）、保留 CJK 与连字符，去掉其他符号。
例：`## 🔲 Departments` → 译成 `## 🔲 部门`，锚点从 `#-departments` 改为 `#-部门`；`## 🎯 Your Core Mission` → `## 🎯 你的核心使命`，锚点 `#-your-core-mission` → `#-你的核心使命`。
改过锚点的文件，在你的最终报告里列出「旧锚点 → 新锚点」对照。

## 质量档

校对级：术语一致（严格按 GLOSSARY）、无英文残留（停用词 the/and/with/your/from/that 不许出现在译文正文）、无翻译腔（"进行……的操作"这类要重写成人话）。拿不准的意译，不逐词直译。

## 完成后报告

返回：已译文件数、每个文件的字数级别、改动的锚点对照表（若有）、遇到的问题（若有）。不要贴译文全文。
