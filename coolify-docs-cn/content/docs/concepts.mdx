很多人是在发现 Coolify 之后才踏上自托管之旅的。如果你也是其中一员，下面这几个概念能帮你把上手体验变得更顺畅。

## 服务器

服务器（Server）是一台用来运行应用或服务的计算机，为你的项目提供所需的算力。

它可以是物理机，比如你家里的一台机器（例如树莓派 Raspberry Pi），也可以是从 Hetzner 这类托管服务商租来的机器。

## 资源

在 Coolify 中，资源（Resource）指的是你在服务器上搭建的应用或服务——比如一个网站、一个数据库或一个 API。

每个资源都有自己的配置项，比如域名、备份、健康检查等等。

Coolify 还提供了一份开箱即用的预置资源清单，称为一键服务（One-click service），可以立即部署。当然，如果你愿意，也可以轻松部署自己的应用。

## 环境

在 Coolify 中，环境（Environment）是服务器上一套量身定制的配置，决定了你的资源以什么方式运行。

举例来说，你可以有一个用于测试和调试代码的开发环境，同时还有一个让完成后的应用正式上线的生产环境。

Coolify 允许你在同一台服务器上搭建多个环境，并在它们之间自如切换。

## 项目

Coolify 中的项目（Project）是你在服务器上部署的环境和资源的集合。

它是 Coolify 中最高层级的组织结构，用来统筹你的部署体系。

你可以在同一台服务器上管理多个项目，每个项目都有自己独有的一组环境和资源。

比如，你可以为所有兴趣相关的资源建一个项目，再为工作相关的资源建另一个项目。

## 容器

在 Coolify 中，你部署的一切都以 Docker 容器的形式运行，这让应用的管理和隔离变得非常简单。

你可以直接使用 Docker Hub 或 GitHub Container Registry 等公共镜像仓库中的现成镜像来部署，无需自己构建。

部署时需要一个 Docker 镜像，它既可以是你自己构建的，也可以是别人提供的。

如果你在开发自己的应用，Coolify 可以从 Dockerfile 或 Docker Compose 文件自动构建镜像——不过这一过程相当消耗资源，需要一台性能过得去的服务器。

另一种做法是在别处构建好镜像，推送到镜像仓库，再让 Coolify 将其部署为容器。

## 反向代理

反向代理（Reverse proxy）是位于你的应用与用户之间的服务器或程序，负责把请求转发到正确的位置。

Coolify 内置了两个代理选项：Caddy 和 Traefik，它们会把发往你网站的请求导向运行应用的容器。

有了这套机制，你可以在一台服务器上运行多个应用，而无需调整配置或端口。

而且 Coolify 支持数量不限的域名，你可以部署 20 个不同的应用，每个都绑一个独立的域名。

反向代理还会为你的应用自动管理 SSL/TLS 证书。当你填入带 `https://` 的域名时，代理会自动向 [Let's Encrypt](https://letsencrypt.org?utm_source=coolify.io) 申请并安装证书，无需任何手动配置。证书会在到期前自动续期，让你的应用在无人干预的情况下始终保持安全。

## 安全

Coolify 不负责你服务器的安全与更新——保证一切安全、保持最新是你的责任。

它存在的意义是简化部署管理。虽然 Coolify 核心团队计划在未来引入更多安全功能，但目前来看，服务器安全完全取决于你自己。

## 团队

Coolify 支持多用户和多团队，让每个团队都能拥有自己的项目和环境。

你可以为用户分配管理员等角色，从而简化同一台服务器上的项目管理与协作。

目前团队功能尚未打磨到可用于生产环境的程度，但 Coolify 核心团队计划后续持续完善它。
