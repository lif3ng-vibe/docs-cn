# 为 Coolify 做贡献

<CoolCallout icon={Warning22} title="外部贡献暂时暂停" type="danger">

由于大量低质量的 pull request 垃圾提交，外部贡献暂时停止。恢复外部贡献**尚无明确时间表**。

在外部贡献重新开放之前，请先不要提交外部 pull request。以下工作流程仍可供参考。

</CoolCallout>

很高兴你有兴趣为 Coolify 做贡献。

<ContributionGuidelinesPage>

<CoolCallout icon={ArrowsRight} title="简要版">

Coolify 拥有 47 万+ 用户，由两位核心维护者维护。我们欢迎贡献，但方向一致比数量更重要：让改动保持聚焦，较大的工作先讨论再动手，提交前做好测试；修复类改动面向 `main`，新特性面向当前的 `release/v4.x` 分支。

</CoolCallout>

<CoolCallout icon={Warning22} title="重要提示" type="warn">

这些准则比许多开源项目更严格，这是有意为之。清晰的结构和边界能减轻维护者的倦怠，让 Coolify 长期可持续。

</CoolCallout>

<CoolCallout icon={Checklist2} title="Commit 与 pull request 格式" contentClassName="!p-0">
<CoolPanel>

提交信息和 pull request 标题应以动作和类别开头。描述保持简洁；罗列每处细小改动的长篇大论可能会被拒绝。

</CoolPanel>
<CoolPanel withDivider>

| 前缀 | 用途 |
| :--- | :--- |
| fix(ui): | UI 相关修复 |
| fix(api): | API 相关修复 |
| feat(api): | API 相关新增 |
| feat(service): | 一键服务改动 |

</CoolPanel>
</CoolCallout>

<CoolCallout icon={MagicWand} title="AI 使用说明">

允许使用 AI 工具，但你必须在 pull request 描述中说明。你仍有责任理解每一处改动、验证正确性并遵循项目既有模式。

</CoolCallout>

<CoolCallout icon={MessageQuestion2} title="常见问题" contentClassName="!p-0">
<CoolAccordions>
<Accordion title="修复错别字或小 bug 前需要先问吗？">

不需要。小而明显的修复可以直接以 pull request 提交。

</Accordion>
<Accordion title="可以为新特性直接开 pull request 吗？">

请先在 GitHub Discussions 或 Discord 上讨论。未经事先对齐的新特性 pull request 可能会被直接关闭、不予评审。

</Accordion>
<Accordion title="可以认领已有的 issue 吗？">

请先留言确认该 issue 仍然有效，且没有其他人正在处理。

</Accordion>
<Accordion title="修别的问题时能顺手清理代码吗？">

请让 pull request 聚焦于既定目标。重构和清理工作应单独讨论、单独提交。

</Accordion>
<Accordion title="可以用 AI 辅助吗？">

可以，但要在 pull request 描述中说明。你必须理解、验证每一处改动并为其负责。

</Accordion>
<Accordion title="为什么我的 pull request 被关闭且没有详细反馈？">

通常意味着该改动与项目方向不符、需要占用过多评审精力，或涉及不在计划内的工作。

</Accordion>
</CoolAccordions>
