# 在 Hetzner 上做负载均衡
Hetzner Cloud 是一家提供多种服务的云托管服务商。本指南将演示如何用 Coolify 在 Hetzner Cloud 上部署负载均衡应用。

## 简介

你的应用不断增长，需要扩展了。扩展应用最常见的方式之一是使用负载均衡器（load balancer）。负载均衡器把入站流量分发到多台服务器上，避免任何一台服务器被压垮，从而提升应用的性能与可靠性。

本指南将演示如何用 Coolify 在 Hetzner Cloud 上部署负载均衡应用。我们会用两台（或更多）服务器托管应用，并用一个负载均衡器分发入站流量，还会介绍如何按需配置数据库服务器。


<Callout type="success" title="提示">

整套基础设施每月大约花费 15 欧元。

</Callout>


## 前提条件

- 一个由 Hetzner Cloud 托管的域名
- Hetzner Cloud 上的 2 台（或更多）服务器
- Hetzner Cloud 上的一个负载均衡器
- 用于限制服务器访问的防火墙规则
- 可选：Hetzner Cloud 上的一台数据库服务器


## 步骤

1. ### 购买服务器

    首先，你需要在 Hetzner Cloud 上购买两台（或更多）服务器。可以根据需求选择服务器类型和位置，并确保所选服务器有足够资源运行你的应用。


<Callout type="warn" title="注意">

    请务必创建私有网络并附加到你的服务器上，这样服务器之间就能通过私有网络互相通信。

</Callout>


    如果你还没有 Hetzner Cloud 账号，可以通过这个[推荐链接](https://coolify.io/hetzner)注册。

2. ### 在 Coolify 中添加并验证

    买好服务器后，需要把它们添加到 Coolify：点击 Coolify 面板中的 `Add Server`（添加服务器）按钮，按提示操作即可。

    Coolify 会自动在服务器上安装所需软件。

3. ### 可选：部署数据库

    建议为应用配备独立的数据库服务器，这不仅是为了性能，也是为了安全。这样你的应用可以连接到一个集中式的数据库服务器。

    如果不需要数据库服务器、或已有托管在别处的数据库，可以跳过这一步。

    买好数据库服务器并添加到 Coolify 后，在上面部署你需要的数据库类型（MySQL、PostgreSQL 等）。


<Callout type="warn" title="注意">

    本指南不使用反向代理。我们会把数据库直接绑定到服务器的公网 IP，并用防火墙限制对数据库服务器的访问。

    你可以在 `Server` 标签页中停止它们，并把代理类型切换为 `None`。

</Callout>


    请正确设置 `Ports Mappings`（端口映射），让应用服务器能够连接数据库服务器。

    - PostgreSQL: `5432:5432`
    - MySQL: `3306:3306`
    - MariaDB: `3306:3306`
    - MongoDB: `27017:27017`

4. ### 部署你的应用

    接下来把应用部署到应用服务器上。具体部署细节取决于你部署的应用类型。

    在 Coolify 中，可以为同一个应用附加多台服务器，从而把应用部署到多台服务器上。


<Callout type="warn" title="注意">

    本指南不使用反向代理。我们会把应用直接绑定到服务器的公网 IP，路由由负载均衡器负责。

    你可以在 `Server` 标签页中停止它们，并把代理类型切换为 `None`。

</Callout>


    请正确设置 `Ports Mappings`，把应用端口转发到服务器的公网 IP。

    如果应用使用了数据库，确保更新数据库连接字符串，指向数据库服务器。

<Callout type="success" title="提示">

     Hetzner Cloud 提供私有网络功能，可以用私有网络连接你的服务器，有助于提升应用的安全性与性能。
     
     请确保在服务器上启用私有网络功能，并在数据库连接字符串中使用它。

</Callout>


    在浏览器中访问服务器的公网 IP 和端口，测试应用是否正常工作。

5. ### 添加并配置负载均衡器

    接下来添加一个负载均衡器，把入站流量分发到你的多台服务器上。

    这个负载均衡器将负责：
    - 在多台服务器之间分发入站流量
    - 终止 TLS 连接（让应用通过 HTTPS 保证安全，并通过 HTTP 把流量转发到你的服务器）
    - 对服务器做健康检查，把流量路由到健康的服务器

    假设你的应用在两台服务器上都运行于 `port 8000`，并且你拥有域名 `example.com`。

    1. 进入 Hetzner Cloud 控制台，点击左侧边栏的 `Load Balancers`（负载均衡器）。
    2. 点击 `Create Load Balancer`（创建负载均衡器）按钮。
    3. 选择你的服务器所在的区域。
    4. 选择你为服务器创建的私有网络。
    5. 在 targets 部分选择所有服务器。**重点**：`(use the private network)`（使用私有网络）。
    6. 在 services 中删除默认服务，添加 `TLS Termination` 预定义服务。
    7. `Destination Port`（目标端口）填 `8000`（源端口应为 `443`）。
    8. 为你的域名添加证书。系统会用 Let's Encrypt 为域名生成证书。
    9. 在 `health check` 部分，把健康检查端点配置为应用的健康检查端点（只要是一个返回 `200 OK` 的端点即可）。
    10. 可选：可以启用粘性会话（sticky sessions），让同一用户在一段时间内始终被路由到同一台服务器；否则负载均衡器会把流量随机分发到各台服务器。
    11. 选择一种算法。
    12. 最后为负载均衡器命名，点击 `Create & Buy now`（创建并立即购买）。

    等待负载均衡器创建完成并转为健康状态。之后就可以检查应用能否通过负载均衡器的 IP 地址访问。

6. ### 配置 DNS

    接下来把域名指向负载均衡器的 IP 地址：在域名服务商的 DNS 设置中添加一条 `A` 记录即可。

    1. 进入你的 DNS 设置。
    2. 添加一条 `A` 记录，填入域名和负载均衡器的 IP 地址。
    3. 保存更改，等待 DNS 生效。

    DNS 生效后，就可以用域名访问你的应用了。

7. ### 配置防火墙

    Hetzner Cloud 提供防火墙功能，可用于限制对你服务器的访问。我们将用它来限制访问。

    由于负载均衡器通过私有网络与你的服务器通信，我们只需为公网 IP 地址添加规则。

    `Inbound`（入站）规则包含所有允许的内容，其余默认全部拦截。

    1. 进入 Hetzner Cloud 控制台，点击左侧边栏的 `Firewalls`（防火墙）。
    2. 点击 `Create Firewall`（创建防火墙）按钮。
    3. 在 `Inbound` 规则中为你的 IP 地址添加 SSH 访问规则。
    4. 把你的服务器添加到 `Apply rule` 部分。
    5. 为防火墙命名，点击 `Create Firewall`。


<Callout type="success" title="提示">

    可选：如有需要，可以添加更多规则，放行对特定端口或 IP 地址的访问。

</Callout>
