# MCP 疑难排查

<Accordions type="multiple">
<Accordion title="MCP 端点返回 404">

在**设置 > 高级 > API and MCP** 中，把 **MCP server** 设为 **Enabled（已启用）**，然后选择 **Save changes（保存更改）**。该设置被禁用时，实例端点会返回 `404`。

</Accordion>
<Accordion title="MCP 端点返回 403">

打开令牌所属团队的 **Team > General**。把 **MCP server** 设为 **Enabled for this team（对此团队启用）**，然后选择 **Save changes（保存更改）**。

</Accordion>
<Accordion title="客户端返回 401 或身份验证失败">

确认 `Bearer` 之后跟的是完整令牌、令牌未过期且未被撤销，并且令牌属于某位团队成员。再确认客户端在每一次 MCP 请求上都带上了该请求头。

</Accordion>
<Accordion title="客户端无法连接">

确认 URL 以 `/mcp` 结尾、实例从客户端机器可达、HTTPS 证书有效，且传输方式为 **Streamable HTTP**。不要为 Coolify 的远程端点配置 SSE 或 stdio。

</Accordion>
<Accordion title="工具报告缺少权限">

检查类操作用 `read`，受支持的敏感输出用 `read:sensitive`，部署或生命周期操作用 `deploy`。执行受限操作时，令牌所有者必须保有所需的团队角色。

</Accordion>
<Accordion title="找不到某个资源">

MCP 只返回令牌所属团队拥有的资源。请为拥有该资源的团队创建或改用令牌。可以先用 `get_current_team` 或 `get_infrastructure_overview` 检查令牌的作用域。

</Accordion>
<Accordion title="日志不可用">

`get_logs` 需要 `read:sensitive` 权限、一个正在运行的容器和一台可达的服务器。对于失败的部署，请先调用 `get_deployment`，仅在确有需要时才请求可选的日志摘要。

</Accordion>
</Accordions>
