# 健康检查

Coolify 会为每个独立数据库配置 Docker 健康检查。探测命令由镜像按引擎提供，在数据库容器内运行，并上报配置的检查是否成功。

打开数据库资源，然后选择 **Healthcheck**（健康检查）。

## 配置检查项

| 设置 | 默认值 | 接受的值 |
| :--- | :---: | :--- |
| **Interval (seconds)**（间隔，秒） | `15` | 大于等于 `1` 的整数。 |
| **Timeout (seconds)**（超时，秒） | `5` | 大于等于 `1` 的整数。 |
| **Retries**（重试次数） | `5` | 大于等于 `1` 的整数。 |
| **Start period (seconds)**（启动等待期，秒） | `5` | 大于等于 `0` 的整数。 |

探测命令由数据库镜像提供。上述设置控制 Docker 何时运行它、何时把容器标记为不健康；它们不会改变数据库的认证、存储或连接 URL。

## 启用或停用检查

健康检查默认启用。只有当镜像或自定义配置无法支持生成的探测命令时，才选择 **Disable healthcheck**（停用健康检查）。停用后，Docker 不再运行健康探测，Coolify 也无法上报数据库的健康或不健康状态。

选择 **Save changes**（保存更改），然后重启数据库以应用生成的健康检查配置。

## 验证健康检查

数据库重启后：

1. 打开数据库状态，确认其显示为健康。
2. 打开 **Runtime Logs**（运行日志），检查数据库是否完成了启动。
3. 从同一目标网络上的应用使用 **Internal URL**（内部 URL）连接。

健康检查通过只能证明配置的探测命令通过了，不代表应用查询、备份完整性、复制或可用磁盘空间没有问题。

<Callout type="warning" title="预留足够的启动时间">

**Start period (seconds)** 要设得足够大，让数据库能在所选服务器和存储上完成初始化。启动等待期过短，可能把一次缓慢的首次启动标记为不健康，即使数据库稍后本可就绪。

</Callout>

MongoDB 的健康检查会 ping 数据库，因此容器在运行但数据库无法响应时，不会再被自动视为健康。检查失败时请查看容器日志。
