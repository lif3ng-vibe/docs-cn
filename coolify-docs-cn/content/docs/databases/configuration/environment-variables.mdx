# 环境变量

数据库环境变量在运行时把配置传给数据库容器。

打开数据库资源，然后选择 **Environment Variables**（环境变量）。

## 添加或编辑变量

使用 **Normal view**（普通视图）逐个添加或编辑变量。选择 **Add**（添加），填写 **Name**（名称）和 **Value**（值），按需选择 **Value type**（值类型）和 **Interpolation**（插值），然后选择 **Add variable**（添加变量）。要编辑某个变量，选择它的名称或编辑图标，修改后选择 **Update variable**（更新变量）。使用 **Developer view**（开发者视图）可以文本形式查看或编辑生产变量列表。可用控件取决于你的团队权限。

每个变量都有键和值。请把密码、令牌和连接字符串当作机密对待。不要把机密放进数据库镜像、提交到 Git 的自定义配置或公开 URL 中。

## 外部机密管理器

可以关联 Doppler、Infisical 或 HashiCorp Vault，并用 `{{vault.KEY}}` 引用远程值。服务商的值变更后，请重启或重新部署数据库。参见[使用机密管理器](/integrations/security/using-secret-managers)。

## 数据库变量与常规设置

环境变量与 **General**（常规）上的凭据和引擎字段是分开的。有些数据库镜像会在初始化阶段使用环境变量，而另一些设置则由常规表单生成。

在新建的 KeyDB 和 Dragonfly 资源上，`REDIS_PASSWORD` 会同时设定服务器密码和连接 URL。此版本之前创建的资源会保留已存储的密码，除非该变量使用机密管理器引用。更改既有资源的凭据前，请先了解对应引擎的行为。

## 应用更改

保存变量会更新资源存储的配置。请重启或重新部署数据库，让容器以新的环境启动。

启动之后：

1. 打开数据库的 **Runtime Logs**（运行日志），确认进程启动时没有环境变量错误。
2. 检查数据库状态和健康检查。
3. 使用更新后的 **Internal URL**（内部 URL）或使用该变量的客户端配置进行连接。

<Callout type="warning" title="初始化变量可能只生效一次">

许多数据库镜像只在数据目录初始化时使用环境变量。修改初始化变量不一定能改变已存在的数据库。对已初始化的数据目录，请遵循引擎文档，用审慎的迁移或 SQL 命令处理。

</Callout>

## 命名与复制值

新的环境变量名必须匹配 `[A-Za-z_][A-Za-z0-9_.]*`：以字母或下划线开头，其后为字母、数字、下划线或点。既有的无效仅运行时名称（如 `my-var`）会带警告和建议名称部署；无效的构建时名称则会导致镜像构建失败。

使用复制按钮可以复制解析后的值。共享变量和 `$SERVICE_*` 引用会解析为实际值。已锁定的变量没有复制按钮，指向已锁定共享变量的引用会保持为引用，不会暴露机密。
