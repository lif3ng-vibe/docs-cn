# 资源限制

打开数据库资源，然后选择 **Resource Limits**（资源限制），即可限制其容器可用的 CPU 和内存。

请从实测的数据库用量出发，并为启动、备份、压实（compaction）和查询高峰预留足够余量。限制过低会让健康的数据库看起来不可用。

## CPU 限制

| 设置 | 接受的值 | 默认值 | 行为 |
| :--- | :--- | :---: | :--- |
| **CPU limit** | 整数或小数，例如 `2` 或 `0.5`。 | `0` | CPU 容量上限。`0` 表示未配置限制。 |
| **CPU set** | CPU 编号或区间，例如 `0-2` 或 `0,1,3`。 | 空 | 把容器限制在选定的 CPU 核心上。 |
| **CPU weight** | 大于等于 `0` 的整数。 | `1024` | 容器争抢 CPU 时间时的相对优先级。 |

**CPU weight** 只在资源争抢时改变优先级，不会预留 CPU 容量。

## 内存限制

内存字段接受 `0`，或后跟 `b`、`k`、`m`、`g` 的数字，例如 `256m` 或 `1g`。

| 设置 | 默认值 | 行为 |
| :--- | :---: | :--- |
| **Memory reservation** | `0` | 服务器内存吃紧时生效的内存预留。 |
| **Swappiness** | `60` | 取值 `0` 到 `100`，控制匿名内存被换出（swap）的倾向。 |
| **Memory limit** | `0` | 容器的硬内存上限。 |
| **Memory and swap limit** | `0` | 容器可用的内存与 swap 总量。 |

CPU 和内存限制字段中的 `0` 表示未配置限制。只有在理解数据库的内存行为和服务器可用容量之后，才设置明确的限制。

<Callout type="warning" title="限制过低可能让数据库停摆">

达到硬内存上限的数据库可能被 Docker 终止。过低的 CPU 限制也可能让启动、健康检查、备份或查询超时。应用限制后，请检查 **Runtime Logs**（运行日志）、**Metrics**（指标）和健康状态。

</Callout>

## 应用并验证

选择 **Save changes**（保存更改），然后重启或重新部署数据库，让容器以新限制启动。

启动之后：

1. 打开 **Metrics**，检查 CPU 和内存用量。
2. 打开 **Runtime Logs**，留意内存耗尽退出、反复重启或启动失败的消息。
3. 在支持的情况下，运行一条有代表性的应用查询和一次备份。
