# PostgreSQL

Coolify 将 PostgreSQL 作为独立容器部署到所选的服务器与目标（Destination）上。新建的资源会获得自动生成的密码、持久化数据卷、内部连接 URL 和一个健康检查。

PostgreSQL 是一种对象关系型数据库，适用于事务型负载、关系型数据和扩展（extension）场景。

## 创建 PostgreSQL 数据库

<Steps>
<Step>

### 打开 New Resource

打开数据库将要归属的项目和环境，然后选择 **New Resource**（新建资源）。

</Step>
<Step>

### 选择 PostgreSQL

在 **Databases**（数据库）下选择 **PostgreSQL**，也可以按名称搜索 **PostgreSQL**。

</Step>
<Step>

### 选择服务器

选择运行 PostgreSQL 的服务器。构建服务器无法选择，因为它们不承载运行中的数据库资源。

</Step>
<Step>

### 选择目标

选择 PostgreSQL 要加入的 Docker 网络目标。

</Step>
<Step>

### 选择 PostgreSQL 类型

选择符合所需主版本和扩展的 PostgreSQL 镜像。除非数据库需要某个扩展镜像，否则请使用标准 PostgreSQL 选项。

</Step>
<Step>

### 检查生成的配置

Coolify 会创建资源并打开 **General**（通用）页面。检查镜像、用户名、生成的密码、初始数据库和连接 URL。除非外部客户端需要访问，否则保持默认的私有网络。

</Step>
<Step>

### 启动 PostgreSQL

选择 **Start**（启动），并关注启动输出。等 PostgreSQL 进入运行且健康的状态后，将 **Postgres URL (internal)**（内部 Postgres URL）复制到同一目标网络内的应用中。

</Step>
</Steps>

## 默认配置

| 设置 | 默认值或行为 |
| :--- | :--- |
| Internal port | `5432` |
| 默认镜像 | PostgreSQL 18（`postgres:18-alpine`） |
| Username | `postgres` |
| 初始数据库 | `postgres` |
| 数据挂载 | PostgreSQL 17 及更早版本为 `/var/lib/postgresql/data`；PostgreSQL 18 及更高版本为 `/var/lib/postgresql` |
| 计划备份 | 支持 |
| SSL | 通过 PostgreSQL SSL 模式支持 |

Coolify 的 PostgreSQL 选择器包含 PostgreSQL 18、17、16 镜像，以及 Supabase PostgreSQL、PostGIS 和 PGVector 扩展镜像。请根据应用所需的扩展、架构和主版本选择镜像。

密码在资源创建时自动生成。如果你在 Coolify 之外修改了运行中数据库的用户名、密码或初始数据库，请同步更新 **General** 中的对应字段，以保证连接 URL 和自动备份继续正常工作。


## 连接 PostgreSQL

同一 Coolify 目标网络内的应用请使用 **Postgres URL (internal)**（内部 Postgres URL）：

```sh
postgres://<username>:<password>@<database-container>:5432/<database>
```

当 **Public access > Access**（公共访问 > 访问）设置为 **Public through TCP proxy**（通过 TCP 代理公开）时，Coolify 还会显示基于服务器地址和 **Public port**（公共端口）的 **Postgres URL (public)**（公共 Postgres URL）。除非外部客户端需要，否则不要暴露 `5432` 端口；应用连接优先走私有网络。

阅读[数据库](/databases)文档，了解端口映射、公共 TCP 代理与防火墙注意事项。

## 配置 PostgreSQL

打开 **General**（通用）页面，然后使用与你需要修改的设置相对应的区块。

<Tabs id="postgresql-configuration" items={['通用（General）', '初始化', '配置文件', '网络与 Docker']}>
<Tab value="通用（General）">

### 资源详情

使用 **Name**（名称）和 **Description**（描述）在 Coolify 中标识该资源。**Image**（镜像）决定 Coolify 创建容器时使用的 PostgreSQL 镜像。

### 数据库凭据

**Username**（用户名）、**Password**（密码）和 **Initial database**（初始数据库）决定了生成的连接 URL，也是 Coolify 数据库操作所使用的值。如果你在 PostgreSQL 内部修改了对应值，请保持 Coolify 中的字段同步。

</Tab>
<Tab value="初始化">

### 初始数据库选项

**Initial database arguments**（初始数据库参数）向 PostgreSQL 初始化过程传递参数。**Host authentication method**（主机认证方式）控制镜像在初始化新数据目录时使用的认证方式。

这些设置不会重新初始化已存在的持久化数据目录。

### 初始化脚本

在 **Initialization scripts**（初始化脚本）下添加文件名和内容。Coolify 会把这些脚本挂载到 `/docker-entrypoint-initdb.d/` 下。

PostgreSQL 镜像只在初始化空数据目录时才运行这些脚本。添加或编辑脚本并不会对现有数据库执行它。

</Tab>
<Tab value="配置文件">

### 自定义 PostgreSQL 配置

使用 **Custom PostgreSQL configuration**（自定义 PostgreSQL 配置）提供容器所用的 `postgresql.conf` 内容。Coolify 会挂载生成的文件，并在配置未定义 `listen_addresses` 时添加 `listen_addresses = '*'`。

应用之前，请对照所选 PostgreSQL 镜像逐条检查指令。无效的指令可能导致 PostgreSQL 无法启动。

</Tab>
<Tab value="网络与 Docker">

### 网络访问

使用 **Port mappings**（端口映射）建立直接的 Docker 主机到容器映射。在 **Public access**（公共访问）下设置 **Public port**（公共端口）与 **Proxy timeout**（代理超时），然后在 **Access**（访问）中选择 **Public through TCP proxy**（通过 TCP 代理公开），即可使用 Coolify 独立的 TCP 代理。

除非外部客户端需要直接访问，否则保持 PostgreSQL 私有。发布数据库端口前，请先阅读[网络访问](/databases#网络访问)。

### Docker 选项

**Custom Docker options**（自定义 Docker 选项）仅用于填写其他字段未涵盖的受支持 Docker run 选项。无效或冲突的选项可能导致容器无法启动。

</Tab>
</Tabs>

修改镜像、端口映射、配置或健康检查会把资源标记为已更改。重启数据库即可用新生成的 Compose 配置重建容器。

## 备份与恢复 PostgreSQL

Coolify 的计划备份任务对所选数据库使用 custom 格式的 `pg_dump`：

```sh
pg_dump --format=custom
```

归档会保留对象所有者与权限（`GRANT`）。**Import Backup**（导入备份）表单默认跳过它们；勾选 **Keep owners and privileges**（保留所有者与权限）即可一并恢复，例如 Supabase 数据库的场景，其角色需要保留各自的授权。角色并不包含在单数据库归档中；同一服务镜像新建的数据库容器会在首次启动时创建自己的角色。

当 **Database selection**（数据库选择）为 **All databases**（所有数据库）时，Coolify 使用 `pg_dumpall` 并存储 gzip 压缩的转储。计划、保留策略和 S3 目标请在[数据库备份](/databases/backups)中配置。内置的 PostgreSQL 导入流程请遵循[恢复数据库](/databases/restore)。

内置的 **Import Backup**（导入备份）表单可在数据库运行期间接受 PostgreSQL 备份。Coolify 会检测转储格式，并使用 `pg_restore` 或 `psql` 生成相应的恢复命令。开始恢复前，请检查只读的 **Import command**（导入命令）。

<Callout type="warning" title="转储格式要与恢复命令匹配">

custom 格式的转储不是纯 `.sql` 文件。custom 格式文件用 `pg_restore`，纯 SQL 用 `psql`。恢复会替换目标数据库中的数据，执行前请先检查命令。

</Callout>

## SSL 与健康检查

PostgreSQL 支持 `allow`、`prefer`、`require`、`verify-ca` 和 `verify-full`。后两种模式要求客户端信任 Coolify CA 证书。参见[数据库 SSL](/databases/ssl)。

默认健康检查在 PostgreSQL 容器内运行。在 **Healthcheck**（健康检查）下配置其间隔、超时、重试次数和启动等待期，然后重启 PostgreSQL 使更改生效。
