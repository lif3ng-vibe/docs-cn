# Dragonfly

Coolify 将 Dragonfly 作为独立的 Redis 兼容数据存储部署到所选的服务器和目标上。新资源会自动获得生成的密码、位于 `/data` 的持久化卷、内部连接 URL 和健康检查。

Dragonfly 是一种 Redis 兼容的数据存储，为内存型工作负载和多线程执行而设计。

## 创建 Dragonfly 数据库

<Steps>
<Step>

### 打开新建资源

打开数据库应归属的项目和环境，然后选择 **New Resource**（新建资源）。

</Step>
<Step>

### 选择 Dragonfly

在 **Databases**（数据库）下选择 **Dragonfly**。也可以按名称搜索 **Dragonfly**。

</Step>
<Step>

### 选择服务器

选择要运行 Dragonfly 的服务器。构建服务器无法选择，因为它们不承载运行中的数据库资源。

</Step>
<Step>

### 选择目标

选择 Dragonfly 要加入的 Docker 网络目标。

</Step>
<Step>

### 检查生成的配置

Coolify 创建资源并打开 **General**（常规）。请检查镜像、生成的密码、SSL 设置和连接 URL。除非外部客户端需要访问，否则保持默认的私有网络设置。

</Step>
<Step>

### 启动 Dragonfly

选择 **Start**（启动）并留意启动输出。等 Dragonfly 进入运行且健康的状态后，把 **Dragonfly URL (internal)**（内部 URL）复制给同一目标网络中的应用。

</Step>
</Steps>

## 默认配置

| 设置 | 默认值或行为 |
| :--- | :--- |
| 内部端口 | `6379`；TLS 使用 `6380` |
| 默认镜像 | `docker.dragonflydb.io/dragonflydb/dragonfly` |
| 认证 | 生成的密码 |
| 数据挂载 | `/data` |
| 计划数据库备份 | Coolify 不支持 |
| SSL | 通过 **SSL** 开关支持 |

Dragonfly 的连接 URL 使用 Redis 协议。Coolify 数据库表单中不提供用户名字段。


## 连接 Dragonfly

同一 Coolify 目标网络上的应用请使用 **Dragonfly URL (internal)**：

```sh
redis://:<password>@<database-container>:6379/0
```

启用 SSL 后，使用生成的 `rediss` URL 和 TLS 端口 `6380`。当 **Public access（公开访问）> Access** 为 **Public through TCP proxy**（经 TCP 代理公开）时，使用生成的 **Dragonfly URL (public)**（公开 URL）。

## 配置 Dragonfly

打开 **General** 修改镜像、密码、**Port mappings**（端口映射）、公开代理和受支持的自定义 Docker 选项。打开 **Persistent Storage**（持久化存储）管理 `/data` 卷。

Dragonfly 的持久化行为由镜像和命令选项决定。在更改启动选项或假定内存数据已落盘之前，请先查阅镜像文档。

## 备份与持久化

Coolify 不为 Dragonfly 创建计划数据库备份。需要恢复副本时，请保留 `/data` 持久化卷，并配置 Dragonfly 支持的快照或持久化特性。恢复请单独测试。

## SSL 与健康检查

Dragonfly 提供 **SSL** 开关，但没有 SSL 模式选择器。CA 证书挂载与 TLS 连接流程见[数据库 SSL](/databases/ssl)。

在 **Healthcheck**（健康检查）下配置 Docker 健康检查，保存后重启 Dragonfly。

## 密码环境变量

对新建数据库，`REDIS_PASSWORD` 同时控制服务器密码和连接 URL。此版本之前创建的数据库会保留已存储的密码，除非该变量引用了机密管理器。更改远程机密后，请重启数据库并验证连接。
