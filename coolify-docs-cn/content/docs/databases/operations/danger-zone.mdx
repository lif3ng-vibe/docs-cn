# 删除数据库

打开数据库，选择 **Danger Zone**（危险区域），即可永久移除该数据库资源。删除操作无法在 Coolify 中撤销。

<Callout type="danger" title="删除前先备份数据库">

删除数据库可能会连同移除其容器、配置、卷（volume）和网络资源。请先完成一次经过验证的数据库备份，并记录好连接设置，再继续操作。持久化存储卷不能替代备份。

</Callout>

## 删除前的准备

- 确认没有应用仍在依赖该数据库。
- 导出或备份所有需要的数据库，并验证恢复流程可用。
- 如果日后可能重建数据库，请记录其镜像、凭据、存储挂载、环境变量、端口、SSL 设置与备份设置。
- 确认自己拥有删除该资源的权限。
- 在确认对话框中逐项查看可选的删除动作，不要不加确认地全盘接受。

## 删除动作

确认对话框中可以勾选以下动作。当前界面中它们默认全部勾选：

| 动作 | 效果 |
| :--- | :--- |
| **Permanently delete all volumes associated with this resource.**（永久删除该资源关联的所有卷） | 删除该数据库的 Docker 卷及其存储的数据。 |
| **Permanently delete all non-predefined networks associated with this resource.**（永久删除该资源关联的所有非预定义网络） | 删除与该资源关联的非预定义 Docker 网络。 |
| **Permanently delete all configuration files from the server.**（永久删除服务器上的所有配置文件） | 从服务器上删除 Coolify 为该资源生成的配置文件。 |
| **Run Docker Cleanup (remove unused images and builder cache).**（运行 Docker 清理，移除未使用的镜像与构建缓存） | 删除完成后在该资源所在的服务器上运行 Docker 清理。 |

只有当你确实想保留卷以便另行恢复或手动清理时，才取消勾选 **volumes**（卷）。保留卷并不意味着保留 Coolify 的数据库资源，也不会让数据自动对新创建的资源可用。

## 确认删除

在确认对话框中选择 **Delete**（删除）。根据实例的确认设置，Coolify 可能要求你输入完整的数据库名称以及 Coolify 账户密码。随后 Coolify 会移除该资源记录，并将所选 Docker 资源的清理任务加入队列。

在删除任务完成之前，该数据库可能会短暂地继续显示。在确认旧资源及其容器已彻底移除之前，不要使用相同的存储或公网端口重建数据库。

## 删除之后

1. 确认该数据库已不再出现在项目环境中。
2. 确认其容器已不再运行于服务器上。
3. 移除或更新曾指向该数据库的应用连接变量，以及公网 DNS 与防火墙规则。
4. 如果重建数据库，请使用受支持的镜像，并先恢复经过验证的备份，再重新接入应用。

Coolify 不会管理你 DNS 服务商处的 DNS 记录，过期的 DNS 记录请另行删除。

当服务器不可达时，删除资源会警告服务器上仍残留 Docker 资源，之后会通知团队。待服务器恢复访问后，再清理这些残留资源。
