# 运维数据库

数据库部署完成后，Coolify 为配置、备份、日志、终端访问和运行时指标提供了各自独立的视图。按需要执行的任务选择对应的页面即可。

## 找到对应的页面

| 页面 | 用途 |
| :--- | :--- |
| **General**（通用） | 修改镜像、凭据、引擎设置和网络。存储、健康检查、环境变量与资源限制在侧边栏的独立页面中。 |
| **Backups**（备份） | 为 PostgreSQL、MySQL、MariaDB、MongoDB 和 ClickHouse 安排并检查引擎专属的备份。 |
| **Runtime Logs**（运行时日志） | 查看数据库容器的输出。 |
| **Terminal**（终端） | 在运行中的数据库容器内执行命令（需团队与服务器允许终端访问）。 |
| **Metrics**（指标） | 当服务器上启用了 Sentinel & Metrics 且容器正在运行时，查看 CPU 与内存使用情况。 |
| **Resource Operations**（资源操作） | 将数据库克隆到另一台服务器或目标（Destination），或移动到另一个项目或环境。 |
| **Danger Zone**（危险区域） | 删除数据库资源，并可选地移除关联的 Docker 资源。 |

Redis、Dragonfly 和 KeyDB 不显示 **Backups**（备份）页面，因为 Coolify 未为它们提供独立的数据库计划备份流程。在正常的容器替换过程中，其持久化卷仍会保护数据；但持久化存储不等于备份。

## 选择生命周期操作

数据库头部会根据当前状态显示相应操作：

| 操作 | 作用 |
| :--- | :--- |
| **Start**（启动） | 启动已停止的数据库容器。 |
| **Restart**（重启） | 重启数据库。重启期间数据库不可用。 |
| **Stop**（停止） | 停止数据库并清除非持久化的容器数据。资源与持久化数据会保留，之后可再次启动。 |

只有当客户端能够容忍中断时，才停止或重启数据库。数据库不可用期间，正在进行的写入或不具备重试机制的客户端可能会失败。

首次部署数据库或应用需要重新部署的配置时，请使用资源页面上的部署控件。修改 SSL、健康检查、存储、端口、镜像或引擎设置后，请关注页面的状态与活动消息，确认数据库恢复运行后再重新接入应用。

## 保护数据库状态

<Callout type="warning" title="持久化存储不等于备份">

持久化卷能在正常的容器替换中保住数据库文件，但无法应对删除卷、磁盘故障、数据损坏或服务器丢失。受支持的引擎请配置引擎专属的备份，并先演练一次恢复再真正依赖它。

</Callout>

在数据库服务器之外至少保留一份经过验证的备份。对 Redis、Dragonfly 和 KeyDB 而言，由于 Coolify 的独立备份流程不可用，请使用引擎自带的持久化或备份工具、一个 Compose 服务或外部备份方案。

## 资源操作按钮

主要资源操作是一个一键按钮，次要操作放在相邻的下拉菜单中。破坏性操作会在 Coolify 模态框中要求确认，继续之前请仔细核对列出的影响。

## 跟踪进行中的操作

使用 **Deploying… View log**（部署中… 查看日志）可以重新打开正在进行的部署或启动日志。在操作进行期间选择 Deploy、Start 或 Restart，同样会重新打开其日志。运行中的部署指示器会显示在侧边栏、移动端顶栏以及仪表盘上。

容器日志查看器将 **Time**（时间）、**Type**（类型）和 **Message**（消息）分列展示。展开某一行即可查看格式化后的 JSON。如果容器列表无法加载，请阅读显示的错误信息，而不要把它当成"没有容器在运行"的证明。

查看容器日志需要具备更新该资源的权限。通过 API 请求日志则需要 `read:sensitive` 或 `root` 权限。
