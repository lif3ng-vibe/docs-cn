# 服务

Coolify 把一个服务（Service）作为 Docker Compose 堆栈部署到一台已连接服务器和网络目标（Destination）上。你可以从现成的一键模板起步，也可以选择 **Docker Compose Empty（空 Docker Compose）**并提交自己的 Compose 定义。

每个 Service 可以包含多个应用和数据库容器。Coolify 会解析 Compose 定义，为识别到的组件生成控制项、生成必需的值、配置域名和存储，并用 Docker Compose 运行整套堆栈。

<Callout type="info" title="选对资源类型">

如果部署应当跟随 Git 仓库中的源码，或只是使用一个现成的 Docker 镜像，请用[应用（Application）](/applications)。如果你需要 Coolify 针对特定数据库引擎的默认配置，请用[独立数据库（Database）](/databases)。多容器堆栈，或想把 Compose 定义直接存在 Coolify 里时，请用 Service。

</Callout>

## 部署一个服务

1. 打开一个项目和环境，然后选择 **Create New Resource（新建资源）**。
2. 选择一个一键 Service，或选择 **Docker Compose Empty（空 Docker Compose）**。
3. 选择堆栈要运行的服务器和网络目标（Destination）。
4. 对于 **Docker Compose Empty（空 Docker Compose）**，粘贴 Compose 定义并保存。
5. 审阅 **配置 > 常规**、**环境变量**和**持久化存储**。
6. 填写所有必需的环境变量，然后选择 **Deploy（部署）**。
7. 跟随部署输出，确认每个必需组件都在运行且健康。

想完整走一遍首次部署，请跟随[部署你的第一个服务](/deploy-your-first-service)。

## 理解一键服务

一键 Service 从 Coolify 服务库维护的 Compose 模板起步。Coolify 会把模板复制到新资源并生成初始值。

部署后的 Service 保留自己的 Compose 定义。之后服务库的变更不会重写这份定义。**Pull Latest Images & Restart（拉取最新镜像并重启）**只会按 Service 中当前保存的标签拉取镜像；它不会用新版本的模板替换已存储的模板。

打开[可搜索的目录](/services/overview)找到某个 Service，然后阅读它的专属指南了解特定服务的设置、凭据或限制。
