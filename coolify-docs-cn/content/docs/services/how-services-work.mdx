# 服务的工作原理

Coolify 将控制平面中的服务（Service）定义与一台已连接服务器上的 Docker Compose 项目结合在一起。

服务定义保存着原始的 Compose YAML、生成的环境变量值、所选的目标（Destination）、组件设置和运维配置。Docker 则保存运行中堆栈所用的镜像、网络、容器和持久化卷。

## 从创建到服务运行

1. 你在某个项目和环境里选择一个一键模板或 **Docker Compose Empty（空 Docker Compose）**。
2. Coolify 把选中的模板或粘贴的 Compose 定义存储到新的 Service 资源上。
3. Coolify 解析每个 Compose 服务，识别常见的数据库镜像，创建组件记录，并生成域名、凭据等被引用的值。
4. 你在 **Configuration（配置）**下审阅堆栈、必需变量、域名和存储。
5. 当你选择 **Deploy（部署）**时，Coolify 会把生成的 `.env` 文件和可部署的 `docker-compose.yml` 保存到所选服务器上的 Service 配置目录中。
6. Coolify 拉取配置的镜像，在需要时创建资源网络，并使用保存的项目名和配置运行 `docker compose up`。
7. Docker 启动各组件容器，并执行镜像或 Compose 定义中声明的健康检查。
8. Coolify 代理把配置的域名路由到相应的应用组件。

## 源定义与可部署 Compose

**Source Compose（源 Compose 定义）**是保存在 Service 上的定义，也就是你编辑的那份副本。

**Deployable Compose（可部署 Compose 定义）**是 Coolify 生成的、交给 Docker Compose 执行的定义。它可能包含规范化后的卷名、容器名、标签、网络、环境变量引用以及代理配置。

除非堆栈确实需要，否则不要把生成出来的名称复制回源定义。可以在 **配置 > 常规 > 编辑 Compose 文件**中同时查看这两个视图。

## 组件从属于一个堆栈

Coolify 会把每个解析出的 Compose 服务显示为 **Configuration（配置）> General（常规）**下的组件卡片：

- 应用组件可以配置域名和代理行为
- 数据库组件可以配置公开代理设置和受支持的备份控制
- 每个组件都能查看其镜像与容器状态

Service 的状态由其未被排除的组件聚合而来。可选组件或一次性组件可以在其 **Advanced（高级）**设置中排除出聚合状态。

单个组件可以单独重启，但 **Deploy（部署）**、**Restart（重启）**、**Stop（停止）**和 **Pull Latest Images & Restart（拉取最新镜像并重启）**作用于整个 Service 堆栈。

## 网络

Coolify 会为 Service 创建一个资源专属的 Docker 网络。同一 Compose 定义中的组件通过 Compose 服务名和内部端口互相通信。

Coolify 会在每台已连接服务器上创建一个名为 `coolify` 的共享 Docker 网络。当堆栈需要与预定义网络上的资源私密通信时，启用 **Connect To Predefined Network（连接到预定义网络）**——对默认目标（Destination）而言该网络即 `coolify`。其他 Docker 网络保持隔离，且 `coolify` 网络不会跨服务器延伸。

公开的 HTTP 流量请使用域名。只有当外部客户端需要直接的 TCP 或 UDP 访问时才发布主机端口。

同堆栈连接、`coolify` 网络、其他 Docker 网络、跨服务器路径、域名与发布端口等更多内容，请阅读[服务网络](/services/configuration/networking)。

## 配置变更与重新部署

保存一个值会更新 Service 定义。但影响容器配置的更改不一定会立即改变正在运行的容器。

更改以下内容后，需要部署或重启 Service：

- Compose 定义或镜像引用
- 环境变量
- 域名、端口、代理行为或网络
- 持久化存储
- 组件日志或状态设置

**Restart（重启）**会重建堆栈，但不会先拉取更新的镜像。**Pull Latest Images & Restart（拉取最新镜像并重启）**会先拉取当前 Compose 定义中所存镜像标签的镜像，然后重建堆栈。

<Callout type="info" title="模板更新不会替换已有的 Service">

Coolify 可以刷新用于创建新资源的模板目录。已存在的一键 Service 会保留其保存的 Compose 定义。当升级需要新的 Compose 设置、数据迁移或镜像标签时，请查看上游发布说明并手动编辑 Service 定义。

</Callout>

## 持久化数据

容器是可替换的。请把需要保留的数据存放在卷、目录、文件挂载或 Compose 定义中声明的外部服务里。

解析出的挂载会显示在使用它们的组件的 **Configuration（配置）> Persistent Storages（持久化存储）**下。对于 Service，Compose 拥有的挂载定义请在**编辑 Compose 文件**中修改，而不是在只读的存储视图里。

## 控制平面与 Service 服务器

Coolify 实例负责存储配置和协调操作。已连接的服务器保存 Service 配置目录并运行其 Docker 资源。

只要 Docker、服务器、其网络、代理和容器保持健康，已经运行中的容器可以在 Coolify 控制平面不可用时继续运转。但新的 Coolify 操作需要控制平面可用。
