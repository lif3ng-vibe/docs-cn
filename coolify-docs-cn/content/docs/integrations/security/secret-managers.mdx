# 机密管理器凭据

Coolify 支持 Doppler、Infisical 和 HashiCorp Vault。在 **Keys & Tokens > Integration Tokens** 下添加凭据，然后在资源的 **Environment Variables（环境变量）** 页面选用该令牌。

## 在 Coolify 中添加凭据

1. 打开 **Keys & Tokens > Integration Tokens**，选择 **New token**。
2. 在 **Provider（提供商）** 中选择 **Doppler**、**Infisical** 或 **HashiCorp Vault**。
3. 填写 **Token name** 以及下文所述的提供商凭据。
4. 选择 **Validate and add**。

要修改已保存的凭据，选择该令牌的编辑图标并使用 **Validate and save**。

## Doppler

两种凭据类型均可使用：

- **Service token（服务令牌）**：在 Doppler 中打开项目与 config，选择 **Access**，创建一个 service token。它的作用域会固定项目与 config。
- **Service account token（服务账户令牌）**：创建一个 service account，授予其访问所需项目/config 的权限并生成令牌。项目与 config 由你在 Coolify 中选择。

把令牌粘贴到 Coolify 的 **API token** 中。参见 [Doppler service tokens](https://docs.doppler.com/docs/service-tokens?utm_source=coolify.io) 与 [service accounts](https://docs.doppler.com/docs/service-accounts?utm_source=coolify.io)。

## Infisical

1. 在 Infisical 中创建一个 **Machine Identity**。
2. 为该身份添加 **Universal Auth** 并生成 client secret。
3. 授予该身份访问存放机密的项目与环境（environment）的权限。
4. 在 Coolify 中填写 **Base URL**、**Client ID** 与 **Client secret**。

使用 Infisical Cloud 时，Base URL 填 `https://app.infisical.com`。自托管部署应使用自己的 Base URL。参见 [Infisical Universal Auth](https://infisical.com/docs/documentation/platform/identities/universal-auth?utm_source=coolify.io)。

## HashiCorp Vault

创建一条 Vault 策略（policy），允许在所需的 KV v2 机密路径上执行 `read` 和 `list`，然后用该策略签发一个令牌。在 Coolify 中填写：

- **Base URL**：Vault 实例的 URL
- **Vault token**：该令牌
- **Namespace（可选）**：仅 Vault Enterprise 或 HCP Vault 需要

关联资源时，选择 KV v2 挂载点与机密路径。请使用范围尽可能小的策略。参见 [Vault tokens](https://developer.hashicorp.com/vault/docs/concepts/tokens?utm_source=coolify.io) 与 [policies](https://developer.hashicorp.com/vault/docs/concepts/policies?utm_source=coolify.io)。

<Callout type="warning" title="保护提供商凭据">

提供商凭据可能一次暴露多个机密。请使用最小权限访问、定期轮换凭据，并且不要把它们粘贴到环境变量里。

</Callout>
