# 使用机密管理器

机密管理器可用于应用、Docker Compose 服务和独立数据库。应用侧同时支持 Git 与非 Git 部署方式。

1. 在 **Keys & Tokens > Integration Tokens** 下添加受支持的提供商。
2. 打开资源并选择 **Environment Variables（环境变量）**。
3. 在 **Secret manager** 下选择一个 **Integration token**。使用 Doppler service account 时，填写 **Project (required)** 与 **Config (required)**；service token 则固定了这些值。使用 Infisical 时，填写 **Project ID**、**Environment slug** 与 **Secret path**。使用 Vault 时，填写 **KV v2 mount** 与 **Secret path**。来源字段在你离开输入框时保存。
4. 选择 **Browse keys**，然后在某个键旁边选择 **Add as variable**，或选择 **Import all keys**。要刷新列表，选择 **Reload keys**。你也可以用下面的值手动添加一个变量：

   ```dotenv
   API_KEY={{vault.API_KEY}}
   ```

5. 部署或重启该资源。

无论提供商是 Doppler、Infisical 还是 HashiCorp Vault，请始终使用 `{{vault.KEY}}`。

Coolify 会在部署或启动时获取这些值。值只保存在内存中并传递给资源；Coolify 不会把获取到的值存入自己的数据库。缺少来源或键时，操作会以部署错误终止。已解析的机密会从部署日志（包括命令失败信息）中脱敏。

## 刷新已更改的机密

更改提供商侧的值后，请重新部署或重启资源。对于应用构建变量，请用重新部署而不是重启。当构建期机密引用可能已发生变化时，Coolify 会跳过构建复用，因此部署会解析当前值，而不是依赖先前构建的镜像。

<Callout type="info" title="每个资源一个来源">

每个资源只能关联一个机密管理器来源。Service 层级的来源会作用于整个 Compose 栈。

</Callout>

如果你还没有创建凭据，请先按照[机密管理器凭据](/integrations/security/secret-managers)操作。
