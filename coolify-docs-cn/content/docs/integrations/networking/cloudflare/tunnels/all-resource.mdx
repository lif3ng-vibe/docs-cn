# 通过 Cloudflare Tunnel 访问所有资源

使用 Cloudflare Tunnel 访问部署在 Coolify 上的所有资源，可以在不暴露服务器 IP 地址、也没有服务器公网 IP 的情况下，安全地访问你的应用。

## 适合谁使用

以下场景非常适合这种方案：

- 服务器没有公网 IP（可能是笔记本电脑、树莓派等设备）。
- 无法进行端口转发（例如使用家庭宽带，或处于内网中）。
- 希望服务器的 IP 地址保持私密，避免暴露给公共互联网。
- 已有资源部署在 Coolify 上，需要一种从外部安全访问它的方法。

## 环境要求

按照本指南操作，你需要：

- 一个免费的 [Cloudflare](https://cloudflare.com) 账户。
- 一个 **DNS 托管在 Cloudflare** 的域名。

## 开始之前

- 默认你的服务器上已经在运行 Coolify。
- 本指南在访客与 Cloudflare 之间使用 HTTPS，在 Cloudflare Tunnel 与 Coolify 代理之间使用 HTTP。
- 如果希望两条链路都走 HTTPS，请改阅 [Full TLS HTTPS 指南](/integrations/networking/cloudflare/tunnels/full-tls)。

## 1. 创建 Cloudflare Tunnel

要创建 Cloudflare Tunnel，先登录你的 [Cloudflare dashboard](https://dash.cloudflare.com/)

<ZoomImage src="/docs-cn/coolify/images/integrations/networking/cloudflare/tunnels/all-resource/0.webp" />

1. 在侧边栏进入 **Networking（网络）**。
2. 点击 **Tunnels**。
3. 点击 **Create tunnel** 按钮。


<ZoomImage src="/docs-cn/coolify/images/integrations/networking/cloudflare/tunnels/all-resource/1.webp" />

系统会提示你输入隧道名称。填一个你喜欢的名字，然后点击 **Create tunnel** 按钮。

<ZoomImage src="/docs-cn/coolify/images/integrations/networking/cloudflare/tunnels/all-resource/2.webp" />

1. 选择 **Docker** 选项。
2. 复制 docker run 命令，其中包含你这条隧道的令牌（令牌以 "`eyJ`" 开头）。请只保存令牌本身（去掉前面的命令部分），并妥善保管，后面会用到。


## 2. 在 Coolify 上部署 cloudflared

在 Coolify dashboard 中进入你的项目，点击 `+ New` 按钮创建一个新资源。

<ZoomImage src="/docs-cn/coolify/images/integrations/networking/cloudflare/tunnels/all-resource/3.webp" />

搜索 `Cloudflared` 并点击它。

<ZoomImage src="/docs-cn/coolify/images/integrations/networking/cloudflare/tunnels/all-resource/4.webp" />

进入 **Environment Variables（环境变量）** 页面，填入你的隧道令牌，然后部署 Cloudflared 应用。

<ZoomImage src="/docs-cn/coolify/images/integrations/networking/cloudflare/tunnels/all-resource/5.webp" />

cloudflared 开始运行后，你就能在 Cloudflare dashboard 上看到它的状态

<ZoomImage src="/docs-cn/coolify/images/integrations/networking/cloudflare/tunnels/all-resource/6.webp" />

点击继续按钮完成隧道创建。


## 3. 启动 Coolify 代理

<ZoomImage src="/docs-cn/coolify/images/integrations/networking/cloudflare/tunnels/all-resource/7.webp" />

1. 在 Coolify dashboard 中，从侧边栏进入 **Servers（服务器）** 页面。
2. 选中你的应用所在的服务器，确认代理显示为运行中。


## 4. 配置隧道路由

<ZoomImage src="/docs-cn/coolify/images/integrations/networking/cloudflare/tunnels/all-resource/8.webp" />

1. 点击你的隧道。
2. 点击 **Configure（配置）** 选项。

<ZoomImage src="/docs-cn/coolify/images/integrations/networking/cloudflare/tunnels/all-resource/9.webp" />

1. 选择 **Routes（路由）**。
2. 点击 **Add route** 按钮。

<ZoomImage src="/docs-cn/coolify/images/integrations/networking/cloudflare/tunnels/all-resource/10.webp" />

3. 选择 **Published Application** 作为路由类型。

<ZoomImage src="/docs-cn/coolify/images/integrations/networking/cloudflare/tunnels/all-resource/11.webp" />

1. **Subdomain（子域名）** ——（可选）你可以让所有资源都能通过任意子域名/域名访问。本指南使用泛子域名 `*`。
2. **Domain（域名）** —— 选择你要用于隧道的域名。
3. **Path（路径）** —— 留空。
4. **Service URL** —— 填入 **http://localhost:80**（这一步非常关键）。如果 `localhost` 解析到了源站无法接受的 IPv6 地址，请改用 `http://127.0.0.1:80`。参见[环回连接疑难排查](/integrations/networking/cloudflare/tunnels/single-resource#realtime-或终端连接因-localhost-失败)。
6. 填写完信息后，点击 **Add route** 按钮。

<ZoomImage src="/docs-cn/coolify/images/integrations/networking/cloudflare/tunnels/all-resource/12.webp" />

<Callout type="success" title="提示">

 Coolify 代理（运行在 `http://localhost:80`）负责把流量路由到你服务器上运行的应用。这样就不必每部署一个新应用，都在 Cloudflare Tunnel 上新建一条路由。

</Callout>


## 5. 配置资源域名

在 Coolify 中为资源填入要使用的域名（以 HTTPS 形式，例如 `https://app.shadowarcanist.com`），然后部署资源。

</Tab>

<Tab value="应用">
<ZoomImage src="/docs-cn/coolify/images/integrations/networking/cloudflare/tunnels/all-resource/16.webp" />

</Tabs>

<Callout type="warn" title="禁用 Coolify 的 HTTPS 重定向">

在资源的 **Domains（域名）** 页面，把 **Redirect HTTP to HTTPS** 设为 **Disabled（已禁用）**。

这一步是必需的，因为隧道通过 `http://localhost:80` 连接 Coolify。Cloudflare 为访客提供 HTTPS，而 Coolify 从隧道收到的是 HTTP。如果保留重定向，会出现 **TOO_MANY_REDIRECTS** 错误。

如果是常规的 Cloudflare 橙云代理场景（Cloudflare 通过 **Full** 或 **Full (Strict)** SSL 以 HTTPS 连接 Coolify），则应保留重定向。

如果还想让 Cloudflare Tunnel 与 Coolify 之间也走 HTTPS，请参照 [Full TLS HTTPS 指南](/integrations/networking/cloudflare/tunnels/full-tls)，为隧道配置 HTTPS 形式的 Service URL。

</Callout>


**恭喜**！你已经成功部署了一个可以让互联网上任何人通过你的域名访问的资源。

## 如何使用多个不同的域名？

你不需要为每个域名新建隧道，只需用新域名创建一条新路由，并把它指向 `http://localhost:80` 即可。

## 已知问题与解决办法

当你在[步骤 4](/integrations/networking/cloudflare/tunnels/all-resource#4-配置隧道路由)中创建新路由时，Cloudflare 会为该主机名创建一条 DNS 记录。

但如果该主机名的 DNS 记录已经存在，Cloudflare 不会更新已有记录。

这种情况下你的应用将无法工作。要解决这个问题，请按以下步骤操作：

<ZoomImage src="/docs-cn/coolify/images/integrations/networking/cloudflare/tunnels/all-resource/8.webp" />

1. 点击你的隧道。
2. 点击 **Configure（配置）** 选项。

<ZoomImage src="/docs-cn/coolify/images/integrations/networking/cloudflare/tunnels/all-resource/18.webp" />

3. 在 Tunnels 详情区域复制你的隧道 ID。

<ZoomImage src="/docs-cn/coolify/images/integrations/networking/cloudflare/tunnels/all-resource/19.webp" />

按以下信息创建一条新的 DNS 记录：

1. 在 Cloudflare dashboard 中进入 **DNS**。
2. 选择 **Records（记录）**。
3. 添加一条 **CNAME** 记录。
4. 名称填 `*` 或你的子域名（应与隧道上应用的主机名一致）。
5. **Target（目标）** 填入隧道 ID，后跟 `.cfargotunnel.com`。
6. 把代理状态设为 **Proxied（已代理）**。

现在访问你应用的域名，应该就能正常访问了。
