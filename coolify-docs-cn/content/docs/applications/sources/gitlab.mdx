# GitLab

Coolify 可以通过公开 HTTPS URL、SSH 部署密钥或 GitLab App 部署 GitLab 仓库。

| 方式 | 适用场景 | 仓库访问 |
| :--- | :--- | :--- |
| 公开仓库 | 无需身份验证的公开源码 | HTTPS URL |
| 部署密钥 | 单个私有仓库，或无法使用 OAuth 应用的 GitLab 实例 | SSH URL 与仓库部署密钥 |
| GitLab App | GitLab.com 或自建 GitLab 实例上的私有仓库 | 带仓库浏览的 OAuth 应用 |

## 设置 GitLab App

<Callout type="warning" title="GitLab App 需要 Coolify v4.3.0">
  GitLab App 集成自 Coolify v4.3.0 起可用
</Callout>

GitLab App 让 Coolify 能列出仓库与分支、通过 HTTPS 克隆私有源码，并接收 push 与 merge request 事件。

<Steps>
<Step>

### 在 Coolify 中添加来源

打开 **Sources**（来源），选择 **New source**（新建来源）> **GitLab App**。

填写 **Name**（名称）；如需限制 Coolify 列出的仓库，可在 **Group name**（组名）中填入以逗号分隔的值（可选）。对于自建实例，展开 **Self-hosted GitLab** 并填写 **GitLab URL** 与 **API URL**。默认使用 GitLab.com。

在自托管 Coolify 实例上，只有希望所有团队都能选用该来源时才启用 **System wide**（全实例），否则保持来源仅对当前团队可用。

选择 **Continue**（继续）。Coolify 会显示 OAuth 应用所需的 redirect URI。

</Step>
<Step>

### 在 GitLab 中创建 OAuth 应用

在 GitLab 中打开 **User Settings > Applications**。如果不想把应用归属到单个用户名下，群组或实例管理员可以在群组或实例层级创建应用。

创建应用时配置：

- Coolify 显示的 redirect URI（原样填写）
- `api`、`read_user` 与 `read_repository` scope

保存应用，然后复制 **Application ID** 与 **Secret**。

</Step>
<Step>

### 连接 Coolify 与 GitLab

回到 Coolify 中的 GitLab 来源，填入 Application ID 与 Secret，核对 GitLab URL 与 API URL，然后保存凭据。

选择 **Connect to GitLab**（连接 GitLab）并授权该 OAuth 应用。GitLab 跳回 Coolify 后，使用 **Test Connection**（测试连接）验证。

</Step>
<Step>

### 配置仓库 webhook

从已连接的来源复制 webhook URL 与 secret token。

在每个需要自动部署的 GitLab 项目中，打开 **Settings > Webhooks**，添加该 URL 与配套的 secret token，然后启用：

- **Push events**（push 事件）用于分支部署
- **Merge request events**（merge request 事件）用于预览部署

secret token 缺失或不匹配时，Coolify 会拒绝 GitLab 的 webhook 请求。

</Step>
<Step>

### 部署仓库

打开一个 Coolify 项目，选择 **+ New**（新建），再选择 **Private Repository (with GitLab App)**（私有仓库（通过 GitLab App））。

选择服务器和已连接的 GitLab App，加载仓库列表，选定仓库与分支，然后配置并部署应用。

在部署日志中确认克隆的是所选仓库、检出的目标 commit。

</Step>
</Steps>

## 使用部署密钥

当 Coolify 只需要一个私有仓库，或无法通过 OAuth 连接 GitLab 实例时，请使用部署密钥。

1. 在 **Keys & Tokens**（密钥与令牌）> **Private Keys**（私钥）下添加一把私钥。
2. 把对应公钥添加到 GitLab 仓库的 **Settings > Repository > Deploy keys** 下。
3. 复制仓库 SSH URL，例如 `git@gitlab.com:example/application.git`。
4. 在 Coolify 中创建 **Private Repository (with deploy key)**（私有仓库（带部署密钥）），并选择已保存的密钥。

完整的配置与安全建议请阅读[部署密钥](/applications/sources/deploy-keys)。

## 配置手动 GitLab webhook

对于通过公开 URL 或部署密钥创建的应用：

1. 在 Coolify 应用中打开 **Webhooks**（Webhook）。
2. 复制 **GitLab** webhook URL，在 **GitLab** 区域填写 **Webhook secret**（Webhook 密钥），然后选择 **Save changes**（保存更改）。
3. 在 GitLab 中打开 **Settings > Webhooks**，填入相同的 URL 与密钥。
4. 启用 push 事件；如使用预览部署，再启用 merge request 事件。
5. 打开 **Advanced > Deployment**，在 Coolify 的 **Auto deploy**（自动部署）中选择 **Deploy on push (webhooks)**（推送时部署（webhook））。

先从 GitLab 测试 webhook，再向配置的分支推送代码，并查看 Coolify 中的 **Deployment Logs**（部署日志）。

## 使用 GitLab Container Registry

仓库凭据不能用于向 GitLab Container Registry 完成 Docker 身份验证。

对于私有镜像仓库，请创建一个带 `read_registry` 权限的 GitLab deploy token，并在每台拉取镜像的服务器上完成 Docker 登录：

```bash
echo "$GITLAB_REGISTRY_TOKEN" | \
  docker login registry.gitlab.com \
  --username "$GITLAB_REGISTRY_USER" \
  --password-stdin
```

在 Docker Image 或 Docker Compose 应用中使用完整的镜像引用（含标签）。服务器身份验证与构建服务器的要求请阅读 [Docker 镜像仓库](/applications/builds/docker-registries)。
