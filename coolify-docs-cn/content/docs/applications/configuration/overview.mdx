# 配置应用

打开一个应用，使用它的设置侧边栏来更改 Coolify 准备镜像、启动容器、暴露流量和运营工作负载的方式。

可用页面取决于应用类型和目标（Destination）。例如，**Git Source** 只在基于 Git 的应用中出现，**Swarm** 只在 Docker Swarm 目标上出现，而应用的 **Healthcheck** 页面不用于 Docker Compose。

<CoolCallout icon={Settings} title="简版结论">

构建、镜像和端口设置用 **General**（常规），公开路由用 **Domains**（域名）。其余配置页面分别对应环境变量、存储、来源认证、自动化、健康、限制和运维操作。

</CoolCallout>

## 应用配置更改

保存设置会更新已存储的配置，但不一定会立即替换正在运行的容器。

更改了影响容器的设置（包括环境变量、存储、健康检查、端口、网络和资源限制）之后，请部署或重启应用。构建配置的更改则需要一次会创建或复用镜像的部署。

可用的操作：

- **Deploy**（部署）：用于首次部署
- **Redeploy**（重新部署）：再次执行部署流程
- **Restart**（重启）：通过部署队列重建运行时；基于源码的方式在符合条件时复用现有镜像，Docker Image 则重新拉取已保存的镜像引用
- **Force deploy (without cache)**（强制部署，不使用缓存）：对 Coolify 生成的源码构建禁用缓存；自定义 Docker Compose 构建命令自行控制缓存标志

镜像准备与容器替换的区别，请阅读[构建与部署模型](/core/build-deployment-model)。
