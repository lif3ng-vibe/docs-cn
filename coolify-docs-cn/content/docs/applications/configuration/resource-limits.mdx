# 资源限制

打开一个应用，然后选择 **Resource Limits**（资源限制），限制其容器可用的 CPU 和内存。

**CPU limit**（CPU 限制）和内存限制字段用 `0` 表示未配置限制。其他字段有各自的默认值。请从应用的实际用量出发设置，而不要选最低可能值。

## CPU 限制

| 设置 | 可接受的取值 | 默认值 | 行为 |
| :--- | :--- | :--- | :--- |
| **CPU limit**（CPU 限制） | 整数或小数，例如 `2` 或 `0.5`。 | `0` | 设置 CPU 容量上限。`0` 表示容器可使用全部 CPU。 |
| **CPU set**（CPU 集合） | CPU 编号或区间，例如 `0-2` 或 `0,1,3`。 | 空 | 把容器限制在所选 CPU 核上。留空允许使用全部 CPU 核。 |
| **CPU weight**（CPU 权重） | `0` 或更大的整数。 | `1024` | 设置容器在竞争 CPU 时间时的相对优先级。 |

**CPU weight** 不预留 CPU 容量，它改变的是竞争时 Docker 分配可用 CPU 时间的方式。

## 内存限制

内存字段接受 `0` 或后跟 `b`、`k`、`m`、`g` 的整数，单位不区分大小写：

```plaintext
256m
1g
```

| 设置 | 可接受的取值 | 默认值 | 行为 |
| :--- | :--- | :--- | :--- |
| **Memory reservation**（内存预留） | 一个内存取值。 | `0` | 设置服务器内存吃紧时 Docker 参考的内存预留。 |
| **Swappiness**（换页倾向） | `0` 到 `100` 的整数。 | `60` | 控制容器匿名内存页被换出的难易程度。 |
| **Memory limit**（内存上限） | 一个内存取值。 | `0` | 设置容器的硬内存上限。 |
| **Memory and swap limit**（内存与 swap 上限） | 一个内存取值。 | `0` | 设置容器可用的内存与 swap 总量。 |

<Callout type="warning" title="过低的限制会让应用停摆">

硬内存上限低于应用的工作集时，Docker 可能因内存耗尽而终止进程。CPU 上限过低则可能让健康检查在负载下超时。

</Callout>

## 应用并验证

选择 **Save changes**（保存更改），然后重新部署或重启应用，让 Coolify 用新限制重建容器。

应用启动后：

1. 打开 **Metrics**（指标），确认 CPU 和内存用量保持在所配置的限制之下。
2. 打开 **Runtime Logs**（运行日志），检查是否有内存耗尽退出、反复重启或健康检查失败。
3. 向应用发送有代表性的流量，确认响应时间仍可接受。

启用和查看容器指标，请阅读[资源指标](/core/observability/monitoring/metrics)。
