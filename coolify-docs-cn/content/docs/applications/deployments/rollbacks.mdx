# 回滚

回滚会部署仍保留在服务器上的旧版应用镜像。它不会撤销数据库迁移、不会恢复持久化存储，也不会改动外部服务。

打开应用并选择 **Rollback**（回滚），即可查看 Coolify 仍可使用的镜像。

## 回滚之前

请确认：

- 想恢复的那个版本的镜像出现在 **Rollback** 列表中
- 当前的环境变量和运行时设置与该镜像兼容
- 数据库结构变更已做到向后兼容
- 如果该版本改动了持久化数据，需另行制定恢复方案

## 部署旧版镜像

1. 打开 **Rollback**。
2. 在 **Available images** 下找到上一个正常工作的部署；列表需要刷新时，选择 **Reload images**。
3. 选择 **Roll back to this image**。只有 commit 和 pull request 的镜像标签支持回滚，当前正在运行的镜像无法选择。
4. 打开 **Deployment Logs**（部署日志），跟踪这次新操作。
5. 核查应用域名、日志、健康检查和关键用户流程。

回滚会把当前的 Coolify 运行时配置套用到所选的旧镜像上。如果在该镜像构建之后有过变量或挂载改动，请先检查再执行。

## 镜像保留

能否回滚取决于镜像保留策略。在 **Image retention** 下设置 **Images to keep**，然后选择 **Save changes**（保存更改）。服务器级别的设置可以禁用镜像保留，并覆盖应用层面的取值。

被清理掉的镜像不会再出现在回滚目标中。镜像仓库里可能还留有另一份副本，但要恢复它，只能部署一个可用的镜像引用，而不是依赖本地已经缺失的回滚条目。

<Callout type="warning" title="状态数据需单独备份">

镜像回滚只改变应用代码和镜像内容。必须恢复的状态数据，请依靠持久化存储和数据库备份。

</Callout>
