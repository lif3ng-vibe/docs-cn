# API 权限

每个 API 令牌都属于创建它的用户和当前团队。其权限决定了它可以使用哪些端点，以及受支持的响应能否包含敏感值。

请选择集成所需的最小权限集。

## 权限级别

| 权限 | 允许的操作 | 重要限制 |
| :--- | :--- | :--- |
| `read` | 列出和查看资源。 | 敏感响应值仍会被脱敏。 |
| `read:sensitive` | 读取受支持端点返回的机密、日志、密码、私钥、环境变量值和 Compose 内容。 | Coolify 会同时附加 `read`。令牌所有者必须是团队管理员或所有者。 |
| `write` | 通过写入端点创建、更新和删除资源。 | 请求执行时，令牌所有者必须仍是团队管理员或所有者。 |
| `deploy` | 触发部署、重启、停止、取消和部署 webhook。 | 在仪表盘中勾选它会创建仅部署令牌。令牌所有者必须是团队管理员或所有者。 |
| `root` | 绕过 API 端点上的 `read`、`write` 和 `deploy` 检查。 | 仍然绑定团队，且不能绕过实例级 API 访问开关或 IP 白名单。令牌所有者必须是团队管理员或所有者。 |

在仪表盘中勾选 `root` 会移除其他权限，因为它们已无必要。但它不能访问属于其他团队的资源。

---

## 团队与角色范围

Coolify 在创建令牌时记录当前团队，之后切换团队不会改变已签发的令牌。

- 为集成需要访问的每个团队分别创建令牌。
- 将令牌所有者移出团队会使令牌失效。
- 执行特权操作的令牌，要求其所有者始终保持团队管理员或所有者身份。
- 实例级的 [API 访问与 IP 白名单控制](/api/ip-allowlist)对每个自托管令牌都生效，包括 `root`。

---

## 敏感响应数据

端点访问与敏感数据访问是两项独立的检查。带 `read` 的请求可能成功，但密码、私钥、环境变量值、日志或 Compose 内容仍会被脱敏。

只有当集成确实需要受支持的敏感字段时才添加 `read:sensitive`。令牌必须具备该权限，且其所有者必须是团队管理员或所有者。`root` 令牌也能收到受支持的敏感数据，但应保留给需要完整 API 访问能力的集成。

---

## 遵循最小权限

- 清点、监控和状态检查使用 `read`。
- 仅部署的 CI 或自动化工作流使用 `deploy`。
- 只有当集成必须修改资源配置时才使用 `write`。
- 只有当脱敏后的响应不够用时才添加 `read:sensitive`。
- 只有当集成必须跨权限级别调用端点，或管理实例级 API 功能时才使用 `root`。

令牌的创建、存放、轮换与撤销请遵循 [API 令牌](/core/security/credentials/api-tokens)。**Endpoints** 下的每个端点都标明了该操作所需的权限。

## 特定操作的检查

- 容器日志端点和计划任务输出需要 `read:sensitive` 或 `root`，而不是普通 `read`。
- 已保存的代理配置和服务器验证日志只有 `read:sensitive` 或 `root` 才能获取。
- 数据库导入的上传与启动需要 `write`；服务器路径导入还需要 `deploy`。
- 带 `instant_deploy` 创建资源时，除创建权限外还需要 `deploy`。
- 资源目录之外的 API 挂载需要 `deploy`。

系统只接受已识别的令牌权限。资源与凭据的归属按资源所属团队校验，即使用户在另一个浏览器标签页里切换了团队也一样。
