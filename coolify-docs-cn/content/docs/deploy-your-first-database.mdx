# 部署你的第一个数据库

在 Coolify 上部署第一个数据库，能在一个简单的流程中帮你验证数据库创建、凭据、端口映射和终端访问是否都正常。

在本指南中，你将从一键数据库资源列表部署 **Redis**。

一键数据库是一种独立运行的数据库资源，由 Coolify 从其 **New Resource > Databases** 列表创建。Coolify 会提供 Redis 镜像、生成的凭据、持久化存储、网络和连接信息，让你无需编写 Docker Compose 文件即可完成部署。

<CoolCallout icon={ArrowsRight} title="简要版">

创建或打开一个项目、创建一个 Redis 数据库资源、映射一个宿主机端口、部署 Redis、复制生成的密码，然后在终端里执行 `PING`。

这条路径非常适合首次数据库部署，因为 Redis 轻量又易于测试。

</CoolCallout>

## 部署你的第一个 Redis 数据库

选择你想使用的部署方式。每个标签页最终都会得到相同的首次部署结果。

<Tabs items={['Dashboard', 'API', 'CLI', 'MCP']}>
<Tab value="Dashboard">

<Steps>
<Step>

### 创建你的第一个项目

在 Coolify 控制台中：

- 点击 **New Project**
- 输入项目名，例如 `my-first-project`
- 点击 **Continue**

<Callout type="success" title="提示">

如果你已经有项目，跳过这一步，直接进入第 2 步。

</Callout>

</Step>
<Step>

### 创建新资源

打开你的项目，点击 **Create New Resource**。

资源是 Coolify 替你运行的东西，比如应用、数据库或服务。在本指南中，资源是一个 Redis 数据库。

</Step>
<Step>

### 从数据库列表中选择 Redis

在资源列表中：

- 搜索 **Redis**
- 点击 **Redis**

Coolify 会用生成的设置和凭据创建一个 Redis 数据库资源。

</Step>
<Step>

### 配置端口映射

设置一个临时端口映射，以便你能从终端连接。

示例：

```txt
6380:6379
```

</Step>
<Step>

### 在防火墙上放行映射的宿主机端口

端口映射把 Redis 发布到了服务器上，但你的防火墙或云服务商可能仍会拦截入站流量。

在管理 Redis 所在服务器防火墙规则的地方，放行映射的宿主机端口（例如 TCP `6380`）。不同服务商和服务器配置的做法各不相同，请检查你的服务商防火墙、安全组或服务器防火墙配置。

为了测试更安全，建议只对你的 IP 地址放行该端口，测试结束后再关闭。通用指引请参见[防火墙](/core/infrastructure/servers/firewall)。

<CoolCallout icon={ShieldAlert} title="不要随意暴露数据库" type="warn">

在生产环境中，把数据库端口公网暴露是有风险的做法。本指南映射 Redis 端口，只是为了让你能在终端里测试这次首次部署。

对真正的生产工作负载而言，除非有明确理由并配好严格的网络管控，否则请保持数据库私有。

</CoolCallout>

</Step>
<Step>

### 启动 Redis

点击 **Start**。

部署完成后，准备好以下信息：

- 服务器 IP 地址
- 映射的宿主机端口，例如 `6380`
- 来自 Coolify 控制台的 Redis 密码

</Step>
<Step>

### 从终端连接 Redis

在终端中使用 `redis-cli`：

```sh
redis-cli --user default -h <server-ip> -p <host-port> -a "<redis-password>"
```

示例：

```sh
redis-cli --user default -h 203.0.113.10 -p 6380 -a "your-password"
```

然后执行：

```sh
PING
```

如果一切正常，Redis 会返回：

```txt
PONG
```

<Callout type="info" title="没有安装 redis-cli？">

改用一个临时 Redis 容器来运行 `redis-cli`：

```sh
docker run --rm -it redis:alpine redis-cli --user default -h <server-ip> -p <host-port> -a "<redis-password>" PING
```

连接正常时会返回 `PONG`。

</Callout>

</Step>
</Steps>

<Tab value="API">

<Callout type="info" title="API 前提条件">

为本教程创建一个 `root` API 令牌。Coolify Cloud 已默认启用 API 访问，Cloud 用户只需创建令牌即可。在自托管 Coolify 上，还需要管理员[启用 API 访问](/api/ip-allowlist#api-访问控制)。发送这些请求之前，请先阅读 [API 授权](/api/authorization)。

在即将运行 cURL 的终端里设置你的基础 URL 和令牌：

```sh
export COOLIFY_URL="https://<your-coolify-domain>"
export COOLIFY_TOKEN="<api-token>"
```

Coolify Cloud 用户应把 `COOLIFY_URL` 设为 `https://app.coolify.io`。

</Callout>

<Callout type="warning" title="生产环境请使用最小权限令牌">

本教程使用 `root` 令牌，这样同一个凭据可以在所有读取、写入、部署和敏感数据请求中通用。`root` 令牌的权限远超大多数集成所需。生产环境中，请为每个工作流单独创建只具备所需权限的令牌，并在教程结束后吊销本教程令牌。

</Callout>

<Steps>
<Step>

### 创建项目并找到服务器

创建项目，然后复制其 UUID：

```sh
curl --fail-with-body --request POST \
  --header "Authorization: Bearer $COOLIFY_TOKEN" \
  --header "Accept: application/json" \
  --header "Content-Type: application/json" \
  --data '{"name":"my-first-project"}' \
  "$COOLIFY_URL/api/v1/projects"

export PROJECT_UUID="<project-uuid>"
```

列出服务器，复制目标服务器的 UUID 并设置：

```sh
curl --fail-with-body \
  --header "Authorization: Bearer $COOLIFY_TOKEN" \
  --header "Accept: application/json" \
  "$COOLIFY_URL/api/v1/servers"

export SERVER_UUID="<server-uuid>"
```

如果项目已存在，改用 `GET /api/v1/projects`。

</Step>
<Step>

### 创建并启动 Redis

下面的请求会把 Redis 发布到服务器端口 `6380`，在省略 `redis_password` 时自动生成密码，并立即启动：

```sh
curl --fail-with-body --request POST \
  --header "Authorization: Bearer $COOLIFY_TOKEN" \
  --header "Accept: application/json" \
  --header "Content-Type: application/json" \
  --data "{"project_uuid":"$PROJECT_UUID","server_uuid":"$SERVER_UUID","environment_name":"production","name":"my-first-redis","is_public":true,"public_port":6380,"instant_deploy":true}" \
  "$COOLIFY_URL/api/v1/databases/redis"
```

从响应中复制数据库 UUID：

```sh
export DATABASE_UUID="<database-uuid>"
```

测试之前，先在服务器防火墙中仅对你的 IP 地址放行 TCP 端口 `6380`。不要对全部来源开放该端口。

</Step>
<Step>

### 读取密码并测试 Redis

本教程使用的 `root` 令牌允许 API 响应中包含密码：

```sh
curl --fail-with-body \
  --header "Authorization: Bearer $COOLIFY_TOKEN" \
  --header "Accept: application/json" \
  "$COOLIFY_URL/api/v1/databases/$DATABASE_UUID"
```

复制 Redis 密码，然后按 Dashboard 标签页中的方法执行同样的 `redis-cli` 测试。收到 `PONG` 响应即说明 Redis 可达。

</Step>
</Steps>

验证成功会提示连接与认证均有效。令牌安全、IP 白名单与故障排查请参见 [CLI 认证](/cli/authentication)。

</Callout>

### 创建项目并找到服务器

从响应中复制数据库 UUID。测试之前，先在服务器防火墙中仅对你的 IP 地址放行 TCP 端口 `6380`。

</Step>

### 读取连接信息并测试 Redis

```sh
coolify database get <database-uuid>
```

复制生成的密码，然后测试连接：

```sh

```

收到 `PONG` 响应即证明部署成功。其他数据库类型和选项请参见 [`coolify database create`](/cli/command-reference/commands/database/create)。

</Callout>

## 首次部署的常见问题

当 Redis 部署成功、但终端测试表现不符合预期时，按下面各项排查。

<Tabs id="first-database-issues" items={['Connection refused', 'Auth failed', 'redis-cli missing']}>
<Tab value="Connection refused" icon={Plug2}>

通常意味着 Redis 在你使用的宿主机端口上不可达。

检查：

- Redis 部署处于 **running** 状态
- **Ports Mappings** 中使用的正是你连接的宿主机端口
- 服务器防火墙放行了该映射的宿主机端口
- 你用的是服务器 IP 地址，而不是 Redis 容器的 IP

</Tab>
<Tab value="Auth failed" icon={Key2}>

通常意味着命令中的密码与 Coolify 里的 Redis 密码不一致。

检查：

- 从 Coolify 控制台重新复制 Redis 密码
- 密码含特殊字符时用引号包起来
- 去掉密码前后误输入的空格

</Tab>
<Tab value="redis-cli missing" icon={BrowserTerminal}>

如果你的电脑上没有 `redis-cli`，可以用 Docker 临时运行一个。

```sh
docker run --rm -it redis:alpine redis-cli --user default -h <server-ip> -p <host-port> -a "<redis-password>" PING
```

如果连 Docker 也没装，就在本地安装 Redis CLI，或者换一台有它的机器测试。

</Tab>
</Tabs>
