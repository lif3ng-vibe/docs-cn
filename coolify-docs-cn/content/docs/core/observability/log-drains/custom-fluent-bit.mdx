# 配置自定义 Fluent Bit 日志转发

当内置的 Axiom 和 New Relic 目标（Destination）无法满足你的日志服务商时，请使用**自定义 Fluent Bit（Custom Fluent Bit）**。Coolify 会按你提供的原样运行配置，因此你必须自行定义日志服务商所需的输入、过滤器、解析、输出、身份验证与目标行为。

<CoolCallout icon={ArrowsRight} title="简要版本">

提供一份完整的 Fluent Bit 2.0 配置，让它在端口 `24224` 上接受 `forward` 协议，并把记录发送到你的目标。Coolify 负责写入配置、启动 `coolify-log-drain`，并把已开启转发的资源容器接入其中。

</CoolCallout>

<CoolCallout type="warning" icon={Warning22} title="Coolify 不校验 Fluent Bit 语法">

Coolify 只检查 **Fluent Bit 配置**是否为空。一条无效的指令、一个不可用的插件或被拒绝的凭据，都可能让 `coolify-log-drain` 停止运行或无法投递日志。

</CoolCallout>

默认情况下，Coolify 会在资源服务器上写入这些文件：

| 文件 | 用途 |
| :--- | :--- |
| `/data/coolify/log-drains/fluent-bit.conf` | **Fluent Bit 配置**中的完整内容 |
| `/data/coolify/log-drains/parsers.conf` | **解析器配置**中的可选内容 |
| `/data/coolify/log-drains/docker-compose.yml` | Coolify 托管的 Fluent Bit 服务 |

容器会把这两个配置文件挂载到 `/fluent-bit.conf` 和 `/parsers.conf`。

## 编写主配置

下面这个骨架展示了必需的输入部分和一个 HTTPS 输出示例。请把主机、URI、身份验证与输出选项替换为你的日志服务商支持的值：

```ini
[SERVICE]
  Flush        5
  Daemon       off
  Log_Level    info
  Parsers_File parsers.conf

[INPUT]
  Name              forward
  Listen            0.0.0.0
  Port              24224
  Buffer_Chunk_Size 1M
  Buffer_Max_Size   6M

[OUTPUT]
  Name   http
  Match  *
  Host   logs.example.com
  Port   443
  URI    /ingest
  format json
  tls    On
```

该示例并非针对特定服务商的完整配置。启用转发之前，请补充服务商要求的请求头、令牌、负载、重试与 TLS 选项。

只能使用 Coolify 所用 Fluent Bit 2.0 镜像中自带的输入、过滤器、解析器和输出插件。

## 添加解析器定义

**解析器配置**是可选的。它会写入 `parsers.conf`，但添加解析器定义并不会自动生效，主配置必须显式引用该解析器。

例如，把下面的解析器定义添加到**解析器配置**：

```ini
[PARSER]
  Name   app_json
  Format json
```

然后在 **Fluent Bit 配置**中添加一个 parser 过滤器：

```ini
[FILTER]
  Name         parser
  Match        *
  Key_Name     log
  Parser       app_json
  Reserve_Data On
```

这个示例会解析存放在传入 `log` 字段中的 JSON，并保留记录的其他字段。

## 配置 Coolify

1. 打开**服务器（Servers）**，选择运行这些资源的服务器。
2. 打开**日志转发（Log Drains）**。
3. 在**自定义 Fluent Bit** 区块中，保持**状态（Status）**为**禁用（Disabled）**。
4. 把完整的主配置粘贴到 **Fluent Bit 配置**中。
5. 如有需要，把解析器定义粘贴到**解析器配置**中。
6. 在自定义区块中选择**保存更改（Save changes）**。
7. 把**状态**设为**启用（Enabled）**。Coolify 会写入文件并启动 `coolify-log-drain`。

## 验证送达

1. 让已开启转发的资源向 `stdout` 或 `stderr` 写入一条可识别的消息。
2. 等待配置中的 **Flush** 间隔。
3. 确认消息出现在外部目标中。
4. 确认 Fluent Bit 容器仍在运行：

```sh
docker ps --filter name=coolify-log-drain
docker logs --tail 100 coolify-log-drain
```

在 Coolify 的服务器终端中，或通过 SSH 在托管资源的服务器上运行这些命令。

---

## 更新配置

转发处于启用状态时，配置字段是只读的。

1. 把**状态**设为**禁用**，停止 `coolify-log-drain`。
2. 更新主配置或解析器配置。
3. 选择**保存更改**。
4. 再次把**状态**设为**启用**。
5. 生成一条新的资源日志，并在外部验证结果。

---

## 排查自定义转发失败

- 确认主配置中有监听端口 `24224` 的 `forward` 输入。
- 阅读 `docker logs --tail 100 coolify-log-drain` 的输出，排查语法、插件、DNS、TLS 与身份验证错误。
- 确认主配置引用的每个解析器都存在于**解析器配置**中。
- 确认所用的插件和选项在 Fluent Bit 2.0 中可用。
- 确认资源的**日志转发（Log drain）**设置已启用，且之后重启过该资源。
- 确认资源服务器能够访问所配置的输出主机和端口。
