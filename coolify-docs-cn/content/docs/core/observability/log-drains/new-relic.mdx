# 把日志发送到 New Relic

Coolify 内置的 New Relic 日志转发会把已开启转发的资源日志发送到 New Relic Log API。

<CoolCallout icon={ArrowsRight} title="简要版本">

复制一个采集许可密钥（ingest license key），选择你的 New Relic 区域对应的 Log API 端点，把这两个值保存到服务器的**日志转发（Log Drains）**页面，然后按照[为资源启用日志转发](/core/observability/log-drains/overview#为资源启用日志转发)中的说明配置**日志转发（Log drain）**，并重启每一个需要转发的资源。

</CoolCallout>

Coolify 只检查必填字段的格式并启动 Fluent Bit。它不会验证许可密钥，也不会向 New Relic 端点发送测试事件。

## 为资源启用

按照[为资源启用日志转发](/core/observability/log-drains/overview#为资源启用日志转发)操作，然后重启或重新部署该资源。

内置的 New Relic 配置每五秒刷新一次记录。

---

例如，给资源添加这个环境变量：

```dotenv
COOLIFY_APP_NAME=worker
```

内置过滤器会排除消息中包含 `127.0.0.1` 的日志记录，因此本地健康检查请求可能不会出现在 New Relic 中。

## 验证送达

1. 让资源向 `stdout` 或 `stderr` 写入一条可识别的消息。
2. 等待至少五秒。
3. 打开 New Relic Logs，在近期事件中搜索该消息、`coolify.server_name` 或 `coolify.app_name`。

必须在 New Relic 中进行验证，因为 Coolify 不会执行服务商连接测试。

---

## 更新端点或许可密钥

1. 在 New Relic 区块中把**状态**设为**禁用**。
2. 更新 **License key** 或 **Endpoint**。
3. 选择**保存更改**。
4. 再次把**状态**设为**启用**。
5. 生成一条新的资源日志，确认它已到达 New Relic。

---

## 排查日志缺失

1. 确认 New Relic 是已启用的服务器级转发，且资源的**日志转发（Log drain）**设置已打开。
2. 确认你在启用该设置之后重启或重新部署过资源。
3. 确认密钥是与端点同一 New Relic 账户、同一区域的 ingest license key。
4. 确认服务器能在 `443` 端口访问所选端点。
5. 检查资源服务器上的 Fluent Bit 容器：

```sh
docker ps --filter name=coolify-log-drain
docker logs --tail 100 coolify-log-drain
```

身份验证、端点和网络错误都会出现在 Fluent Bit 的输出中。
