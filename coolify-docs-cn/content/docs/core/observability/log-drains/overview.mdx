# 日志转发概览

Coolify 的日志转发（log drain）会把工作负载容器的输出转发到外部日志目标（Destination）。在服务器上配置一个目标，再为需要纳入的资源开启日志转发即可。

<CoolCallout icon={ArrowsRight} title="简要版本">

在服务器上启用 Axiom、New Relic 或自定义 Fluent Bit 配置。然后为每个应用、数据库或服务组件打开**日志转发（Log drain）**，并重启或重新部署它。

</CoolCallout>

---

## 日志转发包含哪些内容

Coolify 会在服务器上启动 `coolify-log-drain`。已开启转发的资源容器把各自的 `stdout` 和 `stderr` 发送到这个本地 Fluent Bit 容器，由它把记录转发到你的目标。

## 配置服务器

1. 打开**服务器（Servers）**，选择运行这些资源的已验证服务器。
2. 打开**日志转发（Log Drains）**。
3. 在**状态（Status）**为**禁用（Disabled）**时，输入并保存其中一个目标的设置。
4. 把**状态**设为**启用（Enabled）**，启动 `coolify-log-drain`。

<CoolCallout type="info" title="在日志服务商处验证送达">

Coolify 只检查必填字段的格式，不会验证服务商身份验证，也不会发送测试事件。

</CoolCallout>

---

## 为资源启用日志转发

必须先启用服务器级转发，否则 Coolify 会再次关闭资源的**日志转发（Log drain）**设置。

<CoolCallout type="warning" icon={Warning22} title="更改 Drain Logs 后请重启资源">

Coolify 在创建资源容器时应用 Docker 日志驱动。开启或关闭**日志转发**之后，请重启或重新部署该资源。

</CoolCallout>

## 验证送达

1. 让资源向 `stdout` 或 `stderr` 写入一条可识别的消息。
2. 打开日志服务商控制台，在近期事件中搜索这条消息。
3. 如果找不到事件，检查资源服务器上的日志转发容器：

```sh
docker ps --filter name=coolify-log-drain
docker logs --tail 100 coolify-log-drain
```

内置的 Axiom 和 New Relic 目标每五秒刷新一次。自定义配置则使用自己的 **Flush** 值。

---

## 局限

- 一台服务器同一时间只能使用一个 Coolify 托管的日志转发。
- 保留策略、查询、仪表盘和基于日志的告警由外部服务商管理。
- 禁用服务器级转发会停止投递，但不会清除资源上已保存的**日志转发**设置。
