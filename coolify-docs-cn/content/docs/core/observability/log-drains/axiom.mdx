# 将日志发送到 Axiom

Coolify 内置的 Axiom 日志转发（log drain）通过 HTTPS 把已启用转发的资源日志发送到现有 Axiom 数据集。

<CoolCallout icon={ArrowsRight} title="简要说明">

创建一个 Axiom 数据集和具备摄入权限的 API 令牌，把两个值保存到服务器的 **Log Drains** 页面并启用 Axiom 转发，然后按[为资源启用日志转发](/core/observability/log-drains/overview#为资源启用日志转发)的说明配置 **Log drain**，并重启需要转发的每个资源。

</CoolCallout>

在 [Axiom](https://axiom.co/docs) 中创建数据集和令牌，然后复制它们的精确值，再打开 Coolify。Coolify 的两个 Axiom 字段都接受字母、数字、下划线、连字符和句点。

内置集成将数据发送到 443 端口的 `api.axiom.co`。该端点无法在 Coolify 的 Axiom 区块中修改。

<CoolCallout type="info" title="启用转发不等于摄入测试">

Coolify 只检查两个字段已填写且字符合法，并不会在显示已启用状态之前验证令牌、数据集权限或 Axiom 摄入是否正常。

</CoolCallout>

## 为资源启用

按[为资源启用日志转发](/core/observability/log-drains/overview#为资源启用日志转发)操作，然后重启或重新部署该资源。

Axiom 配置以 gzip 压缩的 JSON 发送日志，把事件时间以 ISO 8601 格式写入 `_time`，并每五秒刷新一次。

例如，为资源添加以下环境变量：

```dotenv
COOLIFY_APP_NAME=web
```

内置过滤器会排除消息中包含 `127.0.0.1` 的日志记录。因此本地健康检查请求可能不会出现在数据集中。

## 验证投递

1. 让资源向 `stdout` 或 `stderr` 写入一条可辨认的消息。
2. 等待至少五秒。
3. 打开 Axiom 数据集，在近期事件中搜索该消息、`coolify.server_name` 或 `coolify.app_name`。

必须在 Axiom 中完成验证，因为 Coolify 不会执行服务商连接测试。

---

## 更新数据集或令牌

1. 在 Axiom 区块将 **Status** 设为 **Disabled**。
2. 更新 **API key** 或 **Dataset name**。
3. 选择 **Save changes**。
4. 重新将 **Status** 设为 **Enabled**。
5. 生成一条新的资源日志，确认它到达了预期的数据集。

---

## 修复日志缺失

1. 确认 Axiom 是已启用的服务器转发目的地，且资源的 **Log drain** 设置已开启。
2. 确认你在开启设置后重启或重新部署了资源。
3. 确认令牌能够向 Coolify 中填写的精确数据集名称摄入数据。
4. 确认服务器能访问 `api.axiom.co:443`。
5. 检查资源服务器上的 Fluent Bit 容器：

```sh
docker ps --filter name=coolify-log-drain
docker logs --tail 100 coolify-log-drain
```

认证、数据集和网络错误都会出现在 Fluent Bit 的输出中。
