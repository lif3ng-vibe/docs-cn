# 多服务器部署

Coolify 可以把同一个应用部署到一台主服务器和一台或多台额外的独立服务器上，让每台服务器都运行一份自己的应用实例。

添加部署服务器本身并不会分发流量。应用在每台服务器上运行起来之后，需要在它们前面配置[云端负载均衡](/core/infrastructure/scaling/cloud-load-balancing)或其他外部流量层。

<Callout type="warning" title="当前的应用限制">
应用的 **Servers** 页面不支持 Docker Compose 应用。当应用配置了持久化存储时，Coolify 也不允许再添加服务器。
</Callout>

## 开始之前

在关联新的部署目标之前，先准备好应用和服务器。

- 在 Coolify 中添加并验证每台服务器。新服务器请按照[添加服务器](/core/infrastructure/servers/add-server)操作。
- 使用相同 CPU 架构的服务器（如 AMD64 或 ARM64），确保每台服务器都能运行同一镜像。
- 所有带代理的服务器都使用同一种[代理](/core/networking/proxy/overview)类型（Traefik 或 Caddy）。Coolify 会为主服务器生成代理标签并在每台服务器上复用，因此 Traefik 标签在 Caddy 服务器上无法工作，反之亦然。没有代理的服务器仍然可以关联。
- 把应用状态放在容器之外。数据库、会话、队列、缓存和上传文件请使用共享或外部服务。
- 创建一个主服务器、构建服务器和所有额外服务器都能访问的 Docker 镜像仓库。
- 在每台需要推送或拉取镜像的服务器上，用 Coolify 中配置的 SSH 用户向该镜像仓库完成认证。参见 [Docker 镜像仓库](/applications/builds/docker-registries#认证私有镜像仓库)。

## 配置应用镜像

1. 在 Coolify 中打开该应用。
2. 选择 **General**（通用）。
3. 在 **Container image**（容器镜像）下，把完整的镜像仓库地址填入 **Image**。例如：

   ```text
   ghcr.io/example/acme-web
   ```

4. 保存应用设置。

必须先填写 **Image**，Coolify 才能把应用部署到额外服务器。部署时，主服务器或所配置的构建服务器会构建镜像并推送到镜像仓库，然后额外服务器拉取同一镜像。

## 添加部署服务器

1. 打开该应用。
2. 在其侧边栏选择 **Servers**（服务器）。
3. 在 **Add another server**（添加其他服务器）下，选择要关联的服务器和网络。
4. 对其余每台服务器重复此选择。

最初为应用选择的服务器仍是 **Primary Server**（主服务器）。每台关联的服务器会出现在 **Additional Server(s)**（额外服务器）下。

如果没有可关联的服务器，请确认候选服务器已通过验证、可用、属于同一团队，并且拥有独立的 Docker 目标（Destination）。已关联到该应用的服务器不会再次显示。

Coolify 会拒绝代理类型与主服务器不同的服务器。如果应用已经关联了这样的服务器，每次部署日志都会显示警告，且应用域名无法通过该服务器上的代理访问。请把该服务器上的代理类型改成与主服务器一致，然后重新部署。

## 部署并验证

关联完所有需要的服务器后再部署应用。

1. 在应用页面选择 **Deploy**（部署）。
2. 关注部署日志，确认 Coolify 把构建好的镜像推送到所配置的镜像仓库，并为每台关联的服务器启动部署。
3. 打开 **Servers**，确认主服务器和额外服务器都显示运行状态。
4. 把服务器加入负载均衡器之前，先通过计划使用的接入路径测试每台服务器。

如果某台额外服务器拉取不到镜像，请在该服务器的 **Registries**（镜像仓库）页面完成登录，然后重新部署。额外服务器会拉取主服务器发布的镜像而不是自己构建；提交、回滚和镜像标签都与主部署保持一致。所有服务器完成后，Coolify 只发送一次部署通知。

## 管理部署服务器

**Servers** 页面为每台关联的服务器提供以下操作：

- **Deploy**（部署）：只把应用部署到该服务器。
- **Stop**（停止）：停掉该服务器上的应用。
- **Promote to Primary**（提升为主服务器）：把某台额外服务器设为主部署目标，原主服务器变为额外服务器。
- **Remove from server**（从服务器移除）：确认服务器名称后，停掉该服务器上的应用并移除部署目标。

应用级别的常规部署、重启和停止操作会同时作用于主服务器和额外服务器。停止操作会尝试每一台服务器，即使其中某台不可达。将多服务器与持久化存储或 Compose 组合的既有配置会在部署日志中收到警告。拉取请求（PR）预览不会部署到额外目标。

## 多服务器部署不包含的内容

关联服务器能让你获得多个应用实例，但并不构成完整的高可用系统。你仍需自行配置：

- 带健康检查的负载均衡器
- 公网域名的 DNS
- 应用服务器的防火墙或安全组规则
- 共享的数据与会话存储
- 应用和每台服务器的监控
