# 扩展概览

扩展应用可以指给单台服务器增加容量、把应用跑到多台服务器上，或在多台服务器之间分发流量。

Coolify 可以把同一个应用镜像部署到多台已连接的服务器，再由云端负载均衡器把请求导向健康的应用实例。Coolify 不会替你创建或管理这个外部负载均衡器。

<Callout type="info" title="从满足需求的最小配置开始">
当负载、可用性要求或实测瓶颈确实需要时再增加基础设施。一台规格合适的单服务器比多服务器部署更容易运维。
</Callout>

## 选择扩展路径

| 需求 | 方案 | 从这里开始 |
| :--- | :--- | :--- |
| 当前工作负载需要更多 CPU、内存或存储 | 调整当前服务器规格，或把资源迁移到更大的服务器 | [服务器概览](/core/infrastructure/servers/overview) |
| 在多台独立服务器上运行同一个应用 | 为应用关联额外的部署服务器 | [多服务器部署](/core/infrastructure/scaling/multi-server-deployments) |
| 分发公网流量并把不健康的服务器移出轮换 | 在应用服务器前面放置提供商管理的负载均衡器 | [云端负载均衡](/core/infrastructure/scaling/cloud-load-balancing) |
| 在 Coolify v4 上维护现有 Docker Swarm 部署 | 仅作为临时遗留方案继续使用 | [Docker Swarm（已弃用）](/core/infrastructure/scaling/docker-swarm) |

多服务器部署和负载均衡解决的是同一架构中的不同问题。Coolify 把一致的应用镜像部署到每台关联的服务器，负载均衡器则决定每个进入的请求由哪台服务器处理。

## Coolify 负责的部分

对于受支持的多服务器应用，Coolify 会：

- 保留一台服务器作为主部署服务器
- 在主服务器或所配置的构建服务器上构建应用
- 把构建好的镜像推送到为应用配置的 Docker 镜像仓库
- 把该镜像部署到关联的额外服务器
- 允许你在应用的 **Servers** 页面对单台服务器执行部署、停止、移除或提升操作

仍需你自己负责的有：

- 配置外部负载均衡器及其健康检查
- 保障负载均衡器与应用服务器之间的流量安全
- 让会话、上传文件和其他应用状态对所有实例可用
- 运维共享的数据库、缓存、队列和文件存储
- 监控容量并决定何时增减服务器

## 准备应用

当任意应用实例都能处理任意请求时，水平扩展效果最好。添加服务器之前：

1. 把会话状态、用户上传、队列和缓存移出容器文件系统。
2. 使用所有应用服务器都能访问的数据库和存储位置。
3. 添加一个健康检查端点，只在实例能接收流量时才返回成功响应。
4. 确认应用能在每台服务器上用相同的镜像和配置运行。
5. 决定 TLS 在哪里终结，以及负载均衡器如何访问每台服务器。

在 Coolify 中配置了持久化存储的应用无法使用当前的多服务器部署功能；Docker Compose 应用也无法通过应用的 **Servers** 页面关联额外的部署服务器。
