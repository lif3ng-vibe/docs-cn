# Coolify 的工作原理

Coolify 把平台控制与工作负载运行分离开来。Coolify 实例存储配置并协调操作,而每台已连接服务器上的 Docker 负责运行你的应用、数据库和服务。

这种分离决定了部署在哪里运行、流量如何到达资源、每次备份包含什么,以及故障期间会发生什么。

<CoolCallout icon={ArrowsRight} title="简要版">

你在 Coolify 仪表盘或 API 中配置资源。Coolify 实例通过 SSH 连接到选定的服务器,然后运行构建、部署和管理该资源所需的 Docker 操作。

对于 HTTP 资源,请求会先到达运行该资源的服务器上的反向代理,再到达它的容器。Coolify 服务器不会中转你的应用流量。

</CoolCallout>

你可以自己运行 Coolify 服务器,也可以使用 Coolify Cloud。自托管 Coolify 时,由你维护 Coolify 服务器;使用 Coolify Cloud 时,由 Coolify 团队维护。无论哪种方式,你的应用、数据库和服务都运行在你自己提供的服务器上。

Coolify 不要求在已连接的服务器上驻留常驻部署代理。它使用 SSH 执行部署和服务器操作。可选的 `coolify-sentinel` 容器提供监控数据,但并不取代 SSH。

### 自托管 Coolify 实例的内部

标准的自托管安装会运行三个基础容器。

| <span className="inline-block min-w-40">容器</span> | 作用 |
| :--- | :--- |
| `coolify` | 提供 Coolify 仪表盘和 API,用 Laravel Horizon 处理排队任务,运行计划任务,通过 Laravel Reverb 提供实时更新,并运行浏览器终端服务器。 |
| `coolify-db` | 运行 PostgreSQL,存储 Coolify 的配置和状态。 |
| `coolify-redis` | 支持排队任务和缓存。 |

`coolify-proxy` 和 `coolify-sentinel` 容器属于服务器运行时,而不属于这组基础控制平面栈。Coolify 会在启用了反向代理的每台服务器上启动一个反向代理,而 Sentinel 始终是可选的。

## 请求如何到达资源

当 HTTP 资源配置了域名并使用反向代理时,请求会按以下顺序流转:

1. DNS 或上游网络层把域名指向已连接的服务器。
2. 该服务器上的反向代理在端口 `80` 或 `443` 接收请求,并在已配置的情况下处理 TLS。
3. 反向代理匹配主机名和路径,然后通过已附加的 Docker 网络把请求转发给资源容器。
4. 容器处理请求并返回响应。

Coolify 服务器不会中转这些请求。即使 Coolify 和资源运行在同一台机器上,反向代理仍会把每个请求直接发送到资源容器。

如果你为某台服务器禁用了 Coolify 管理的反向代理,就必须自行提供外部路由和 TLS 路径。非 HTTP 资源可以通过 Docker 网络或显式发布的端口通信,而不必走这条反向代理路径。

Docker 网络、反向代理选项、域名以及你的防火墙职责,参阅[Coolify 中的网络](/core/networking-in-coolify)。

## 配置与数据存放在哪里

Coolify 配置和工作负载数据并非全都存放在一处。

| 层级 | 位置 | 内容 |
| :--- | :--- | :--- |
| Coolify 配置 | Coolify 实例 | 控制平面使用的项目、环境、服务器与资源设置、凭据以及平台状态。 |
| 部署与运行时文件 | 已连接服务器或构建服务器 | 为该服务器的工作生成的部署文件、构建产物、Docker 镜像、容器和网络。 |
| 资源数据 | 已连接服务器或外部存储 | 应用、数据库和服务使用的 Docker 卷、绑定挂载和外部存储。 |
| 反向代理状态 | 启用了反向代理的已连接服务器 | 用于在该服务器上路由流量的反向代理配置与证书数据。 |

[实例备份](/core/backup-and-recovery/instance-backup)包含控制平面所用 Coolify 数据库的副本。已连接服务器上的应用文件、数据库数据、卷和外部存储不属于实例备份。

## 当 Coolify 实例不可用时

已在运行的资源依靠 Docker 和现有反向代理配置工作。它们不需要 Coolify 服务器来处理每一个请求。

  ]}

失去 SSH 访问也有类似的边界:Coolify 无法操作该服务器,但 SSH 故障本身并不会让已有容器停止。如果已连接的服务器、Docker 守护进程、反向代理或上游网络发生故障,这条路径上的资源可能不可用,即使 Coolify 实例本身仍然健康。

标准 Docker 资源降低了平台锁定,因为你可以直接检查和操作它们。但 Coolify 实例仍然保存着让它们作为 Coolify 资源可被管理的配置与自动化。请为 Coolify 数据库和工作负载数据分别保留备份。
