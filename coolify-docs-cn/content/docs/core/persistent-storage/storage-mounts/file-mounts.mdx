# 文件挂载（file mount）

文件挂载把部署服务器上的一个文件放置到容器内的精确路径。Coolify 在 **Persistent Storage** 下提供两种文件工作流：

| 工作流 | 源文件 | Coolify 管理的范围 |
| :--- | :--- | :--- |
| **File Mount** | Coolify 在资源的配置目录下创建该文件 | 源文件、其内容以及挂载配置 |
| **Host File Mount** | 由你在服务器的绝对路径上创建并维护既有文件 | 仅挂载配置 |

文件挂载适用于单个配置文件、初始化脚本、策略文件或映射文件。目录请使用[绑定挂载（bind mount）](/core/persistent-storage/storage-mounts/bind-mounts)，数据库文件、上传内容和其他不断变化的应用数据请放在[卷挂载（volume mount）](/core/persistent-storage/storage-mounts/volume-mounts)中。

不要把仪表盘编辑器当作版本控制或机密管理器的替代品。任何有权限管理该资源的人都可能查看或修改托管 File Mount 的内容。

## 添加托管文件挂载

1. 在 Coolify 中打开该应用或独立数据库。
2. 选择 **Configuration** > **Persistent Storage**。
3. 选择 **Add** > **File Mount**。
4. 填写容器内的精确 **Destination Path**，例如 `/etc/example/app.conf`。
5. 查看显示的 **Host file path**。这是 Coolify 将在部署服务器上创建源文件的位置。
6. 填写文件 **Content**。
7. 选择 **Add**，然后重新部署该资源。

Coolify 会在部署服务器上资源专属的目录下创建源文件：

- 应用：`/data/coolify/applications/<resource-uuid>/<destination-path>`
- 独立数据库：`/data/coolify/databases/<resource-uuid>/<destination-path>`

例如，应用的目标路径 `/etc/example/app.conf` 会存储在部署服务器的 `/data/coolify/applications/<resource-uuid>/etc/example/app.conf`。

重新部署后，请验证文件存在于运行中容器的目标路径上，且应用加载了预期的配置。

## 编辑托管文件挂载

Coolify 中显示的内容可能比部署服务器上当前存储的文件更旧。

1. 如果应用或管理员可能在 Coolify 之外修改过源文件，请先选择 **Load from server** 再编辑。
2. 编辑 **Content**。
3. 选择 **Save**。

Coolify 会把更新后的内容写入部署服务器上的源文件。运行中的容器能看到挂载的文件，但应用可能需要重新加载或重启后才会读取新内容。

## 添加主机文件挂载

当文件已存在于部署服务器上、并由其他进程或管理员管理时，请使用 **Host File Mount**。

1. 通过 SSH 连接到该资源的部署服务器。
2. 在其固定的绝对路径上创建源文件，并设置允许容器进程读取的权限。
3. 在 Coolify 中打开该应用或独立数据库。
4. 选择 **Configuration** > **Persistent Storage**。
5. 选择 **Add** > **Host File Mount**。
6. 在 **Host File Path** 中填写既有的绝对路径。
7. 在 **Destination Path** 中填写容器内的精确路径。
8. 选择 **Add**，然后重新部署该资源。

验证容器能读取该文件，且应用加载了预期的配置。

<Callout type="warning" title="Coolify 不管理主机文件">
对于 Host File Mount 所用的源文件，Coolify 不会创建、编辑、加载、更改权限或删除。如果源文件缺失或不可读，请直接在部署服务器上修正。
</Callout>

Coolify 会在容器启动前写入托管的内容文件。如果 Docker 之前在该文件路径上创建过目录，Coolify 在准备文件时会保留已配置的内容。对于非托管的主机文件，请在部署前确认源路径确实是一个文件。

## 在 Docker Compose 中定义文件挂载

对于 Docker Compose 应用或一键服务，在 Compose 文件中定义文件挂载。Coolify 支持带内联 `content` 的绑定挂载：

```yaml
services:
  app:
    image: example/app:latest
    volumes:
      - type: bind
        source: ./config/app.conf
        target: /etc/example/app.conf
        content: |
          log_level=info
```

保存 Compose 文件并在 Coolify 中重新加载其配置。仪表盘会列出解析出的文件挂载。如需更改其源路径或目标路径，请在 Compose 文件中修改。

目录挂载及其他 Compose 特有的存储行为，请阅读 [Docker Compose 存储指南](/applications/builds/docker-compose#存储)。

## 文件挂载的限制

- Coolify 不在仪表盘中编辑大于 5 MiB 的托管文件。
- 二进制文件无法在文本框中编辑。
- 在 Docker Compose 中声明为只读的文件无法从仪表盘修改。
- 目标必须是文件路径，不能是目录。目录请使用 **Directory Mount**。
- 文件路径不能包含 `.` 或 `..` 路径段，也不能用反斜杠作目录分隔符。
- 容器进程仍需拥有读取挂载文件的权限。

如果托管文件超出编辑器限制，请直接在部署服务器上编辑，或通过该资源的源代码仓库管理。

## 备份文件挂载

File Mount 和 Host File Mount 不是 Coolify 计划存储备份的目标。适当情况下，请将托管的原始内容保存在版本控制或其他安全位置；既有主机文件则通过管理它的流程来备份。

Coolify 可以为应用的卷和 Directory Mount 安排文件级归档。受支持的目标和限制请阅读[存储挂载备份](/core/persistent-storage/storage-mounts/backups)。

## 安全删除文件挂载

删除托管的 **File Mount** 可能同时从部署服务器上删除其源文件。确认删除之前：

1. 如果源文件内容没有存放在其他地方，先复制一份。
2. 确认应用是否仍需要该目标路径。
3. 阅读确认对话框中的永久删除选项。
4. 移除挂载后重新部署，让下一个容器不再依赖它。

删除 **Host File Mount** 只会移除挂载配置。Coolify 会把源文件保留在部署服务器上。请重新部署该资源，让下一个容器在没有该挂载的情况下启动。

## 相对路径与权限

相对的文件和目录源会解析到资源目录内，而不是 SSH 用户的主目录。文件存储路径必须位于允许的资源目录之内；Coolify 不会通过其中的符号链接写入，也不会删除无关的主机路径。对资源目录之外的挂载发起 API 请求需要 `deploy` 权限。
