# 备份存储挂载

Coolify 可以对挂接到应用的符合条件的存储挂载创建计划化的文件级归档。Coolify 会先在应用的部署服务器上生成 `.tar.gz` 压缩归档，然后可以把副本发送到 S3 兼容存储，并且（如果配置了）在上传成功后删除本地归档。

<Callout type="warning" title="文件级归档可能包含不一致的数据">
如果 Coolify 创建归档期间应用正在修改文件，备份可能不一致甚至损坏。对数据库而言尤其如此。如果应用提供了感知应用状态的备份方式，请优先使用；否则请在归档阶段暂停应用的写入。
</Callout>

## 确认挂载是否受支持

本页描述的仪表盘备份工作流适用于应用的存储挂载。

| 挂载工作流 | 计划存储备份 |
| :--- | :--- |
| 不带 **Source Path** 的 **Volume Mount** | 支持 |
| 带 **Source Path** 的 **Volume Mount** | 支持 |
| **Directory Mount** | 支持 |
| **File Mount** | 不支持 |
| **Host File Mount** | 不支持 |

对于 File Mount 或 Host File Mount，请通过版本控制或管理该文件的流程来备份源文件。对于数据库数据，请使用数据库引擎支持的备份工作流，不要只依赖文件级存储归档。

## 创建计划备份

应用必须先拥有一个符合条件的挂载，才能将其选为备份目标。

1. 在对应的项目和环境中打开该应用。
2. 选择 **Backups**。
3. 在 **Storage backups** 下选择 **Add**。
4. 在 **Backup target** 中选择卷或目录。
5. 在 **Frequency** 中填写 `every_minute`、`hourly`、`daily`、`weekly`、`monthly`、`yearly` 或有效的 cron 表达式。
6. 选择 **Create schedule**。

Coolify 会创建并启用该计划。打开它即可修改设置，或选择 **Back up now**。新建计划显示的默认频率为 `daily`。

你也可以打开 **Persistent Storage**，找到符合条件的卷或目录，然后选择 **Configure Backup**。

## 降低中断或一致性风险

在 **General > Backup schedule** 下，可以选择 Coolify 创建归档时是否停止使用所选存储的容器：

- 将 **Archive behavior** 设为 **Keep containers running**，避免主动造成中断。但归档期间文件可能发生变化。
- 选择 **Stop containers during archive** 以获得更安全的文件级备份。Coolify 会优雅地停止使用该存储的容器，创建归档后再重新启动它们。在该归档阶段应用不可用。

将 **Timeout** 设为备份允许的最长运行时间（秒）。可接受范围为 `60` 到 `36000`，默认为 `3600` 秒。**Timezone** 为只读，跟随运行该计划的服务器；若服务器未配置时区，则跟随实例时区。

## 选择备份的存储位置

默认情况下，每个计划都会在部署服务器上保留一份本地归档。只靠本地存储无法在服务器丢失时保护数据。

要创建服务器外的副本：

1. 为当前团队配置并通过验证一个 [S3 兼容存储目标](/core/s3-storage/overview)。
2. 打开该存储备份计划，选择 **S3** 以进入 **S3 storage**。
3. 选择 **S3 storage** 目标，然后选择 **Enable S3**。
4. 选择 **Save changes**。

仅当 S3 应作为唯一保留副本时，才将 **Local copy** 设为 **Delete after S3 upload**。S3 上传成功后，Coolify 会删除本地归档；若上传失败，该次执行会显示 **Success (S3 Warning)**，并且 Coolify 会保留本地归档。

## 设置保留上限

在 **Retention** 下，本地与 S3 归档各自拥有三个独立的限制：

- **Backups to keep**
- **Days to keep**
- **Maximum storage (GB)**

值为 `0` 表示该限制不设上限。配置了多个限制时，其中任意一项达到阈值都会触发对该位置最旧的成功归档的清理。本地与 S3 备份的默认保留数量为 `7`；天数与存储限制默认为 `0`。

## 验证并下载备份

打开 **Executions** 并等待本次运行结束。可用的结果会显示 **Success**，且 **Backup Availability** 下至少有一个可用位置。

- **Local Storage** 表示归档仍存在于部署服务器上。选择 **Download** 可将本地归档保存到你的电脑。
- **S3 Storage** 表示归档已上传到所选的 S3 目标。
- **Success (S3 Warning)** 表示本地归档成功，但其 S3 上传失败。请阅读执行消息并在依赖远程副本前先解决 S3 问题。
- **Failed** 表示归档未完成。重试前请先阅读执行消息。
- **Needs attention** 表示恢复需要人工处理。阅读原因、修正问题，然后使用重试按钮。失败的恢复不会无限期阻塞新的备份。

<Callout type="warning" title="Coolify 不提供从此页面恢复存储归档的功能">
存储备份工作流可以创建、下载和删除归档，但不提供仪表盘内的恢复操作。在依赖某个计划之前，请先下载一份归档，并在单独的环境中演练你的恢复流程。
</Callout>

## 删除备份或计划

删除单次执行会同时移除其本地归档。若存在 S3 副本，请同时选择 S3 删除选项，才能一并移除该副本。

删除计划备份的影响更大：它会永久删除该计划及其创建的所有本地与 S3 归档。带有备份计划的卷或 Directory Mount 必须先删除该计划及其归档，Coolify 才允许你删除该挂载。
