# Docker 与容器

Coolify 使用 Docker 在你连接的服务器上运行应用、数据库和服务。Coolify 负责协调工作;Docker 则提供让每个资源得以运行的镜像、容器、存储和网络。

第一次部署并不需要你手工管理 Docker。但理解这些 Docker 概念有助于你选择存储、看懂部署日志,以及诊断资源为何无法启动或连接。

<CoolCallout icon={ArrowsRight} title="简要版">

镜像描述要运行什么。容器是镜像的一个运行实例。持久化存储把数据保存在可替换的容器之外。网络把容器连接起来,而 Docker Compose 定义则描述多个容器如何一起运行。

Coolify 准备容器配置,并指挥 Docker 构建或拉取镜像、附加存储与网络,在已连接的服务器上启动容器。

</CoolCallout>

## 镜像与容器

镜像是 Docker 用来创建容器的可复用打包。镜像包含应用及其所需文件,但它本身并不是一个正在运行的应用。

根据你在 Coolify 中的资源设置,Docker 可以从源代码构建应用镜像、从容器镜像仓库拉取预构建镜像,或启动 Docker Compose 文件中定义的镜像。

## 持久化数据

容器的可写文件系统不是存放需要跨重新部署留存数据的可靠位置。如果 Docker 删除并替换了容器,只存在该文件系统中的更改会随之消失。

Coolify 的持久化存储可以使用具名 Docker 卷(volume),也可以使用来自服务器文件系统的绑定挂载(bind mount)。两种类型都是把容器之外的存储附加到容器内的某个路径上。

## 网络与 Docker Compose

网络与 Compose 描述容器如何组合在一起。网络提供连接;Compose 记录期望的多容器配置。

### 网络

Docker 网络让容器之间可以通信,而不必把每个服务都直接暴露到互联网。同一网络上的容器可以访问它们需要的服务;位于不同、互不连接的网络上的容器,则无法通过这些网络通信。

Coolify 创建或使用每个资源所需的网络,并在需要 HTTP 路由时连接服务器代理。代理接收公网流量,然后通过 Docker 网络把流量转发到正确的容器。

域名、代理模式、公网端口和内部服务连接参阅[Coolify 中的网络](/core/networking-in-coolify)。Docker 的[网络指南](https://docs.docker.com/engine/network/)涵盖底层网络驱动与行为。

### Docker Compose

Docker Compose 文件描述一个或多个服务,以及它们的镜像、环境变量、端口、存储挂载、网络、健康检查和依赖关系。

Coolify 会为应用、数据库等资源生成所需的 Compose 配置。对于 Docker Compose 应用或一键服务,Coolify 使用你提供或选择的 Compose 定义。你不需要为每个资源都编写 Compose 文件。

Compose 定义的是期望的运行时配置;它不会让容器本地数据变得持久。存储仍然需要卷、绑定挂载或外部数据服务。

服务、网络和卷之间的关系,参阅 Docker 的 [Compose 应用模型](https://docs.docker.com/compose/intro/compose-application-model/)。

## 资源标签

Coolify 使用 UUID 标签标识资源容器:`coolify.applicationUuid`、`coolify.serviceUuid`、`coolify.service.subUuid` 和 `coolify.databaseUuid`。现有容器保持兼容,并会在下次部署或重启时获得新标签。请把依赖旧数字 ID 标签的脚本更新为使用对应的 UUID 标签。

## 查看 Docker 资源

你可以在不改动 Docker 状态的前提下查看它。通过 SSH 连接到运行资源的服务器,然后使用标准的 Docker 列表命令:

```bash
docker ps
docker image ls
docker volume ls
docker network ls
```

这些命令只显示当前服务器上的资源。如果一个 Coolify 实例管理多台已连接的服务器,请在你正在检查的资源所在的那台服务器上运行它们。

### 检查自托管的 Coolify 容器

自托管时,Coolify 本身也运行在容器中。在托管你的 Coolify 实例的机器上运行以下命令:

```bash
docker ps --filter "name=coolify" \
  --format "table {{.Names}}\t{{.Image}}\t{{.RunningFor}}"
```

Coolify Cloud 用户无法访问托管控制平面的主机。你可以改为检查连接到 Cloud 账户的工作负载服务器。

<CoolCallout icon={Warning22} title="持久性改动请在 Coolify 中进行" type="warning">

直接使用 Docker 命令,仅限查看和范围明确、谨慎进行的调试。直接对 Coolify 管理的容器所做的更改,可能在 Coolify 重建该容器时消失。

请把持久性改动放入 Coolify 中的资源设置,或源 Docker Compose 文件里。

</CoolCallout>

## 为什么标准 Docker 很重要

Docker 让工作负载层保持熟悉且可移植。你可以在自己控制的服务器上使用常规的 Docker 概念和检查工具,运行中的资源也始终是标准 Docker 容器。

如果 Coolify 控制平面变得不可用,已在运行的容器仍会留在其已连接的服务器上。在 Coolify 实例恢复之前,仪表盘控制和部署自动化无法使用。

控制平面、已连接服务器、Docker 与代理流量之间的关系,参阅[Coolify 的工作原理](/core/how-coolify-works)。
