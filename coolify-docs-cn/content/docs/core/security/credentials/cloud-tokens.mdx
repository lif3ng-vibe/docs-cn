# 云令牌

Coolify 使用云令牌（cloud token）连接受支持的云提供商。云令牌属于当前所在的 Coolify 团队，可在该提供商账号下创建或管理服务器时使用。

只有团队管理员和所有者可以管理云令牌。Coolify 会在数据库中加密存储令牌值，且不会再次显示已保存的值。

<Callout type="warning" title="把云令牌当作密码对待">
为 Coolify 创建专用的提供商令牌，只授予它所需的访问权限，并把原始值存入机密管理工具。令牌一旦泄露，立即撤销并更换。
</Callout>

## 创建提供商令牌

选择让 Coolify 在哪个提供商账号下创建和管理服务器。大多数读者只需要其中一种流程。

<Tabs id="cloud-token-provider" items={['Hetzner', 'DigitalOcean', 'Vultr', 'Hostinger']}>
<Tab value="Hetzner" icon={ServerCloud}>

Hetzner 令牌属于单个项目。请在希望 Coolify 管理服务器的项目中创建令牌。

<Steps>
<Step>

### 打开 Hetzner 项目

打开 [Hetzner Cloud Console](https://console.hetzner.cloud/projects)，选择所需的项目。

</Step>
<Step>

### 打开 API tokens

在项目侧边栏选择 **Security**（安全），打开 **API Tokens**，然后选择 **Generate API Token**（生成 API 令牌）。

</Step>
<Step>

### 配置令牌

输入 `coolify-shadowarcanist` 之类的描述，然后选择 **Read & Write**（读写）。

Coolify 需要写权限来创建和删除服务器、上传 SSH 密钥、控制服务器电源，以及（可选）启用 Hetzner 备份。**Read**（只读）令牌可以通过初始验证，但无法执行这些操作。

</Step>
<Step>

### 生成并复制令牌

选择 **Generate API Token**，复制完整值并妥善保管。关闭对话框后，Hetzner 不会再显示该令牌。

</Step>
</Steps>

</Tab>
<Tab value="DigitalOcean" icon={Droplet}>

为 Coolify 要管理 Droplet 的团队创建一个 DigitalOcean 个人访问令牌（personal access token）。

<Steps>
<Step>

### 打开个人访问令牌页面

打开 [Applications & API](https://cloud.digitalocean.com/account/api/tokens)，找到 **Personal access tokens**（个人访问令牌），然后选择 **Generate New Token**（生成新令牌）。

</Step>
<Step>

### 命名令牌并选择有效期

输入 `coolify-shadowarcanist` 之类的名称。选择一个有效期，确保你有足够的时间在令牌过期前完成轮换。

</Step>
<Step>

### 选择自定义作用域

选择 **Custom Scopes**（自定义作用域），然后授予以下作用域：

- `account:read`
- `regions:read`
- `sizes:read`
- `image:read`
- `ssh_key:read`
- `ssh_key:create`
- `droplet:read`
- `droplet:create`
- `droplet:update`
- `droplet:delete`

这些作用域让 Coolify 能够验证账号、列出服务器表单所需的选项、管理 SSH 密钥，以及创建、查看、启动或删除 Droplet。**Full Access**（完全访问）也可以，但授予的权限超出了 Coolify 的实际需要。

</Step>
<Step>

### 生成并复制令牌

选择 **Generate Token**，复制完整值并妥善保管。DigitalOcean 只显示一次令牌密钥。

</Step>
</Steps>

</Tab>
<Tab value="Vultr" icon={CloudBolt}>

为 Coolify 要管理实例的账号创建一个 Vultr API 密钥。

<Steps>
<Step>

### 打开 Vultr API 访问页面

打开 [Vultr API 页面](https://console.vultr.com/user/apiaccess/)。根据 Vultr Console 版本不同，该页面可能显示为 **Orchestration** 下的 **Vultr API**，或 **Account** 下的 **API Access**。

如果该 Vultr 用户的 API 访问被禁用，请将其启用。

</Step>
<Step>

### 检查 API 访问控制

如果 Vultr 账号按 IP 地址限制 API 访问，请放行 Coolify 实例的公网出站 IP 地址。这些 API 请求来自 Coolify，而不是你的浏览器或 Coolify 将要创建的服务器。

</Step>
<Step>

### 创建 API 密钥

在 **User Access Tokens** 下输入 `coolify-shadowarcanist` 之类的名称，选择一个有效期选项，然后选择 **Add Key**（添加密钥）。

该 Vultr 用户必须有权列出套餐（plan）、区域、操作系统和 SSH 密钥，并有权创建、查看、启动和删除实例。

</Step>
<Step>

### 复制 API 密钥

复制完整密钥并妥善保管。离开页面后，Vultr 不允许你再找回该值。

</Step>
</Steps>

</Tab>
<Tab value="Hostinger" icon={Server}>

为 Coolify 要购买和管理 VPS 服务器的账号创建一个 Hostinger API 令牌。

如果你还没有 Hostinger 账号，可以[通过 Coolify 链接注册](https://www.hostinger.com/vps/coolify-hosting?ref=coolify.io)。令牌表单中也会显示同样的链接。

<Steps>
<Step>

### 在 hPanel 中打开 API 页面

登录 Hostinger，打开 [hPanel 的 API 页面](https://hpanel.hostinger.com/profile/api)。

</Step>
<Step>

### 创建令牌

创建一个新的 API 令牌，用一个能识别出 Coolify 的名称，例如 `coolify-shadowarcanist`。

</Step>
<Step>

### 复制令牌

复制完整的令牌值，并将其存放在安全的位置。

</Step>
</Steps>

<Callout type="warning" title="Hostinger 令牌可以购买服务器">
Coolify 会使用该令牌订购 VPS 服务器，每笔订单都会计入账号的默认支付方式。请妥善保管该令牌。
</Callout>

</Tab>
</Tabs>

## 将令牌添加到 Coolify

<Steps>
<Step>

### 打开 Cloud Tokens

在 Coolify 侧边栏打开 **Keys & Tokens**，然后选择 **Cloud Tokens**。

</Step>
<Step>

### 选择提供商

选择 **New token**（新建令牌），然后在 **Provider**（提供商）中选择 **Hetzner**、**DigitalOcean**、**Vultr** 或 **Hostinger**。

</Step>
<Step>

### 填写令牌信息

填写表单：

- **Token name**（令牌名称）：输入能识别提供商账号或环境的名称，例如 `shadowarcanist-production`。
- **Description**（描述）：可选填项目、团队、账号或用途。
- **API token**（API 令牌）：粘贴从提供商复制的完整令牌或 API 密钥。

选择 **Validate and add**（验证并添加）。

</Step>
<Step>

### 确认令牌已添加

验证通过后，Coolify 会关闭表单，并在 **Cloud Provider Tokens**（云提供商令牌）页面显示新令牌。

</Step>
</Steps>

<Callout type="info" title="验证只检查凭据本身，而非全部权限">
Coolify 通过列出服务器来验证 Hetzner 令牌，通过账号端点验证 DigitalOcean 和 Vultr 令牌，并用 `GET https://developers.hostinger.com/api/vps/v1/virtual-machines` 验证 Hostinger 令牌。验证成功只能说明提供商接受该凭据，并不能证明创建或管理服务器所需的每项权限都可用。
</Callout>

## 管理云令牌

打开 **Keys & Tokens > Cloud Tokens**，选择令牌旁边的 **Edit**（编辑）图标。

- 修改 **Name**（名称）或 **Description**（描述），然后选择 **Save changes**（保存更改）。
- 选择 **Validate**（验证）检查提供商是否仍接受已保存的凭据。
- 选择 **Delete**（删除）移除不再使用的令牌。

提供商和创建日期为只读。Coolify 不会在此页面显示或替换已保存的密钥。如需轮换凭据，请先在提供商处创建替换凭据，将其添加为新的云令牌，并把所有依赖它的服务器迁移到新令牌，之后再撤销旧凭据。

只要还有一个或多个服务器在使用该令牌，Coolify 就会阻止删除。在这些服务器迁移到其他令牌、或不再通过该提供商连接管理之前，不要在提供商处撤销凭据。

## 故障排查

<Accordions type="multiple">
<Accordion title="Coolify 提示 Invalid API token">

确认选择了匹配的提供商，并完整粘贴了令牌、前后没有多余空格。检查凭据是否已过期或被撤销。

Hetzner：确认项目仍然存在。DigitalOcean：确认令牌包含 `account:read`。Vultr：确认 API 访问已启用，且 Vultr 的访问控制列表允许来自 Coolify 实例的请求。

</Accordion>
<Accordion title="令牌验证通过但服务器操作失败">

初始验证并不会测试所有写操作。

- Hetzner：使用 **Read & Write**（读写）令牌。
- DigitalOcean：将令牌的自定义作用域与 [DigitalOcean 标签页](#cloud-token-provider)中的列表进行比对。
- Vultr：确认该 Vultr 用户可以管理实例和 SSH 密钥，且 API 访问控制允许 Coolify 实例访问。
- Hostinger：确认账号有有效的默认支付方式。如果 Coolify 无法列出安装后脚本，说明令牌缺少相应权限。Coolify 会显示来自 Hostinger 的报错信息。

修正提供商权限后，回到已保存的云令牌并选择 **Validate**（验证）。

</Accordion>
<Accordion title="Vultr 拒绝来自 Coolify 的请求">

检查 Vultr API 页面上的 **Access Control**（访问控制）。如果启用了 IP 白名单，其中必须包含 Coolify 实例的公网出站 IP 地址。

把浏览器的 IP 地址或你打算创建的服务器地址加入白名单，并不能放行 Coolify 发出的请求。

</Accordion>
<Accordion title="看不到 Hetzner 资源">

Hetzner 令牌是项目级的。确认令牌创建在包含你期望 Coolify 使用的服务器、网络、防火墙和 SSH 密钥的项目中。

如果 Coolify 需要操作另一个 Hetzner 项目，请另外创建并添加一个令牌。

</Accordion>
<Accordion title="Coolify 不允许删除令牌">

该令牌仍被一个或多个服务器使用。请把这些服务器迁移到另一个有效的提供商令牌，或解除该提供商关联，然后重试删除。

不要先撤销提供商凭据。在依赖解除之前，Coolify 需要可用的凭据来执行该提供商相关的服务器操作。

</Accordion>
</Accordions>
