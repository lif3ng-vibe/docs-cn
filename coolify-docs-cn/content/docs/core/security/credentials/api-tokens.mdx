# API 令牌

API 令牌用于让集成、脚本、部署 webhook 和 MCP 客户端通过 Coolify 的身份验证。每个令牌属于创建它的用户，绑定到创建时所在团队，并携带所选的权限。

<Callout type="warning" title="把 API 令牌当作密码对待">
令牌无需交互式登录或 2FA 验证即可获得访问权限。请将它存放在机密管理工具中，绝不提交到代码仓库；一旦泄露，立即撤销。
</Callout>

## 创建令牌之前

先确定团队和 API 控制项：

- 切换到拥有集成所需资源的团队。令牌无法访问其他团队的资源。
- 在自托管 Coolify 上，打开 **设置 > 高级**，将 **API access**（API 访问）设置为 **Enabled**（启用）。
- 当调用方使用可预测的源地址时，将 **Allowed API IPs**（允许的 API IP）设置为所需的 IP 地址或 CIDR 网段。
- 确定最小的权限集合和切实可行的最短有效期。

Coolify Cloud 的 API 访问始终可用，因此 Cloud 用户无需启用实例级的 **API access** 设置。

---

## 创建令牌

<Steps>
<Step>

### 打开 API Tokens

在主侧边栏打开 **Keys & Tokens**（密钥与令牌），然后选择 **API Tokens**。

</Step>
<Step>

### 填写令牌描述

填写能识别调用方和用途的 **Description**（描述），例如 `production-status-monitor` 或 `docs-deploy-workflow`。

描述长度必须在 3 到 255 个字符之间。

</Step>
<Step>

### 选择有效期

通过 **Expires in**（有效期）选择 **7 天**、**30 天**、**60 天**、**90 天**、**1 年**或 **Never**（永不过期）。

可定期轮换的自动化任务应优先选择有限期。只有当集成无法按计划安全轮换时才使用 **Never**（永不过期）。

</Step>
<Step>

### 选择权限

打开 **Permissions**（权限），只选择集成所需的权限。使用 `write`、`read:sensitive` 或 `root` 之前，请先阅读[令牌权限](#令牌权限)。

</Step>
<Step>

### 创建并复制令牌

选择 **Create token**（创建令牌），然后立即复制生成的令牌。Coolify 只会显示一次完整的令牌值。

离开页面前先把它存入调用方的机密管理工具。如果值已丢失，请撤销已签发的令牌并重新创建。

</Step>
</Steps>

## 令牌权限

| 权限 | 用途 | 重要行为 |
| :--- | :--- | :--- |
| `read` | 列出和查看资源。 | 敏感响应值保持脱敏。 |
| `read:sensitive` | 读取受支持端点返回的机密、日志、密码、私钥、环境变量值和 Compose 内容。 | 选择该权限时，Coolify 会同时附加 `read`。 |
| `write` | 通过写入端点创建、更新和删除资源。 | 请求执行时，令牌所有者必须仍是令牌所属团队的管理员或所有者。 |
| `deploy` | 触发部署、重启、停止、取消和部署 webhook。 | 选择 `deploy` 会在 Dashboard 中创建仅限部署的令牌。 |
| `root` | 跳过 API 端点上的 `read`、`write` 和 `deploy` 权限检查。 | 实例级 **API access** 与 IP 白名单控制仍然生效。只有团队管理员和所有者可以创建这种令牌。选择它会移除其他权限，因为它们已无必要。 |

`read` 适用于资源清点和监控，`deploy` 适用于仅部署的工作流，只有调用方必须修改配置时才使用 `write`。仅在脱敏后的值不够用时才添加 `read:sensitive`。

`root` 令牌仍然只属于一个团队，其所有者必须保持为该团队成员。它不提供跨团队访问。

## 发起测试请求

以 Bearer 凭据的形式发送完整令牌：

```sh
export COOLIFY_URL="https://coolify.shadowarcanist.com"
export COOLIFY_TOKEN="<api-token>"

curl --fail-with-body \
  --header "Authorization: Bearer $COOLIFY_TOKEN" \
  "$COOLIFY_URL/api/v1/teams/current"
```

请求成功会返回令牌绑定的团队。不要把真实令牌直接粘贴进 shell 历史；生产环境中应从调用方的机密存储中加载。

请求示例请阅读 [Making Requests](/api/making-requests)，令牌作用域和角色限制请阅读 [API Permissions](/api/permissions)。[Rate Limits](/api/rate-limits) 说明了响应头和重试行为，[API Errors](/api/errors) 介绍了状态码。仅部署类的自动化请参考[部署 Webhook](/core/automation/deploy-webhooks)。

## 团队与角色范围

Coolify 在创建令牌时记录当时的当前团队。之后切换团队不会改变已签发的令牌。

- 为集成需要访问的每个团队分别创建令牌。
- 将令牌所有者移出团队会使令牌失效。
- 如果令牌所有者不再拥有管理员或所有者角色，`write` 或 `root` 请求会失败。
- 修改用户密码会撤销该用户的 API 令牌。
- 移除成员、通过 Coolify 降级成员角色或删除团队，都会撤销受影响团队的令牌。

**Issued Tokens**（已签发令牌）列表属于当前登录用户。用户可以撤销自己的令牌，但无法再次复制其密钥值。

## 轮换或撤销令牌

在令牌过期之前，或其存放位置、调用方发生变化时，进行轮换：

1. 在同一个团队下创建替换令牌，只保留仍然需要的权限。
2. 把替换令牌复制到集成的机密存储中。
3. 用替换令牌发起一次测试请求。
4. 回到 **Keys & Tokens > API Tokens**，对旧令牌选择 **Revoke token**（撤销令牌）。
5. 确认集成继续正常工作，且旧令牌现在返回 `401 Unauthenticated`。

过期的令牌会被自动拒绝。Coolify 每小时检查一次 24 小时内到期的令牌，并发送团队已启用的 **API token expiring**（API 令牌即将过期）通知。

## 故障排查

<Accordions type="multiple">
<Accordion title="API 返回 401 Unauthenticated">

确认 `Bearer` 之后是完整令牌、令牌未过期也未被撤销，且其所有者仍是令牌所属团队的成员。

修改密码、被移出团队或团队被删除都可能撤销或使令牌失效。

</Accordion>
<Accordion title="API 返回 403 Forbidden">

在自托管 Coolify 上，确认 **API access** 已启用，且调用方 IP 匹配 **Allowed API IPs**。

然后检查端点所需的权限。对于 `write` 或 `root`，确认令牌所有者仍是团队管理员或所有者。

</Accordion>
<Accordion title="敏感值被脱敏">

创建或使用同时具有 `read` 和 `read:sensitive` 的令牌；只有需要完整管理权限时才使用 `root` 令牌。

</Accordion>
<Accordion title="找不到预期的资源">

该资源可能属于另一个团队。在 Dashboard 中切换到那个团队并另外创建令牌；已签发令牌的团队无法更改。

</Accordion>
<Accordion title="令牌值已无法查看">

Coolify 只在创建后显示一次完整令牌。如果当时没有保存令牌值，请撤销该令牌，然后创建并保存替换令牌。

</Accordion>
</Accordions>
