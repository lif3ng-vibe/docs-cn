# SSH 密钥

Coolify 使用 SSH 私钥免密连接服务器，并通过部署密钥（deploy key）访问私有 Git 仓库。密钥属于当前所在的 Coolify 团队，可被该团队中的资源复用。

<Callout type="warning" title="使用不带 passphrase 的密钥">
Coolify 只能使用无需交互输入的 SSH 密钥。不要给 Coolify 使用的密钥添加 passphrase 或二次验证提示。
</Callout>

## Coolify 如何使用密钥对

一个 SSH 密钥对包含两部分：

- Coolify 保存并在发起 SSH 连接时使用**私钥**（private key）。
- 你把对应的**公钥**（public key）添加到服务器账号的 `~/.ssh/authorized_keys` 文件中，或作为 deploy key 添加到 Git 提供商。

没有对应的私钥，公钥本身不会授予任何访问权限。绝不要把私钥复制到受管服务器或 Git 仓库上。

---

## 创建 SSH 密钥

在主侧边栏打开 **Keys & Tokens**，选择 **Private Keys**（私钥），然后打开 **New private key**（新建私钥）。

<ZoomImage src="/docs-cn/coolify/images/core/security/credentials/ssh-keys/private-keys-page.webp" alt="Coolify 的 Private Keys 页面" />

<Tabs id="ssh-key-source" items={['在 Coolify 中生成', '导入现有密钥']}>
<Tab value="在 Coolify 中生成">

默认选择 **Generate ED25519**（生成 ED25519）。只有目标系统不支持 ED25519 密钥时才使用 **Generate RSA**（生成 RSA）。

Coolify 会立即生成并保存密钥。点击它的 **Edit**（编辑）图标可以查看公钥，或修改名称以标识用途，例如 `production-servers`。编辑后选择 **Save changes**（保存更改）。

</Tab>
<Tab value="导入现有密钥">

选择 **Add manually**（手动添加），将完整私钥粘贴到 **Private key**（私钥）输入框，包括 `BEGIN` 和 `END` 行。Coolify 会校验私钥并推导出对应的 **Public Key**（公钥）。

输入一个易于辨认的名称和可选的描述，然后选择 **Continue**（继续）。

不要导入带 passphrase 的密钥。Coolify 在部署或服务器检查过程中无法响应交互式的 passphrase 提示。

</Tab>
</Tabs>

<ZoomImage src="/docs-cn/coolify/images/core/security/credentials/ssh-keys/new-private-key-form.webp" alt="New Private Key 表单，包含密钥生成和公钥字段" />

Coolify 会拒绝无效的私钥以及当前团队中重复的密钥。

## 在服务器上授权公钥

把公钥添加到 Coolify 将用于 SSH 的账号。以下命令以 `root` 为例；如有需要，替换为所配置的非 root 账号。

<Steps>
<Step>

### 从 Coolify 复制公钥

打开 **Keys & Tokens > Private Keys**，点击密钥的 **Edit** 图标，复制 **Public key**（公钥）。

</Step>
<Step>

### 连接到服务器

在受信任的终端上，用现有的管理方式连接：

```sh
ssh root@<server-ip>
```

如果 SSH 使用其他端口，加上 `-p <ssh-port>`。

</Step>
<Step>

### 将密钥添加到 SSH 账号

在服务器上运行：

```sh
mkdir -p ~/.ssh
chmod 700 ~/.ssh
nano ~/.ssh/authorized_keys
```

把完整公钥单独粘贴为一行，保存文件，然后运行：

```sh
chmod 600 ~/.ssh/authorized_keys
```

在新的 Coolify 连接验证成功之前，不要移除当前 SSH 会话正在使用的密钥。

</Step>
</Steps>

服务器要求和防火墙规则请参阅 [OpenSSH](/core/infrastructure/servers/openssh)。

## 选择并验证服务器密钥

对于新服务器，按照[添加服务器](/core/infrastructure/servers/add-server)操作时，在 **Private Key**（私钥）字段中选择密钥。

对于已连接的服务器：

1. 打开 **服务器**，选择该服务器。
2. 在服务器设置中打开 **Private Key**。
3. 找到已授权的密钥，选择 **Use this key**（使用此密钥）。
4. 选择 **Check connection**（检查连接）。

当 Coolify 报告服务器可达时，说明更改已验证。如果检查失败，恢复之前可用的密钥选择，并确认新公钥已写入所配置 SSH 用户的 `~/.ssh/authorized_keys` 文件。

---

## 将密钥用于私有 Git 仓库

通过 deploy key 从私有仓库创建应用时，在 Coolify 中选择或创建一个私钥，并把它的公钥添加到仓库的 deploy key 设置中。

仓库访问与服务器访问是相互独立的。把公钥添加到 Git 提供商并不会让它在服务器上生效，添加到 `~/.ssh/authorized_keys` 也不会授予仓库访问权限。

如果希望在不影响服务器连接的情况下轮换或撤销仓库访问权限，请使用专用密钥。

---

## 轮换 SSH 密钥

应创建新密钥，而不是就地替换共享的私钥。这样在过渡期间现有连接仍然可用。

1. 在 **Keys & Tokens > Private Keys** 下创建替换密钥。
2. 把它的公钥添加到每个需要它的目标服务器账号或 Git 仓库。
3. 对每台已连接的服务器，在 **Server > Private Key** 下选择替换密钥并运行 **Check connection**。
4. 更新使用旧密钥的应用或 Git 集成，并通过一次部署验证仓库访问。
5. 只有在所有依赖资源都换用新密钥后，才从各服务器或提供商移除旧公钥。
6. 旧密钥被标记为未使用（Unused）后，再从 Coolify 中删除它。

如果多个资源共用一把密钥，请逐个轮换。直接替换现有密钥的私钥值，会同时改变所有关联服务器和 Git 集成的凭据。

---

## 删除未使用的密钥

当没有任何服务器、应用、GitHub App 或 GitLab App 引用某个密钥时，**Private Keys** 列表会将其标记为 **Unused**（未使用）。

- 打开未使用的密钥，选择 **Delete**（删除）将其移除。
- 在列表页选择 **Delete unused keys**（删除未使用密钥），一次性移除当前团队中所有被标记为未使用的密钥。

Coolify 的安全删除机制不会移除仍被引用的密钥。删除密钥前，请先移除或替换所有依赖。

---

## 安全与存储

只有团队管理员和所有者可以创建、修改或删除私钥。为每个密钥取一个标明用途的名称，避免在不相关的环境间共用一把密钥。

Coolify 会对数据库中存储的私钥值加密。在自托管实例上，Coolify 还会以严格的文件权限把密钥写入其 SSH 密钥存储目录，供 SSH 客户端使用。请把 Coolify 数据库、`/data/coolify/source/.env`、`/data/coolify/ssh/keys/` 和实例备份当作特权恢复材料加以保护。

迁移自托管实例时，请按照[恢复 Coolify](/core/backup-and-recovery/instance-restore) 操作，确保数据库、加密密钥和 SSH 密钥文件保持一致。
