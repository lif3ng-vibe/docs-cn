# Cloud-init 脚本

cloud-init 脚本会在新云服务器首次启动时对其进行配置。创建 Hetzner、DigitalOcean 或 Vultr 服务器时，Coolify 可以将其作为提供商用户数据（user data）发送。

可以用脚本完成可重复的初始化工作，例如在 Coolify 验证服务器之前创建文件、安装软件包或应用操作系统设置。

<Callout type="warning" title="正式使用前先测试脚本">
有问题的 cloud-init 脚本可能导致新服务器配置不完整或无法访问。请先用临时服务器测试，并避免改动 Coolify 所需的 SSH 访问配置。
</Callout>

只有团队管理员和所有者可以创建、更新或删除 cloud-init 脚本。脚本属于当前所在团队。

## 创建可复用脚本

<Steps>
<Step>

### 打开 Cloud-Init Scripts

在 Coolify 侧边栏打开 **Keys & Tokens**（密钥与令牌），然后选择 **Cloud-Init Scripts**。

</Step>
<Step>

### 添加脚本

1. 选择 **New script**（新建脚本）。
2. 输入一个描述性的 **Script name**（脚本名称）。
3. 在 **Script content**（脚本内容）下输入 cloud-config YAML。
4. 选择 **Create script**（创建脚本）。

名称和脚本内容均为必填。保存前，Coolify 会校验内容是否为合法的 cloud-init YAML。

</Step>
</Steps>

例如：

```yaml
#cloud-config
package_update: true
packages:
  - curl

write_files:
  - path: /etc/motd
    content: |
      Managed by Coolify
```

cloud-init 功能因 Linux 镜像和提供商而异。依赖某个模块之前，请先确认镜像支持它。

## 创建服务器时使用脚本

1. 打开 **服务器**，选择 **New server**（新建服务器）。
2. 选择 **Hetzner**、**DigitalOcean** 或 **Vultr**。
3. 填写该提供商的服务器设置。
4. 展开高级选项。
5. 选择已保存的 cloud-init 脚本。
6. 检查其余选项，然后选择 **Buy & Create Server**（购买并创建服务器）。

也可以直接在创建表单中输入脚本。如果希望将其加入团队的可复用脚本，请开启 **Save this script for later use**（保存此脚本供以后使用）。

脚本只在提供商创建服务器时发送。验证服务器或手动添加已有服务器时不会执行。

Hostinger 不使用 cloud-init 脚本。对于 Hostinger VPS，请在高级选项中选择 Hostinger 的安装后脚本（post-install script）。参见[创建云服务器](/core/infrastructure/servers/provision-cloud-server)。

<Callout type="info" title="已保存的脚本只是模板">
编辑已保存的脚本会影响之后使用它的创建请求，但不会重新运行 cloud-init，也不会修改已创建的服务器。
</Callout>

## 编辑或删除脚本

打开 **Keys & Tokens > Cloud-Init Scripts**，选择脚本旁边的 **Edit**（编辑）图标。

- 修改 **Script name** 或 **Script content**，然后选择 **Save changes**（保存更改）。
- 选择 **Delete**（删除），输入所需的确认文字，再选择 **Delete script**（删除脚本）将其永久移除。

删除已保存的脚本不会影响已经用它创建的服务器。

---

## 故障排查

如果新服务器没有按预期完成配置：

1. 在提供商控制台确认服务器已创建并正在运行。
2. 打开服务器控制台，查看 cloud-init 状态：

   ```sh
   cloud-init status --long
   ```

3. 查看 cloud-init 日志：

   ```sh
   sudo less /var/log/cloud-init.log
   sudo less /var/log/cloud-init-output.log
   ```

4. 修正已保存的脚本，再用临时服务器创建一次进行测试。

cloud-init 通常只在机器首次启动时运行。修改已保存的模板无法修复已有的机器。
