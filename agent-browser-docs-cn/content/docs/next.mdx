在 Vercel 上的 Next.js 应用中通过 Vercel Sandbox 运行 agent-browser。Linux microVM 按需启动，运行 agent-browser + Chrome，然后关闭。没有二进制体积限制，也没有打包 Chromium 的复杂性。

## 安装

```bash
pnpm add @agent-browser/sandbox @vercel/sandbox
```

## 服务器操作（Server Action）

Vercel Sandbox 运行 Amazon Linux。Chromium 需要默认未安装的系统库，因此全新的沙盒需要先执行一步 `dnf install`，agent-browser 才能启动 Chrome。生产环境可用沙盒快照（见下文）完全跳过这一步。`@agent-browser/sandbox` 助手默认会安装这些系统依赖并处理命令执行。

```ts
"use server";
import { runAgentBrowserCommand, withAgentBrowserSandbox } from "@agent-browser/sandbox/vercel";

export async function screenshotUrl(url: string) {
  return withAgentBrowserSandbox(async (sandbox) => {
    await runAgentBrowserCommand(sandbox, ["open", url]);

    const ssResult = await runAgentBrowserCommand<{ data?: { path?: string } }>(sandbox, [
      "screenshot",
    ]);
    const ssPath = ssResult.json?.data?.path;
    if (!ssPath) throw new Error("Screenshot did not return a file path.");

    const b64Result = await sandbox.runCommand("base64", ["-w", "0", ssPath]);
    const screenshot = (await b64Result.stdout()).trim();
    await runAgentBrowserCommand(sandbox, ["close"], { json: false });
    return { ok: true, screenshot };
  });
}

export async function snapshotUrl(url: string) {
  return withAgentBrowserSandbox(async (sandbox) => {
    await runAgentBrowserCommand(sandbox, ["open", url]);

    const result = await runAgentBrowserCommand(sandbox, ["snapshot", "-i", "-c"], {
      json: false,
    });

    await runAgentBrowserCommand(sandbox, ["close"], { json: false });
    return { ok: true, snapshot: result.stdout };
  });
}
```

## MCP server over stdin

当智能体在同一个 Vercel Sandbox 中进行大量 MCP 工具调用时，使用 `@agent-browser/sandbox/vercel` 的 `startAgentBrowserMcp`。它会启动一个 `agent-browser mcp` 进程，并把每个请求都通过该命令的 stdin 发送，使工具调用复用进程，而不是像 `runAgentBrowserCommand` 那样每次都启动一个 CLI 命令：

```typescript
import { startAgentBrowserMcp, withAgentBrowserSandbox } from "@agent-browser/sandbox/vercel";

const snapshot = await withAgentBrowserSandbox(async (sandbox) => {
  const mcp = await startAgentBrowserMcp(sandbox, { timeout: 60_000 });
  try {
    await mcp.callTool("agent_browser_open", { url: "https://example.com" });
    return await mcp.callTool("agent_browser_snapshot", { interactive: true });
  } finally {
    await mcp.close();
  }
});
```

`startAgentBrowserMcp` 需要 `@vercel/sandbox` 3.7 或更高版本。`timeout` 单位为毫秒，作用于每个请求与 `close()`；不设置时请求会无限等待。在其他运行时中，把带 `stdin` 与 `stdout` 流的进程传给 `@agent-browser/sandbox` 的 `connectAgentBrowserMcp`。

## 沙盒快照

不做优化的情况下，每次 Sandbox 运行都要从零安装系统依赖 + agent-browser + Chromium（约 30 秒）。**沙盒快照**（sandbox snapshot）是预先装好一切的已保存 VM 镜像，类似 Vercel Sandbox 的 Docker 镜像。设置 `AGENT_BROWSER_SNAPSHOT_ID` 后，沙盒直接从该镜像启动而不再安装，启动时间降到亚秒级。

它与 agent-browser 的*无障碍快照*（导出页面无障碍树）不同。沙盒快照是 Vercel 基础设施概念。

运行一次辅助脚本即可创建沙盒快照：

```bash
npx tsx scripts/create-snapshot.ts
```

脚本会启动一个全新沙盒，安装系统依赖 + agent-browser + Chromium，保存 VM 状态，并打印快照 ID：

```
AGENT_BROWSER_SNAPSHOT_ID=snap_xxxxxxxxxxxx
```

把它添加到 Vercel 项目的环境变量中（本地开发用 `.env.local`）。任何生产部署都推荐这样做。

## 认证

在 Vercel 部署上，Sandbox SDK 经 OIDC 自动认证。本地开发时请显式提供凭据：

## 定时工作流（cron）

对于每日监控等周期性任务，使用 Vercel Cron Jobs：

```ts
// app/api/cron/monitor/route.ts
import { runAgentBrowserCommand, withAgentBrowserSandbox } from "@agent-browser/sandbox/vercel";

export async function GET() {
  const result = await withAgentBrowserSandbox(async (sandbox) => {
    await runAgentBrowserCommand(sandbox, [
      "open", "https://example.com/pricing",
    ]);
    const snap = await runAgentBrowserCommand(sandbox, [
      "snapshot", "-i", "-c",
    ], { json: false });
    await runAgentBrowserCommand(sandbox, ["close"], { json: false });
    return snap.stdout;
  });

  // 处理结果、发送告警、存储数据……
  return Response.json({ ok: true, snapshot: result });
}
```

```json
// vercel.json
{
  "crons": [
    { "path": "/api/cron/monitor", "schedule": "0 9 * * *" }
  ]
}
```
