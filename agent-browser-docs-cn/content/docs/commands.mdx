## 核心

未知命令以状态码 1 退出，请求命令帮助时同样如此。

当顶层 Chrome/CDP `eval` 的结果是 JSON 无法表示的值时，纯文本输出会打印其精确的 JavaScript 字面量，包括 `NaN`、`Infinity`、`-Infinity`、`-0`、BigInt 字面量与 `undefined`。使用 `--json` 时，`data.result` 保持为 `null`，旁边的 `data.unserializable` 包含该字面量。MCP 文本输出会打印该字面量，结构化响应则在 `structuredContent.response.data.unserializable` 中暴露它。

```bash
agent-browser open                    # 启动浏览器（不导航）；停留在 about:blank
agent-browser open <url>              # 启动并导航（别名：goto、navigate）
agent-browser read [url]              # 抓取智能体可读文本，或读取已渲染的活动标签页 DOM
agent-browser click <sel>             # 点击元素（--new-tab 在新标签页打开）
agent-browser dblclick <sel>          # 双击
agent-browser fill <sel> <text>       # 清空并填写
agent-browser type <sel> <text>       # 在元素中输入
agent-browser press <key>             # 按键（Enter、Tab、Control+a）（别名：key）
agent-browser keyboard type <text>    # 在当前焦点处输入（无需选择器）
agent-browser keyboard inserttext <text>  # 不触发按键事件地插入文本
agent-browser keydown <key>           # 按住键
agent-browser keyup <key>             # 释放键
agent-browser hover <sel>             # 悬停在元素上
agent-browser focus <sel>             # 聚焦元素
agent-browser select <sel> <val>      # 按值或可见标签选择下拉项
agent-browser check <sel>             # 勾选复选框
agent-browser uncheck <sel>           # 取消勾选复选框
agent-browser scroll <dir> [px]       # 滚动（up/down/left/right，--selector <sel>）
agent-browser scrollintoview <sel>    # 将元素滚动到可视区
agent-browser drag <src> <dst>        # 拖放
agent-browser upload <sel> <files>    # 上传文件
agent-browser screenshot [path]       # 截图（--full 截全页）
agent-browser screenshot --annotate   # 带编号元素标注的截图
agent-browser screenshot --if-changed # 推荐：跳过未变化的图像以节省 token
agent-browser screenshot --threshold 0.01 # 忽略至多影响 1% 像素的变化
agent-browser screenshot --screenshot-dir ./shots    # 保存到自定义目录
agent-browser screenshot --screenshot-format jpeg --screenshot-quality 80
agent-browser pdf <path>              # 将页面保存为 PDF
agent-browser snapshot                # 带引用（ref）的无障碍树
agent-browser eval <js>               # 运行 JavaScript
agent-browser connect <port|url>      # 通过 CDP 连接浏览器
agent-browser stream enable [--port <port>]  # 启动运行时 WebSocket 流式输出
agent-browser webmcp list                     # 列出实验性页面工具
agent-browser webmcp invoke <tool> --params @input.json
agent-browser stream status           # 显示运行时流式输出状态与绑定端口
agent-browser stream disable          # 停止运行时 WebSocket 流式输出
agent-browser close                   # 关闭浏览器（别名：quit、exit）
agent-browser close --all             # 关闭所有活动会话
agent-browser mcp                     # 启动 MCP stdio 服务器
agent-browser mcp call <tool> <json>  # 运行一个 MCP 工具并打印结果
```

对 `fill` 与 `type`，请把选项放在可选的 `--` 标记之前。标记之后的文本按字面处理，包括形似 flag 的值。例如，`agent-browser fill "#search" -- --json` 会填入 `--json`；`agent-browser --json type "#search" --clear --delay 10 -- --clear` 会先清空字段，再输入 `--clear`。MCP 的 `agent_browser_fill` 与 `agent_browser_type` 按字面传递键入的 `text` 值，因此不需要该标记。

浏览器响应会在首次发现及目录变化时自动播报 WebMCP 工具。摘要只包含名称、简述、来源与 frame ID。选一个相关工具，先通过 `agent-browser webmcp list <tool> --frame <frame-id> --json` 获取完整 schema，再调用它。schema 与注解绝不会主动附带。未变化的目录与没有工具的页面不增加上下文。JSON 以 `data.webmcp` 暴露更新；CLI 与 MCP 文本包含同样的有界摘要。更新语义与安全性见 [WebMCP](/webmcp)。

当其他元素覆盖了目标点击点时，点击会在派发前失败。错误会指明覆盖元素，例如 `covered by <div#consent-banner>`。请先关掉或处理该元素，重新快照，再重试原操作。当元素隐藏、禁用或不在视口内时，click 与 dblclick 会报错而非假装成功。`click --new-tab` 直接打开链接 URL，因此不适用这些检查。

无头 Chromium 截图会隐藏原生滚动条，以保证图像输出一致。启动时传入 `--hide-scrollbars false` 可保留原生滚动条。

```bash
agent-browser get text <sel>          # 获取文本内容
agent-browser get html <sel>          # 获取 innerHTML
agent-browser get value <sel>         # 获取输入值
agent-browser get attr <sel> <attr>   # 获取属性
agent-browser get title               # 获取页面标题
agent-browser get url                 # 获取当前 URL
agent-browser get cdp-url             # 获取 CDP WebSocket URL
agent-browser get count <sel>         # 统计匹配元素数量
agent-browser get box <sel>           # 获取包围盒
agent-browser get styles <sel>        # 获取计算样式
```

`get cdp-url` 报告已在运行的浏览器的 CDP WebSocket URL。它要求浏览器已在运行，绝不启动浏览器。只含 `get cdp-url` 命令的批量执行也会跳过浏览器启动；混合批量则可能为其他命令启动浏览器。

## 读取智能体友好的文本

```bash
agent-browser read
agent-browser read https://example.com/article
agent-browser read https://example.com/article --filter overview
agent-browser read https://example.com/article --outline
agent-browser read https://docs.example.com --llms index --filter auth
agent-browser read https://docs.example.com --llms full --filter auth
agent-browser read example.com/article --require-md
agent-browser read https://example.com/article --json
```

`read` 无需启动 Chrome 即可抓取 URL。省略 URL 时，读取当前浏览器会话中活动标签页已渲染的 DOM，包括浏览器认证状态与客户端更新。显式 URL 读取默认发送 `Accept: text/markdown`；首个响应不是 markdown 时会尝试在同一 URL 后追加 `.md`；再沿祖先路径向 `/` 逐级查找最近的 `llms.txt` 以匹配文档链接；有 markdown 或纯文本时打印之，否则回退到从 HTML 提取的可读文本。不带 URL 的 `--llms` 与 `--require-md` 使用活动标签页的 URL，因为它们依赖 HTTP 资源。`read` 不会读取 `llms-full.txt`，除非你明确要求。

选项：`--raw` 不做 HTML 提取直接打印响应体；`--require-md` 在服务器不返回 `Content-Type: text/markdown` 时失败；`--outline` 打印单页的紧凑标题大纲；`--llms index` 打印紧凑的最近祖先 `llms.txt` 链接列表；`--llms full` 读取最近祖先的 `llms-full.txt`；`--filter <text>` 收窄页面小节、llms 链接/小节或大纲标题；`--timeout <ms>` 更改请求超时。`--allowed-domains`、`--content-boundaries`、`--max-output` 等全局防护同样适用于 read 的抓取与输出。

## 查找元素

带动作的语义定位器（`click`、`fill`、`check`、`hover`、`text`）：

```bash
agent-browser find role <role> <action> [value]
agent-browser find text <text> <action> [value]
agent-browser find label <label> <action> [value]
agent-browser find placeholder <ph> <action> [value]
agent-browser find alt <text> <action> [value]
agent-browser find title <text> <action> [value]
agent-browser find testid <id> <action> [value]
agent-browser find first <sel> <action> [value]
agent-browser find last <sel> <action> [value]
agent-browser find nth <n> <sel> <action> [value]
```

选项：

- `--name <name>`：按无障碍名称过滤角色
- `--exact`：精确且区分大小写的匹配。对 `role` 作用于无障碍名称，其默认为不区分大小写的子串匹配

示例：

```bash
agent-browser find role button click --name "Submit"
agent-browser find role heading text --name "Skills"     # 隐式角色可用：<h2>=heading、<ul>=list、顶层 <header>=banner
agent-browser find label "Email" fill "test@test.com"
agent-browser find alt "Logo" click
agent-browser find first ".item" click
agent-browser find last ".item" text
agent-browser find nth 2 ".card" hover
```

## 等待

```bash
agent-browser wait <selector>         # 等待元素
agent-browser wait <ms>               # 等待时间
agent-browser wait --text "Welcome"   # 等待文本（子串匹配）
agent-browser wait --url "**/dash"    # 等待 URL 模式
agent-browser wait --load domcontentloaded # 等待 DOMContentLoaded
agent-browser wait --load load        # 等待 load 事件
agent-browser wait --load networkidle # 仅用于已知会安静下来的页面
agent-browser wait --fn "condition"   # 等待 JS 条件
agent-browser wait --download [path]  # 等待下载
agent-browser wait --fn "!document.body.innerText.includes('Loading...')"  # 等待文本消失
agent-browser wait "#spinner" --state hidden           # 等待元素消失
```

选择器等待中，`--state` 接受 `visible`、`hidden`、`attached` 或 `detached`，且不能与 URL、load、函数、文本、下载或毫秒等待模式组合。全局的认证状态 `--state <path>` 仍可放在 `wait` 之前，与其他命令一样。

页面变化后，优先选择能代表你所需状态的选择器、文本、URL 或 JavaScript 条件。只在页面确定会安静下来时才用 `networkidle`，因为 SSE、WebSocket、轮询与长轮询可能让它永远无法满足。

load 状态等待会耗尽全部超时预算（取自 `--timeout` 或 `AGENT_BROWSER_DEFAULT_TIMEOUT`），到期时返回错误。

## 下载

```bash
agent-browser download <sel> <path>   # 点击元素触发下载
agent-browser wait --download [path]  # 等待任意下载完成
```

`wait --download` 返回最早一个尚未被先前 wait 领取的下载，包括在该命令运行前就已完成的那个，因此它可以排在触发下载的命令之后。带 `[path]` 时文件会移动过去；不带时，输出的是浏览器保存的位置。保存到本地路径只适用于 agent-browser 自己启动的浏览器：在 `--cdp`、`--auto-connect` 或提供商之下，保存文件由远端命名，因此 `download` 与 `wait --download [path]` 会被拒绝。

用 `--download-path <dir>`（或 `AGENT_BROWSER_DOWNLOAD_PATH` 环境变量）设置默认下载目录。不设置时，下载进入一个临时目录，浏览器关闭时删除。

上传、下载、本地文件、截图、PDF 与剪贴板的工作流见[文件与剪贴板](/files)。

## 鼠标

```bash
agent-browser mouse move <x> <y>      # 瞬时移动鼠标
agent-browser mouse move 600 400 --duration 250 --steps 24
agent-browser mouse move 600 400 --human --seed 42
agent-browser mouse down [button]     # 按下按键
agent-browser mouse up [button]       # 释放按键
agent-browser mouse wheel <dy> [dx]   # 滚轮
```

滚轮在当前被跟踪的指针处滚动，指针初始位于 `0,0`。滚轮派发失败时，被跟踪的指针保持不变。

鼠标坐标与滚轮增量接受有限小数；非法的传入值会被拒绝。对 `mouse wheel`，省略的 `dy` 与 `dx` 分别默认为 `100` 与 `0`，显式的 `0` 值会保留。

要滚动别处，请先移动指针：

```bash
agent-browser mouse move 600 400
agent-browser mouse wheel 100
```

对 `click`、`drag` 或 `mouse move` 使用 `--human`，可获得从当前光标位置出发的曲线缓动移动。对 `mouse move`，`--duration` 设定包含浏览器响应时间在内的目标总毫秒数，`--steps` 设定事件数，`--seed` 使路径可复现。浏览器缓慢时实际耗时仍可能超出请求的时长。

## Cookie 与存储

```bash
agent-browser cookies                 # 获取全部 Cookie
agent-browser cookies set <name> <val> # 设置 Cookie
agent-browser cookies clear           # 清空 Cookie

agent-browser storage local           # 获取全部 localStorage
agent-browser storage local <key>     # 获取指定键
agent-browser storage local set <k> <v>  # 设置值
agent-browser storage local clear     # 清空全部

agent-browser storage session         # sessionStorage 同理
```

读取最多接受一个键，设置要求一键一值，清空不接受操作数。裸键是单键读取的简写。

Cookie 的操作有 `get`（默认）、`set`、`clear`；未知操作返回错误。Cookie 属性使用 kebab-case flag，如 `--http-only` 与 `--same-site`。旧式拼写 `--httpOnly` 与 `--sameSite` 仍被接受。设置单个 Cookie 时，未知 flag 与多余参数返回错误。

```bash
agent-browser cookies set session_id abc123 --http-only --same-site Strict
```

### 稳定的标签页 id 与标签

标签页 id 是形如 `t1`、`t2`、`t3` 的稳定字符串。会话内绝不复用，因此即使其他标签页开关，`t2` 也始终指向同一个标签页。`t` 前缀与 `@e1` 元素引用的约定相呼应，但与位置序数不可互换——`agent-browser tab 2` 会报错并给出提示信息；请使用 `t2`。

你也可以在创建标签页时指定一个好记的标签（`docs`、`app`、`admin`），并在任何接受 id 的地方使用它：

```bash
agent-browser tab new --label docs https://docs.example.com
agent-browser tab docs          # 切换到 docs 标签页
agent-browser snapshot          # 为 docs 填充引用（ref）
agent-browser click @e3         # click 使用 docs 的引用
agent-browser tab close docs    # 按标签关闭
```

标签绝不自动生成，导航时也绝不改写——智能体把标签页命名为 `docs` 后，该名称一直保留到标签页关闭。标签在会话内唯一；用已存在的标签再建一个标签页会报错。

标签以字母开头，只能包含字母、数字、`-` 或 `_`，且不能使用保留的 `t<N>` 或 `T<N>` 标签页 id 形式。被拒绝的标签会保留当前标签页的引用（ref）与所选框架。

通过 `tab new` 或 `click --new-tab` 打开的标签页，会在首个文档加载前继承会话的设置：User-Agent、`set headers`、`set credentials`、源级 `--headers`、初始化脚本、`route` 规则与模拟覆盖（配色方案、时区、语言环境、地理位置、离线）。关闭离线模式或将 headers 设为 `{}`，可恢复后续标签页的默认设置。

`tab list --json` 还会报告每个标签页的 CDP `targetId`，且任何接受标签页引用的地方都接受 target id（`tab <targetId>`、`tab close <targetId>`）。与作为守护进程内计数器的 `t<N>` id 不同，target id 在守护进程重启后保持稳定。每个会话按 target id 绑定其活动标签页，守护进程重启后回到它；开启 `--pin-tab` 后绑定是严格的，被绑定的标签页关闭会产生 `tab_gone` 错误而非静默回退。JSON 错误包含 <code>code: "tab_gone"</code>、<code>data.targetId</code> 与可选的脱敏 <code>data.lastUrl</code>。批量输出在 <code>result</code> 下携带恢复对象。多会话工作流见 [CDP 模式](/cdp-mode)。

引用（`@e1` 等）的作用域限于快照运行时的活动标签页，因此先切换标签页，再快照并交互：

```bash
agent-browser tab docs          # 先切换
agent-browser snapshot          # docs 的引用
agent-browser click @e3         # 使用 docs 的引用
```

### 被丢弃标签页的恢复

浏览器为省内存会丢弃后台标签页，使其没有可驱动的渲染器。切换到被丢弃的标签页会重新激活它，这会重载页面并重置未保存的状态；切换结果会附加 `"revived": true`，让重载可见而非静默发生。页面被 JavaScript 对话框暂停的标签页是存活而非丢弃状态：切换不会动它，只会附加 `"dialogBlocked": true`。用 `dialog accept` 或 `dialog dismiss` 处理对话框后，标签页保留其状态。关闭活动标签页而落到被丢弃的后继标签页时，同样会以这种方式恢复它，并报告 `"activeTabRevived": true`。

### 快照增量

```bash
agent-browser snapshot --delta
agent-browser snapshot --delta --full
```

`snapshot --delta` 按标签页与选项组合返回 `full`、`unchanged` 或增量更新。URL 变化或大增量返回完整状态；`--full` 重置基线。将增量的 `changes` 应用于引用（ref）元数据、`treeChange` 应用于上一棵树：按换行拆分，把从零基 `startLine` 起的 `deleteCount` 行替换为 `lines`，再拼接回去。推进到 `revision` 之前，先将两者应用于 `baseRevision`。

### iframe 支持

快照期间自动检测 iframe。`Iframe` 节点会被解析，其内容内联展示在快照输出中 iframe 元素的下方。分配给 iframe 内部元素的引用（ref）携带框架上下文，因此 `click`、`fill` 等交互无需手动切换框架。

```bash
agent-browser snapshot -i
# @e3 [Iframe] "payment-frame"
#   @e4 [input] "Card number"
#   @e5 [button] "Pay"

# 直接使用引用交互——无需切换框架
agent-browser fill @e4 "4111111111111111"
agent-browser click @e5

# 或切换框架上下文以获取限定范围的快照
agent-browser frame @e3
agent-browser snapshot -i             # 仅该 iframe 内部的元素
agent-browser frame main              # 返回主框架
```

`frame` 命令接受元素引用（`@e3`）、CSS 选择器（`"#my-iframe"`）或框架名称/URL。

## 认证保险库

```bash
agent-browser auth save <name> [opts]    # 保存认证配置文件（profile）
agent-browser auth login <name>          # 用已保存的凭据登录
agent-browser auth login <name> --no-navigate
                                          # 源校验后使用活动页面
agent-browser auth login <name> --credential-provider <plugin> [--item <ref>] [--url <url>]
                                          # 从插件解析凭据
agent-browser auth login <name> --username-selector <s> --password-selector <s> [--submit-selector <s>]
                                          # 为单次登录覆盖选择器
agent-browser auth list                  # 列出已保存的 profile（仅名称与 URL）
agent-browser auth show <name>           # 显示 profile 元数据（不含密码）
agent-browser auth delete <name>         # 删除已保存的 profile
agent-browser plugin add <ref>           # 从 npm 或 GitHub 添加插件
agent-browser plugin list                # 列出已配置的插件
agent-browser plugin show <name>         # 显示某个已配置的插件
agent-browser plugin run <name> <type> --payload <json>
                                          # 运行任意插件请求
```

保存选项：

- `--url <url>`：登录页 URL（必填）
- `--username <user>`：用户名（必填）
- `--password <pass>`：密码（必填，除非用 `--password-stdin`）
- `--password-stdin`：从 stdin 读取密码（推荐，避免进入 shell 历史）
- `--username-selector <sel>`：用户名字段的自定义 CSS 选择器
- `--password-selector <sel>`：密码字段的自定义 CSS 选择器
- `--submit-selector <sel>`：提交按钮的自定义 CSS 选择器

`auth login` 会按布局尺寸、计算的可见性与透明度、禁用/只读状态过滤匹配的控件，包括自定义 CSS 选择器。如果选中的凭据字段在输入前被替换或转移焦点，命令会失败且不提交。

`auth login` 以 `load` 导航，然后等待用户名/密码/提交选择器出现后再交互。这提升了 SPA 登录页（字段在初始加载后才渲染）上的可靠性。

在页面内点击、通过人机验证、关闭同意弹窗或其他必须延续到凭据输入的有状态步骤之后，使用 `--no-navigate`：

```bash
agent-browser open https://example.com/
agent-browser click "a[href='/login']"
agent-browser auth login work --no-navigate
```

该 flag 只抑制 auth-login 最初的导航。它要求已存在活动的顶层 HTTP(S) 页面，并按协议、主机与有效端口将该页面与生效的凭据 URL 比较。路径、查询与片段可以不同。等待、填写、点击提交以及提交触发的导航保持不变。命令级 `--url` 覆盖 profile 或提供商的 URL 元数据，作为预期源约束而非导航目标。

插件登录选项：

- `--credential-provider <plugin>`：从已配置的插件解析凭据
- `--item <ref>`：提供商专属的保险库条目引用
- `--url <url>`：登录 URL 覆盖
- `--no-navigate`：先对照生效的凭据源校验活动的顶层页面，再使用它
- `--username-selector <sel>`：本次登录的用户名选择器覆盖
- `--password-selector <sel>`：本次登录的密码选择器覆盖
- `--submit-selector <sel>`：本次登录的提交选择器覆盖

凭据提供商插件经 `agent-browser.plugin.v1` stdio JSON 协议在进程外运行。它们把凭据返回给守护进程供单次登录使用，agent-browser 不会在本地保存这些凭据。

其他插件能力使用同一协议：

- `browser.provider`：用 `--provider <name>` 使用该插件，返回 CDP WebSocket URL
- `launch.mutate`：在 Chrome 启动前追加本地启动参数、扩展或初始化脚本
- `command.run`：通过 `agent-browser plugin run` 运行任意命名空间化请求

`plugin run` 用于 `command.run` 与自定义能力。核心能力与协议请求类型走各自的专用命令路径。

```bash
echo "pass" | agent-browser auth save github --url https://github.com/login --username user --password-stdin
agent-browser auth login github
agent-browser plugin add agent-browser-plugin-vault --name vault
agent-browser auth login my-app --credential-provider vault --item "My App"
agent-browser auth login my-app --credential-provider vault --item "My App" --no-navigate --url https://identity.example.com/login
agent-browser --provider cloud-browser open https://example.com
agent-browser plugin run captcha captcha.solve --payload '{"siteKey":"...","url":"https://example.com"}'
agent-browser auth list
```

## 仪表盘

## React / Web Vitals

React 命令要求启动时带 `--enable react-devtools`（在页面 JS 运行前安装 React DevTools hook）。`vitals` 与 `pushstate` 适用于任何站点。

## 无障碍审计

对当前页面运行内置的 axe-core 审计，或先导航到某个 URL。内置的引擎无需 CDN 请求即可工作，并能在严格的页面 CSP 下运行。它跨页面的框架树运行私有的部分审计，不经页面消息传递就合并序列化结果，因此页面自带的 `window.axe` 值保持原样，iframe 内的违规也保留其框架选择器路径。无障碍审计需要 CDP 浏览器，Safari 与 iOS WebDriver 会话不可用。

```bash
agent-browser a11y                                 # 审计当前页面
agent-browser a11y https://example.com             # 先导航再审计
agent-browser a11y --tags wcag2a,wcag2aa           # 按 axe 规则标签过滤
agent-browser a11y --selector "#main"              # 限定到某个子树
agent-browser a11y https://example.com --json      # 结构化结果
```

默认输出列出违规与未完成的检查，附带影响级别、规则 ID、修复指引与失败节点路径。JSON 输出保留 axe 的 `target` 选择器路径数组，包括 shadow DOM 边界的嵌套数组与框架边界的多个条目。

```bash
--model <name>           # chat 的 AI 模型（或 AI_GATEWAY_MODEL 环境变量）
-v, --verbose            # 显示工具命令及其原始输出（chat）
-q, --quiet              # 只显示 AI 文本响应（chat）
--config <path>          # 使用自定义配置文件
--debug                  # 调试输出
--relaunch               # 即使没有设置变化也重新启动会话的浏览器
```

在 `batch` 中，`--relaunch` 只重新启动浏览器一次：由第一个能启动浏览器的命令携带它。从不启动浏览器的命令（如 `read`）、被策略拒绝或等待确认的命令会把它传递给下一个命令。

配置文件与环境变量见[配置](/configuration)。代理服务器、绕过与凭据设置见[代理](/proxy)。

## 批量执行

在单次调用中执行多条命令。命令可以作为带引号的参数传入，也可以经 stdin 以 JSON 管道传入。

```bash
# 参数模式：每个带引号的参数是一条完整命令
agent-browser batch "open https://example.com" "snapshot -i" "screenshot"

# 加 --bail 在首个错误处停止
agent-browser batch --bail "open https://example.com" "click @e1" "screenshot"

# stdin 模式：以 JSON 管道传入命令
echo '[
  ["open", "https://example.com"],
  ["snapshot", "-i"],
  ["click", "@e1"],
  ["screenshot", "result.png"]
]' | agent-browser batch --json

echo '[["fill", "#password", "secret"]]' | agent-browser batch --json --omit-command
```

<table>
  <thead>
    <tr><th>选项</th><th>说明</th></tr>
  </thead>
  <tbody>
    <tr><td><code>--bail</code></td><td>首个错误即停止（默认：继续执行全部命令）</td></tr>
    <tr><td><code>--json</code></td><td>以 JSON 数组输出结果</td></tr>
    <tr><td><code>--omit-command</code></td><td>配合 <code>--json</code>，把每个 <code>command</code> 数组替换为稳定的零基 <code>index</code> 字段</td></tr>
  </tbody>
</table>

把 `--init-script`、`--enable` 等全局 flag 放在外层 batch 调用上。命令专属的选项与字面命令参数留在每个条目内。

```bash
agent-browser --enable react-devtools batch "open" "navigate data:text/html,<h1>hi</h1>"
```

使用 `--json --omit-command` 时，成功、失败或 `--bail` 的各行都带稳定的零基 `index` 字段；默认 JSON 输出保留 `command` 字段。它只移除命令数组，并不让输出对机密安全。错误与响应数据不变：`type` 会回显键入的文本，`get value`/`eval` 可能返回输入值。MCP 的 `agent_browser_batch` 工具接受 `omitCommand: true`。

## MCP 服务器

```bash
agent-browser mcp
agent-browser mcp --tools all
agent-browser mcp --tools core,network,react
agent-browser mcp call agent_browser_open '{"url":"https://example.com"}'
agent-browser mcp --config /path/to/trusted-config.json
agent-browser mcp call agent_browser_open '{"url":"https://example.com"}' --config /path/to/trusted-config.json
echo '{"selector":"@e2"}' | agent-browser mcp call agent_browser_click -
```

经 stdio 启动 Model Context Protocol 服务器。MCP 客户端把它作为子进程启动，并在 stdin 与 stdout 上交换换行分隔的 JSON-RPC。服务器默认采用 MCP 协议 2025-11-25，并在初始化期间接受较旧的受支持客户端协议版本。带 schema 未声明参数的工具调用会以 invalid-params 错误失败，错误会指明未知键并列出该工具自身的参数。

`mcp call` 无需 stdio 会话即可运行一个 MCP 工具，并把 `tools/call` 结果打印为 JSON，agent-browser 版本位于 `_meta.agentBrowserVersion`。工具参数以 JSON 对象传入，或用 `-` 从 stdin 读取。除非 `--tools` 把调用限制到某些 profile，所有工具都可用。退出码：成功为 0，工具报错为 1，未知工具或非法参数为 2。适合无法在工具调用之间保持 stdio 会话的运行时（如 serverless 智能体）使用。`AGENT_BROWSER_ALLOWED_DOMAINS` 等访问设置来自环境，与服务器一致。

对运行 CLI 的工具调用，`structuredContent.response` 包含解析后的 CLI JSON。仅当输出无法解析为 JSON 时才包含 `stdout`；`exitCode` 与 `stderr` 始终包含。

在 Vercel Sandbox 中，`startAgentBrowserMcp` 经沙盒命令的 stdin 运行服务器。见 [Next.js + Vercel](/next#mcp-server-over-stdin)。

默认工具 profile 是 `core`，让日常浏览器自动化的 MCP 上下文保持精简。用 `--tools all` 获得完整的类型化 CLI 对等面，或用逗号组合 profile，如 `--tools core,network,react`。

Profile：

- `core` - 默认。导航、快照、交互、等待、读取、截图、JavaScript eval、close、标签页基础与 profile 发现
- `network` - 网络路由、请求检查、HAR、头、凭据、离线
- `state` - Cookie、存储、认证、已保存状态、会话、profile、技能
- `debug` - 控制台/错误、trace、性能分析、录制、无障碍审计、剪贴板、插件、doctor、仪表盘、install、upgrade、chat、diff、batch、confirm/deny
- `tabs` - 后退/前进/重载、标签页、窗口、框架、对话框
- `react` - React tree/inspect/renders/suspense、vitals、pushstate
- `mobile` - 视口/设备/地理位置/媒体、触摸、滑动、鼠标、键盘
- `all` - 每个 MCP 工具，包括完整的类型化 CLI 对等面

MCP 客户端配置示例：

```json
{
  "mcpServers": {
    "agent-browser": {
      "command": "agent-browser",
      "args": ["mcp"]
    }
  }
}
```

使用 `--tools all` 时，服务器跨 CLI 命令面暴露类型化工具，涵盖导航、快照、输入、等待、截图/PDF、get/is/find、鼠标、网络、存储、Cookie、标签页、窗口、框架、对话框、trace、录制、无障碍审计、剪贴板、认证、状态、iOS、diff、React、vitals、会话、技能、插件、doctor、仪表盘、install、upgrade、chat、eval 与 close。

常用工具包括：

- `agent_browser_tools_profiles`
- `agent_browser_open`
- `agent_browser_snapshot`
- `agent_browser_click`
- `agent_browser_fill`
- `agent_browser_type`
- `agent_browser_press`
- `agent_browser_wait_for_selector`
- `agent_browser_screenshot`
- `agent_browser_get_url`
- `agent_browser_eval`
- `agent_browser_close`

每个工具都有 `url`、`selector`、`text`、`key` 等类型化字段，因此 MCP 客户端展示有意义的审批提示而非原始命令数组。工具发现是分页的，并带只读/开放世界注解，现代 MCP 客户端可以渐进加载庞大的类型化面。

每个工具还接受共享参数 `session`、`restore`、`allowedDomains`、`extraArgs`、`timeoutMs`、`namespace`、`restoreSave`、`restoreCheckUrl`、`restoreCheckText`、`restoreCheckFn`、`caCert`、`useSystemCa`、`clearCaCert`、`idleTimeout` 与 `relaunch`。工具的 schema 只列出对它通常重要的那些：`session` 出现在每个工具上，`restore` 与 `relaunch` 出现在 `open` 与 `tab_new` 上，`allowedDomains` 与 `extraArgs` 出现在 `open`、`tab_new` 与 `read` 上，`timeoutMs` 出现在会导航、等待或运行脚本的工具上。服务器的 `initialize` 指令描述了全部参数。`allowedDomains` 映射到 `--allowed-domains`，激活同样的 WebRTC 约束与启动模式限制，且当服务器已设置允许域名时会被拒绝。`idleTimeout` 映射到 `--idle-timeout`，接受 `30s`、`5m`、`1h` 或原始毫秒等取值，`0` 禁用空闲关闭。`relaunch: true` 映射到 `--relaunch`。`extraArgs` 携带逐命令选项与 `--engine` 等显示或模拟 flag；它不能设置 `--config` 或改变网络、文件、策略与主机访问的全局 flag。主机级选项请放进 MCP 服务器的环境或所选配置。

默认情况下，工具调用使用与 CLI 相同的配置发现与环境变量。用工具参数中的 `session`，或设置 `AGENT_BROWSER_SESSION`，来隔离浏览器状态。

向 `agent-browser mcp` 或 `agent-browser mcp call` 传 `--config <trusted-path>` 可选定一个受信任的配置文件。MCP 工具子进程只加载该文件，替代默认的用户/项目发现。请把必需的安全策略放进其中。环境变量与被接受的逐工具 CLI 参数保持正常优先级。

## 命令链接

在单次 shell 调用中用 `&&` 串联命令。浏览器通过后台守护进程保持运行，因此链接自然生效，且比分开调用更高效：

```bash
agent-browser open example.com && agent-browser wait --load domcontentloaded && agent-browser snapshot -i
agent-browser fill @e1 "user@example.com" && agent-browser fill @e2 "pass" && agent-browser click @e3
agent-browser open example.com && agent-browser wait --load load && agent-browser screenshot page.png
```

不需要读取中间输出时用 `&&`。需要先解析输出时（如先快照发现引用，再用这些引用交互）请分开执行命令。

## 本地文件

用 `file://` URL 打开本地文件（PDF、HTML）：

```bash
agent-browser --allow-file-access open file:///path/to/document.pdf
agent-browser --allow-file-access open file:///path/to/page.html
agent-browser screenshot output.png
```

`--allow-file-access` flag 允许 JavaScript 访问其他本地文件。仅限 Chromium。

本地文件、上传、下载、截图、PDF 与剪贴板的工作流见[文件与剪贴板](/files)。
