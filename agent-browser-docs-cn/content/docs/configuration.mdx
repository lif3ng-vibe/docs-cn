创建 `./agent-browser.json` 即可设置持久化的项目默认值，免去在每条命令上重复传 flag。

## 配置文件位置

agent-browser 会检查两个位置，并按优先级合并：

<table>
  <thead>
    <tr><th>优先级</th><th>位置</th><th>作用域</th></tr>
  </thead>
  <tbody>
    <tr><td>1（最低）</td><td><code>~/.agent-browser/config.json</code></td><td>用户级默认值</td></tr>
    <tr><td>2</td><td><code>./agent-browser.json</code></td><td>白名单内的项目默认值</td></tr>
    <tr><td>3</td><td><code>AGENT_BROWSER_*</code> 环境变量</td><td>覆盖配置值</td></tr>
    <tr><td>4（最高）</td><td>CLI flag</td><td>覆盖一切</td></tr>
  </tbody>
</table>

允许的项目级取值覆盖用户级取值；环境变量覆盖两者；CLI flag 永远优先。自动发现的 `./agent-browser.json` 只接受 `headed`、`json`、`debug`、`userAgent`、`hideScrollbars`、`annotate`、`colorScheme`、`maxOutput`、`screenshotQuality`、`screenshotFormat` 与 `idleTimeout`。其他运行时键——包括 `extensions`、`initScripts`、状态、信任、策略、会话、连接及路径设置——会被忽略并给出警告。`$schema` 元数据键会被静默忽略。高级设置请放入 `~/.agent-browser/config.json`，或通过 `--config` / `AGENT_BROWSER_CONFIG` 加载受信任的文件。

使用 `--config <path>` 或 `AGENT_BROWSER_CONFIG` 环境变量可以只加载某个受信任的配置文件，替代默认发现。环境变量与 CLI flag 依然覆盖其中的取值：

```bash
agent-browser --config ./ci-config.json open example.com
AGENT_BROWSER_CONFIG=./ci-config.json agent-browser open example.com
```

## 配置示例

```json
{
  "headed": true,
  "userAgent": "my-agent/1.0",
  "hideScrollbars": false,
  "colorScheme": "dark",
  "maxOutput": 50000,
  "screenshotQuality": 80,
  "screenshotFormat": "png",
  "idleTimeout": "30m"
}
```

提供有 [JSON Schema](https://agent-browser.dev/schema.json)，可用于 IDE 自动补全与校验。在配置文件中加一个 `$schema` 键即可启用：

```json
{
  "$schema": "https://agent-browser.dev/schema.json",
  "headed": true
}
```

## 常见配置

以下示例使用的设置不在项目配置白名单内。请保存到 `~/.agent-browser/config.json`，或用 `--config` 显式加载该文件。

### 本地开发

```json
{
  "headed": true,
  "profile": "./browser-data"
}
```

### 代理之后

```json
{
  "proxy": "http://proxy.corp.example.com:8080",
  "proxyBypass": "localhost,*.internal.com",
  "caCert": "/etc/ssl/certs/proxy-ca.crt"
}
```

在 Linux 上，`caCert` 会将给定的 CA 证书或 PEM 捆绑包导入一个独立的 NSS 数据库，供本地启动的 Chromium 使用。主机名校验、有效期校验及其他无关 CA 的校验仍然启用。后续命令省略该设置时，导入的 CA 继续生效。设置不同的证书内容或 `clearCaCert: true` 会重新启动 Chromium，而无需重启守护进程。`agent-browser install --with-deps` 会安装所需的 `certutil`；否则请在 Debian/Ubuntu 上安装 `libnss3-tools`，或在 RPM 系 Linux 上安装 `nss-tools`。浏览器信任不支持 Chrome 配置文件（profile）、CDP attach、提供商、Lightpanda、macOS 或 Windows。

`caCert` 与 `useSystemCa` 同样作用于 CLI 自身在各平台上的 HTTPS 请求。`read`、`install`、`upgrade` 与 `doctor` 会发起各自的 HTTPS 请求，默认信任内置的 Mozilla 根证书。在所有平台上，`--ca-cert` 会把该 CA 加入这些请求，`--use-system-ca` 则让它们改用操作系统信任库——后者已包含由 MDM 或企业镜像部署的 CA。`SSL_CERT_FILE` 作为回退 CA 文件使用，不可用时会被忽略并给出警告。这两个选项都不会关闭证书或主机名校验。对 `read` 而言，命令行上给定的选择在会话内持续生效直到 `close`，包括守护进程重启之后；`--no-ca-cert` 或 `--use-system-ca false` 可将其关闭。`read` 绝不会因这些选项而启动或重启浏览器。它们目前也不会改变 agent-browser 经 `--cdp`、`--auto-connect` 或提供商连接远端浏览器的方式。

拿不到 CA 证书时，可以退而忽略所有证书错误，这样安全性较低：

```json
{
  "proxy": "http://proxy.corp.example.com:8080",
  "proxyBypass": "localhost,*.internal.com",
  "ignoreHttpsErrors": true
}
```

### CI / Devcontainer

```json
{
  "args": "--no-sandbox,--disable-gpu",
  "ignoreHttpsErrors": true
}
```

请把这些设置放进 `~/.agent-browser/config.json` 或用 `--config` 加载的文件；自动发现的 `./agent-browser.json` 会忽略 `args` 并给出警告。

### iOS 测试

```json
{
  "provider": "ios",
  "device": "iPhone 16 Pro"
}
```

### AI 智能体安全

```json
{
  "contentBoundaries": true,
  "maxOutput": 50000,
  "allowedDomains": ["your-app.com", "*.your-app.com"],
  "actionPolicy": "./policy.json"
}
```

## 覆盖布尔选项

布尔 flag 可接受可选的 `true`/`false` 取值来覆盖配置：

```bash
agent-browser --headed false open example.com
```

裸 flag 等价于传 `true`：

```bash
agent-browser --headed open example.com       # 等同于 --headed true
agent-browser --headed true open example.com  # 显式指定
```

这适用于 `--headed`、`--debug`、`--json`、`--ignore-https-errors`、`--allow-file-access`、`--hide-scrollbars`、`--auto-connect`、`--annotate`、`--content-boundaries`、`--confirm-interactive`、`--no-auto-dialog` 等布尔 flag。

## 扩展

自动发现的项目配置会忽略 `extensions` 并给出警告。请把扩展路径放进用户配置或显式加载的配置，或设置 `AGENT_BROWSER_EXTENSIONS`，或传 `--extension`。

## 插件

在用户配置或用 `--config` 加载的文件中，通过 `plugins` 数组配置外部插件：

插件作者协议与实现示例见[插件](/plugins)页。使用 `agent-browser plugin add <ref>` 可自动生成这份配置；它默认写入 `~/.agent-browser/config.json`，加 `--project` 则写入 `./agent-browser.json`（仅与 `--config` 配合使用）。

```json
{
  "plugins": [
    {
      "name": "vault",
      "command": "agent-browser-plugin-vault",
      "args": [],
      "capabilities": ["credential.read"]
    },
    {
      "name": "cloud-browser",
      "command": "agent-browser-plugin-cloud-browser",
      "capabilities": ["browser.provider"]
    },
    {
      "name": "stealth",
      "command": "agent-browser-plugin-stealth",
      "capabilities": ["launch.mutate"]
    },
    {
      "name": "captcha",
      "command": "agent-browser-plugin-captcha",
      "capabilities": ["command.run", "captcha.solve"]
    }
  ]
}
```

自动发现的 `./agent-browser.json` 会忽略 `plugins` 并给出警告。要使用项目文件中的插件条目，请用 `--config` 加载它；该文件将替代默认发现。`AGENT_BROWSER_PLUGINS` 可用一个相同结构的 JSON 数组取代配置发现。

不要把保险库令牌或密码放进插件命令参数。请使用保险库厂商自己的登录/会话机制，或 agent-browser 配置之外的环境变量。

```bash
agent-browser plugin list
agent-browser auth login my-app --credential-provider vault --item "My App"
agent-browser --provider cloud-browser open https://example.com
agent-browser plugin run captcha captcha.solve --payload '{"siteKey":"...","url":"https://example.com"}'
```

`plugin run` 用于 `command.run` 与自定义能力（capability）。核心能力与协议请求类型走各自的专用命令路径。

## 错误处理

- **自动发现的配置文件**（`~/.agent-browser/config.json`、`./agent-browser.json`）缺失时静默忽略。
- **`--config <path>`** 指向缺失或格式非法的文件时报错退出。
- 自动发现文件中的**非法 JSON** 会向 stderr 打印警告，并在无该文件的情况下继续。
- 自动发现的项目配置中的**不支持的键**会被忽略并给出警告。
- 用户配置或显式加载配置中的**未知键**为保持向前兼容而静默忽略。

使用了高级键的既有项目配置，必须把这些设置迁到用户配置，或用 `--config` 显式加载。
