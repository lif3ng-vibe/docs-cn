运行多个相互隔离的浏览器实例：

```bash
# 不同会话
agent-browser --session agent1 open site-a.com
agent-browser --session agent2 open site-b.com

# 或通过环境变量
AGENT_BROWSER_SESSION=agent1 agent-browser click "#btn"

# 列出活动会话
agent-browser session list
# Output:
# Active sessions:
# -> default
#    agent1

# 显示当前会话
agent-browser session

# 生成稳定的、以 worktree 为作用域的会话 id
agent-browser session id --scope worktree --prefix next-dev-loop

# 查看守护进程、启动与恢复状态
agent-browser session info --json
```

## 会话隔离

每个会话都拥有独立的：

- 浏览器实例
- Cookie 与存储
- 导航历史
- 认证状态

## 修改运行中会话的设置

每条命令都会携带你为它设置的选项——无论来自 flag、环境变量还是配置文件。守护进程会将其与会话当前运行的设置比对，并按差异采取行动：

- 未指定的设置保持当前运行值。
- 与运行值相同的设置不产生任何动作，因此每条命令都重复 `--profile ./work` 并不会重启浏览器。
- 超时、`--action-policy`、`--confirm-actions`、`--no-auto-dialog` 以及恢复与固定相关设置会原地生效。
- `--profile`、`--args`、`--headed`、`--proxy`、`--state`、`--allowed-domains` 等启动类设置会重启浏览器，守护进程继续运行。

每一项生效的变更都会逐行打印到 stderr，并且所有变更都会列在 `--json` 响应的 `lifecycle.settings.changes` 中，标记 `applied: true` 或 `applied: false`。在没有浏览器运行时修改的启动类设置为 `applied: false` 且没有 stderr 输出，因为它要到下次启动才生效。两处的机密都会脱敏：密码与 CDP 请求头被隐藏，CDP URL 会去掉凭据和查询串。

从不启动浏览器的命令（如 `get cdp-url` 或 `session info`）只应用实时生效类设置；`get cdp-url` 则完全不发送启动类设置。对其余命令，启动类设置既不应用也不保留；由会启动浏览器的命令再次携带。启动类设置只有在使用它的启动成功后才被保留；若启动失败，会话保留之前的启动设置——唯一的例外是 `--allowed-domains`，它在启动失败后仍然保持安装状态，隔离因此绝不会被放松。被策略拒绝或等待确认的命令不会更改任何启动设置，浏览器继续运行。

安全设置（`--allowed-domains`、`--action-policy`、`--confirm-actions`）同样能在守护进程重启后保留。它们保存在会话 socket 旁的仅属主可访问文件中（socket 目录下的 `<session>.settings`），并在新值生效前写入，因此空闲超时过期、崩溃、kill 或升级都不会悄悄丢掉隔离。重启后的守护进程以存储值为起点；只有在没有文件时才使用环境变量，你传入的值会替换存储值（`--allowed-domains ""` 清除过滤器，且该清除会被保留）。相对的 `--action-policy` 路径会以设置它的命令所在目录解析为绝对路径存储，因此重启后的守护进程绝不会读取别的目录的策略。`close` 成功时该文件被删除。`close --all` 也会按存储的设置启动一个守护进程，从而关闭守护进程已消失但文件仍在的会话，规则相同；被策略拒绝或等待确认的 close 会保留该文件，CLI 触发的重启（升级、守护进程选项变更）也一样。如果文件存在但无法读取或解析，或在 Unix 上可被其他用户读取，守护进程会拒绝启动并指出该文件；用 `agent-browser --session <name> close` 即可清除。Windows 没有权限位检查，该文件依赖 socket 目录的访问规则。

描述由 agent-browser 自行启动的浏览器的设置（`--profile`、`--args`、`--executable-path`、`--extension`、`--proxy`、`--user-agent`、`--state` 等），对通过 `--cdp`、`--auto-connect` 或提供商附加的会话会被忽略：它们不会重启该浏览器，也不会开启新的云会话，并且会在 `lifecycle.settings.changes` 中以 `effect: "ignored"` 出现。切换之前继承的敏感设置值（`--state`、`--profile`、`--extension`、`--proxy` 及其凭据、`--executable-path`、`--args`）会被丢弃，因此本地启动产生的状态文件或代理凭据永远不会应用到外部浏览器。空的 `--provider` 会把提供商会话重置为本地启动；`--no-auto-connect` 对以 `--auto-connect` 附加的会话做同样的事。设置 `--state` 会替换继承的 `--profile` 或 `--extension`，设置 `--profile` 或 `--extension` 则会替换继承的 `--state`。

在批量（batch）命令中使用 `--relaunch` 时，浏览器只在第一条命令处重启一次。

会话的第一条命令仍会从守护进程启动时的环境继承初始设置，但连接目标（`--cdp`、`--auto-connect`、`--provider`）例外：它只在附加成功后才被保留，因此失败的附加不会被记住。

```bash
agent-browser --profile ./a open https://example.com
agent-browser --profile ./b get url
# ⚠ profile: ./a → ./b (--profile), relaunched browser
```

`--state <path>` 会在浏览器启动时加载该文件。再次传入相同路径不会重新加载；需要传 `--relaunch` 重启浏览器并重新加载。

## 共享浏览器中的标签页固定

只有当每个会话各自启动浏览器时才有完全隔离。当多个会话通过 `--cdp` 共享同一个 Chrome 时，区分它们的只有标签页的选择。每个会话都记得自己绑定的是哪个标签页（按 CDP target id，跨守护进程重启持久化），因此重启后的守护进程会重新附加到该会话自己的标签页，而不是接管最近活动的那个。

加上 `--pin-tab`（或设置 `AGENT_BROWSER_PIN_TAB=1`）可以让绑定变为严格模式：

```bash
agent-browser --session agent1 --cdp 9222 --pin-tab open https://site-a.com
agent-browser --session agent2 --cdp 9222 --pin-tab open https://site-b.com
```

启用 `--pin-tab` 后，绑定标签页已被关闭的会话会收到 `tab_gone` 错误，而不是悄悄操作别的会话的标签页；运行 `tab new <url>` 或从 `tab list` 中选择一个标签页即可恢复。JSON 输出包含 <code>"code": "tab_gone"</code>、<code>data.targetId</code> 以及可选的、已脱敏的 <code>data.lastUrl</code>。批量输出用 <code>result</code> 表示同一个恢复对象。该 flag 对会话具有粘性；传 `--no-pin-tab` 可再次关闭。详见 [CDP 模式](/cdp-mode)。

在固定标签页的会话运行期间，其他会话无法用 `tab <ref>` 抢占该标签页（`tab_locked`）；显式 `close` 会解除固定。

## Chrome 配置文件复用

复用现有登录状态最简单的方式：把 Chrome 配置文件（profile）名传给 `--profile`。agent-browser 会把该配置文件复制到临时目录（只读快照），并带着你现有的 Cookie 和会话启动 Chrome。

```bash
# 列出可用的 Chrome 配置文件
agent-browser profiles

# 复用默认 Chrome 配置文件的登录状态
agent-browser --profile Default open https://gmail.com

# 使用具名配置文件（按显示名或目录名）
agent-browser --profile "Work" open https://app.example.com

# 或通过环境变量
AGENT_BROWSER_PROFILE=Default agent-browser open https://gmail.com
```

## 持久化配置文件

若要一个跨浏览器重启持久保存状态的自定义配置文件目录，把路径传给 `--profile`：

```bash
# 使用持久化配置文件目录
agent-browser --profile ~/.myapp-profile open myapp.com

# 登录一次，之后复用已认证的会话
agent-browser --profile ~/.myapp-profile open myapp.com/dashboard

# 或通过环境变量
AGENT_BROWSER_PROFILE=~/.myapp-profile agent-browser open myapp.com
```

该配置文件目录会保存：

- Cookie 与 localStorage
- IndexedDB 数据
- Service Worker
- 浏览器缓存
- 登录会话

## 从你的浏览器导入登录状态

如果你已在 Chrome 中登录了某个网站，可以把这份认证状态抓取出来在 agent-browser 中复用。这是绕过登录流程、OAuth、SSO 或 2FA 最快的方式。

**第 1 步**：以远程调试方式启动 Chrome：

```bash
# macOS
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --remote-debugging-port=9222

# Linux
google-chrome --remote-debugging-port=9222
```

在这个 Chrome 窗口中登录你的目标网站。

`--remote-debugging-port` 会在 localhost 上暴露完整的浏览器控制权，任何本地进程都能连接。请只在可信机器上使用，完成后关闭 Chrome。

**第 2 步**：连接并保存认证状态：

```bash
agent-browser --auto-connect state save ./my-auth.json
```

**第 3 步**：在以后的会话中使用保存的认证：

```bash
# 启动时加载认证
agent-browser --state ./my-auth.json open https://app.example.com/dashboard

# 或加载到已启动的会话
agent-browser open about:blank
agent-browser state load ./my-auth.json
agent-browser open https://app.example.com/dashboard
```

保存的 localStorage 与 sessionStorage 是通过 Chrome DevTools 写入的，而非页面 JavaScript，且只在页面处于被保存的源（origin）上时进行。如果某个源重定向到了别处或加载失败，其存储会被跳过，其余部分仍会加载，`state load` 会把它列在 `skippedOrigins` 下。对启动时的 `--state` 与 `--restore`，`session info` 会把它列在 `restoreSkippedOrigins` 下。

配合 `--session <id> --restore`，导入的认证就能在重启后自动持久保存：

```bash
SESSION="$(agent-browser session id --scope worktree --prefix myapp)"
agent-browser --session "$SESSION" --restore --state ./my-auth.json open https://app.example.com/dashboard
# 从此该会话的状态自动保存/恢复
```

状态文件以明文包含会话令牌。请将其加入 `.gitignore`，不再需要时删除。静态加密见下方[状态加密](#状态加密)。

## 会话持久化

将 `--restore` 与稳定的 `--session` 配合使用，即可在浏览器重启之间自动保存和恢复 Cookie 与 localStorage：

```bash
# 为该 worktree 自动保存/加载状态
SESSION="$(agent-browser session id --scope worktree --prefix twitter)"
agent-browser --session "$SESSION" --restore open twitter.com

# 登录一次，之后状态自动持久化
agent-browser --session "$SESSION" --restore click "#login"

# 可选校验可防止一次糟糕的恢复覆盖之前的好状态
agent-browser --session "$SESSION" --restore --restore-check-text Dashboard open twitter.com
```

状态文件存储在 `~/.agent-browser/sessions/`，导航前自动加载。在默认的 `--restore-save auto` 策略下，恢复失败或校验失败会跳过自动保存。

配置了 `--restore` 或其他恢复键后，浏览器关闭时（显式 `close`、空闲超时或守护进程关闭）会保存状态，浏览器打开期间也会周期性保存，因此你手动关掉的浏览器窗口也会留下较新的保存。会话 ID 本身只隔离守护进程，并不启用持久化；没有恢复键时，关闭会丢弃临时浏览器状态（transient browser state）和打开的标签页。周期性自动保存会等待命令平息，然后每 `AGENT_BROWSER_AUTOSAVE_INTERVAL_MS` 最多保存一次（默认 30000；设为 `0` 则只在关闭时保存）。配置了持久化的空闲会话也会按相同间隔持续保存，因此页面自行发生的变化（令牌刷新、后台请求）也能被捕获。默认情况下，一小时没有命令或仪表盘输入后守护进程退出；可用 `--idle-timeout <time>` 或 `AGENT_BROWSER_IDLE_TIMEOUT_MS` 调整，`0` 表示禁用。有头、Safari/iOS WebDriver 以及用户手动附加的浏览器不受默认超时约束；提供商所有的云浏览器则受约束。状态保存遵循 `--restore-save` 策略。

### 恢复键规则

会话名与恢复名只接受 Unicode 字母和数字、连字符与下划线。例如 `café-東京_7` 是合法的，而 `my session` 因包含空格会被拒绝。

用 `agent-browser session id` 生成合法的键：

```bash
# 合法的生成键
agent-browser session id --scope worktree --prefix my-project

# 非法（会被拒绝）
agent-browser --session "../bad" --restore open example.com    # 路径穿越
agent-browser --session "my session" --restore open example.com # 含空格
agent-browser --session "foo/bar" --restore open example.com    # 含斜杠
```

## 状态加密

使用 AES-256-GCM 加密已保存的状态文件（Cookie、localStorage）：

```bash
# 生成 256 位密钥（64 个十六进制字符）
openssl rand -hex 32

# 设置加密密钥
export AGENT_BROWSER_ENCRYPTION_KEY=<your-64-char-hex-key>

# 此后状态文件会自动加密
agent-browser --session secure-session --restore open example.com

# state list 会显示加密状态
agent-browser state list
```

## 状态自动过期

自动删除过期的状态文件，防止无限累积：

```bash
# 设置过期时间（默认 30 天）
export AGENT_BROWSER_STATE_EXPIRE_DAYS=7

# 手动清理旧状态
agent-browser state clean --older-than 7
```

## 状态管理命令

```bash
# 列出所有已保存的状态
agent-browser state list

# 显示状态摘要（Cookie、源、域名）
agent-browser state show my-session-default.json

# 重命名状态文件
agent-browser state rename old-name new-name

# 清除特定会话名的状态
agent-browser state clear my-session

# 清除所有已保存的状态
agent-browser state clear --all

# 手动保存/加载（用于自定义路径）
agent-browser state save ./backup.json
agent-browser state load ./backup.json
```

## 已认证会话

使用 `--headers` 为特定源设置 HTTP 请求头：

```bash
# 请求头仅作用于 api.example.com
agent-browser open api.example.com --headers '{"Authorization": "Bearer <token>"}'

# 发往 api.example.com 的请求会带上认证头
agent-browser snapshot -i --json
agent-browser click @e2

# 导航到其他域名——不发送请求头
agent-browser open other-site.com
```

适用于：

- **跳过登录流程**——通过请求头完成认证
- **切换用户**——每个会话使用不同的认证令牌
- **API 测试**——访问受保护的端点
- **安全**——请求头限定在源内，不外泄

## 多源

```bash
agent-browser open api.example.com --headers '{"Authorization": "Bearer token1"}'
agent-browser open api.acme.com --headers '{"Authorization": "Bearer token2"}'
```

## 全局请求头

对所有域名生效的请求头：

```bash

```
