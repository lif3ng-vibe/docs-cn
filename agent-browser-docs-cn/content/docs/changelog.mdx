## v0.41.0

<p className="text-[#888] text-sm">2026 年 10 月 28 日</p>

### 破坏性变更

- **`@agent-browser/eve` 的工具现在来自 MCP 工具目录**。该扩展暴露 CLI 的 MCP 工具，而非 21 个手写工具，因此工具名与输入发生变化：`navigate` 改为 `open`，`evaluate` 改为 `eval`，`press_key` 改为 `press`，`select_option` 改为 `select`，`set_checked` 改为 `check` 与 `uncheck`，`get` 改为 `get_text`、`get_url` 及其他 `get_*` 工具，`tabs` 改为 `tab_*` 系列工具，`wait_for` 改为 `wait_*` 系列工具。同样的命名适用于 `@agent-browser/eve/tools` 覆盖。沙盒需要 agent-browser 0.41，扩展默认会安装该版本 (#2241)

### 新功能

- 新增 **`agent-browser mcp call <tool> '<json>'`**：无需 stdio 会话即可运行单个 MCP 工具，并把结果连同 agent-browser 版本以 JSON 打印，适合无法在工具调用之间保持进程开启的运行时 (#2238)
- 新增 **`@agent-browser/sandbox/mcp-tools.json`**：包含全部 MCP 工具的标题、描述、输入 schema、注解与 profile，由 CLI 生成并经测试校验 (#2240)

### 改进

- **`@agent-browser/eve` 现在将每个工具作为独立的短生命周期进程运行**，因此没有 `agent-browser` 进程会比一次工具调用存活更久。28 个 `core` 工具会列给模型，其余 14 个为延迟加载，通过 `eve__search` 查找，使列出的工具上下文保持原有大小 (#2241)

### 问题修复

- **MCP 工具参数不能再设置全局 flag**。CLI 会在参数的任意位置读取全局 flag，因此选择器或 `extraArgs` 条目之类的值可能自带 `--allowed-domains` 并覆盖服务器或调用方的允许列表。现在此类工具调用会被拒绝 (#2238)

## v0.40.0

<p className="text-[#888] text-sm">2026 年 10 月 27 日</p>

### 破坏性变更

- **`@agent-browser/eve` 现在要求 eve 0.84.0 或更高版本**。eve 0.84.0 拒绝由更早版本构建的扩展，因此扩展现在以它构建。运行旧版 eve 的应用应留在 `@agent-browser/eve@0.39` (#2226)

### 新功能

- 新增**每个 Vercel Sandbox 一个 MCP 服务器**：`@agent-browser/sandbox/vercel` 中的 `startAgentBrowserMcp` 会在 Sandbox stdin 上保持单个 `agent-browser mcp` 运行；`connectAgentBrowserMcp` 面向任何暴露 stdin 与 stdout 流的运行时 (#2228)
- 为 `batch` 新增 **`--omit-command`**、为 MCP batch 工具新增 `omitCommand`，用从 0 开始的索引替代 JSON 输出中重复出现的原始命令数组 (#2216)

### 问题修复

- 修复 **`state load` 与启动时的存储恢复**向页面脚本暴露已保存 token、以及在重定向后把一个源的存储写入另一个源的问题；存储现在仅在页面处于保存时的源上时才通过 DevTools 写入，被跳过的源会被报告 (#2212)
- 修复 **`<session>.config` 文件**在守护进程退出后堆积于 socket 目录的问题 (#2128)
- 修复**被模拟的跨域响应**无法通过 CORS 的问题：`network route --body` 现在接受 `--allow-origin <origin>`（MCP `network_route` 工具同样支持），用于应答预检请求并向该源发送 CORS 头；未设置内容类型时，JSON 主体以 `application/json` 发送 (#2229)
- 修复 **Windows 会话**中已死守护进程可能一直占用被固定标签页、以及不同 socket 目录中的同名会话可能连到彼此守护进程的问题 (#2223)

## v0.33.2

<p className="text-[#888] text-sm">2026 年 7 月 31 日</p>

### 新功能

- 为流服务器新增**输入优先级与逐客户端投递设置**：每个 WebSocket 连接现在拆分为读取任务与写入循环，点击与按键无需排在帧写入之后即可派发给浏览器。新增逐客户端 `{"type":"config","maxFps":N}` 上限（1 到 120，`0` 为不限），以及可选开启的 ack 节流 `{"type":"config","pacing":"ack"}`（配合 `{"type":"ack","seq":N}`），保持一帧在途，卡住的客户端不会排空积压。两项设置也可在连接 URL 上声明（`?pacing=ack&maxFps=10`），这是覆盖开帧的唯一方式。每帧现在都携带单调递增的 `seq` (#1594)
- 新增**可配置的流编码**：帧此前硬编码为会话视口下的 jpeg 质量 80，帧率是唯一的带宽调节手段。`AGENT_BROWSER_STREAM_QUALITY`、`AGENT_BROWSER_STREAM_MAX_WIDTH` 与 `AGENT_BROWSER_STREAM_MAX_HEIGHT` 由每个守护进程读取一次，不减帧即可削减字节：在 1280x720 的繁忙页面上，质量 20 把一帧从 54 KB 降到 25 KB，质量 20 加 640x360 降到 9 KB，两种情况下帧率均不变。宽度与高度默认为会话视口，只有两者都设置时才会缩小更大的视口 (#1626)

### 行为变更

- **帧投递现在是最新者胜**。流服务器只保留最新一帧并在发送时读取，前一帧仍在写入期间产生的帧会被跳过。假设能从 WebSocket 收到每一帧的客户端现在收到的帧会变少。本仓库内没有以该方式消费流的地方——`record` 通过 CDP 捕获，仪表盘只是查看器——因此这只影响外部消费者 (#1594)
- **`metadata.timestamp` 现在携带真实值**。它此前恒为 0，因为 CDP 以浮点秒发送捕获时间，而代码按整数读取。现在它是 epoch 毫秒，客户端可据此测量正在绘制的帧有多旧。把 0 当作未知的客户端不受影响 (#1594)

### 问题修复

- 修复**流上的键盘输入**，此前的三种文档写法全都不工作：缺失的 `key`、`code` 或 `text` 会以显式 null 到达 CDP，导致整条命令被拒，因此每次按键释放与每个不可打印键都被静默丢弃，仪表盘自己的载荷也不例外 (#1594)
- 修复**鼠标移动之后的点击延迟**：输入派发此前要等 Chrome 回复才读下一条消息，导致每次点击落后于排队的鼠标移动一个往返。300 个事件的连续操作后，点击会迟到 2471ms；现在 6ms 内落地 (#1627)
- 修复 **`stream disable`** 在慢客户端的输入读取器仍在运行时就返回的问题 (#1594)

- **域名允许列表** -- `--allowed-domains` 把导航、子资源请求、WebSocket 连接与 EventSource 流限制在可信域内。支持精确匹配与通配符前缀模式（如 `*.example.com`）。

- **操作确认**（confirmation）-- `--confirm-actions` 要求对敏感操作类别显式批准。新增供编排器使用的 `confirm` 与 `deny` 命令。`--confirm-interactive` 启用人在环路的终端提示（stdin 不是 TTY 时自动拒绝）。待处理的确认 60 秒后自动拒绝。
- **输出长度限制** -- `--max-output` 截断过大的页面输出，防止 LLM 上下文被淹没。
- **`--download-path` 选项** -- 通过 flag、`AGENT_BROWSER_DOWNLOAD_PATH` 环境变量或 `downloadPath` 配置键设置默认下载目录。未设置时，下载会进入临时目录，并在浏览器关闭时删除。
- **scroll 的 `--selector` flag** -- 在特定容器元素内滚动而非整页：`agent-browser scroll down 500 --selector "div.scroll-container"`
