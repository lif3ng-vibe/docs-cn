<Aside type="note" title="需求">
处于学习阶段，动手操作——但是在测试，不是在学习。读者正在评估产品，或刚注册完，想要产品可用的证明：一个真实结果，越快越好。他们的开场问题是：*"多快能看到它做点什么？"*衡量指标是"首次成功耗时"，而且这个时间是有价格的：冗长的快速上手会实打实地流失读者。
</Aside>

## 何时使用

每个产品对每条主要路径只配一篇快速上手（例如 API 一篇、控制台一篇）。它不是：

- **教程**。没有学习目标，除了一句"刚才发生了什么"之外没有解释。读者不是在学习，而是在测试。
- **操作指南**。操作指南服务于工作中带着具体目标的读者。快速上手的唯一目标是*首次*成功，而且目标由你替读者选好。

决定性的约束：**所有选择都由作者替读者做好**。一种语言（其余用标签页）、一种安装方式、处处用默认值。当某个选择确实无法用默认值消化（地区、组织类型），替读者做出推荐选择，并在末尾用一行注明备选项——绝不在步骤中途分叉。

**"快速开始"（Get started）变体**。有些产品不做真实配置（DNS、租户设置、绕不开的决策）就到不了名副其实的首次成功。对这类产品，把同一份配方写成 **Get started** 页：标题固定为"Get started"，篇幅放宽到最通用用例的*最小可行配置*，前提条件里可以包含真实决策——每一条都压缩成一个推荐默认值，外加一行说明何时该选别的。下文其余规则（替读者做选择、展示输出、只有一个主下一步）原样适用。有快速路径的产品两者都出：快速上手证明能用，快速开始负责正经配置好。

## 标题与描述

- **标题**：只有一篇时用"Quickstart"；按框架或入口路径分别出品时用"Quickstart: *路径或技术栈*"（"Quickstart: Next.js""Quickstart: Dashboard"）。"快速开始"变体的标题永远是"Get started"。
- **描述公式：**"*在时间上限内达成某成果*。"——例如"Send your first webhook in five minutes."（五分钟发出你的第一个 webhook。）只承诺你亲眼见过陌生人达成的时限。

## 脚手架生成此页

安装这份配方——你的编码智能体会读取完整的骨架和清单，并把它们适配到你的产品上：

<PackageManagers pkg="@cloudflare/nimbus-docs" type="dlx" args="add content-quickstart" />

"You should see"和"Next step"是契约式的固定标题——读者（和智能体）会学会直接跳到它们。

## 组件建议

- **Steps** 和**带可见输出的围栏代码**就是整页。"You should see"块是全页最重要的元素——它是证明。
- **Tabs** 只用于语言/技术栈这一个维度，且仅当各份示例真正平行时。其他任何选择：作者拍板。
- **不适合**：Cards、手风琴折叠、关于边缘情况的提示块、步骤中间的链接。凡是不在最短路径上的东西，都放错了页面。

## 结尾

固定页脚：**You should see**（预期输出 + 一句"刚才发生了什么"）→ **Next step**，只放一个主链接。下一步的位置要有章法——指向能加深采用的那件事，而不是笼统的文档首页；最好的站点把快速上手的结尾当作旅程路由来设计。

## 阈值

- **约 600 词以内、6 步以内、只讲一个特性**。词数预算按**一条渲染路径**算——即选定一个标签页——而不是多语言页面的源码总量。
- **当顺理成章的集成超出预算时，收缩首次成功**——一个托管页面、一次由 CLI 触发的闭环、一次调用——而不是给快速上手注水，或怪罪产品。完整集成属于"快速开始"页或操作指南。
- **没有错误处理、没有可选项、没有生产级加固**。结尾可以用一行实话注明跳过了什么，就像安静的"test mode"标签那样。
- **步骤必须每次都能跑通**。快速上手借用教程的可靠性规则：陌生人的头五分钟，不该出现"效果因人而异"。

## 链接与时效性

页脚之前几乎不放链接——首次成功之前的每个链接都是出口。在所有类型里，这一页腐烂得最快（安装命令、CLI 输出、注册流程）：每次发版只要碰到它的路径，就从头到尾重跑一遍，并在 frontmatter 里盖上 `lastVerified`。

## 智能体须知

- 智能体会逐字执行快速上手；这一页实际上就是一份包着说明文字的脚本。每条命令都必须可复制运行——占位符用尖括号 `<angle-brackets>`（`hl_test_<your-key>`），命令里绝不出现光秃秃的省略号。
- 把随运行变化的输出字段（耗时、生成的 ID）标注为占位符（`<n>ms`），这样智能体在 diff 它的输出和你的输出时，就不会把正常波动当成失败。输出块里其余内容保持逐字一致。
- 在 `.md` 版本里，语言标签页摊平成带标签的先后排列块——预期输出必须每条路径出现一次，绝不能只出现在默认标签页里。
- 前提条件要写成可核查的事实（"Node 20+"），而不是感觉（"较新的 Node"）。
