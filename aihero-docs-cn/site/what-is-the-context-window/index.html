    什么是上下文窗口（上下文窗口（context window））？

    了解 AI 中的上下文窗口：输入/输出 token、上下文限制与“lost in the middle”问题。优化 token 用量，让模型表现更好。

    Matt Pocock

    这个 上下文窗口（context window） 由输入和 输出 token（output tokens）共同组成。 输入 token（input tokens） 可能包括一个系统提示词（system prompt）和一个用户提示词（即用户发来的消息）。而输出 token 则是助手返回的内容：

    上下文窗口就是输入 和 输出 token 的组合。

    随着会话变长、越来越多的消息进入会话，消耗的 token 数量也会增长。

    可以想见，这不可能无限持续下去。每个模型都有一个硬编码的上限，限制它一次能看到多少 token。

    上下文窗口的限制

    想象一段超长会话，我们最终会撞上上限。如果你用这段超长会话去查询 LLM 并触顶，API 大概率会返回某种错误。

    你甚至可能在一条消息的生成过程中撞上上限。也就是说，这条消息开始时还没到上下文窗口上限，但生成继续进行，直到碰到上下文窗口上限为止。

    模型本身还不够聪明，无法绕过自己的上下文窗口限制。所以你有时会遇到这类问题。

    “lost in the middle”（中间迷失）问题

    但上下文窗口最大的问题在于：窗口越大，“lost in the middle”（中间迷失）问题就越多。

    想象一场超大的对话，这些圆环是一条条单独的消息：历史开头处的消息对输出影响相当大，结尾处的消息也一样，但对中间的内容，LLM 的关注会少一些。

    这是一个众所周知的现象，而且上下文窗口越大，它就越明显。

    所以，在评估模型时，你不该只想：“哇，这个上下文窗口上限太大了，太厉害了，我能塞好多东西进去。”

    那个模型大概率仍会有“lost in the middle”问题，甚至可能难以从自己的上下文窗口中检索信息。

    所以，即使那个模型支持很大的上下文窗口，在上下文中少用一些 token 依然一定会带来更好的结果。
