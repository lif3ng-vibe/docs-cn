    用 Vercel AI SDK 进行工具调用

    用尽可能简单的例子，学习如何在 TypeScript 中用 Vercel AI SDK 进行工具调用。

    Matt Pocock
    源代码下一课
    本页内容
    • 调试
    • 接下来

    到目前为止，我们一直在让 LLM 回答问题、扫描文档和做数据提取。

    但它们能做的远不止这些——LLM 可以与现实世界交互。

    它们实现这一点的方式，是调用我们提供给它们的工具或函数。

    Vercel AI SDK 为此提供了一流的解决方案。

    我们将从一个能想到的最简单的工具开始，然后逐步深入。

    Scrollycoding

    1

    我们的工具只是往控制台打条日志。创建它时，我们要导入 tool ，它来自 ai.

    2

    任何工具首先需要的，是对它将接收哪些参数的描述。

    我们可以在工具上指定 parameters 来添加这一点。

    这同样用 Zod schema 来完成，和我们之前做结构化输出时一样。

    3

    我们还使用了 describe 来向 LLM 描述各个参数。

    4

    接下来，我们要说明这个工具要做的是什么。

    具体做法是指定一个 execute 函数。

    这个 execute 函数可以是异步的，所以它几乎什么都能做——调用 API、写数据库等等。

    在我们的例子里，它只是往控制台打条日志。

    5

    接下来，我们要给工具本身添加一个 description 字段。

    这会告诉 LLM 应该拿这个工具做什么。

    import { tool } from "ai";

    

    const logToConsoleTool = tool({});

    现在工具已经创建好了，来把它真正用进一个 generateText 调用里。

    Scrollycoding

    1

    让我们创建名为 logToConsole的函数，传入一个模型和一个提示词（prompt）。

    2

    我们会给它一个系统提示词（系统提示词（system prompt）），鼓励它使用这个工具。

    3

    最后，把我们的工具传给它。

    import { generateText } from "ai";

    

    const logToConsole = async (prompt: string) => {

      await generateText({

        model,

        prompt,

      });

    };

    回顾一下：我们创建了一个工具，把它传给了 generateText ，并给它一个简单的 系统提示词（system prompt）.

    运行一下，看看会发生什么。

    Hello, world!

    成功了！控制台里打印出了“hello world”。

    调试

    效果不错，但过程相当不透明。我们该怎么进去调试呢？

    Scrollycoding

    1

    让我们解构出 steps 属性，它来自 generateText.

    steps 是一个数组，记录着 LLM 走出的每一步。

    我们会在后面再看 steps ，因为它开始涉及智能体行为和推理这类有意思的内容。

    2

    现在，我们只从第一步里取出一个属性：工具调用（工具调用的结果s）。

    它会告诉你那一步里调用了哪些工具。

    import { generateText } from "ai";

    

    const logToConsole = async (prompt: string) => {

      const { steps } = await generateText({

        model,

        prompt,

        system:

          `Your only role in life is to log ` +

          `messages to the console. ` +

          `Use the tool provided to log the ` +

          `prompt to the console.`,

        tools: {

          logToConsole: logToConsoleTool,

        },

      });

    };

    运行后可以看到，名为 logToConsole 的工具被调用了。

    还能看到传给它的参数。

    [

      {

        type: 'tool-call',

        toolCallId: 'toolu_012hbsiE2sXvPrAwAvE3kgxM',

        toolName: 'logToConsole',

        args: { message: 'Hello, world!' }

      }

    ]

    如果我们改为打印 toolResults ……

    console.dir(steps[0]?.toolResults, { depth: null });

    ……就能看到 工具调用的结果。在我们的例子里，函数没有返回任何东西，所以值是 undefined.

    [

      {

        toolCallId: 'toolu_012hbsiE2sXvPrAwAvE3kgxM',

        toolName: 'logToConsole',

        args: { message: 'Hello, world!' },

        result: undefined

      }

    ]

    这些 toolResults 可以反馈给 LLM，为它提供更多信息，尤其是在多步骤运行时。

    所以，借助 steps 来调试，是一种能让你看清工具调用到底发生了什么的办法。
