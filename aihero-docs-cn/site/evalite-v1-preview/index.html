    Evalite v1 预览：更快的评测、内置评分器

    Evalite v1 自带 10 个生产可用的评分器（字符串匹配、RAG 评测、智能体测试），并默认采用内存存储。目前仍处于 beta 阶段。

    如果你写过评测（eval），就知道这种痛苦。每次需要检查 LLM 的输出是否正确，你都得再写一个自定义评分器。SQL 有效吗？它产生幻觉了吗？JSON 格式正确吗？

    Evalite v1（仍处于 beta）用 10 个生产可用的评分器解决了这个问题，还带来一次重大的架构升级，让上手变得毫不费力。

    完整文档见 v1.evalite.dev.

    10 个内置评分器

    Evalite v1 自带覆盖最常见评测场景的评分器，不必再重复造轮子。

    字符串评分器

    这些是用于简单文本校验的确定性评分器：

    • exactMatch ——检查输出是否与期望字符串完全一致
    • contains ——检查输出是否包含某个子串
    • levenshtein ——基于 Levenshtein 距离的模糊字符串匹配

    其中 levenshtein 评分器 对 SQL 生成或代码输出尤其有用——微小的格式差异不应该让评测失败：

    scorers: [

      {

        scorer: ({ output }) =>

          levenshtein({

            actual: output,

            expected: "SELECT * FROM users WHERE id = 1",

          }),

      },

    ];

    RAG 评分器

    这些评分器用 LLM 当裁判来评估 RAG 管线：

    • faithfulness ——通过检查输出是否有上下文依据来检测幻觉
    • answerSimilarity ——比较输出与期望答案的语义相似度
    • answerCorrectness ——对照事实标准评估事实正确性
    • answerRelevancy ——检查输出是否真正回答了问题
    • contextRecall ——衡量是否检索到了所有相关上下文

    用 faithfulness 捕捉幻觉的示例：

    scorers: [

      {

        scorer: ({ output, input }) =>

          faithfulness({

            question: input.question,

            answer: output,

            groundTruth: input.context, // Retrieved context

            model: yourModel,

          }),

      },

    ];

    高级评分器

    面向专门的用例：

    • toolCallAccuracy ——评估智能体是否用正确的参数调用了正确的工具
    • noiseSensitivity ——通过添加噪声并检查一致性来测试提示词的稳健性

    工具调用（tool call） 的准确性对智能体评测至关重要：

    scorers: [

      {

        scorer: ({ output }) =>

          toolCallAccuracy({

            actualCalls: output.toolCalls,

            expectedCalls: [{ toolName: "search", input: { query: "..." } }],

          }),

      },

    ];

    自由组合评分器

    真正的威力来自组合使用评分器。一套全面的 RAG 评测可能会用：

    scorers: [

      {

        scorer: (opts) => faithfulness({ ...opts, model: yourModel }),

      },

      {

        scorer: (opts) => answerRelevancy({ ...opts, model: yourModel }),

      },

      {

        scorer: (opts) => contextRecall({ ...opts, model: yourModel }),

      },

    ];

    每个评分器返回 0-1 的分数，Evalite 会把它们汇总成一个整体评测得分。

    默认使用内存存储

    最大的架构变化： Evalite v1 默认使用内存存储.

    之前你需要先设置 SQLite，这对新用户来说多了些摩擦。现在你只需运行 npx evalite 就能立刻开始评测。

    想要持久化？在配置里切换到 SQLite：

    // evalite.config.ts

    import { defineConfig } from "evalite/config";

    

    export default defineConfig({

      storage: {

        type: "sqlite",

        path: "./evalite.db",

      },

    });

    但对大多数开发工作流来说，内存存储更简单，还省掉一个设置步骤。

    与 Vercel AI SDK 深度集成

    Evalite v1 围绕 Vercel AI SDK构建。用 wrapAISDKModel() 把任意 AI SDK 模型包一层，即可获得自动追踪与缓存。

    缓存一切

    不只是评分器 ——缓存你的整个评测管线。task 函数里用的模型、评分器里用的模型，任何地方都可以包装：

    import { wrapAISDKModel } from "evalite/ai-sdk";

    import { openai } from "@ai-sdk/openai";

    

    const model = wrapAISDKModel(openai("gpt-4"));

    

    evalite("RAG Eval", {

      data: [...],

      task: async (input) => {

        // Cached automatically

        const result = await generateText({

          model,

          prompt: input.question,

        });

        return result.text;

      },

      scorers: [

        {

          // Also cached automatically

          scorer: (opts) => faithfulness({ ...opts, model }),

        },

      ],

    });

    这彻底改变了 watch 模式。改评分器逻辑、调阈值、重构评测结构——昂贵的 LLM 调用保持缓存，只运行真正变化的部分。

    evalite watch

    这个包装器对所有 AI SDK 方法都有效： generateText(), streamText(), generateObject()，以及 streamObject().

    生产环境零开销 - wrapAISDKModel() 在 Evalite 上下文之外调用时是空操作。你的生产代码运行方式与之前完全一样。

    DX 改进

    最大的 DX 改进是 自动 .env 支持。环境变量自动加载。

    Evalite UI 有多项升级：

    • 深色模式 ——主题切换器，可选浅色/深色
    • 表格渲染 ——对象和数组以 markdown 表格而非 JSON 树的形式渲染
    • 重新运行按钮 ——在 watch 模式下重新运行评测，无需重启
    • AI SDK 消息 UI ——直接传入 AI SDK 消息，获得自定义的 UI 渲染

    快速上手

    Evalite v1 仍在积极开发中（beta）。功能还在演进，目前尚无正式的迁移指南。

    试用方法：

    pnpm install evalite@beta

    完整文档见 v1.evalite.dev.

    v1 仍是 beta，你的反馈将塑造最终版本。发现了 bug？想要我们还缺少的评分器？
