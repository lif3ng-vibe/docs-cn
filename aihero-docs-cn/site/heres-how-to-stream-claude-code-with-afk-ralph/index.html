    教你如何用 AFK Ralph 流式查看 Claude Code

    运行 AFK Ralph 时实时流式查看 Claude Code 的输出。学会用 jq 看清 Claude 在做什么，而不是盯着一块空白屏幕。

    Matt Pocock

    本指南写给那些在 Claude Code 上试过 Ralph、并撞上那个挫败点的人：运行 AFK 脚本，最后落得盯着一屏空白。

    如果你从没听说过 Ralph，从这里开始：

    问题：一块空白屏幕

    当你想让 Ralph 在你离开键盘时继续跑，你可能会用这样一个脚本：

    #!/bin/bash

    set -e

    

    if [ -z "$1" ]; then

      echo "Usage: $0 <iterations>"

      exit 1

    fi

    

    for ((i=1; i<=$1; i++)); do

      result=$(docker sandbox run --credentials host claude \

        --print \

        "<your prompt here>")

    

      if [[ "$result" == *"<promise>COMPLETE</promise>"* ]]; then

        echo "Ralph complete after $i iterations."

        exit 0

      fi

    done

    这里的问题让人沮丧：当你用 --print 标志运行 Claude 时，你得不到任何流式输出，终端一片空白。

    你走开了，却完全不知道发生了什么。Claude 在干活吗？卡住了吗？是不是出了什么错？直到它跑完你才会知道。

    AFK Ralph 的梦想是两全其美：既想实时看到 Claude 在做什么，又想在你走开时让它继续跑。

    解决方案：用 jq 实现流式输出

    Claude 可以输出 stream-json 格式，每条消息一发生就能拿到。但这种输出极其冗长、没法读。

    把 stream-json 和 jq 过滤组合起来，你就能只提取有用的信息并实时流向终端。与此同时，你会捕获最终结果，用来检查 <promise>COMPLETE</promise> 标记。

    完整脚本如下：

    #!/bin/bash

    set -e

    

    if [ -z "$1" ]; then

      echo "Usage: $0 <iterations>"

      exit 1

    fi

    

    # jq filter to extract streaming text from assistant messages

    stream_text='select(.type == "assistant").message.content[]? | select(.type == "text").text // empty | gsub("\n"; "\r\n") | . + "\r\n\n"'

    

    # jq filter to extract final result

    final_result='select(.type == "result").result // empty'

    

    for ((i=1; i<=$1; i++)); do

      tmpfile=$(mktemp)

      trap "rm -f $tmpfile" EXIT

    

      docker sandbox run --credentials host claude \

        --verbose \

        --print \

        --output-format stream-json \

        "<your prompt here>" \

      | grep --line-buffered '^{' \

      | tee "$tmpfile" \

      | jq --unbuffered -rj "$stream_text"

    

      result=$(jq -r "$final_result" "$tmpfile")

    

      if [[ "$result" == *"<promise>COMPLETE</promise>"* ]]; then

        echo "Ralph complete after $i iterations."

        exit 0

      fi

    done

    这个脚本接受一个参数：要运行的迭代次数。

    脚本结构详解

    拆解流式过滤器

    流式过滤器做了几件重要的事：

    1. 筛选 assistant 消息: select(.type == "assistant") ——只抓取 Claude 的回复
    2. 提取文本内容: .message.content[]? | select(.type == "text").text ——只抽出文本部分
    3. 修正行尾: gsub("\n"; "\r\n") ——把换行符替换为回车 + 换行
    4. 添加空行: . + "\r\n\n" ——在消息之间插入额外的空行

    替换回车符修掉了一个 bug：光标之前无法正确回到行首字符。

    数据管线

    数据在脚本中的流动方式如下：

    Docker 流式输出 stream-json 格式的数据，但其中混入一些非 JSON 的噪声行。 grep --line-buffered '^{' 过滤器确保只有合法的 JSON 行才会被处理。

    而 tee "$tmpfile" 命令把所有内容写入一个临时文件，同时不打断流。你稍后需要这个文件来检查 Claude 是否已经跑完。

    最后， jq --unbuffered -rj "$stream_text" 应用流式过滤器，把文本实时显示到你的终端。

    结语

    我的希望是：用不了多久我就能删掉这篇文章，因为 Claude Code 会发布一个功能，让你既能流式查看回复，又能捕获最终输出。

    OpenCode 已经有这个功能，所以没必要为它写这样的文章。但在那之前，这是一个可行的方案，让你在运行 AFK Ralph 的同时从 Claude 获得实时流式输出。
