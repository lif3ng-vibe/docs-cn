    用 Vercel AI SDK 打造替代文本生成器

    通过一份简单指南，学习如何用 Vercel AI SDK 基于本地文件和 URL 为图片生成替代文本（alt text）。

    Matt Pocock
    源代码下一课
    本页内容
    • 从 URL 读取
    • 接下来

    AI SDK 开箱即支持的另一件事，是把图片和文件传给 LLM。

    LLM 随后就能查看这个文件或图片并对其进行处理。这是一个极其强大的功能。

    并非所有 LLM 都支持这一点，但对支持的那些，AI SDK 同样让你用得上。

    这里我们想让 LLM 为我们传入的图片生成一段替代文本（alt text）。

    我们可能会在网站等场景使用这些替代文本，帮看不见图片的人理解图片里有什么。

    Scrollycoding

    1

    我们会用一个相当简单的系统提示词（system prompt）：

    2

    然后，我们要创建一个名为 describeImage 的函数，它会接收本地文件系统上一张图片的路径。

    const systemPrompt =

      `You will receive an image. ` +

      `Please create an alt text for the image. ` +

      `Be concise. ` +

      `Use adjectives only when necessary. ` +

      `Do not pass 160 characters. ` +

      `Use simple language. `;

    这看起来没问题，但我们还没有在函数里用到 imagePath 。

    我们不能把图片路径直接当作提示词（prompt）传进去；得先把图片真正加载进内存，再把它传给 generateText 函数。

    Scrollycoding

    1

    为了把它加载进内存，我们会使用 readFileSync ，它来自 Node.js。

    它会把图片以 Uint8Array的形式存进内存——本质上就是构成图片的那些字节的原始表示。

    2

    当然，我们也可以用 readFile ，它来自 fs.promises ，如果想要非阻塞 I/O 的话。不过 readFileSync 对我们的用途来说就足够了。

    3

    现在，我们可以把这个 Uint8Array 放进 generateText 函数。但不能直接把它当作提示词传入；而是要作为一个 messages 数组传入：

    它的格式和我们之前看到的聊天历史一样，只是这次多了一个 content ，它是由不同消息部分（message part）组成的数组。

    我们传入的这个消息部分类型为 image，然后把 Uint8Array 放进 image 属性。

    import { readFileSync } from "fs";

    import { generateText } from "ai";

    

    export const describeImage = async (

      imagePath: string,

    ) => {

      const imageAsUint8Array = readFileSync(imagePath);

      const { text } = await generateText({

        model,

        system: systemPrompt,

      });

    

      return text;

    };

    来跑一下试试。我这里有一张烟花图片，把它传进去看看会发生什么。

    const description = await describeImage(

      "./fireworks.jpg",

    );

    

    console.log(description);

    我们拿到了这段漂亮的描述：

    Colorful fireworks display over a city skyline at night, with bursts of red, white, and blue reflections on the water. Spectators watch from the shoreline.

    总结一下：我们把一张图片读入内存，直接传给了 generateText ，用的是 messages 数组，然后拿到了对这张图片的描述。相当漂亮。

    从 URL 读取

    当前的做法在文件已在内存里时没问题。但如果你只有一个指向该文件的 URL 呢？

    好消息是，有一个非常方便的捷径——你可以把 URL 直接传给 AI SDK。

    import { generateText } from "ai";

    

    export const describeImage = async (

      imageUrl: string,

    ) => {

      const { text } = await generateText({

        model,

        system:

          `You will receive an image. ` +

          `Please create an alt text for the image. ` +

          `Be concise. ` +

          `Use adjectives only when necessary. ` +

          `Do not pass 160 characters. ` +

          `Use simple language. `,

        messages: [

          {

            role: "user",

            content: [

              {

                type: "image",

                image: new URL(imageUrl),

              },

            ],

          },

        ],

      });

    

      return text;

    };

    我们用 new URL 来包裹这个 URL，向 AI SDK 表明它是网络上的一个 URL，我们想把它发给 LLM。

    来测试一下。这里有一张我们想描述的教堂图片，我把它托管在了 GitHub 上：

    const description = await describeImage(

      "https://github.com/ai-hero-dev/ai-hero/blob/main/internal/assets/image.jpg?raw=true",

    );

    

    console.log(description);

    运行时，URL 会被传给 LLM。LLM 会下载这张图片并查看它，然后我们就拿到了描述。

    Lake Bled in Slovenia with church on small peninsula and castle on cliff, surrounded by mountains. Calm water reflects buildings and autumn trees.

    当你处理托管在网络上的图片时，这是一个非常好用的捷径。
