    什么是工具（tool）？

    了解 LLM 工具如何通过系统提示词定义、选择和执行任务，增强 AI 能力。

    Matt Pocock

    给 LLM 提供工具是通过 系统提示词（system prompt）完成的。系统提示词只是消息历史中的又一条消息，它告诉 LLM 应该做什么，在本例中还告诉它能调用哪些工具。

    对每个工具，我们提供三样东西：

    1. 工具的名称，例如 writeFile)
    2. 工具的描述（例如“把一个文件写入文件系统”）
    3. 它接受的参数及其类型，例如 path 和 content)

    这些参数用 JSON schema 来声明，因此凡是 JSON schema 支持的类型都可以传，比如对象、数组和其他复杂类型。

    这些工具定义会被注入系统提示词，而你提供给系统提示词的其他信息则放在它下面。这里没有任何花哨的东西——只是系统提示词里放着工具定义而已。

    LLM 选择工具

    神奇的事情发生在我们让 LLM 选择工具的时候。系统提示词写着“你可以使用以下工具。”然后我们添加一条用户消息：“写一个名为 .gitignore 的新文件。”

    然后我们会收到一条包含 工具调用（tool call） 的助手消息。这只是 LLM 指示该调用哪个工具的一条指令。它上面带有一个 id ，还包含所需的参数。

    在这个例子里，它要在路径“.gitignore”处写一个空文件。

    工具调用与工具执行

    这个工具调用只是关于该调用哪个工具的一条指令。什么都还没发生——助手只是产出了一条消息。仅此而已。

    然后，这个工具需要在我们的机器上执行。LLM 创建了这条消息，但我们还需要在自己的机器上真正执行创建文件的操作。

    实现要求

    这意味着，系统提示词里的每一个工具，都要在我们的代码库里有与之对应的函数。

    如果工具执行成功，我们就会向 LLM 发回一条用户消息。它会带有一个 id ，与上一个工具调用中的相同，并且我们还会发送一条消息，说明执行工具时发生了什么。

    处理错误

    这种错误处理非常重要。如果工具执行时出现任何错误，我们需要把错误信息展示给 LLM，让它换一种做法。

    所以 工具结果（tool result） 既可能是成功，也可能是失败。

    完整流程

    我们把整个流程再过一遍：

    1. 我们在系统提示词里声明工具：“你可以使用以下工具……”，并传入一堆 JSON schema
    2. 我们发送一条用户消息：“写一个名为 .gitignore 的新文件”（注意我们不必特意说“调用这个工具”——由 LLM 自己决定调用哪个工具）
    3. LLM 产出一条带全所有正确参数的工具调用消息
    4. 我们看到这条工具调用消息，并在自己的机器上执行它
    5. 我们把结果连同一条说明发生了什么的消息发回去
    6. LLM 看到这整段历史后，用一段总结作为回应

    在这个例子里，它回复说：“完成了。里面该放什么？”

    工具小结

    工具就是这么回事——它们只是让 LLM 产出特定类型消息的手段，你随后可以拦截这些消息、在自己的机器上执行，并把结果交还给 LLM。

    借助这个简单的循环，你就能构建非常非常强大的应用。
