    什么是智能体（agent）？

    了解 LLM 系统中智能体与工作流各自的威力：智能体随机应变，工作流为可预测、可重复的任务而优化。

    Matt Pocock

    自从 Anthropic 发布了 《构建高效智能体》（building effective agents）一文，大家就一直在谈论智能体与工作流。智能体和工作流都是用 LLM 构建更强大系统的方式，而且两者都要编排多次对 LLM 的调用。

    什么是工作流？

    工作流通过预先确定的步骤做到这一点：一次 LLM 调用接着另一次调用，再接着下一次调用。这些预先确定的步骤由开发者写进代码。

    由代码本身决定何时停止程序、何时调用下一个 LLM。一切都写在代码里。

    什么是智能体（agent）？

    而智能体不使用预先确定的步骤。它调用一个 LLM，并给它一堆工具——也就是接下来可以做的不同选择。由 LLM 决定调用哪个工具，然后根据这些工具的结果做出响应。

    由 LLM 自己决定何时认为任务完成并停止程序。换句话说，这是 LLM 在即兴发挥——这把大得多的权力交给了 LLM，但当然也让它更难预测。

    智能体与工作流的比较

    智能体和工作流都涉及多次 LLM 调用。如果你只做一次 LLM 调用，那其实两者都算不上。

    关键区别在于由谁决定何时停止：

    智能体非常适合这样的场景：完成任务所需的步骤并不十分明确，需要即兴发挥才能摸索出攻克难题的路径。

    而工作流则很适合需要一遍遍以同样方式完成的事情。工作流常常受到不公的贬低，只因为它们不像智能体那样刺激、炫酷。

    只要任务被清晰地界定，用工作流往往比用智能体得到更好的结果。

    并行工作流示例

    比如，你可以用工作流来并行处理。假设我们拿到一大段文本，可以把它拆成两部分，分别独立摘要，然后再对摘要再做一次摘要。

    这就是智能体与工作流的区别。不知道是不是我变老变无聊了，反正比起智能体，工作流更让我兴奋。
