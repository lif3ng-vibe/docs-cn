    用 Vercel AI SDK 构建你的第一个智能体

    我们来构建一个 AI 智能体（agent）。了解如何用 Vercel AI SDK 让 LLM 对工具调用的结果做出响应。

    Matt Pocock

    在上一个例子中，我们看到了 LLM 如何调用工具在现实世界里做事。

    但它们能做的不止于此——它们还能对从工具那里收到的信息做出反应。

    这可以形成一个强大的反馈回路：LLM 不断让自己扎根于现实世界。

    而这个反馈回路，正是包括 Anthropic 在内的大多数人所说的智能体（agent）。

    Vercel AI SDK 用一个叫 steps 的概念把这件事变得超级简单。

    我们要打造一个智能体，它能为我们查询指定城市的当前天气。

    Scrollycoding

    1

    先从这里开始：我们要创建一个 getWeather 工具。

    我们先给它一个描述和一组参数。

    2

    接着，我们来实现 execute 函数。

    这里我们只是先打个桩：直接返回这个城市的天气是 25 度。

    不过如果愿意，我们也可以调用天气 API 来获取真实天气。

    import { tool } from "ai";

    import { z } from "zod";

    

    const getWeatherTool = tool({

      description:

        "Get the current weather in the specified city",

      parameters: z.object({

        city: z

          .string()

          .describe("The city to get the weather for"),

      }),

    });

    接下来，我们要把这个工具接到一个名为 askAQuestion.

    Scrollycoding

    1

    我们将调用 streamText ，传入一个模型和一个提示词（prompt），并把 getWeather 工具。

    2

    然后，我们会遍历文本流，把文本打印到 stdout.

    3

    最后，我们问它伦敦的天气怎么样。

    import { streamText } from "ai";

    

    const askAQuestion = async (prompt: string) => {

      await streamText({

        model,

        prompt,

        tools: {

          getWeather: getWeatherTool,

        },

      });

    };

    运行之后，我们注意到一个有意思的现象。

    I'll help you check the current weather in London right away.

    我们没有拿到想要的信息，它只说了一句“我来帮你”。

    为什么会这样？

    调试 steps

    我们用和上次一样的策略来调试：查看 steps 属性——它来自 streamText.

    import { streamText } from "ai";

    

    const askAQuestion = async (prompt: string) => {

      const { steps } = await streamText({

        model,

        prompt,

        tools: {

          getWeather: getWeatherTool,

        },

      });

    

      console.dir(await steps, { depth: null });

    };

    

    await askAQuestion(`What's the weather in London?`);

    因为我们使用的是 streamText ，所以要先 await ，等待 steps.

    这是 它输出的内容。

    这一大坨 JSON 里有好几个值得注意的地方。

    首先，我们注意到它只有一个 step 的长度——LLM 在这里只走了一步。

    可以看到，它调用了一个工具并拿到了返回结果，分别记录在 toolCalls 和 toolResults 属性中。

    toolCalls: [

      {

        type: 'tool-call',

        toolCallId: 'toolu_011n3T6TJnwZLyR4G8h1ZcMz',

        toolName: 'getWeather',

        args: { city: 'London' }

      }

    ],

    toolResults: [

      {

        type: 'tool-result',

        toolCallId: 'toolu_011n3T6TJnwZLyR4G8h1ZcMz',

        toolName: 'getWeather',

        args: { city: 'London' },

        result: 'The weather in London is 25°C and sunny.'

      }

    ],

    也就是说， LLM 调用了 getWeather 工具，城市为伦敦，并拿到了结果：伦敦天气 25°C、晴天。

    但接下来它决定就此打住。

    这样看来， LLM 做得没错——它调用了工具，却又因为某种原因停了下来。我们怎么让它走不止一步呢？

    maxSteps

    默认情况下，AI SDK 只允许 LLM 走一步。

    如果想让它走更多步，就可以把 maxSteps 传给 streamText.

    这会强制这个循环在仅仅两步之后就停下。

    运行后，我们会得到一段很酷的输出：

    I'll help you check the current weather in London right away.

    

    It looks like London is experiencing a pleasant day with sunny conditions and a temperature of 25°C (which is about 77°F). It sounds like a great day to be outside and enjoy the nice weather!

    可以看到，LLM 现在会对工具提供的信息做出反应了。

    如果我们再打印一次 steps，会发现 这次一共走了两步.

    停止信号

    如果我们指定的步数超过两步会发生什么？试着把 maxSteps 调到 10，看看会怎样。

    结果发现，我们得到的 几乎是同样的结果.

    LLM 在两步之后就停了下来。

    可以看到，第二步里的 finishReason 值为 stop:

    finishReason: 'stop'

    这是因为 LLM 内置了一套机制：完成任务后就停止。

    这意味着这个循环有两种结束方式：要么 LLM 自己停下，要么达到它设定的 maxSteps.

    把 maxSteps 设为 Infinity 并不是个好主意，因为有时 LLM 就是不会自己停下来。

    结语

    总结一下，我们学习了如何用 Vercel AI SDK 创建一个简单的智能体循环。

    使用 maxSteps 能让 LLM 走多个步骤，并对自己的工具结果做出反应。

    这让你能构建把 LLM 锚定于现实、从而更加实用的系统。
