    技能变更日志：/h 和 off、/prototype、/review 与 /writing

    Matt Pocock

    我向自己的 技能（skill）仓库: /handoff 和 /prototype 中新增了两个全新技能。它们都极大升级了我与智能体（agent）协作的方式，尤其是在规划阶段。

    这个仓库的增长速度惊人——大家的反响非常热烈。

    我还修复了 /grill-with-docs, /to-prd 和 /to-issues 中的一些 bug。我还会抢先分享几个开发中的技能：写作与代码评审。

    /handoff

    全新的 /handoff 技能会把当前会话压缩成一份交接（h 和 off）文档，供另一个智能体接手。它会创建一个临时文件，总结上下文、捕捉会话的氛围与意图，并建议下一个智能体应使用哪些技能。

    这解决了一个常见问题：你正在进行一场已用到 60K token 的追问（grilling）会话，此时需要做个原型或修个 bug。与其把这项工作塞进剩余的上下文窗口（context window），不如把任务移交给一个带着完整上下文的全新智能体。你甚至可以在事后带着学到的经验交接回原来的会话。

    主要有两种模式： 发射后不管（fire 和 forget） （在会话中途启动一个智能体去修 bug）和 DIY 子智能体（sub-agent） （在规划时交接出去、做些工作、再交接回来）。这个技能放在生产力分区，因为它在工程工作之外也很有用。

    /prototype

    全新的 /prototype 技能会构建一次性原型，在敲定设计决策之前先把问题探明。这对 AI 工程至关重要——你需要把原型当作调研和试探（spike），去回答那些只有看代码才能弄清的未知未知。

    UI 原型是最显而易见的用例，但这个技能也能处理业务逻辑原型。当你有复杂的状态机或会随时间变化的实体时，可以构建一个微型的交互式终端应用，把状态推过那些在纸面上很难推演的边界情况。

    对于 UI 工作，它会生成几个风格迥异的变体，并配一个悬浮按钮来切换。你可以沿着设计树走下去，组合不同变体中的元素、丢弃其余。要让 AFK 智能体擅长前端，这一点至关重要——你需要人在回路（human-in-the-loop）来注入品味，因为 AI 往往看不见自己在构建什么。

    Bug 修复

    The /grill-with-docs 技能有时太急于动手实现，而不愿先提问。修复办法是把辅助信息包进 XML 标签里，以降低它相对于核心指令的“音量”。这等于向 LLM 传递信号： <supporting-info> 里面的内容优先级应略低一些。

    这两者 /to-prd 和 /to-issues 现在都改用了 ready-for-agent-triage 标签，而不是 needs-triage。用这些技能创建好工单（issue）之后，它们就已经适合直接交给智能体处理——无需额外分诊（triage）。

    开发中预览

    有一个三段式的写作技能正在开发中： 碎片（fragments）, 节拍（beats） 和 塑形（shape）。其理论源自作家记录灵感笔记、最终融入作品的做法：你先口述碎片（灵感），再写下节拍（贯穿故事的路径），最后做一次塑形润色，确保成品不带有 AI 腔。

    还有一个 review 技能即将推出，它会启动两个并行子智能体：一个检查 diff 是否遵循仓库的编码规范，另一个检查它是否忠实实现了原始工单（issue）或 PRD。另外还会有一个单独的技能，从你的仓库中提取编码规范，让规范检查更有效。
