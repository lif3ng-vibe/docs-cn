    AI 技能更新日志

    v1：token 减少 63%，新增 /ask-matt、/writing-great-skills

    Matt Pocock

    这个 技能目录 已随 v1 达成一个重要里程碑。超过 420 万次下载和 13.5 万 GitHub star 之后，这次发布带来了关键改动：大幅降低 token 消耗、按调用类型重组技能，并解锁强大的新能力。

    上手最新的技能

    安装或升级到新技能很简单。使用以下命令：

    npx skills add mattpocock/skills

    无论你是第一次用这些技能，还是从更早的版本升级，现在都是享受这些改进的最佳时机。

    改动内容

    disable-model-invocation：token 成本下降 63%

    v1 最大的结构性改动是广泛使用了 disable-model-invocation: true 。给技能设置这个标志后，它的描述就不会再进入模型在决定调用哪个技能时审阅的上下文窗口。

    这个简单的改动带来了 技能描述的 token 成本下降 63% ——对使用受限上下文模型的人来说是巨大的改进。

    这次改动如何重组你的技能

    此前，像 /grill-with-docs 这样的技能里，共享代码把同样的信息复制到多处。现在这些代码已被抽取出来：

    这个 /grilling 技能包含了此前内嵌在其他技能里的核心访谈循环：

    Interview me relentlessly about every aspect of this plan

    until we reach a shared understanding.

    由于 /grilling 技能 并未 对模型禁用，它仍然可以被智能体自行调用。这意味着你可以在其他技能之间自由共享它，而不会撑大它们的描述。

    /grill-with-docs 现在的 frontmatter 和内容都精简得多：

    ---

    name: grill-with-docs

    description: A relentless interview to sharpen a plan or design, which also creates docs (ADR's and glossary) as we go.

    disable-model-invocation: true

    ---

    

    Run a `/grilling` session, using the `/domain-modeling` skill.

    同样的原则也适用于其他重构过的技能：

    • /domain-modeling ——移入独立的技能，不再与后者耦合 /grill-with-docs
    • /codebase-design ——抽取为带深模块词汇的独立技能
    • /diagnosing-bugs （曾名 /diagnose）——现在引用设计原则，而不是复述它们

    用户调用与模型调用技能

    v1 引入了更清晰的分类： 用户调用（user-invoked） 和 模型调用（model-invoked） 技能。

    类型用途何时由你使用
    用户调用编排工作流；只在你显式键入时运行你显式请求它们
    模型调用模型可自动调用的聚焦任务模型自行决定使用

    这一划分意味着模型可以在需要时偶尔调用特定技能——诊断疑难 bug、应用测试驱动开发、或对领域概念建模——而不会让不必要的选项把界面搅乱。

    看一眼工程 readme，模型调用技能只有寥寥几个：

    • /diagnosing-bugs ——用于复杂调试场景
    • /tdd ——当测试驱动开发合理时
    • /domain-modeling ——用于领域模型工作
    • /codebase-design ——用于架构指导
    • /grilling ——可复用的访谈循环

    用户调用技能仍然是你编排工作的主要方式。

    新技能与重大重写

    写出优秀技能：深度剖析

    招牌新技能之一是 /writing-great-skills。Matt 花了六七个小时打磨这个技能，其中包括一份内容详尽的 GLOSSARY.md ，里面为每个术语都设有词条。

    这份术语表涵盖如下概念：

    • No-op（无操作） ——应当删除的无操作段落
    • Sprawl（蔓延） ——不必要的扩张或重复
    • Sediment（沉积物） ——沉积在技能里的陈年杂物
    • 过早完成 ——还没充分理解就过早收尾
    • 引导词（leading words） ——模型预训练中已有的紧凑概念

    当你调用 /writing-great-skills时，它会寻找重构技能和使用引导词的机会——引导词是那些高效且语言模型早已熟悉的术语。

    单是这个技能就包含足够多有用的模式，很快会有一期专门视频来探索它的全部深度。

    /ask-matt：用于导航的路由技能

    随着用户调用技能不断增多，记住所有技能会带来认知负担。新的 /ask-matt 技能充当路由器来解决这个问题——一个入口点，报出所有其他技能的名字，并说明各自该在什么时候用。

    /ask-matt 记录了以下内容：

    • 如何使用目录中的所有其他技能
    • 主工作流及其编排方式
    • 交接（h和off）模式与交接期间的原型设计
    • 如何判断多会话构建是否需要 PRD
    • 上下文卫生实践
    • 开始工作的不同入口
    • 通过其改善代码库健康度 /improve-codebase-architecture

    不用去 Discord 提问，也不用翻文档，这个技能本身就会教你如何使用整套技能。这就是你一直想要的那份全面指南。

    新增与重命名的技能

    v1 还包含其他几项改动：

    • /writing-great-skills ——取代了 /write-a-skill ，换上了深入得多的参考内容
    • /diagnosing-bugs ——曾名 /diagnose，如今名字更清晰
    • /resolving-merge-conflicts ——处理 git merge 与 rebase 冲突的全新独立技能
    • /codebase-design ——带深模块词汇的全新共享技能
    • /domain-modeling ——用于构建项目领域模型的全新共享技能
    • 已移除的 - /caveman 和 /zoom-out 技能已被弃用

    我为什么做这些改动

    这些改进体现了一个核心原则： 掌控权始终在用户手里，而不是智能体手里。模型是你编排的工具，而不是反过来。

    是的，这意味着你在挑选该用哪个技能时要承担更多认知负担。但这正是 /ask-matt 存在的原因——毫无摩擦地为你引路。

    大幅降低 token 消耗并把用户调用与模型调用技能分开，你解锁了更强的能力：设计更好的代码库、修更难的 bug、写更好的技能——而且不必把上下文浪费在不必要的描述上。
