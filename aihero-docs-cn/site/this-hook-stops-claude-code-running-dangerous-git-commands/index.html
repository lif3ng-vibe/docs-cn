    这个 hook 能阻止 Claude Code 运行危险的 git 命令

    学会用 PreToolUse hook 在 Claude Code 中阻止危险的 git 命令，用 git 护栏（guardrail）防止意外的数据丢失。

    Matt Pocock

    我做了一个技能，让你能防止 Claude Code 运行任何危险的 git 命令。通过以下命令添加： npx skills add:

    npx skills add mattpocock/skills/skills/misc/git-guardrails-claude-code

    Claude 会引导你完成安装——选择是装到当前项目还是全局所有项目，然后自定义你想阻止哪些 git 命令。

    这个技能为什么存在

    Docker Sandbox 的前情

    我最近一直在试验 Ralph 风格的工作流 ，而我发现让 Claude 自主运行的最强大方式是通过 Docker Sandbox.

    它让 Claude Code 以 YOLO 模式运行，不必每条命令都请求许可，同时把运行隔离在 microVM 里保护你的系统。你可以让智能体无人值守地干活，你每隔几分钟来查看一眼。

    代价呢？Docker Sandbox 并不会限制 哪些 命令能被 Claude 运行，它只是隔离这些命令 在哪里 运行。

    Docker Sandbox 留下的空档

    问题在于：你的 git 历史就存在那个沙箱文件夹里。

    Docker Sandbox 能阻止 Claude 伸手到项目目录之外，却拦不住 Claude 在那个目录里运行破坏性的 git 命令 内部 。仅一条 git reset --hard 或 git push --force 就能抹掉数周的工作。

    这个技能用一个硬护栏填上这个空档——阻止 Claude Code 运行危险命令。

    哪些操作会被阻止

    该技能默认阻止这些危险模式：

    • git push （包括所有变体，含 --force)
    • git reset --hard
    • git clean -f / git clean -fd
    • git branch -D
    • git checkout . / git restore .

    这些不是“永不允许”规则，而是“默认安全”规则。

    你可以在安装时自定义被阻止的模式，也可以随时编辑。如果你的工作流确实需要 Claude 推送远程 PR，你可以放行。

    工作原理：hook 系统

    该技能使用一个 PreToolUse hook，在 Claude 执行 bash 命令之前进行拦截。

    过滤脚本如下：

    #!/bin/bash

    

    INPUT=$(cat)

    COMMAND=$(echo "$INPUT" | jq -r '.tool_input.command')

    

    DANGEROUS_PATTERNS=(

      "git push"

      "git reset --hard"

      "git clean -fd"

      "git clean -f"

      "git branch -D"

      "git checkout \."

      "git restore \."

      "push --force"

      "reset --hard"

    )

    

    for pattern in "${DANGEROUS_PATTERNS[@]}"; do

      if echo "$COMMAND" | grep -qE "$pattern"; then

        echo "BLOCKED: '$COMMAND' matches dangerous pattern '$pattern'. The user has prevented you from doing this." >&2

        exit 2

      fi

    done

    

    exit 0

    脚本读取传入的命令，对照危险清单逐一检查，命中就阻止执行。

    Claude 看到什么

    当 Claude 试图运行被阻止的命令时，它会看到一条清晰的消息：

    BLOCKED: 'git push origin main' matches dangerous pattern 'git push'.

    The user has prevented you from doing this.

    Claude 理解这个约束并会随之调整。这是一个硬护栏，不是埋在散文里的建议。

    验证它是否生效

    安装之后，测试一下护栏：

    1. 清空你的会话上下文
    2. 让 Claude 运行 git push
    3. 看它失败并看到阻止消息

    这证明 hook 已经生效，Claude 无法意外绕过它。
