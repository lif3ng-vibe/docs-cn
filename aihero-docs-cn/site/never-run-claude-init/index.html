    永远别运行 Claude /init

    了解为什么自动生成的 Claude.md 文件会拖累你的编码智能体，以及用什么替代它来获得更好的性能和更低的成本。

    Matt Pocock

    如果你在使用 Claude Code 或任何编码智能体，有一个 init 命令，声称会创建一个 CLAUDE.md 或 agents.md 文件，里面写有关于你代码库的文档。

    永远别运行它。如果你发现一个自动生成的，直接删掉。

    它创建的文件会烧 token、分散智能体的注意力，而且过期的速度比大热天里的梨还快。 研究证实了这一点：不必要的上下文文件会让任务更难，而不是更简单。

    智能体如何使用上下文

    智能体的 上下文窗口（context window） 会分为几个阶段：

    阶段用途灵活性
    系统提示词LLM 指令、MCP 服务器、系统工具、 CLAUDE.md 内容不灵活，启动时即已固化
    探索理解代码库中有什么非常灵活
    实现编写和修改文件非常灵活
    测试运行测试、调试、反馈回路非常灵活，出问题时可能会膨胀

    探索、实现和测试都是灵活的。简单的任务不需要多少探索，没有 bug 的实现不需要多少测试。

    但 系统提示词（system prompt） 是 在智能体启动的那一刻就写死了。你 CLAUDE.md 里写的一切都会把它撑大，留给真正干活的阶段的余地就更少。

    缩小系统提示词能给你更多空间做实际工作，还能降低成本。

    指令预算

    LLM 有上下文窗口，但它们还受一个 指令预算（instruction budget）的约束：一次能遵循的指令数量有限。

    你的 CLAUDE.md 里的每一句话都是一条指令。LLM 实际上一轮大约能处理 300 到 400 条指令 。更大的模型也许能到 500 条。

    如果你往 CLAUDE.md里塞进几十条不相干的指令，那么在智能体开始处理你的任务之前，预算就已经被烧掉了。

    全局性问题

    一个常见的建议：如果智能体做了你不喜欢的事，就往 CLAUDE.md.

    也许它用 npm 而不是 pnpm，也许它用了你讨厌的 React 模式。于是你加一行规则。

    问题在于它是 CLAUDE.md 是 全局的。每条指令都作用于每一个会话：前端、后端、文档、数据库，无一例外。

    那条 React 规则对前端会话有用。但下一个会话可能是纯后端工作，它完全不相关；再下一个会话可能是在写文档。

    你加的每一行都有成本，而且无论相不相关，都会在每个会话中不断累积。

    init 实际生成的内容

    init 命令往往会生成同样几类内容，而它们全都有问题。

    命令清单。 init 热衷于把 package.json 里的每个脚本都倒进文件。这些信息一眼就能查到，智能体直接去读 package.json就行了。你是在花 token 复制事实来源。

    架构描述。 框架名、渲染模式、编译器设置。这些都能从配置文件和 imp或t 中发现。一个 react-router.config 文件已经能告诉它你在用 React Router。一个 effect imp或t 则告诉它你在用 Effect。

    文件与服务引用。 这是最糟的一类。init 会记录具体的文件、服务及其关系。一旦你重命名文件、移动服务或更改实现，这些文档就错了。它会开始 主动误导 智能体。

    实现模式。 具体功能如何运作、在哪里该用什么模式。这不仅可以从代码里发现，而且只对少数会话有意义。大多数任务不会碰到大多数模式。

    贯穿始终的主线：init 生成的东西，要么从源码一眼可查，要么终将过时。你的文件系统 是 本身就是文档。只要结构良好，智能体就能从事实来源获得你架构的准确图景，而不是从一份慢慢烂掉的摘要。

    解决方案

    信任探索步骤

    每个现代编码智能体都有探索阶段。在动手更改之前，它会读文件、搜索代码库，针对手头的任务即时构建上下文。

    这严格优于一份静态的 CLAUDE.md ，因为它只加载相关的内容，而且始终反映代码的当前状态。

    用技能来引导

    确实 是 存在你想给智能体的有益引导。也许你想让它在复杂 UI 状态时优先用 reducer，也许你想让它遵循特定的测试模式。

    这些内容应该放进 技能：即可被发现的指令，智能体在相关时才拉取，不会在每个会话里都烧掉指令预算。

    让 CLAUDE.md 几乎为空

    如果基础设置类的内容不该放进 CLAUDE.md，而引导类内容该放进技能，那还剩下什么？

    几乎什么都没有。我的整个 CLAUDE.md 内容是：

    you are on WSL on Windows

    六个词。写它是因为 WSL 有不直观的路径解析问题，智能体自己发现不了。门槛就在这里：只写既 无法自行发现的 又 全局相关的.

    最终结论

    永远别运行 init。它生成的文件会把不相关的信息倒进你的全局上下文，撑大你的系统提示词，浪费你的指令预算，而且你的代码一变它就烂掉。

    你要么烧 token 保持它不过时，要么把它删掉。直接跳到删除这一步吧。

    信任探索步骤。用技能来引导。让 CLAUDE.md 几乎为空。
