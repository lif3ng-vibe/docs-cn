    将你的 MCP 服务器发布到 NPM

    使用 Node.js 轻松将你的 MCP 服务器发布到 NPM，用简单的命令即可向全球推送更新。跟随我们的分步指南，分发毫不费力。

    Matt Pocock

    MCP 设计的一大好处是：借助随处可得的现成工具，就能非常轻松地分发 MCP 服务器。

    在本例中，我们要拿 我们之前写好的简单 MCP 服务器 并把它发布到 NPM。

    完成之后，任何安装了 Node 的用户都能立即通过 npx运行我们的 MCP 服务器。我们可以向它推送更新，用户会自动获取这些更新。

    我们将参考我之前发表在 Total TypeScript 上关于 如何创建 NPM 包.

    基础

    用户运行我们 MCP 服务器的方式是使用 npx。这是 Node.js 自带的工具，可以让用户运行 NPM 上的任何包。

    他们会运行这条命令：

    npx -y @mattpocockuk/mcp-server-example@latest

    这条命令会：

    1. 把我们包的最新版本下载到全局缓存（使用 @latest 标签）
    2. 忽略首次运行包时通常出现的确认提示（使用 -y 标志）。
    3. 运行该包的 package.json 文件里引用的那个文件

    所以，这是一种无需安装即可运行包的方式。

    值得注意的是，这并非没有风险。如果要运行来源不可信的包，务必先检查其源代码。

    设置服务器

    服务器和传输层（transport）会放在同一个文件里，文件名为 main.ts。这就是用户运行我们的服务器时所执行的文件。

    我们要在这个文件顶部添加一行：shebang。

    这是一个特殊的行，用来告诉操作系统如何运行该文件。在这里，我们是让它用 Node.js 来运行文件。

    #!/usr/bin/env node

    import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";

    import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";

    import { z } from "zod";

    

    const server = new McpServer({

      name: "Weather Service",

      version: "1.0.0",

    });

    

    server.tool(

      "getWeather",

      {

        city: z.string(),

      },

      async ({ city }) => {

        return {

          content: [

            {

              type: "text",

              text: `The weather in ${city} is sunny!`,

            },

          ],

        };

      },

    );

    

    const transport = new StdioServerTransport();

    await server.connect(transport);

    package.json

    我们还需要一个 package.json 文件来描述我们的包。它看起来是这样的：

    {

      "name": "@mattpocockuk/mcp-server-example",

      "version": "0.0.1",

      "description": "An example of a MCP server",

      "bin": {

        "mcp-server-example": "./dist/main.js"

      },

      "files": ["dist"],

      "type": "module",

      "scripts": {

        "build": "tsc",

        "ci": "npm run build",

        "prepublishOnly": "npm run ci"

      },

      "dependencies": {

        "@modelcontextprotocol/sdk": "^1.7.0"

      }

    }

    请注意，如果要把这段配置复制粘贴到自己的 package.json.

    package.json#bin

    这个文件中最重要的部分是 bin 字段。它会告诉 npx 在执行你的 MCP 服务器时该运行哪个文件。这一逻辑的工作细节描述于 这里。其中关键的引文是：

    如果包的 bin 字段在 package.json [...]，那么就会使用该命令。

    所以，只要在 bin 字段里只有一个条目，无论它叫什么名字，都意味着 npx 会去运行那个文件。在我们的例子里，它就是 mcp-server-example.

    {

      "bin": {

        "mcp-server-example": "./dist/main.js"

      },

    }

    我们要运行的文件是 ./dist/main.js。这个文件将由 TypeScript 构建生成。

    TypeScript

    TypeScript 将负责把我们的 .ts 文件转换成 Node 可以运行的文件，也就是 .js 文件。

    我们先来添加一个 tsconfig.json 文件：

    {

      "compilerOptions": {

        /* Base Options: */

        "esModuleInterop": true,

        "skipLibCheck": true,

        "target": "es2022",

        "allowJs": true,

        "resolveJsonModule": true,

        "moduleDetection": "force",

        "isolatedModules": true,

        "verbatimModuleSyntax": true,

    

        /* Strictness */

        "strict": true,

        "noUncheckedIndexedAccess": true,

        "noImplicitOverride": true,

    

        "module": "NodeNext",

        "outDir": "dist",

    

        "lib": ["ES2022"]

      }

    }

    这会告诉 TypeScript 如何构建我们的项目。其中最重要的部分是 outDir 字段。它告诉 TypeScript 应该把构建产物放在哪里。也就是说， main.ts 会变成 dist/main.js.

    发布我们的包

    要发布我们的包，需要运行以下命令：

    npm publish --access public

    这会把我们的包发布到 NPM。其中 --access public 标志表示任何人都可以安装它。

    你可能会遇到以下几种错误之一：

    • 如果你还没有登录，需要先运行 npm login 。
    • 如果你的包名已经被占用，就需要换一个名字。

    不过，把这些问题都解决之后，你的包就发布成功了！

    实际测试

    你可以运行以下命令来测试：

    npx -y @mattpocockuk/mcp-server-example@latest

    这会运行你包的最新版本。你也可以把 @latest 改成 @1.0.0 或其他任何你想运行的版本。

    奇怪的是，终端里不会显示任何东西。这是因为服务器正在监听 stdin，等待接收命令。

    你可以试着把它连接到 Cursor 这样的 MCP 服务器，让它查询你所在城市的天气。

    结语

    在本文中，我们看到了把 MCP 服务器发布到 NPM 有多么简单。这意味着任何安装了 Node.js 的用户都能用一条命令运行你的服务器。

    对于把 MCP 服务器分发给任何想使用的人来说，这是一种非常强大的方式。
