    什么是 token？

    了解 token 如何驱动 LLM、影响成本与效率，并学习编码、解码与词表大小，优化文本处理。

    Matt Pocock

    token 是帮助大语言模型（LLM）处理文本的基本构件。理解 token 至关重要，尤其你的账单是按 token 用量计算的。

    什么是 token？

    token 只是一些数字，表示 LLM 对你提供的文本的“思考”方式。把文本转换成 token 的过程称为 编码（encoding）.

    分词（tokenization）过程分两步：

    1. 分词器（tokenizer）把文本拆成它认识的 token
    2. 这些 token 被转换成数字

    解码（decoding）则是相反的过程：

    1. 数字被转换回文本 token
    2. 这些 token 拼接在一起，形成输出

    LLM 处理流程

    完整的 LLM 流程如下：

    1. 分词器把你的输入文本编码成 token
    2. LLM 处理你的 token
    3. LLM 产出 输出 token（output tokens）
    4. 输出 token 再被解码回可读文本

    澄清一下， 输入 token（input tokens） 包括：

    • 你与 LLM 的对话历史
    • 系统提示词
    • 工具定义

    输出 token 则是 LLM 作为响应发回的内容。

    输入和输出 token 都会计费，通常费率不同。省钱的一个办法，是设计提示词让它生成更少的输出 token。

    token 是如何产生的

    分词过程始于一个大型文本语料库——与训练 LLM 本身所用的语料类似。我们来想象一个只含一句话的迷你语料库：“the cat sat on the mat.”

    首先，提取出所有单个字符：

    T H E space C A T space S A T space O N space T H E space M A T

    每个字符都会在词表中成为自己的一个 token。

    接着，识别出常见的字符组合：

    • “TH”出现在“the”里（两次）
    • “HE”出现在“the”里（两次）
    • “AT”出现在“cat”“sat”和“mat”里

    这些组合也各自被分配一个 token。

    然后，再识别组合的组合——比如“TH”+“HE”组成“THE”（即“the”这个词），它也获得自己的 token。

    词表大小很重要

    目标是构建一个庞大的 token 词表，因为词表越大，就能把单词拆成越少的 token，处理效率也越高。

    例如，1,000 的词表大小可能把“understanding”拆成 5 个 token；50,000 的词表可能把它拆成 3 个 token，而 200,000 的词表可能把它拆成 2 个 token。

    拥有更大的词表，意味着你能把单词拆成更少的 token，处理也更高效。

    处理不常见的词

    分词器处理不常见的词会很吃力。例如，Lewis Carroll 诗中的“O Frabjous Day”会被拆成很多 token，因为“Frabjous”是个生造词，在训练语料中并不常见。

    可以看到，它被拆成了 7 个 token——比 15 个字符本该拆出的数量要多。
