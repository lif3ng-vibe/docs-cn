    软件工程的格局正在变化。随着 AI API 与开源模型的普及，一个新角色应运而生： AI 工程师。这些开发者专注于构建利用 AI 能力的应用。

    本文基于那篇开山之作 “AI 工程师的崛起（The Rise of the AI 工程师）” ，来自 Latent Space。所有职位头衔都不完美，但有些是有用的。他们极具说服力地论证了 AI 工程师为何契合市场中日益增长的需求。我推荐完整读一读。

    什么是 AI 工程师？

    AI 工程师是构建 AI 驱动应用的软件开发者。这听起来可能让人望而却步，但其实没那么可怕：

    • 你不需要懂线性代数或高等数学
    • 你不需要知道如何从零构建基础模型（foundation model）
    • 你不需要读过《Attention is All You Need》

    而你确实需要的是：

    • 扎实的软件工程基础
    • 构建可靠、可扩展应用的能力
    • 了解现代 AI 工具与框架
    • 关注用户体验与实际应用

    AI 工程师架起了传统软件工程与人工智能之间的桥梁。他们的日常是编排 AI API、实现 RAG 系统，并构建健壮的评测系统，确保应用稳定可靠地运行。

    而且他们用当下最火的新编程语言写着大量代码： 英语.

    AI 工程与 ML 工程

    AI 工程不是 ML 工程。它们是两种不同的角色，侧重点和要求各不相同。

    理解这种差异的一个实用视角，是看 API 边界：

    • AI 工程师 构建通过 API 使用 AI 模型的应用。
    • ML 工程师 构建 AI API 本身。

    下面快速对比一下这两种角色：

    ML 工程师AI 工程师
    主要方向模型训练与优化用这些模型构建应用
    专业能力深入掌握数学、统计学与模型架构扎实的软件工程基础
    语言仅 PythonPython 和 TypeScript
    教育背景通常要求高阶教育软件工程背景
    市场高度专业化，需求旺盛快速增长，更易上手

    ML 工程是一条专业化的路线，需要高阶教育，薪酬也更高。ML 工程师非常稀缺，市场需求旺盛。

    AI 工程更容易上手，需求也在增长。它是软件开发中增长最快的领域之一。随着 AI 工具与 API 的平民化，软件工程师可以相对轻松地转型进入 AI 工程。

    这不就是提示词工程吗？

    但 AI 工程师难道不只是包装华丽一点的提示词工程师吗？这个角色到底有多大深度？

    这是一种常见的误解。AI 工程师面临的复杂挑战远远超出编写提示词：

    • 构建能应对 AI 固有不可预测性的生产级系统
    • 设计评测框架，度量和改进系统性能
    • 打造反馈回路，让系统从用户交互中学习
    • 管理包含多个模型与 API 的复杂 AI 架构
    • 确保系统安全无虞，符合隐私法规
    • 在整个应用栈上优化成本与性能

    真正的挑战不在于写提示词——而在于构建可靠、可扩展的应用：既有效利用 AI 能力，又遵循软件工程最佳实践。

    AI 工程师与 AI 辅助开发者

    来澄清一个常见的混淆：

    • 一名 AI 工程师 会构建使用 AI 的应用（比如 ChatGPT 套壳或 RAG 系统）。
    • 一名 AI 辅助开发者 则借助 AI 工具（如 Cursor 或 GitHub Copilot）更快地写代码。

    两种角色都用 AI，但目的不同：AI 工程师创造 AI 驱动的应用，而 AI 辅助开发者用 AI 提升自己的开发工作流。

    Web 开发者能成为 AI 工程师吗？

    当然能！Web 开发者非常适合成为 AI 工程师。优秀的 Web 开发者都有一个共同特质：对实际交付和用户需求的极致专注——这些品质在 AI 工程领域同样关键。

    你在构建应用上已有的直觉，可以直接迁移到构建有效的 AI 系统上。在 AI 工程中，UX 与 Web 开发里同样重要。

    懂一些 Python 固然有用，但 TypeScript 生态发展迅速，同样非常适合 AI 工程。
