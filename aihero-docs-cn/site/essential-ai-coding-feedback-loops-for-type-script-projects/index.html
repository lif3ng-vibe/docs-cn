    TypeScript 项目必备的 AI 编程反馈回路

    学习用 TypeScript 构建 AI 编程反馈回路。掌握类型检查、测试与 pre-commit hook，让 AI 智能体始终正确工作。

    与 AI 编程智能体协作时，尤其是它们独立运行的时候，你需要反馈回路（feedback loop）让 AI 校验自己的工作。当你在做 AFK 编程时——比如使用 Ralph Wiggum.

    1. 设置 TypeScript 与类型检查

    TypeScript 本质上是为你的 AI 提供了免费的反馈。请用它而不是 JavaScript。

    创建一个 typecheck 脚本，加到你的 package.json:

    {

      "scripts": {

        "typecheck": "tsc"

      }

    }

    TypeScript 能捕获 AI 不在浏览器里测试就永远发现不了的错误。

    2. 添加自动化测试

    使用类似 Vitest 这样的测试框架来捕捉逻辑错误：

    {

      "scripts": {

        "test": "vitest"

      }

    }

    覆盖核心功能的基础单元测试，有助于让 AI 不跑偏。

    3. 安装 Husky 以使用 pre-commit hook

    Husky 会在每次提交前强制执行反馈回路。

    安装并初始化 Husky：

    pnpm install --save-dev husky

    pnpm exec husky init

    创建一个 .husky/pre-commit 文件，让它运行你的所有检查：

    npx lint-staged

    npm run typecheck

    npm run test

    任何一步失败，提交就会被阻止，AI 会收到一条错误消息。

    另一个强大的反馈回路，是确保 LLM 能在本地访问你正在运行的开发服务器，来检查你的前端。 观看这个视频 了解如何设置。

    4. 设置自动代码格式化

    使用 lint-staged 搭配 Prettier 在提交前自动格式化代码。

    安装 lint-staged：

    pnpm install --save-dev lint-staged

    配置 .lintstagedrc:

    {

      "*": "prettier --ignore-unknown --write"

    }

    它会对所有已暂存的文件运行 Prettier，并自动重新暂存。这样，所有 AI 生成的代码都符合你的格式规范。

    我们也可以在这里运行 ESLint ，因为它和 lint-staged 配合得很好。

    为什么这对 AI 有效

    AI 智能体不会因为重复而烦躁。当代码没通过类型检查或测试时，智能体只会再试一次。这让反馈回路（尤其是 pre-commit hook）在 AI 驱动的开发中威力惊人。
