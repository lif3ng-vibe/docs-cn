    Ralph 入门

    学会以循环方式运行 AI 编码智能体。配置 Claude Code、创建 PRD，让你在离开键盘时 AI 也能交付特性。附分步指南。

    Ralph 是一种让 AI 编码智能体循环运行的技术。你反复运行同一条提示词，AI 从 PRD 里自己挑任务，每个特性完成后提交，你稍后回来就能看到能跑的代码。

    本指南带你构建你的第一个 Ralph 循环。我们将使用 Claude Code 和 Docker Desktop.

    本文假设 Linux 环境，但你可以把这篇文章丢给 AI，让它为你的操作系统或 AI 编码 CLI 转换。

    想了解更多榨干 Ralph 的技巧，看看我的 使用 Ralph 进行 AI 编码的 11 条技巧.

    1. 安装 Claude Code

    Claude Code 是 Anthropic 的智能体编码 CLI。用原生二进制安装：

    curl -fsSL https://claude.ai/install.sh | bash

    如果安装后出现 "comm和 not found: claude"，把安装位置加进你的 PATH：

    echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc

    source ~/.bashrc

    或者通过 npm:

    npm i -g @anthropic-ai/claude-code

    运行 claude 以你的 Anthropic 账户完成认证。

    2. 安装 Docker Desktop

    Docker Desktop 让你在隔离的 沙箱中运行 Claude Code。AI 可以执行命令、安装包、修改文件，而不碰你的本地机器。

    安装 Docker Desktop 4.50+，然后运行：

    docker sandbox run claude

    首次运行时你需要用 Anthropic 认证。凭据存储在一个 Docker 卷里。

    沙箱的关键好处：

    • 你的工作目录在容器内挂载于相同路径
    • 自动注入 git 配置，保证提交署名正确
    • 每个工作区一个沙箱——状态在多次运行之间保留

    详见 Docker S和boxes 文档 。

    3. 创建你的计划文件

    Ralph 需要一份 PRD（产品需求文档）来挑任务。你可以手写一份，但更快的做法是用 Claude 的 计划模式（plan mode）.

    运行 Claude：

    claude

    然后按 shift-tab 进入 计划模式（plan mode）。你可以反复打磨计划，直到满意为止。

    对计划满意后，让 Claude 把它保存为 PRD.md.

    再创建一个空的进度文件：

    touch progress.txt

    PRD 定义最终状态，进度文件追踪已完成的事。Claude 在每轮循环读取两者，找出下一个未完成项，实现它，并更新进度。

    PRD 可以是任何格式——Markdown 清单、JSON、纯文本都行。关键是范围清晰，智能体能拆出单个任务。更多写好 PRD 的技巧见我的 使用 Ralph 进行 AI 编码的 11 条技巧.

    4. 创建你的 ralph-once.sh 脚本

    在完全 AFK之前，先用人在回路（HITL）的 Ralph。你运行脚本，观察它做什么，然后再跑一次。这能建立对循环如何工作的直觉。

    创建 ralph-once.sh:

    #!/bin/bash

    

    claude --permission-mode acceptEdits "@PRD.md @progress.txt \

    1. Read the PRD and progress file. \

    2. Find the next incomplete task and implement it. \

    3. Commit your changes. \

    4. Update progress.txt with what you did. \

    ONLY DO ONE TASK AT A TIME."

    关键要素：

    要素作用
    --permission-mode acceptEdits自动接受文件编辑，避免循环卡住
    @PRD.md让 Claude 指向你的需求文档
    @progress.txt在多次运行之间追踪已完成的工作
    ONLY DO ONE TASK强制小步增量提交

    给它加可执行权限：

    chmod +x ralph-once.sh

    用 ./ralph-once.sh运行它。观察 Claude 在做什么，检查提交，再跑一次。

    5. 创建你的 afk-ralph.sh 脚本

    等你用惯了人在回路的 Ralph，把它包进一个循环：

    #!/bin/bash

    set -e

    

    if [ -z "$1" ]; then

      echo "Usage: $0 <iterations>"

      exit 1

    fi

    

    for ((i=1; i<=$1; i++)); do

      result=$(docker sandbox run claude --permission-mode acceptEdits -p "@PRD.md @progress.txt \

      1. Find the highest-priority task and implement it. \

      2. Run your tests and type checks. \

      3. Update the PRD with what was done. \

      4. Append your progress to progress.txt. \

      5. Commit your changes. \

      ONLY WORK ON A SINGLE TASK. \

      If the PRD is complete, output <promise>COMPLETE</promise>.")

    

      echo "$result"

    

      if [[ "$result" == *"<promise>COMPLETE</promise>"* ]]; then

        echo "PRD complete after $i iterations."

        exit 0

      fi

    done

    这个 -p 标志让 Claude 以 print 模式运行——非交互、输出到 stdout。这样我们才能捕获结果、检查完成印记（sigil）。

    ./afk-ralph.sh 20

    去泡杯咖啡吧。回来就有提交等着你。

    要素作用
    set -e任何错误即退出
    $1 （迭代次数）给循环设上限，防止成本失控
    -pprint 模式——非交互输出
    <promise>COMPLETE</promise>Claude 完成时输出的完成印记

    6. 打造属于你的 Ralph

    Ralph 只是一个循环。这份简单让它有无限的可定制性。

    你可以更换任务来源。不用本地 PRD，改从 GitHub Issues、 Linear或 beads拉取任务。选什么任务仍然由智能体决定——你只是换了个清单存放的地方。

    你可以改变产出方式。不直接提交到 main，每次迭代可以建分支并开 PR。对分诊积压的 issue 很有用。

    你还可以跑完全不同的循环类型：

    循环类型它做什么
    测试覆盖率找出未覆盖的行，写测试直到覆盖率达目标
    Lint逐个修复 lint 错误
    重复代码接入 jscpd，把克隆代码重构成共享工具函数
    熵扫描代码异味并清理

    任何符合"看看仓库、改进点什么、提交"的任务都适用于 Ralph。
