    如何消灭 Claude Code 系统提示词里的冗余

    Matt Pocock

    你发给 Claude Code 的每条消息，都附带一份你从来看不到的负载。不是你的提示词——而是围绕它的机器部件：工具定义、技能目录、你可能永远碰不到的功能的系统指令。它随每次请求发出，每一轮都计入你的账单。

    其中大部分你可以移除。下面六个步骤会先教你看清请求里到底装了什么，再用 Claude Code 自带的两个设置来修剪。我的每轮负载降了数万 token。

    1. 测量你的上下文，用 /context

    输入 /context （在任何 Claude Code 会话中）。它把你的 上下文窗口（context window） 按类别拆解—— 系统提示词（system prompt）、系统工具、MCP 工具、记忆文件、消息——每一类都给出 token 计数及其占窗口的比例。

    在改动任何东西之前，先记下这些数字。最后一步你要拿来对比。

    /context 把工具作为一组来展示。它不会告诉你哪个单独的工具最大——它只报一个“tools”总数，不做排名。下一步来解决这个问题。

    2. 用日志代理找出最大的元凶

    Claude Code 通过 HTTP 与 Anthropic API 通信，所以你可以在中间放一个代理，让它原样转发每个请求、把回复直接流回，并记录经过的内容。CLI 察觉不到任何异样。

    获取 proxy.mjs ——单文件、零依赖，只用 Node 内置模块。运行它：

    node proxy.mjs

    在另一个终端把 Claude Code 指向它，然后发一条消息：

    ANTHROPIC_BASE_URL=http://localhost:8787 claude

    每个请求都会写入 ./logs/ ，内容是可读的 Markdown，终端同时打印一张排名表：

    [agent-proxy] 69 tools · 154,946 tool bytes · 65,538 real input tokens

      Workflow      21229 B  ~5307 tok

      DesignSync     8978 B  ~2245 tok

      Monitor        7767 B  ~1942 tok

      …

    打开 Markdown 文件读一读：每个工具的完整 schema、系统提示词、消息历史——模型收到的完整请求。顶部的排名表就是你的工作清单，你可以精准移除自己用不到的工具，而不是靠猜。

    现在你知道负载里有什么、哪几块最大了。接下来两步把它们移除。这两个设置都放在你的设置文件里—— ~/.claude/settings.json 管所有项目，或 .claude/settings.json 只管单个项目。

    3. 整体关闭功能，用 disable* 开关

    有些功能会随身带来一整组工具和指令。一个开关就能把功能连同它携带的一切一起关掉：

    • disableBundledSkills ——一次性移除 Anthropic 内置的全部技能（即 dataviz, review, init 目录），同时它们的斜杠命令仍可键入。
    • disableWorkflows ——移除多智能体的 Workflow 工具，表格里最大的一行。

    只要某个功能名不副实，就用其中一个开关把它关掉。

    4. 移除单个工具，用 deny 规则

    对单个工具，一条 permissions.deny 规则只要写上裸工具名，就能把该工具的定义从负载中移除——Claude 根本看不到它：

    {

      "permissions": {

        "deny": ["NotebookEdit", "CronCreate"]

      }

    }

    一个值得知道的细节：裸名称（"NotebookEdit"）会移除工具。带作用域的规则（"Bash(rm *)", "Skill(dataviz)"）会拦截匹配的调用，但定义仍留在负载里。想缩小请求体积，就用裸名称。

    上一步的开关是宽口径的第一遍；这些 deny 规则负责挑掉开关没覆盖到的单个工具。

    想保留一部分技能而不是全部？ disableBundledSkills 是全有或全无的。想逐个移除，用 skillOverrides ，把某个技能设为 "off" （从负载中移除）或 "user-invocable-only" （仍可键入，但 Claude 看不到它）。

    5. 应用完整配置

    下面就是前两步的产物——用来修剪冗余的开关与 deny 规则，可直接放进 ~/.claude/settings.json:

    {

      "permissions": {

        "deny": [

          "EnterPlanMode",

          "ExitPlanMode",

          "DesignSync",

          "NotebookEdit",

          "SendMessage",

          "PushNotification",

          "RemoteTrigger",

          "ReportFindings",

          "ScheduleWakeup",

          "AskUserQuestion",

          "CronCreate",

          "CronDelete",

          "CronList"

        ]

      },

      "disableBundledSkills": true,

      "disableWorkflows": true,

      "disableRemoteControl": true,

      "disableClaudeAiConnectors": true,

      "disableArtifact": true

    }

    把它当菜单，别当处方。先看清自己负载的原因，就是让你砍掉自己用不到的东西。如果你在 计划模式（Plan Mode）下工作，就留着它。如果你写 notebook，就保留 NotebookEdit。上面这份清单就是我自己实际移除的内容。

    一个提醒：有些看似冗余的东西，是后台任务和多智能体运行所依赖的机器部件——任务工具、 Workflow、worktree 工具。如果你在用，就保留。

    想要我整套 Claude Code 配置、连同冗余移除一起吗？ /setup-matt-pocock-skills 技能一次运行即可套用。

    6. 再次测量，用 /context

    重启 Claude Code 让它重新加载设置，然后再次运行 /context 。工具数量与 token 总数都应该变低了。

    这个差值就是你过去每轮都在发、现在不再发的 token——请求更便宜，模型在触及你的问题之前要翻过的杂音也更少。
