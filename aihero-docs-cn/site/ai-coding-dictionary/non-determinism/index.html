    模型

    Non-determinism（非确定性）

    相同的输入可能产生不同的输出。这是模型生成文本方式与提供商服务请求方式的固有属性。

    Matt Pocock

    相同的输入可能产生不同的输出。把一个 模型（model） 用完全相同的 上下文（context） 跑两次，你可能得到两个不同的答案——有时只差一个词，有时是完全不同的思路。代码一行都不用改，这种情况就会发生。

    这是模型生成文本方式的属性，也是 模型提供商（模型（model） provider） 服务 请求（request）的方式所带来的。在 推理（inference）期间，模型会为所有可能的下一个 token 生成一个概率分布，并从中采样出一个——通常故意带些随机性，因为永远挑概率最高的 token 会产生重复、质量更低的文本。回答早期一个被不同采样的 token 会改变它之后的每一个 token，这就是为什么一个词不同，整条思路就完全不同。提供商侧的服务再叠上一层变化：请求在共享硬件上批量执行，批次之间微小的浮点数差异就能在两个 token 难分伯仲时一锤定音。没有任何设置能把这些全部消除。

    要有心理准备：同一任务上，来自 智能体 的结果会是一片分布。大多数回答都落在一条还算像样的质量钟形曲线之内——非确定性之所以还能容忍，正因为如此——但两条尾巴是真实存在的：有些日子模型会显得锋利；有些日子它像是丢了魂。同一个任务，不同的掷骰结果。这有两个实际推论。重试是一种正当策略：一次失败不过是从分布里抽出的一次样本，同一任务再试一次可能就是更好的一注。而且验证比在确定性工具里更要紧——你没法测一次智能体的行为就指望它次次复现，所以 自动化检查 得负责拦住那些坏签。

    小心别把这过度叙事化。人类是模式匹配机器，一连串糟糕的运行会让你觉得这就是“模型这周变差了”的证据。通常那只是分布而已。

    用法：

    “Claude 今天糟透了。是他们上线了更差的版本吗？”

    “多半不是——模型输出是非确定性的。同一个任务你总会遇到好日子和坏日子。明天再试一次，再去找原因。”
