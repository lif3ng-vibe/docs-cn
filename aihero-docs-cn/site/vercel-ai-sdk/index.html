    Vercel AI SDK 让你的 AI 技术栈面向未来

    用 Vercel AI SDK 为你的 AI 功能做好面向未来的准备。一次编写，即可在 OpenAI、Anthropic 及其他 LLM 提供商之间随处运行。

    Matt Pocock
    本页内容

    AI 领域每周都在变，你的代码不该跟着变。

    这就是为什么 Vercel AI SDK 是 我最先拿起的工具之一 ——在 TypeScript 中构建 AI 功能的时候。它实在太出色，我正打算把它变成 AI Hero 的基础构建块.

    供应商锁定很糟心

    每个 LLM 提供商都有自己的 API，但功能和怪癖都略有不同。如果你的应用直接构建在其中某个 API 之上，往往就会集成得太深、难以轻松切换。

    虽然这些 API（和 SDK）表面上看起来足够相似， 在它们之间切换却很痛苦 ——你经常需要写大量包装代码来处理它们之间的差异。

    下面是处理不同提供商的典型包装代码的样子：

    // This example is BAD - what code looks like without

    // Vercel's AI SDK.

    

    import OpenAI from "openai";

    import Anthropic from "@anthropic-ai/sdk";

    

    // 1. Initialize both clients

    const openai = new OpenAI({

      apiKey: "my_api_key",

    });

    const anthropic = new Anthropic({

      apiKey: "my_api_key",

    });

    

    // 2. Switch between them based on the client

    const ask = async (

      question: string,

      client: "openai" | "anthropic",

    ) => {

      // If we're using OpenAI, use their SDK

      if (client === "openai") {

        return await openai.chat.completions.create({

          messages: [{ role: "user", content: question }],

          model: "gpt-4o",

        });

      } else {

        // If we're using Anthropic, use their SDK

        return await anthropic.messages.create({

          model: "claude-3-5-sonnet-20241022",

          max_tokens: 1024,

          messages: [{ role: "user", content: question }],

        });

      }

    };

    随着你接入的提供商越来越多，情况只会越来越糟，尤其是每个提供商都有自己的怪癖和特性时。它会让 切换模型变得格外困难 ——一旦有新模型出现，你的应用就可能陷进供应商锁定的流沙里。

    想看一个更可怕的例子——流式传输，请查看下面的附录。

    单一、统一的 API

    Vercel AI SDK 通过提供一个 单一、统一的 API 解决了这个问题，它包裹了所有主流的 LLM 提供商。同样的代码，用 Vercel AI SDK 写出来是这样的：

    import { generateText, type LanguageModel } from "ai";

    

    export const ask = async (

      prompt: string,

      model: LanguageModel,

    ) => {

      const { text } = await generateText({

        model,

        prompt,

      });

    

      return text;

    };

    现在，我们可以把 任意 AI SDK 支持的模型传给 ask，它都能正常工作：

    import { anthropic } from "@ai-sdk/anthropic";

    import { openai } from "@ai-sdk/openai";

    

    const prompt = `Tell me a story about your grandmother.`;

    

    const anthropicResult = await ask(

      prompt,

      anthropic("claude-3-5-haiku-latest"),

    );

    

    const openaiResult = await ask(

      prompt,

      openai("gpt-4o-mini-2024-07-18"),

    );

    这样一来， 在模型之间切换 就变得容易得多 ——你的整个应用都可以构建在 AI SDK 之上，切换模型只需一行代码。

    这也意味着你可以 只学一次这套 API ，然后在所有项目中通用。这对生产力是巨大的提升，尤其当你要构建大量 AI 功能时。

    一个更可怕的例子

    再举一个提供商差异的例子：流式补全（streaming completions）。OpenAI 的流式响应长这样：

    const stream = await openai.chat.completions.create({

      messages: [{ role: "user", content: prompt }],

      model: "gpt-4",

      stream: true,

    });

    

    for await (const chunk of stream) {

      const content = chunk.choices[0]?.delta?.content;

      if (content) {

        // Each chunk contains a delta of new content

        process.stdout.write(content);

      }

    }

    而 Anthropic 的长这样：

    const stream = await anthropic.messages.create({

      messages: [{ role: "user", content: prompt }],

      model: "claude-3-sonnet",

      stream: true,

    });

    

    for await (const chunk of stream) {

      if (chunk.type === "content_block_delta") {

        // Anthropic uses a different structure with content blocks

        process.stdout.write(chunk.delta.text);

      }

    }

    而用 Vercel AI SDK，你只需要这样写：

    const ask = async (

      prompt: string,

      model: LanguageModel,

    ) => {

      const { textStream } = await streamText({

        model,

        prompt,

      });

    

      // The textStream is the same for all providers!

      for await (const chunk of textStream) {

        process.stdout.write(chunk);

      }

    };

    妙极了。
