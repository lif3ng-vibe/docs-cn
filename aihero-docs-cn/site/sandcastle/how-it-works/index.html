    工作原理

    在 GitHub 上编辑此页

    Sandcastle 使用 分支策略 ，它配置在沙箱提供方上，用于控制智能体的改动与分支之间的关系。共有三种策略：

    • Head（直写） ({ type: "head" }）——智能体直接写入宿主机工作目录。不建 worktree，也没有分支间接层。默认用于 docker().
    • Merge-to-head（合并回 HEAD） ({ type: "merge-to-head" }）——Sandcastle 在一个 git worktree 中创建临时分支。智能体在临时分支上工作，完成后改动合并回 HEAD。临时分支在合并后会被清理。
    • Branch（指定分支） ({ type: "branch", branch: "foo" }）——提交落在 git worktree 中一个显式命名的分支上。用同一分支重新运行时，会复用现有的 worktree，并在安全时从 origin 快进（fast-forward）。参见 ADR 0003.

    对绑定挂载提供方（如 Docker）来说，worktree 目录会被绑定挂载进容器——智能体通过挂载直接写入宿主机文件系统，因此无需同步。

    从你的视角看，你只需在 branchStrategy: { type: 'branch', branch: 'foo' } 上配置 run()，然后等运行完成，就能在分支 foo 上拿到提交。全程 100% 本地。
