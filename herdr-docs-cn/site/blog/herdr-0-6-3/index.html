Herdr 0.6.3：会话持久化、更安全的更新与工作区导航

本次更新为更新流程、服务器重启与更大规模的会话新增了持久化路径。

为最难的部分做持久化

让会话保持存活，意味着要处理好几种不同情况：客户端断开、服务器停止、终端历史回放、智能体对话恢复，以及一次更新交接。每一种情况保护的都是工作区的不同部分。

Herdr 0.6.3 改进了其中三条路径。

服务器重启后的智能体恢复

当 Herdr 服务器停止时，普通窗格进程也会随之停止。原生智能体恢复（native agent restore）就是在这类重启之后，把受支持智能体的对话找回来的路径。

配置 [session] resume_agents_on_restore = true 后，Herdr 可以利用受支持集成提供的官方会话引用，把 Pi、Claude Code、Codex、OpenCode 与 Hermes 的窗格重新拉起，并接回它们之前的对话。

阅读会话恢复文档。

窗格屏幕历史

窗格屏幕历史解决的是重启恢复的"视觉"那一半。启用后，Herdr 会保存窗格近期的输出，并在恢复窗格时回放进去，让工作区回来时不再是一排空终端。

对于 shell、日志、开发服务器和智能体窗格，它都很实用——这些场景里，近期的输出恰好说明了服务器停止前正在发生什么。

阅读文档，了解窗格历史与实时持久化的区别。

更新时的实时交接

实时交接（live handoff）是针对受支持运行中会话的更新路径。Herdr 不再停掉旧服务器、杀掉窗格进程，而是请旧服务器把活着的 PTY 归属权移交给更新后的服务器。

该功能目前仍是实验性的，需要显式选择启用：通过 herdr update --handoff 和 herdr --remote <host> --handoff。在功能积累更多真实场景验证之前，默认路径保持保守。

阅读实时交接文档。

想了解技术背景，可以读这篇深挖文章：实时更新，不杀你的终端进程。

会话导航器

大型 Herdr 会话需要快速移动。新的会话导航器（session navigator）按 prefix+g 即可打开，为你呈现一棵可搜索的工作区、标签页与窗格树。

整棵工作区、标签页与窗格树一目了然。按 / 可按文本模糊查找；按 b、w、i 或 d，可分别按被阻塞、工作中、空闲或已完成筛选窗格；按 a 或 Backspace 可清除状态筛选。

借助它，你可以直接跳到需要关注的窗格，而不必在侧边栏里逐个翻找。

更多终端工作流打磨

直接接入智能体终端（attach）的视图现在支持回滚——当正在运行的终端应用没有为自己请求这类输入时，PageUp、PageDown 和鼠标滚轮滚动都能在接入视口中生效。

Herdr 还为包管理器安装方式带来了更好的更新与远程引导（remote-bootstrap）行为，让高负载下的事件投递更可靠，并修复了智能体检测、终端颜色、声音提醒与集成生命周期处理等方面的若干问题。

窗格元数据上报

新增的 pane.report_metadata socket 方法与 herdr pane report-metadata CLI 命令，让集成和本地钩子能够自定义 Herdr 为窗格显示的内容。

安装之后，集成就可以上报标题、对外可见的智能体名称、紧凑状态标签、状态标签以及原生会话元数据，而不会接管无关的生命周期行为。

你也可以在自己的脚本里使用它。例如，钩子可以把一个窗格标记为正在执行部署、给长期运行的任务改名，或者让智能体为手头的工作上报更具体的状态。

这为集成提供了一条受支持的途径来提升窗格的可读性，同时保持 Herdr 的会话与智能体归属规则原封不动。

阅读 socket API 文档。
