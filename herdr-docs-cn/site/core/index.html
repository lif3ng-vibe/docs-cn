herdr-core · hc

永不松手
的终端。

面向编码智能体的终端运行时。hc 在常驻存活的终端里运行程序，让智能体能够启动并操控其他智能体，也让你能随时 attach 到其中任何一个、接手现场。Herdr 应用正是构建在它之上。

$ curl -fsSL https://releases.herdr.dev/core/install.sh | sh
$ powershell -c "irm https://releases.herdr.dev/core/install.ps1 | iex"

取材于一轮真实运行：Claude Code 通过 hc 启动了一次测试运行和一个 Codex 审阅者，它们的回报直接落进它自己的输入。

##跑得起来，留得住

每个程序都运行在一个由 herdr-core 托管的终端里，而不是某个窗口里。关掉应用、退出终端、更新其中任意一个，程序都照常运行；你随时可以重新 attach，从它原本的位置接手。

# 运行它并等待，就像 shell 那样
hc run cargo test
# 启动它并立即返回
hc run --bg --name web bun dev
# 查看正在运行的东西
hc ls
# 接手它（ctrl+\ 分离）
hc attach web

hc update 负责更新 herdr-core 本身，正在运行的终端继续运行。

##智能体指挥智能体

一个智能体可以启动辅助智能体（helper），给它们分配工作、等待它们，并读取它们做了什么。辅助智能体归属于启动它的那个智能体之下，完成后回报，启动者停止时它们也随之停止。

# 启动一个智能体，并告诉它如何回报
hc run --bg --name review codex "review src/x.rs. Done: hc send $HC_TERMINAL_ID"
# 等它完成，再读取输出
hc wait review
hc read --lines 60 review
# 操控它
hc send review "also check the tests"

智能体一次读取即可拿到完整手册：hc --skill。

本站的示例布局 recipe 正是这样写成的：一个智能体把任务交给一个辅助智能体，自己继续干活，并在任务完成时收到回报。

##每一台机器

把你的服务器、虚拟机或另一台笔记本通过 SSH 添加进来。它的终端会汇入同一个列表，你在那里的操作方式完全相同。

hc machine add box@my-server
hc run --on my-server --bg claude
hc ls                # 本机与 my-server 一起显示

##状态来自源头

herdr-core 不做任何绘制，也不做任何猜测。终端的状态（working 工作中、done 已完成、needs you 需要你）是由它里面的程序通过 OSC 7501 亲自上报的——这是一套开放的程序状态协议（Program Status Protocol）。不做屏幕刮取，也不维护已知智能体名单。任何会说这套协议的程序都有状态；你自己的脚本同样可以。

printf '\e]7501;state=blocked:app=my-agent\e\\'

##打造你自己的客户端

Herdr 应用只是其中一个客户端。同一套 API 也向你自己开放：手机应用、编辑器面板、Stream Deck 都可以。hc schema 会以 OpenRPC 形式打印出这套 API，并附带用于实时更新的流（stream）与事件（event）。
