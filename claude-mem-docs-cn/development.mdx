# 开发指南

## 从源码构建

### 前提条件

- Node.js 20.0.0 或更高版本
- npm（随 Node.js 附带）
- Git

### 克隆与构建

```bash
# 克隆仓库
git clone https://github.com/thedotmack/claude-mem.git
cd claude-mem

# 安装依赖
npm install

# 构建所有组件
npm run build
```

### 构建过程

构建流程使用 esbuild 编译 TypeScript：

1. 将 TypeScript 编译为 JavaScript
2. 为 `plugin/scripts/` 下的每个 Hook 生成独立可执行文件
3. 将 MCP 检索服务打包为 `plugin/scripts/mcp-server.cjs`
4. 将 worker 服务打包为 `plugin/scripts/worker-service.cjs`
5. 将 Web 查看器 UI 打包为 `plugin/ui/viewer.html`

**构建产物**：
- Hook 可执行文件：`*-hook.js`（ESM 格式）
- Setup 版本检查：`version-check.js`（ESM 格式，手写脚本；负责安装缺失的插件依赖，并记录安装标记）
- worker 服务：`worker-service.cjs`（CJS 格式）
- MCP 服务：`mcp-server.cjs`（CJS 格式）
- 查看器 UI：`viewer.html`（自包含 HTML 打包产物）

### 已提交的发布产物（committed release bundles）

Marketplace 安装运行的是 `plugin/scripts/` 中已提交的文件。若修改了发布版本或 worker 生命周期相关代码，需要用 `npm run build` 重新生成并提交受影响的运行时产物。较新的 manifest 配上较旧的 worker 产物，可能触发反复的版本不匹配重启。

CI 会在重新构建**之前**检查已提交产物的版本一致性：

```bash
bun test tests/infrastructure/version-consistency.test.ts
```

如果替换后的 worker 仍上报旧版本，Hook 会把失败的 recycle 记录到数据目录，并跳过对该未变更产物的后续 recycle。重新构建或重装产物即可修正版本；产物内容发生变化后，才允许再次尝试 recycle。

### 构建脚本

```bash
# 构建全部
npm run build

# 只构建 Hook
npm run build:hooks

# 构建脚本定义在 scripts/build-hooks.js 中
```

## 查看器 UI 开发

Web 查看器 UI 是一个 React 应用，最终构建为自包含的 HTML 打包产物。

**所在位置**：`src/ui/viewer/`

**目录结构**：
```

│   ├── Sidebar.tsx        # 项目过滤侧边栏
│   ├── Feed.tsx           # 主信息流（无限滚动）
│   ├── cards/             # 卡片组件
│   │   ├── ObservationCard.tsx
│   │   ├── PromptCard.tsx
│   │   ├── SummaryCard.tsx
│   │   └── SkeletonCard.tsx
├── hooks/                 # 自定义 React Hook
│   ├── useSSE.ts          # Server-Sent Events 连接
│   ├── usePagination.ts   # 无限滚动分页
│   ├── useSettings.ts     # 设置持久化

├── utils/                 # 工具函数
```

### 构建查看器 UI

```bash
# 构建全部（包含查看器）
npm run build

# 查看器构建到 plugin/ui/viewer.html
# 是一个内联了 JS 与 CSS 的自包含 HTML 文件
```

### 测试查看器改动

1. 修改 `src/ui/viewer/` 中的 React 组件
2. 构建：`npm run build`
3. 同步到已安装的插件：`npm run sync-marketplace`
4. 重启 worker：`npm run worker:restart`

**热重载**：目前不支持。任何改动都需要完整重新构建 + 重启。

**示例：新增一种卡片类型**

1. 在 `src/ui/viewer/components/cards/YourCard.tsx` 中创建组件：

```tsx

  // Your data structure

  return (

```

### 查看器 UI 架构

**数据流**：
1. worker 服务对外提供 HTTP + SSE 端点
2. React 应用通过 HTTP 分页拉取初始数据
3. SSE 连接提供实时更新
4. 自定义 Hook 负责状态管理与数据合并
5. 组件根据条目类型渲染卡片

**关键模式**：
- **无限滚动**：`usePagination` Hook 配合 Intersection Observer
- **实时更新**：`useSSE` Hook 搭配自动重连
- **数据去重**：`merge.ts` 工具函数防止条目重复
- **设置持久化**：`useSettings` Hook 使用 localStorage
- **主题支持**：基于 CSS 变量，支持浅色/深色/跟随系统三种主题

## 测试

### 测试理念

claude-mem 依赖**真实使用与手动测试**，而非传统的单元测试。项目理念看重以下几点：

1. **手动验证**——在实际的 Claude Code 会话中测试功能
2. **集成测试**——端到端运行完整系统
3. **数据库检查**——通过 SQLite 查询验证数据正确性
4. **CLI 工具**——用交互式工具检查系统状态
5. **可观测性**——完善的日志与 worker 健康检查

之所以采用这套做法，是因为：
- Hook 行为高度依赖 Claude Code 的运行时环境
- SDK 交互需要真实的 API 请求与响应
- SQLite 与 Bun 运行时提供了稳定性保障
- 手动测试能发现单元测试漏掉的集成问题

### 手动测试流程

开发新功能时：

1. **构建并同步**：
   ```bash
   npm run build
   npm run sync-marketplace
   npm run worker:restart
   ```

2. **在真实会话中测试**：
   - 启动 Claude Code
   - 触发你正在测试的功能
   - 验证行为符合预期

3. **检查数据库状态**：
   ```bash
   sqlite3 ~/.claude-mem/claude-mem.db "SELECT * FROM your_table;"
   ```

4. **监控 worker 日志**：
   ```bash
   npm run worker:logs
   ```

5. **验证队列健康**（针对恢复功能）：
   ```bash
   bun scripts/check-pending-queue.ts
   ```

## 代码风格

### TypeScript 规范

- 使用 TypeScript 严格模式
- 为所有数据结构定义 interface
- 异步代码使用 async/await
- 显式处理错误
- 为公开 API 添加 JSDoc 注释

### 格式化

- 遵循现有代码的格式风格
- 使用 2 空格缩进
- 字符串一律使用单引号
- 对象/数组末尾加尾随逗号

### 示例

```typescript
/**
 * Create a new observation in the database
 */
export async function createObservation(
  obs: Observation
): Promise<number> {
  try {
    const result = await db.insert('observations', {
      session_id: obs.session_id,
      tool_name: obs.tool_name,
      // ...
    });
    return result.id;
  } catch (error) {
    logger.error('Failed to create observation', error);
    throw error;
  }
}
```

## 发布

生产发布只从 `main` 分支进行。`core-dev` 与 `community-edge` 是源代码运行分支；参见 [发布分支](branches)。

### 版本号更新

更新所有携带包版本号的 manifest：

- `package.json`
- `plugin/package.json`
- `.claude-plugin/marketplace.json`
- `.claude-plugin/plugin.json`
- `plugin/.claude-plugin/plugin.json`
- `.codex-plugin/plugin.json`
- `plugin/.codex-plugin/plugin.json`
- `openclaw/openclaw.plugin.json`

验证旧版本号已彻底消失、新版本号出现在所有预期位置：

```bash
git grep -n '"version": "NEW_VERSION"'
git grep -n '"version": "OLD_VERSION"'
```

### 构建、打标签与发布

```bash
npm run build-and-sync
git add -A
git commit -m "chore: bump version to NEW_VERSION"
git tag -a vNEW_VERSION -m "Version NEW_VERSION"
git push origin main
git push origin vNEW_VERSION
```

发布到 npm 需要维护者的 npm 凭据与双重验证（2FA）：

```bash
npm publish
npm view claude-mem@NEW_VERSION version
```

只有在 npm 能解析到该版本之后，才创建 GitHub release 并重新生成 changelog：

```bash
gh release create vNEW_VERSION --title "vNEW_VERSION" --notes "..."
npm run changelog:generate
git add CHANGELOG.md
git commit -m "docs: regenerate changelog for vNEW_VERSION"
git push origin main
```

不要手工编辑 `CHANGELOG.md`；它由 GitHub release 自动生成。

2. 检查 worker 状态：
   ```bash
   npm run worker:status
   ```

3. 查看日志：
   ```bash
   npm run worker:logs
   ```

### worker 无法启动

1. 结束现有进程：
   ```bash
   npm run worker:stop
   ```

2. 检查端口：
   ```bash
   WORKER_PORT=$(jq -r .CLAUDE_MEM_WORKER_PORT ~/.claude-mem/settings.json)
   lsof -i :$WORKER_PORT
   ```

3. 尝试自定义端口：
   ```bash
   export CLAUDE_MEM_WORKER_PORT=38000
   npm run worker:start
   ```
