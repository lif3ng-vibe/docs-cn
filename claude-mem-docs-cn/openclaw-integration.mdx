## 概述

OpenClaw 插件让 claude-mem 把持久记忆（persistent memory）带给运行在 [OpenClaw](https://openclaw.ai) 网关上的 agent。它负责三件事：

1. **观察记录（observation）**——捕获 OpenClaw 内置 runner 的工具使用情况，并发送给 claude-mem worker 服务做 AI 处理
2. **系统提示词上下文注入（context injection）**——通过 `before_prompt_build` hook 把观察记录时间线（timeline）注入每个 agent 的系统提示词，让 `MEMORY.md` 留给 agent 自行整理记忆
3. **观察记录推送（feed）**——通过 SSE 把新观察记录实时流式转发到消息通道（Telegram、Discord、Slack 等）

<Info>
OpenClaw 的内置 runner（`pi-embedded`）直接调用 Anthropic API，不会派生 `claude` 进程，因此 claude-mem 的标准 hook 永远不会触发。本插件利用 OpenClaw 的事件系统捕获同样的数据，补上这个缺口。
</Info>

## 工作原理

```plaintext
OpenClaw Gateway
  │
  ├── before_agent_start ───→ 初始化会话
  ├── before_prompt_build ──→ 向系统提示词注入上下文
  ├── after_tool_call ──────→ 记录观察
  ├── agent_end ────────────→ 摘要＋完成会话
  └── gateway_start ────────→ 重置会话跟踪与上下文缓存
                    │
                    ▼
         Claude-Mem Worker (localhost:37777)
           ├── POST /api/sessions/init
           ├── POST /api/sessions/observations
           ├── POST /api/sessions/summarize
           ├── POST /api/sessions/complete
           ├── GET  /api/context/inject ──→ 系统提示词上下文
           └── GET  /stream ─────────────→ SSE → 消息通道
```

### 事件生命周期

<Steps>
  <Step title="Agent 启动（before_agent_start）">
    OpenClaw agent 启动时，插件把用户提示词发送到 `POST /api/sessions/init` 来初始化会话，让 worker 创建新会话并开始处理。
  </Step>
  <Step title="注入上下文（before_prompt_build）">
    每次 LLM 调用前，插件都会从 worker 的 `/api/context/inject` 端点获取观察记录时间线，并以 `appendSystemContext` 返回。这样就把跨会话上下文直接注入了 agent 的系统提示词，全程不写任何文件。

    上下文会缓存 60 秒，避免同一会话内每次 LLM 调用都重新获取。
  </Step>
  <Step title="记录工具调用（after_tool_call）">
    agent 每次使用工具（Read、Write、Bash 等），插件都会把观察记录连同工具名、输入和截断后的响应（最多 1000 字符）发送到 `POST /api/sessions/observations`。如果调用失败，响应会以报错文本开头。这一切都是即发即忘——不会阻塞 agent 继续工作。

    以 `memory_` 开头的工具会被跳过，以避免递归记录。
  </Step>
  <Step title="Agent 结束（agent_end）">
    agent 结束时，插件提取最后一条助手消息发送到 `POST /api/sessions/summarize`，然后调用 `POST /api/sessions/complete` 关闭会话。两个调用都是即发即忘。
  </Step>
  <Step title="网关重启（gateway_start）">
    清空所有会话跟踪状态（会话 ID、上下文缓存），让 agent 在网关重启后拿到全新的状态。
  </Step>
</Steps>

### 系统提示词上下文注入

插件通过 OpenClaw 的 `before_prompt_build` hook，把跨会话的观察上下文注入每个 agent 的系统提示词。内容来自 worker 的 `GET /api/context/inject?projects=<project>` 端点，它从 SQLite 数据库生成格式化的 markdown 时间线。

这种做法让 `MEMORY.md` 仍由 agent 自己掌控，用来存放精心整理的长期记忆（决策、偏好、持久事实）；而观察记录时间线则走系统提示词，各归其位。

<Info>
上下文按项目缓存 60 秒，避免每次 LLM 调用都重新获取。缓存会在网关重启时清空。可用 `syncMemoryFileExclude` 让特定 agent 完全退出上下文注入。
</Info>

### 观察记录推送（SSE → 消息通道）

插件会启动一个后台服务，连接到 worker 的 SSE 流（`GET /stream`），并把 `new_observation` 事件转发到配置好的消息通道。你可以在 Telegram、Discord、Slack 或任何 OpenClaw 支持的通道上，实时查看 agent 学到了什么。

SSE 连接使用指数退避（1 秒 → 30 秒）自动重连。

## 配置观察记录推送

每当 claude-mem 生成一条新观察记录，观察记录推送就会向你的 OpenClaw 通道发送一条格式化消息。消息里包含观察记录的标题和副标题，方便你跟着 agent 的工作节奏了解进展。

通道里的消息长这样：

```
🧠 Claude-Mem Observation
**Implemented retry logic for API client**
Added exponential backoff with configurable max retries to handle transient failures
```

### 第 1 步：选择通道

观察记录推送可以使用 OpenClaw 网关已配置的任何通道。你需要准备两项信息：

- **通道类型**——已在 OpenClaw 注册的通道插件名称（如 `telegram`、`discord`、`slack`、`signal`、`whatsapp`、`line`）
- **目标 ID**——消息要发送到的聊天 ID、频道 ID 或用户 ID

### 第 2 步：把配置加入网关

在 OpenClaw 网关配置里，把 `observationFeed` 块加入 claude-mem 插件的 config：

```json
{
  "plugins": {
    "claude-mem": {
      "enabled": true,
      "config": {
        "project": "my-project",
        "observationFeed": {
          "enabled": true,
          "channel": "telegram",
          "to": "123456789"
        }
      }
    }
  }
}
```

<Warning>
`channel` 的取值必须与 OpenClaw 网关上已配置并运行的通道插件一致。如果通道未注册，日志中会出现 `Unknown channel type: <channel>`。
</Warning>

### 第 3 步：验证连接

网关启动后，检查推送是否已连接：

1. **查看日志**——你应该能看到：
   ```
   [claude-mem] Observation feed starting — channel: telegram, target: 123456789
   [claude-mem] Connecting to SSE stream at http://localhost:37777/stream
   [claude-mem] Connected to SSE stream
   ```

2. **使用状态命令**——在任意 OpenClaw 聊天中运行 `/claude_mem_feed`，会显示：
   ```
   Claude-Mem Observation Feed
   Enabled: yes
   Channel: telegram
   Target: 123456789
   Connection: connected
   ```

3. **触发一次测试**——让 agent 干点活。当 worker 把工具使用情况处理成观察记录后，你配置的通道就会收到消息。

<Info>
推送只发送 `new_observation` 事件，不含原始工具使用记录。观察记录由 worker 内的 AI agent 异步生成，因此从工具调用到消息出现在通道中会有 1–2 秒延迟。
</Info>

### 推送故障排查

| 现象 | 原因 | 解决方法 |
|---------|-------|-----|
| `Connection: disconnected` | worker 未运行或端口不对 | 检查 `workerPort` 配置，运行 `npm run worker:status` |
| `Connection: reconnecting` | worker 原本在运行，但连接断开了 | 插件会以退避方式自动重连——最长等 30 秒 |
| 日志中出现 `Unknown channel type` | 网关上没有加载该通道插件 | 确认 OpenClaw 网关已配置该通道插件 |
| 收不到任何消息 | 推送已连接，但没有生成观察记录 | 确认 agent 正在运行、worker 正在处理观察记录 |
| 日志中出现 `Observation feed disabled` | `enabled` 为 `false` 或缺失 | 把 `observationFeed.enabled` 设为 `true` |
| 日志中出现 `Observation feed misconfigured` | 缺少 `channel` 或 `to` | `channel` 和 `to` 都是必填项 |

## 安装

运行下面这条单行命令，即可全自动安装一切：

```bash
curl -fsSL https://install.cmem.ai/openclaw.sh | bash
```

安装脚本会完成依赖检查（Bun、uv）、插件安装、记忆槽位配置、AI 提供商（provider）设置、worker 启动，以及可选的观察记录推送配置。

也可以预选选项：

```bash
# 指定 AI 提供商
curl -fsSL https://install.cmem.ai/openclaw.sh | bash -s -- --provider=gemini --api-key=YOUR_KEY

# 全程免交互（默认使用 Claude Max Plan）
curl -fsSL https://install.cmem.ai/openclaw.sh | bash -s -- --non-interactive

# 升级已有安装
curl -fsSL https://install.cmem.ai/openclaw.sh | bash -s -- --upgrade
```

### 手动配置

在 OpenClaw 网关的插件配置中加入 `claude-mem`：

```json
{
  "plugins": {
    "claude-mem": {
      "enabled": true,
      "config": {
        "project": "my-project",
        "syncMemoryFile": true,
        "workerPort": 37777,
        "observationFeed": {
          "enabled": true,
          "channel": "telegram",
          "to": "your-chat-id"
        }
      }
    }
  }
}
```

<Note>
claude-mem worker 服务必须与 OpenClaw 网关运行在同一台机器上。插件通过 HTTP 访问 `localhost:37777` 与它通信。
</Note>

## 配置

<ParamField body="project" type="string" default="openclaw">
  在记忆数据库中划分观察记录归属用的项目名。该网关产生的所有观察记录都会存到这个项目名之下。
</ParamField>

<ParamField body="syncMemoryFile" type="boolean" default={true}>
  通过 `before_prompt_build` hook 向 agent 系统提示词注入观察上下文。设为 `true` 时，agent 自动获得跨会话上下文；设为 `false` 则完全关闭上下文注入（观察记录仍会继续记录）。
</ParamField>

<ParamField body="syncMemoryFileExclude" type="string[]" default={[]}>
  排除在自动上下文注入之外的 agent ID。适合那些自行整理记忆、不需要观察记录时间线的 agent（例如 `["snarf", "debugger"]`）。被排除的 agent 的观察记录仍会照常记录——只是跳过上下文注入。
</ParamField>

<ParamField body="workerPort" type="number" default={37777}>
  claude-mem worker 服务的端口。worker 未使用默认端口时需要覆盖此项。
</ParamField>

<ParamField body="observationFeed.enabled" type="boolean" default={false}>
  开启观察记录向消息通道的实时推送。
</ParamField>

<ParamField body="observationFeed.channel" type="string">
  通道类型：`telegram`、`discord`、`signal`、`slack`、`whatsapp`、`line`
</ParamField>

<ParamField body="observationFeed.to" type="string">
  观察记录推送的目标聊天/用户/频道 ID。
</ParamField>

## 命令

### /claude_mem_feed

查看或切换观察记录推送的状态。

```
/claude_mem_feed        # 查看当前状态
/claude_mem_feed on     # 请求开启
/claude_mem_feed off    # 请求关闭
```

### /claude_mem_status

检查 worker 健康状态与会话状态。

```
/claude_mem_status
```

返回 worker 状态、端口、活跃会话数，以及观察记录推送的连接状态。

## 架构

插件通过 HTTP 调用已在运行的 claude-mem worker 服务，而不是派生子进程。这意味着：

- 网关上无需安装 `bun` 依赖
- 每个事件没有进程派生开销
- 使用与 Claude Code hook 相同的 worker API
- 所有操作均不阻塞（能即发即忘就即发即忘）

### 会话跟踪

每个 OpenClaw agent 会话都会拿到一个唯一的 `contentSessionId`（格式：`openclaw-<sessionKey>-<timestamp>`），映射到 worker 中的一个 claude-mem 会话。插件维护以下状态：

- `sessionIds`——把 OpenClaw 会话键映射到内容会话 ID
- `contextCache`——上下文注入响应的 TTL 缓存（60 秒），按项目为键

两者都会在 `gateway_start` 时清空。

## 系统要求

- claude-mem worker 服务运行在 `localhost:37777`（或已配置的端口）
- 支持插件的 OpenClaw 网关
- 网关与 worker 之间网络可达（仅限 localhost）
