# 开始使用 Claude-Mem

## 自动运作

Claude-Mem 安装完成后即可自动运行，无需任何手动干预！

### 完整循环

1. **启动 Claude Code**——最近 10 个会话的上下文自动出现
2. **正常工作**——每次工具执行都会被捕获
3. **Claude 回答完毕**——Stop hook 自动生成并保存一份摘要
4. **下一个会话**——之前的工作会出现在上下文里

### 哪些内容会被捕获

Claude 每次调用工具，claude-mem 都会把它记录下来：

- **Read**——读取文件与访问内容
- **Write**——新建文件
- **Edit**——修改文件
- **Bash**——执行命令
- **Glob**——按模式查找文件
- **Grep**——搜索内容
- 以及 Claude Code 的所有其他工具

### 哪些内容会被加工

worker 服务对工具产生的观察记录（observation）做加工，提取出：

- **标题**——对发生了什么的简述
- **副标题**——补充上下文
- **叙事**——详细说明
- **事实**——以要点形式列出的关键收获
- **概念**——相关的标签与分类
- **类型**——归类（决策、bug 修复、新功能等）
- **文件**——读取或修改了哪些文件

### 会话摘要

Claude 回答完毕时（触发 Stop hook），会自动生成一份摘要，包含：

- **请求**——你提了什么
- **调查**——Claude 探索了什么
- **收获**——关键发现与洞见
- **完成**——完成了哪些事
- **后续步骤**——接下来做什么
- **备注**——其他值得保留的内容

### 上下文注入

启动新的 Claude Code 会话时，SessionStart hook 会：

1. 在数据库中查询你项目的最近观察记录（默认 50 条）
2. 取回最近的会话摘要作为背景
3. 以时间线形式展示观察记录，并附带会话标记
4. 仅当摘要在最后一条观察记录之后生成时，才展示完整的摘要详情（调查、收获、完成、后续步骤、备注）
5. 把整理好的上下文注入 Claude 的初始上下文中

**摘要展示逻辑**：

最新的摘要只有在其生成时间晚于最近一条观察记录时，完整详情才会显示在上下文的末尾。这样，当摘要代表项目的最新状态时你就能看到它的详情；而在上一个摘要之后又捕获了新的观察记录时，旧摘要详情则不会出现。

举个例子：

- ✅ **显示摘要**：最后一条观察记录在下午 2:00，摘要生成于下午 2:05 → 显示摘要详情
- ❌ **隐藏摘要**：摘要生成于下午 2:00，新观察记录在下午 2:05 → 隐藏摘要详情（已过期）

这可以避免在新工作已被捕获但尚未总结成摘要时，把过期的摘要展示出来。

这意味着 Claude 能"记住"先前会话中发生过什么！

## 手动命令（可选）

### worker 管理

worker 会在第一个 SessionStart hook 触发时自动启动，所以通常用不到这些命令。它们在做诊断时很方便。

```bash
# 启动 worker 服务（可选——本来就会自动启动）
npm run worker:start

# 停止 worker 服务
npm run worker:stop

# 重启 worker 服务
npm run worker:restart

# 查看 worker 日志
npm run worker:logs

# 检查 worker 状态
npm run worker:status
```

### 测试

```bash
# 运行全部测试
npm test

# 测试上下文注入
npm run test:context

# 带详细输出的上下文测试
npm run test:context:verbose
```

### 开发

```bash
# 构建 hooks 与 worker
npm run build

# 只构建 hooks
npm run build:hooks

# 发布到 npm（仅限维护者）
npm run publish:npm
```

## 查看已存储的上下文

上下文以 SQLite 数据库的形式存放在 `~/.claude-mem/claude-mem.db`。

可以直接查询数据库：

```bash
# 打开数据库
sqlite3 ~/.claude-mem/claude-mem.db

# 查看最近的会话
SELECT session_id, project, created_at, status
FROM sdk_sessions
ORDER BY created_at DESC
LIMIT 10;

# 查看会话摘要
SELECT session_id, request, completed, learned
FROM session_summaries
ORDER BY created_at DESC
LIMIT 5;

# 查看某个会话的观察记录
SELECT tool_name, created_at
FROM observations
WHERE session_id = 'YOUR_SESSION_ID';
```

## 理解渐进式披露

上下文注入采用渐进式披露（progressive disclosure）来高效使用 token：

### 第 1 层：索引展示（会话启动时）

- 显示观察记录标题及其 token 成本估算
- 以时间线顺序展示会话标记
- 按文件对观察记录分组，便于浏览
- 显示完整摘要详情——**仅当**摘要在最后一条观察记录之后生成时
- token 成本：索引视图约 50-200 token

### 第 2 层：按需详情（MCP 工具）

- 自然地问："我们修过哪些 bug？"或"X 是怎么实现的？"
- Claude 自动调用 MCP 搜索工具获取完整详情
- 按概念、文件、类型或关键词搜索
- 展示特定观察记录周边的时间线上下文
- token 成本：每条观察记录约 100-500 token
- 采用 3 层工作流：search → timeline → get_observations

### 第 3 层：完美回忆（直接读代码）

- 需要时直接阅读源文件
- 访问原始对话记录与原始数据
- 完整上下文按需可取

这样既保证 token 用得高效，需要时又能随时取用完整历史。

## 多轮提问会话与 `/clear` 的行为

Claude-Mem 支持跨越多次用户提问的会话：

- **prompt_counter**——记录会话中的提问总数
- **prompt_number**——标识会话内的某一次具体提问
- **会话连续性**——观察记录与摘要跨提问互相关联

### 关于 `/clear` 的重要说明

使用 `/clear` 时，会话并不会结束——它会以新的提问编号继续。这意味着：

- ✅ **上下文会重新注入**——来自最近的会话（SessionStart hook 以 `source: "clear"` 触发）
- ✅ **观察记录仍会被捕获**——并追加到当前会话
- ✅ **摘要照常生成**——Claude 回答完毕时（Stop hook 触发）

`/clear` 命令清空的是 Claude 可见的对话上下文，同时从最近的会话重新注入新鲜上下文；底层的会话仍在持续记录观察记录。

## 搜索你的历史

Claude-Mem 提供 MCP 工具用于查询项目历史。像平时说话一样直接问即可：

```
"我们上个会话修了哪些 bug？"
"认证功能是怎么实现的？"
"worker-service.ts 有过哪些改动？"
"给我看看这个项目最近的工作"
```

Claude 会自动识别你的意图并调用 MCP 搜索工具，后者采用 3 层工作流（search → timeline → get_observations）来高效使用 token。
