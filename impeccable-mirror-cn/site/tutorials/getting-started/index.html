安装与第一步

安装 Impeccable，然后构建或改进一个页面。

本页内容 5 个小节
  1. 1. 安装 Impeccable
  2. 2. 为 Impeccable 提供项目上下文
  3. 3. 选择第一个任务
  4. 4. 检查结果
  5. 接下来可以尝试

你需要一个编码工具、一个项目文件夹，以及 Node.js 18.19 或更高版本。空项目或刚脚手架生成的应用都可以。

我可以使用哪些编码工具？

Impeccable 支持 Claude Code、Codex、Cursor、GitHub Copilot、Gemini CLI、OpenCode、Pi 以及其他编码工具。安装器会让你选择所用工具，并安装对应的构建版本。

在用 GitHub Copilot 应用？Impeccable 已内置其中。在 Settings → Experimental 中启用它，然后直接跳到第 2 步。这条路无需终端安装器。

其他安装方式参见首页的安装选项。

1. 安装 Impeccable

在终端中打开你的项目文件夹，运行：

npx impeccable install

按提示选择你的编码工具，并选择为本项目还是所有项目安装。然后重新加载你的编码工具。

其他方式参见首页的安装选项。

用 Git submodule 保持团队共享版本

在项目文件夹中把 Impeccable 添加为 submodule，并链接你的团队所用的编码工具：

git submodule add https://github.com/pbakaus/impeccable vendor/impeccable
npx impeccable link --source=vendor/impeccable --providers=claude,cursor

把 claude,cursor 换成你团队使用的 provider。若要改用已有的本地 checkout，把 --source 指向那个文件夹即可。链接使用的是本地源码，无需全局安装 Impeccable。已有的技能目录会原样保留，除非你用 --force 显式替换。

提交 .gitmodules、submodule 引用和生成的链接。队友用以下命令拉取记录的版本：

git submodule update --init --recursive

要采用更新的版本：更新 submodule、刷新链接，然后审查并提交新的引用：

git submodule update --remote vendor/impeccable
npx impeccable link --source=vendor/impeccable --providers=claude,cursor

安装或更新后请重新加载你的编码工具。链接安装的是技能，不含设计钩子（hook）；自动检查的设置与你工具的信任要求需另行参照完成。

其余的命令都输入到智能体聊天里。在任意命令框中选择你的编码工具，示例会使用其语法。

没有出现？或已启用自动检查？

如果重新加载后 Impeccable 没有出现，请重新运行安装器，并检查编码工具与安装范围的选择。

如果你启用了自动设计钩子，请允许它在你的编码工具中运行。它会检查 UI 修改，并把发现反馈给你的智能体。

2. 为 Impeccable 提供项目上下文

Impeccable 需要知道你的项目服务于谁、这些人需要完成什么。用以下命令保存这些上下文：

/impeccable init

Impeccable 会先读取项目，再请你补全空缺。描述将要使用它的人群，以及他们的需求应当塑造哪些决策。例如：

我们的客户每周都要复购同样的耗材。他们需要快速找到常用商品并完成结账，而且常常是在手机上。

工作中必须保留的内容也一并写上，例如既定的产品名或无障碍要求。颜色和字体可以留给设计环节处理。

Impeccable 把双方确认的上下文保存在 PRODUCT.md 中。继续之前先读一遍，纠正它理解有误的地方；后续命令会以这个文件指导工作。

选择新设计的启动方式

先出视觉稿（mockup first，comp-led）能把视觉方向推得更远，但把图像转译成代码会损失细节；预计要经过几轮提示与审查。直接构建（code-led）首次实现通常更连贯，视觉上则相对保守。两条路径都包含设计方向与审查环节。

为「先出视觉稿」路径配置图像

使用内置的图像生成或 OpenAI API key。视觉稿会增加生成时间与用量；没有图像能力时，Impeccable 会直接以代码构建。

启用图像生成 →

init 可能会询问把哪条路径存为默认值，之后可以在设计选择器里切换。比较工作流与默认值。

已有设计系统？构建之前先记录下来 
/impeccable document

Impeccable 会读取界面，并把颜色、字体排印与组件规则记录到 DESIGN.md。请检查这个文件，让后续工作遵循你想保留的决策。没有样式的脚手架可以跳过这一步。

工作流详见使用设计系统工作。

3. 选择第一个任务

日常语言就够用了。选择适合你项目的路径：

  • 从零构建创建一个页面，或重新设计一个界面。
  • 改进现有设计在保留可取之处的前提下精修页面。

从零构建

描述一个页面、它的受众，以及访客需要能完成的事：

/impeccable design a signup page for our monthly book club. Help visitors understand the next event and reserve a seat.

Impeccable 会帮你补全缺失的细节，发展出一个你可以选择与定向的设计方向，然后构建并审查界面。在先出视觉稿的工作流中，实现之前由你确认构图。成熟产品中的新页面会遵循该产品的视觉系统。

从零构建一文涵盖方向选择器、视觉稿、重新设计，以及哪些内容会带入后续会话。想让流程停在实现之前的方案阶段，可使用 shape。

改进现有设计

描述哪里感觉不对，或指定一个页面做一次专注的打磨（polish）：

/impeccable polish the pricing page

polish 会在现有设计之内精修间距、字体排印、标签与交互状态。可以在请求里附上约束，例如：“保留我们的配色和当前的套餐名称。”

不确定要修什么？让智能体执行 /impeccable critique the pricing page，读完各项发现，再决定处理哪些。示例见改进现有设计。

4. 检查结果

打开页面，试一下主要任务。你能预订一个座位吗？能比较套餐并选定其一吗？再用窄屏检查一遍，并审查代码改动。

告诉你的智能体哪些要保留、哪些要调整。例如：

现在套餐对比更易读了，保留这一点，但把上方的按月/按年切换恢复出来。

如果整体设计仍然不对劲，描述你想改变什么，或要求重新设计。打磨（polish）适用于精修你已有的设计。

接下来可以尝试

  • 让以后的页面保持一致：使用设计系统工作，记录共享决策并复用现有组件。
  • 比较视觉备选：在聊天里说出元素与方向即可生成变体，或在 Live Mode 中直接选取。在页面上比较后，把其中一个采纳进你的代码。
  • 上线前先检查：/impeccable audit the pricing page 会审查无障碍、性能、响应式行为及其他实现问题。

要更新通过 npx impeccable install 完成的安装，在终端运行 npx impeccable update。市场安装则通过你的编码工具的插件菜单更新。
