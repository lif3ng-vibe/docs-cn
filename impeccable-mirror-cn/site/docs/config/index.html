配置与忽略

设置共享默认值，让检查保持实用。

用配置保存构建工作流、记录有意的检测器豁免，并调整检查的运行方式。可以请 Impeccable 更改工作流默认值；检测器豁免可通过 CLI 管理。

设置存放在 .impeccable/ 下。产品的用途放在 PRODUCT.md，视觉决策放在 DESIGN.md；见上下文文件。

选择构建工作流

把 buildPath 设为 comp 表示视觉稿优先（comp-led），设为 code 表示直接构建（code-led）：

{
  "buildPath": "comp"
}

把这项设置合并进你现有的 .impeccable/config.json，保留其中的其他设置。需要按开发者覆盖团队默认值时，用 .impeccable/config.local.json。

也可以用自然语言请 Impeccable 更改默认值。选择器里的切换只影响当前会话。没有已保存的偏好时，图像生成可用则默认视觉稿优先；不可用时，无论已保存的偏好如何，Impeccable 都按代码优先构建。

比较两种工作流，或启用图像生成。API 密钥应放在智能体的环境里，绝不要放进这些配置文件。

记录特定豁免

假设 Inter 是你们已确认的品牌字体。只忽略这个值，同时让字体规则对其他一切保持生效：

npx impeccable ignores add-value overused-font Inter --reason "Brand font"

列出当前豁免，或之后移除这一条：

npx impeccable ignores list
npx impeccable ignores remove-value overused-font Inter

手动扫描与钩子使用同一套忽略。真问题就去修；如果报告的选择是有意的，才用豁免。

限制范围

对于单个文件里的一条规则，使用限定文件的值忽略：

npx impeccable ignores add-value design-system-color "*" --file "src/demo.css" --reason "Palette comparison demo"

这里 "*" 表示允许该文件中的任意颜色。其他检查照常运行，其他位置的颜色仍会被检查。通配符值必须限定文件范围。

排除整个文件或整条规则

当整个文件都不在设计评审范围内（例如刻意保留的坏设计测试夹具）时，用文件排除：

npx impeccable ignores add-file "tests/fixtures/bad-design/**"

这会抑制匹配文件上的所有规则，包括未来的规则。要跨整个项目抑制一条规则：

npx impeccable ignores add-rule side-tab

对 overused-font 而言，整条规则抑制还需要 --all-values。如果只需要针对某个字体的豁免，优先采用具体的值。

用 remove-file 或 remove-rule 加相同参数即可撤销这些选择。ignores clear 会移除所选配置中的全部忽略项。

决策共享还是留在本地

  • 默认共享：命令写入 .impeccable/config.json。团队层面的决策（例如品牌豁免）提交这个文件。
  • 用 --local 时私有：命令写入 .impeccable/config.local.json。Impeccable 会把该文件排除在 git 之外。
npx impeccable ignores add-file "src/private-experiment/**" --local

移除豁免时使用相同的作用域。在 remove 或 clear 命令上加 --all，可同时作用于共享与本地配置。

行内忽略注释

如果豁免需要随文件走出仓库，就写进注释里：

<!-- impeccable-disable overused-font: exported brand document -->

有三种形式可用：

标记 作用范围
impeccable-disable 整个文件
impeccable-disable-line 当前行
impeccable-disable-next-line 下一行

静态 HTML 的发现没有行号，对它们要使用整文件形式。行级范围适用于带行号的发现，例如 CSS 和 JSX 的源码检查。

注释语法与绕过行内忽略

把标记写进该文件惯用的注释语法中：HTML、CSS、JavaScript、JSX 或其他受支持的源码格式。标记后面跟一个规则 ID 或逗号分隔的多个 ID。省略 ID 或使用 *，会抑制该范围内的所有规则。

: 或 -- 之后的理由供评审代码的人参考；扫描器会丢弃这段理由。

/* impeccable-disable-next-line overused-font: brand font */
.brand { font-family: Inter; }

detect --no-inline-ignores 会绕过这些注释，但保留配置中的忽略。detect --no-config 则两者都绕过，同时也不加载项目设置与本地设计系统上下文。

服务端模板

当你的 UI 使用 Blade、ERB、Twig 或其他模板格式时，添加扩展名：

{
  "detector": {
    "extensions": [
      { "ext": ".blade.php", "engine": "html" },
      { "ext": ".html.erb", "engine": "html" }
    ]
  }
}

把这段合并进 .impeccable/config.json。扩展名匹配文件名结尾，包括双扩展名。html 是默认分析器；JS、TS 或 CSS 类源码用 text。自定义条目会追加到检测器和钩子使用的内置类型之上。

项目边界

Impeccable 能从 package.json workspaces、pnpm-workspace.yaml 或 lerna.json 发现嵌套项目。如果你的设计边界与此不同，用 projectRoots 声明：

{
  "projectRoots": ["docs/design/skins/*"]
}

每个匹配的文件夹都可以有自己的 PRODUCT.md 与 DESIGN.md，并出现在应用选择器里。缺失的上下文按文件逐个回退到仓库根目录。

模式优先级与私有根

模式相对于仓库根目录，支持 *、** 与 ! 排除。本地 projectRoots 条目是对共享列表的扩充。

对于被配置模式（包括排除模式）匹配到的路径，projectRoots 优先于 package workspaces。其余路径由 package 声明决定。例如，!apps/internal 可以排除包管理器纳入的应用；但包层面的排除无法移除 Impeccable 配置中明确包含的根。

检查你的配置

如果某项设置似乎没有生效，运行doctor：

/impeccable doctor

它会检查未知键、过时的规则 ID，以及匹配不到任何内容的 project-root 模式。不查的话，这类错误会让你想要的设置落空。

配置结构与钩子设置

一个最小示例：

{
  "detector": {
    "designSystem": { "enabled": true }
  },
  "hook": {
    "enabled": true,
    "quiet": false
  }
}

detector 存放手动扫描与钩子共享的设置，包括 ignoreRules、ignoreFiles 与 ignoreValues。忽略命令会替你维护这些字段。

hook 控制自动检查。安静模式会抑制「已通过」与「待处理」的确认信息，同时保留新发现。激活方式、逐次编辑检查、日志与环境变量覆盖见设计钩子。

顶层设置 "stalenessCheck": false 用于关闭会话开始时关于上下文过时的提示。

关闭设计系统检查

如果记录的系统已过时，用 document 更新它。如果它有意不作为权威，把 detector.designSystem.enabled 设为 false。

不改配置、仅为某次扫描跳过这些检查：

npx impeccable detect --no-design-system src/

这会保留其他项目设置与忽略。想要一次不带这些设置与本地设计系统上下文的扫描，用 --no-config。
