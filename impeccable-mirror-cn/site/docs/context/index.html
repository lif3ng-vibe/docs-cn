上下文文件

把智能体需要了解的项目信息保存下来。

本页内容 6 个小节

  2. 记录已有的视觉系统
  3. 什么内容放在哪里
  4. 指明你正在处理的页面
  5. 让文件保持有用

缺失或含糊的上下文会让设计更加泛泛。Impeccable 能读取你的代码，但它还需要理解你的用户、他们的目标，以及你想保留的那些决策。把这些知识随项目保存下来，让它指导后续工作。

关于保持页面一致的实操走查，见在设计系统内工作。本页介绍各类上下文记录及其解析方式。

从你的产品开始

在你的智能体对话里运行：

/impeccable init

Impeccable 会读取项目，就缺失的上下文提问，并把敲定的细节保存到 PRODUCT.md。请检查它写下的内容。你可以自己编辑该文件，也可以让 Impeccable 修正。

重点写清楚产品为谁服务、他们要完成什么，以及设计必须满足的种种要求。有用的回答会把用户的处境与一个决策联系起来：

人们离开工位时会在手机上查看服务故障。他们需要看到哪些功能受了影响、是否已有人在处理。

设置阶段不需要指定调色板或挑选字体。

记录已有的视觉系统

如果你的项目已有想保留的视觉风格，运行：

/impeccable document

Impeccable 会把现有的颜色、字体排印、布局规则和组件记录到 DESIGN.md。在用它指导更多工作之前先通读一遍。凡是记下偶然现象或过时决策的地方，都要修正。

想要这份记录时单独运行 document；init 只保存产品上下文，不会创建 DESIGN.md。新项目可以通过构建新东西确立视觉方向。

什么内容放在哪里

文件 应放内容 示例
PRODUCT.md 受众、目标、平台、约束、术语，以及已确认的品牌承诺。 “客户在手机上复购耗材。”
DESIGN.md 共享的视觉系统：颜色、字体排印、组件与设计规则。 “主要操作沿用现有的主按钮。”
.impeccable/surfaces/*.md 针对单个页面或路由的决策，例如它的用途与选定的设计方向。 “定价页应帮助购买者比较各档方案。”
.impeccable/design.json 供工具使用的生成式设计元数据。用 document 刷新；不要手工编辑。 组件预览与额外的令牌信息。

这些 Markdown 文件由你审查与编辑。记录已有系统时，document 会把设计令牌存入 DESIGN.md 的 frontmatter，并在其旁生成额外的元数据。

指明你正在处理的页面

/impeccable polish the marketing homepage
/impeccable audit the billing settings

首页帮助人们判断产品是否符合自己的需求；账单设置帮助他们完成一项任务。指明页面能让 Impeccable 采用合适的处理方式，而不是把产品的每个部分一概而论。

Impeccable 如何选择页面的处理方式

Impeccable 依据访客到该页面想做什么，采用四种模式：

  • 说服（Persuade）：做出决策并行动。落地页、营销活动页与定价页。
  • 操作（Operate）：完成一项任务。仪表盘、设置、编辑器及其他应用界面。
  • 阅读（Read）：理解某件事。文档、指南与帮助页。
  • 体验（Experience）：欣赏作品本身。作品集、画廊与展示页。

模式由页面决定。开发者工具的落地页可以用「说服」，它的文档则用「阅读」。如果页面用途不明确，就说明访客应在该页面做什么。

解析出的模式会与该页面的简报一并记录在 .impeccable/surfaces/ 下。

让文件保持有用

项目变化时更新上下文：

变化了什么 该做什么
你的受众、目标、平台或产品需求 编辑 PRODUCT.md，或运行 /impeccable init 重新确认相关细节。
你的视觉系统 运行 /impeccable document，从实现中更新记录。
某个页面的用途或设计方向 更新它在 .impeccable/surfaces/ 下的简报。
不确定哪些内容过时了 运行 /impeccable doctor。关于 Doctor。

如果结果显得泛泛或没对准用户需求，先检查上下文。补上缺失内容、修正过时之处，然后告诉智能体还有哪里需要改进。好的上下文能改善它的判断；反馈则帮助它精修结果。

在还没有任何代码时先建 DESIGN.md

可以让 document 为新项目确立视觉方向。它需要产品上下文和一个要设计的具体首个页面，然后与你一起选定方向。

得到的 DESIGN.md 会标记为种子（seed）。它记录选定的方向，把未定的实现细节留白。此时还不会生成设计元数据文件。等有了代码再运行一次 document，以捕捉实际的令牌与组件。

要为检测规则做有意豁免，请使用配置与忽略。

参考细节

原生应用：iOS、Android 与 adaptive（alpha）

PRODUCT.md 在 ## Platform 下记录平台。init 会从项目推断它，证据不明确时会发问。缺省值为 web。

取值适用对象设计指南
web网站与 Web 应用，包括移动端 Web。Web 界面指南。
ios原生 iPhone 与 iPad 应用。Apple Human Interface Guidelines。
android原生 Android 应用。Material Design 3。
adaptive共享一套代码库，界面随各操作系统自适应。同时采用 iOS 与 Android 指南。

原生支持处于 alpha 阶段。audit 与 adapt 会就屏幕阅读器、触控目标与平台惯例采用原生指南。Live Mode、浏览器检测器与设计钩子不会检查原生界面。

Flutter、React Native 或 Kotlin Multiplatform 可以支持 adaptive 界面，但仅凭框架本身并不能决定取值。移动端 Web 仍算 web，包括在原生壳里展示的网站。

上下文文件放在哪里（包括 monorepo）

把 PRODUCT.md 和 DESIGN.md 一起放在项目根目录。Impeccable 也支持 .agents/context/ 与 docs/：从根目录开始，按这一顺序采用第一个实际含有上下文的位置。

在 monorepo 中，每个应用可以有自己的上下文。应用自己的文件优先；缺失的文件回退到仓库根目录。产品与设计上下文各自独立解析。

例如，下面这家店铺共用产品的受众与目标，但拥有自己的视觉系统：

repo/
├── PRODUCT.md          Shared audience and goals
├── DESIGN.md           Shared visual system
└── apps/
    └── store/
        ├── DESIGN.md   Store’s visual system
        └── src/
在 apps/store/ 里工作Impeccable 读取
产品上下文repo/PRODUCT.md
设计上下文repo/apps/store/DESIGN.md

如果这家店铺还需要不同的产品上下文，就为它添加自己的 PRODUCT.md。

项目边界来自 package workspace 声明或 .impeccable/config.json 中的 projectRoots。对于所匹配的路径，配置的模式可以覆盖 package 边界。示例与优先级见项目边界。

生成的设计元数据放在 .impeccable/design.json。旧的 DESIGN.json 仍会被识别为回退；用 document 生成当前格式。

上下文与代码不一致时怎么办

每种记录回答的是不同的问题：

  • PRODUCT.md：产品为谁服务、承诺什么，以及哪些要求与品牌承诺必须成立。
  • DESIGN.md：共享的视觉选择、组件与交互规则。
  • 页面简报：该页面要达成什么，以及为它选定的方向。

实现本身也是证据。当既有惯例比文档更新时，Impeccable 应当保留它们。

例如，代码已用上你批准的新字体而 DESIGN.md 还写着旧字体，就更新记录；如果代码引入了一次意外的字体改动，就修代码。当证据不足以裁定时，说明哪个决策是当前有效的。

用 document 刷新已有视觉系统的记录，或用 doctor 检查过时或不兼容的上下文。

检测器会对照设计系统检查什么

当 DESIGN.md 可用时，检测器与设计钩子可以检查是否偏离了记录在案的设计值：

规则检查内容
design-system-font记录的类型系统之外的字体。
design-system-color调色板与配套文件色阶之外的硬编码颜色。
design-system-radius记录刻度之外的圆角半径。
design-system-font-size记录的字号刻度之外的硬编码字号。

这些检查需要对应的设计值。文件存在本身并不构成完整的系统。用 document 让 DESIGN.md 及其生成的配套文件保持最新。

DESIGN.md 缺失、配置将其停用或扫描使用 --no-design-system 时，设计系统检查会被跳过。其他检测器检查仍会运行。扫描选项见 Detector CLI，有意豁免见配置与忽略。

从旧的 brand/product 调性升级

模式取代了旧的 brand/product 调性：brand 对应说服（Persuade），product 对应操作（Operate）；阅读（Read）与体验（Experience）覆盖以学习或探索为目的的页面。

模式归属于页面的简报。PRODUCT.md 里旧的 ## Register 小节已不再使用。doctor 会标记它并提议移除，以免后来的读者误以为它仍是现行设置。
