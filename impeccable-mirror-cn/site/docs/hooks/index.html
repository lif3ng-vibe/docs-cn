自动设计检查

在智能体工作的同时拦住设计问题。

设计钩子会在你的智能体处理 UI 文件期间运行检测器。趁改动还在上下文之中，发现让智能体有机会及时纠正问题。

你的编码工具还需要放行钩子

在 Impeccable 里打开检查只是一步。请查阅你的工具对应的设置说明，钩子才能运行。

查看你工具的设置 →

打开检查

在你的 AI 编码工具中，查看当前状态：

/impeccable hooks status

为本项目启用或停用检查：

/impeccable hooks on
/impeccable hooks off

在你的编码工具中放行钩子

Claude Code

在交互式会话中，接受工作区信任。打开 /hooks 查看 Impeccable 的 PostToolUse 与 Stop 钩子。项目安装通常使用 .claude/settings.local.json；插件安装可自带钩子。

Claude Code 的钩子与信任指南

Codex

在应用中打开Settings → Hooks，或在 CLI 里使用 /hooks。审核并信任 Impeccable 的 PostToolUse 与 Stop 钩子定义。新增或修改过的定义需要重新审核。

Codex 的钩子与信任指南

Cursor

信任工作区，然后在Customize → Hooks 中查看项目的 .cursor/hooks.json。该文件变更时 Cursor 会重新加载。如果仍未出现，重启 Cursor 并查看 Hooks 输出通道。

Cursor 的钩子指南

GitHub Copilot

提交 .github/hooks/impeccable.json 并合入仓库默认分支。这是一个共享的项目钩子，供 Copilot CLI 与云端智能体使用。在 CLI 中，还要接受该文件夹的信任提示。

Copilot 的钩子安装指南

Grok Build

运行 /hooks-trust，审核并信任 .grok/hooks/ 中的项目钩子。用 /hooks 查看已加载的钩子。

Grok Build 的钩子指南

工作时会发生什么

  • Claude Code 与 Codex：每次编辑后给出聚焦反馈，智能体结束回合时再做一次更全面的检查。
  • Grok Build：编辑发生时即被跟踪；发现会在智能体结束回合时送达。
  • GitHub Copilot：受支持的编辑之后运行完整检测器。
  • Cursor：完整检测器检查受支持的拟议写入。发现可以拦下写入，让智能体先行修改。
为什么有些检查要等到回合结束

对 Claude Code 与 Codex 而言，逐次编辑检查聚焦当下的问题：图片损坏、溢出、可读性差、渐变文字、发光效果，以及偏离设计系统。更全面的检查在 Stop 事件上对本次会话触碰过的 UI 文件运行，即智能体结束回复之时。已报告过的发现会被过滤掉。

这让未完成的工作有展开的余地，不必每次编辑都重复所有观察。若之后没有新东西可报，再次 Stop 会保持安静。

把 hook.perEditRules 设为 "all"，即可在每次编辑后运行完整规则集。Cursor 和 Copilot 已经使用完整规则集，因为 Impeccable 不会把它们的发现推迟到 Stop 阶段。Grok 即使在编辑过程中扫描，也通过 Stop 交付反馈。

钩子检查 Web 代码。若项目的 PRODUCT.md 声明了 ios、android 或 adaptive，钩子会跳过该项目。原生界面评审请使用 audit。

确认检查在正常工作

安装或移动项目之后，运行 doctor：

/impeccable doctor

它能发现脚本路径已不存在的钩子，或已安装配置与启用状态不匹配的情况。没有任何消息可能意味着本次编辑干净、处于安静模式，或钩子未生效；仅凭沉默无法分辨是哪一种。

保留一项有意的选择

对已确认的豁免，记录具体的值以及它成立的理由：

/impeccable hooks ignore-value overused-font Inter --reason "Brand font"

该豁免与手动检测扫描共享。配置与忽略介绍了更细的文件作用域、私有豁免，以及更大范围的规则或文件排除。

安装与排错详情

受支持的文件与跳过安装

内置文件类型包括 .tsx、.jsx、.html、.vue、.svelte、.astro、.css、.scss、.sass、.less、.ts 与 .js。纯 JS 和 TS 会保持安静，除非发现了设计问题。

通过 detector.extensions 添加服务端模板类型。

若要为单次安装或更新跳过钩子安装：

npx impeccable install --no-hooks
npx impeccable update --no-hooks
安静模式、日志与环境变量覆盖

运行时选项位于 .impeccable/config.json 的 hook 键下。本地覆盖（包括安装许可）则位于被 gitignore 的 .impeccable/config.local.json。

hook.quiet: true 会抑制「已通过」与「待处理」的确认信息，同时保留新发现。它不会关闭检查。

调试时，把 hook.auditLog 设为 .impeccable/hook.ndjson 这样的路径。每次调用会写入一行 JSON。日常工作时请保持日志关闭。

IMPECCABLE_HOOK_DISABLED、IMPECCABLE_HOOK_QUIET 与 IMPECCABLE_HOOK_LOG 会为接收到这些环境变量的进程覆盖对应的配置项。status 命令会报告相关的覆盖。

钩子清单损坏会阻止安装

遇到损坏的清单，install 与 update 会停下来，而不是将其覆盖。请先检查该文件。若决定替换，请带 --force 重新运行；替换之前，Impeccable 会以 .bak 扩展名备份损坏的文件。
