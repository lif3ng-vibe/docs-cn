运行检测扫描

在终端里检查你的 UI。

本页内容 5 个小节
  1. 运行一次扫描
  2. 读懂一条发现
  3. 对照设计系统检查
  4. 保留有意的选择
  5. 更多扫描选项

无需开启 AI 对话，即可扫描已知的设计问题。检测器会检查代码与渲染后的页面，找出低对比度、文本溢出、常见 AI 设计模式，以及偏离设计系统之类的问题。

运行一次扫描

在你的项目文件夹里运行：

npx impeccable detect src/

传入单个文件做聚焦检查，或传入 URL 检查渲染后的页面：

npx impeccable detect src/components/Card.tsx
npx impeccable detect http://localhost:3000

源码扫描检查 UI 代码与样式。URL 扫描会在浏览器中打开页面，检查便能利用渲染后的布局。按你想检查的对象选择目标。

退出码与自动化

当脚本或 CI 任务需要结果时，使用 JSON：

npx impeccable detect --json src/
退出码 含义
0 扫描完成，无主要发现。仍可能出现提示类发现。
2 扫描完成，存在主要发现。
1 至少有一个目标未能扫描。

主要发现决定发现计数与退出码。提示类发现（advisory）是附加的观察项，不会导致扫描失败。退出码 1 应视为扫描失败，即使其他目标产生了发现。

保存输出或隐藏提示类发现

JSON 输出到标准输出；人类可读的发现输出到标准错误：

npx impeccable detect --json src/ > findings.json
npx impeccable detect src/ 2> findings.txt

--quiet 把文本输出精简为最终计数。--no-advisory 在这一次扫描中隐藏提示类发现。

对照设计系统检查

当本地存在 DESIGN.md 时，检测器会用它来检查已记录的字体、颜色、圆角半径与字号。.impeccable/design.json 伴生文件则提供结构化的令牌与字号阶梯数据。

用 document 让记录保持最新：

/impeccable document

若要单次扫描跳过设计系统检查：

npx impeccable detect --no-design-system src/

保留有意的选择

手动扫描与设计钩子使用同一套忽略。尽量记录具体的值：

npx impeccable ignores add-value overused-font Inter --reason "Brand font"

这样该规则对其他字体仍然生效。配置与忽略介绍了文件作用域、私有豁免，以及之后如何移除忽略项。

更多扫描选项

文件类型与服务端模板

会在文件夹中搜索受支持的 UI 与样式文件。HTML 扫描会包含其链接的本地 CSS。JSX、TSX、Vue、Svelte、Astro 及样式表文件会接受源码检查。

在 detector.extensions 下声明额外的模板扩展名，例如 Blade 或 ERB。参见服务端模板。

检测器检查的是 Web 界面。原生 iOS 或 Android 项目请使用 audit，获得适合该平台的评审。

视口、设计域与管道输入

URL 扫描默认使用 1280 × 800 视口。想检查移动端布局，可以选更小的尺寸：

npx impeccable detect --viewport 390x844 http://localhost:3000

把检查限制在某个设计域，或用逗号组合多个域：

npx impeccable detect --scope type src/
npx impeccable detect --scope type,layout src/

通过管道传入文本且未指定目标时，检测器会读取标准输入：

cat component.css | npx impeccable detect
项目设置与不受忽略影响的扫描

手动扫描会读取 .impeccable/config.json 与 .impeccable/config.local.json。把钩子关掉并不会停用手动扫描。

--no-inline-ignores 会绕过文件内的忽略注释，但保留配置中的忽略。--no-config 则两者都绕过，同时也不加载项目设置与本地设计系统上下文。

若豁免需要随文件走出仓库，请使用行内忽略注释。
