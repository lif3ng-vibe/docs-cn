构建新东西

做出新东西，方向由你塑造。

描述你想做的页面。Impeccable 帮你选定方向、完成构建并评审结果。不需要特殊命令或视觉概念。

想把视觉方向推得更远？

图像生成会打开更大胆的构图空间。把这份雄心带进代码预计要几轮打磨；首次构建会损失一些视觉稿的细节。

启用图像生成 → 
/impeccable design a pricing page for our enterprise customers
  1. 描述任务

    说明它为谁服务、要做什么、什么必须保留。

  2. 选定方向

    比较各选项，把控设计走向。小幅增补可以沿用你现有的风格。

  3. 构建并评审

    试用界面并精修。Impeccable 会记录这些决策，供后续工作使用。

只需要一份规划？从 shape 开始。

评审视觉稿，或直接写代码

你可以选择新设计以何种方式变成可用的界面。comp 是一幅视觉构成：页面的详细视觉稿。

comp 主导不是一次性工作流。图像模型提出的构图，编码模型未必能在首轮忠实复现。字体、间距、图像与比例都会在转换中走样。Impeccable 为构建提供一个视觉目标，并帮助检查还原度，但你要预期多轮提示、直到满意。这项工作请使用一个能力足够的编码模型。

选视觉稿先行，得到一个你愿意为之努力的更高视觉上限。选直接构建，在模型自然范围内得到更强的首次实现。没有图像生成时，Impeccable 会走代码主导路径。

在设计选择器中用工作流开关做一次仅限当前会话的选择：

默认值与保存你的工作流偏好

图像生成可用且没有已保存偏好时，Impeccable 默认视觉稿先行。没有图像生成时，它直接用代码构建，也不显示这个开关。

选择器里的开关只作用于当前会话。要更改项目默认值，用自然语言提出：

/impeccable use code-led as this project's default for new design work
/impeccable use comp-led as this project's default for new design work

该设置是 .impeccable/config.json 里的 buildPath：comp 或 code。.impeccable/config.local.json 中的值会为该开发者覆盖共享设置。文件格式见配置与忽略。

在没有已保存偏好的项目上，切换开关时可能会触发一次性询问，确认是否保留新选择。init 也能在初始化时确立这一偏好。

这两条路径适用于新设计工作和重设计。专注的 polish 打磨会保持当前设计。两条路径都可以把生成图像当作成品素材；代码主导会跳过视觉稿采纳环节。

设定可改动多少

告诉 Impeccable 它可以改什么。新板块应融入所在页面；新页面应融入产品。做重设计时，指明要保留什么。

在我们当前系统内重设计这个页面。保留产品名称和注册流程。

从零开始、扩展系统，或在文档不全时工作
  • 添加板块或组件：它会继承周围的设计。
  • 在现有产品中创建页面：视觉系统保持一致；布局可以为任务而变。
  • 从零开始或重设计：视觉方向完全开放。产品事实、功能与约束仍然适用。

Impeccable 在读取 DESIGN.md 之余，还会读取实际界面、令牌、组件和素材。文档缺失不会抹掉已确立的设计。它可以在扩展之前把该系统记录下来。

如果边界不清晰，Impeccable 应当询问。「换掉现在的外观」与「在我们当前系统内重设计」给出的权限并不相同。

选定你想推进的方向

在选择器中比较各选项，然后选定其一，或告诉 Impeccable 要改什么。下面，同一个发布目录呈现出三种不同形态：

  • 选定其一：在想要的方向上选择 Build this（构建此方向）。
  • 再要一组：重新生成，或用 Safer hand（保守档）与 Bolder hand（大胆档）改变范围。
  • 把控下一轮：用文本框说明要改什么、留什么。
  • 保持熟悉：类别标准选项提供一种常规做法。

你也可以把整组都否掉。连续出现两次新组之后，Impeccable 会追问缺少了什么质感，让下一次尝试有更明确的依据。如果浏览器决策页无法运行，选择会转入对话中进行。

已有视觉想法？写进提示带来

你的参考与约束会引导设计：

/impeccable design a landing page for our vinyl shop with a 1970s hi-fi catalog look. Use Futura and lead with the records.

Impeccable 会发展你的简报中留而未决的选择。选定的美学只是完整设计的起点，还包括导航、控件与交互。

看一幅视觉稿如何落成可用的页面

对比字形、插画与各板块比例：整体方向得以延续，但转换会改变细节。弥合差距需要评审与迭代。实现还需要可读的文本、可用的控件、无障碍行为和响应式布局。

构建之后

试用主任务，检查窄屏表现，并告诉 Impeccable 保留什么、调整什么。选定的方向指导评审；完成的界面仍要为真实用户好好工作。

什么会带进下一个会话
  • 视觉系统：当工作确立或替换了一个设计时，DESIGN.md 会在实现与评审之后记录结果。普通增补则沿用现有系统。
  • 页面的决策：.impeccable/surfaces/ 下的页面简报记录页面的目的、选定的方向、约束和未决问题。后续工作可以读到设计为何长成这般形态。
  • 视觉参考：生成的视觉稿保存在 .impeccable/mocks/ 下，连同生成细节，以及（如适用）记录在案的采纳结论。

设计规划属于开发记录。它不会写进页面的 HTML 注释、隐藏内容或其他发给访客的输出。

为什么选项不止于显而易见

有创意的提示仍可能得到眼熟的答案。在 Impeccable 公开的 2026 年 7 月实验中，不同创意框架下的 35 个答案有 30 个返回了同一概念。实验及其局限见这项研究。

Impeccable 在选取过程中引入变化。它从你的产品和受众出发发展各方向，用带种子的选取避免总是选中模型的第一偏好，并在视觉识别开放时从精选目录中考虑备选。

这些参考必须变成为你的产品而做的设计：它的内容、任务、控件与约束。目录图像展示的是灵感与完成度，而不是一张可供照抄的现成页面。

流程的更多细节

一个候选方向如何被评估

方向在到达你面前之前，必须先贴合产品：

  • 真实：它展示的主张和关系必须属实。示例性数据必须标明是示例。
  • 目的：它的结构必须能帮人理解产品或完成任务。
  • 效果：它的独到之笔必须改善体验，而不只是加一层装饰性主题。
  • 可行：它必须能在目标设备上，用现有的素材、工具和性能预算跑起来。
  • 贴合：它的取舍必须尊重你的简报。

对于已确立系统中的新页面，各备选方案在该系统内探索结构。对于全新或替换的视觉识别，它们可以探索不同的视觉语言。

书面方向与种子

页面简报中保存着一份简短的方向契约：核心想法、视觉语言、访客路径、首屏构图、选定的形态与种子，以及工作完成前必须检查的事项。

收尾评审用这些承诺来评估结果。对视觉稿主导的工作，它还会把实现与已采纳的图像做对比。

如果想重放那次选取（包括其中的重新生成轮次），请保留种子。重放选取并不保证生成完全相同的图像或代码。

委托决策与无人值守工作

当你在评审选项时，Impeccable 会请你选定一个方向，并在该工作流适用时采纳视觉稿。你也可以把选择委托出去。

无人值守运行时，它会按指定的方向推进，并说明自己的假设。如果决策页关闭时没有得到回答，它会先在对话中尝试一次，再把该运行当作无人值守处理。

你可以因任何理由要求新的选项。智能体自己要求重新生成，需要指出产品事实或任务上的具体问题；它个人的偏好不算数。

从 craft 命令过来的？

/impeccable craft 是普通 new work 请求的已弃用别名。你可以直接向 /impeccable 描述工作。
