Renaissance Geek, Inc.（下称「我们」）运营 impeccable.style 及下文所述的 Impeccable 服务。

你的项目与编码工具

Impeccable 为你的 AI 编码智能体提供设计指令和工具。它的项目检查在本地运行，并把发现返回给该智能体；检查不会把你的项目文件或检测结果上传到 Impeccable 的服务器。

你的编码工具可能把提示词、文件、截图及其他上下文发送给它所用的 AI 服务商。这类处理取决于该工具、你的设置以及服务商的条款。以下各节说明 Impeccable 自身发起的网络请求和网站服务。

版本检查与下载

Impeccable 可以在 impeccable.stylehttps://impeccable.style/api/version 检查是否有更新版本的技能（skill）。该检查不发送任何项目内容，通常借助本地缓存每天至多运行一次。设置 IMPECCABLE_NO_UPDATE_CHECK=1 可将其关闭。

安装或更新 Impeccable 时，软件从你的安装方式所使用的服务下载，例如 npm 或 GitHub。网站上的安装包下载会重定向到 GitHub Releases。这些服务按各自的政策接收并处理下载请求。

视觉世界与预览

当 Impeccable 向 impeccable.stylehttps://impeccable.style/api/roll 请求设计选项时，它会发送：

  • roll 密钥和轮次编号，用于复现某次选择以及请求下一轮。密钥默认随机生成。
  • 范围（scope）和可选过滤器，描述这次设计工作的类型：页面目的、正在设计界面的哪个部分、目标平台。API 还接受一个目录最低评分。

这些请求不包含你的项目名称、文件路径、提示词或简报。配置了本地目录时，无需这个 API 请求即可提供选项。展示目录预览时，可能会单独向 Impeccable 的服务器请求预览图。

可选的选择上报

对于由我们 API 提供的一轮选项，Impeccable 可以上报所选卡片的类型、它在页面上的位置，以及（当选中的是目录里的视觉世界时）它的目录 ID。如果用户没有选择而是要求换一批新选项，也会上报这一点。上报内容还包括 roll 密钥、轮次编号、目录版本、范围、页面模式、用户是否要求更保守或更大胆的选项，以及这次选择来自本地选择器里的点击还是来自你的智能体。它绝不会发送为你的项目创建的方向名称或描述。即便这类内容真的被发送过来，我们的服务器也会将其丢弃。

要关闭上报，运行 npx impeccable telemetry off，或设置 IMPECCABLE_NO_TELEMETRY=1 或 DO_NOT_TRACK=1。项目也可以为所有参与者关闭上报：在 .impeccable/config.json 中设置 "telemetry": false；npx impeccable telemetry status 可查看当前设置。关闭上报后，Impeccable 不发送任何选择报告，并且自 4.6.0 版本起，它的 roll 请求会要求我们的服务器不要记录，因此也不会保留 roll 的任何记录。更早的版本只对选择报告遵守那两个环境变量。目录选项和预览图的请求仍会发生，因为功能本身依赖它们。

我们的服务器从 roll 与选择中保留什么

我们的 roll 与选择处理程序会为每个事件保留一条记录，以了解哪些选项被展示、哪些被选中。我们把这些记录存储在 Cloudflare D1 数据库和 Cloudflare Analytics Engine 中，并归档到 Cloudflare R2。一条记录包含被发出或被选中的目录 ID、上文列出的选择细节、Impeccable 版本，以及一个宽泛的客户端类型（例如命令行工具或浏览器）。

roll 密钥本身绝不存储。我们只保存它的带密钥哈希，它能把一次 roll 的各轮与结束它的那次选择关联起来，但无法还原出密钥本身。记录中不包含 IP 地址、项目内容或用户/设备 ID。Cloudflare 会另行处理请求信息以交付服务，详见下文。

我们首页上实时展示的视觉世界集合使用的也是同一个 API。这些请求以相同方式记录，并被标记为网站流量，因此绝不会计为在 Impeccable 中做出的选择。

我们无固定删除日期地保留这些记录，以便对比目录扩充过程中选择的变化。由于其中任何一条都无法对应到具体的人或设备，我们无法按请求查找或删除某个用户的记录。

图像生成

当你的编码工具通过自带的图像工具生成图像时，适用该服务商的条款和数据设置。

如果你配置 OPENAI_API_KEY 来运行 Impeccable 的图像生成器，它会将图像提示词发送给 OpenAI，费用记在该密钥上。提供给命令的参考图像也会一并上传。提示词和参考图可能包含你项目的细节。移除该密钥即可停用这条 API 通道；它不会停用你编码工具内置的图像生成。参见 OpenAI 的 API 数据控制。

Live Mode 与方向选择器

Live Mode 和方向选择器使用本地服务器与你的智能体交换选择、标注及其他工作状态。它们的控件通过 localhost 通信。Live Mode 可以把截图和标注保存在你的项目中，供智能体读取。

该本地连接不会把这些工作状态上传给 Impeccable。你的智能体的处理过程以及页面加载的任何远程资源，仍受相应服务商政策的约束。

网站服务与浏览器存储

我们的首页使用 Google Analytics 来统计访问和交互。它可能收集页面与来源页信息、设备和浏览器细节、大致位置以及 Cookie 标识符。Google Analytics 使用 Cookie 区分访客和会话。参见 Google 对 Analytics Cookie 的说明和数据收集。

impeccable.style 的每个页面都使用 PostHog 来了解网站的使用情况。它记录页面浏览、点击、你复制的命令、你选择的安装方式以及 JavaScript 错误，同时收集页面与来源页信息、设备和浏览器细节以及大致位置。它在 Cookie 和本地存储中保存一个随机标识符，以关联同一浏览器的多次访问。这些请求经由 impeccable.style/relay 转发给 PostHog，并附带你的 IP 地址以便其估算位置。参见 PostHog 的隐私政策。

本站还从 Google Fonts 加载字体。你的浏览器会向 Google 发送加载这些字体所需的请求。命令语法切换开关会把你的偏好保存在浏览器的本地存储中。

Cloudflare 为我们的网站、API 和目录图像提供托管。它处理请求信息（包括 IP 地址）以交付并保护这些服务。Cloudflare 的隐私政策说明了它对这类信息的处理方式。

Do Not Track 与 Global Privacy Control：当你的浏览器发送这些信号时，网站目前不会改变其收集内容。无论信号如何，Google Analytics 和 PostHog 都照常运行。你可以在浏览器中阻止或清除 Cookie 和本地存储，Google 也提供一款退出 Google Analytics 的浏览器插件。上文提到的 DO_NOT_TRACK=1 设置只控制编码工具中 Impeccable 的上报，不控制网站。

Impeccable Pro 候补名单

加入候补名单时，我们会把你的电子邮箱地址和注册时间存储在 Cloudflare D1 中。在可获得时，我们还会存储注册来源、来源页、国家/地区以及你 IP 地址的哈希值。该哈希用于限制重复注册；候补名单表不存储原始 IP 地址。

我们使用你的邮箱确认注册，并在 Pro 就绪时通知你。确认邮件通过 Cloudflare 的邮件服务发送。来源和来源页信息告诉我们注册来自哪里。

你可以用邮件中的链接取消订阅。确认该请求后，你的注册记录会从候补名单数据库中删除。如果邮件提供的是回复式退订选项，请按那些说明操作。

Chrome 扩展

Impeccable 扩展在你的浏览器内检查页面。页面快照和检测结果都在本地处理，包括在一个离屏（offscreen）扩展文档中处理。检测器不会把它们上传到外部服务器。

扩展使用 chrome.storage.sync 保存规则和显示偏好。启用同步后，Chrome 可以跨登录了你 Google 账号的浏览器同步这些设置。参见 Chrome 的存储文档。

扩展会请求以下权限：

  • activeTab 和 scripting：检查你选定的页面。
  • storage：保存你的偏好设置。
  • webNavigation：响应页面导航以进行自动扫描。
  • offscreen：在扩展文档中运行检测器的 WebAssembly 代码。
  • 访问所有网址：支持对你选定的网站进行检查。
