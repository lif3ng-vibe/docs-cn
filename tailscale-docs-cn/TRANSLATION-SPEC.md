# 翻译规范（tailscale-docs-cn，子代理必读）

你是本翻译项目的译员子代理。开工前先读 `GLOSSARY.md`（术语表，全站统一）。

## 任务纪律

**一次回复只译一个文件**：Read 原文件 → 翻译 → Write 覆盖写回同一路径，然后只回一行极简汇报（文件名 + 完成）。多文件单回复会撞输出上限直接死亡。不要改名、不要移动、不要增删文件。

## 范围与保留

**必须翻译**：
- frontmatter 的 `title`、`description` 值（`sidebar.order` 数字不动，键名一律不动）
- 正文全部：标题、段落、列表、表格文字、`>` 引用块、**加粗文字**
- 引用式链接的显示文字：`[链接文字][docs-xxx]` 只译方括号里的文字
- `> **Note:**` / `> **Warning:**` 引用块译为 `> **注意：**` / `> **警告：**`
- `#` 注释（CLI 命令清单里 `#` 开头的注释行要译）
- `Last validated <日期>` 行译为「最后验证于 <日期>」，日期原样保留

**绝不翻译**：
- 代码块（``` 围栏内）全部内容——命令、配置、报错原文、示例输出、URL
- 行内代码 `` `...` `` 的内容（命令、路径、配置键、autogroup 名、API 名）
- 引用式链接的定义行：文末 `[docs-xxx]: /docs/...` 一字不动
- 链接的目标路径/URL/锚点中未变的部分（只译显示文字；路径一个字符都不能改）
- 产品/组件/技术名（见 GLOSSARY 不译名单：Tailscale、tailnet、MagicDNS、DERP、tsnet…）
- frontmatter 键名、YAML 结构、`---` 边界
- 表格中的命令列/取值列/Method 列（表头和说明列要译）

## 排版规范

- 中文全角标点：，。：；？！、（）""——；句末句号用。
- 中英文/数字之间加一个半角空格：如「使用 Tailscale 连接 3 台设备」
- 引号一律用 ""（不用「」）；破折号——两侧不带空格
- 术语首次出现附英文原词（如「出口节点（exit node）」），同页再出现只用中文
- 统一用「你」不用「您」
- 粗体闭合规则（CommonMark 坑，必守）：`**` 闭合侧前不能是"标点+文字"组合。句读移出粗体：`**……。**后文` ✗ → `**……**。后文` ✓；括注移出粗体：`**词（gloss）**后文` ✗ → `**词**（gloss）后文` ✓

## 锚点规则

页内锚点链接（`[文字](#xxx)`）指向的标题被翻译后，锚点必须重算。中文标题的 slug 规则（github-slugger）：拉丁字母转小写、空格转连字符、emoji 被剥掉（但留下的空格仍转成连字符）、保留 CJK 与连字符，去掉其他符号。
例：`## Create a tailnet` → `## 创建 tailnet`，锚点 `#create-a-tailnet` 改为 `#创建-tailnet`。
改过锚点的文件，在你的最终报告里列出「旧锚点 → 新锚点」对照。跨页链接（`/docs/...` 路径）一律不动。

## 质量档

校对级：术语一致（严格按 GLOSSARY）、无英文残留（停用词 the/and/with/your/from/that 不许出现在译文正文）、无翻译腔（"进行……的操作"这类要重写成人话）。拿不准的意译，不逐词直译。

## 完成后报告

每个文件译完只回一行：`<文件路径> ✓`。整批结束时才汇总：已译文件数、改动的锚点对照表（若有）、遇到的问题（若有）。不要贴译文全文。
