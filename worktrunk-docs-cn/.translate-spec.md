# 英文→简体中文技术文档翻译规范

供并行翻译子代理逐条遵守。

1. 任务：将指定的 .md 文档完整译为简体中文并写回原路径（覆盖）。校对级质量：术语一致、锚点正确、无英文残留、无翻译腔。
2. 先读同目录 GLOSSARY.md，术语与不译口径以它为准。
3. 不译：围栏代码块内全部内容；命令（wt、git 等及其子命令与选项）；CLI 选项名；环境变量；hook 名；模板变量（BRANCH、#branch 等）；产品/工具/协议名；配置键；路径；报错原文；console/终端示例代码块内的工具输出。代码块内的代码注释也不译。
4. 要译：frontmatter 的 title 与 description（保持一句话摘要为一句话）；正文散文；表格表头与说明列； admonition 块（:::note/tip/warning 等）的标题与正文；aria-label；工具输出示例前后的说明段；raw HTML 里可见的英文文案（如 `<td data-label="Plain git">` 的 data-label 值、`<span class="cmd-compare-value">` 内的括注说明）；**cli 命令清单中 `#` 开头的注释要译**（只出现在无围栏的行内命令清单里）。
5. 链接处理：链接的路径部分与 `#fragment` 锚点**一字不改**（锚点统一回修）；只译链接显示文字。
6. raw HTML 块：标签、属性名、src/srcset/href 值一律不动；仅译其中可见文案（可见文案翻译时不得改变标签结构）。
7. `<!-- ⚠️ AUTO-GENERATED ... -->` 与 `<!-- END AUTO-GENERATED -->` 标记行本身及其包裹的终端输出内容一律原样保留（终端输出是快照，不译）；标记行以外的 AUTO-GENERATED 注释若包裹的是 md 散文，则注释行原样保留、内部散文照常翻译。
8. 结构不变：标题层级、数量、顺序，列表嵌套层级，表格行列结构，围栏代码块数量与 info string 必须与原文一致。标题文本译成中文，但形态为 `wt xxx` 的命令标题（如 `wt step push`）整行保留原文。
9. 标点排版：中文全角标点（，。：；？！、（）“”）；中英文/数字之间一个半角空格；代码内保持半角；引号统一用“”不使用「」；破折号——两侧不加空格。
10. CJK 粗体闭合：粗体闭合 ** 前不能是标点。句读移出粗体：`**……。**后文` 改写为 `**……**。后文`；`**标题：**正文` 改写为 `**标题**：正文`；括注移出粗体：`**词（gloss）**后文` 改写为 `**词**（gloss）后文`。粗体结尾是文字或行尾则无问题。
11. 分轮写盘：目标文件超过约 400 行时，先 Write 已译的前半部分（未译尾部保持英文原样同文件写回），再 Read 该文件后用 Edit 把未译尾部替换为译文。全程保持结构与行数序不变。
12. 完成后：不要在回复中粘贴译文；汇报两样东西——(a) 一句话说明翻译概况（含 frontmatter 是否有 title/description 与其译法）；(b) 文件内全部标题（含层级）按顺序列成「层级 | 原文标题 | 中文标题」清单（标题文本用原文与译文原样，不含 wt 命令标题的可跳过注明）。
