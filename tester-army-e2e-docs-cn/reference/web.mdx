`@e2e-dev/web` 通过 Playwright 驱动 Chromium、Firefox 和 WebKit。web target
以它为引擎，它为纯浏览器工作贡献 `browser` fixture。从该包导入 `test` 即可获得
带类型的 `browser`。

该包依赖固定到精确版本的 `playwright-core`，因此引擎始终运行经过测试的那套
Playwright。自身也依赖 Playwright 的应用会保留自己的副本；只有版本一致时双方
才共享浏览器缓存。

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';

export default {
  targets: [{ engine: web(), app: { url: 'http://localhost:3000' } }],
} satisfies E2EConfig;
```

## 安装浏览器

缺失的浏览器会在每场运行开始计时之前下载一次。若要在 CI 或容器镜像里把
浏览器安装作为独立步骤，请运行该包的命令。它会为引擎所指定的 Playwright
版本安装浏览器：

<CodeGroup>
```bash npm
npx @e2e-dev/web install chromium --with-deps
```

```bash pnpm
pnpm exec e2e-web install chromium --with-deps
```

```bash bun
bunx @e2e-dev/web install chromium --with-deps
```
</CodeGroup>

可指定 `chromium`、`firefox`、`webkit` 中的任意一个；不指定时安装
`chromium`。`--with-deps` 还会安装浏览器在 Linux 上所需的系统库。命令以
安装器的退出码退出。

## 选项

```ts
/**
 * Options of the browser engine: how it drives the app. The app itself
 * (its `url`, `environment`, `identity`, and the command that starts it) is
 * the target's `app`.
 */
export interface WebOptions {
  /**
   * Browser to launch, `chromium` by default. A `BrowserProvider` leases
   * hosted browsers instead: one per worker slot at `prepare`, or one per
   * attempt, each attached to over CDP and released when its scope ends. A
   * provider implies chromium and excludes `connect`.
   */
  readonly browser?: BrowserName | BrowserProvider;
  /**
   * Initial viewport of every attempt's page; default 1280 by 720. `null`
   * emulates no size: the page fills the browser window, whatever size the
   * window has (a hosted browser's live view, a headed run), and
   * `browser.setViewport` still fixes one for the rest of the attempt.
   */
  readonly viewport?: ViewportSize | null;
  /**
   * How the engine's own screencast records an attempt that records video.
   * A browser provider that records (`BrowserProvider.record`) records in
   * its place, and ignores these. Which attempts record is the config's
   * `video`, not an engine option.
   */
  readonly screencast?: WebScreencastOptions;
  /**
   * Attach to a remote browser over CDP instead of launching locally. Requires
   * the chromium browser (the default). Wired by a hosted-browser engine.
   */
  readonly connect?: WebConnectOptions;
  /**
   * Headers added to requests within the app's site, including subdomains.
   * Useful for preview-protection tokens. Other sites never receive them.
   * Names are case-insensitive and replace existing headers of the same name.
   * This enables request routing, disables the browser's HTTP cache, and
   * blocks service workers.
   */
  readonly headers?: Readonly<Record<string, string>>;
  /**
   * HTTP basic authentication. The browser answers a `401` challenge with
   * these credentials on any origin, matching Playwright's `httpCredentials`.
   */
  readonly basicAuth?: WebBasicAuth;
  /**
   * The attribute that carries an element's test id: what the `testId` query
   * (`screen.getByTestId`) resolves and what `SemanticNode.testId` reports.
   * Defaults to `data-testid`.
   */
  readonly testIdAttribute?: string;
  /**
   * The `User-Agent` every attempt's context sends and `navigator.userAgent`
   * reports, for an app that switches into a test mode on a marker in the
   * agent string. Defaults to the browser's own. A `user-agent` entry in
   * `headers` beside it is `INVALID_CONFIG`, and so is a persistent context
   * (`connect.reconnectEndpoint`, or a provider with `scope: 'attempt'`).
   */
  readonly userAgent?: string;
  /**
   * The locale every attempt's context runs in, a BCP 47 tag such as
   * `de-DE`: what `navigator.language`, `Intl` formatting, and the
   * `Accept-Language` header report. Defaults to the browser's own. An
   * `accept-language` entry in `headers` beside it is `INVALID_CONFIG`, and
   * so is a persistent context.
   */
  readonly locale?: string;
  /**
   * The IANA time zone every attempt's context runs in, such as
   * `Europe/Berlin`: what `Date` and `Intl` resolve local time against.
   * Defaults to the machine's. A persistent context is `INVALID_CONFIG`.
   */
  readonly timezoneId?: string;
  /** Scripts every document runs before the page's own. See [Init scripts](#初始化脚本). */
  readonly initScripts?: readonly WebInitScript[];
}

/** JavaScript source, a file relative to the project root, or a function. */
export type WebInitScript = string | { readonly path: string } | (() => unknown);

/** The engine's screencast of the page: the frame size and the JPEG quality of the frames it encodes. */
export interface WebScreencastOptions {
  /** Frame size in pixels; default the viewport's, or the window's under `viewport: null`. A smaller size makes a smaller file. */
  readonly size?: ViewportSize;
  /** JPEG quality of each captured frame, 0 through 100; Playwright's default when unset. */
  readonly quality?: number;
}
```

`targets: [{ engine: web(), app: { url } }]` 中的被测应用是 target 的 `app`，不是引擎选项：详见[被测应用](/reference/config#被测应用)。`web()` target
需要 `app.url` 并拒绝设备键（`bundleId`、`appPath`、`launchArguments`、
`permissions`）；`web({ url })` 或 `web()` 上的任何其他 app 键都是未知键，
报 `INVALID_CONFIG`。带 `app.url` 的 target 是 `browser` target，因此
`requires: ['browser']` 可选中 web target。

`connect` 需要 chromium；`cdpEndpoint(signal)` 每个 worker 调用一次，断连后
每次尝试开始时再调一次。`browser` 提供者对象租用托管浏览器，并在运行或尝试
结束时释放它们；`BrowserProvider` 契约与示例提供者见[托管浏览器](/browser#托管浏览器)。`browser: provider` 与 `connect` 并用是 `INVALID_CONFIG`；
`web()` 不接受的选项、`connect` 或 `basicAuth` 中的未知键同样如此——疑似
拼写错误时指名最接近的已知键（`viewprt` 应为 `viewport`），否则列出全部键。
`basicAuth` 的用户名中不允许出现 `:`。`basicAuth` 密码是字符串或
`secrets.get(name)`：引擎在每次尝试开始时解析该机密、像其他已配置机密一样
脱敏，而它变成的 `Authorization` 头的 base64 凭据也如此。这层保护仅限文本：
与 fill 不同，它不遮蔽截图或模型拿到的像素，因此把密码渲染到屏幕上的页面
在这些像素中并不会被遮蔽（[安全](/security#机密)）。

`headers` 和 `basicAuth` 是测试访问[受保护预览](/web#受保护的预览)的手段。

`screencast` 决定录制成什么样，而不决定哪些尝试录制：那是 config 的
[`video`](/reference/config#video) 模式管的事。`size` 接受整数像素——每边
至少 1，`quality` 接受 0 到 100 的整数；其他任何值或多余的键都会在配置加载时
报 `INVALID_CONFIG`。旧的 `web({ video })` 写法报 `INVALID_CONFIG` 并指名
`screencast`。

### 恢复 CDP 传输

`connect.reconnectEndpoint(signal)` 开启在同浏览器的 CDP 传输断开后的恢复。
这一模式使用浏览器的持久默认上下文，因为 Chrome 会在普通 Playwright 上下文
的传输脱离时将其删除。

```ts
interface WebConnectOptions {
  cdpEndpoint(signal: AbortSignal): string | Promise<string>;
  reconnectEndpoint?(signal: AbortSignal): string | Promise<string>;
}
```

在此模式下，`cdpEndpoint` 会在每次尝试开始时（包括重试）新开一台专用的
浏览器。引擎会拒绝上一个尝试用过的浏览器。远端只能有默认上下文，且宿主必须
在该尝试结束时删除这台浏览器。引擎清理只断开自己的连接，不会终止宿主上的
浏览器。

断连之后，下一个操作会调用一次 `reconnectEndpoint`，受该操作的超时与中止
信号约束。该解析器必须返回已有浏览器的端点。引擎会校验持久默认上下文 ID 和
原页面的 target ID，并拒绝不暴露默认上下文 ID 的浏览器。页面缺失或上下文
不同都会使尝试失败。仅凭 URL 相同不足以选定一个替代标签页。引擎在发布每个
CDP 绑定之前先装好安全字段遮蔽；不兼容的 Playwright 版本会让连接失败，而
不是让像素外泄。恢复还需要原页面的各个 frame 保留其关闭式 shadow DOM 的
追踪钩子。若某个文档在断连期间加载时没有装上该钩子，恢复会以 `ENGINE_FAILURE`
失败——已有的关闭式根必须重新加载应用才能找回。遮蔽查询会拒绝任何未被
追踪的文档。

端点解析、CDP 附着、setup 与指令派发共用一个超时。耗尽它抛 `OPERATION_TIMEOUT`；
调用方或尝试被取消抛 `CANCELLED`。取消一个并发等待者不会取消已启动恢复的那个
操作；取消恢复的发起者则会使共享的恢复失败。

恢复会清除旧的节点引用。基于观测的 `tapAt` 调用、观测根滑动和聚焦引擎键盘
输入，恢复后需要先重新做一次引擎观测才能继续。在恢复之前启动的观测或定位器
读取，不能再在连接变更之后发布引用。每次尝试拥有自己的绑定与录制，迟到的
清理无法影响后来的尝试。确定性的 `browser.mouse` 与 `browser.keyboard`
fixture 无需智能体观测即可使用：测试代码自理输入，并可在操作前用
`browser.evaluate` 读取当前的几何信息与焦点。

恢复会保留页面未保存的状态、存储、尝试的机密污点与智能体台账。已经派发的
操作绝不重试。对话框与路由处理器会重新挂接。视频录制继续，但断连期间丢失的
分段找不回来。使用 `surfaceOf(engine)` 的代码在恢复之后必须重新获取其访问器
——先前持有的 Playwright 对象都属于已断开的传输。

持久恢复不支持 `headers`、`basicAuth`、`userAgent`、`locale`、`timezoneId`、
`app.clearState`，以及会话状态的捕获与恢复。`app.restart` 仍然可用。省略
`reconnectEndpoint` 即维持普通的隔离上下文与既有行为。`scope: 'attempt'` 的
`browser` 提供者共用同一个持久上下文，限制也相同：租期的 `cdpEndpoint` 开通
该尝试的浏览器，其 `reconnectEndpoint`（没有则再次用 `cdpEndpoint`）负责
重连。按提供者契约，租期都是全新的，因此引擎不会把它和早前尝试的上下文比较
：托管服务可能从同一个快照恢复浏览器，从而赋予新浏览器相同的上下文 id。

尝试的第一个页面就是浏览器自己的第一个标签页（导航到 `about:blank`），而不是
旁边另开的第二个标签页；此后打开的页面（例如 `app.restart` 打开的那个）才是
新标签页。

## 活动标签页

`browser` 是整个浏览器，当前显示一个活动标签页。读取或操作页面的东西都作用
在那个标签页上：`goto`、`reload`、`back`、`forward`、`url`、`title`、
`waitForURL`、`locator`、`frameLocator`、`evaluate`、`waitForResponse`、
`waitForDownload`、`keyboard`、`mouse`、`expect(browser)` 匹配器，以及所有
`screen` 查询。属于浏览器的则覆盖每个标签页：`cookies`、`setCookies`、
`route`、`unroute`、`onDialog` 和 `addInitScript`。`setViewport` 调整活动
标签页以及其后打开的每个标签页的大小。

应用自己打开的标签页（来自 `target="_blank"` 链接或 `window.open`）不会被
跟进：活动标签页仍是尝试开始时打开的那个，因此请断言那个标签页显示的内容，
或用 `browser.goto` 打开链接的 URL。

## browser fixture

```ts
/**
 * The browser the attempt drives, showing one active tab. Navigation, reads,
 * `locator`, `frameLocator`, `evaluate`, `waitForResponse`, `waitForDownload`,
 * the keyboard and mouse, `expect(browser)`, and `screen` act on the active
 * tab; cookies, routes, and dialog handlers cover the whole browser, every
 * tab included. A tab the app opens itself (a `target="_blank"` link,
 * `window.open`) is not followed: the active tab stays the one the attempt
 * opened.
 */
export interface Browser extends Expectable<BrowserExpectation> {
  /** Navigates to an allowed URL. */
  goto(
    url: string,
    options?: {
      waitUntil?: 'load' | 'domcontentloaded' | 'networkidle';
      timeout?: number;
    },
  ): Promise<void>;
  /** Reloads the current document. */
  reload(options?: ActionOptions): Promise<void>;
  /** Navigates browser history back once. */
  back(options?: ActionOptions): Promise<void>;
  /** Navigates browser history forward once. */
  forward(options?: ActionOptions): Promise<void>;
  /** Returns the current URL. */
  url(): Promise<string>;
  /** Returns the current title. */
  title(): Promise<string>;
  /** Waits for the current URL to match. */
  waitForURL(url: string | RegExp, options?: { timeout?: number }): Promise<void>;
  /** Creates a web-only CSS or XPath locator. */
  locator(selector: string): Locator;
  /** Creates a screen query scope inside one iframe. */
  frameLocator(selector: string): FrameScreen;
  /** Evaluates trusted test code in the page: a function, or a string expression whose value is returned, called first if it is a function. */
  evaluate<T extends JsonValue>(fn: string | (() => T | Promise<T>)): Promise<T>;
  /** Evaluates trusted test code with one required JSON-safe argument. */
  evaluate<T extends JsonValue, Arg extends JsonValue>(
    fn: string | ((arg: Arg) => T | Promise<T>),
    arg: Arg,
  ): Promise<T>;
  /** Adds a script every document runs before the page's own, from the next navigation on. */
  addInitScript(script: string | { path: string } | (() => unknown)): Promise<void>;
  /** Adds an init script function called with one JSON argument. */
  addInitScript<Arg extends JsonValue>(script: (arg: Arg) => unknown, arg: Arg): Promise<void>;
  /** Adds an attempt-scoped network route. */
  route(
    pattern: string | RegExp,
    handler: (route: WebRoute) => void | Promise<void>,
  ): Promise<void>;
  /** Removes matching attempt-scoped routes. */
  unroute(pattern: string | RegExp): Promise<void>;
  /** Waits for a matching response. */
  waitForResponse(
    pattern: string | RegExp,
    options?: { timeout?: number },
  ): Promise<WebResponse>;
  /** Returns cookies visible to the current context. */
  cookies(): Promise<Cookie[]>;
  /** Sets cookies after URL validation. */
  setCookies(cookies: readonly Cookie[]): Promise<void>;
  /** Sets the viewport size. */
  setViewport(size: { width: number; height: number }): Promise<void>;
  /** Registers an attempt-scoped dialog handler and returns an unsubscribe function. */
  onDialog(handler: DialogHandler): Promise<() => Promise<void>>;
  /** Runs a trigger and waits for its download. */
  waitForDownload(
    trigger: () => Promise<void>,
    options?: { timeout?: number },
  ): Promise<{ path: string; suggestedFilename: string }>;
  /** Viewport-level keyboard, for whatever has focus. */
  readonly keyboard: {
    /** Sends one key. */
    press(key: string): Promise<void>;
    /** Types plain text. */
    type(text: string): Promise<void>;
  };
  /**
   * Direct pointer input from test code, independent of agent observations.
   * After CDP recovery, test code can read current geometry with `evaluate`
   * before starting a pointer sequence.
   */
  readonly mouse: {
    /** Moves the pointer. */
    move(x: number, y: number): Promise<void>;
    /** Scrolls the pointer wheel. */
    wheel(deltaX: number, deltaY: number): Promise<void>;
    /** Presses the primary pointer button. */
    down(): Promise<void>;
    /** Releases the primary pointer button. */
    up(): Promise<void>;
  };
}
```

| 成员 | 默认超时 |
| --- | --- |
| `goto`、`reload`、`back`、`forward` | `config.timeout`，120000 ms，与 `app.open()` 用的是同一份预算；`{ timeout }` 可覆盖，上限受测试截止时间约束 |
| `waitForResponse`、`waitForDownload` | `config.actionTimeout`，30000 ms；`{ timeout }` 可覆盖，上限受测试截止时间约束 |
| `waitForURL` | `config.assertionTimeout`，5000 ms |
| `url`、`title`、`evaluate`、`addInitScript`、`route`、`unroute`、`cookies`、`setCookies`、`setViewport`、`onDialog`、`keyboard.*`、`mouse.*` | `config.actionTimeout`，30000 ms，不可覆盖 |

每次 `browser` 调用都会被记录为一个 `browser.<method>` 步骤，`locator` 和
`frameLocator` 除外：它们只构建定位器而不触碰页面，作用于其上的动作或断言
才是步骤。相对 URL 按目标 target 的 `app.url` 解析，否则报
`APP_URL_REQUIRED`。在也会于其他平台运行的套件里请声明 `requires: ['browser']`。

### 导航

`goto` 的 `waitUntil` 默认为 `'load'`；URL 的 scheme 不是 `http:` 或
`https:`（`about:blank` 例外）时抛 `POLICY_DENIED`。`waitForURL` 每 100 ms
轮询一次；相对字符串按基础 URL 解析并在归一化后精确匹配，`RegExp` 对完整
URL 做测试，其他任何值（比如谓词函数）都是 `INVALID_ARGUMENT`，超时则为
`ASSERTION_FAILED`。它只接受 `timeout`：其他键（如 Playwright 的
`waitUntil`）是 `INVALID_ARGUMENT`。其余导航抛 `ACTION_FAILED`。

```ts
await browser.goto('/dashboard', { waitUntil: 'networkidle' });
await browser.waitForURL(/\/orders\/\d+$/, { timeout: 15_000 });
```

### 定位器与 frame

`locator` 和 `frameLocator`——不管在页面级还是 frame 内——遇到空选择器抛
`INVALID_LOCATOR`。`frameLocator` 对缺失的 frame 抛 `LOCATOR_NOT_FOUND`，
对多个抛 `LOCATOR_AMBIGUOUS`。选择器是 Playwright 选择器：默认 CSS，
`xpath=` 或前导 `//` 为 XPath，`>>` 为链式，因此
`browser.locator('[data-testid="row"] >> nth=2 >> [data-testid="conditions"] > div')`
会把 CSS 约束在同一行的范围里。最后一段之前的 `*` 捕获
（`*css=article >> text=Hello`）是 `INVALID_LOCATOR`：包含另一个元素的场合
请用 `filter({ has })`。

```ts
const payment = browser.frameLocator('#payment-frame');
await payment.getByLabel('Card number').fill('4242424242424242');
```

`frameLocator` 返回一个 `FrameScreen`：一个查询从 frame 内部作答的 `Screen`，
外加两个仅限 web 的逃生舱口（限定在该 frame 范围内）。

```ts
export interface FrameScreen extends Screen {
  /** Creates a web-only CSS or XPath locator inside this frame. */
  locator(selector: string): Locator;
  /** Creates a screen query scope inside an iframe nested in this frame. */
  frameLocator(selector: string): FrameScreen;
}
```

只有当控件没有可访问名称、label、placeholder 或 test id 时才动用 frame 的
`locator`；何时适用见[浏览器指南](/browser#深入-iframe)。

每个 `screen` 查询都会搜索其范围下、页面附着的所有关闭式 shadow root，用
Playwright 原生的 role、name、text、label、attribute 匹配，且每个节点只命中
一次，因此被观测树列在关闭根内的控件能够被解析出、能接受动作和读取。
`locator`、`frameLocator` 和 `filter({ hasText })` 保持 Playwright 的能力
范围并在关闭根处停下；细节见[浏览器指南](/browser#shadow-dom)。

### evaluate

函数在页面里运行，无法访问测试侧的变量。它按源码序列化并注入页面，因此不能
闭包自己函数体之外的东西；在体内声明的辅助函数可以。外部值请通过 `arg`
传入。`arg` 与返回值都必须是 `JsonValue`，否则调用以 `INVALID_ARGUMENT` 失败。

字符串按单个表达式求值，而不是按语句。若求值结果是函数，则以 `arg` 调用它；
否则其值就是结果。返回的 promise——无论来自哪种——都会被等待。

求值代码中的异常是 `EVALUATE_FAILED` 并附带其消息。Playwright 超时是
`ACTION_FAILED`；页面已关闭或上下文丢失是 `ENGINE_FAILURE`。

```ts
const count = await browser.evaluate(() => document.querySelectorAll('li').length);
const flag = await browser.evaluate(
  (name: string) => window.localStorage.getItem(name),
  'featureFlags',
);
const title = await browser.evaluate<string>('document.title');
```

### 初始化脚本

初始化脚本在每个标签页和每个 frame 的每个文档中、先于页面自身脚本运行。
`web({ initScripts })` 对所有测试生效；`browser.addInitScript` 添加一个，
生效至该测试结束。

脚本可以是 JavaScript 源码、相对项目根的 `{ path }`，或一个函数。函数不能
闭包测试变量；请改为传入 JSON `arg`。

```ts
await browser.addInitScript((value) => { Math.random = () => value; }, 0.5);
await app.open('/raffle');
```

页面打开之后才添加的脚本，从下一次导航或 reload 起生效。

### 路由

`route`、`unroute` 和 `waitForResponse` 接受字符串模式（路径段内的 `*`，
跨 `/` 的 `**`）或 `RegExp`，都对完整 URL 做测试；谓词函数是
`INVALID_ARGUMENT`。路由在 `app.restart()`、`app.clearState()` 和会话恢复
之后依然存活。处理器必须用 `fulfill`、`continue`、`fallback` 或 `abort`
恰好决策一次；决策两次或一次不决都是 `ACTION_FAILED`。路由按新到旧优先
运行。`continue` 把请求放行到网络，其他路由不再看到它；其 `url` 按基础 URL
解析并走与 `goto` 相同的规则，被禁的 scheme 是 `POLICY_DENIED`，且必须保持
请求原有的 scheme。`headers` 替换每个请求头。配置的 `headers` 仍会搭在去往
应用站点的放行请求上——且仅限该站点。`fallback` 把请求交给此路由之前注册
的那个路由，没有匹配时交给网络。`fulfill` 接受 `json`、`body` 或 `path`
三者之一，`path` 指向相对项目根的文件、其扩展名决定 `Content-Type`（除非
`contentType` 或 `content-type` 头另行设定）。决策不接受的选项（如
Playwright 的 `abort(errorCode)`、拼写错误的键）是 `INVALID_ARGUMENT`：
请求被中止，下一步失败。

在截止时间内无人匹配的 `waitForResponse` 是 `ACTION_FAILED`。截止时间约束
匹配：响应头一到就解析，`text()` 和 `json()` 等正文用的是自己的预算
（`config.actionTimeout`，上限受测试截止时间约束）；预算用尽时仍在流式传输
的正文是 `ACTION_FAILED`。`url`、`status` 和 `headers` 总是可读的；浏览器
读不到的正文（不足声明的 `Content-Length` 就重置的连接、被页面中止的请求，
以及重定向——浏览器从不保留其正文）会让 `text()` 和 `json()` 以
`ACTION_FAILED` 拒绝，而不是返回空字符串。真正的空正文读作 `''`。抛错的
处理器（比如对请求做了一次失败的 `expect`）以其错误让下一步失败；若后面没有
步骤，则在尝试结束时使其失败；仍在运行的处理器会拿到清理预算来收尾。超出
预算仍未结束的处理器会让尝试以 `CLEANUP_TIMEOUT` 失败，之后它抛出的东西一律
丢弃。

```ts
await browser.route('**/api/quote', async (route) => {
  await route.fulfill({ json: { cents: 4200 } });
});

const response = await browser.waitForResponse('**/api/orders');
expect(response.status).toBe(201);
```

```ts
/**
 * One of `json`, `body`, or `path`, or none for an empty body. `path` names a
 * file relative to the project root; its `Content-Type` follows its
 * extension unless `contentType` or a `content-type` header sets one.
 */
export type RouteFulfillResponse = {
  status?: number;
  headers?: Record<string, string>;
  /** Sets the `Content-Type` response header. */
  contentType?: string;
} & (
  | { json: JsonValue; body?: never; path?: never }
  | { body: string; json?: never; path?: never }
  | { path: string; json?: never; body?: never }
  | { body?: never; json?: never; path?: never }
);

/** What `continue` changes about the request before it goes to the network. */
export interface RouteContinueOverrides {
  /** Resolved against the base URL like `goto`; must keep the request's scheme. */
  url?: string;
  /** Request method. */
  method?: string;
  /** Replaces every request header; the configured `headers` for the app's site are added on top. */
  headers?: Record<string, string>;
  /** Request body. */
  postData?: string;
}

export interface WebRoute {
  /** The intercepted request. */
  readonly request: {
    readonly url: string;
    readonly method: string;
    readonly headers: Readonly<Record<string, string>>;
    readonly postData?: string;
  };
  /** Fulfills the intercepted request once. */
  fulfill(response: RouteFulfillResponse): Promise<void>;
  /** Sends the intercepted request to the network once, skipping every other route. */
  continue(overrides?: RouteContinueOverrides): Promise<void>;
  /** Hands the intercepted request to the route registered before this one, or the network when none matches. */
  fallback(): Promise<void>;
  /** Aborts the intercepted request once. */
  abort(): Promise<void>;
}

export interface WebResponse {
  /** Response URL. */
  readonly url: string;
  /** HTTP status. */
  readonly status: number;
  /** Response headers, lower-cased names. */
  readonly headers: Readonly<Record<string, string>>;
  /** Waits for the body and parses it as JSON. */
  json<T = unknown>(): Promise<T>;
  /** Waits for the body and reads it as text. */
  text(): Promise<string>;
}
```

### Cookie 与视口

`setCookies` 先校验每个 cookie，再统一设置；解析不了的目标或被禁的 scheme
是 `POLICY_DENIED`，什么都不设置。相对 `url` 按基础 URL 解析，与 `goto` 的
解析方式相同。`domain` 形式的 scheme 跟随基础 URL，前导 `.` 会被剥掉。
`setViewport` 会把新尺寸记入报告。它在第一次导航之前同样有效，与 Playwright
的 `setViewportSize` 一样：下一次 `app.open` 就按该尺寸加载，手机尺寸的测试
不会先渲染出桌面布局。该尺寸对本次尝试的剩余部分持续有效，贯穿
`app.restart()` 和 `app.clearState()`。

```ts
export interface CookieFields {
  /** Cookie name. */
  name: string;
  /** Cookie value. */
  value: string;
  /** Unix timestamp in whole seconds. */
  expires?: number;
  /** HttpOnly flag. */
  httpOnly?: boolean;
  /** Secure flag. */
  secure?: boolean;
  /** SameSite attribute. */
  sameSite?: 'Strict' | 'Lax' | 'None';
}

/** `url`, or `domain` with an optional `path`, never both. */
export type Cookie = CookieFields &
  (
    | { url: string; domain?: never; path?: never }
    | { url?: never; domain: string; path?: string }
  );
```

```ts
await browser.setCookies([{ url: 'http://localhost:3000', name: 'tz', value: 'UTC' }]);
```

### 对话框与下载

函数处理器必须调用 `accept` 或 `dismiss`；两者都不调用的，对话框会被关闭，
并像未处理的对话框一样让下一步以 `APP_NOT_OPEN` 失败。抛错的处理器以其错误
让下一步失败——若后面没有步骤，则在尝试结束时失败：失败的 `expect` 仍是
`ASSERTION_FAILED`，未分类的抛出是 `ENGINE_FAILURE`。`waitForDownload` 会把
文件登记为一个 `download` 产物，未按时完成则抛 `ACTION_FAILED`。触发器按时
resolve 却没启动下载时，失败为 `no download started within <n>ms; the trigger resolved after <m>ms`——等待时间包含触发器自己的耗时。超时时刻仍在
运行的触发器以步骤超时失败，抛错的触发器以其自身错误失败。托管浏览器上，
文件通过提供者的 [`downloads`](/browser#提供者侧的下载) 返回。

```ts
/** A native dialog as a test's handler sees it. */
export interface Dialog {
  /** The dialog's text. */
  readonly message: string;
  /** Accepts the dialog once. */
  accept(text?: string): Promise<void>;
  /** Dismisses the dialog once. */
  dismiss(): Promise<void>;
}
```

```ts
const off = await browser.onDialog('accept');
await screen.getByRole('button', 'Delete').tap();
await off();

const file = await browser.waitForDownload(() =>
  screen.getByRole('link', 'Export CSV').tap(),
);
```

## 语义捕获恢复

当语义读取器超时时，智能体观测可以改用一张全新的视口截图来恢复。Playwright
会在每个可达 frame——包括开启与关闭的 shadow root——重新做一轮安全字段
遮蔽排查。每一次遮蔽探测都必须成功。观测会显式报告语义不可用，并清除更早的
节点引用。

恢复需要操作预算尚有余裕，且需要 runner 的许可。`act` 在任何机密填充之前
允许它；判定还要求 `vision: true` 或 `'only'`。遮蔽失败、取消和严重的引擎
错误仍会叫停观测。

允许回退时，读取器会预留剩余观测预算的四分之一（上限两秒）给截图。该截止
时间涵盖页面遍历、元数据与元素的回读，以及嵌套 frame。语义元数据以单个
JSON 字符串跨 Playwright 连接传输，以减少序列化开销。动作仍使用与该元数据
一起捕获的活跃元素句柄。替换了 `JSON.stringify` 或给 object/array 原型加了
`toJSON` 方法的页面会改用结构化传输。清理过程不等待停滞的协议应答。被放弃
的读取器不得复用节点 ID，也不得在更新的观测之上发布句柄。

## surfaceOf

```ts
import { web, surfaceOf } from '@e2e-dev/web';

const engine = web();
const live = surfaceOf(engine);   // PlaywrightLiveSurface | undefined
live!.page();                     // the Page of the current attempt
live!.context();                  // its BrowserContext
```

在[自定义执行器](/executors#自己驱动页面)里用
`surfaceOf(handle)` 直接访问当前 Playwright 页面与上下文。对来自其他包的
句柄，它返回 `undefined`。活动尝试之外，这些访问器抛 `INVALID_STATE`。
直接的 Playwright 调用不会记录为步骤。
