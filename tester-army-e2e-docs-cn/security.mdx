测试代码和配置以你的操作系统权限运行——引擎、工具、报告器、store、机密提
供者（secret provider）和应用命令全都如此。e2e 不为它们做沙箱隔离。不受
信任的 pull request 代码请在外部沙箱中运行，且不提供机密或写入 token。

应用内容作为不受信任的证据提供给模型。模型通过工具请求动作；runner 校验
并执行这些动作。缓存的动作同样以你的权限运行，因此要像审查测试代码一样审
查共享的缓存条目。

## 模型看到什么

模型请求把 runner 的策略与受信任的项目上下文，同应用内容区分开。应用内容
无法授出工具、凭据或更大的预算。[智能体步骤如何工作](/agent-steps)说明了
步骤向模型展示什么、模型又能做什么；本页列出的是信任边界。

| 提示中的内容 | 形式 |
| --- | --- |
| 你的指令与 params | 包在 `<instruction>` 中并标记为数据。`Secret` 类 param 只投影出名称与用途。 |
| 屏幕 | 一棵可访问性树，含节点 id、role、名称、文本、test ID、链接目标与状态，按尺寸上限截断。不含选择器。链接的 query 与 fragment——token 藏身之处——只显示为 `?…` 和 `#…`。 |
| 位置 | 当前 URL，已脱敏。 |
| 截图 | 在需要或被请求时，且仅当引擎能证明安全字段已遮挡、本次尝试未填充过任何机密时才提供。 |
| 之前的步骤 | `agent.act` 从同一测试或串行组收到有界的记录。判定只用当前屏幕和指令，不使用先前步骤的记录。 |

安全字段显示为 `value=<secure>`。模型输入和报告中的已知机密值会变成
`<secret:name>`。这项[脱敏](#脱敏)对变换后的值、图像和应用日志仍有局限。

## 模型可以做什么

内置工具的 schema 是封闭的，且仅在引擎支持时提供。项目工具必须用
`defineTool` 创建，不能顶替内置名称。只有只读的项目工具才能请求观测。

调用了步骤未提供的工具，或传入了 schema 未声明的参数，一概不会执行：模型
读到拒绝说明后会再试。不在当前屏幕上的节点 id 会让动作以 `LOCATOR_NOT_FOUND`
失败。runner 绝不把模型文本当作代码、选择器、shell 命令或配置来执行。

违反规则的工具调用以 `POLICY_DENIED` 失败：

| 被拒绝的行为 | 原因 |
| --- | --- |
| 导航到 `http:` 和 `https:` 之外的 scheme（`about:blank` 除外） | `file:`、`data:`、`javascript:` 以及 `view-source:file:` 这类包装形式会加载本地或内嵌内容。 |
| 格式错误的 URL | 不做任何修复。 |
| `Secret` 进入 JSON sink | 句柄不携带值，任何值都不得被序列化。 |
| 用 getter 或 `toHaveValue`、`toHaveText`、`toContainText`、`toHaveAttribute` 匹配器从安全字段读取值、文本或属性 | 断言结果，而不是机密。被扣留的值显示为脱敏后的形式，不是空串，也不是缺失。 |
| 对未声明的名称使用 `type_secret` | 只有步骤 params 里的机密才能填充。 |
| 把 `type_secret` 用在禁用或不可编辑的节点上 | 可接收填充的节点是 `textbox`、`searchbox` 和 `combobox`。 |
| 把密码填进非密码字段 | 用途必须匹配；普通机密可以填任何可编辑输入。 |
| 不是用 `defineTool` 创建、或没有 `execute` 的项目工具 | 未声明的语义不可信。 |
| 会改动状态的项目工具请求观测 | 请在单独的调用中观测。 |
| 在像素被扣留时使用 `vision: 'only'` | 没有可退回的东西。 |
| 机密填充之后调用 `app.screenshot()` | 应用可能把机密显示在安全字段之外。 |

## 导航与 origin

导航和机密填充没有 origin 允许列表。智能体可以跟随应用转到其他站点，并在
那里使用提供给当前步骤的机密。密码填充仍要求密码字段。

浏览器引擎基于主机名做站点判定，用于两个目的：

- 配置的 `headers` 会加到 target 站点的请求上。
- 该站点之外的子 frame，以及 `data:` frame，不会进入观测。

站点判定在没有公共后缀列表的情况下近似可注册域。`vercel.app` 这类共享托
管域算作一个站点，因此 headers 可到达该域下的其他主机。`basicAuth` 更宽：
它应答来自任何 origin 的 `401` 挑战。

runner 在显式导航时检查 scheme。`app.open`、`browser.goto` 和智能体的
`navigate` 动词只接受 `http:`、`https:` 和严格的 `about:blank`。设备链接
可能使用应用的自定义 scheme，因此 `device.openLink` 改为拒绝一份黑名单：
`file:`、`data:`、`javascript:`、`view-source:`、`blob:` 和 `filesystem:`。
`device.openApp` 和 `open_app` 工具接受的是应用 id，拒绝链接，因为设备会把
链接当作 URL 打开。runner 不复查重定向，也不连接 popup 页面。注册
`browser.onDialog` 来处理浏览器对话框。

## 机密

`Secret` 是一个不透明句柄，没有明文访问器。接受它的 sink 有三个：定位器的
`fill`、智能体步骤的 params，以及声明接收它的引擎选项
（`web({ basicAuth: { password } })`）。用法见[登录](/authentication)指
南；规则在本页。

模型主导的填充发生之前，runner 会检查：步骤已声明该机密、该机密已配置、
目标是一个启用的可编辑输入。密码要求密码字段。然后 runner 在宿主上解析出
值并交给引擎。回放会重复这些检查。

确定式的 `fill(secret)` 使用测试代码选定的字段，不做那些面向模型的字段检
查。它仍会把值登记脱敏，并在本次尝试的剩余部分禁用像素。

### 机密填充后的截图

任何机密填充之后，在本次尝试的剩余时间里，截图与像素工具不可用，
`app.screenshot()` 被拒绝，runner 也省略断言与失败截图。应用可能在字段遮
挡矩形之外的任何地方显示该值。语义采集先于步骤超时的 `act` 或 `vision: true`
步骤会以 `POLICY_DENIED` 失败，而不是去读兜底截图。

恢复某个设置测试填充过机密的[会话](#会话)的测试也保留这层保护。设置测试
若登录时没有填充机密——例如用 `browser.setCookies` 设置会话 cookie——恢复
它的测试仍可使用截图。它使用的值若不是已配置的机密，则不会被脱敏。

### 引擎选项中的机密

引擎选项持有的机密（`web({ basicAuth: { password: secrets.get(name) } })`）
在每次尝试开始时于宿主上解析，并在那时连同引擎从它派生出的东西（对 basic
auth 来说，是 `Authorization` 头携带的 base64 `user:password`）一起登记脱
敏。它不算填充，且只按文本提供保护：报告、`screen-at-failure.txt`、链路
页、模型与 `e2e mcp` 会话读到的内容、文本下载都会脱敏，而截图与模型的像素
原样保留。把密码渲染到屏幕上的页面，在像素里不会被遮挡。

### 脱敏

runner 会把已登记机密值的每一次出现替换为 `<secret:name>`，位置包括：模型
输入、报告、`e2e run` 期间你的代码打印的内容（测试、配置与测试文件的顶层
代码、报告器），以及文本下载。这包括测试以普通字符串传入的值（而非
`secrets.get()` 句柄）：test 与 `describe` 标题、步骤标签（`app.open` 的
URL、定位器的文字）、`fill`、`agent.act` 或 `agent.assert` 指令、
`agent.act` params 中的字符串、`agentContext`，以及 `e2e explore` 的目标。
普通字符串不是机密填充：它只按文本保护，截图仍然可用。标题在测试文件被收
集时就已脱敏，因此 test ID、`--grep`、报告器、产物与失败页的文件名看到的
都是 `<secret:name>`；同一文件里仅机密值不同的两个标题算作重复的标题路径。
自定义执行器的 `ctx.step` 和内置智能体的提示携带该标记，因此只有句柄才能
真正键入那个值。

匹配覆盖值本身、其 JSON 转义、HTML 转义和百分号编码形式（任意大小写，因此
CSS 的 `text-transform` 藏不住它），以及折叠空白后的形式。按长度上限截断
的文本，若其结尾是某值的开头 8 个以上字符（值本身短于 16 时为一半），无论
原样还是折叠空白，同样会被脱敏——这与引擎在截断前折叠文本的方式一致。观测
屏幕上的每一个字符串——名称、文本、值、test ID、属性、选择器、frame 路径
一概如此——都会在模型、执行器的树、回放缓存描述符或结束锚点读取之前，先脱
敏一次。脱敏只改写 runner 报告的内容；断言仍比较页面实际显示的文本。机密
值及其截断片段绝不进入缓存条目。

配置加载期间打印的输出会在加载完成后出现。加载失败时，这批输出被扣留不
发，因为配置中的机密尚不可知。

静态值短于 6 个字符属于 `INVALID_CONFIG`，提供者返回过短的值会让填充失
败：这么短的值每一次出现都会连带把普通文本一起误伤。

### 脱敏的边界

- 值的变换形态，比如最后四位，不再是机密本身，会原样通过。
- 整体编码（而非逐字符编码）后的值——base64 或哈希——是另一个字符串，会
  通过。
- 应用以另一种 Unicode 规范化形式渲染的值——机密用组合式变音符号而页面用
  分解式——会通过。
- 把值内部的空白去掉的文本会通过。把空白加宽的文本也会通过，但观测屏幕除
  外：折叠后恰好含该值的字段会保持折叠并被遮挡。
- 分散在多个节点上的值——像 PIN 键盘那样一格一字符——在树里不是单个字符
  串，会通过。
- 会改变长度的 case 映射（`ß` 显示为 `SS`）能逃过按长度截断文本的前缀规
  则。
- 标题在其文件被收集时（任何提供者运行之前）就已脱敏，因此机密提供者随后
  返回的值不会从标题中脱敏。
- 当测试由宿主以内存方式传入配置或测试、在 runner 自己的进程里运行时，它
  们的控制台输出不做脱敏。
- 视频什么都不遮挡，标记为 `redaction: "incomplete"`。除非你要求，否则从
  不录制。托管浏览器或设备服务保有的录像留在该服务处，报告只保存它的
  URL。
- 下载文件就是应用原样交付的内容。当会话知道某个机密值时，文本下载
  （`text/*` 或按扩展名判定为 JSON 的）会被改写并标记
  `redaction: "complete"`：值的每一次完整出现、其连续 8 个以上字符的片段
  （是否折叠空白均算，因此与值共享 8 个字符的无关文本也会被遮挡）、以及解
  码后等于前两者之一的 base64 或 base64url 串，都会变成 `<secret:name>`。
  其他任何下载——二进制、无效 UTF-8、无法改写，或来自不知晓任何机密值的会
  话——都按交付原样保留，标记 `redaction: "incomplete"`。
- `command.log` 按进程写入的原样捕获，runner 不对它脱敏。请把机密挡在应用
  stdout 之外。

## 会话

保存的会话包含登录状态，加密存储，且只在一次运行内有效。会话还在同一份密
文中携带设置测试在保存之前从提供者解析出的机密值，以及是否在它之上填充过
机密。恢复会话的测试会脱敏这些值并继续扣留像素，因此被应用回显的存储
token 永远到不了失败消息、报告或模型。信封以明文（经认证）写出机密的名
称；值绝不以未加密形式落盘。

| 属性 | 值 |
| --- | --- |
| 位置 | [输出目录](/reference/config#output)下的 `sessions/<runId>/`（默认 `.e2e/sessions/<runId>/`），目录模式 `0700`，文件 `0600` |
| 加密 | AES-256-GCM，每次保存使用新的 12 字节 IV |
| 密钥 | 每次运行生成 32 个随机字节，只存内存。worker 通过 IPC 接收，绝不经过磁盘或环境变量。 |
| 绑定 | 运行 id、target、引擎名称与版本、平台和应用身份，全部作为附加数据参与认证 |
| 有效期 | 最长 24 小时；保存的状态自带更早过期时间时以其为准 |
| 清理 | 运行结束时删除该目录 |

无效、过期、缺失或不匹配的会话都会被拒绝。对应错误码见
[会话错误](/reference/errors)。

## 缓存信任

共享的缓存条目应像测试代码一样接受审查。它们可以不经模型就回放动作，也没
有签名。

runner 在使用前校验条目，无效条目视为未命中。文件以期望键的哈希命名，超
过 1 MiB 即拒绝。键中的智能体上下文只以脱敏后文本的哈希形式出现，因此没有
机密值进入其中。条目保存的是动作和脱敏后的摘要；回放只执行动作。机密填充
只存名称，并在回放时再次获准填充。一个智能体记录的条目绝不为另一个智能体
回放；在应用本 origin 上记录的条目，绝不在来自其他 origin 的页面上回放。

`e2e init` 已把 `.e2e/cache/` 加进 Git 忽略。如果你选择
[提交录制的条目](/cache#提交回放缓存)，请审查其中的动作与键入
的值。未配置缓存模式时，CI 默认只读。

## 产物与日志

默认情况下，运行写出的所有内容都落在 `.e2e/` 之下。
[`output`](/reference/config#output) 选项或 `--output` 可以把它挪走；回放
缓存仍在 `cache.dir`；`command.log` 则是你配置的任意项目相对路径。

| 路径 | 内容 | 脱敏 |
| --- | --- | --- |
| `report.json` | 运行记录。错误、推理摘录与动作摘要都经过脱敏器。 | complete |
| `results/<test>/trace.md` | 链路页，由脱敏后的报告写出。 | complete |
| `results/.../*.png` | 截图。安全字段在截图返回或保存为产物之前先被遮挡。 | complete |
| `results/.../*.webm`, `*.mp4` | 视频，通过 `video` 或 `--video` 主动启用；`retain-on-failure` 只保留未通过的尝试。 | incomplete |
| `results/.../downloads/*` | 应用通过下载交付的文件。会话知晓机密值时文本类会被改写；其余按原样保留。 | complete 或 incomplete |
| `results/.../screen-at-failure.txt` | 失败时刻的脱敏树。 | complete |
| `ai-trace.json` | 每次模型调用，通过 `--ai-trace` 主动启用。提示是模型看到的脱敏后版本；内联图像字节以其大小替代。 | 与提示一致 |
| `sessions/<runId>/` | 加密的会话，清理时删除。 | encrypted |
| `videos/<session>/*.webm`, `*.mp4` | `e2e mcp` 会话用 `start_recording` 录制的视频，保留到你手动删除为止。从不交给 `artifacts.store`。 | none |
| `cache.dir`（默认 `.e2e/cache/`） | 回放缓存条目。不在 `output` 之下。 | 构造上不含机密 |
| `command.log` 所配置的路径 | 应用的 stdout 与 stderr，逐字原样。必须位于项目根之内。 | none |

`artifacts.store` 会在每个产物产生时收到其字节——经过下载脱敏之后，并带上
报告记录的 `redaction` 标签，因此 store 只会导出 runner 背书的内容。
`cache.store` 接收每一条录制的条目、供给每一条回放的条目；返回的内容在使
用前会再次校验。

## 出站连接

内置功能可能连接到：

- 每次 CLI 调用向 `eu.i.posthog.com` 发一次遥测请求，`e2e mcp` 服务的每个
  会话至多再加一次，除非你选择退出；见 [遥测](/telemetry)
- 每运行一次 `e2e feedback`，向 `eu.i.posthog.com` 发一次请求；见
  [反馈](/telemetry#反馈)
- 你配置的模型所用的提供者端点。确定式测试与完全回放的动作步骤不会调用模
  型。
- 对 runner 启动的应用的 `readyUrl` 做就绪探测
- 浏览器缺失时，下载一次 Playwright 浏览器
- 你在 `web({ connect })` 中指定的 DevTools 端点
- GitHub API，仅来自主动启用的 `@e2e-dev/github` 报告器
- Kernel API 及其托管浏览器，仅来自
  [`kernel()`](/integrations/kernel)
- Expo API 与模拟器上的 agent-device 守护进程，仅来自
  [`easSimulators()`](/integrations/eas)。它以 `EXPO_TOKEN` 认证，否则使用
  `~/.expo/state.json` 中的 eas-cli 登录态：在 CI runner 上，请设置
  `EXPO_TOKEN`，或把该登录态从 runner 的 home 目录排除出去
- 被测应用，以及该应用自己加载的任何东西

没有崩溃上报，也没有更新检查。`--ai-trace` 只写本地文件、不上传。你的测
试代码、插件和应用可以自行发起额外连接。

## MCP 与探索

`e2e mcp` 使用 stdio，动作获准机制与测试运行相同。默认同时允许四个打开的
会话（[`--max-sessions`](/reference/mcp)，1 到 16），并关闭空闲会话。

`e2e explore` 把每一条配置的凭据都提供给每个步骤。探索者看得到账户名和用
户名。密码保持为机密句柄，需要引擎支持敏感字段的填充；没有这种引擎时，探
索者会跳过用它们登录。只配置探索所需的账户。没有任何凭据时，探索者可能用
编造的测试凭据登录，以明文键入。
