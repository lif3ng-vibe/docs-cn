在 EAS 工作流中，`build` 作业负责产出模拟器 `.app` 或 `.apk`，然后由一个自定义作业下载构建产物、启动设备并运行套件。开始前请先读[移动端作业](/ci#移动端作业)，该节说明了每个作业在每个 CI 服务上需要什么。

<Note>
本页讲的是 EAS Workflows 这个 CI 服务。若要在 EAS 托管的模拟器和仿真器上运行测试，参见 [EAS Simulators](/integrations/eas)。
</Note>

## 构建配置档

添加一个无需凭据的构建配置档：

```json title="eas.json"
{
  "build": {
    "e2e": {
      "withoutCredentials": true,
      "ios": { "simulator": true },
      "android": { "buildType": "apk" }
    }
  }
}
```

## 工作流

iOS 作业运行在 macOS runner 上。Android 作业需要 `nested-virtualization` 的 Linux runner。只有这些 EAS 机器能运行仿真器。

```yaml title=".eas/workflows/e2e.yml" expandable
name: e2e

on:
  pull_request:
    branches: ['*']
  push:
    branches: [main]

defaults:
  tools:
    node: '22'

jobs:
  build_ios:
    type: build
    params:
      platform: ios
      profile: e2e

  build_android:
    type: build
    params:
      platform: android
      profile: e2e

  e2e_ios:
    needs: [build_ios]
    runs_on: macos-medium
    environment: preview
    env:
      CI: '1'
    steps:
      - uses: eas/checkout
      - uses: eas/install_node_modules
      - uses: eas/download_build
        id: download_build
        with:
          build_id: ${{ needs.build_ios.outputs.build_id }}
          extensions: [app]
      - name: Boot a simulator and install the app
        run: |
          UDID=$(xcrun simctl create e2e "iPhone 17" com.apple.CoreSimulator.SimRuntime.iOS-26-5)
          xcrun simctl bootstatus "$UDID" -b
          xcrun simctl install "$UDID" "${{ steps.download_build.outputs.artifact_path }}"
      - name: Run e2e
        run: npx e2e run --target ios --reporter list,junit
      - uses: eas/upload_artifact
        if: ${{ always() }}
        with:
          type: other
          name: e2e-ios
          path: .e2e

  e2e_android:
    needs: [build_android]
    runs_on: linux-medium-nested-virtualization
    environment: preview
    env:
      CI: '1'
    steps:
      - uses: eas/checkout
      - uses: eas/install_node_modules
      - uses: eas/download_build
        id: download_build
        with:
          build_id: ${{ needs.build_android.outputs.build_id }}
          extensions: [apk]
      - uses: eas/start_android_emulator
        with:
          system_image_package: system-images;android-35;google_apis;x86_64
      - name: Install the app
        run: adb install -r "${{ steps.download_build.outputs.artifact_path }}"
      - name: Run e2e
        run: npx e2e run --target android --reporter list,junit
      - uses: eas/upload_artifact
        if: ${{ always() }}
        with:
          type: other
          name: e2e-android
          path: .e2e
```

## 注意事项

- **机密**。把 `AI_GATEWAY_API_KEY`（或你的提供者的密钥）放在 secret 可见性的 [EAS 环境变量](https://docs.expo.dev/eas/environment-variables/)中。`environment:` 设置作业读取的 EAS 环境。请在每个作业上都设置它，因为自定义作业默认读取 `production`。凡是读取该环境的作业都能读到密钥，包括运行不可信拉取请求代码的作业。只把密钥交给受信任分支的构建。参见[移动端作业](/ci#移动端作业)。
- **CI 模式**。`CI: '1'` 开启 [CI 默认值](/ci#ci-模式的变化)，在本来不设置 `CI` 的 runner 上也能生效。
- **仿真器函数**。`eas/start_android_emulator` 是一个 EAS build function，其文档在 [custom builds](https://docs.expo.dev/custom-builds/schema/) 下，不在 Workflows 语法页。它会用 `sdkmanager` 下载你指定的系统镜像。iOS 作业用 `xcrun simctl` 创建模拟器以固定运行时。
- **更少构建**。使用带 `get-build` 和 `repack` 的 `fingerprint` 作业可以复用上一次的原生构建，只打包 JavaScript。[agent-device EAS 模板](https://github.com/callstackincubator/eas-agent-device/blob/main/.eas/workflows/agent-qa-mobile.yml)在两个平台上都是这样做的。

EAS Workflows 还有内置的 `maestro` 作业类型，它会启动设备并运行 Maestro flows。对 e2e，请像上面那样使用自定义作业。
