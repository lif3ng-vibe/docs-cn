把 Maestro 命令翻译成 await 的 TypeScript 调用。精确的交互保留为定位器调用，或者给智能体一个可覆盖多条交互的目标。两个 runner 可以共用同一台模拟器或仿真器。

按[移动端指南](/mobile)配置 target，按[快速上手](/quickstart)配置模型，然后一次迁移一个流程。本页把每条 Maestro 命令映射到对应的 e2e 命令，并说明它是否存在。细节在参考页：[screen](/reference/screen)、[expect](/reference/expect)、[test](/reference/test) 以及[移动引擎](/reference/mobile)。

| --- | --- | --- |
| 每条流程顶部的 `appId` | target 上的 `app: { bundleId: 'com.example.app' }`，即 `app.open()` 启动的 app | 更名 |
| 每条流程各不相同的 `appId` | 测试内用 `device.openApp(id)`，或为每个 app 建独立的配置和运行；每条测试都会在每个被选中的 target 上运行 | 更名 |

## 改写前后的流程

```yaml title="Maestro"
appId: com.example.app
---
- launchApp:
    clearState: true
- tapOn: "Get started"
- tapOn:
    id: "email"
- inputText: "ada@example.test"
- tapOn: "Continue"
- assertVisible: "Check your inbox"
- scrollUntilVisible:
    element: "Resend"
- assertVisible:
    id: "resend"
```

```ts title="e2e"
import { test } from '@e2e-dev/mobile';
import { expect } from 'e2e';

test('asks for the email', async ({ app, agent, screen }) => {
  await app.clearState();
  await agent.act('get started with the email {email}', { params: { email: 'ada@example.test' } });
  await expect(screen.getByText('Check your inbox')).toBeVisible();
  await screen.scrollUntilVisible(screen.getByTestId('resend'));
  await expect(screen.getByTestId('resend')).toBeVisible();
});
```

上手引导交给智能体。定位器断言检查确认信息和 Resend 控件。流程也可以完全确定化：每个 `tapOn` 都有一行对应的 `screen.getBy*(...).tap()`。

## 命令对照表

对 `screen`、`app`、`agent` 与 `expect(locator)` 的调用在每个 target 上运行，浏览器也包含在内。对 `device` 的调用只在设备上运行：用到它的测试要声明 `requires: ['device']`，其他 target 会跳过它。状态列取值为 `same`（相同）、`renamed`（更名）、`device only`（仅 device）、`by design`（有意为之，见[选择器](#选择器)与[有意为之](#有意为之)）或 `missing`（暂缺），并给出今天的对策。

### App 生命周期

| Maestro | e2e | 状态 |
| --- | --- | --- |
| `launchApp` | `app.open()`，全新启动 target 的 `app.bundleId`；没有任何东西会自行启动 | 更名 |
| `launchApp: { clearState: true }`, `clearState` | `app.clearState()` | 更名 |
| `launchApp: { stopApp: false }` | 不带 `relaunch` 的 `device.openApp(id)` | 仅 device |
| `launchApp: { arguments }` | target 上的 `app.launchArguments`，或单次启动用 `device.openApp(app, { relaunch: true, launchArguments })`；是一串字符串，不是映射表 | 更名 |
| `launchApp: { permissions }` | target 上的 `app.permissions`，每次全新启动前都会设置，或单次授予用 `device.openApp(app, { relaunch: true, permissions })`；`grant`、`deny`、`reset` 对应 `allow`、`deny`、`unset`；没有 `all`，未点名的权限一律不授予 | 更名 |
| `stopApp`, `killApp` | `device.closeApp()` | 仅 device |
| 先 `stopApp` 再 `launchApp` | `app.restart()` | 更名 |
| `clearKeychain` | `device.clearKeychain()`，清的是整个模拟器的钥匙串；仅 iOS | 更名 |
| `openLink` | `device.openLink(url, { app })`；iOS 上链接在 `app` 中打开，默认为固定的那个 app | 更名 |
| `addMedia` | 暂无 | 暂缺 |
| `back` | `app.back()`，或 `device.back()` | 更名 |

| Maestro | e2e | 状态 |
| --- | --- | --- |
| `tapOn: "Text"` | `screen.getByText('Text').tap()`；精确匹配，见[选择器](#选择器) | 更名 |
| `tapOn: { id: x }` | `screen.getByTestId('x').tap()` | 更名 |
| `tapOn: { text, index: 2 }` | `.nth(2)` | 更名 |
| `tapOn: { below: "Email" }`、`above`、`leftOf`、`rightOf`、`containsDescendants` | 无对应物，见[选择器](#选择器) | 有意为之 |
| `tapOn: { point: "x,y" }` | `screen.tapAt({ x, y })`；节点内部用 `.tap({ position: { x, y } })` | 更名 |
| `retryTapIfNoChange`, `waitToSettleTimeoutMs` | `mobile({ settle, transition })`，对整个引擎生效；没有每次调用的旋钮 | 更名 |
| `doubleTapOn`, `longPressOn` | `.doubleTap()`, `.longPress({ duration })` | 更名 |

| `pressKey: Home`, `back` | `device.home()`, `device.back()` | 仅 device |

## 选择器

Maestro 的选择器简写无法一一对应移植。五处差异占了大多数改动。

- Maestro 里文本和 id 都是正则，因此 `tapOn: ".*Save.*"` 能匹配任何含 Save 的文本。`getByText` 是精确匹配。要匹配模式就写 `getByText(/Save/)`；要大小写不敏感的子串就写 `{ exact: false }`。`getByTestId` 匹配字符串时按完整 id 匹配；要按模式就写 `getByTestId(/^row-/)`。
- `index: 2` 即 `.nth(2)`。多个节点匹配而未给 index 时，Maestro 会静默点第一个；e2e 报 `LOCATOR_AMBIGUOUS` 失败。当第一个匹配正是你要的，写 `.first()`。
- `optional: true` 和 `runFlow: { when: { visible } }` 变成 `if (await locator.isVisible())`。`isVisible()` 是一次读取：零个匹配返回 `false`，多个匹配报 `LOCATOR_AMBIGUOUS`。若可能存在隐藏的孪生节点，在查询上加 `{ visible: true }` 或在定位器上加 `.first()`。
- `below`、`above`、`leftOf`、`rightOf` 与 `containsDescendants` 没有对应移植。e2e 有 `filter({ has, hasText })` 和链式查询来表达结构，但没有任何空间关系表述；锚定在布局上的选择器在下一次改版就会失效。没有 label 的输入框，可以用 `getByLabel` 锚定、给它一个 test id，或把这一步交给一个目标：`agent.act('enter {email} in the email field', { params })` 会读屏幕并找到那个字段。
- `env:` 和 `${VAR}` 变成模块常量，以及目标内的 `params`：`agent.act('sign in as {email}', { params: { email } })`。`MAESTRO_*` 变量变成配置里的 `process.env`。密码或 token 放到 `credentials` 或 `secrets` 下，模型永远看不到值。

## 有意为之

以下差异是有意为之，并将保持不变。

- 要么恰好一个匹配，要么报 `LOCATOR_AMBIGUOUS`，见[选择器](#选择器)。
- 密码是模型永远看不到的 `Secret`，见[登录](/authentication)。
- 每个 `device` 调用都是一步。它以 `device.<method>` 的形式写进报告，因此失败时会展示确切的调用，无需 `label`。
- 测试中没有 agent-device 客户端。`device.locator` 覆盖平台专属选择器；其余一切经由 `screen`、`app`、`device` 与智能体，因此都会被记录并脱敏。
- 设备上没有 `test.setup` 或 `session:`，见[与 web 的差异](/mobile#与-web-的差异)。
