文档

从命令行驱动任何应用

CLI-Hub 是面向 Agent 原生 CLI 的注册表与安装器。按名称安装工具、启动它；当一项任务横跨多个工具时，再引入基于能力的工作流矩阵（Workflow Matrix）。每条命令同时为人和 AI Agent 设计，带 --json 输出与成文的退出码契约。

开始上手

安装

CLI-Hub 以 cli-anything-hub 包发布，会装上 cli-hub 命令。需要 Python 3.10 或更高版本。

$ pip install cli-anything-hub
$ cli-hub --version

这一条命令就是下面一切的入口——浏览目录、安装工具、使用矩阵。你也可以把元技能（meta-skill）SKILL.md交给 Agent，让它自主发现并安装 CLI。

两分钟速览

快速上手

找到一个工具、装上、跑起来——或者把整条工作流收窄到你的任务真正需要的那部分。

# 浏览并安装单个 CLI
$ cli-hub search diagram
$ cli-hub install drawio
$ cli-hub launch drawio --help

# 跨所有矩阵询问某项任务需要什么
$ cli-hub can "transcribe audio"

# 检查一个矩阵，然后只安装你需要的能力
$ cli-hub matrix preflight video-creation --summary
$ cli-hub matrix install video-creation --capability text.transcribe

提示。几乎所有命令都可以加 --json 获得机器可读输出，并结合退出码（见退出码）让脚本和 Agent 无需解析文本即可做出反应。

目录

目录命令

目录是所有单个 CLI 的扁平列表——CLI-Anything 发布的第一方 harness 工具，加上精选的公开工具。这些命令负责发现、安装和运行它们。

cli-hub list
列出全部可用 CLI，按分类分组，并带已安装标记。
-c, --category <name>按单个分类过滤。
-s, --source <harness|public|npm|all>按来源过滤（npm 是 public 的别名）。
--json机器可读输出。
cli-hub search <query>
按名称、描述或分类搜索 CLI。
--json机器可读输出。
cli-hub info <name>
显示单个 CLI 的完整详情——描述、分类、来源、版本、依赖、入口点、主页与贡献者。
cli-hub install <name>
从注册表安装一个 CLI。harness 工具经 pip 安装；公开工具按其声明的策略安装（npm / uv / 命令）。
cli-hub launch <name> [args…]
启动已安装的 CLI，名称之后的每个参数都原样透传给它。
cli-hub update <name>  ·  cli-hub uninstall <name>
把已安装的 CLI 更新到最新版本，或将其移除。
cli-hub previews <inspect|html|watch|open>
检查、渲染、监视或打开由 harness CLI 产生的预览包与实时会话（如 FreeCAD / Blender 预览循环）。watch 和 open 会伺服一个实时自动刷新的页面。
核心概念

工作流矩阵

一个真实任务——“给视频配字幕”——很少只对应一个工具。矩阵把一个领域打包成若干能力（capability）（Agent 调用的动词），每种能力再配若干提供方（provider）（兑现它的具体途径）。你按能力选路径，而不是背下十四个包里该装哪个。

Matrix  ── 一个领域的能力打包（如 video-creation）
│
├─ capabilities[]   Agent 可调用的动词——visual.generate、text.transcribe …
│   └─ providers[]   兑现某项能力的具体途径，每个都带类型标注
│
├─ recipes[]        面向特定任务的具名能力子集
├─ clis[]           matrix install 实际安装的扁平列表
└─ SKILL.md         提供方选择手册，安装时渲染到本地

提供方类型

每个提供方都声明一个 kind，告诉你它如何获取、要付出什么：

harness-cli

可用 cli-hub 安装的第一方 CLI；每个都自带 SKILL.md。

public-cli

经 brew / npm / pip 安装的第三方 CLI。

python

直接使用的 Python 库（免费的兜底选项）。

native

系统上的原生二进制，如 ffmpeg。

api

云端 API——需要密钥与用户明确同意。

agent-skill

Agent 自行安装的外部 Agent Skill；不计入预检。

预检只报告，不替你选。注册表顺序是文档顺序，不是排名。preflight 告诉你有什么可用；Agent 按矩阵 SKILL.md 中的规则挑选提供方。未配置密钥且未经用户同意，付费 API 绝不会被使用。

矩阵命令家族

矩阵命令

所有矩阵操作都在 cli-hub matrix 之下，另有一个顶层的 cli-hub can 快捷方式用于能力搜索。每个子命令都支持 --json。

发现

cli-hub can <query>
跨所有矩阵搜索某项任务的能力，并给出各提供方在本机的可用性。有命中退出 0，无命中退出 1。
--json以 JSON 输出能力匹配。
$ cli-hub can "download bilibili video"
  video.download  (video-creation)
    available here: yt-dlp · missing: BBDown, lux
    next: cli-hub matrix preflight video-creation -c video.download
cli-hub matrix list
列出全部矩阵及其描述，以及每个矩阵有多少成员 CLI 已安装。
--json机器可读输出。
cli-hub matrix search <query>
按名称、能力、提供方、配方或缺口搜索矩阵——并给出匹配归因（哪个能力命中、命中在哪个字段）。
--json包含 matched_capabilities[]。
cli-hub matrix info <name>
单个矩阵的完整详情——成员与状态、带提供方计数的能力、配方以及已知缺口。
--json机器可读输出。
cli-hub matrix recipes
列出所有矩阵里面向任务的配方，每个配方附其能力与一条可直接运行的预检命令。
--search <text>按 id、描述或能力过滤。
--json机器可读输出。

预检

预检是整个流程的支点：它报告在你的当前环境里哪些提供方真正可用，让你（或 Agent）在动手之前决定要装什么。

cli-hub matrix preflight <name>
逐能力检查提供方可用性。当每个（过滤后的）能力都至少有一个可用提供方时退出 0，存在缺口时退出 3。
-c, --capability <id>只检查一个能力。
--recipe <id>只检查某配方用到的能力。
--offline只考虑可离线使用的提供方。
--fix-hints在每个缺失的提供方下方打印安装命令。
--summary只打印两行摘要。
--json机器可读输出。
# 用覆盖率给动作上闸——只有配方可以完全满足时才继续
$ cli-hub matrix preflight video-creation --recipe screencast-tutorial --json \
    || echo "capability gap — read the missing list before installing"

安装

cli-hub matrix install <name>
安装矩阵的 CLI。不带范围参数时安装全部成员 CLI；下方各范围参数只安装子集。安装是幂等的——已安装的工具会被跳过。
--dry-run零副作用地展示安装计划。
-c, --capability <id>只安装一个能力背后的 CLI。
--recipe <id>只安装某配方用到的 CLI。
--only <a,b,c>安装矩阵 CLI 中具名的逗号分隔子集。
--resume只重试上次失败的 CLI。
--skill-only只渲染矩阵技能（SKILL.md + 参考文档 + 脚本），不安装 CLI。
--json机器可读的计划或结果。
$ cli-hub matrix install video-creation --dry-run
  Plan: video-creation
  skip (already installed): audacity, gimp, kdenlive
  install via pip:          inkscape, krita, obs-studio, …
  not managed here:         python libs, native binaries, cloud APIs — see preflight

范围参数（--capability、--recipe、--only）互斥。每个矩阵的安装状态记录在 ~/.cli-hub/matrix_state.json，这正是 --resume 的依据。

修复

cli-hub matrix doctor <name>
审计矩阵 CLI 的安装完整性——凡是记录为已安装却从 PATH 消失的都会被标出，并给出修复建议。（预检问的是「某个提供方可不可用？」；doctor 问的是「我装的东西还健康吗？」）
--json机器可读审计。
契约

退出码

矩阵命令家族遵循统一的退出码契约，脚本和 Agent 无需读文本即可分支。目录命令使用更简单的 0 / 1 成败约定。

0
成功
所有检查通过，或所有能力缺口均已覆盖。
1
失败
矩阵或能力未找到；什么都没装成。
2
用法错误
使用了互斥参数，或能力 / 配方 / --only 名称非法。
3
部分完成
存在能力缺口，或部分 CLI 安装成功而其余失败或损坏。
面向 Agent 与脚本

JSON 与自动化

CLI-Hub 从设计上就同等地面向 AI Agent 与人。两个设计决定让它变得可靠：

  • 处处结构化输出。目录命令与整个矩阵家族都接受 --json——包括 matrix install，其 JSON 携带完整的计划或结果。无需抓屏解析。
  • 退出码即控制流。把上面的契约与 && / || 组合起来给步骤上闸——比如先预检一个配方，返回 0 才安装。

安装矩阵之后，它的 SKILL.md 会渲染到你的机器上。请读一读：里面有提供方选择规则、面向付费升级的「建议用户」模板和参考资料——这些是注册表本身编码不了的判断力，Agent 需要它们。

元技能 SKILL.md 内含工作流矩阵章节，本站也发布 llms.txt 与机器可读注册表——把这些入口交给 Agent，它就能从冷启动一路自主走到「预检 → 按能力安装 → JSON 结果」。

参考

注册表与配置

CLI-Hub 读取三个已发布的注册表，并缓存在本地 ~/.cli-hub/ 下（一小时 TTL）：

  • registry.json——第一方 harness CLI。
  • public_registry.json——精选公开 CLI。
  • matrix_registry.json——矩阵：能力 × 提供方，带预检契约。

它们由项目的 GitHub Pages 域名伺服（例如 …/CLI-Anything/matrix_registry.json）。本地状态与缓存放在一起：installed.json 跟踪已安装的 CLI；matrix_state.json 记录每个矩阵的安装结果，供 --resume 使用。

环境变量

  • CLI_HUB_NO_ANALYTICS=1——退出匿名的即发即忘使用统计。
  • CLI-Hub 会自动检测自己是否被 AI Agent 调用（Claude Code、Codex、Cursor 等），仅用于统计分桶。
  • 输出被管道接管或非 TTY 时自动关闭着色，保持日志与解析器干净。

统计绝不阻塞你的工作流，也可以彻底关闭。矩阵是这里真正的差异点——从矩阵章节开始，或运行 cli-hub matrix list 看看有什么可用。
