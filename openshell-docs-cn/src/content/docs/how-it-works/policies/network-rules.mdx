网络规则控制沙箱中每个二进制可以访问哪些目的地，以及可以发送哪些请求。它们构成典型策略的大部分。本页解释 OpenShell 如何评估网络规则，然后给出可改用于常见服务与协议的示例规则。

## 网络规则如何工作

OpenShell 用策略的 `network_policies` 小节检查沙箱发出的每一条出站连接，没有规则允许的连接一律拒绝。

### 规则结构

`network_policies` 中的每个条目是一条规则。条目的键即规则名，规则包含两个列表：`endpoints` 列出规则允许的目的地，`binaries` 列出可以连接这些目的地的可执行文件。一条规则允许每个列出的二进制访问每个列出的端点。

例如，这条规则名为 `example_api`，列出两个二进制与两个端点：

```yaml
network_policies:
  example_api:
    endpoints:
      - host: api.example.com
        port: 443
      - host: uploads.example.com
        port: 443
    binaries:
      - path: /usr/bin/curl
      - path: /usr/bin/wget
```

该规则允许以下四种组合：

| 二进制 | 端点 |
|---|---|
| `/usr/bin/curl` | `api.example.com:443` |
| `/usr/bin/curl` | `uploads.example.com:443` |
| `/usr/bin/wget` | `api.example.com:443` |
| `/usr/bin/wget` | `uploads.example.com:443` |

如果 `wget` 只应访问 `api.example.com`，把该二进制与端点放进单独的规则。

### 二进制匹配

编写网络规则时，列出打开连接的可执行文件的路径。这不总是你运行的命令。例如 `pip` 是 Python 脚本，因此连接 PyPI 的进程是 Python 解释器，`pip install` 的规则必须列出解释器而不是 `/usr/bin/pip`。

OpenShell 按内核报告的可执行文件真实路径识别每个进程，因此请列出真实路径而非符号链接。例如在 Ubuntu 24.04 上，`/usr/bin/python3` 是指向 `/usr/bin/python3.12` 的符号链接。要找真实路径，在沙箱内对该路径运行 `readlink -f`。OpenShell 拒绝连接时，沙箱日志会显示它识别的路径。[允许 PyPI 下载](#允许-pypi-下载)与[允许 npm 安装](#允许-npm-安装)给出了列出解释器的规则。

规则也适用于列出的二进制启动的进程。例如规则列出了某个智能体的可执行文件时，该智能体启动的工具也能使用这条规则。`binaries` 列表为空的规则不匹配任何二进制，不授予任何访问。

OpenShell 在每个可执行文件首次参与连接时记录其哈希，该路径上的文件发生变化后拒绝后续连接。

### 连接与请求检查

OpenShell 分两个阶段检查网络流量：

1. 二进制打开连接时，OpenShell 用你的规则检查目的地主机、端口与二进制。没有规则匹配时，OpenShell 拒绝该连接。
2. 匹配的端点设置了请求协议（例如 `rest`）时，OpenShell 还会读取该连接上发送的每条请求，并按端点的请求规则检查。例如 `protocol: rest` 时，规则可以允许对某个 API 的 `GET` 请求，同时阻断 `POST` 与 `DELETE` 请求。

第二阶段称为请求检查（request inspection），使用它的端点是被检查端点。`protocol` 字段选择 OpenShell 检查的内容：

| `protocol` | OpenShell 在每条请求中检查的内容 | 示例 |
|---|---|---|
| `rest` | HTTP 方法、路径与查询参数。 | [REST](#允许只读-api-访问) |
| `websocket` | WebSocket 升级请求与客户端发送的每条文本消息。 | [WebSocket](#允许-websocket-消息) |
| `graphql` | GraphQL 操作类型、操作名与顶层字段。 | [GraphQL](#允许-graphql-操作) |
| `mcp` | MCP 方法与工具名。 | [MCP](#允许-mcp-工具) |
| `json-rpc` | JSON-RPC 方法名。 | [JSON-RPC rules](/how-it-works/policies/schema#json-rpc-规则) |
| `tcp` | 无请求规则。用于说 HTTP 之外协议的客户端，例如数据库。 | [Native TCP](#允许原生-tcp) |
| 省略 | 无请求规则。 | -- |

省略 `protocol` 时，OpenShell 允许任何方法与路径。除非端点设置 `tls: skip`，它仍会终结 TLS，并拒绝发往其他主机或路径畸形的 HTTP 请求，例如包含 `%2F` 的路径。既非 TLS 也非 HTTP 的流量原样转发、不做检查。服务器先说话的协议（例如 SMTP）请设置 `tls: skip`。

风险不只取决于目的地、还取决于请求本身时，使用被检查端点，例如允许对 API 读取但不允许写入。

### 强制模式

被检查端点上的 `enforcement` 字段决定请求违反端点请求规则时的处理：

- `enforce` 阻断请求。HTTP 客户端收到 OpenShell 的 `policy_denied` 响应。
- `audit` 放行请求并记录违规。这是默认值。

审计模式只作用于端点的允许与拒绝规则。无法安全处理的请求 OpenShell 仍会拒绝，例如畸形请求与发往其他主机的请求。

用 `audit` 在强制之前查看新规则会阻断什么。以 `enforcement: audit` 应用规则，运行工作负载，然后在沙箱日志中查找违规事件：

```shell
openshell logs my-sandbox --since 5m --source sandbox
```

不要用 `--level warn` 过滤该日志，它会隐藏策略事件。日志只显示你预期的违规时，把端点切换为 `enforce`，因为审计模式的端点不阻断违反其规则的请求。

### 重叠规则

网络规则不是有序的防火墙清单。多条规则可以匹配同一连接或请求，每条匹配的规则都会贡献它允许的访问。匹配的拒绝规则优先于任何允许规则，与两者在文件中的位置无关。一条匹配规则检查请求而另一条不检查时，OpenShell 检查该连接，没有 `protocol` 的规则不添加请求访问。可能匹配相同主机与端口的端点还必须在 `tls` 与 `allowed_ips` 等设置上一致，否则 OpenShell 拒绝该策略。

例如，一条规则在某主机上允许 `GET /repos/**`，另一条针对相同主机、端口与二进制的规则拒绝 `GET /repos/private/**`，OpenShell 会拒绝 `/repos/private/` 之下的请求。收紧访问时，请检查每条可能放行该请求的规则，包括提供商贡献的规则。[允许特定方法与路径](#允许特定方法与路径)给出了拒绝规则的示例。

### 网络访问与凭据

允许流量到达某目的地的网络规则，并不允许 OpenShell 向那里发送提供商凭据。OpenShell 只向提供商配置档案或显式凭据绑定允许的目的地提供该提供商的凭据。请求未通过凭据检查时，请修正提供商绑定，而不是放宽网络规则。配置档案端点参见[提供商配置档案](/how-it-works/providers/profiles)，显式绑定参见[凭据字段](/how-it-works/policies/schema#凭据字段)。

## 示例

以下规则覆盖常见服务与协议。把示例中的主机、路径与二进制替换为你自己的取值，并确保沙箱内存在客户端可执行文件。

一条 `openshell policy update` 命令能创建的规则，示例直接给出命令。否则，把 YAML 添加到完整策略文件的 `network_policies` 小节下，用 `openshell policy set` 应用，参见[整体替换策略](/how-it-works/policies/manage-policies#整体替换策略)。应用规则之后，测试流量前先[验证变更](/how-it-works/policies/manage-policies#验证变更)。

### 允许只读 API 访问

二进制需要读取 HTTP API 但不得做任何更改时使用这条规则。`read-only` 预设允许 `GET`、`HEAD` 与 `OPTIONS`。

<Tabs>
<TabItem label="CLI">

```shell
openshell policy update my-sandbox \
  --rule-name github_readonly \
  --binary /usr/bin/curl \
  --add-endpoint api.github.com:443:read-only:rest:enforce \
  --wait
```

</TabItem>
<TabItem label="YAML">

```yaml
github_readonly:
  endpoints:
    - host: api.github.com
      port: 443
      protocol: rest
      enforcement: enforce
      access: read-only
  binaries:
    - path: /usr/bin/curl
```

</TabItem>
</Tabs>

验证一条被放行的 `GET` 与一条被拒绝的 `POST`：

```shell
openshell sandbox exec -n my-sandbox --no-login-shell -- \
  /usr/bin/curl --silent --show-error --fail \
  https://api.github.com/zen
openshell sandbox exec -n my-sandbox --no-login-shell -- \
  /usr/bin/curl --silent --show-error \
  --request POST https://api.github.com/zen
```

`POST` 应返回 OpenShell 的 `policy_denied` 响应。`read-only` 是 HTTP 方法预设，不保证上游 `GET` 没有副作用。

### 允许特定方法与路径

二进制需要特定方法或路径时，用显式 `rules` 代替访问预设，并用 `deny_rules` 阻断其中的例外。这条规则让 GitHub CLI 对单个仓库发起任意 API 请求，但对 webhooks 的请求除外，后者可能把仓库事件发送到另一个目的地。替换 `<org>` 与 `<repo>`，只保留你的镜像使用的可执行路径：

```yaml
github_repository_api:
  endpoints:
    - host: api.github.com
      port: 443
      protocol: rest
      enforcement: enforce
      rules:
        - allow:
            method: "*"
            path: "/repos/<org>/<repo>/**"
      deny_rules:
        - method: "*"
          path: "/repos/<org>/<repo>/hooks"
        - method: "*"
          path: "/repos/<org>/<repo>/hooks/**"
  binaries:
    - path: /usr/bin/gh
    - path: /usr/local/bin/gh
```

在请求路径中，`*` 匹配单个路径段之内，整体占一个段的 `**` 跨段匹配，因此 `/repos/<org>/<repo>/**` 覆盖仓库之下的每个路径，但不包括 `/repos/<org>/<repo>` 本身。出于同样的原因，拒绝规则把 webhooks 路径与其下所有内容分开列出。允许规则授予仓库路径下所有 HTTP 方法，包括写入，因此智能体只需要特定操作时请收窄它。它不覆盖 Git 传输或 GraphQL 请求。不使用完整策略文件、向既有规则添加拒绝规则时，用 `openshell policy update` 的 `--add-deny`，参见[添加或移除网络访问](/how-it-works/policies/manage-policies#添加或移除网络访问)。

应用规则时挂接 GitHub 提供商。其配置档案必须允许在 `api.github.com` 上使用凭据，且令牌必须授权这些仓库操作。验证 `gh api repos/<org>/<repo>/issues` 成功、`gh api repos/<org>/<repo>/hooks` 返回 OpenShell 拒绝。完整的 Git push 示例参见[向沙箱中的智能体授予 GitHub push 访问](/tutorials/github-push-access)。

### 允许 PyPI 下载

包管理器用 `GET` 请求下载包，因此只读 REST 规则允许安装而阻断上传。`pip` 是 Python 脚本，因此规则列出 Python 解释器的真实路径，沙箱中的任何 Python 程序都能使用它。这条规则让 `pip` 与 `uv` 从 PyPI 安装包：

```yaml
pypi:
  endpoints:
    - host: pypi.org
      port: 443
      protocol: rest
      enforcement: enforce
      access: read-only
    - host: files.pythonhosted.org
      port: 443
      protocol: rest
      enforcement: enforce
      access: read-only
  binaries:
    - path: /usr/bin/python3.12
    - path: /usr/local/bin/uv
```

`/usr/bin/python3.12` 是 Ubuntu 24.04 上的解释器。要找你的解释器，在沙箱内运行 `readlink -f /usr/bin/python3`。镜像使用其他解释器（例如 uv 管理的 Python）时，列出其真实路径或匹配它的 glob，例如 `/sandbox/.uv/python/*/bin/python3*`。私有包索引请把主机替换为你索引的主机。

安装了 `pip` 的沙箱，验证下载成功：

```shell
openshell sandbox exec -n my-sandbox --no-login-shell -- \
  /usr/bin/python3 -m pip download --no-deps --dest /tmp/pypi-check requests
```

### 允许 npm 安装

与 `pip` 一样，`npm` 是脚本，因此规则列出 Node.js 解释器。这条规则让 `npm` 从公共 npm 镜像仓库安装包。它列出 `/usr/bin/node`，但官方 Node.js 镜像把 `node` 装在 `/usr/local/bin/node`，请按你的镜像调整路径：

```yaml
npm_registry:
  endpoints:
    - host: registry.npmjs.org
      port: 443
      protocol: rest
      enforcement: enforce
      access: read-only
      allow_encoded_slash: true
  binaries:
    - path: /usr/bin/node
```

npm 请求范围包（scoped package，例如 `@types/node`）时在路径中带编码斜杠。除非端点设置 `allow_encoded_slash: true`，OpenShell 拒绝请求路径中的 `%2F`。npm 还会以 `POST` 请求发送安全审计，只读预设会拒绝它。运行 `npm install --no-audit`，或把 `access: read-only` 换成同时允许审计 `POST` 请求的显式规则。端点不能同时组合 `access` 与 `rules`。

验证范围包查询成功：

```shell
openshell sandbox exec -n my-sandbox --no-login-shell -- \
  /usr/bin/npm view @types/node version
```

### 限制目的地地址

为防止服务器端请求伪造（SSRF），OpenShell 默认阻断到私网地址的连接。精确主机名的端点仍可访问其主机名解析到的私网地址，除非该端点来自已批准的[策略顾问](/how-it-works/policies/advisor)提案。网络策略绝不授权目的地为回环、链路本地或未指定地址的出站端点，包括云元数据地址 `169.254.169.254`。该限制不适用于沙箱本地的回环连接：工作负载可以访问同一沙箱中监听在 `127.0.0.1` 上的服务。

用 `allowed_ips` 限制端点可访问的地址，或让 `*.internal.example` 这类通配符主机访问私网地址。这条规则只允许对内部 API 在 `10.20.0.0/16` 内地址上的只读访问：

<Tabs>
<TabItem label="CLI">

```shell
openshell policy update my-sandbox \
  --rule-name internal_api \
  --binary /usr/bin/curl \
  --add-endpoint 'api.internal.example:443:read-only:rest:enforce:allowed-ip=10.20.0.0/16' \
  --wait
```

</TabItem>
<TabItem label="YAML">

```yaml
internal_api:
  endpoints:
    - host: api.internal.example
      port: 443
      protocol: rest
      enforcement: enforce
      access: read-only
      allowed_ips:
        - 10.20.0.0/16
  binaries:
    - path: /usr/bin/curl
```

</TabItem>
</Tabs>

端点设置 `allowed_ips` 后，其主机名解析到的每个地址（包括公共地址）都必须落在该列表内。固定地址之前请考虑 DNS 轮换与服务故障转移。共享同一主机与端口的所有端点必须使用相同的 `allowed_ips` 列表。

验证对该服务的请求成功。被拒绝时，沙箱日志会显示解析到的地址与原因。地址变化时请同时复查主机名与地址，而不是扩大范围。

### 允许 WebSocket 消息

用 `protocol: websocket` 控制 WebSocket 连接与客户端在其上发送的消息。该模板需要 `/usr/bin/node` 与一个你控制的 WebSocket 服务。它允许 `/v1/realtime` 升级及客户端在该升级路径上的文本消息，同时拒绝 `/v1/admin/**`：

```yaml
realtime:
  endpoints:
    - host: realtime.example.com
      port: 443
      protocol: websocket
      enforcement: enforce
      rules:
        - allow:
            method: GET
            path: /v1/realtime
        - allow:
            method: WEBSOCKET_TEXT
            path: /v1/realtime
      deny_rules:
        - method: "*"
          path: /v1/admin/**
  binaries:
    - path: /usr/bin/node
```

用你的 Node 客户端测试 `/v1/realtime` 上的成功升级与文本消息，以及 `/v1/admin/**` 上被拒绝的升级或消息。`WEBSOCKET_TEXT` 规则上的路径是最初的升级路径，不是文本帧内容。

OpenShell 检查完整的客户端文本消息，不检查二进制帧或来自服务器的消息。端点承载提供商凭据时，客户端发送二进制帧会让 OpenShell 以关闭码 `1008` 关闭连接，因为它无法检查该帧是否携带凭据。仍要转发二进制帧请设置 `allow_uninspected_credentials: true`。仅当客户端文本消息包含必须解析的 OpenShell 凭据占位符时才设置 `websocket_credential_rewrite: true`。

新网络规则生效时，OpenShell 关闭已打开的 WebSocket 连接，客户端必须重新连接。客户端可能收到关闭码 `1012`，或连接在没有关闭帧的情况下断开。

### 允许 GraphQL 操作

用 `protocol: graphql` 允许或拒绝 GraphQL 操作。GitHub 等 API 在同一主机上同时提供 REST 与 GraphQL。REST 规则把每条 GraphQL 请求都看作 `POST /graphql`，无法区分查询与变更。在一条规则中为每个 API 给出各自的端点，并用端点的 `path` 字段把 `/graphql` 请求导向 GraphQL 规则。这条规则允许只读 REST 请求、GraphQL 查询与 `createIssue` 变更：

```yaml
github_api:
  endpoints:
    - host: api.github.com
      port: 443
      protocol: rest
      enforcement: enforce
      access: read-only
    - host: api.github.com
      port: 443
      path: /graphql
      protocol: graphql
      enforcement: enforce
      rules:
        - allow:
            operation_type: query
        - allow:
            operation_type: mutation
            fields: [createIssue]
  binaries:
    - path: /usr/bin/gh
```

OpenShell 选择 `path` 与请求匹配最具体的端点，因此发往 `/graphql` 的请求使用 GraphQL 规则，所有其他路径使用 REST 规则。没有 `path` 的端点匹配所有路径。共享主机与端口的端点必须在 `tls` 与 `allowed_ips` 上一致。

对允许规则，操作中的每个顶层字段都必须匹配。畸形或不允许的操作会拒绝整个批量请求。GraphQL 字段名因应用而异，依赖之前请对照该服务的 schema 审查。拒绝规则、持久化查询与 WebSocket 上的 GraphQL 参见 [GraphQL 规则](/how-it-works/policies/schema#graphql-规则)。

`enforce` 与 `audit` 模式下，GraphQL 端点都以 `403 Forbidden` 拒绝携带 `Upgrade` 头部的请求。WebSocket 上的 GraphQL 请在另一个路径或端口上用单独的 `protocol: websocket` 端点提供，并配 GraphQL 操作规则。同一主机与端口上的一个路径只能使用两种协议之一。

挂接 GitHub 提供商后，用 `gh api zen` 验证 REST 读取，用 `gh api graphql -f query='{ viewer { login } }'` 验证查询，然后确认 `createIssue` 之外的变更返回 OpenShell 拒绝。

### 允许 MCP 工具

`protocol: mcp` 用于沙箱到服务器的 MCP Streamable HTTP 请求。该模板需要运行在 `/usr/bin/python3.12` Python 解释器上的 MCP 客户端，以及一个你控制的 Streamable HTTP 服务器。它允许初始化、工具发现与 `read_status`，同时拒绝 `delete_resource`：

```yaml
mcp_server:
  endpoints:
    - host: mcp.example.com
      port: 443
      path: /mcp
      protocol: mcp
      enforcement: enforce
      rules:
        - allow:
            method: initialize
        - allow:
            method: notifications/initialized
        - allow:
            method: tools/list
        - allow:
            method: tools/call
            tool: read_status
      deny_rules:
        - method: tools/call
          tool: delete_resource
  binaries:
    - path: /usr/bin/python3.12
```

先验证初始化与 `read_status`，再确认 `delete_resource` 返回策略拒绝。不支持工具参数匹配，被允许的工具可以接收服务器接受的任意参数。

省略 `mcp.versions` 时只允许 `2025-11-25` 修订。要支持使用其他修订的服务器，列出它需要的精确修订，参见 [MCP 版本选择](/how-it-works/policies/schema#mcp-版本选择)。服务器响应与 SSE 消息原样转发，不做 MCP 策略解析。不要把 MCP 端点与使用其他协议的端点放在同一主机与端口上。`openshell policy update` 拒绝这种组合。

使用无会话 `2026-07-28` 修订的服务器没有初始化步骤。其客户端随每条请求发送协议版本与能力，并可以调用 `server/discover` 了解服务器支持什么。这条规则允许在此类服务器上发现与 `read_status`：

```yaml
mcp_server:
  endpoints:
    - host: mcp.example.com
      port: 443
      path: /mcp
      protocol: mcp
      enforcement: enforce
      mcp:
        versions: ["2026-07-28"]
      rules:
        - allow:
            method: server/discover
        - allow:
            method: tools/list
        - allow:
            method: tools/call
            tool: read_status
  binaries:
    - path: /usr/bin/python3.12
```

`2026-07-28` 请求缺少必需的 `MCP-Protocol-Version`、`Mcp-Method` 或 `Mcp-Name` 头部，或头部与正文不匹配时，OpenShell 拒绝它。完整的请求检查参见[无会话 MCP 请求](/how-it-works/policies/schema#无会话-mcp-请求)。要在同一端点上服务两种修订的客户端，列出两个修订并组合两个示例中的规则。OpenShell 按请求选择的修订检查每条请求。

MCP 与 JSON-RPC 端点只承载 HTTP 请求，因为其规则逐条请求生效。`enforce` 与 `audit` 模式下，OpenShell 在发往这些端点、携带 `Upgrade` 头部（例如 WebSocket 升级）的请求到达服务器之前以 `403 Forbidden` 应答。服务器也接受 WebSocket 连接时，用单独的 `protocol: websocket` 端点允许它们，该端点应用 `GET` 与 `WEBSOCKET_TEXT` 规则，而不是 MCP 方法或工具规则。对 MCP 服务器，把该端点放在不同的主机或端口上。JSON-RPC 端点可以与使用不同 `path` 的 WebSocket 端点共享主机与端口。

### 允许原生 TCP

`protocol: tcp` 用于说 HTTP 之外协议的客户端，例如数据库客户端。OpenShell 检查主机名、端口与可执行文件，但不应用请求规则，因此客户端支持被检查协议时优先使用。

在 Debian 与 Ubuntu 上，`/usr/bin/psql` 是启动 `/usr/lib/postgresql/<version>/bin/psql` 的包装脚本，因此这条规则用 glob 列出该路径：

<Tabs>
<TabItem label="CLI">

```shell
openshell policy update my-sandbox \
  --rule-name postgres \
  --binary '/usr/lib/postgresql/*/bin/psql' \
  --add-endpoint db.internal.example:5432::tcp \
  --wait
```

</TabItem>
<TabItem label="YAML">

```yaml
postgres:
  endpoints:
    - host: db.internal.example
      port: 5432
      protocol: tcp
  binaries:
    - path: /usr/lib/postgresql/*/bin/psql
```

</TabItem>
</Tabs>

不要向 TCP 端点添加 `access`、`enforcement`、请求规则或凭据改写字段。验证 `psql` 能到达服务器，然后在连接边界验证另一个二进制或端口被拒绝。规则不存在时会在应用层认证之前失败的客户端命令适合做验证。数据库认证错误可以说明 TCP 连接到达了服务器，但不能证明数据库凭据正确。

OpenShell 在沙箱启动时就准备好 DNS 与 TCP 处理，因此可以向运行中的沙箱添加 TCP 端点而无需重建沙箱。

客户端一连上就启动 TLS、客户端必须自行完成 TLS（例如出示客户端证书），或服务器先说话（如 SMTP、IMAP 与 MySQL）时，设置 `tls: skip` 让 OpenShell 不加检查地转发连接。先说话并在协议内协商 TLS 的客户端（例如 `psql`）不需要它。参见[检查字段](/how-it-works/policies/schema#检查字段)。

优先使用精确主机名。通配符会授权对每个匹配名字的 DNS 查询，可能暴露 DNS 标签外泄通道。共享基础设施上的允许主机名也可能经由同一连接到达其他租户或虚拟服务，因为 OpenShell 无法检查非 HTTP 载荷寻址的是哪个服务。

OpenShell 用占位地址应答规则中主机的 DNS 查询，其 TTL 至多 30 秒。这适用于每个端点，不只 `protocol: tcp`。沙箱不应用 DNS 搜索域，请严格按规则中的名字请求每个主机名。客户端重连之前必须重新解析主机名。无限期缓存地址的客户端可能在地址过期后失败，即使端点仍然被允许。OpenShell 对 AAAA 查询返回空应答，双栈客户端必须回退到 A 记录。
