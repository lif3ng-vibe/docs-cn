本页列出运行 OpenShell 所需的宿主机平台、计算驱动、软件、运行时与内核要求。

## 发布

OpenShell 按发布周期的不同阶段发布 dev、预发布与稳定版构建。生产部署请使用稳定版。

| 发布类型 | 发布方式 | 适用场景 |
|---|---|---|
| Dev | 从每个通过常规 CI 的 `main` 提交构建。浮动的 `dev` 别名指向最新构建。 | 测试即将推出的功能。dev 构建启用了开发中的特性，且未通过发布资格验证。 |
| 预发布 | `main` 有变更且常规 CI 通过时每晚构建。版本号形如 `X.Y.Z-pre.N`。 | 验证为下一个稳定版提议的不可变产物集。预发布使用与稳定版相同的特性集，但可能尚未通过资格验证。 |
| 稳定版 | 从通过一致性、升级、API 兼容性、产物与安全检查的预发布晋升而来。版本号形如 `X.Y.Z`。 | 本支持矩阵范围内的生产使用。 |

预发布的发布不依赖资格验证。资格验证失败只会将该次运行标记为失败，已发布的包、镜像与 chart 仍然可用。稳定版产物只有在当前资格验证档案通过后才会发布。资格验证证据保留在 CI 存储中。当前档案只覆盖完整发布资格策略的一部分；通过它并不等于满足 RFC 0014 的完整覆盖。

带标签的稳定版通常每周发布一次。OpenShell 在有变更且所有阻塞性资格检查通过时，以周二发布为目标。安全版本可能提前发布。

Stable API 与其他 Stable 接口在补丁版本间保持向后兼容。补丁版本可以包含修复与增量功能。对 Stable 接口的破坏性变更需要一个次版本发布，并附通知与迁移指引。标记为 Experimental 的接口可能在补丁版本中变更或移除。

OpenShell 为最新次版本和上一个次版本（即 N-1）提供安全与关键可靠性更新。支持范围适用于每个在维护中的次版本线的最新补丁；请更新到该补丁以获得修复，OpenShell 不会为每个更旧的补丁发布修复。维护更新不会向后移植特性。

完整的发布与兼容性策略参见 [RFC 0014](https://github.com/NVIDIA/OpenShell/blob/main/rfc/0014-release-stability/README.md)。

## 支持的平台

OpenShell 为 `linux/amd64` 和 `linux/arm64` 发布多架构网关镜像。CLI、策略证明器、包管理器安装的网关与独立网关二进制支持以下宿主机平台：

| 平台 | 架构 | 状态 |
| --- | --- | --- |
| Linux (Debian/Ubuntu) | x86_64 (amd64) | 已支持 |
| Linux (Debian/Ubuntu) | aarch64 (arm64) | 已支持 |
| macOS (Docker Desktop) | Apple Silicon (arm64) | 已支持 |
| Windows (WSL 2 + Docker Desktop) | x86_64 | 实验性 |

在 Linux 上，`openshell` CLI 是静态 musl 二进制，运行时不依赖 glibc。

## 独立网关二进制

OpenShell 为以下平台发布可手动下载的独立 `openshell-gateway` 发布产物：

| 平台 | 产物命名模式 |
| --- | --- |
| Linux x86_64 (amd64) | `openshell-gateway-x86_64-unknown-linux-gnu` |
| Linux aarch64 (arm64) | `openshell-gateway-aarch64-unknown-linux-gnu` |
| macOS Apple Silicon | `openshell-gateway-aarch64-apple-darwin` |

这些产物附在 GitHub release 上。Kubernetes 部署应使用 Helm chart 与已发布的网关镜像。

在 Linux 上，`openshell-gateway` 要求 glibc 2.28 或更新版本。兼容系统例如 Ubuntu 20.04+、RHEL 8+、Rocky Linux 8+、Amazon Linux 2023+ 与 Fedora 32+。

## 沙箱运行时二进制

`openshell-sandbox` 是工作负载侧的可信运行时二进制。它在沙箱边界内运行，启动并拥有智能体进程树，观察可执行文件身份，并将受控的 TCP 与 DNS 操作发送给监管器。它不持有提供商凭据，也不建立上游连接；这些职责仍由工作负载边界之外的监管器承担。

OpenShell 为沙箱运行时支持的 Linux 架构发布静态 musl 构建：

| 平台 | 产物命名模式 |
|---|---|
| Linux x86_64 (amd64) | `openshell-sandbox-x86_64-unknown-linux-musl.tar.gz` |
| Linux aarch64 (arm64) | `openshell-sandbox-aarch64-unknown-linux-musl.tar.gz` |

该静态二进制不依赖智能体镜像的 libc。每个稳定版还会为独立归档发布 `openshell-sandbox-checksums-sha256.txt`。

受支持的运行时会自动交付该二进制，与智能体镜像相互独立。Docker 和 Podman 将其暂存进工作负载，Kubernetes 使用可信沙箱运行时镜像，VM 运行时将其嵌入客户机 rootfs。大多数用户不需要直接调用该二进制。在集成运行时或为气隙环境准备产物时使用独立归档，并保持沙箱二进制与 OpenShell 发布的其余部分版本一致。

## 独立策略证明器

OpenShell 为以下平台发布可手动下载的独立 `openshell-prover` 发布产物：

| 平台 | 产物命名模式 |
| --- | --- |
| Linux x86_64 (amd64) | `openshell-prover-x86_64-unknown-linux-musl.tar.gz` |
| Linux aarch64 (arm64) | `openshell-prover-aarch64-unknown-linux-musl.tar.gz` |

## 运行时

网关可以通过多种运行时管理沙箱。

| 运行时 | 状态 | 说明 |
|---|---|---|
| Docker | 支持本地开发与单机网关。 | 要求可访问的 Docker API 套接字。监管器网络默认使用 host 模式；运维人员可选择 bridge。端点与隔离要求参见 [Docker 运行时配置](/how-it-works/sandboxes/runtimes#docker-驱动)。 |
| Podman | 支持无 root 的本地与工作站工作流。 | 要求 Podman 兼容的套接字与无 root 网络配置。 |
| Kubernetes | 通过 [OpenShell Helm chart](https://github.com/NVIDIA/OpenShell/blob/main/deploy/helm/openshell/README.md) 支持。 | 要求运维人员提供 Kubernetes 集群。 |
| MicroVM | 支持基于 VM 的沙箱。 | 使用 VM 计算驱动与基于 libkrun 的运行时。 |

| 组件 | 最低版本 | 说明 |
|---|---|---|
| Docker Desktop 或 Docker Engine | 28.0 | Docker 网关、本地镜像构建与 Docker 开发工作流所必需。 |
| Podman | 5.x | Podman 网关所必需。 |
| Kubernetes | 1.29 | Helm 部署与 Kubernetes 沙箱调度所必需。 |
| Helm | 3.x | 安装 `deploy/helm/openshell` 所必需。 |
| kubectl | 与集群兼容 | Kubernetes 运维检查与机密创建所必需。 |
| 宿主机虚拟化 | 取决于宿主机 | MicroVM 网关所必需。MicroVM 在 macOS 上使用 Hypervisor.framework，在 Linux 上使用 KVM。 |

## 工作负载镜像

OpenShell 接受标准的 Linux OCI 镜像。内置默认工作负载是适用于 `linux/amd64` 和 `linux/arm64` 的 `nvcr.io/nvidia/base/ubuntu:24.04`。它是一个最小化的 Ubuntu Noble 用户空间，不捆绑智能体 CLI。运维人员可以更改默认值，用户可以用 `--from` 指定明确的镜像。

## 容器镜像

| 镜像 | 引用 | 拉取时机 |
|---|---|---|
| 网关 | `ghcr.io/nvidia/openshell/gateway:latest` | Helm chart 安装或升级，或独立容器部署 |
| 沙箱运行时 | `ghcr.io/nvidia/openshell/sandbox:latest` | 受支持的运行时将 `openshell-sandbox` 暂存进工作负载边界时 |
| 默认工作负载 | `nvcr.io/nvidia/base/ubuntu:24.04` | 首次创建沙箱时，除非已预加载或被覆盖 |

`deploy/helm/openshell` 中的 Helm chart 为 Kubernetes 部署网关工作负载、服务账户、Service、可选持久存储与网络策略。它默认使用 StatefulSet 适配基于 SQLite 的安装，也可以渲染 Deployment 适配外部数据库的安装。

要覆盖默认镜像引用，使用 Helm values：

| Helm value | 用途 |
|---|---|
| `global.image.registry` / `global.image.tag` / `global.image.pullPolicy` | 覆盖网关、监管器与可信沙箱运行时共享的镜像设置。 |
| `gateway.image.registry` / `gateway.image.repository` / `gateway.image.tag` / `gateway.image.digest` | 覆盖网关镜像引用。 |
| `supervisor.image.registry` / `supervisor.image.repository` / `supervisor.image.tag` / `supervisor.image.digest` | 覆盖监管器镜像引用。 |
| `sandbox.image.repository` / `sandbox.image.tag` / `sandbox.image.digest` | 覆盖默认工作负载沙箱镜像。 |

## 内核要求

沙箱边界要求以下 Linux 内核设施，即便它运行在容器或 microVM 内部也不例外：

| 模块 | 要求 | 说明 |
| --- | --- | --- |
| [Landlock LSM](https://docs.kernel.org/security/landlock.html) | 必需 | ABI 3 或更新版本（Linux 6.2 引入），且已启用 Landlock。该强制基线保护私有信道与引导文件，包括防止截断。文件系统策略的 `best_effort` 设置永远不会关闭该基线。 |
| seccomp | 必需 | 嵌套的 user-notification 过滤器，以及携带 `SECCOMP_ADDFD_FLAG_SEND` 的原子操作 `SECCOMP_IOCTL_NOTIF_ADDFD`，可在运行时既有 seccomp profile 下使用而无需附加 capabilities。沙箱会在接纳工作负载之前主动探测这些操作。 |
| 任务内存访问 | 必需 | 不可转储（non-dumpable）的 broker 必须能通过 `process_vm_readv` 或 `/proc/<pid>/mem` 读取同 UID、可转储的工作负载子进程内存。broker 从不写入工作负载内存。沙箱会在接纳工作负载之前主动探测生产环境的父到子拓扑。 |
| 套接字设备绑定 | 必需 | 沙箱用 `SO_BINDTODEVICE` 将工作负载的每个 TCP 与 UDP 套接字绑定到回环接口，无需附加 capabilities。被接受的套接字继承该绑定，因此工作负载只能接受来自沙箱网络命名空间内部的连接。沙箱会在接纳工作负载之前探测这一点。 |

仅有内核版本号并不足以确立支持。被禁用的 Landlock LSM 或阻断所需 seccomp 操作的运行时 profile 会导致启动以失败即关闭的方式终结。上游 Linux 6.2 或更新内核提供所需的 Landlock ABI；发行版回移补丁必须通过同样的主动资格验证。broker 在资格验证期间保持不可转储。即使内核省略了 `process_vm_readv` 系统调用，运行时也可以通过 `/proc/<pid>/mem` 满足任务内存访问要求；OpenShell 验证的正是与受控工作负载相同的父进程到被执行子进程的访问形态。

在 macOS 上，这些内核模块运行在 Docker Desktop 的 Linux VM 内，而不是宿主机内核中。

### 套接字对端地址

在由 OpenShell 中继的出站 TCP 连接上，`getpeername()` 报告的是本地中继的回环地址（`127.0.0.1` 或 `::1`）与端口，而非上游目的地。被接受的套接字与直接建立的本地套接字报告真实的对端地址；入站对端地址的报告保持常规套接字语义。连接授权始终基于所请求的目的地，与 `getpeername()` 报告的地址无关。

## 智能体工作负载

OpenShell 运行你安装在用户自有 OCI 镜像中的智能体与工具。镜像必须满足所选计算驱动的平台要求。镜像、提供商与策略工作流参见[运行你的第一个智能体](/about/run-your-first-agent)。
