agent-desktop 通过 UI Automation (UIA) 读取 Windows 应用。操作循环节、引用、JSON 信封、会话与追踪记录在所有平台上保持一致，因此本页只讲 Windows 上不同的部分。本文所述的 Windows 行为已对照 Windows 适配器、其测试与 Windows 技能文档（`agent-desktop skills get windows`）核验，并非为撰写本文而实际运行。其他地方的示例是 POSIX shell；PowerShell 的写法见[使用 PowerShell](#使用-powershell)。

## 系统要求

- Windows 10 1809 或更高版本，或 Windows Server 2019 或更高版本，x64 或 ARM64。
- 必须是已登录用户的交互式桌面会话。会话 0（服务和 SYSTEM 任务）、Server Core、安全桌面（UAC 提示与登录屏幕）、锁定的桌面以及其他用户的会话均不受支持。
- 二进制文件未签名。SmartScreen 可能对浏览器下载发出警告，杀毒软件可能隔离它，全新安装的 Windows 11 上的 Smart App Control 会阻止它。

## 权限与提权

Windows 没有针对 UI Automation 的授权对话框；访问由完整性级别控制。

- 与你终端同完整性级别的应用无需授权。UIA 能应答时 `permissions` 报告 `accessibility: granted`，且 `automation: not_required`。`permissions --guide` 返回 `PLATFORM_NOT_SUPPORTED`。
- 以管理员身份运行的应用只能被读取，无法从较低完整性级别的终端驱动它，因为用户界面特权隔离（UIPI）会阻断输入。agent-desktop 在发送任何东西之前会比较进程令牌，返回 `PERM_DENIED`，并在 `platform_detail` 中带 `E_ACCESSDENIED`。请从一个提升到相同级别的终端运行 agent-desktop。
- 提权与未提权的运行不能共享同一个状态根目录；第二个会以 `INTERNAL` 失败，报 “private file parent is owned by a foreign principal”。给提权运行单独指定一个 `AGENT_DESKTOP_HOME`。

## 应用命名

- `launch` 接受绝对路径，或 System32 与 Windows 目录下的裸名称，`.exe` 可省可不省（`notepad` 或 `notepad.exe`）。它不解析 “Google Chrome” 这类显示名。
- 对运行中的应用，把 `list-apps` 输出的名称传给 `--app`，例如 `notepad.exe`。
- 窗口 id 是 `w-` 后接窗口句柄。寄宿的（UWP）应用通过其 `ApplicationFrameHost` 框架报告。
- 被其他窗口挡住的应用仍可驱动。被最小化的则不行：每个元素都报告 `offscreen`。请运行 `restore --app IMAGE` 再重新快照，而不是 `focus-window`——后者会抢走用户的前台。

## 表面

`supported_surfaces` 列出 `window`、`focused`、`sheet`（Chromium 模态框）、`menu`，以及 shell 类型 `start-menu`、`taskbar`、`system-tray`、`system-tray-overflow` 和 `action-center`。没有 `menubar` 表面。`snapshot --surface KIND` 无需 `--app` 也无需 `--headed` 就能读取 shell 表面；对已关闭的表面返回 `WINDOW_NOT_FOUND`，其 `suggestion` 指明可用 `open-system-surface`。`menu` 检测覆盖传统 Win32、WPF 以及 Chromium 或 Electron 菜单，但不覆盖 WinUI 3 或 MSIX 宿主，因此在那种环境下“没有菜单”应理解为“未检测到”。参见[表面](/desktop/surfaces)。

## 使用 PowerShell

PowerShell 把裸 `@token` 读成它的展开（splatting）运算符，在 agent-desktop 看到之前就把参数吃掉了。每个引用都要加引号：

```powershell
agent-desktop set-value '@s8f3k2p9:e1' "hello"
$env:AGENT_DESKTOP_HOME = "$env:TEMP\ad-scratch"
$start = agent-desktop session start | ConvertFrom-Json
$env:AGENT_DESKTOP_SESSION = $start.data.session_id
```

用 `$env:NAME = 'value'` 代替 `export`，用 `| ConvertFrom-Json` 代替 `jq`。不加引号的引用会以 `INVALID_ARGS` 失败。`cmd.exe` 和 bash 不需要引号。

## 按键

- `cmd` 与 `meta` 都是 Windows 键，因此 `meta+c` 是一条 shell 快捷键。复制请写 `ctrl+c`。
- `alt+f4`、`win+l`、`win+d`、`alt+tab`、`win+r`、`win+x`、`win+e`、`ctrl+shift+esc` 及其超集在不加 `--force` 时被拒绝。`ctrl+alt+delete` 完全无法合成。
- `type` 是按键合成，需要 `--headed`；无头时用 `set-value`。
- `press --app` 写入的是前台输入队列，无法针对某个后台进程。

## Chromium 与 Electron

Chromium 138 及更高版本无需任何 flag 就会暴露完整的 UIA 树，但第一次读取会启动渲染器的无障碍树构建，只返回树的一小部分。冷启动需要 10 到 25 秒才能就绪。

- 给 `snapshot` 传更长的 `--timeout-ms`，而不是断定树为空。
- 一个已就绪的树若边界节点带 `children_count` 且没有控件，这是深度效应所致：用 `snapshot --root` 对边界下钻。
- 对可以全新启动的应用的 web 内容，`launch --cdp` 会为 agent-browser 打开 DevTools 端口；参见[Chromium 与 Electron 应用](/desktop/guides/chromium-and-electron)。
- 在自动化对等类（automation peer）尚未存在之前读取的 WPF 窗口可能绑定一个空的通用提供器。几秒后再取一份新快照。
