### 正式发布

* 新增 Linux 支持: CLI、C 库与 npm 包现在经由 AT-SPI 运行于 x86_64 与 aarch64 Linux（glibc 2.35 或更高）。
* 集成后的 macOS、Windows、Linux CLI 与 C 库以 1.0.0 发布。
* npm 安装中捆绑原生 CLI 可执行文件与平台辅助程序,包括禁用了生命周期脚本的安装。
* 通过手动 release 工作流校验发布归档、校验和与构建出处。

## [0.10.0](https://github.com/vercel-labs/agent-desktop/compare/v0.9.4...v0.10.0) (2026-10-18)

### ⚠ 破坏性变更

* 本次发布携带以下契约变更。
    - C ABI 主版本号为 5。每个都有 `*_exact` 替代者的旧入口被移除: ad_list_surfaces, ad_surface_list_count,
      ad_surface_list_get, ad_surface_list_free, ad_list_windows,
      ad_window_list_count, ad_window_list_get, ad_window_list_free,
      ad_launch_app, ad_release_window_fields, ad_get_tree, ad_find, ad_is,
      ad_focus_window, ad_window_op, ad_resolve_element and
      ad_execute_ref_action_with_policy, 连同 AdSurfaceList 与 AdWindowList
      句柄。AdScreenshotKind 失去 WINDOW（FULL_SCREEN 仍为 2,1 被拒绝）; AdScreenshotTarget 失去 pid; AdExactSurfaceInfo 为版本 2,
      48 字节,带尾部的 unclassified 字段; ad_execute_by_ref 与 ad_execute_by_ref_timeout 的 snapshot_id 参数以及
      AdWaitPredicate.snapshot_id 字段被移除,因此 AdWaitPredicate 为 40
      字节,AdWaitArgs 为 104。使用方必须基于重新生成的头文件重新构建。
    - 所有接受引用的 CLI 命令、wait
      --element、snapshot --root、find --root、drag --from/--to、batch 条目
      与 FFI 都移除了裸 @eN 引用输入。只接受带快照限定的 @&lt;snapshot_id>:eN,
      裸引用以 INVALID_ARGS 失败。只用于限定裸引用的 --snapshot flag
      已从所有命令移除,携带 snapshot 或 snapshot_id 字段的 batch
      条目会被当作未知字段拒绝。
    - get --property text 不再返回与 --property value 相同的值。
      它对 textfield、combobox、listbox、datefield 与
      timefield 优先取 value,回退到可访问名称;其余角色优先
      可访问名称,回退到 value。空白字符串按缺席处理。想要
      之前的答案,请显式请求 --property value。
    - kind 为 PermissionDenied 的 io 错误回答 PERM_DENIED 而非
      INTERNAL,在 CLI 信封与 FFI 信封、返回码和
      last error 中均是如此。
    - 元素已消失的引用操作不再以 TIMEOUT 结束。不可重试的
      解析失败立即回答;可重试的继续轮询,若之后没有任何一次解析成功,
      该操作在期限处回答记录下来的 STALE_REF 或 AMBIGUOUS_TARGET。

## [0.6.0](https://github.com/vercel-labs/agent-desktop/compare/v0.5.0...v0.6.0) (2026-07-26)

### ⚠ 破坏性变更

* Windows 上的私有工件不再通过经 ACL 加固的句柄写入。这层加固守护的是 refmap、trace 与 session 文件,但在该平台上没有任何命令能产生它们,而它也从未被真正执行过。它将在 Phase 2.1 回归,在 Windows 上构建并依托一条真正运行它的 CI lane,约束条件记录在 `docs/solutions/best-practices/never-ship-platform-code-that-ci-cannot-execute.md`。

### 重构

* 从 core 移除投机性的 Win32 私有文件层,新增真实的 Windows/Linux 测试 lane ([#106](https://github.com/vercel-labs/agent-desktop/issues/106)) ([8ad66b8](https://github.com/vercel-labs/agent-desktop/commit/8ad66b8f2115704eed56e59e2709c4eddf3cffac))
  * 从 `agent-desktop-core` 删除 1,062 行 Windows 专属的 `unsafe` Win32 文件 I/O,并去掉 `windows-sys` 依赖; Windows 现在与所有其他非 unix 目标一样,走可移植的 `std::fs` 路径
  * 这是结构性修复而非降级:`std::fs::OpenOptions` 默认把 `share_mode` 设为 `FILE_SHARE_READ | FILE_SHARE_WRITE | FILE_SHARE_DELETE`,恰是被删代码遗漏、也是其 sharing-violation 失败根源的那个 flag
  * `cargo test` 现在在 windows-latest 与 ubuntu-latest 上运行,core 中每个平台条件分支都随每个 PR 真正执行,而不只是被编译

### Bug 修复

* 新平台 lane 暴露了四个仅在 macOS 跑测试时不可抵达的既有缺陷:
  * trace 文件以 append-only 打开,而 `trace.rs` 锁住该句柄;Windows 的 `LockFileEx` 拒绝 append-only 句柄,所以所有 trace 写入都以 `Access is denied` 失败
  * `refs_lock` 测试把锁文件直接放进了 `/tmp`,而它属于 root 且全局可写,私有父目录检查正确地拒绝了它们
  * 一个 trace 测试把原始路径内插进 JSON 字符串字面量,导致 Windows 路径产生非法转义,事件被静默丢弃而非跳过
  * 默认的 `SystemOps::permission_report` 返回 `Denied`,导致 CLI 预检在适配器只是未实现的 Windows 与 Linux 上报告 `PERM_DENIED`;它现在报告 `Unknown` 并如实上抛 `PLATFORM_NOT_SUPPORTED`,FFI 上同样如此
* 钉住的工具链补上了 `clippy` 与 `rustfmt`,此前 `profile = "minimal"` 漏掉了它们

## [0.5.0](https://github.com/vercel-labs/agent-desktop/compare/v0.4.7...v0.5.0) (2026-07-20)

### ⚠ 破坏性变更

* 全新默认开启的 auto-wait 改变了此前所有未被触碰的引用操作调用时序（有界默认 5000 ms;`--timeout-ms 0` 恢复单发）。`ENVELOPE_VERSION` 现为 `2.1`（新增 `APP_UNRESPONSIVE` 错误码及错误详情中的进程状态）。FFI ABI 主版本为 `3`（仅追加的结构体演进;`wait --event` 有意不通过 FFI 暴露）。旧的字符串剪贴板 API 被移除,改为类型化内容。在守护进程持有的按住输入出现之前,`key-down`/`key-up` 以失败收场。`close-app` 会验证进程终止,osascript 回退路径被移除。`--text` 匹配是子树包含:`find --text X --first` 返回最外层匹配容器。

### 新特性

* 实现 Playwright 级的基础契约 ([3f32272](https://github.com/vercel-labs/agent-desktop/commit/3f322728b44548d2e22f4ee6ef4e6853af4e4550))
  * 默认开启的 auto-wait:每个引用操作在派发前等待可操作性（可见、启用、稳定、无遮挡）,且有界预算约束
  * 存活 `find` locator 加可序列化 `LocatorQuery`,以及如实反映的 `is --property visible`
  * 三态 `hit_test` 遮挡门控与元素操作前的 core `scroll_into_view`
  * `list-displays` 与带每屏缩放系数的如实 `--screen`;`native_id` 身份脊柱;window-id 优先解析
  * 带 `APP_UN-responsive` 错误码（信封 `2.1`）的 `ProcessState` 分类;类型化 `ActionStep` 投递层级
  * `LaunchOptions`（`--arg`/`--env`/`--cwd`/`--no-attach`）;经 `wait --event` 的基线差分桌面信号
  * 类型化剪贴板（`Text`/`Image`/`FileUrls`）;鼠标修饰键组合与 `mouse-wheel` 原语
  * 能力超 trait 拆分 `PlatformAdapter` 并配 `not_supported()` 默认实现,Windows 与 Linux 由此继承契约
