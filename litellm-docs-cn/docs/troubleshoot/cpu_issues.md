# CPU 问题分类与复现

## 1. 对 CPU 问题进行分类

勾选最符合你所观察到的 CPU 表现的选项。

- [ ] CPU 随流量增长而上升（由 RPS 驱动）
- [ ] 流量没有增加，CPU 却在上升
- [ ] 升级 LiteLLM 后 CPU 上升

## 2. 能否复现该问题？

在把问题上报之前，先验证该 CPU 问题能否在一个与生产环境一致的测试环境中复现。  

如果可以复现，请提供**详细的复现步骤**，以及所有相关的请求或所用配置。  
关于需要收集哪些信息，可参考 [LiteLLM 故障排查指南](../troubleshoot)。

## 3. 问题无法复现

如果该 CPU 问题无法在与生产环境一致的测试环境中复现，请提供以下内容：

1. **第 1 节和第 2 节的信息**  
   - CPU 分类结果（第 1 节）  
   - 复现尝试与环境详情（第 2 节）  

2. **帮助排查的其他背景信息**：  
   - **负载情况**：高峰前后及高峰期间实际处理的请求样本，包括近期的任何配置变更。  
   - **指标**：CPU 使用率、P50/P99 延迟、内存使用量。请尽可能附上指标的**截图**。  
   - **日志与告警**：**高峰前与高峰期间**捕获的所有相关日志或告警。

> 提供这些信息后，团队才能分析规律、把 CPU 高峰与流量或配置关联起来，并在内部尝试复现该问题。缺少这些信息，我们的工程师就没有足够的依据去排查问题。
