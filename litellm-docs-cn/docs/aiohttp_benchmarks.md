# LiteLLM v1.71.1 性能基准测试

## 概览

本文给出 LiteLLM v1.71.1 与此前各版本的性能基准对比。

**相关 PR**：[#11097](https://github.com/BerriAI/litellm/pull/11097)

## 测试方法

负载测试采用以下参数：
- **请求速率**：200 RPS（每秒请求数）
- **用户递增**：200 个并发用户
- **传输层对比**：httpx（现有实现）对比 aiohttp（新实现）
- **LiteLLM pod/实例数量**：1
- **机器配置**：2 vCPU、4 GB 内存
- **LiteLLM 设置**：
    - 测试目标是一个[假的 openai 端点](https://exampleopenaiendpoint-production.up.railway.app/)
    - aiohttp 在 v1.71.1 中还是可选启用，因此 aiohttp 那一轮测试设置了 `USE_AIOHTTP_TRANSPORT="True"`。该开关如今已不存在，设置后也不再生效：aiohttp 已成为默认传输层，无需任何配置。如果想改用 httpx 传输层（例如复现 httpx 基线），请设置 `DISABLE_AIOHTTP_TRANSPORT="True"` 或 `litellm.disable_aiohttp_transport = True`。启用 HTTP/2（`LITELLM_HTTP2="True"`）同样会强制使用 httpx


## 基准测试结果

| 指标 | httpx（现有） | aiohttp（LiteLLM v1.71.1） | 提升 | 计算方式 |
|--------|------------------|-------------------|-------------|-------------|
| **RPS** | 50.2 | 224 | **+346%** ✅ | (224 - 50.2) / 50.2 × 100 = 346% |
| **中位延迟**| 2,500ms | 74ms |**-97%** ✅ | (74 - 2500) / 2500 × 100 = -97% |
| **95 百分位**| 5,600ms | 250ms |**-96%** ✅ | (250 - 5600) / 5600 × 100 = -96% |
| **99 百分位**| 6,200ms | 330ms |**-95%** ✅ | (330 - 6200) / 6200 × 100 = -95% |

## 主要提升

- 每秒请求数**提升 4.5 倍**（从 50.2 RPS 增至 224 RPS）
- 中位响应时间**缩短 97%**（从 2.5 秒降至 74ms）
- 95 百分位延迟**降低 96%**（从 5.6 秒降至 250ms）
- 99 百分位延迟**降低 95%**（从 6.2 秒降至 330ms）
