# 使用 Lightpanda Agent

本教程将带你了解如何使用 Lightpanda Agent 创建可复现的
JavaScript 浏览器脚本。

所有 flag 与 REPL 命令请查阅 [agent 命令参考](/reference/cli/agent)。

## 前置条件

- 已安装 Lightpanda，且其位于你的 `PATH` 中。
- 一个 Hacker News 账号。
- 自然语言章节所需的 LLM API key（Anthropic、OpenAI、
  Gemini、Hugging Face 或本地 Ollama）。录制生成的 `.js` PandaScript 无需 key。

将你的 HN 凭据导出为 `LP_*` 环境变量。`LP_` 前缀关乎安全：
Lightpanda 只会在自己的子进程内解析这些占位符（因此你的密码
永远不会传给 LLM），并且 `getEnv` 工具会拒绝任何不以
`LP_` 开头的变量（因此 LLM 无法读取你的其他机密）。

```sh copy
export LP_HN_USERNAME="your-hn-handle"
export LP_HN_PASSWORD="your-hn-password"
```

检查这些变量是否已设置。如果缺少某个变量，`/fill` 会静默地
把字面量 `$LP_HN_USERNAME` 输入到表单里，而不是你的用户名：

```sh copy
lightpanda agent --no-llm
```
```console
> /getEnv LP_HN_USERNAME
```

## 1. 启动 REPL

```sh copy
lightpanda agent
```

启动横幅会显示自然语言功能是否可用；`/model` 会打印解析后的
模型。REPL 历史保存在工作目录下的 `.lp-history` 中。

```console
> /help            # 列出所有浏览器工具
> /help goto       # 查看单个工具的 JSON schema
> /quit
```

没有 API key？`lightpanda agent --no-llm` 会运行仅支持斜杠命令的
REPL。

## 2. 运行单个任务

在做复杂操作之前，先运行一个一次性任务，确认一切正常：

```sh copy
lightpanda agent --task "what is the top story on news.ycombinator.com?"
```

`--task` 只运行一轮用户输入，把答案打印到 stdout 后退出。
工具调用与进度信息走 stderr，因此重定向即可得到干净的答案：

```sh copy
lightpanda agent --task "top story on news.ycombinator.com?" > out.txt
```

使用 `-a <path>`（可重复）附加本地文件。

## 3. 登录 Hacker News

按顺序把这些命令粘贴进 REPL：

```console
> /goto https://news.ycombinator.com/login
> /fill selector='form[action="login"] input[name="acct"]' value='$LP_HN_USERNAME'
> /fill selector='form[action="login"] input[name="pw"]' value='$LP_HN_PASSWORD'
> /click selector='form[action="login"] input[type="submit"][value="login"]'
> /waitForSelector '#logout'
```

几点值得注意：

- **仅支持斜杠命令**。`click '#foo'` 会被转发给 LLM；
  只有 `/click '#foo'` 会作为命令执行。TAB 可补全工具名。
- **`/waitForSelector '#logout'` 既是同步点也是断言**。它会阻塞，
  直到 HN 登录后的 DOM 渲染完成。如果凭据有误（或网站弹出
  验证码，或页面布局变化），命令会在失败真正发生的那一行
  超时。每个改变状态的操作之后都请使用这一模式。
- **选择器仅限 CSS**。click 系列工具（`/click`、`/fill`、
  `/hover`、`/selectOption`、`/setChecked`）只接受 CSS。
  后端 node ID 会因任何 DOM 变更而失效，也无法序列化进
  录制脚本。

确认登录成功：

```console
> /extract '{"karma": "#karma"}'
{"karma":"42"}
```

`/extract` 接受一个 JSON schema，并向 stdout 打印一个 JSON 对象。
schema 语法：

- `"<sel>"`：第一个匹配项的文本。
- `["<sel>"]`：所有匹配项的文本。
- `{"selector": "<sel>", "attr": "<name>"}`：第一个匹配项的属性。
- `[{"selector": "<sel>", "fields": {…}}]`：记录数组，其中每个
  `fields` 条目都相对于所匹配元素进行解析。

现在前往首页并抓取帖子列表：

```console
> /goto https://news.ycombinator.com
> /extract '''
{
  "topStories": [{
    "selector": ".athing",
    "fields": {
      "rank": ".rank",
      "title": ".titleline > a",
      "url": {"selector": ".titleline > a", "attr": "href"}
    }
  }]
}
'''
```

三引号包裹的值允许 schema 跨多行。

### 这些选择器是怎么来的

如果你愿意直接照用，可以跳过本节。

`/tree` 会打印语义树。在登录页你会看到两个表单（登录和注册），
其中的文本框没有标签，这意味着 `/findElement role=textbox name=username`
不会返回任何结果。

`/detectForms` 直接读取 HTML，并列出每个表单的 `action` 以及
每个输入框的 `name`。第一个表单的 `action` 为 `"login"`，
字段名为 `acct` 和 `pw`，由此我们得到表单作用域内的选择器
（`form[action="login"] input[name="acct"]`），不会与注册表单冲突。

`/nodeDetails backendNodeId=<n>` 是另一种方式：它会为 `/tree`
输出中的任意节点 ID 返回一个可直接使用的 CSS 选择器。

## 4. 将会话保存为脚本

在同一个 REPL 会话中重新输入登录加首页的完整序列，然后执行：

```console
> /save hn_login.js
> /quit
```

在 `--no-llm` 模式下，`/save` 会确定性地转录会话。在有 LLM 的
情况下，它会综合生成一段符合习惯的脚本。结果为 JavaScript：

```js copy
const page = new Page();
await page.goto("https://news.ycombinator.com/login");
page.fill({ selector: "form[action=\"login\"] input[name=\"acct\"]", value: "$LP_HN_USERNAME" });
page.fill({ selector: "form[action=\"login\"] input[name=\"pw\"]", value: "$LP_HN_PASSWORD" });
page.click({ selector: "form[action=\"login\"] input[type=\"submit\"][value=\"login\"]" });
page.waitForSelector("#logout");
await page.goto("https://news.ycombinator.com");
return page.extract({ topStories: [{ selector: ".athing", fields: { rank: ".rank", title: ".titleline > a", url: { selector: ".titleline > a", attr: "href" } } }] });
```

只有改变状态的命令会被记录；只读命令（`/tree`、`/markdown`）
会被丢弃。`/extract` 会被记录，因为它决定了脚本的返回内容。

## 5. 不依赖 LLM 重放脚本

```sh copy
lightpanda agent hn_login.js
```

无需 `--provider`、无需 API key、不消耗 token。脚本 `return`
的内容会自动以 JSON 打印。由于保存的脚本以
`return page.extract(...)` 结尾，stdout 上得到的就是干净的 JSON：

```sh copy
lightpanda agent hn_login.js > stories.json
```

在 REPL 内部，`/load hn_login.js` 会针对当前会话运行同一个脚本。

要调整输出形态，请把结果赋给变量并以 `return <value>` 结尾
（返回什么就打印什么）：

```js copy
const page = new Page();
await page.goto("https://news.ycombinator.com");

const topStories = page.extract({
  topStories: [{
    selector: ".athing",
    fields: {
      rank: ".rank",
      title: ".titleline > a",
      url: { selector: ".titleline > a", attr: "href" }
    }
  }]
});

return topStories;
```

## 6. 添加你自己的 JavaScript 逻辑

Agent 脚本运行在与页面隔离的独立 JavaScript 上下文中。没有
`window`、`document`、DOM API、`require` 或 `process`。浏览器
交互通过 `Page` 对象完成：`new Page()` 创建页面，
`await page.goto(url)` 进行导航，其余所有原语都是它身上的
同步方法。

用 `page.extract(...)` 把页面数据取回本地逻辑，再用普通
JavaScript 处理：

```js copy
const page = new Page();
await page.goto("https://news.ycombinator.com");

const topStories = page.extract({
  topStories: [{
    selector: ".athing",
    limit: 5,
    fields: {
      rank: ".rank",
      title: ".titleline > a",
      url: { selector: ".titleline > a", attr: "href" }
    }
  }]
});

return topStories.map((s) => ({ rank: s.rank, title: s.title, url: s.url }));
```

只有当你有意让一段字符串在页面的 JavaScript 上下文中运行时，
才使用 `page.evaluate(...)`。页面 evaluate 无法看到 Agent 变量，
也无法调用 Agent 原语。

## 7. 从其他 Agent 使用 Lightpanda（MCP）

如果你是从另一个 Agent（Claude Code、自定义 MCP 客户端、
你自己的 harness）驱动 Lightpanda，请改用 `lightpanda mcp`。
调用方 Agent 自带 LLM，因此 Lightpanda 不需要 API key。

```json copy
{
  "mcpServers": {
    "lightpanda": {
      "command": "/path/to/lightpanda",
      "args": ["mcp"]
    }
  }
}
```

用常用工具（`goto`、`fill`、`click`、`waitForSelector`）驱动
浏览器，然后用 `save` 工具交回一段脚本：

```json
{
  "tool": "save",
  "args": {
    "path": "hn_login.js",
    "script": "const page = new Page();\nawait page.goto(\"...\");\n..."
  }
}
```

路径必须是相对路径且不含 `..`。写入文件之前，字面量
`LP_*` 值会被清洗回占位符。产物可直接原样运行：

```sh copy
lightpanda agent hn_login.js
```
