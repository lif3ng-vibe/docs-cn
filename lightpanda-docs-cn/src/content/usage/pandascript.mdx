# PandaScript

PandaScript 是一种可以由 Lightpanda 浏览器直接运行的网页自动化脚本。

无需像 NodeJS 或 Python 那样搭建环境，无需编写 Puppeteer/Playwright
代码，没有 CDP 序列化开销，也不需要 LLM：只需原生 JavaScript 加一小
组原语（primitive）。

可以使用普通的 JavaScript 变量、函数、循环、对象、数组、`JSON.parse`、
`JSON.stringify` 及其他标准 ECMAScript 内置能力。

它可复现、确定性且零 token 消耗（无需 LLM）。

运行一个 PandaScript：

```sh copy
lightpanda run <my_script>.js
```

## 运行时环境

Agent 脚本运行在自己的 V8 上下文中，该上下文与网页的 JavaScript 上下文
相互独立。

- 它不是浏览器页面环境。Agent 脚本中没有 `window`、`document`、DOM、
  `localStorage`、`navigator` 或页面全局状态。读取页面数据用
  `page.extract(...)`；当页面 JavaScript 确实是合适的工具时，再显式
  使用 `page.evaluate(...)`。
- 它不是 Node.js。没有 `require`、`process`、`fs`、`path`、npm 包
  加载、命令行参数 API，也没有 Node 的网络/文件系统 API。
- 页面脚本看不到 Agent 变量或 Lightpanda 原语。Agent 脚本也无法直接
  看到页面变量。
- `page.evaluate(...)` 在页面上下文中运行 JavaScript，与 Agent 上下文
  自身的原生 `eval` 不同。它不是全局函数，而是 page 对象上的方法。
- Agent 变量在一次脚本运行的生命周期内持续存在，可跨导航与原语调用。
  之后再执行 `lightpanda run script.js` 会从全新的 Agent 上下文开始。
- `goto` 是唯一异步的原语：务必 `await page.goto(...)`。其余所有页面
  方法（`extract`、`evaluate`、`click`、`fill` 等）都是同步阻塞的。
  脚本主体运行在 async 包装器内，因此允许顶层 `await`，这与普通经典
  脚本不同。
- 工具失败会抛出 JavaScript `Error` 异常并停止执行，除非你捕获它们。
- 脚本的输出就是它从顶层 `return` 的内容（对象和数组以 JSON 打印；
  其他值被强制转换）。脚本以 `return page.extract({ ... });` 或
  `return results;` 结尾。裸的尾随表达式不会被打印。`console.log(...)`
  用于额外或调试输出，不会对对象做 JSON 格式化。

Agent 上下文包含一个小的 `console` 对象，输出分流到两条流上。全部方法
见 [PandaScript 参考](/reference/pandascript#console)。

```js
console.log("printed to stdout");
console.error("printed to stderr");
```

## 值与返回类型

大多数原语把浏览器工具的结果文本作为 JavaScript 字符串返回。
`page.extract(...)` 是例外：它把提取到的数据作为普通 JavaScript 值
返回，本地脚本逻辑可以直接使用。结果与你的 schema 一一对应：对象
schema 返回以你的字段为键的对象（即使只有一个字段），裸数组 schema
返回数组：

```js copy
const page = new Page();
await page.goto("https://news.ycombinator.com/");

const data = page.extract({
  title: "title",
  stories: [{
    selector: "tr.athing",
    limit: 5,
    fields: {
      id: { attr: "id" },
      title: ".titleline > a"
    }
  }]
});

return data; // printed automatically as JSON
```

只需要单个字段时，可以解构：

```js copy
const { stories } = page.extract({
  stories: [{
    selector: "tr.athing",
    limit: 5,
    fields: {
      id: { attr: "id" },
      title: ".titleline > a"
    }
  }]
});

for (const story of stories) {
  console.log(story.title);
}
```

`page.evaluate(...)` 返回的仍是 page evaluate 工具的结果文本。当它
返回对象或数组时，该文本就是 JSON。

原语参数必须可 JSON 序列化。字符串、数字、布尔值、数组、普通对象和
`null` 都可以。其他值会抛出什么见
[PandaScript 参考](/reference/pandascript#调用约定)。

## 已安装的原语

只有会被录制的浏览器原语才会全局安装：先 `new Page()`，然后 `goto`、
`extract`、`evaluate`、`screenshot`，交互方法与 `waitFor*` 方法作为
page 对象的方法。完整表格、调用约定与超时见
[PandaScript 参考](/reference/pandascript)。

## 导航

用 `goto(...)` 导航到一个 URL：

```js copy
const page = new Page();
await page.goto("https://example.com");

await page.goto({
  url: "https://example.com/app",
  timeout: 15000
});
```

一旦达到 `waitUntil`（默认 `load`），该调用就会 resolve 为同一个
page 对象（`await page.goto(url) === page`）；导航失败或超时
（`"navigation timed out"`）则 reject。传入
`waitUntil: "networkidle"`（或其他状态）可以直接等待到 `load` 之后，
或者在完整性重要时接上 `waitForState(...)` / `waitForSelector(...)`。

## 结构化提取

用 `page.extract(...)` 从当前页面读取数据，而无需编写页面侧
JavaScript。这是从页面内容进入本地 Agent 逻辑的首选桥梁。

```js copy
const result = page.extract({
  heading: "h1",
  links: [{
    selector: "a",
    limit: 10,
    fields: {
      text: "",
      href: { attr: "href" }
    }
  }]
});
```

所有 schema 形式见
[PandaScript 参考](/reference/pandascript#提取-schema)。

每个值都是字符串（去除首尾空白的文本或原始属性值）或 `null`；数字请
在脚本逻辑中自行解析。匹配不到任何内容的数组字段会毫无怨言地给出
`[]`（零条评论的页面也是合法结果），但如果 schema 中*每一个*字段都
没匹配到，`page.extract(...)` 会抛出
`no schema selector matched any element`；请把它理解为"我的选择器
写错了"，而不是"页面是空的"。

`page.extract(...)` 只读取当前页面。列表转详情的抓取方式是：先抓
列表，然后在脚本中循环（`goto` 每行的 URL 并 `extract` 详情）。本地
Agent 上下文会跨导航保留数据，因此组装工作在普通 JavaScript 中完成。
完整示例见下文[完整示例](#完整示例)。

用局部变量把提取到的数据留给后续脚本逻辑使用：

```js copy
const data = page.extract({ title: "title" });
```

## 页面 JavaScript

`page.evaluate(...)` 是进入当前页面 JavaScript 上下文的显式逃生通道。
它的脚本字符串运行在 `window` 和 `document` 存在的地方。

```js copy
await page.goto("https://example.com");

const title = page.evaluate("document.title");
console.log(title);
```

把边界划清楚：

```js copy
const selector = "h1";

// Good: local agent logic builds an extract schema.
const data = page.extract({ heading: selector });

// Bad: page evaluate cannot see local agent variables.
page.evaluate("document.querySelector(selector).textContent");
```

`page.evaluate(...)` 不能调用 `page.goto`、`page.extract` 或其他
Agent 原语。Agent 脚本无法直接访问 `document`。需要页面 DOM 数据时，
优先用 `page.extract(...)`；只有提取无法表达的页面行为才用
`page.evaluate(...)`。

`page.waitForScript(...)` 同样在页面上下文中求值，会反复执行，直到
表达式为真值或超时：

```js copy
page.waitForScript("document.querySelectorAll('.row').length >= 5");
```

## 交互原语

操作原语作用于当前页面。大多数接受一个对象，其字段与浏览器工具
schema 一致：

```js copy
page.click({ selector: "a.login" });
page.fill({ selector: "input[name='acct']", value: "$LP_HN_USERNAME" });
page.fill({ selector: "input[name='pw']", value: "$LP_HN_PASSWORD" });
page.press({ key: "Enter" });

page.waitForSelector("#logout");

page.hover({ selector: "#menu" });
page.selectOption({ selector: "select[name='country']", value: "FR" });
page.setChecked({ selector: "input[name='terms']", checked: true });
page.setChecked({ selector: "input[name='newsletter']", checked: false });

page.scroll({ y: 600 });
page.scroll();
```

省略 `checked` 字段时，`setChecked` 默认为 `true`
（`setChecked("#chk")` 会勾选该框）。`press` 的第一个位置参数是可选的
`selector`，而不是 `key`：直接写 `press("Enter")` 会把 `"Enter"` 绑定
到 `selector` 上并失败。用 `press({ key: "Enter" })` 或
`press(null, "Enter")` 在文档上按键（不一定是焦点元素）；用
`press("#search", "Enter")` 或
`press({ key: "Enter", selector: "#search" })` 定位到某个元素。

字符串参数中的 `$LP_*` 占位符会在 Lightpanda 进程内解析。这样凭据就
不会进入录制的脚本和 LLM 提示。在录制中，已解析的 `LP_*` 值会被清洗
回占位符。

## 错误处理

原语失败会抛出 JavaScript 异常：

```js copy
try {
  page.waitForSelector({ selector: "#dashboard", timeout: 1000 });
} catch (err) {
  console.error("dashboard did not appear:", err.message);
  throw err;
}
```

常见失败：

| 错误 | 含义 |
|-------|---------|
| `ReferenceError: document is not defined` | 你试图在 Agent 上下文中使用浏览器 DOM API。请改用 `page.extract(...)` 或 `page.evaluate(...)`。 |
| `ReferenceError: require is not defined` | Agent 脚本不是 Node.js 脚本。 |
| `no page loaded - run page.goto(url) first` | 依赖页面的原语在导航之前被调用。 |
| `invalid arguments` | 原语收到的参数数量或形态不对，或包含了不可 JSON 序列化的值。 |
| `extract: no schema selector matched any element` | schema 中每个字段都没匹配到。请修复选择器；页面区块为空时各字段会得到 `null`/`[]`，而不是这个错误。 |

完整列表见 [PandaScript 参考](/reference/pandascript#错误)。

## 完整示例

这个脚本打开 Hacker News，提取五条帖子，逐个访问评论页，最后打印一个
JSON 对象。循环与对象组装都发生在本地 Agent 脚本中，而不是页面里。

```js copy
const HN = "https://news.ycombinator.com";

const page = new Page();
await page.goto(HN);

const { stories } = page.extract({
  stories: [{
    selector: "tr.athing",
    limit: 5,
    fields: {
      id: { attr: "id" },
      title: ".titleline > a",
      url: { selector: ".titleline > a", attr: "href" }
    }
  }]
});

for (const story of stories) {
  story.comments = [];
  if (!story.id) continue;

  await page.goto(`${HN}/item?id=${story.id}`);
  const { comments } = page.extract({
    comments: [{
      selector: "tr.athing.comtr:has(.commtext)",
      limit: 3,
      fields: {
        author: ".hnuser",
        text: ".commtext"
      }
    }]
  });
  story.comments = comments;
}

return stories; // printed automatically as JSON
```
