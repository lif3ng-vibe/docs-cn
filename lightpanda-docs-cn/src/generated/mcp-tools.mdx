## 仅 MCP 工具

这些工具只存在于 MCP 服务器中，agent 与脚本里没有。在 [HTTP 传输](/usage/mcp#http-传输)模式下，每次工具调用都运行在 `Mcp-Session-Id` 请求头指定的会话里，缺省时落到始终存在的 `default` 会话；`session_*` 工具负责创建、列出与关闭这些会话。

### save

**把会话保存为 agent 脚本。** 将会话保存为可复用的 Lightpanda agent 脚本。对话由你掌握，所以 `script` 由你亲自合成——先写 `const page = new Page(); await page.goto(url);`，再把你在工具里用过的内建（extract、click、fill……）作为 `page` 上的方法调用，参数对象保持一致。保留 `$LP_*` 占位符；绝不把已解析的密钥内联进去。

把这段会话提炼成一个 Lightpanda agent 脚本（.js），它日后单独运行时能复现用户想完成的事。你复现的是用户的目标，不是回放对话记录：
- 从整段对话（包括用户的纠正）推断目标——用户最终意图优先于最初的表述。
- 只保留干净重跑所需的步骤，按实际生效的顺序。丢掉失败的尝试、重试、死胡同与探索性读取（那些只为决定下一步服务的 tree/markdown/extract 探测）。
- 你在工具调用之间做的推理——比较、过滤、挑选、跨页汇总——都化为普通的顶层 JavaScript，让脚本无需你也能到达结果。
- 读取页面用 page.extract(schema)——`const page = new Page(); await page.goto(url); page.extract({...})`。CSS 选择器把文本与属性提为字符串，对这些字符串做的一切 trim/split/regex/parse/merge 都是顶层 JavaScript。不要写先 querySelect 页面再加工结果的 page.evaluate(...)——那是 page.extract + 顶层 JS。page.evaluate 只用于必须在页面内执行、且没有内建能覆盖的部分。顶层变量在导航之间也会保留；页面上下文里的东西每次导航都被清空。
忠于真正生效的调用：参数与选项都用它们实际用过的。不要添加会话没用过的 `timeout`（或任何选项）。绝不让结果在 `lp.*` 里绕一圈，也绝不在结尾追加空转的 page.extract(...) 探测或 `page.evaluate("return lp....")` 尾巴来"露出"输出。
用简短的 `//` 意图注释标注脚本，让后来的读者一眼看懂：每个逻辑块（导航、提取列表、扇出到详情页、汇总、返回）上方一条注释，说明这个块为达成目标做了什么——不是复述 API 调用。一步一条注释，而不是一行一条；不言自明的行不用注释。
只输出 JavaScript 源码本身，外面不要包 markdown 围栏或散文。

脚本规则：
- `Page` 是唯一的全局。`new Page()` 造一个页面；`await page.goto(url)` 导航它（异步——务必 `await`）。其余全部内建都是这个页面上的同步方法：`const data = page.extract({...})`，绝不 `await page.extract`。文件作为 async 脚本运行，顶层 `await` 可用。
- 读取页面用 page.extract(schema)；对返回字符串的全部加工（trim、split、parse、merge、循环、跨页汇总）都是脚本上下文里的普通顶层 JavaScript。page.evaluate(...) 只用于必须在页面内运行、且没有内建覆盖的 JS——绝不是 querySelector 再解析的代码块。它看不到脚本变量（把值插值进它的字符串），而且页面状态每次导航都被清空，脚本变量则持续存在。
- `return <value>` 是脚本的输出，自动打印（对象/数组以 JSON 形式）。以 `return page.extract({...});` 或 `return results;` 结尾——裸的末尾表达式不会被打印，console.log 与 JSON.stringify 也不会。
- 现代、可读的 JS：`const`/`let`、`for (const x of xs)`、模板字符串、解构、2 空格缩进。

| 参数 | 类型 | 必填 | 描述 |
|---|---|---|---|
| `path` | string | yes | 脚本写入的相对路径（不允许 '..' 段）。文件会被创建或覆盖。响应里报告绝对位置。 |
| `script` | string | yes | 要写入的 JavaScript agent 脚本。按本工具的描述自行合成。 |

提示：destructive, idempotent

### session_new

**创建隔离的浏览器会话。** 创建一个新的隔离浏览器会话（拥有自己的页面、Cookie 与内存）并返回其 id。用它给另一个 agent 独立的浏览上下文，或取一个 id 供分享。之后把该 id 作为 `Mcp-Session-Id` 请求头传回，调用就会路由到它。需要 HTTP 传输（`lightpanda mcp --port <PORT>`）；stdio 模式下只有 `default` 会话，此调用会返回错误。

| 参数 | 类型 | 必填 | 描述 |
|---|---|---|---|
| `name` | string | no | 可选的新会话 id。省略则自动生成。复用已存在的 id 会返回那个会话（在多个 agent 之间共享同一浏览上下文的办法）。 |

提示：idempotent

### session_list

**列出浏览器会话。** 列出活跃的浏览器会话及其 id 与当前 URL。`default` 会话始终存在。需要 HTTP 传输（`lightpanda mcp --port <PORT>`）；stdio 模式下只有 `default` 会话，此调用会返回错误。

无参数。

提示：read-only, idempotent

### session_close

**关闭浏览器会话。** 关闭一个浏览器会话，释放其页面与内存。`default` 会话不可关闭。需要 HTTP 传输（`lightpanda mcp --port <PORT>`）；stdio 模式下只有 `default` 会话，此调用会返回错误。

| 参数 | 类型 | 必填 | 描述 |
|---|---|---|---|
| `id` | string | yes | 会话 id。 |

提示：destructive

## 资源

宿主应用通过 `resources/read` 读取这些资源。页面类资源需要已加载的页面；skill 资源不需要。

| URI | MIME 类型 | 描述 |
|---|---|---|
| `mcp://page/html` | `text/html` | 当前页面序列化的 HTML DOM |
| `mcp://page/markdown` | `text/markdown` | 当前页面节省 token 的 markdown 表示 |
| `mcp://skill/pandascript` | `text/markdown` | 编写 PandaScript agent 脚本（.js）——Lightpanda 可回放的浏览器自动化格式，用 `lightpanda run script.js` 免 token 运行。 |

```json copy
{"jsonrpc":"2.0","id":2,"method":"resources/read",
 "params":{"uri":"mcp://page/markdown"}}
```

`markdown` 工具与 `mcp://page/markdown` 资源返回同样的内容，区别只在谁发起：agent 在工作流中调用**工具**，宿主应用读取**资源**——比如 IDE 在后台展示页面状态。
