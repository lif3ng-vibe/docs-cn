# 什么是集成？

AG-UI 集成让你的智能体（agent）会"说" AG-UI 协议。这意味着你的智能体可以与任何兼容 AG-UI 的客户端应用协作——比如对话界面、copilot 或自定义 AI 工具。

可以把它想象成给你的智能体装上一个通用翻译器。你无需为每个客户端分别定制 API，只需实现一次 AG-UI，就能立刻与任何兼容应用协同工作。

接入 AG-UI 的智能体可以：
- **流式输出响应**——文本边生成边实时呈现
- **调用客户端侧工具**——你的智能体可以使用客户端定义的函数与服务
- **共享状态**——智能体状态成为双向的共享状态
- **通用执行**——可与任何兼容 AG-UI 的客户端应用集成
- **还有更多**——完整规范请见[这里](/concepts/events)。

### 什么时候需要自己做集成？
如果你要找的集成不在[集成页面](/integrations)的列表里，就需要自己动手做一个。下文提供了几份相关指南！

不过，如果你想使用现成的集成（比如 LangGraph、CrewAI、Mastra 等），可以跳过这一步，直接前往[构建应用](/quickstart/applications)。

### 何时使用服务端实现
服务端实现让你可以直接从智能体或服务端发出 AG-UI 事件。如果你没有使用智能体框架，或者还没有为所用框架设计过协议，这是最好的入门方式。

服务端实现也适合以下场景：
- 从零开始构建**全新的智能体框架**
- 对事件如何发出、发出哪些事件拥有**最大限度的控制**
- 把你的智能体暴露为**独立的 API**

### 何时使用中间件实现
中间件是更灵活的方案。它让你能把现有协议与应用翻译成 AG-UI 事件，在现有系统与 AG-UI 之间架起一座桥梁。

中间件适合以下场景：
- 拿着你的**现有协议或 API**，把它**翻译成通用格式**
- 在**现有系统或框架**的约束下工作
- **当你无法直接控制**智能体框架或系统时
