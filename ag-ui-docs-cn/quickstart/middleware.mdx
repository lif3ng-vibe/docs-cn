# 简介

中间件实现让你可以**把现有协议与应用翻译成 AG-UI 事件**。这种方式会在现有系统与 AG-UI 之间架起一座桥梁，非常适合为现有应用添加智能体（agent）能力。

## 何时使用中间件实现

中间件是更灵活的方案。它让你能把现有协议与应用翻译成 AG-UI 事件，在现有系统与 AG-UI 之间架起一座桥梁。

中间件适合以下场景：

- 拿着你的**现有协议或 API**，把它**翻译成通用格式**
- 在**现有系统或框架**的约束下工作
- **当你无法直接控制**智能体框架或系统时

## 我们要构建什么

在本指南中，我们将创建一个中间件智能体，它能够：

1. 继承 `AbstractAgent` 类
2. 连接 OpenAI 的 GPT-4o 模型
3. 把 OpenAI 的响应翻译成 AG-UI 事件
4. 以进程内方式随你的应用一起运行

这种方式让你在保留 AG-UI 协议全部能力的同时，最大限度地灵活对接现有代码库。

这个占位智能体目前的逻辑如下：

```ts
// integrations/openai/src/index.ts
import {
  AbstractAgent,
  BaseEvent,
  EventType,
  RunAgentInput,
} from "@ag-ui/client"
import { Observable } from "rxjs"

export class OpenAIAgent extends AbstractAgent {
  run(input: RunAgentInput): Observable<BaseEvent> {
    const messageId = Date.now().toString()
    return new Observable<BaseEvent>((observer) => {
      observer.next({
        type: EventType.RUN_STARTED,
        threadId: input.threadId,
        runId: input.runId,
      } as any)

      observer.next({
        type: EventType.TEXT_MESSAGE_START,
        messageId,
      } as any)

      observer.next({
        type: EventType.TEXT_MESSAGE_CONTENT,
        messageId,
        delta: "Hello world!",
      } as any)

      observer.next({
        type: EventType.TEXT_MESSAGE_END,
        messageId,
      } as any)

      observer.next({
        type: EventType.RUN_FINISHED,
        threadId: input.threadId,
        runId: input.runId,
      } as any)

      observer.complete()
    })
  }
}
```

## 第 4 步——把 OpenAI 接入 AG-UI

我们来把这个占位实现改造成一个真正从 OpenAI 流式获取补全结果的智能体。

### 安装 OpenAI SDK

首先，我们需要 OpenAI SDK：

```bash
cd integrations/openai
pnpm install openai
```

### AG-UI 要点回顾

一个 AG-UI 智能体会继承 `AbstractAgent`，并发出一串事件来表示：

- 生命周期事件（`RUN_STARTED`、`RUN_FINISHED`、`RUN_ERROR`）
- 内容事件（`TEXT_MESSAGE_*`、`TOOL_CALL_*` 等）

### 实现流式智能体

现在我们把这个占位智能体改造成一个真正的 OpenAI 集成。关键区别在于：我们将不再发送硬编码的 "Hello world!" 消息，而是连接 OpenAI 的 API，并通过 AG-UI 事件把响应流式传回。

实现沿用与占位实现相同的事件流，但我们会把 OpenAI 客户端的初始化放进构造函数，并用真实的 API 调用取代模拟响应。如果响应中包含工具调用，我们也会进行处理，让智能体在需要时能够完整地使用函数。

```typescript
// integrations/openai/src/index.ts
import {
  AbstractAgent,
  RunAgentInput,
  EventType,
  BaseEvent,
} from "@ag-ui/client"
import { Observable } from "rxjs"

import { OpenAI } from "openai"

export class OpenAIAgent extends AbstractAgent {
  private openai: OpenAI

  constructor(openai?: OpenAI) {
    super()
    // Initialize OpenAI client - uses OPENAI_API_KEY from environment if not provided
    this.openai = openai ?? new OpenAI()
  }

  run(input: RunAgentInput): Observable<BaseEvent> {
    return new Observable<BaseEvent>((observer) => {
      // Same as before - emit RUN_STARTED to begin
      observer.next({
        type: EventType.RUN_STARTED,
        threadId: input.threadId,
        runId: input.runId,
      } as any)

      // NEW: Instead of hardcoded response, call OpenAI's API
      this.openai.chat.completions
        .create({
          model: "gpt-4o",
          stream: true, // Enable streaming for real-time responses
          // Convert AG-UI tools format to OpenAI's expected format
          tools: input.tools.map((tool) => ({
            type: "function",
            function: {
              name: tool.name,
              description: tool.description,
              parameters: tool.parameters,
            },
          })),
          // Transform AG-UI messages to OpenAI's message format
          messages: input.messages.map((message) => ({
            role: message.role as any,
            content: message.content ?? "",
            // Include tool calls if this is an assistant message with tools
            ...(message.role === "assistant" && message.toolCalls
              ? {
                  tool_calls: message.toolCalls,
                }
              : {}),
            // Include tool call ID if this is a tool result message
            ...(message.role === "tool"
              ? { tool_call_id: message.toolCallId }
              : {}),
          })),
        })
        .then(async (response) => {
          const messageId = Date.now().toString()

          // NEW: Stream each chunk from OpenAI's response
          for await (const chunk of response) {
            // Handle text content chunks
            if (chunk.choices[0].delta.content) {
              observer.next({
                type: EventType.TEXT_MESSAGE_CHUNK, // Chunk events open and close messages automatically
                messageId,
                delta: chunk.choices[0].delta.content,
              } as any)
            }
            // Handle tool call chunks (when the model wants to use a function)
            else if (chunk.choices[0].delta.tool_calls) {
              let toolCall = chunk.choices[0].delta.tool_calls[0]

              observer.next({
                type: EventType.TOOL_CALL_CHUNK,
                toolCallId: toolCall.id,
                toolCallName: toolCall.function?.name,
                parentMessageId: messageId,
                delta: toolCall.function?.arguments,
              } as any)
            }
          }

          // Same as before - emit RUN_FINISHED when complete
          observer.next({
            type: EventType.RUN_FINISHED,
            threadId: input.threadId,
            runId: input.runId,
          } as any)

          observer.complete()
        })
        // NEW: Handle errors from the API
        .catch((error) => {
          observer.next({
            type: EventType.RUN_ERROR,
            message: error.message,
          } as any)

          observer.error(error)
        })
    })
  }
}
```

### 底层发生了什么？

我们来拆解一下你的智能体在做什么：

1. **初始化**——创建 OpenAI 客户端并发出 `RUN_STARTED`
2. **请求**——把用户消息连同 `stream: true` 发送给 `chat.completions`
3. **流式传输**——把每个 chunk 转发为 `TEXT_MESSAGE_CHUNK` 或 `TOOL_CALL_CHUNK`
4. **收尾**——发出 `RUN_FINISHED`（如果出错则发出 `RUN_ERROR`），并结束这个 observable

## 把 AG-UI 桥接到任意协议

你刚刚实现的那套模式——翻译输入、转发流式 chunk、发出 AG-UI 事件——几乎适用于任何后端：

- REST 或 GraphQL API
- WebSockets
- MQTT 之类的 IoT 协议

## 把智能体连接到前端

[CopilotKit](https://docs.copilotkit.ai) 这类工具已经原生理解 AG-UI，并提供即插即用的 React 组件。把它们指向你的智能体端点，就能直接得到一个功能齐全的对话 UI。
