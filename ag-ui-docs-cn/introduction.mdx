# 智能体–用户交互协议（AG-UI）


AG-UI 是一个<u><strong>开放</strong></u>、<u><strong>轻量</strong></u>、<u><strong>基于事件</strong></u>的协议，用于规范化 AI 智能体（agent）与面向用户的应用之间的连接方式。

AG-UI 的设计目标，是在面向用户的应用与任意智能体后端（agentic backend）之间，架起一条通用的双向连接。

它为简洁与灵活而生，规范化了智能体状态、UI 意图（UI intent）和用户交互在模型/智能体运行时与面向用户的前端应用之间的流转方式——让应用开发者能够快速交付可靠、易调试、对用户友好的智能体功能，同时专注于应用自身的需求，避免复杂的一次性适配接线。

## 智能体协议

<Note>
<strong>分不清 "A2UI" 和 "AG-UI"？</strong>这很正常！尽管名字相似，两者其实截然不同，而且能很好地配合使用。A2UI 是一套[生成式 UI 规范](./concepts/generative-ui-specs)——让智能体可以输出 UI 组件；而 AG-UI 是智能体↔用户交互协议——负责把智能体前端连接到任意智能体后端。[了解更多](https://copilotkit.ai/ag-ui-and-a2ui)
</Note>

AG-UI 是三大知名开放[智能体协议](./agentic-protocols)之一。

| **层级** | **协议 / 示例** | **用途** |
| --- | --- | --- |
| **智能体 ↔ 用户交互** | **AG-UI<br />(Agent–User Interaction Protocol)** | 开放、基于事件的标准，把智能体连接到面向用户的应用——支持实时、多模态、可交互的体验。 |
| **智能体 ↔ 工具与数据** | **MCP <br />(Model Context Protocol)** | 开放标准（由 Anthropic 发起），让智能体能够安全地连接外部系统——工具、工作流与数据源。 |
| **智能体 ↔ 智能体** | **A2A<br />(Agent to Agent)** | 开放标准（由 Google 发起），定义了智能体如何在分布式智能体系统之间协作与分工。 |

## 为什么智能体应用需要 AG-UI

智能体应用打破了前智能体时代主导前后端开发的简单请求/响应模型：客户端发起请求，服务端返回数据，客户端完成渲染，交互随之结束。

#### 面向用户的智能体有哪些特殊要求

智能体虽然本质上也是软件，却表现出一些特性，使得很难用传统 REST/GraphQL API 在背后为它们提供服务：

- 智能体**长时间运行**，并会**流式输出**中间工作成果——往往跨越多轮会话。
- 智能体的行为是**非确定性的**，还能**以非确定的方式控制应用 UI**。
- 智能体会同时混合**结构化 + 非结构化 IO**（例如文本与语音，以及工具调用和状态更新）。
- 智能体需要支持用户交互的**组合**：例如它们可能调用子智能体，而且常常是递归调用。
- 还有更多……

AG-UI 是一个基于事件的协议，让智能体前端与后端之间能够动态通信。它构建在 Web 的基础协议（HTTP、WebSockets）之上，是一个为智能体时代设计的抽象层——弥合了传统客户端-服务端架构与 AI 智能体动态、有状态特性之间的鸿沟。

### 客户端

| 客户端 | 状态 | AG-UI 资源 | 集成 |
| :----- | ------ | --------------- | ------------ |
| [CopilotKit](https://github.com/CopilotKit/CopilotKit) | 已支持 | [入门](https://docs.copilotkit.ai/direct-to-llm/guides/quickstart) | 一方官方 |
| [Terminal + Agent]() | 已支持 | [入门](https://docs.ag-ui.com/quickstart/clients) | 社区 |
| 聊天平台（Slack、Microsoft Teams） | 已支持 | [Channels SDK](https://github.com/CopilotKit/channels-sdk), [OpenTag 示例](https://github.com/CopilotKit/OpenTag) | 一方官方 |
| [React Native](https://reactnative.dev/) | 已支持 | [示例](https://github.com/CopilotKit/CopilotKit/tree/main/examples/v2/react-native/demo) | 一方官方 |
| [OpenBot](https://open.bot) | 已支持 | [入门](https://open.bot/builders), [源码](https://github.com/CopilotKit/OpenBot) | 一方官方 |

AG-UI 客户端并不非得是 Web 应用。协议描述的是事件流，而不是某个渲染目标，因此终端（terminal）、移动应用或聊天平台都可以充当客户端。

聊天平台客户端是任何人都能够基于 AG-UI 构建的东西。[Channels SDK](https://github.com/CopilotKit/channels-sdk) 就是它的一个实现，而 [OpenTag](https://github.com/CopilotKit/OpenTag) 则是构建在其上的一个完整应用：一个 Python LangGraph 智能体，通过 AG-UI 接入 Slack 和 Microsoft Teams。在这个应用里，智能体及其运行时由使用者自行托管，而平台凭据与消息投递则交给 CopilotKit Intelligence 处理——这是一项托管服务，并不属于协议的一部分。

[OpenBot](https://open.bot) 是位于协议客户端侧的一个完整应用：一个面向 AI 协作者（AI coworker）的开源工作区，可以连接任意 AG-UI 智能体端点。每位协作者都可以分到一台属于自己的"电脑"，配有浏览器、文件与工具，而且它执行的每一个动作都会先对照部署方的策略校验通过后才运行。这个应用由你自己托管。它的会话线程与记忆保存在 CopilotKit Intelligence 中——这是一项独立于协议之外的服务，既可以由 CopilotKit 代为托管，也可以自行部署运行。
