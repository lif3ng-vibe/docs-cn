# 工具

工具是 AG-UI 协议中的一个基础概念，它让 AI 智能体能够与外部系统交互，并把人类判断融入自己的工作流。

AG-UI 区分由智能体后端定义的工具与客户端在运行时提供的工具。后端定义的工具保留在后端智能体或框架配置中；客户端定义的工具通过 `RunAgentInput.tools` 传入，智能体借此可以回调应用专属的前端行为，例如 UI 操作、审批或需要用户参与的工作流。

## 什么是工具？

在 AG-UI 中，工具是智能体可以调用的函数，用来：

1. 请求特定的信息
2. 在外部系统中执行操作
3. 请求人类输入或确认
4. 访问专门的能力

工具在 AI 推理与真实世界动作之间架起桥梁，让智能体能够完成单靠对话不可能完成的任务。

## 工具结构

工具遵循一致的结构，定义其名称、用途与预期参数：

```typescript
interface Tool {
  name: string // Unique identifier for the tool
  description: string // Human-readable explanation of what the tool does
  parameters: {
    // JSON Schema defining the tool's parameters
    type: "object"
    properties: {
      // Tool-specific parameters
    }
    required: string[] // Array of required parameter names
  }
}
```

`parameters` 字段使用 [JSON Schema](https://json-schema.org/) 定义工具所接受参数的结构。这份 schema 同时被智能体（用于生成合法的工具调用）和前端（用于校验与解析工具参数）使用。

## 前端定义的工具

AG-UI 工具系统的一个关键特点：工具在前端定义，并在执行期间传给智能体：

```typescript
// Define tools in the frontend
const userConfirmationTool = {
  name: "confirmAction",
  description: "Ask the user to confirm a specific action before proceeding",
  parameters: {
    type: "object",
    properties: {
      action: {
        type: "string",
        description: "The action that needs user confirmation",
      },
      importance: {
        type: "string",
        enum: ["low", "medium", "high", "critical"],
        description: "The importance level of the action",
      },
    },
    required: ["action"],
  },
}

// Pass tools to the agent during execution
agent.runAgent({
  tools: [userConfirmationTool],
  // Other parameters...
})
```

这种方式有几个优点：

1. **前端掌控**：由前端决定智能体可以使用哪些能力
2. **动态能力**：可以根据用户权限、上下文或应用状态增删工具
3. **关注点分离**：智能体专注于推理，前端负责工具的实现
4. **安全性**：敏感操作由应用控制，而不是由智能体控制

`RunAgentInput.tools` 只用于这些客户端提供的工具。它并不打算装下后端智能体可用的每一个工具。如果你的集成里有后端工具，请在后端框架中定义它们，或通过智能体能力宣告，而不是由客户端发送它们的 schema。

## 工具调用生命周期

智能体需要使用工具时，遵循一套标准化的事件序列：

1. **ToolCallStart**：以唯一 ID 和工具名称标志一次工具调用的开始

   ```typescript
   {
     type: EventType.TOOL_CALL_START,
     toolCallId: "tool-123",
     toolCallName: "confirmAction",
     parentMessageId: "msg-456" // Optional reference to a message
   }
   ```

2. **ToolCallArgs**：在参数生成的同时流式传输

   ```typescript
   {
     type: EventType.TOOL_CALL_ARGS,
     toolCallId: "tool-123",
     delta: '{"act' // Partial JSON being streamed
   }
   ```

   ```typescript
   {
     type: EventType.TOOL_CALL_ARGS,
     toolCallId: "tool-123",
     delta: 'ion":"Depl' // More JSON being streamed
   }
   ```

   ```typescript
   {
     type: EventType.TOOL_CALL_ARGS,
     toolCallId: "tool-123",
     delta: 'oy the application to production"}' // Final JSON fragment
   }
   ```

3. **ToolCallEnd**：标志工具调用完成
   ```typescript
   {
     type: EventType.TOOL_CALL_END,
     toolCallId: "tool-123"
   }
   ```

前端累积这些增量，还原出完整的工具调用参数。工具调用完成后，前端即可执行该工具，并把结果回传给智能体。

### 工具调用元数据

这三个事件都可以携带 `metadata` 对象，而且它累积在**工具调用本身**上，而不是拥有它的助手消息上：

```typescript
assistantMessage.toolCalls[0].metadata
// { provider: "anthropic", latencyMs: 84 }
```

这是有意为之。一条助手消息可能拥有多个工具调用，若把它们的元数据都折叠进父消息，结果就会取决于这些调用恰好交错的顺序。让每次工具调用拥有自己的元数据，才能保持无歧义。

`ToolCallResult` 则不同——它会创建一条工具消息，因此其元数据会像其他构建消息的事件一样合并进那条消息。见[元数据](/concepts/metadata)。

## 工具结果

工具执行完成后，结果以“工具消息”的形式回传给智能体：

```typescript
{
  id: "result-789",
  role: "tool",
  content: "true", // Tool result as a string
  toolCallId: "tool-123" // References the original tool call
}
```

这条消息会进入对话历史，智能体因此在后续响应中可以引用并利用工具的结果。

如果工具没有执行成功，把 `error` 设为失败信息：

```typescript
{
  id: "result-789",
  role: "tool",
  content: "Deployment blocked: the production environment is locked",
  toolCallId: "tool-123",
  error: "the production environment is locked" // Marks this result as a failure
}
```

`error` 是协议表达客户端侧工具失败的方式。没有它，失败的工具与成功的工具将无从区分——前端碰巧放在 `content` 里的内容就是智能体拥有的全部线索。完整的 `ToolMessage` 结构见[消息](/concepts/messages)。

## 人在回路工作流

AG-UI 的工具系统在实现人在回路工作流方面尤为强大。通过定义请求人类输入或确认的工具，开发者可以创造出把自主运行与人类判断无缝结合的 AI 体验。

例如：

1. 智能体需要做一个重要决策
2. 智能体带上决策细节调用 `confirmAction` 工具
3. 前端向用户展示确认对话框
4. 用户给出自己的输入
5. 前端把用户的决定回传给智能体
6. 智能体带着对用户选择的认知继续处理

这一模式支撑的用例包括：

- **审批工作流**：AI 建议需要人类批准的操作
- **数据校验**：由人类核实或修正 AI 生成的数据
- **协作决策**：AI 与人类共同解决复杂问题
- **有监督学习**：人类反馈改进 AI 未来的决策

## CopilotKit 集成

[CopilotKit](https://docs.copilotkit.ai/) 通过其 [`useCopilotAction`](https://docs.copilotkit.ai/guides/frontend-actions) hook，为在 React 应用中使用 AG-UI 工具提供了简化方式：

```tsx
import { useCopilotAction } from "@copilotkit/react-core"

// Define a tool for user confirmation
useCopilotAction({
  name: "confirmAction",
  description: "Ask the user to confirm an action",
  parameters: {
    type: "object",
    properties: {
      action: {
        type: "string",
        description: "The action to confirm",
      },
    },
    required: ["action"],
  },
  handler: async ({ action }) => {
    // Show a confirmation dialog
    const confirmed = await showConfirmDialog(action)
    return confirmed ? "approved" : "rejected"
  },
})
```

这种方式让定义工具变得简单：工具可以直接与你的 React 组件集成，并以干净、声明式的方式处理工具执行逻辑。

## 工具示例

下面是 AG-UI 应用中常见的几类工具：

### 用户确认

```typescript
{
  name: "confirmAction",
  description: "Ask the user to confirm an action",
  parameters: {
    type: "object",
    properties: {
      action: {
        type: "string",

      },

        type: "string",
        enum: ["low", "medium", "high", "critical"],
        description: "The importance level"
      }
    },
    required: ["action"]
  }
}
```

### 数据获取

```typescript
{
  name: "fetchUserData",
  description: "Retrieve data about a specific user",
  parameters: {
    type: "object",
    properties: {
      userId: {
        type: "string",
        description: "ID of the user"
      },
      fields: {
        type: "array",
        items: {
          type: "string"
        },
        description: "Fields to retrieve"
      }
    },
    required: ["userId"]
  }
}
```

### 界面控制

```typescript
{
  name: "navigateTo",
  description: "Navigate to a different page or view",
  parameters: {
    type: "object",
    properties: {
      destination: {
        type: "string",

      },

        type: "object",
        description: "Optional parameters for the navigation"
      }

### 内容生成

```

## 最佳实践

为 AG-UI 设计工具时：

1. **命名清晰**：使用描述性的、面向动作的名称
2. **描述详尽**：写清楚工具的用途，帮助智能体理解何时以及如何使用它
3. **参数结构化**：定义精确的参数 schema，字段名要有描述性并加上约束
4. **必填字段**：只在真正必要时才把参数标记为必填
5. **错误处理**：在工具执行代码中实现健壮的错误处理
6. **用户体验**：为人类决策设计能提供恰当上下文的工具 UI

## 结语

AG-UI 的工具在 AI 推理与真实世界动作之间架起桥梁，支撑起结合 AI 与人类智慧各自优势的精细工作流。通过在前端定义工具并传给智能体，开发者可以打造出 AI 与人类高效协作的交互体验。

工具系统在实现人在回路工作流方面尤其强大：AI 可以建议操作，但把关键决策留给人类。这在自动化与人类判断之间取得平衡，造就既强大又可信的 AI 体验。
