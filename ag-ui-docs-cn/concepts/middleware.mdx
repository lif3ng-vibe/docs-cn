# 中间件

AG-UI 的中间件提供了一种强大的方式，可以转换、过滤和增强流经智能体的事件流。它让你能够在不改动核心智能体逻辑的前提下，加入日志、鉴权、限流、事件过滤等横切关注点。

以下示例假设相关 RxJS 操作符/工具（`map`、`tap`、`catchError`、`switchMap`、`timer` 等）均已导入。

## 什么是中间件？

中间件位于智能体执行与事件消费方之间，让你能够：

1. **转换事件**——在事件流经管道时修改或增强它们
2. **过滤事件**——有选择地放行或拦截某些事件
3. **添加元数据**——注入额外的上下文或追踪信息
4. **处理错误**——实现自定义的错误恢复策略
5. **监控执行**——增加日志、指标或调试能力

## 中间件的工作方式

中间件构成一条链，每个中间件包裹下一个，形成一层层叠加的功能。智能体运行时，事件流依次流过每个中间件。

```typescript
import { AbstractAgent } from "@ag-ui/client"

const agent = new MyAgent()

// Middleware chain: logging -> auth -> filter -> agent
agent.use(loggingMiddleware, authMiddleware, filterMiddleware)

// When agent runs, events flow through all middleware
await agent.runAgent()
```

通过 `agent.use(...)` 添加的中间件会在 `runAgent()` 中生效。`connectAgent()` 目前直接调用 `connect()`，不执行中间件。

## 函数式中间件

对于简单的转换，可以使用函数式中间件。这是添加中间件最简洁的方式：

```typescript
import { MiddlewareFunction } from "@ag-ui/client"
import { EventType } from "@ag-ui/core"

const prefixMiddleware: MiddlewareFunction = (input, next) => {
  return next.run(input).pipe(
    map(event => {
      if (
        event.type === EventType.TEXT_MESSAGE_CHUNK ||
        event.type === EventType.TEXT_MESSAGE_CONTENT
      ) {
        return {
          ...event,
          delta: `[AI]: ${event.delta}`
        }
      }
      return event
    })
  )
}

agent.use(prefixMiddleware)
```

## 类式中间件

对于需要状态或配置的更复杂场景，请使用类式中间件：

```typescript
import { Middleware } from "@ag-ui/client"
import { Observable } from "rxjs"
import { tap } from "rxjs/operators"

class MetricsMiddleware extends Middleware {
  private eventCount = 0

  constructor(private metricsService: MetricsService) {
    super()
  }

  run(input: RunAgentInput, next: AbstractAgent): Observable<BaseEvent> {
    const startTime = Date.now()

    return this.runNext(input, next).pipe(
      tap(event => {
        this.eventCount++
        this.metricsService.recordEvent(event.type)
      }),
      finalize(() => {
        const duration = Date.now() - startTime
        this.metricsService.recordDuration(duration)
        this.metricsService.recordEventCount(this.eventCount)
      })
    )
  }
}

agent.use(new MetricsMiddleware(metricsService))
```

如果你在编写类中间件，优先使用这些辅助方法：
- `runNext(input, next)` 把 chunk 事件规范化为完整的 `TEXT_MESSAGE_*`/`TOOL_CALL_*` 序列。
- `runNextWithState(input, next)` 还会在每个事件之后提供累积的 `messages` 与 `state`。

## 内置中间件

AG-UI 为常见用例提供了几个内置中间件组件：

### FilterToolCallsMiddleware

基于允许或禁止列表过滤工具调用：

```typescript
import { FilterToolCallsMiddleware } from "@ag-ui/client"

// Only allow specific tools
const allowedFilter = new FilterToolCallsMiddleware({
  allowedToolCalls: ["search", "calculate"]
})

// Or block specific tools
const blockedFilter = new FilterToolCallsMiddleware({
  disallowedToolCalls: ["delete", "modify"]
})

agent.use(allowedFilter)
```

`FilterToolCallsMiddleware` 过滤已发出的 `TOOL_CALL_*` 事件。它不会阻止上游模型/运行时中的工具执行。

## 中间件模式

常见模式包括日志、基于 `forwardedProps` 的鉴权以及限流。具体实现见 [JS 中间件参考](/sdk/js/client/middleware)。

## 组合中间件

你可以组合多个中间件，构建复杂的处理管道：

```typescript
const logMiddleware: MiddlewareFunction = (input, next) => next.run(input)
const metricsMiddleware = new MetricsMiddleware(metricsService)
const filterMiddleware = new FilterToolCallsMiddleware({ allowedToolCalls: ["search"] })

agent.use(logMiddleware, metricsMiddleware, filterMiddleware)
```

## 执行顺序

中间件按添加顺序执行，每个中间件包裹下一个：

1. 第一个中间件接收原始输入
2. 它可以在传给下一个中间件之前修改输入
3. 每个中间件处理链中下一个中间件的事件
4. 最后一个中间件调用真正的智能体

```typescript
agent.use(middleware1, middleware2, middleware3)

// Execution flow:
// → middleware1
//   → middleware2
//     → middleware3
//       → agent.run()
//     ← events flow back through middleware3
//   ← events flow back through middleware2
// ← events flow back through middleware1
```

## `RUN_STARTED` 上的协议版本

每次运行的 `RUN_STARTED.protocolVersion` 标明的是这次运行的事件流所“说”的版本，而不是谁来转发它（[版本管理](/spec/1.0/basic/versioning#版本协商)）。对中间件而言，这意味着一条规则，由这次运行的产出方决定：

- **转发运行**。当 `RUN_STARTED` 来自链中的下一个智能体时，原样透传，不要动它的 `protocolVersion`：不要新增、覆盖或删除。如果下游智能体早于该字段出现，缺失声明才是如实的情况。
- **合成运行**。当中间件自行响应请求并发出自己的 `RUN_STARTED`（没有下游智能体运行）时，中间件就是这次运行的产出方。请用 SDK 的 `PROTOCOL_VERSION` 常量声明它构建时所针对的版本。不要照抄客户端的 `RunAgentInput.protocolVersion`，也不要省略该字段。
- **转译运行**。把事件流改写成另一种协议版本的中间件，声明它所发出的版本。

与任何其他产出方一样，合成运行使用输入中的 `threadId` 与 `runId`：

```typescript
import { EventType, PROTOCOL_VERSION, type RunStartedEvent } from "@ag-ui/client"

const runStarted: RunStartedEvent = {
  type: EventType.RUN_STARTED,
  threadId: input.threadId,
  runId: input.runId,
  protocolVersion: PROTOCOL_VERSION,
}
```

## 最佳实践

1. **保持中间件聚焦**——每个中间件应只承担单一职责
2. **优雅处理错误**——使用 RxJS 的错误处理操作符
3. **避免阻塞操作**——I/O 操作使用异步模式
4. **记录副作用**——如果中间件会修改状态，要明确说明
5. **独立测试中间件**——为每个中间件编写单元测试
6. **关注性能**——注意事件流中的处理开销

## 高级用例

### 条件中间件

根据运行时条件应用中间件：

```typescript
const conditionalMiddleware: MiddlewareFunction = (input, next) => {
  if (input.forwardedProps?.debug === true) {
    // Apply debug logging
    return next.run(input).pipe(
      tap(event => console.debug(event))
    )
  }
  return next.run(input)
}
```

事件转换与流控制的更多变体见 [JS 中间件参考](/sdk/js/client/middleware)。

## 结语

中间件提供了一种灵活而强大的方式，无需修改核心逻辑即可扩展 AG-UI 智能体。无论你需要简单的事件转换，还是复杂的有状态处理，中间件系统都提供了构建健壮、可维护的智能体应用所需的工具。
