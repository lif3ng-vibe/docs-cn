---
title: "中断"
description:
  "智能体–用户交互协议中的人在回路暂停与恢复"
---

智能体有时需要暂停：在执行敏感操作前等待人类批准、请求结构化输入，或等待带外的策略决策。AG-UI 把这一需求呈现为**中断感知的运行生命周期**（interrupt-aware run lifecycle）——一种终结式模型：运行以中断结果结束，客户端再启动一次新的运行，携带针对每个中断的响应。

## 生命周期

```mermaid
sequenceDiagram
  participant Agent
  participant Client as Client App

  Note over Agent,Client: Run 1 begins
  Agent-->>Client: RunStarted (runId: r1)
  Agent-->>Client: ...ToolCall* / TextMessage* / StateSnapshot...
  Note over Agent,Client: Agent needs user input — emit snapshot, then interrupt
  Agent-->>Client: RunFinished { outcome: { type: "interrupt", interrupts: [...] } }

  Note over Agent,Client: User resolves interrupts
  Client-->>Agent: RunAgentInput { threadId, resume: [{interruptId, status, payload?}, ...] }

  Note over Agent,Client: Run 2 begins; resume[].interruptId links back to run 1's interrupts
  Agent-->>Client: RunStarted (runId: r2)
  Agent-->>Client: ...continue / ToolCallResult / ...
  Agent-->>Client: RunFinished { outcome: { type: "success" }, result }
```

## 运行结果

`RunFinished` 携带一个可选的 `outcome` 字段——一个可辨识联合，变体专属的数据嵌套其中：

- **缺省**——旧式/向后兼容。按正常完成处理。尚不了解中断机制的既有 AG-UI 客户端仍会发出这种形态，新的读取方应当接受它。
- `{ type: "success" }`——运行正常完成。可选的 `result` 仍保留在事件根节点上，以向后兼容。
- `{ type: "interrupt", interrupts: [...] }`——运行因等待用户输入而暂停。`interrupts` 是一个非空数组，位于 outcome 内部，从而随需要它的变体一起传递。

```typescript
type RunFinishedOutcome =
  | { type: "success" }
  | { type: "interrupt"; interrupts: Interrupt[] }

type RunFinishedEvent = {
  type: "RUN_FINISHED"
  threadId: string
  runId: string
  result?: unknown
  outcome?: RunFinishedOutcome
}
```

由于 `outcome` 是可选的，从未听说过中断的旧式生产方（没有 `outcome` 字段）在新 schema 下仍然能通过 `RunFinished` 事件的校验——客户端只有在关心中断感知变体时才需要检查 `outcome`。

## Interrupt 类型

```typescript
type Interrupt = {
  id: string
  reason: string
  message?: string
  toolCallId?: string
  responseSchema?: JsonSchema
  expiresAt?: string
  metadata?: Record<string, any>
  subagentRunId?: string
}
```

| 字段             | 用途                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `id`             | 在中断、恢复、幂等与审计之间起关联作用的键。                                                                                                                                                                                                                                                                                                                                                                                    |
| `reason`         | 分类路由提示——见[原因分类](#原因分类)。                                                                                                                                                                                                                                                                                                                                                                                        |
| `message`        | 人类可读的提示语。通用的兜底 UI 内容。                                                                                                                                                                                                                                                                                                                                                                                          |
| `toolCallId`     | 把中断绑定到此前的 `ToolCall*` 事件序列。                                                                                                                                                                                                                                                                                                                                                                                       |
| `responseSchema` | 预期 `resume.payload` 的 JSON Schema。                                                                                                                                                                                                                                                                                                                                                                                          |
| `expiresAt`      | 可选的 ISO-8601 有效期。过期后的恢复会产生 `RunError`。                                                                                                                                                                                                                                                                                                                                                                         |
| `metadata`       | 自由格式的框架专属数据。                                                                                                                                                                                                                                                                                                                                                                                                        |
| `subagentRunId`  | 引发该中断的子智能体——由根级直接引发时缺省。归属信息按中断记录，因为一次运行可能携带来自多个子智能体的中断。会发出子智能体生命周期事件的生产方还会以 `outcome: { type: "suspended" }` 关闭该子智能体——生命周期事件仍然是可选的，因此这里的归属信息单独成立（见[子智能体](/concepts/subagents#挂起)）。 |

## 恢复运行

同一线程上的下一个 `RunAgentInput` 会携带一个 `resume` 数组：

```typescript
type RunAgentInput = {
  // ... existing fields
  resume?: Array<{
    interruptId: string
    status: "resolved" | "cancelled"
    payload?: any
    metadata?: Record<string, any>
  }>
}
```

- `resolved`——用户已回应。`payload` 携带响应内容，并按该中断的 `responseSchema` 校验。拒绝也在 payload 内部表达（例如 `{ approved: false }`），而不是单独的状态。
- `cancelled`——用户放弃且未提供有效输入。应省略 `payload`。
- `metadata`——关于该响应的可选信封数据（例如证明人类决策未被篡改的签名，或路由键），与 `payload` 相对——后者是智能体所要的、并将据此行动的答案。按键开放；键下允许任意 JSON 值，包括 `null`。对象本身要么缺省、要么是对象，绝不能是 `null`。`ag-ui` 键保留给 AG-UI 自用。两种状态下都可用。

## 契约规则

1. **同一线程**。恢复请求必须使用与被中断运行相同的 `threadId`。
2. **恢复关联**。`resume[].interruptId` 必须引用被中断运行的 `interrupts[]` 中出现的 `id`。`parentRunId` 与之正交——保留其既有的 AG-UI 分支/时间旅行语义。
3. **覆盖全部待处理中断**。单个 `resume` 数组必须逐一回应被中断运行中的每个待处理中断。不支持部分恢复。
4. **待处理中断阻塞新输入**。如果线程上存在未解决的中断，该线程上的任何 `RunAgentInput` 都必须包含针对它们的 `resume`。收到不符合要求的输入时，智能体必须发出 `RunError`。
5. **幂等性**。相同 `(threadId, interruptId, status, payload)` 的恢复请求必须可以安全重放。
6. **负载校验**。如果中断声明了 `responseSchema`，智能体可以校验对应的恢复 `payload`，并在不匹配时发出 `RunError`。客户端应在提交前自行校验。
7. **过期强制执行**。客户端不得在超过中断的 `expiresAt` 之后提交恢复。过期的恢复会产生 `RunError`。
8. **优雅处理**。智能体应通过 `RunError` 处理缺失或无效的恢复负载，而不是静默失败。

## 中断边界处的状态

中断发生时，智能体必须把恢复所需的全部状态通过 `StateSnapshot` 与 `MessagesSnapshot` 事件发出，且要在携带中断的 `RunFinished` 事件**之前**。

这条规则让协议与恢复模式无关：无论是重放式的续跑（从消息 + 状态重建上下文），还是检查点式的续跑（恢复一个被挂起的协程），在恢复时都必须产生完全一致的可观测行为。框架原生的检查点机制是实现层面的优化，不是协议契约。

## 错误处理

`RunError` 是唯一的错误事件。`outcome` 枚举中没有 `"error"` 取值。会触发 `RunError` 的中断相关错误情形：

- 恢复请求在超过中断的 `expiresAt` 之后到达。
- 恢复负载未通过其 `responseSchema` 的校验。
- 恢复请求引用了智能体无法关联的 `interruptId`。
- 恢复请求未能回应全部待处理中断（违反规则 3）。
- 存在待处理中断的线程上的 `RunAgentInput` 省略了 `resume`（违反规则 4）。

## 原因分类

`reason` 是必填字符串。一小部分核心取值由规范定义；其他任何字符串都是合法的扩展。

### 核心取值

| 取值             | 语义                                                 | 常见的伴随字段                      |
| ---------------- | ---------------------------------------------------- | ----------------------------------- |
| `tool_call`      | 绑定到某个等待决策的工具调用的中断。                 | 必须设置 `toolCallId`。             |
| `input_required` | 智能体需要结构化输入才能继续。                       | 应设置 `responseSchema`。           |
| `confirmation`   | 不绑定工具的独立“是/否”决策。                        | `responseSchema` 可选；默认布尔型。 |

### 自定义原因

其他任何字符串都合法。智能体应给自定义原因加上 `<framework>:<name>` 形式的命名空间前缀（例如 `langgraph:database_modification`、`mastra:workflow_suspend`）。`core:` 前缀保留给规范未来的新增内容。

### 客户端路由

- 对于已知的核心取值，客户端应据此切换到专门的 UI。
- 对于未知的原因，客户端不得报错。应基于 `message`、`responseSchema` 和 `metadata` 渲染。

## 绑定工具的中断

当中断携带 `reason: "tool_call"` 和 `toolCallId` 时，这次工具调用及其解决过程跨越两次运行。完整的审计链路是：

1. 被中断运行中的 `ToolCallArgs`（智能体的提议）。
2. 恢复运行中 `RunAgentInput.resume` 的负载（用户决策与编辑）。
3. 恢复运行中的 `ToolCallResult`（实际执行结果）。

智能体在恢复运行中**不会**重新发出 `ToolCallStart`/`ToolCallArgs`/`ToolCallEnd`——而是针对原始的 `toolCallId` 发出 `ToolCallResult`。

### 服务端持有的工具执行

生产方可以用 `metadata: { "ag-ui:tool-execution": "server" }` 标记一个绑定工具的中断，以明确标识该工具由服务端持有。客户端在 `resume` 中转达用户的批准或拒绝，且不得据此自行拼造工具结果消息。服务端会针对原始的 `toolCallId` 提供实际执行结果。.NET 适配器在原生工具审批请求中会发出这个标记。

持久化或恢复待处理中断时应保留这条元数据。它的缺失并不能证明工具归属；既有的前端完成契约保持不变。这个标记向客户端说明执行归属，并不是授权凭证：服务端仍必须校验决策，并拒绝客户端为服务端持有的工具提交的结果。

### 带编辑批准

对于支持“带编辑批准”的绑定工具中断，推荐的 `responseSchema` 模式：

```json
{
  "type": "object",
  "properties": {
    "approved": { "type": "boolean" },
    "editedArgs": {
      "type": "object",
      "description": "Full replacement of the tool args. Not merged."
    }
  },
  "required": ["approved"]
}
```

`editedArgs` 是整体替换，不是部分合并。它出现在 schema 中，就是一个**能力信号**，表示客户端可以提供编辑 UI。

## 示例

### 最小工具审批

智能体在提议 `sendEmail` 之后发起中断：

```json
{
  "type": "RUN_FINISHED",
  "threadId": "thread-1",
  "runId": "run-1",
  "outcome": {
    "type": "interrupt",
    "interrupts": [
      {
        "id": "int-abc123",
        "reason": "tool_call",
        "message": "Send email to a@b.com with subject 'Hi'?",
        "toolCallId": "tc-001",
        "responseSchema": {
          "type": "object",
          "properties": { "approved": { "type": "boolean" } },
          "required": ["approved"]
        }
      }
    ]
  }
}
```

客户端提交恢复请求：

```json
{
  "threadId": "thread-1",
  "runId": "run-2",
  "resume": [
    {
      "interruptId": "int-abc123",
      "status": "resolved",
      "payload": { "approved": true }
    }
  ]
}
```

智能体在 `run-2` 中继续执行，针对 `tc-001` 发出 `ToolCallResult`，然后发出 `RunFinished { outcome: { type: "success" } }`。

### 带编辑批准（完整审计）

```json
{
  "type": "RUN_FINISHED",
  "threadId": "thread-2",
  "runId": "run-10",
  "outcome": {
    "type": "interrupt",
    "interrupts": [
      {
        "id": "int-email-edit",
        "reason": "tool_call",
        "message": "Send email to a@b.com? You can edit the body before approving.",
        "toolCallId": "tc-42",
        "responseSchema": {
          "type": "object",
          "properties": {
            "approved": { "type": "boolean" },
            "editedArgs": {
              "type": "object",
              "properties": {
                "to": { "type": "string", "format": "email" },
                "subject": { "type": "string" },
                "body": { "type": "string" }
              }
            }
          },
          "required": ["approved"]
        },
        "metadata": {
          "langgraph": {
            "checkpointId": "ckpt-xyz",
            "nodeId": "tool_executor"
          }
        }
      }
    ]
  }
}
```

客户端带编辑提交恢复请求：

```json
{
  "threadId": "thread-2",
  "runId": "run-11",
  "resume": [
    {
      "interruptId": "int-email-edit",
      "status": "resolved",
      "payload": {
        "approved": true,
        "editedArgs": {
          "to": "a@b.com",
          "subject": "Hi",
          "body": "Hi (revised per my note)"
        }
      }
    }
  ]
}
```

`tc-42` 的审计链路：

- `run-10` 的 `ToolCallArgs`——最初的提议。
- `run-11` 的 `RunAgentInput.resume[0].payload.editedArgs`——用户的编辑。
- `run-11` 的 `ToolCallResult`——实际结果。

### 并行中断

```json
{
  "type": "RUN_FINISHED",
  "threadId": "thread-3",
  "runId": "run-20",
  "outcome": {
    "type": "interrupt",
    "interrupts": [
      {
        "id": "i-1",
        "reason": "tool_call",
        "toolCallId": "tc-a",
        "message": "Approve sendEmail to x@y.com?"
      },
      {
        "id": "i-2",
        "reason": "tool_call",
        "toolCallId": "tc-b",
        "message": "Approve sendEmail to y@z.com?"
      },
      {
        "id": "i-3",
        "reason": "tool_call",
        "toolCallId": "tc-c",
        "message": "Approve sendEmail to z@w.com?"
      }
    ]
  }
}
```

客户端批准两个、取消一个：

```json
{
  "threadId": "thread-3",
  "runId": "run-21",
  "resume": [
    {
      "interruptId": "i-1",
      "status": "resolved",
      "payload": { "approved": true }
    },
    {
      "interruptId": "i-2",
      "status": "resolved",
      "payload": { "approved": true }
    },
    { "interruptId": "i-3", "status": "cancelled" }
  ]
}
```

在 `run-21` 中，智能体为 `tc-a` 和 `tc-b` 发出 `ToolCallResult`，并把 `tc-c` 视为未执行。

### 非工具类输入请求

```json
{
  "type": "RUN_FINISHED",
  "threadId": "thread-4",
  "runId": "run-30",
  "outcome": {
    "type": "interrupt",
    "interrupts": [
      {
        "id": "int-form",
        "reason": "input_required",
        "message": "Please provide the quarterly filing details.",
        "responseSchema": {
          "type": "object",
          "properties": {
            "quarter": { "type": "string", "enum": ["Q1", "Q2", "Q3", "Q4"] },
            "year": { "type": "integer", "minimum": 2000 },
            "revenue": { "type": "number" }
          },
          "required": ["quarter", "year", "revenue"]
        },
        "expiresAt": "2026-04-20T17:00:00Z"
      }
    ]
  }
}
```

客户端响应：

```json
{
  "threadId": "thread-4",
  "runId": "run-31",
  "resume": [
    {
      "interruptId": "int-form",
      "status": "resolved",
      "payload": { "quarter": "Q1", "year": 2026, "revenue": 4200000 }
    }
  ]
}
```

## 框架集成

| 框架        | 包                                     | 中断支持                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ----------- | -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| LangGraph   | `@ag-ui/langgraph` / `ag-ui-langgraph` | ✅ 接受 `RunAgentInput.resume[]`。可以发出 `RunFinishedEvent.outcome = {type:"interrupt"}`——通过 `emitInterruptOutcome` / `emit_interrupt_outcome` 选择性开启（默认关闭；经由 `command.resume` 恢复的旧式客户端一旦看到结构化 outcome 就会停止恢复）。默认仍会发出旧式的 `CustomEvent(name="on_interrupt")`，可通过 `enableLegacyOnInterruptEvent: false` 关闭。提供子类钩子用于自定义 HITL 转换。 |
| AWS Strands | `@ag-ui/aws-strands`                   | ✅ 通过 `RunFinishedEvent.outcome` 转发 Strands 原生中断。                                                                                                                                                                                                                                                                                                                                                                                              |
