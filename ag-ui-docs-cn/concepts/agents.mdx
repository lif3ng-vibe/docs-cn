# 智能体

智能体（agent）是 AG-UI 协议中处理请求并生成响应的核心组件。它为前端应用与 AI 服务之间的通信建立了一套标准化方式：无论底层实现如何，双方都通过一致的接口进行交互。

## 什么是智能体？

在 AG-UI 中，智能体是一个类（class），它负责：

1. 管理对话状态与消息历史
2. 处理传入的消息与上下文
3. 通过事件驱动的流式接口生成响应
4. 遵循标准化的通信协议

智能体可以接入任何 AI 服务，包括：

- GPT-4、Claude 等大语言模型（LLM）
- 自定义 AI 系统
- 检索增强生成（RAG）系统
- 多智能体系统

## 智能体架构

AG-UI 中的所有智能体都继承自 `AbstractAgent` 类，它为以下能力打下基础：

- 状态管理
- 消息历史追踪
- 事件流处理
- 工具使用

```typescript
import { AbstractAgent } from "@ag-ui/client"

class MyAgent extends AbstractAgent {
  run(input: RunAgentInput): RunAgent {
    // Implementation details
  }
}
```

### 核心组件

AG-UI 智能体包含几个关键组件：

1. **配置**：智能体 ID、线程 ID 与初始状态
2. **消息**：包含用户消息与助手消息的对话历史
3. **状态**：跨交互持久保存的结构化数据
4. **事件**：用于与客户端通信的标准化消息
5. **工具**：智能体可用来与外部系统交互的函数

## 智能体类型

AG-UI 提供了多种智能体实现，以满足不同需求：

### AbstractAgent

所有智能体都会继承的基类，负责核心的事件处理、状态管理与消息历史。

### HttpAgent

一个通过 HTTP 连接远程 AI 服务的具体实现：

```typescript
import { HttpAgent } from "@ag-ui/client"

const agent = new HttpAgent({
  url: "https://your-agent-endpoint.com/agent",
  headers: {
    Authorization: "Bearer your-api-key",
  },
})
```

### 自定义智能体

继承 `AbstractAgent`，你就可以创建自定义智能体来接入任何 AI 服务：

```typescript
class CustomAgent extends AbstractAgent {
  // Custom properties and methods

  run(input: RunAgentInput): RunAgent {
    // Implement the agent's logic
  }
}
```

## 实现智能体

### 基础实现

要创建自定义智能体，只需继承 `AbstractAgent` 类并实现必需的 `run` 方法：

```typescript
import {
  AbstractAgent,
  RunAgent,
  RunAgentInput,
  EventType,
  BaseEvent,
} from "@ag-ui/client"
import { Observable } from "rxjs"

class SimpleAgent extends AbstractAgent {
  run(input: RunAgentInput): RunAgent {
    const { threadId, runId } = input

    return () =>
      new Observable<BaseEvent>((observer) => {
        // Emit RUN_STARTED event
        observer.next({
          type: EventType.RUN_STARTED,
          threadId,
          runId,
        })

        // Send a message
        const messageId = Date.now().toString()

        // Message start
        observer.next({
          type: EventType.TEXT_MESSAGE_START,
          messageId,
          role: "assistant",
        })

        // Message content
        observer.next({
          type: EventType.TEXT_MESSAGE_CONTENT,
          messageId,
          delta: "Hello, world!",
        })

        // Message end
        observer.next({
          type: EventType.TEXT_MESSAGE_END,
          messageId,
        })

        // Emit RUN_FINISHED event
        observer.next({
          type: EventType.RUN_FINISHED,
          threadId,
          runId,
        })

        // Complete the observable
        observer.complete()
      })
  }
}
```

## 智能体能力

AG-UI 协议中的智能体提供了一整套丰富的能力，足以支撑复杂的 AI 交互：

### 交互式通信

智能体通过事件流与前端应用建立双向通信通道。这让以下能力成为可能：

- 实时逐字符流式输出响应
- 用户与 AI 之间的即时反馈闭环
- 为长时间运行的操作提供进度指示
- 双向的结构化数据交换

### 工具使用

智能体可以使用工具来执行操作、访问外部资源。值得注意的是，工具由前端应用定义并传入智能体，这让整个系统既灵活又易于扩展：

```typescript
// Tool definition
const confirmAction = {
  name: "confirmAction",
  description: "Ask the user to confirm a specific action before proceeding",
  parameters: {
    type: "object",
    properties: {
      action: {
        type: "string",
        description: "The action that needs user confirmation",
      },
      importance: {
        type: "string",
        enum: ["low", "medium", "high", "critical"],
        description: "The importance level of the action",
      },
      details: {
        type: "string",
        description: "Additional details about the action",
      },
    },
    required: ["action"],
  },
}

// Running an agent with tools from the frontend
agent.runAgent({
  tools: [confirmAction], // Frontend-defined tools passed to the agent
  // other parameters
})
```

工具通过一系列事件来调用：

1. `TOOL_CALL_START`：表示一次工具调用的开始
2. `TOOL_CALL_ARGS`：流式传输工具调用的参数
3. `TOOL_CALL_END`：标记工具调用完成

随后，前端应用可以执行该工具，并把结果回传给智能体。这种双向流转支撑起复杂的人在回路（human-in-the-loop）工作流：

- 智能体可以请求执行特定操作
- 由人类凭借恰当的判断来执行这些操作
- 执行结果回传给智能体，供其继续推理
- 智能体全程掌握过程中做出的每一项决策

这一机制在实现 AI 与人类协作的界面时尤为强大。例如，[CopilotKit](https://docs.copilotkit.ai/) 的 [`useCopilotAction`](https://docs.copilotkit.ai/guides/frontend-actions) hook 用的正是这套模式，它为 React 应用中定义和处理工具提供了更简洁的方式。

借助工具机制让 AI 了解人类做出的决策，应用就能保持上下文连贯，在用户与 AI 助手之间营造更自然的协作体验。

### 状态管理

智能体维护着一份跨交互持久保存的结构化状态。这份状态可以：

- 通过 `STATE_DELTA` 事件增量更新
- 通过 `STATE_SNAPSHOT` 事件整体刷新
- 被智能体与前端共同访问
- 用于存储用户偏好、对话上下文或应用状态

```typescript
// Accessing agent state
console.log(agent.state.preferences)

// State is automatically updated during agent runs
agent.runAgent().subscribe((event) => {
  if (event.type === EventType.STATE_DELTA) {
    // State has been updated
    console.log("New state:", agent.state)
  }
})
```

### 多智能体协作

AG-UI 支持智能体之间的交接（handoff）与协作：

- 智能体可以把任务委派给其他专职智能体
- 多个智能体可以在协同工作流中配合完成工作
- 状态与上下文可以在智能体之间传递
- 前端在智能体切换的全程保持一致的体验

例如，通用助手智能体在需要编程协助时，可以交接给专职的编程智能体，同时带上对话上下文和具体需求。

### 人在回路工作流

智能体支持人类介入与协助：

- 智能体可以就特定决策请求人类输入
- 前端可以暂停智能体执行，并在收到人类反馈后恢复运行
- 人类专家可以在智能体输出定稿前审查并修改
- 混合工作流将 AI 的效率与人类的判断结合在一起

这让智能体得以在应用中扮演协作伙伴，而非完全自主的系统。

### 对话记忆

智能体维护着完整的对话消息历史：

- 过往的交互会影响后续响应
- 消息历史在客户端与服务端之间保持同步
- 消息可以包含富内容（文本、结构化数据、引用）
- 可以管理上下文窗口，聚焦于相关信息

```typescript
// Accessing message history
console.log(agent.messages)

// Adding a new user message
agent.messages.push({
  id: "msg_123",
  role: "user",
  content: "Can you explain that in more detail?",
})
```

### 元数据与埋点

智能体可以发出描述其内部过程的元数据：

- 通过自定义事件输出推理步骤
- 性能指标与耗时信息
- 来源引用与参考信息追踪
- 不同响应选项的置信度评分

这让前端得以透明展示智能体的决策过程，帮助用户理解结论是如何得出的。

## 使用智能体

实现或实例化智能体之后，就可以这样使用它：

```typescript
// Create an agent instance
const agent = new HttpAgent({
  url: "https://your-agent-endpoint.com/agent",
})

// Add initial messages if needed
agent.messages = [
  {
    id: "1",
    role: "user",
    content: "Hello, how can you help me today?",
  },
]

// Run the agent
agent
  .runAgent({
    runId: "run_123",
    tools: [], // Optional tools
    context: [], // Optional context
  })
  .subscribe({
    next: (event) => {
      // Handle different event types
      switch (event.type) {
        case EventType.TEXT_MESSAGE_CONTENT:
          console.log("Content:", event.delta)
          break
        // Handle other events
      }
    },
    error: (error) => console.error("Error:", error),
    complete: () => console.log("Run complete"),
  })
```

## 智能体配置

智能体通过构造函数接受配置：

```typescript
interface AgentConfig {
  agentId?: string // Unique identifier for the agent
  description?: string // Human-readable description
  threadId?: string // Conversation thread identifier
  initialMessages?: Message[] // Initial messages
  initialState?: State // Initial state object
}

// Using the configuration
const agent = new HttpAgent({
  agentId: "my-agent-123",
  description: "A helpful assistant",
  threadId: "thread-456",
  initialMessages: [
    { id: "1", role: "system", content: "You are a helpful assistant." },
  ],
  initialState: { preferredLanguage: "English" },
})
```

## 智能体状态管理

AG-UI 智能体会在多次交互之间维护状态：

```typescript
// Access current state
console.log(agent.state)

// Access messages
console.log(agent.messages)

// Clone an agent with its state
const clonedAgent = agent.clone()
```

## 结语

智能体是 AG-UI 协议的基石，为前端应用连接 AI 服务提供了标准化方式。通过实现 `AbstractAgent` 类，你可以创建接入任何 AI 服务的自定义集成，同时为应用保持一致的接口。

事件驱动架构带来了现代 AI 应用必不可少的实时流式交互，而标准化协议则确保了不同实现之间的兼容性。
