---

`@ag-ui/omnara` 把 AG-UI 前端连接到 [Omnara](https://omnara.com) 智能体。每个对话线程（thread）都会为每个用户启动一个专属的 Omnara 智能体——从某个 Omnara profile 或内联定义启动——并且该智能体在两次请求之间会持续运行在 Omnara 中。

## 前置要求

- Node.js 22.12 或更新版本
- `@ag-ui/client` 与 `@ag-ui/core` 1.x（使用会解析到 1.x 系列的 CopilotKit 发行版）
- 一个 Omnara 项目、一个具有 developer 角色的[组织 API key](https://docs.omnara.com/api/authentication#org-api-keys-for-services)，以及一个要启动的 [profile](https://docs.omnara.com/agents/configuration)（或下文的内联定义）

## 把 Omnara 加进应用

安装服务端依赖：

```bash
npm install @ag-ui/omnara @copilotkit/runtime hono
```

在服务端读取的环境里设置你的 key 与项目：

```dotenv
OMNARA_API_KEY=omnara_org_v1_...
OMNARA_ORG_ID=org_...
OMNARA_PROJECT_ID=proj_...
```

创建 `app/api/copilotkit/route.ts`。智能体是按请求构建的，因此它的 `user` 来自你自己的鉴权：

```typescript
import { OmnaraAgent } from "@ag-ui/omnara"
import {
  CopilotRuntime,
  InMemoryAgentRunner,
  createCopilotEndpointSingleRoute,
} from "@copilotkit/runtime/v2"
import { handle } from "hono/vercel"
import { getSession } from "@/lib/auth" // your server-side auth

export const runtime = "nodejs"

const copilotRuntime = new CopilotRuntime({
  agents: async ({ request }) => {
    const session = await getSession(request)
    return {
      assistant: new OmnaraAgent({
        orgId: process.env.OMNARA_ORG_ID!,
        projectId: process.env.OMNARA_PROJECT_ID!,
        profile: "support-agent",
        user: { id: session.userId, name: session.userName },
      }),
    }
  },
  runner: new InMemoryAgentRunner(),
})

const endpoint = createCopilotEndpointSingleRoute({
  runtime: copilotRuntime,
  basePath: "/api/copilotkit",
})

export const POST = handle(endpoint)
```

`apiKey` 默认取 `OMNARA_API_KEY`。如果想用内联的[智能体配置](https://docs.omnara.com/agents/configuration)而不是 profile 来启动，请把 `profile` 换成 `definition`。`omnara-openrouter` 是每个组织一开始就自带的[模型提供方](https://docs.omnara.com/organization/model-providers)：

```typescript
definition: {
  source: {
    version: "v1",
    instruction: "Be concise and use the page's tools when they help.",
    model: { provider_config: "omnara-openrouter", name: "anthropic/claude-fable-5.1" },
  },
},
```

前端现在可以通过任意 AG-UI 客户端选择 `assistant` 智能体。CopilotKit React 应用会在其 `CopilotKit` provider 上使用 `runtimeUrl="/api/copilotkit"` 与 `agent="assistant"`。

## 线程、运行与停止

线程的智能体按"智能体 + 用户 + 线程 id"作为键，并在多次运行之间复用，因此修改 profile 或定义只对新线程生效。关闭标签页或断开连接不会取消任何东西：下一次运行会从 Omnara 的日志把对话补齐。`abortRun()`（CopilotKit 的停止按钮）会取消该智能体及其正在运行的子智能体。线程 id 来自客户端，因此请在 `beforeRequestMiddleware` 里校验调用者确实拥有该线程。一个线程只属于一个用户：如果想以他人身份继续对话，请新开一个线程。

## 集成支持的行为

- 流式输出文本与推理（reasoning），并在每次运行结束时附带 Omnara 日志的快照
- Omnara 的[内置工具](https://docs.omnara.com/tools/built-in)与 [MCP 工具](https://docs.omnara.com/tools/mcp)调用及其结果
- 前端工具——作为[自定义工具](https://docs.omnara.com/tools/custom)加入线程的智能体（运行以 `pendingToolCallIds` 结束），以及由你的服务端执行的后端工具（`backendTools`）
- Omnara 的[批准与提问](https://docs.omnara.com/events/interactions)以可恢复中断的形式呈现，子智能体的也包括在内
- [子智能体](https://docs.omnara.com/tools/built-in#subagents)报告，以及从别处（Omnara 控制台、API）发来的消息，并带有发送者的 `name`
- 应用上下文，以及图片与文档附件
- 稳定的 `RUN_ERROR` 代码；上游错误文本进入 `onError`，而不会到达客户端

该集成仅限服务端使用：绝不要从浏览器组件里导入 `@ag-ui/omnara`。可用选项、resume 负载与限制，请参阅 [Dojo 实时示例](https://dojo.ag-ui.com/omnara/feature/tool_based_generative_ui)与[包的 README](https://github.com/ag-ui-protocol/ag-ui/tree/main/integrations/community/omnara/typescript)。
