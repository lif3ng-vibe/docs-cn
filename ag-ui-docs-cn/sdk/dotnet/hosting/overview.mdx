# AGUI.Server

`AGUI.Server` 是 AG-UI 的 .NET 服务端侧适配器。它把
`Microsoft.Extensions.AI.IChatClient` 流转换为 AG-UI 协议事件，让你可以把任意对话
客户端暴露为一个 AG-UI 端点——该端点接受 `RunAgentInput`，并把 AG-UI 事件流式推送给
前端 UI。

```bash
dotnet add package AGUI.Server
```

## 核心思想

你不需要学习一套新的智能体编程模型，只需要托管一个 `IChatClient`。

该包把 AG-UI 请求体适配为 `Microsoft.Extensions.AI` 的消息与选项，调用你的对话
客户端，再把流式返回的 `ChatResponseUpdate` 值转换回 AG-UI 协议事件。

## 依赖项

`AGUI.Server` 刻意保持小巧：

- 来自 `AGUI.Abstractions` 的
  [AG-UI 协议类型](/sdk/dotnet/abstractions/events)
- `Microsoft.Extensions.AI.Abstractions`

它与框架无关：不依赖 ASP.NET Core 或任何 Web 框架。你可以把该适配器托管在你选择的
Web 框架里（示例与文档使用 ASP.NET Core）。它也不依赖 .NET 的 AG-UI 客户端包。
服务端包与客户端包共享协议类型，但彼此独立。

<Note>
  服务端包面向 `net10.0`、`net9.0` 和 `net8.0`。
</Note>

## 托管层处理什么

托管层（hosting layer）替你处理协议细节：

- 把 `RunAgentInput.Messages` 转换为 `ChatMessage` 值
- 把 `RunAgentInput.Resume` 翻译为 MEAI 的批准与中断响应内容，把负载——对非工具类
  中断还有元数据——带到 `InterruptResponseContent` 上
- 把客户端声明的工具安装到 `ChatOptions` 上
- 把原始输入存放在
  `ChatOptions.AdditionalProperties[AGUIConstants.RunAgentInputKey]` 下
- 发出 `RUN_STARTED` 与终止性的 `RUN_FINISHED` 结果
- 把文本、推理、工具调用、工具结果、状态、Raw 事件与中断映射为 AG-UI 事件
- 以 SSE（服务器推送事件）流式返回结果

## 验证与框架归属

服务端测试验证：`RunAgentInput` 变成 `ChatMessage` 与 `ChatOptions`，resume 负载
变成标准 MEAI 响应内容，生命周期事件被发出，流式的 `ChatResponseUpdate` 值变成
预期的文本、推理、工具、状态、Raw、自定义与中断事件。包括 `RUN_ERROR` 在内的原始
AG-UI 事件，只要提供在 `ChatResponseUpdate.RawRepresentation` 上就会透传。

```bash
cd sdks/dotnet
dotnet test tests/AGUI.Server.UnitTests/
dotnet test tests/AGUI.Hosting.AspNetCore.IntegrationTests/
```

SDK 负责共享的 AG-UI 与 `Microsoft.Extensions.AI` 桥接。框架特有的映射归使用它的
框架所有。例如 Microsoft Agent Framework 可以用 `AGUI.Server` 处理公共桥接，再用
`AGUIStreamOptions` 或原始 AG-UI 事件映射自己的工作流、步骤与智能体事件。

## 服务端与客户端配合使用

构建 AG-UI 服务端时使用 `AGUI.Server`。当 .NET 代码需要把 AG-UI 端点当作
`IChatClient` 消费时，使用
[AGUI.Client](/sdk/dotnet/client/overview)。
