# AGUI.Client

AG-UI .NET 客户端 SDK 把 AG-UI 端点适配到标准的
`Microsoft.Extensions.AI.IChatClient` 抽象。`AGUI.Client` 不引入新的智能体基类，
而是让 .NET 应用像消费其他任何对话模型一样消费 AG-UI 服务端。

```bash
dotnet add package AGUI.Client
```

<Note>
  如果你已经在用 `Microsoft.Extensions.AI`，那么一个 AG-UI 服务端不过是另一个
  `IChatClient`。
</Note>

## AGUIChatClient

`AGUIChatClient` 是本包中的主类型。它包装一个 AG-UI HTTP+SSE 端点，同时暴露
`IChatClient` 的 `GetStreamingResponseAsync` 与 `GetResponseAsync`。

- [构建](/sdk/dotnet/client/chat-client#构建) - 从 `HttpClient` 与端点创建
  客户端，或从自定义传输层创建
- [流式](/sdk/dotnet/client/chat-client#流式响应) - 以
  `ChatResponseUpdate` 值的形式消费 AG-UI 事件
- [无状态行为](/sdk/dotnet/client/chat-client#无状态与-conversationid) -
  每一轮都发送完整的消息历史
- [线程延续性](/sdk/dotnet/client/chat-client#线程延续性) - 保持稳定的线程，
  或从上一次运行分支
- [中断与批准](/sdk/dotnet/client/chat-client#中断与批准) -
  用标准 MEAI 内容类型处理服务端暂停

## 传输层

客户端包包含一个小的传输层（transport）抽象，用于发送 `RunAgentInput` 请求并接收
AG-UI 事件流。默认路径使用 HTTP POST 与 SSE（服务器推送事件）；自定义传输层适用于
测试或非 HTTP 环境。

- [IAGUITransport](/sdk/dotnet/client/transport#iaguitransport) -
  `AGUIChatClient` 使用的传输层接口
- [HTTP 传输层](/sdk/dotnet/client/transport#http-传输层) - 内置的 HTTP+SSE 行为
- [自定义传输层](/sdk/dotnet/client/transport#自定义传输层) - 接入内存实现或
  其他线上协议

## 设计上无状态

从 .NET 客户端的视角看，AG-UI 端点是无状态的。每个请求都发送完整的消息历史，返回的
`ChatResponseUpdate` 对象不暴露 `ConversationId`。更新通过 `ResponseId` 关联，它
映射到 AG-UI 的运行 ID。AG-UI 线程 ID 可以从 `RUN_STARTED` 事件获得，也可以从
`AdditionalProperties["agui_thread_id"]` 获得。

线上携带的协议类型见 [.NET 事件参考](/sdk/dotnet/abstractions/events)。

## 客户端验证

客户端测试守护 `Microsoft.Extensions.AI` 与 AG-UI 之间的转换。它们验证：
`ChatMessage` 历史变成 AG-UI 消息，`ChatOptions.Tools` 变成 AG-UI 工具，调用方提供的
AG-UI 上下文、转发属性与 resume 负载被保留，`RUN_ERROR` 事件变成 MEAI
`ErrorContent` 更新。

它们还守护无状态会话契约：线程与运行标识符通过 AG-UI 字段保留，返回的更新会清空
`ConversationId`，服务端侧的工具调用被标记为仅提示性质（informational），从而
.NET 客户端不会在本地执行它们。

cd sdks/dotnet
