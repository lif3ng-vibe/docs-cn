# AGUIChatClient

`AGUIChatClient` 是面向 AG-UI 的 `IChatClient` 实现。它把 `ChatMessage` 值与
`ChatOptions` 转换为 `RunAgentInput`，把该输入发送到 AG-UI 端点，再把返回的事件流
转换为 `ChatResponseUpdate` 值。

```csharp
using AGUI.Client;
using Microsoft.Extensions.AI;
```

<Note>
  .NET 客户端没有定义等价于 `AbstractAgent` 的类型。集成点是
  `Microsoft.Extensions.AI.IChatClient`。
</Note>

## 构建

从 `AGUIChatClientOptions` 创建客户端。最简单的形式是用一个 `HttpClient` 与 AG-UI
端点 URL 构建内置的 HTTP 传输层：

```csharp
using AGUI.Client;
using Microsoft.Extensions.AI;

HttpClient httpClient = new();
IChatClient client = new AGUIChatClient(new(httpClient, "https://api.example.com/agent"));
```

`AGUIChatClient` 只有一个接受 `AGUIChatClientOptions` 的构造函数：

```csharp
new AGUIChatClient(AGUIChatClientOptions options);
```

`AGUIChatClientOptions` 携带传输层与可选的序列化器设置：

```csharp
public sealed class AGUIChatClientOptions
{
    public AGUIChatClientOptions();
    public AGUIChatClientOptions(HttpClient httpClient, string endpoint); // builds the HTTP transport
    public required IAGUITransport Transport { get; init; }
    public JsonSerializerOptions? JsonSerializerOptions { get; init; }
}
```

当测试需要自定义传输层，或需要另一种线上协议时，直接设置 `Transport`。
见[传输层](/sdk/dotnet/client/transport)。配置好的 `JsonSerializerOptions` 也会在
转换 MEAI 消息内容时使用，包括 `AIContent.AdditionalProperties` 中的自定义 CLR 值。

## 流式响应

`GetStreamingResponseAsync` 把 AG-UI 输出以 MEAI
`ChatResponseUpdate` 对象的形式流式返回：

```csharp
using AGUI.Client;
using Microsoft.Extensions.AI;

using HttpClient httpClient = new();
IChatClient client = new AGUIChatClient(new(httpClient, "https://api.example.com/agent"));

List<ChatMessage> messages =
[
    new(ChatRole.User, "Explain AG-UI in one paragraph"),
];

await foreach (ChatResponseUpdate update in client.GetStreamingResponseAsync(
    messages,
    options: null,
    cancellationToken: CancellationToken.None))
{
    if (!string.IsNullOrEmpty(update.Text))
    {
        Console.Write(update.Text);
    }
}
```

在内部，客户端把 AG-UI 事件流转换回 `ChatResponseUpdate` 对象。文本事件变成文本
增量，工具调用事件变成 MEAI 工具调用内容，生命周期事件则通过
`RawRepresentation` 继续可用。

## 非流式响应

`GetResponseAsync` 也有实现。它消费流式响应并返回最终的 `ChatResponse`：

```csharp
ChatResponse response = await client.GetResponseAsync(
    messages,
    cancellationToken: CancellationToken.None);

Console.WriteLine(response.Text);
```

## 无状态与 ConversationId

`AGUIChatClient` 是无状态的。它在每一轮都发送完整的消息历史，并且从不在返回的更新上
暴露 `ConversationId`。

这是有意为之。在 `Microsoft.Extensions.AI` 中，非 null 的 `ConversationId`
表示由服务管理的会话，智能体包装层随后可能在下一轮只发送新的消息增量。面对无状态的
AG-UI 服务端，这会截断历史。

请改用这些标识符：

- `ChatResponseUpdate.ResponseId` 是 AG-UI 的运行 ID。
- `update.RawRepresentation as RunStartedEvent` 暴露 `RUN_STARTED` 事件中的 AG-UI
  `ThreadId` 与 `RunId`。
- `update.AdditionalProperties["agui_thread_id"]` 在 `RUN_STARTED` 更新上也携带
  解析出的 AG-UI 线程 ID。

```csharp
using AGUI.Abstractions;
using Microsoft.Extensions.AI;

static (string? ThreadId, string? RunId) GetAGUIIds(
    IEnumerable<ChatResponseUpdate> updates)
{
    RunStartedEvent? started = updates
        .Select(update => update.RawRepresentation)
        .OfType<RunStartedEvent>()
        .FirstOrDefault();

    return (started?.ThreadId, started?.RunId);
}
```

<Warning>
  不要把 `ConversationId` 当作 AG-UI 的会话状态。每轮传递完整的消息历史，并使用
  AG-UI 的线程/运行 ID 做线级关联。
</Warning>

## 线程延续性

要维持一个稳定的 AG-UI 线程，请在多轮之间复用同一个 `ChatOptions` 实例。客户端会把
解析出的线程 ID 固定（pin）到该 options 实例上，而不会设置 `ConversationId`。

要显式延续或分支，通过 `ChatOptions.RawRepresentationFactory` 设置
`RunAgentInput.ThreadId` 和 `RunAgentInput.ParentRunId`。
这是 AG-UI 原生的线级字段控制方式：

```csharp
using AGUI.Abstractions;
using Microsoft.Extensions.AI;

List<ChatResponseUpdate> firstTurn = [];
await foreach (ChatResponseUpdate update in client.GetStreamingResponseAsync(
    [new ChatMessage(ChatRole.User, "Hello, tell me about serialization")],
    cancellationToken: CancellationToken.None))
{
    firstTurn.Add(update);
    Console.Write(update.Text);
}

RunStartedEvent? runStarted = firstTurn
    .Select(update => update.RawRepresentation)
    .OfType<RunStartedEvent>()
    .FirstOrDefault();

ChatOptions followUpOptions = new()
{
    RawRepresentationFactory = _ => new RunAgentInput
    {
        ThreadId = runStarted?.ThreadId ?? string.Empty,
        ParentRunId = runStarted?.RunId,
    },
};

await foreach (ChatResponseUpdate update in client.GetStreamingResponseAsync(
    [new ChatMessage(ChatRole.User, "Tell me more about event compaction")],
    followUpOptions,
    CancellationToken.None))
{
    Console.Write(update.Text);
}
```

<Tip>
  当希望下一个请求从上一次运行分支时使用 `ParentRunId`；只需在同一线程上继续时则
  省略它。
</Tip>

## 中断与批准

当 AG-UI 服务端以中断结果结束一次运行时，客户端会把这次暂停以 MEAI 内容的形式呈现
出来：

- 工具调用批准变成 `ToolApprovalRequestContent`。
- 其他中断变成 `InterruptRequestContent`。

调用方追加一条响应消息并发送下一个请求。客户端从最新的消息中提取
`ToolApprovalResponseContent` 与 `InterruptResponseContent`，并作为
`RunAgentInput.Resume` 发送。

```csharp
using AGUI.Abstractions;
using Microsoft.Extensions.AI;

List<ChatMessage> messages =
[
    new(ChatRole.User, "Delete the generated files"),
];

ChatResponse firstResponse = await client.GetResponseAsync(
    messages,
    cancellationToken: CancellationToken.None);

ToolApprovalRequestContent? approval = firstResponse.Messages
    .SelectMany(message => message.Contents)
    .OfType<ToolApprovalRequestContent>()
    .FirstOrDefault();

if (approval?.ToolCall is FunctionCallContent toolCall)
{
    messages.AddRange(firstResponse.Messages);
    messages.Add(new ChatMessage(ChatRole.User,
    [
        new ToolApprovalResponseContent(approval.RequestId, approved: true, toolCall),
    ]));

    ChatResponse resumed = await client.GetResponseAsync(
        messages,
        cancellationToken: CancellationToken.None);

    Console.WriteLine(resumed.Text);
}
```

对于非工具类中断，用 `InterruptResponseContent` 响应：

```csharp
using System.Text.Json;
using AGUI.Abstractions;
using Microsoft.Extensions.AI;

static ChatMessage CreateInterruptResponse(InterruptRequestContent request)
{
    using JsonDocument payload = JsonDocument.Parse("""{"approved":true}""");

    return new ChatMessage(ChatRole.User,
    [
        new InterruptResponseContent(request.RequestId)
        {
            Payload = payload.RootElement.Clone(),
        },
    ]);
}
```

`InterruptResponseContent.Metadata` 可选地携带关于该响应的信封数据——证明决定未被
篡改的签名、路由 key 等——与之相对，`Payload` 是智能体索求的答案。客户端会把它复制到
resume 条目的 `metadata` 上，托管层再通过 `InterruptResponseContent` 把它交回服务端
管线；见[元数据](/concepts/metadata#恢复条目)。

```csharp
new InterruptResponseContent(request.RequestId)
{
    Payload = payload.RootElement.Clone(),
    Metadata = JsonDocument.Parse(
        """{"definitionId":"review-plan","key":"afterModel-review"}""")
        .RootElement.Clone(),
}
```
