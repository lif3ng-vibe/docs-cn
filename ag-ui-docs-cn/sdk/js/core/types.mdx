# 核心类型

智能体–用户交互协议 SDK 构建在一组核心类型之上，它们表示整个系统中使用的基础结构。本页记录这些类型及其属性。

## RunAgentInput

运行智能体的输入参数。在 HTTP API 中，它是 `POST` 请求的请求体。

`tools` 包含客户端为本次运行提供的工具。后端定义的工具应保留在后端智能体或框架配置中，并可通过智能体能力（capabilities）单独对外声明。

```typescript
type RunAgentInput = {
  threadId: string
  runId: string
  parentRunId?: string
  state?: any // absent means "no state"; a bare null is read as absent
  messages: Message[]
  tools: Tool[]
  context: Context[]
  forwardedProps: any
  resume?: ResumeEntry[]
}
```

| 属性 | 类型 | 描述 |
| ---------------- | -------------------------- | ---------------------------------------------------------------------------------------- |
| `threadId` | `string` | 会话线程的 ID |
| `runId` | `string` | 当前运行的 ID |
| `parentRunId` | `string (optional)` | 生成此运行的父运行的 ID |
| `state` | `any (optional)` | 智能体的当前状态；缺失表示"无状态"，单独一个 `null` 会被读作缺失 |
| `messages` | `Message[]` | 会话中的消息数组 |
| `tools` | `Tool[]` | 本次运行可用的客户端提供的工具 |
| `context` | `Context[]` | 提供给智能体的上下文对象数组 |
| `forwardedProps` | `any` | 转发给智能体的附加属性 |
| `resume` | `ResumeEntry[] (optional)` | 针对每次中断的响应，用于恢复一个以中断（interrupt）结果结束的运行 |

## ResumeEntry

`RunAgentInput.resume` 中针对每次中断的响应，用于应答上一次运行产生的中断。完整的恢复（resume）约定参见 [Interrupts（中断）](/concepts/interrupts#resuming-a-run)。

```typescript
type ResumeEntry = {
  interruptId: string
  status: "resolved" | "cancelled"
  payload?: any
  metadata?: Record<string, any>
}
```

| 属性 | 类型 | 描述 |
| ------------- | -------------------------------- | ------------------------------------------------------------------------------------- |
| `interruptId` | `string` | 此条目所应答的中断的 ID |
| `status` | `"resolved" \| "cancelled"` | 用户是响应了该中断，还是放弃了它 |
| `payload` | `any (optional)` | 响应本身，需通过该中断的 `responseSchema` 校验 |
| `metadata` | `Record<string, any> (optional)` | 关于响应的信封数据——签名、路由 key 等——绝不是答案本身 |

`metadata` 遵循协议中其他所有地方元数据的相同约定：按键开放，任意 key 下允许任何 JSON 值（包括 `null`），对象本身要么缺失、要么是对象但绝不能是 `null`，且 `ag-ui` key 为保留 key。resume 条目是请求字段，因此不会有任何内容合并进来；参见 [Metadata（元数据）](/concepts/metadata#resume-entries)。

## 消息类型

SDK 包含若干消息类型，表示系统中不同种类的消息。

<Note>
  每种消息类型都带有一个可选的 `metadata` 对象（`Record<string, any>`），`ToolCall` 也是如此。为简洁起见，下面的分类型表格中省略了它们。
  它是按键开放的——任意 key 下允许任何 JSON 值，包括 `null`——对象本身可以缺失，但绝不会是 `null`。`ag-ui` key 为 AG-UI 自用保留。元数据会随着消息由其事件逐步构建而累积；合并规则参见 [Metadata（元数据）](/concepts/metadata)。
</Note>

### Role

表示消息发送者可能具有的角色。

```typescript
type Role =
  | "developer"
  | "system"
  | "assistant"
  | "user"
  | "tool"
  | "activity"
  | "reasoning"
```

### DeveloperMessage

表示来自开发者（developer）的消息。

```typescript
type DeveloperMessage = {
  id: string
  role: "developer"
  content: string
  name?: string
}
```

| 属性 | 类型 | 描述 |
| --------- | ------------- | ------------------------------------------------ |
| `id` | `string` | 消息的唯一标识符 |
| `role` | `"developer"` | 消息发送者的角色，固定为 "developer" |
| `content` | `string` | 消息的文本内容（必填） |
| `name` | `string` | 发送者的可选名称 |

### SystemMessage

表示系统消息。

```typescript
type SystemMessage = {
  id: string
  role: "system"
  content: string
  name?: string
}
```

| 属性 | 类型 | 描述 |
| --------- | ---------- | --------------------------------------------- |
| `id` | `string` | 消息的唯一标识符 |
| `role` | `"system"` | 消息发送者的角色，固定为 "system" |
| `content` | `string` | 消息的文本内容（必填） |
| `name` | `string` | 发送者的可选名称 |

### AssistantMessage

表示来自助手（assistant）的消息。

```typescript
type AssistantMessage = {
  id: string
  role: "assistant"
  content?: string
  name?: string
  toolCalls?: ToolCall[]
}
```

| 属性 | 类型 | 描述 |
| ----------- | ----------------------- | ------------------------------------------------ |
| `id` | `string` | 消息的唯一标识符 |
| `role` | `"assistant"` | 消息发送者的角色，固定为 "assistant" |
| `content` | `string` (optional) | 消息的文本内容 |
| `name` | `string` (optional) | 发送者的名称 |
| `toolCalls` | `ToolCall[]` (optional) | 此消息中发起的工具调用 |

### UserMessage

表示来自用户（user）的消息。

```typescript
type UserMessage = {
  id: string
  role: "user"
  content: string | ContentPart[]
  name?: string
}
```

| 属性 | 类型 | 描述 |
| --------- | ------------------------- | --------------------------------------------------------------------- |
| `id` | `string` | 消息的唯一标识符 |
| `role` | `"user"` | 消息发送者的角色，固定为 "user" |
| `content` | `string \| ContentPart[]` | 纯文本，或多模态内容片段的有序数组 |
| `name` | `string` | 发送者的可选名称 |

### ContentPart

受支持的内容部分（content part）的联合类型。同样的部分既出现在 `UserMessage` 上，也出现在 `ToolMessage` 上：工具调用结果可以是字符串，也可以是这些部分组成的列表。每个部分都可以携带可选的 `id`；`metadata` 不作约束，文本搜索命中会在其中保存来源与标题。

```typescript
type ContentPart = TextPart | ImagePart | AudioPart | VideoPart | DocumentPart
```

### PartSource

```typescript
type PartSource = DataSource | UrlSource | FileSource

type DataSource = {
  type: "data"
  value: string
  mimeType: string
}

type UrlSource = {
  type: "url"
  value: string
  mimeType?: string
}

type FileSource = {
  type: "file"
  value: string // the handle, exactly as the provider issued it
  provider?: string // who issued it, e.g. "openai", "anthropic", "google"
  mimeType?: string
}
```

`FileSource` 指向已经存放在模型提供商侧的字节——一个 OpenAI 或 Anthropic 的文件 id，或一个 Gemini 文件 URI。不会发生任何抓取，`value` 是不透明的：智能体把它交给自己的提供商，或者丢弃这个部分，绝不把它当作 URL 使用。

### ToolMessage

表示来自工具（tool）的消息。

```typescript
type ToolMessage = {
  id: string
  content: string | ContentPart[]
  role: "tool"
  toolCallId: string
  error?: string
  encryptedValue?: string
}
```

| 属性 | 类型 | 描述 |
| ---------------- | ------------------- | ----------------------------------------------- |
| `id` | `string` | 消息的唯一标识符 |
| `content` | `string` | 消息的文本内容 |
| `role` | `"tool"` | 消息发送者的角色，固定为 "tool" |
| `toolCallId` | `string` | 此消息所响应的工具调用的 ID |
| `error` | `string` (optional) | 工具调用失败时的错误消息 |
| `encryptedValue` | `string` (optional) | 通过签名附加的可选加密值 |

### ActivityMessage

表示在对话消息之间发出的结构化活动进度。

```typescript
type ActivityMessage = {
  id: string
  role: "activity"
  activityType: string
  content: Record<string, any>
}
```

| 属性 | 类型 | 描述 |
| -------------- | --------------------- | ------------------------------------------------------- |
| `id` | `string` | 活动消息的唯一标识符 |
| `role` | `"activity"` | 固定的判别值，标识该消息为活动消息 |
| `activityType` | `string` | 用于选择渲染器的活动判别值 |
| `content` | `Record<string, any>` | 表示活动状态的结构化负载 |

### Message

表示系统中任意消息类型的联合类型。

```typescript
type Message =
  | DeveloperMessage
  | SystemMessage
  | AssistantMessage
  | UserMessage
  | ToolMessage
  | ActivityMessage

```

### ToolCall

表示智能体发起的一次工具调用。

```typescript
type ToolCall = {
  id: string
  type: "function"
  function: FunctionCall
  encryptedValue?: string
}
```

| 属性 | 类型 | 描述 |
| ---------------- | ------------------- | ----------------------------------------------- |
| `id` | `string` | 工具调用的唯一标识符 |
| `type` | `"function"` | 工具调用的类型，始终为 "function" |
| `function` | `FunctionCall` | 被调用函数的详细信息 |
| `encryptedValue` | `string` (optional) | 通过签名附加的可选加密值 |

#### FunctionCall

表示工具调用中的函数名与参数。

```typescript
type FunctionCall = {
  name: string
  arguments: string
}
```

| 属性 | 类型 | 描述 |
| ----------- | -------- | ------------------------------------------------ |
| `name` | `string` | 要调用的函数名 |
| `arguments` | `string` | 传给函数的参数的 JSON 编码字符串 |

## Context

表示提供给智能体的一段上下文信息。

```typescript
type Context = {
  description: string
  value: string
}
```

| 属性 | 类型 | 描述 |
| ------------- | -------- | ------------------------------------------- |
| `description` | `string` | 对这段上下文所表示内容的描述 |
| `value` | `string` | 实际的上下文值 |

## Tool

定义一个可被智能体调用的工具。

```typescript
type Tool = {
  name: string
  description: string
  parameters: any // JSON Schema
}
```

| 属性 | 类型 | 描述 |
| ------------- | -------- | ------------------------------------------------ |
| `name` | `string` | 工具名称 |
| `description` | `string` | 对工具用途的描述 |
| `parameters` | `any` | 定义工具参数的 JSON Schema |

## State

表示智能体在执行期间的状态。

```typescript
type State = any
```

状态类型十分灵活，可以容纳智能体实现所需的任何数据结构。

## AgentCapabilities

`getCapabilities()` 返回的类型化能力声明。所有字段都是可选的——智能体只声明自己支持的能力。

```typescript
interface AgentCapabilities {
  identity?: IdentityCapabilities
  transport?: TransportCapabilities
  tools?: ToolsCapabilities
  output?: OutputCapabilities
  state?: StateCapabilities
  multiAgent?: MultiAgentCapabilities
  reasoning?: ReasoningCapabilities
  multimodal?: MultimodalCapabilities
  execution?: ExecutionCapabilities
  humanInTheLoop?: HumanInTheLoopCapabilities
  custom?: Record<string, unknown>
}
```

| 属性 | 类型 | 描述 |
| ---------------- | ---------------------------- | -------------------------------------------- |
| `identity` | `IdentityCapabilities` | 智能体身份与元数据 |
| `transport` | `TransportCapabilities` | 受支持的传输层（transport）机制 |
| `tools` | `ToolsCapabilities` | 智能体提供的工具与工具调用配置 |
| `output` | `OutputCapabilities` | 输出格式支持 |
| `state` | `StateCapabilities` | 状态与记忆管理 |
| `multiAgent` | `MultiAgentCapabilities` | 多智能体协作 |
| `reasoning` | `ReasoningCapabilities` | 推理与思考（thinking）支持 |
| `multimodal` | `MultimodalCapabilities` | 多模态输入/输出支持 |
| `execution` | `ExecutionCapabilities` | 执行控制与限制 |
| `humanInTheLoop` | `HumanInTheLoopCapabilities` | 人在回路（human-in-the-loop）支持 |
| `custom` | `Record<string, unknown>` | 集成专属的能力 |

完整的类别类型定义与用法模式参见 [Capabilities（能力）](/concepts/capabilities)。
