# 事件

智能体–用户交互协议 SDK 采用基于事件的流式架构。事件是智能体与前端之间通信的基本单位。本节记录事件类型及其属性。

## EventType 枚举

`EventType` 枚举定义了系统中所有可能的事件类型：

```typescript
enum EventType {
  TEXT_MESSAGE_START = "TEXT_MESSAGE_START",
  TEXT_MESSAGE_CONTENT = "TEXT_MESSAGE_CONTENT",
  TEXT_MESSAGE_END = "TEXT_MESSAGE_END",
  TOOL_CALL_START = "TOOL_CALL_START",
  TOOL_CALL_ARGS = "TOOL_CALL_ARGS",
  TOOL_CALL_END = "TOOL_CALL_END",
  TOOL_CALL_RESULT = "TOOL_CALL_RESULT",
  STATE_SNAPSHOT = "STATE_SNAPSHOT",
  STATE_DELTA = "STATE_DELTA",
  MESSAGES_SNAPSHOT = "MESSAGES_SNAPSHOT",
  ACTIVITY_SNAPSHOT = "ACTIVITY_SNAPSHOT",
  ACTIVITY_DELTA = "ACTIVITY_DELTA",
  RAW = "RAW",
  CUSTOM = "CUSTOM",
  RUN_STARTED = "RUN_STARTED",
  RUN_FINISHED = "RUN_FINISHED",
  RUN_ERROR = "RUN_ERROR",
  STEP_STARTED = "STEP_STARTED",
  STEP_FINISHED = "STEP_FINISHED",
  REASONING_START = "REASONING_START",
  REASONING_MESSAGE_START = "REASONING_MESSAGE_START",
  REASONING_MESSAGE_CONTENT = "REASONING_MESSAGE_CONTENT",
  REASONING_MESSAGE_END = "REASONING_MESSAGE_END",
  REASONING_MESSAGE_CHUNK = "REASONING_MESSAGE_CHUNK",
  REASONING_END = "REASONING_END",
  REASONING_ENCRYPTED_VALUE = "REASONING_ENCRYPTED_VALUE",
  SUBAGENT_STARTED = "SUBAGENT_STARTED",
  SUBAGENT_FINISHED = "SUBAGENT_FINISHED",
  SUBAGENT_ERROR = "SUBAGENT_ERROR",
}
```

## BaseEvent

所有事件都继承自 `BaseEvent` 类型，它提供所有事件类型共享的公共属性。

```typescript
type BaseEvent = {
  type: EventType // Discriminator field
  timestamp?: number
  rawEvent?: any
  metadata?: Record<string, any>
}
```

| 属性 | 类型 | 描述 |
| ----------- | ------------------- | ----------------------------------------------------- |
| `type` | `EventType` | 事件的类型（联合类型的判别字段） |
| `timestamp` | `number` (optional) | 事件创建时的时间戳 |
| `rawEvent` | `any` (optional) | 如果此事件经过转换，则为原始事件数据 |
| `metadata` | `Record<string, any>` (optional) | 附加到事件上的额外信息 |

`metadata` 是按键开放的：任意 key 下允许任何 JSON 值，包括 `null`。对象可以缺失，但存在时绝不会是 `null`——显式的 `null` 会被解析为缺失。`ag-ui` key 为 AG-UI 自用保留。使用 `@ag-ui/core` 中的 `mergeMetadata` 把事件元数据合并进消息；参见 [Metadata（元数据）](/concepts/metadata)。

## 生命周期事件

这些事件表示一次智能体运行的生命周期。

### RunStartedEvent

表示一次智能体运行的开始。

```typescript
type RunStartedEvent = BaseEvent & {
  type: EventType.RUN_STARTED
  threadId: string
  runId: string
  parentRunId?: string
  input?: RunAgentInput
}
```

| 属性 | 类型 | 描述 |
| ------------- | -------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `threadId` | `string` | 会话线程的 ID |
| `runId` | `string` | 智能体运行的 ID |
| `parentRunId` | `string` (optional) | （可选）用于分支/时间旅行的血统指针。如果存在，指向同一线程中较早的一次运行 |
| `input` | `RunAgentInput` (optional) | （可选）本次运行发送给智能体的确切输入负载。可以省略历史中已有的消息 |

### TokenUsage

附在终止性运行事件上的可复用、纯数值的 token 用量摘要。它有意只包含**提供商/模型标签与 token 计数**——不含提示词、补全结果、消息或标识符。这些计数遵循协议的[记账规则](/spec/1.0/events/lifecycle#token-usage)：输入与输出计数是总量，缓存与推理计数是它们的组成部分，绝不是额外的累加。

```typescript
type TokenUsage = {
  provider?: string
  model?: string
  inputTokens?: number
  outputTokens?: number
  totalTokens?: number
  reasoningTokens?: number
  cachedInputTokens?: number
  cacheWriteInputTokens?: number
}
```

| 属性 | 类型 | 描述 |
| ----------------------- | ------------------- | -------------------------------------------------------------- |
| `provider` | `string` (optional) | 上报该用量的提供商（例如 `openai`） |
| `model` | `string` (optional) | 产生该用量的模型 |
| `inputTokens` | `number` (optional) | 全部输入 token，包括缓存读与缓存写 |
| `outputTokens` | `number` (optional) | 全部输出 token，包括推理部分 |
| `totalTokens` | `number` (optional) | `inputTokens` 加上 `outputTokens` |
| `reasoningTokens` | `number` (optional) | 花在推理上的输出 token；是 `outputTokens` 的一部分 |
| `cachedInputTokens` | `number` (optional) | 从提示词缓存读取的输入 token；是 `inputTokens` 的一部分 |
| `cacheWriteInputTokens` | `number` (optional) | 写入提示词缓存的输入 token；是 `inputTokens` 的一部分 |

### RunFinishedEvent

表示一次智能体运行成功完成。

```typescript
type RunFinishedEvent = BaseEvent & {
  type: EventType.RUN_FINISHED
  threadId: string
  runId: string

  usage?: TokenUsage[]
}
```

| 属性 | 类型 | 描述 |
| ---------- | -------------------------- | ------------------------------------------------------------------- |
| `threadId` | `string` | 会话线程的 ID |
| `runId` | `string` | 智能体运行的 ID |
| `result` | `any` (optional) | 智能体运行的结果数据 |
| `usage` | `TokenUsage[]` (optional) | 本次运行按（提供商，模型）分别统计的 token 用量，在上报时提供 |

| `code` | `string` (optional) | 错误码 |

### StepStartedEvent

## 文本消息事件

这些事件表示会话中文本消息的生命周期。

### TextMessageStartEvent

表示一条文本消息的开始。

```typescript
type TextMessageStartEvent = BaseEvent & {
  type: EventType.TEXT_MESSAGE_START
  messageId: string
  role: "assistant"
}
```

| 属性 | 类型 | 描述 |
| ----------- | ------------- | --------------------------------- |
| `messageId` | `string` | 消息的唯一标识符 |
| `role` | `"assistant"` | 角色始终为 "assistant" |

### TextMessageContentEvent

表示流式文本消息中的一个内容 chunk。

```typescript
type TextMessageContentEvent = BaseEvent & {
  type: EventType.TEXT_MESSAGE_CONTENT
  messageId: string
  delta: string // Non-empty string
}
```

| 属性 | 类型 | 描述 |
| ----------- | -------- | ----------------------------------------- |
| `messageId` | `string` | 与 TextMessageStartEvent 中的 ID 一致 |
| `delta` | `string` | 文本内容 chunk（非空） |

### TextMessageEndEvent

表示一条文本消息的结束。

```typescript
type TextMessageEndEvent = BaseEvent & {
  type: EventType.TEXT_MESSAGE_END
  messageId: string
}
```

| 属性 | 类型 | 描述 |
| ----------- | -------- | ----------------------------------------- |
| `messageId` | `string` | 与 TextMessageStartEvent 中的 ID 一致 |

### TextMessageChunkEvent

便捷事件，在 JS/TS 客户端中会自动展开为 `TextMessageStart` → `TextMessageContent` → `TextMessageEnd`。

```typescript
type TextMessageChunkEvent = BaseEvent & {
  type: EventType.TEXT_MESSAGE_CHUNK
  messageId?: string // required on the first chunk for a message
  role?: "developer" | "system" | "assistant" | "user"
  delta?: string
}
```

行为

- 省略 start/end：客户端会把 chunk 序列转换为标准的 start/content/end 三元组，因此你无需手动发出它们。
- 首个 chunk 的要求：一条消息的首个 chunk 必须包含 `messageId`。省略 `role` 时，默认为 `assistant`。
- 流式：后续具有相同 `messageId` 的 chunk 会发出 `TextMessageContent` 事件。当另一条消息开始或流结束时，会自动发出 `TextMessageEnd`。

## 状态管理事件

这些事件用于管理智能体状态。

### StateSnapshotEvent

提供智能体状态的完整快照。

```typescript
type StateSnapshotEvent = BaseEvent & {
  type: EventType.STATE_SNAPSHOT
  snapshot: any // StateSchema
}
```

| 属性 | 类型 | 描述 |
| ---------- | ----- | ----------------------- |
| `snapshot` | `any` | 完整的状态快照 |

### StateDeltaEvent

使用 JSON Patch 提供智能体状态的增量更新。

```typescript
type StateDeltaEvent = BaseEvent & {
  type: EventType.STATE_DELTA
  delta: any[] // JSON Patch operations (RFC 6902)
}
```

| 属性 | 类型 | 描述 |
| -------- | ------- | ------------------------------ |
| `delta` | `any[]` | JSON Patch 操作数组 |

### MessagesSnapshotEvent

提供会话中所有消息的快照。

```typescript
type MessagesSnapshotEvent = BaseEvent & {
  type: EventType.MESSAGES_SNAPSHOT

}
```

| 属性 | 类型 | 描述 |
| ---------- | ----------- | ------------------------ |
| `messages` | `Message[]` | 消息对象数组 |

### ActivitySnapshotEvent

交付一条活动消息的完整快照。

```typescript
type ActivitySnapshotEvent = BaseEvent & {
  type: EventType.ACTIVITY_SNAPSHOT
  messageId: string
  activityType: string
  content: Record<string, any>
  replace?: boolean
}
```

| 属性 | 类型 | 描述 |
| -------------- | --------------------- | ----------------------------------------------------------------------------------------------------- |
| `messageId` | `string` | 目标 `ActivityMessage` 的标识符 |
| `activityType` | `string` | 活动判别值，例如 `"PLAN"` 或 `"SEARCH"` |
| `content` | `Record<string, any>` | 描述完整活动状态的结构化负载 |
| `replace` | `boolean` (optional) | 默认为 `true`；为 `false` 时，如果已存在相同 ID 的消息，则忽略该快照 |

### ActivityDeltaEvent

使用 JSON Patch 提供活动快照的增量更新。

```typescript
type ActivityDeltaEvent = BaseEvent & {
  type: EventType.ACTIVITY_DELTA
  messageId: string
  activityType: string
  patch: any[] // RFC 6902 JSON Patch operations
}
```

| 属性 | 类型 | 描述 |
| -------------- | -------- | ---------------------------------------------------------------- |
| `messageId` | `string` | 目标 `ActivityMessage` 的标识符 |
| `activityType` | `string` | 与最近一次快照一致的活动判别值 |
| `patch` | `any[]` | 应用到结构化活动负载上的 JSON Patch 操作 |

## 子智能体事件

这些事件表明智能体把工作委托给了子智能体，前端因此可以把输出归因（attribution）到产生它的那个子智能体。归因本身以可选的 `subagentRunId` 字段随大多数其他事件类型传递。

`subagentRunId` 标识的是**一次调用**，而不是可复用的子智能体定义——同一个子智能体运行两次会得到两个不同的值。完整模型参见 [Subagents（子智能体）](/concepts/subagents)。

### SubagentStartedEvent

宣告一次新的子智能体调用，并给出用于展示的名称。

```typescript
type SubagentStartedEvent = BaseEvent & {
  type: EventType.SUBAGENT_STARTED
  subagentRunId: string
  name: string
  description?: string
  parentSubagentRunId?: string
  parentToolCallId?: string
  parentMessageId?: string
}
```

| 属性 | 类型 | 描述 |
| --------------------- | -------- | ---------------------------------------------- |
| `subagentRunId` | `string` | 本次调用的不透明标识符 |
| `name` | `string` | 声明的子智能体名称或类型，用于展示 |
| `description` | `string` | 可选描述 |
| `parentSubagentRunId` | `string` | 可选的外层子智能体，嵌套时存在 |
| `parentToolCallId` | `string` | 可选的、生成此子智能体的工具调用 |
| `parentMessageId` | `string` | 可选的、持有该工具调用的消息 |

### SubagentFinishedEvent

把一次子智能体调用标记为已完成。

```typescript
type SubagentFinishedEvent = BaseEvent & {
  type: EventType.SUBAGENT_FINISHED
  subagentRunId: string
  result?: any
  outcome?: { type: "success" } | { type: "suspended"; interruptIds?: string[] }
}
```

| 属性 | 类型 | 描述 |
| --------------- | -------- | -------------------------------------------------- |
| `subagentRunId` | `string` | 与 `SubagentStartedEvent` 中的 id 一致 |
| `result` | `any` | 可选负载，对应 `RunFinishedEvent.result` |
| `outcome` | `SubagentFinishedOutcome` | 可选的可辨识联合；省略表示成功（沿用旧语义）。`{ type: "suspended", interruptIds?: string[] }` 表示子智能体已建立检查点、正在等待外部输入；`interruptIds` 指出恢复它所需应答的那些运行级中断。 |

### SubagentErrorEvent

把一次子智能体调用标记为已失败。

```typescript
type SubagentErrorEvent = BaseEvent & {
  type: EventType.SUBAGENT_ERROR
  subagentRunId: string
  message: string
  code?: string
}
```

| 属性 | 类型 | 描述 |
| --------------- | -------- | ----------------------------------------- |
| `subagentRunId` | `string` | 与 `SubagentStartedEvent` 中的 id 一致 |
| `message` | `string` | 人类可读的错误消息 |
| `code` | `string` | 可选的错误码 |

### 其他事件上的归因

大多数事件类型都接受可选的 `subagentRunId`。不带该字段的事件归属于父智能体，因此从不设置该字段的事件流，其行为与子智能体出现之前完全一致。

`RunStartedEvent`、`RunFinishedEvent` 与 `RunErrorEvent` 是不可归因的——它们描述的是整个运行。`MessagesSnapshotEvent` 则按消息携带归因，因为一份快照会混合来自多个生产者的消息。

`StateSnapshotEvent` 与 `StateDeltaEvent` 是可归因的，但其上的归因表示来源（provenance）而非所有权——它记录的是哪个子智能体产生了这次更新。状态始终以运行为作用域，因此带归因的快照或增量与不带归因的一样，都会应用到该运行唯一的状态文档上。不存在按子智能体划分的状态。

订阅者可以通过 `onSubagentStartedEvent`、`onSubagentFinishedEvent` 与 `onSubagentErrorEvent` 直接响应这一生命周期。

## 特殊事件

### RawEvent


| 属性 | 类型 | 描述 |
| -------- | ------------------- | ------------------- |
| `event` | `any` | 原始事件数据 |
| `source` | `string` (optional) | 事件的来源 |

### CustomEvent

用于应用专属的自定义事件。

```typescript
type CustomEvent = BaseEvent & {
  type: EventType.CUSTOM
  name: string
  value: any
}
```

| -------- | -------- | ------------------------------- |
| `name` | `string` | 自定义事件的名称 |
| `value` | `any` | 与该事件关联的值 |

### ToolCallChunkEvent

便捷事件，在 JS/TS 客户端中会自动展开为 `ToolCallStart` → `ToolCallArgs` → `ToolCallEnd`。

```typescript
type ToolCallChunkEvent = BaseEvent & {
  type: EventType.TOOL_CALL_CHUNK
  toolCallId?: string // required on the first chunk for a tool call
  toolCallName?: string // required on the first chunk for a tool call
  parentMessageId?: string
  delta?: string
}
```

行为

- 省略 start/end：客户端会把 chunk 序列转换为标准的 start/args/end 三元组。
- 首个 chunk 的要求：首个 chunk 必须同时包含 `toolCallId` 与 `toolCallName`；如果给出 `parentMessageId`，它会传递给 `ToolCallStart`。
- 流式：后续具有相同 `toolCallId` 的 chunk 会发出 `ToolCallArgs`。当工具调用变化或流结束时，会自动发出 `ToolCallEnd`。
