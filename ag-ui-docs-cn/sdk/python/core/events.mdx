# 事件

智能体–用户交互协议（AG-UI）Python SDK 采用基于事件的流式架构。事件是智能体与前端
之间通信的基本单位。本节记录事件类型及其属性。

## EventType 枚举

`from ag_ui.core import EventType`

`EventType` 枚举定义了系统中所有可能的事件类型：

```python
class EventType(str, Enum):

    TEXT_MESSAGE_CONTENT = "TEXT_MESSAGE_CONTENT"
    TEXT_MESSAGE_END = "TEXT_MESSAGE_END"

    TOOL_CALL_ARGS = "TOOL_CALL_ARGS"

    ACTIVITY_DELTA = "ACTIVITY_DELTA"
    RAW = "RAW"
    CUSTOM = "CUSTOM"
    RUN_STARTED = "RUN_STARTED"
    RUN_FINISHED = "RUN_FINISHED"
    RUN_ERROR = "RUN_ERROR"
    STEP_STARTED = "STEP_STARTED"
```

## BaseEvent

`from ag_ui.core import BaseEvent`

所有事件都继承自 `BaseEvent` 类，它提供所有事件类型共享的公共属性。

```python
class BaseEvent(ConfiguredBaseModel):
    type: EventType
    timestamp: Optional[int] = None
    raw_event: Optional[Any] = None
    metadata: Optional[Dict[str, Any]] = None
```

| 属性        | 类型            | 说明                                           |
| ----------- | --------------- | ----------------------------------------------------- |
| `type`      | `EventType`     | 事件类型（联合类型的判别字段） |
| `timestamp` | `Optional[int]` | 事件创建时的时间戳                  |
| `raw_event` | `Optional[Any]` | 该事件若经过转换，则保存原始事件数据     |
| `metadata`  | `Optional[Dict[str, Any]]` | 附加到事件上的额外信息               |

`metadata` 按键开放：key 下允许任意 JSON 值，包括 `None`。对象可以缺省，但一旦出现
就绝不会是 `None`——显式的 `null` 读回时视为缺省，因此普通的 `model_dump_json()`
可以完整往返。`EventEncoder` 使用 `exclude_none=True`，所以缺省的对象在线上直接省略，
而不会输出为 `null`。`ag-ui` key 保留为 AG-UI 自用。

## 生命周期事件

这些事件表示一次智能体运行的生命周期。

### RunStartedEvent

`from ag_ui.core import RunStartedEvent`

表示一次智能体运行的开始。

```python
class RunStartedEvent(BaseEvent):
    type: Literal[EventType.RUN_STARTED]
    thread_id: str
    run_id: str
    parent_run_id: Optional[str] = None
    input: Optional[RunAgentInput] = None
```

| 属性            | 类型                      | 说明                                                                                                    |
| --------------- | ------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `thread_id`     | `str`                     | 会话线程的 ID                                                                                  |
| `run_id`        | `str`                     | 智能体运行的 ID                                                                                            |
| `parent_run_id` | `Optional[str]`           | （可选）用于分支/时间旅行的血统指针。若存在，指向同一线程内较早的一次运行 |
| `input`         | `Optional[RunAgentInput]` | （可选）本次运行发送给智能体的确切输入负载。可以省略历史中已有的消息  |

### TokenUsage

`from ag_ui.core import TokenUsage`

一个可复用、只含数字的 token 用量摘要，由终止性运行事件携带。它在设计上**只**包含
提供商/模型标签与 token 计数——不含提示词、补全、消息或标识符。这些计数遵循协议的
[记账规则](/spec/1.0/events/lifecycle#token-usage)：输入与输出计数是总量，缓存与
推理计数是总量的一部分，绝不是额外累加。

```python
class TokenUsage(ConfiguredBaseModel):
    provider: Optional[str] = None
    model: Optional[str] = None
    input_tokens: Optional[int] = None
    output_tokens: Optional[int] = None
    total_tokens: Optional[int] = None
    reasoning_tokens: Optional[int] = None
    cached_input_tokens: Optional[int] = None
    cache_write_input_tokens: Optional[int] = None
```

| 属性                       | 类型            | 说明                                                     |
| -------------------------- | --------------- | --------------------------------------------------------------- |
| `provider`                 | `Optional[str]` | 上报该用量的提供商（例如 `openai`）                |
| `model`                    | `Optional[str]` | 产生该用量的模型                                   |
| `input_tokens`             | `Optional[int]` | 全部输入 token，含缓存读取与写入               |
| `output_tokens`            | `Optional[int]` | 全部输出 token，含推理                           |
| `total_tokens`             | `Optional[int]` | `input_tokens` 加 `output_tokens`                             |
| `reasoning_tokens`         | `Optional[int]` | 用于推理的输出 token；是 `output_tokens` 的一部分       |
| `cached_input_tokens`      | `Optional[int]` | 从提示词缓存读取的输入 token；是 `input_tokens` 的一部分   |
| `cache_write_input_tokens` | `Optional[int]` | 写入提示词缓存的输入 token；是 `input_tokens` 的一部分  |

### ReasoningMessageChunkEvent

`from ag_ui.core import ReasoningMessageChunkEvent`

便捷事件，用于发送完整的推理消息而无需手动发出
`ReasoningMessageStart`/`ReasoningMessageEnd`。

```python
class ReasoningMessageChunkEvent(BaseEvent):
    type: Literal[EventType.REASONING_MESSAGE_CHUNK]
    message_id: Optional[str] = None  # required on first chunk for a message
    delta: Optional[str] = None
```

行为

- 便捷性：一些消费方（例如 JS/TS 客户端）会自动把 chunk 事件展开为标准的
  start/content/end 序列。
- 首个 chunk 的要求：某条消息的第一个 chunk 必须包含
  `message_id`。
- 流式：后续携带相同 `message_id` 的 chunk 对应各个内容片段；完成时会触发一个隐式
  end（在执行展开的客户端中）。

## 子智能体事件

这些事件报告智能体已把工作委托给子智能体，前端借此可以把输出归因到产生它的子智能体。
归因本身以可选的 `subagent_run_id` 字段随大多数其他事件类型一起传输。

`subagent_run_id` 标识的是**一次调用**，而不是可复用的子智能体定义——同一个子智能体
运行两次会得到两个不同的值。完整模型见[子智能体](/concepts/subagents)。

字段名在 Python 中是 snake_case，在线上序列化为 camelCase，因此
`subagent_run_id` 在 JSON 中显示为 `subagentRunId`。

### SubagentStartedEvent

`from ag_ui.core import SubagentStartedEvent`

宣告一次新的子智能体调用，并给出用于展示的名称。

```python
class SubagentStartedEvent(BaseEvent):
    type: Literal[EventType.SUBAGENT_STARTED]
    subagent_run_id: str
    name: str
    description: Optional[str] = None
    parent_subagent_run_id: Optional[str] = None
    parent_tool_call_id: Optional[str] = None
    parent_message_id: Optional[str] = None
```

| 属性                     | 类型  | 说明                                   |
| ------------------------ | ----- | --------------------------------------------- |
| `subagent_run_id`        | `str` | 本次调用的不透明标识符         |
| `name`                   | `str` | 声明的子智能体名称或类型，用于展示   |
| `description`            | `str` | 可选的描述                          |
| `parent_subagent_run_id` | `str` | 嵌套时的可选外层子智能体     |
| `parent_tool_call_id`    | `str` | 派生出该子智能体的可选工具调用 |
| `parent_message_id`      | `str` | 持有该工具调用的可选消息       |

### SubagentFinishedEvent

```python
    outcome: Optional[SubagentFinishedOutcome] = None
```

| 属性              | 类型  | 说明                                            |
| ----------------- | ----- | ------------------------------------------------------ |
| `subagent_run_id` | `str` | 与 `SubagentStartedEvent` 中的 ID 一致               |
| `result`          | `Any` | 可选负载，对应 `RunFinishedEvent.result`   |
| `outcome`         | `Optional[SubagentFinishedOutcome]` | `SubagentFinishedSuccessOutcome` 与 `SubagentFinishedSuspendedOutcome`（带可选的 `interrupt_ids`）构成的可辨识联合；`None` 表示成功（沿用旧的读法）。Suspended 表示子智能体已设置检查点、等待外部输入；`interrupt_ids` 指出哪些运行级中断的答案可以恢复它 |

### SubagentErrorEvent

`from ag_ui.core import SubagentErrorEvent`

将一次子智能体调用标记为失败。

```python
class SubagentErrorEvent(BaseEvent):
    type: Literal[EventType.SUBAGENT_ERROR]
    subagent_run_id: str
    message: str
    code: Optional[str] = None
```

| 属性              | 类型  | 说明                                |
| ----------------- | ----- | ------------------------------------------ |
| `subagent_run_id` | `str` | 与 `SubagentStartedEvent` 中的 ID 一致  |
| `message`         | `str` | 人类可读的错误消息               |
| `code`            | `str` | 可选的错误码                        |

### 其他事件上的归因

大多数事件类型接受可选的 `subagent_run_id`。不带该字段的事件属于父智能体，因此从不
设置该字段的事件流，其行为与子智能体出现之前完全一致。

`RunStartedEvent`、`RunFinishedEvent` 和 `RunErrorEvent` 不可归因——它们描述的是
运行整体。`MessagesSnapshotEvent` 则按消息携带归因。

`StateSnapshotEvent` 和 `StateDeltaEvent` 可以归因，但其归因表示的是
来源（provenance）而非所有权——它记录是哪个子智能体产生了这次更新。状态始终以运行
为作用域，因此带归因的快照或增量与不带归因的一样，都应用到该运行的唯一一份状态文档上。

### TextMessageChunkEvent

便捷事件，用于发送完整的文本消息而无需手动发出
`TextMessageStart`/`TextMessageEnd`。

```python
from ag_ui.core import TextMessageChunkEvent

class TextMessageChunkEvent(BaseEvent):
    type: Literal[EventType.TEXT_MESSAGE_CHUNK]
    message_id: Optional[str] = None  # required on first chunk for a message
    role: Optional[TextMessageRole] = None  # defaults to "assistant" in JS client
    delta: Optional[str] = None
```

行为

- 便捷性：一些消费方（例如 JS/TS 客户端）会自动把 chunk 事件展开为标准的
  start/content/end 序列，让生产方在使用 chunk 时可以省略显式的 start/end 事件。
- 首个 chunk 的要求：某条消息的第一个 chunk 必须包含
  `message_id`。
- 流式：后续携带相同 `message_id` 的 chunk 对应各个内容片段；完成时会触发一个隐式
  end（在执行展开的客户端中）。

### ToolCallChunkEvent

便捷事件，用于工具调用而无需手动发出
`ToolCallStart`/`ToolCallEnd`。

```python
from ag_ui.core import ToolCallChunkEvent

class ToolCallChunkEvent(BaseEvent):
    type: Literal[EventType.TOOL_CALL_CHUNK]
    tool_call_id: Optional[str] = None      # required on first chunk
    tool_call_name: Optional[str] = None    # required on first chunk
    parent_message_id: Optional[str] = None
    delta: Optional[str] = None
```

行为

- 便捷性：消费方可以把 chunk 序列展开为标准的 start/args/end 三元组
  （JS/TS 客户端会自动这样做）。
- 首个 chunk 的要求：第一个 chunk 要同时给出 `tool_call_id` 和
  `tool_call_name`。
- 流式：后续携带相同 `tool_call_id` 的 chunk 对应各段参数；完成时会触发一个隐式
  end（在执行展开的客户端中）。
