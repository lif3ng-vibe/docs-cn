## 结果与中断

运行与子智能体如何报告结束，以及被中断的运行在等待什么。行为规范：[中断与恢复](/spec/draft/basic/patterns/interrupt-resume)。

### `RunFinishedSuccessOutcome`

运行已完成。等价于缺省的 outcome。像所有其他对象一样封闭，这也使它无法携带 suspended 兄弟取值的中断——一个带着未决中断的 success 是自相矛盾，而非扩展。已完成的运行仍可能给应用留下了待应答的前端工具调用；pendingToolCallIds 列出它们。

**字段：**

- `type` — `"success"`, **required**. 判别字段。
- `pendingToolCallIds` — array of `string`, optional. 本次运行发起且未获应答的工具调用——运行中没有对应的 TOOL_CALL_RESULT——按发起顺序列出，供应用在下一次输入的消息中应答。缺省或为空表示生产者未指名任何调用，消费者从事件流推导该列表；否则它就是那份列表，且与事件流一致。它放在 success outcome 上而非事件本身，因为因前端工具调用而停止的运行就是一次已完成的运行：应用是否延续该线程是它自己的决定，所以生产者只报告自己知道的，不多不少。每个条目：一个工具调用 id，与 TOOL_CALL_START 所携带的一致。

封闭对象：schema 拒绝未在此列出的成员。

### `Interrupt`

运行在继续之前需要从外部获得的东西，例如一项批准或一个缺失的值。

**字段：**

- `subagentRunId` — [`SubagentRunId`](#subagentrunid), optional. 本条目所属的子智能体调用。缺省表示由父智能体直接产生。
- `id` — `string`, **required**. 标识该中断。resume 条目以这个 id 应答它。
- `reason` — `string`, **required**. 运行为何停止。用开放字符串而非枚举：协议不打算对智能体需要输入的每一种原因都做分类。
- `message` — `string`, optional. 给应答者看的人类可读提示词。
- `toolCallId` — `string`, optional. 本中断所涉及的工具调用（当它是工具批准时）。
- `responseSchema` — `object`，按 key 开放, optional. 描述本中断所期待答案的 JSON Schema，消费者可以据此为它构建表单。以不透明方式承载：协议不约束也不校验它。限定为对象，是因为 TypeScript 与 Python 都这样声明；.NET 把它保存为任意 JSON，而提出这份 schema 的工单也把它列在任意 JSON 字段之中。跟随约束它的那两方，可以让 schema 不接受参考客户端会拒绝的文档，代价是连 JSON Schema 同样允许的布尔 schema——表示"任何答案"的裸 true——也一并拒绝。记录为已知分歧，未作定论。
- `expiresAt` — `string`, optional. 中断在何时之后不再可应答。有意不作约束、不用日期时间格式，因为生产者对表示方式本就各执一词，在这里收紧会拒绝今天本可正常工作的事件流。成文的约定是 ISO 8601，消费者在比较该值时会把它当日期解析，因此不是日期的值会让中断看起来永远不过期。
- `metadata` — [`Metadata`](#metadata), optional. 附加到此中断上的额外信息。

封闭对象：schema 拒绝未在此列出的成员。

组合自 [`Attributable`](#attributable)；组合而来的字段已在上方列出。

### `RunFinishedInterruptOutcome`

运行已暂停，在等待来自外部的某个东西。恢复意味着启动一次新运行，用它的 resume 条目应答这些中断。

**字段：**

- `type` — `"interrupt"`, **required**. 判别字段。
- `interrupts` — array of [`Interrupt`](#interrupt) (min 1), **required**. 运行在等待的内容。至少一条：没有任何东西可应答的 interrupt outcome 会让消费者无事可做。

封闭对象：schema 拒绝未在此列出的成员。

### `RunFinishedCancelledOutcome`

运行在完成之前被运行它的那一方停止，且并未失败。既非 success 也非 interrupt：没有产生任何 result，也没有在等待任何东西，因此该线程上的下一次运行是一次普通的新运行，而非恢复。与其兄弟取值一样封闭：被取消的运行没有可携带的中断。在 1.0 之前就写入 schema，是因为消费者无法识别的 outcome 会被剥离并当作 success 读取——若事后才加入取消取值，它会以"已完成的运行"的面目到达每一个 1.0 消费者。

**字段：**

- `type` — `"cancelled"`, **required**. 判别字段。

封闭对象：schema 拒绝未在此列出的成员。

### `RunFinishedOutcome`

运行为何结束。

**成员：**

- [`RunFinishedSuccessOutcome`](#runfinishedsuccessoutcome)
- [`RunFinishedInterruptOutcome`](#runfinishedinterruptoutcome)
- [`RunFinishedCancelledOutcome`](#runfinishedcancelledoutcome)

以 `type` 判别。

### `SubagentFinishedSuccessOutcome`

子智能体完成了它的工作。等价于缺省的 outcome。

**字段：**

- `type` — `"success"`, **required**. 判别字段。

封闭对象：schema 拒绝未在此列出的成员。

### `SubagentFinishedSuspendedOutcome`

子智能体已暂停，等待外部输入。对这个事件流而言是终点，对子智能体本身则不是：一旦中断得到应答，后续运行可以延续同一次调用。

**字段：**

- `type` — `"suspended"`, **required**. 判别字段。
- `interruptIds` — array of `string`, optional. 该子智能体自己引发的运行级中断。可以为空或缺省：因后代中断而被挂起的子智能体并不拥有自己的中断。每个条目：一个 Interrupt.id。

封闭对象：schema 拒绝未在此列出的成员。

### `SubagentFinishedOutcome`

子智能体在运行中的区段为何结束。比 RunFinishedOutcome 低一层，与之对应。

**成员：**

- [`SubagentFinishedSuccessOutcome`](#subagentfinishedsuccessoutcome)
- [`SubagentFinishedSuspendedOutcome`](#subagentfinishedsuspendedoutcome)

以 `type` 判别。

## 通用类型

以上各节共用的内容。

### `Metadata`

附加到事件、消息、工具调用、工具、中断或 resume 条目上的额外信息。按 key 开放：key 下允许任意 JSON 值，包括 null，因为这里的 null 是有意义的数据。对象本身可以缺省，但一旦存在就绝不是 null。key ag-ui 为协议自用而保留；这种保留只是约定，因为校验某个 key 的值形态就与"按 key 开放"相矛盾。

**类型：** `object`，按 key 开放

### `SubagentRunId`

一次子智能体调用的不透明句柄（handle），不是子智能体定义的可复用名称：对同一子智能体的两次调用携带两个不同的值。命名与低一层的 runId 对应，正如子智能体的名称与 agentId 对应。

**类型：** `string`

### `State`

智能体状态。任意 JSON 值：协议承载状态而不解读它，因此对象、数组、字符串与数字都有效。

**类型：** any JSON value

### `JsonPointer`

RFC 6901 定义的 JSON Pointer。要么是空字符串（表示整个文档），要么是以斜杠开头的一系列引用 token，其中波浪号转义为 ~0，斜杠转义为 ~1。不以斜杠开头的值，或波浪号后跟 0、1 以外字符的值，都不是 JSON Pointer。

**类型：** `string`，须匹配 `^(/([^/~]|~[01])*)*$`

### `AddOperation`

在 path 处插入 value。RFC 6902 第 4.1 节。

**字段：**

- `op` — `"add"`, **required**. add 操作的判别字段。
- `path` — [`JsonPointer`](#jsonpointer), **required**. 值插入到哪里。
- `value` — any JSON value, **required**. 要插入的值。任意 JSON 值，包括 null——null 是可以合法添加的东西。

开放对象：超出这些成员之外的内容协议上合法，且永远不会被剥离。

### `RemoveOperation`

移除 path 处的值。RFC 6902 第 4.2 节。

**字段：**

- `op` — `"remove"`, **required**. remove 操作的判别字段。
- `path` — [`JsonPointer`](#jsonpointer), **required**. 要移除什么。

开放对象：超出这些成员之外的内容协议上合法，且永远不会被剥离。

### `ReplaceOperation`

替换 path 处的值。RFC 6902 第 4.3 节。

**字段：**

- `op` — `"replace"`, **required**. replace 操作的判别字段。
- `path` — [`JsonPointer`](#jsonpointer), **required**. 要替换什么。
- `value` — any JSON value, **required**. 替换后的值。任意 JSON 值，包括 null。

开放对象：超出这些成员之外的内容协议上合法，且永远不会被剥离。

### `MoveOperation`

把 from 处的值移动到 path。RFC 6902 第 4.4 节。

**字段：**

- `op` — `"move"`, **required**. move 操作的判别字段。
- `from` — [`JsonPointer`](#jsonpointer), **required**. 值从哪里移出。
- `path` — [`JsonPointer`](#jsonpointer), **required**. 值移动到哪里。

开放对象：超出这些成员之外的内容协议上合法，且永远不会被剥离。

### `CopyOperation`

把 from 处的值复制到 path。RFC 6902 第 4.5 节。

**字段：**

- `op` — `"copy"`, **required**. copy 操作的判别字段。
- `from` — [`JsonPointer`](#jsonpointer), **required**. 值从哪里复制。
- `path` — [`JsonPointer`](#jsonpointer), **required**. 值复制到哪里。

开放对象：超出这些成员之外的内容协议上合法，且永远不会被剥离。

### `TestOperation`

断言 path 处的值等于 value。RFC 6902 第 4.6 节。

**字段：**

- `op` — `"test"`, **required**. test 操作的判别字段。
- `path` — [`JsonPointer`](#jsonpointer), **required**. 比较的对象。
- `value` — any JSON value, **required**. 目标必须等于的值。任意 JSON 值，包括 null。

开放对象：超出这些成员之外的内容协议上合法，且永远不会被剥离。

### `JsonPatchOperation`

单个 RFC 6902 操作。必须恰好匹配其中一种操作形态，以 op 判别。与协议自己的对象不同，这些操作是开放的：RFC 6902 第 4 节要求忽略而非拒绝操作未定义的成员，因此带着多余 value 的 remove 也是合法补丁。RFC 有两条规则是值与值之间的关系而非形态，任何静态 schema 都无法表达，这里也不检查：from 是 path 真前缀的 move（第 4.4 节），以及指针在目标文档中无法解析的任何操作。两者都由应用方拒绝。

**成员：**

- [`AddOperation`](#addoperation)
- [`RemoveOperation`](#removeoperation)
- [`ReplaceOperation`](#replaceoperation)
- [`MoveOperation`](#moveoperation)
- [`CopyOperation`](#copyoperation)
- [`TestOperation`](#testoperation)

以 `op` 判别。

### `JsonPatch`

RFC 6902 定义的 JSON Patch 文档，被 STATE_DELTA.delta 与 ACTIVITY_DELTA.patch 引用：应用于目标文档的有序操作序列。空数组是合法的空操作补丁。这些操作是否真的能应用于目标文档，是运行时问题，RFC 6902 把它留给应用方；这里结构上的有效与否对此不作判断。

**类型：** [`JsonPatchOperation`](#jsonpatchoperation) 数组

### `FunctionCall`

一次工具调用的名称与参数。

**字段：**

- `name` — `string`, **required**. 正在调用哪个工具。
- `arguments` — `string`, **required**. 以 JSON 字符串形式保存的参数，而非解析后的 JSON。保持原样，因为模型可能发出不合法的 JSON 参数；若在协议边界丢失它们，必须处理该问题的消费者反而看不见故障。

封闭对象：schema 拒绝未在此列出的成员。

### `ToolCall`

助手消息发起的一次调用。自身不携带子智能体归因，而是继承其所在消息的归因，因为多个调用可以共享同一个父消息。

**字段：**

- `id` — `string`, **required**. 标识该调用。应答它的工具消息以它作为 toolCallId。
- `type` — `"function"`, **required**. 协议建模的唯一调用类型。
- `function` — [`FunctionCall`](#functioncall), **required**. 调用的是什么，以及用什么参数。
- `encryptedValue` — `string`, optional. 属于该调用的提供方不透明产物。
- `encryptedValueType` — `string`, optional. 生产者自己为 encryptedValue 这类产物取的名称。与值一起存储并原样返回，消费者绝不解读。
- `metadata` — [`Metadata`](#metadata), optional. 附加到本次调用上的额外信息。放在这里而非并入所在消息，因为多个调用可以共享同一个父消息，合并它们会让结果取决于顺序。

封闭对象：schema 拒绝未在此列出的成员。

### `TokenUsage`

一个提供方与一个模型的 token 计数，采用协议自己的记账口径：每个计数要么是总量，要么是某个总量的具名组成部分，因此不同提供方的条目可以直接相加而不会重复计数。inputTokens 与 outputTokens 是总量；reasoningTokens、cachedInputTokens 与 cacheWriteInputTokens 是它们的组成部分，绝不是在总量之外另加的部分；totalTokens 是两个总量之和。每个字段都只是标签或数字——不包含任何内容性或可识别信息，没有提示词、补全、消息，也没有线程、运行与用户标识符。

**字段：**

- `provider` — `string`, optional. 由哪个提供方服务该请求。
- `model` — `string`, optional. 由哪个模型服务该请求。
- `inputTokens` — `integer` (min 0, max 9007199254740991), optional. 本次调用被计费的全部提示词 token：从提供方缓存读取的 token、写入缓存的 token，以及音频或其他非文本输入都计入其中。cachedInputTokens 与 cacheWriteInputTokens 是对这个数字的拆分，绝不会另加其上——如果提供方在较小的输入计数旁边报告缓存计数，生产者会在条目发出前把它们加进来。与 timestamp 一样限定范围，理由也相同：超出 JSON 安全整数范围的计数无法无损往返，消费者会悄然读到一个与生产者写入值不同的数字。
- `outputTokens` — `integer` (min 0, max 9007199254740991), optional. 生成的全部 token，在提供方加以区分时包含推理 token。reasoningTokens 是对这个数字的拆分，绝不会另加其上——如果提供方在较小的补全计数旁边报告推理 token，生产者会把它们加进来。
- `totalTokens` — `integer` (min 0, max 9007199254740991), optional. inputTokens 加 outputTokens，按上述口径。生产者 MAY 自行计算而不照抄提供方的总量，并且只在提供方总量按同一口径统计时才照抄，这样消费者可以把本字段读作另外两个字段之和。
- `reasoningTokens` — `integer` (min 0, max 9007199254740991), optional. 花在推理上的输出 token（在提供方加以区分时）。是 outputTokens 的组成部分，不是其之外的另加部分。
- `cachedInputTokens` — `integer` (min 0, max 9007199254740991), optional. 从提供方缓存读取的输入 token。是 inputTokens 的组成部分，不是另加部分，且与 cacheWriteInputTokens 不相交。
- `cacheWriteInputTokens` — `integer` (min 0, max 9007199254740991), optional. 本次调用写入提供方缓存的输入 token（在提供方加以区分时）。是 inputTokens 的组成部分，不是另加部分，且与 cachedInputTokens 不相交。单列一个字段，是因为提供方对缓存写入的计价与缓存读取不同，计算成本的消费者离不开它。

封闭对象：schema 拒绝未在此列出的成员。

### `TransportCapabilities`

**字段：**

- `resumable` — `boolean`, optional. 若智能体支持通过序列号恢复被中断的流则设为 true。

封闭对象：schema 拒绝未在此列出的成员。

- `items` — array of [`Tool`](#tool), optional. 该智能体自己提供的工具（完整 JSON Schema 定义）。它们与通过 RunAgentInput.tools 传入的客户端工具不同。

封闭对象：schema 拒绝未在此列出的成员。

- `codeExecution` — `boolean`, optional. 若智能体能在运行期间执行代码（如 Python、JavaScript）则设为 true。
- `sandboxed` — `boolean`, optional. 若代码执行发生在沙箱或隔离环境中则设为 true。仅当 codeExecution 为 true 时才有意义。
- `maxIterations` — `integer` (min 0, max 9007199254740991), optional. 智能体每次运行将执行的"工具调用/推理"迭代次数上限。帮助客户端展示进度或设置超时预期。
- `maxExecutionTime` — `integer` (min 0, max 9007199254740991), optional. 智能体运行的最大墙钟时间（毫秒），超过即超时。

封闭对象：schema 拒绝未在此列出的成员。

### `HumanInTheLoopCapabilities`

人在回路（human-in-the-loop）交互支持。当智能体能在继续之前暂停执行、请求人类输入、批准或反馈时启用。

**字段：**

- `supported` — `boolean`, optional. 若智能体支持任何形式的人在回路交互则设为 true。
- `approvals` — `boolean`, optional. 若智能体能在执行敏感操作（如发送邮件、删除数据）之前暂停并请求明确批准则设为 true。
- `interventions` — `boolean`, optional. 若智能体允许人类在执行中途介入并修改其计划则设为 true。
- `feedback` — `boolean`, optional. 若智能体能吸纳用户反馈（点赞/点踩、纠正）以在当前会话内改进自身行为则设为 true。
- `interrupts` — `boolean`, optional. 若智能体参与 AG-UI 中断协议则设为 true：它以携带 interrupt outcome 的 RUN_FINISHED 结束运行，并在 RunAgentInput.resume 中接受应答。
- `approveWithEdits` — `boolean`, optional. 若工具调用中断接受 resume 负载中的 editedArgs 则设为 true。仅当 interrupts 为 true 时才有意义。

封闭对象：schema 拒绝未在此列出的成员。

### `AgentCapabilities`

智能体当前能力的类型化、分类快照。所有字段皆可选——智能体只声明自己支持的。字段缺省表示该能力未声明（未知），而不表示不支持。custom 字段是一个逃生舱，用于容纳装不进标准分类的集成专属能力。

**字段：**

- `identity` — [`IdentityCapabilities`](#identitycapabilities), optional. 智能体身份与元数据。
- `transport` — [`TransportCapabilities`](#transportcapabilities), optional. 支持的传输机制（SSE、WebSocket、二进制等）。
- `tools` — [`ToolsCapabilities`](#toolscapabilities), optional. 智能体提供的工具与工具调用配置。
- `output` — [`OutputCapabilities`](#outputcapabilities), optional. 输出格式支持（结构化输出、MIME 类型）。
- `state` — [`StateCapabilities`](#statecapabilities), optional. 状态与记忆管理（快照、增量、持久化）。
- `multiAgent` — [`MultiAgentCapabilities`](#multiagentcapabilities), optional. 多智能体协作（委派、移交、子智能体）。
- `reasoning` — [`ReasoningCapabilities`](#reasoningcapabilities), optional. 推理与思考支持（思维链、加密思考）。
- `multimodal` — [`MultimodalCapabilities`](#multimodalcapabilities), optional. 多模态输入/输出支持（图像、音频、视频、文件）。
- `execution` — [`ExecutionCapabilities`](#executioncapabilities), optional. 执行控制与限制（代码执行、超时、迭代上限）。
- `humanInTheLoop` — [`HumanInTheLoopCapabilities`](#humanintheloopcapabilities), optional. 人在回路支持（批准、介入、反馈）。
- `custom` — `object`，按 key 开放, optional. 标准分类未覆盖的集成专属能力。按 key 开放：key 下允许任意 JSON 值，因为上述分类无法预知某个集成会声明什么。

封闭对象：schema 拒绝未在此列出的成员。

## 混入

共享的字段集合，展平进每个组合它们的定义。它们在 schema 中以具名定义存在，因此其文档只需写一次；线上对象绝不会只是一个混入。

### `Attributable`

组合进一切可能属于子智能体工作的东西：描述内容或进度的事件、各消息类型，以及每个中断。作用于运行整体的事件不含它——RUN_STARTED、RUN_FINISHED 与 RUN_ERROR 描述的是运行本身，MESSAGES_SNAPSHOT 覆盖整个对话——因此它们都不能归属于某个子智能体。工具调用也不含它，而是继承其所在消息的归因。

**字段：**

- `subagentRunId` — [`SubagentRunId`](#subagentrunid), optional. 本条目所属的子智能体调用。缺省表示由父智能体直接产生。


### `BaseEvent`

无论类型如何，每个事件都携带的字段。组合进每个事件定义而非重复书写，因此在这里改一处，所有事件同时生效。

**字段：**

- `type` — [`EventType`](#eventtype), **required**. 标识这是哪种事件。每个事件定义都把它收窄为单一取值。
- `timestamp` — `integer` (min -9007199254740991, max 9007199254740991), optional. 事件创建的时间。取值限定在 JSON 数字能无损往返的范围内，因此消费者读到的值就是生产者写入的值。有意不用浮点数。此处不约束单位，因为从未有过规范性的说法；实践中所有设置该值的 SDK 都使用 Unix 纪元以来的毫秒数，选择其他单位的生产者即使通过校验，也会被消费者误读。协议中没有任何计算会用到这个值。
- `rawEvent` — any JSON value except `null`, optional. 本事件由哪个提供方原生事件翻译而来，原样携带以便调试，也供需要协议未建模细节的消费者使用。可以是任意 JSON 值。
- `metadata` — [`Metadata`](#metadata), optional. 附加到此事件上的额外信息。


### `BaseMessage`

developer、system、assistant 与 user 消息共享的字段。有意不包含 content，因为用户消息的 content 可以是数组而其他是字符串，而这里的组合取交集而非覆盖：若基类把 content 约束为字符串，数组形式的 content 就会失效。tool、activity 与 reasoning 消息不组合它，因为它们不携带 name。

**字段：**

- `subagentRunId` — [`SubagentRunId`](#subagentrunid), optional. 本条目所属的子智能体调用。缺省表示由父智能体直接产生。
- `id` — `string`, **required**. 在对话内标识该消息。
- `role` — `string`, **required**. 消息来自谁。每个消息定义都把它收窄为单一取值。
- `name` — `string`, optional. 作者的可选显示名。
- `encryptedValue` — `string`, optional. 属于该消息的提供方不透明产物，由消费者存储并在后续轮次返回。
- `encryptedValueType` — `string`, optional. 生产者自己为 encryptedValue 这类产物取的名称。与值一起存储并原样返回，消费者绝不解读。
- `metadata` — [`Metadata`](#metadata), optional. 附加到此消息上的额外信息。
