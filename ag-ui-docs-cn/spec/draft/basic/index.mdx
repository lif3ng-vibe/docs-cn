基础协议是每个实现无论使用哪些特性都必须讲的语言：

- **事件模型**——即本页：所有事件共享的信封、其通用字段，以及把事件串联起来的标识符。
- **[运行输入](/spec/draft/basic/run-input)**——朝反方向传输的那条唯一消息。
- **[元数据](/spec/draft/basic/metadata)**——附着在一切之上的开放通道，以及它的合并方式。
- **[能力](/spec/draft/basic/capabilities)**——智能体在运行前对自己作出的声明，以及声明带来的义务。
- **[事件模式](/spec/draft/basic/patterns)**——事件组合成流的种种方式。
- **[传输层](/spec/draft/basic/transports)**——流如何被分帧与投递。
- **[处理模型](/spec/draft/basic/processing)**——消费者如何处理自己无法识别的内容。
- **[版本管理与兼容性](/spec/draft/basic/versioning)**——与更旧或更新的对端通信。

所有实现 MUST 支持事件模型与事件模式。运行生命周期之外的[事件族](/spec/draft/events)都是特性：生产者只发出自己有内容要表达的那些。

## 事件

每个事件都是一个 JSON 对象，共享同一个信封，在 schema 中定义为 `BaseEvent`：

- `type`——REQUIRED。判别字段，取 `EventType` 的 31 个值之一。本规范的每条规则都通过这个字段附着到事件上。
- `timestamp`——OPTIONAL。事件创建的时间。仅供参考：消费者 MUST NOT 用它来为事件排序——到达顺序就是协议的顺序。按惯例，单位是 Unix 纪元以来的毫秒数。
- `rawEvent`——OPTIONAL。本事件由哪个提供方原生事件翻译而来，原样携带。消费者 MUST NOT 从它推导协议行为。
- `metadata`——OPTIONAL。见[通用字段](#通用字段)。

可能属于子智能体工作的事件还额外携带 OPTIONAL 的 `subagentRunId`（schema 中的 `Attributable`），由[子智能体规则](/spec/draft/events/subagents)管辖。作用于运行整体的事件——`RUN_STARTED`、`RUN_FINISHED`、`RUN_ERROR`、`MESSAGES_SNAPSHOT`——描述的是运行或对话整体，不携带归因。

## 通用字段

### `metadata`

附着在一切之上的开放通道：按 key 开放，key 下可为任意 JSON 值，在构建一个条目的事件间累积——逐 key 合并、最后写入者胜出、不递归——并按事件族确定合并目标，`ag-ui` key 为保留 key。它有独立页面：[元数据](/spec/draft/basic/metadata)。

### 缺省即缺省

没有取值的可选字段 MUST 省略，而不是以 `null` 发送。

这适用于每一个可选字段，包括承载任意 JSON 的字段，如 `rawEvent`、`RUN_FINISHED.result` 与 `forwardedProps`。整体取值为 `null` 的可选字段 MUST 省略。必填的 JSON 负载可以为 `null`，例如 `CUSTOM.value` 或 `STATE_SNAPSHOT.snapshot`。

<Note>
  这不是风格偏好。必须同时接受两种写法的消费者，不得不在所有地方把它们视为相等，而这样的宽容一旦发布便是永久的。协议只承载每个实现都能表示的那一种写法。
</Note>

*按 key 开放对象之下的* `null` 值——一个元数据值、`state` 里的某样东西——是数据，MUST 保留。只有顶替整个缺失字段的 `null` 才被禁止。

协议已经发布的、对可选位置上 `null` 的宽容，由兼容性垫片（shim）处理，而不是由本条规则处理。见[版本管理与兼容性](/spec/draft/basic/versioning)。

## 标识符

- `threadId` 标识一段对话。它由应用生成，跨运行保持稳定。
- `runId` 标识一次运行。在同一线程上，它 MUST NOT 被另一次运行复用。
- `messageId` 标识一条消息。它会跨越运行边界——后续运行中的快照 MAY 借 id 重述一条消息——因此它 MUST 在其线程内唯一。
- `toolCallId` 标识一次工具调用，并把它的结果以及任何涉及它的中断绑回该调用。
- `subagentRunId` 是一次子智能体*调用*的不透明句柄，不是子智能体定义的可复用名称：对同一子智能体的两次调用携带两个不同的值。

所有标识符都是不透明字符串：消费者 MUST NOT 从中解析出结构。

## schema

协议的完整结构由 [`/spec/draft/schema.json`](/spec/draft/schema.json) 处的 JSON Schema 定义。它是事实来源：TypeScript、Python 与 .NET 模型都由它生成，本文档提及某个字段时，指的都是 schema 定义过的东西，绝不复述其形态。

schema 有意不说本文档所说的内容：顺序、生命周期、归因（attribution）、错误处理与兼容性都属于行为，schema 无法表达它们。若两者在结构上不一致，以 schema 为准，本文档视为有误。
