这是默认绑定。应用把运行输入 POST 到智能体的端点；响应是一条承载本次运行的[服务器推送事件（SSE）](https://html.spec.whatwg.org/multipage/server-sent-events.html)流。

## 请求

- 客户端向智能体端点发送 `POST`。请求体是作为单个 JSON 对象的 [`RunAgentInput`](/spec/draft/basic/run-input)，UTF-8 编码，带 `Content-Type: application/json`。
- 客户端发送 `Accept: text/event-stream`（若也能消费 [protobuf 媒体类型](/spec/draft/basic/transports/http-protobuf)则一并加上）。

## 响应

- 开启的运行以 `200` 应答，带 `Content-Type: text/event-stream`。
- 每个 SSE 事件的 `data` 负载恰好是一个协议事件的 JSON 对象——绝不多于一个，也绝不是片段。多行 `data:` 字段按 SSE 规范拼接。
- 生产者 MUST 以 LF（`\n`）行结束符为流分帧。SSE 语法也容许 CR 与 CRLF，但本绑定钉死这种所有已知消费者都能解析的形式；消费者 MAY 额外接受完整语法。
- 消费者 MUST 忽略 `data` 之外的 SSE 字段（`event:`、`id:`、`retry:`），并 MUST 容忍 SSE 注释行（`: keep-alive`），生产者 MAY 以任意节奏发送注释行。
- 生产者在最后一次运行的终止事件之后关闭响应体。一个 POST 携带一次请求；但当生产者在所请求的运行之前回放线程历史时，响应 MAY [携带多次运行](/spec/draft/events/lifecycle#several-runs-on-one-stream)——按[绑定契约](/spec/draft/basic/transports#the-binding-contract)，不为它们传输进一步的输入。

## 错误

- 运行开始之前被拒绝的输入——JSON 格式错误、校验失败、认证被拒——是一个不带事件流的 HTTP 错误状态。运行从未开始。
- 流开启之后的失败走流内传输，即 `RUN_ERROR`。HTTP 状态已经发出、无法更改；消费者 MUST NOT 仅凭 `200` 推断成功。
- 没有终止事件就断开的连接是一次[被截断的运行](/spec/draft/basic/transports#truncation)。

## 不可续传

该绑定没有流续传：SSE 的 `Last-Event-ID` 机制不被使用，断掉的流无法重新进入。重跑就是一次带着新 `runId` 的新运行，其输入携带消费者保留下来的一切。

## 示例

```
POST /agent HTTP/1.1
Content-Type: application/json
Accept: text/event-stream

{"threadId":"thr-1","runId":"run-1","messages":[…]}

HTTP/1.1 200 OK
Content-Type: text/event-stream

data: {"type":"RUN_STARTED","threadId":"thr-1","runId":"run-1"}

data: {"type":"TEXT_MESSAGE_START","messageId":"msg-1","role":"assistant"}

data: {"type":"TEXT_MESSAGE_CONTENT","messageId":"msg-1","delta":"Hello."}

data: {"type":"TEXT_MESSAGE_END","messageId":"msg-1"}

data: {"type":"RUN_FINISHED","threadId":"thr-1","runId":"run-1"}
```
