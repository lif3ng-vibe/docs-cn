# 调试 AG-UI 集成

调试基于智能体的应用可能颇具挑战，尤其是在使用 AG-UI 这类实时、事件驱动的协议时。本指南将向你介绍 AG-UI Dojo——一个用于学习、测试和调试 AG-UI 实现的强大工具。

## AG-UI Dojo

AG-UI Dojo 是把 AG-UI 带到新载体（surface）上的最佳方式，也是学习协议基础能力的极佳资源。它提供了一个结构化的环境，你可以在其中测试和验证 AG-UI 协议的每个组件。

### Dojo 是什么？

Dojo 由一系列"hello world"规模的小型演示组成，覆盖 AG-UI 提供的各个构建块。每个演示：

1. 展示一项具体 AG-UI 能力的实际运行
2. 并排呈现用户可见的交互与底层代码
3. 让你可以测试并验证自己的实现

### 把 Dojo 用作实现清单

在把 AG-UI 带到新的载体或平台时，你可以把 Dojo 当作一份完整的"待办清单"：

1. 逐个过一遍每个演示
2. 在你的环境中实现并测试每个 AG-UI 构建块
3. 当所有演示在你的实现中都正常工作时，你就可以确信，功能完整的 copilot 与智能体原生应用都能构建在你的新载体之上

这种有条不紊的方法能确保你覆盖了完整 AG-UI 实现所需的全部功能。

### 把 Dojo 用作学习资源

对于刚接触 AG-UI 的开发者，Dojo 是一份交互式学习资源：

- 每一项都演示了一项具体的 AG-UI 能力
- 你既能看到从用户视角看交互是什么样子
- 底层代码也会一并展示，帮助你理解其工作原理
- 复杂度循序渐进，帮助你从基础一路理解到高级特性

### 常见调试模式

在使用 Dojo 调试你的 AG-UI 实现时，请留意以下模式：

1. **事件序列问题**：验证事件是否以正确的顺序、正确的嵌套发出（例如 `TEXT_MESSAGE_START` 在 `TEXT_MESSAGE_CONTENT` 之前）

2. **数据格式问题**：确保你的事件负载符合每种事件类型的预期结构

3. **传输层调试**：检查你所选的传输机制（SSE、WebSockets 等）是否正确交付事件

4. **状态同步**：确认状态更新是否通过快照与增量正确应用

5. **工具执行**：验证工具调用与响应的格式正确且得到正确处理

## Dojo 入门

要开始使用 AG-UI Dojo：

1. 从 [github.com/ag-ui-protocol/ag-ui](https://github.com/ag-ui-protocol/ag-ui) 克隆仓库
2. 按照 README 中的设置说明操作
3. 按顺序逐一完成各个演示
4. 使用提供的测试用例验证你的实现

Dojo 的结构化方式使它成为学习 AG-UI 并确保实现满足全部要求的宝贵资源。
