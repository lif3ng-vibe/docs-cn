描述你想做的页面。Impeccable 帮你选定方向、把它构建出来，并评审结果。不需要特殊命令，也不需要先想好视觉概念。

> **想把视觉方向推得更远？** 图像生成能打开更大胆的构图。把这份雄心带进代码需要几轮迭代；首次构建会损失视觉稿的一些细节。[启用图像生成 →](/docs-cn/impeccable/docs/image-generation))

```text
/impeccable design a pricing page for our enterprise customers
```

1. **描述任务**：说清它服务谁、要做什么、什么必须保留。
2. **选定方向**：比较各个选项，驾驭设计走向。小的增量可以沿用你现有的风格。
3. **构建与评审**：试用界面并不断精修。Impeccable 会把决策记录下来供后续工作使用。

只需要一份计划？从 [shape](/docs-cn/impeccable/docs/shape)) 开始。

## 评审视觉稿，或直接写代码

新设计如何变成可运行的界面，你可以选。**comp** 是一张视觉构图：页面的精细视觉稿。

| 视觉稿先行（comp 主导） | 直接构建（代码主导） |
|---|---|
| **机会**<br>比编码模型本能会做的更大胆的构图、更有创意的视觉方向。 | **机会**<br>更连贯的首次实现，构建在编码模型天然的视觉范围之内。 |
| **你评审**<br>先生成视觉稿，再对照你选定的图像评审可运行界面。 | **你评审**<br>先看提议的概念，再看它在可运行界面中的实现。 |
| **代价**<br>图像到代码的转译有细节损耗。预期多轮提示与评审才能逼近视觉稿。 | **代价**<br>结果开箱观感通常更好，但执行力度一般不及 comp 主导的方向。 |
| **你需要**<br>图像生成、额外的时间与用量，以及迭代的意愿。 | **你需要**<br>不需要图像生成。评审与精修仍然重要。 |

**comp 主导不是一把就中的工作流。** 图像模型可能提出一个编码模型第一遍无法忠实复现的构图。字体、间距、图像和比例都会在转译中漂移。Impeccable 为构建立起视觉目标、帮助检查还原度，但请预期多轮提示直到满意。这项工作请用能力足够的编码模型。

想要一个你愿意为之投入的更高视觉上限，选**视觉稿先行**。想要模型天然范围内更强的首次实现，选**直接构建**。没有图像生成时，Impeccable 走代码主导路径。

在设计选择器里用工作流开关做一次仅限当前会话的选择：

![工作流开关选中 Comp first：视觉稿先行，即 comp 主导。](/docs-cn/impeccable/images/docs/new-work/03-comp-first-crop.png))

**视觉稿先行（comp 主导）。** 比较多个构图，确认一个，然后对照它构建和评审。

![工作流开关选中 Code first：直接构建，即代码主导。](/docs-cn/impeccable/images/docs/new-work/04-code-first-crop.png))

**直接构建（代码主导）。** 用代码展开已商定的设计，并在可运行界面中评审。

### 默认值与保存工作流偏好

图像生成可用且没有保存过偏好时，Impeccable 默认**视觉稿先行**。没有图像生成时，它直接用代码构建，且不显示这个开关。

选择器里的开关只作用于当前会话。要改项目默认值，用自然语言提出：

```text
/impeccable use code-led as this project's default for new design work
/impeccable use comp-led as this project's default for new design work
```

该设置是 `.impeccable/config.json` 里的 `buildPath`：`comp` 或 `code`。`.impeccable/config.local.json` 里的值会为该开发者覆盖共享设置。文件格式见[配置与忽略](/docs-cn/impeccable/docs/config))。

在没有保存偏好的项目里，切换开关时可能会被一次性询问是否保留新选择。init 也可以在设置过程中确立这一偏好。

这些路径适用于新设计工作和重设计。专注的 polish 会保留当前设计。两条路径都可以把生成图像用作成品素材；代码主导会跳过视觉稿确认环节。

## 设定可改动多少

告诉 Impeccable 它能改什么。新区块应当融入周围的页面；新页面应当融入产品。重设计时，点名要保留的东西。

> 在我们当前系统内重设计这个页面。保留产品名称和注册流程。

### 从零开始、扩展系统，或文档不全时

- **加一个区块或组件：**它继承周围的设计。
- **在既有产品里新建页面：**视觉系统保持一致；布局可以因任务而变。
- **从零开始或重设计：**视觉方向是开放的。产品事实、功能和约束依然适用。

Impeccable 会在读取 `DESIGN.md` 的同时读取真实的界面、令牌、组件和素材。文档缺失不会抹掉一套既有设计。它可以先[把那套系统记录下来](/docs-cn/impeccable/docs/design-system))，再动手扩展。

边界不清晰时，Impeccable 应当发问。"换掉现在这身外观"和"在现有系统内重设计"是两种不同的授权。

## 选定你想推进的方向

比较选择器里的选项，然后选定一个，或告诉 Impeccable 要改什么。下面是同一份发布目录的三种不同形态：

![真实的 Impeccable 选择器把 Relay 呈现为蓝色图文电视索引、印刷版节目单和图示主导的发布日程三种方向。每张卡片展示预览、设计选择、风险和一个 Build this 按钮。](/docs-cn/impeccable/images/docs/new-work/01-directions.png))

**为同一个产品比较不同设计。** 打开预览细看，或翻卡片看理由。图中虚构 Relay 目录的这几个示例方向展示的就是真实的选择器。[查看完整尺寸截图](/docs-cn/impeccable/images/docs/new-work/01-directions.png))。

- **选定一个：**在想要的方向上点 **Build this**。
- **再来一组：**重新生成（re-roll），或用 **Safer hand** 和 **Bolder hand** 调整范围。
- **驾驭下一轮：**用文本框说要改什么、留什么。
- **保持熟悉：**品类常规选项提供一种保守做法。

整组拒绝也可以。连续两组都是新的之后，Impeccable 会问缺的是哪种质量，让下一次尝试依据更清晰。浏览器决策页跑不起来时，选择会转入对话进行。

### 已有视觉想法？写进你的提示词

你的参照和约束指引着设计：

```text
/impeccable design a landing page for our vinyl shop with a 1970s hi-fi catalog look. Use Futura and lead with the records.
```

Impeccable 会展开你的简报留白的那些选择。选定的美学只是一个完整设计的起点，导航、控件和交互都还要补齐。

## 构建之后

试用主要任务，检查一遍窄屏，告诉 Impeccable 什么要保留、什么要调整。选定的方向引导评审；完成的界面仍然要对真实用户可用。

### 哪些内容会带入下一个会话

- **视觉系统：**当这项工作确立或替换了一套设计，`DESIGN.md` 会在实现与评审之后记录结果。普通的增量则沿用现有系统。
- **页面的决策：**`.impeccable/surfaces/` 下的一份页面简报记录页面的目的、选定的方向、约束和未决问题。后续工作可以读到设计为何长成这样。
- **视觉参照：**生成的视觉稿留在 `.impeccable/mocks/` 下，连同生成细节以及（如适用）已记录的确认。

设计规划属于开发记录。它不会写进页面的 HTML 注释、隐藏内容或任何发给访客的输出。

### 为什么选项不止于显而易见

有创意的提示词仍可能换来眼熟的答案。在 Impeccable 公布的 2026 年 7 月实验里，不同创意框架下的 35 个答案中有 30 个返回了同一个概念。实验及其局限见[研究页](/docs-cn/impeccable/research))。

Impeccable 在选择过程中引入变化。它从你的产品和受众出发展开方向，用带种子的选择避免总是挑中模型的第一偏好；当视觉识别开放时，还会参考一个精选目录里的替代方案。

这些参照最终要变成你产品自己的设计：它的内容、任务、控件和约束。目录图像展示的是灵感和一种完成度，不是拿来就抄的现成页面。

## 流程的更多细节

### 提议的方向如何被评估

方向在抵达你面前之前，必须先适配产品：

- **真实：**它展示的声明与关系必须为真。示意性数据必须标明是示意。
- **目的：**它的结构必须帮助人理解产品或完成任务。
- **后果：**它的独特手法必须改善体验，而不只是加一层装饰主题。
- **可行：**它必须能在目标设备上、以可用的素材、工具和性能预算跑起来。
- **契合：**它的取舍必须尊重你的简报。

在既有系统内新建页面时，备选方案在该系统内探索结构。新品牌识别或替换识别时，它们可以探索不同的视觉语言。

### 书面方向与种子

页面简报里存着一份简短的方向契约：核心想法、视觉语言、访客路径、首屏构图、选定的形态与种子，以及工作完成前必须检查的事项。

收尾评审用这些承诺来衡量结果。视觉稿主导的工作还会把实现与确认过的图像做对比。

想重放一次选择（包括其中的 re-roll 轮次）就保留种子。重放选择并不保证生成完全相同的图像或代码。

### 委托决策与无人值守运行

你在评审选择时，在适用的工作流里，Impeccable 会请你选定方向并确认视觉稿。你也可以把选择委托出去。

无人值守运行时，它会按指派的方向推进，并说明自己的假设。如果决策页在没有得到回答的情况下关闭，它会先在对话里试一次，再把本次运行当作无人值守。

你可以因为任何原因要求换一组新选项。agent 自己的 re-roll 需要指出产品事实或任务上的具体问题；仅是它个人的偏好不算。

### 从 craft 命令过来？

`/impeccable craft` 是普通新工作请求的已废弃别名。直接向 `/impeccable` 描述工作即可。
