## 什么时候用

`/impeccable delight` 面向那些能用却毫无感觉的界面。当核心体验已经扎实，你想添加那些让人记住它的人性化小触点时，用它：一个用心设计的空状态，一句有态度的加载文案，一个恰到好处的成功动画，一条能让人会心一笑的微文案。

它是一项收尾技能。新建项目时，永远别第一个跑它。

## 工作原理

这项技能在大多数设计师会跳过的地方寻找愉悦机会：

1. **空状态**：不是"暂无条目"，而是符合品牌个性的表达。
2. **加载与等待时刻**：最好的产品能把等待变成内容。
3. **成功反馈**：值得庆祝的事情发生时，给一刻庆祝。
4. **微文案**：按钮标签、tooltip、错误信息、占位文本。有品位的极短文案。
5. **彩蛋与次级状态**：让用户自己发现、并奖励他们用心的东西。

这项技能从 `PRODUCT.md` 读取品牌调性。严肃的分析工具得到严肃的愉悦（干练、精确、略带机锋）。活泼的消费级应用得到更外露的个性。当幽默不适合受众时，它不会硬上幽默。

规则是：删掉愉悦之后，每个时刻仍必须运转完好。没有任何东西依赖那个微笑。

## 试一试

```
/impeccable delight the first-run experience
```

预期新增：

- 空仪表盘把"暂无数据"换成"你的仪表盘很安静。我们来改变这一点。"，外加一个单操作 CTA。
- 首次同步得到一段三段式推进的加载文案："正在找到你的账户… / 正在拉取最近 30 天… / 正在让它好看一点…"
- 第一次成功操作触发一次性的 toast，带一个微小的庆祝时刻。之后只有一个安静的勾。
- 那个容易犯迷糊的字段上的帮助 tooltip，读起来像真人写的。

## 常见陷阱

- **硬上幽默**。不是每个品牌都活泼。如果 `PRODUCT.md` 里的品牌语调是"临床般冷静而精确"，delight 会添加聪明的克制，而不是段子。
- **过度装饰**。一个愉悦时刻令人记住，二十个就成了噪音。这项技能刻意保守。
- **在 polish 之前跑 delight**。polish 修掉错的东西，delight 补上缺的东西。按这个顺序来。
