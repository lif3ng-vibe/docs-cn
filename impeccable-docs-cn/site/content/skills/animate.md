## 什么时候用

`/impeccable animate` 面向那些显得死气沉沉的界面：状态变化瞬间生硬跳变，加载内容突兀弹出，用户始终不太确定自己的点击是否生效。用它来添加那些传达"正在发生什么"的小动效：入场、退场、反馈、状态之间的过渡。

不要为了"有活力"而用它添加弹跳或弹性效果。那是装饰，这项技能不会给你。

## 工作原理

这项技能找出能从动效中受益的静止瞬间，然后以严格的纪律加以应用：

1. **入场与退场**：元素以 200 到 300ms 的淡入淡出加轻微的 Y 轴位移或缩放出现和离开，绝不动布局属性。
2. **状态反馈**：hover、active、focus、加载、成功都通过动效传达，而不是瞬间切换。
3. **视图间过渡**：在合理之处使用共享元素过渡，其余场合用淡入淡出。
4. **进度与加载**：骨架屏、确定进度条，用动效表达"还在工作中"。
5. **减弱动效**：每个动画都有 `prefers-reduced-motion` 回退。

缓动始终用指数曲线（ease-out-quart、quint 或 expo），因为真实物体是平滑减速的。不用弹跳，不用弹性，除进度指示器外也不用线性。

这项技能只动画 `transform` 和 `opacity`。如果你发现它在动画 `width`、`height`、`top` 或 `left`，那就是做错了。高度过渡请用 `grid-template-rows`。

## 试一试

```
/impeccable animate the sign-up flow
```

典型新增：

- 邮箱输入框在 focus-visible 时出现聚焦光晕（opacity + 阴影，180ms）
- 提交按钮进入加载状态时在按钮内部显示 spinner，而不是在旁边另放一个
- 成功页以 opacity + translateY(8px) 入场，260ms，ease-out-quart
- 错误信息用 grid-template-rows（而不是 height）展开下滑，220ms
- 每个过渡都有 `@media (prefers-reduced-motion: reduce)` 回退

## 常见陷阱

- **要求"更多动画"**。animate 不是一个可调的旋钮。它只在动效能传达信息的地方添加，而不是到处添加。
- **移除减弱动效回退**。这项技能会自动添加它们。这是无障碍上的不可妥协项。
