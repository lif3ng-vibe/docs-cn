## 什么时候用

`/impeccable harden` 为界面直面现实的那一天而生。真实用户数据很混乱：60 个字符长的名字、德语的产品标题、以十亿计的价格、500 错误、离线模式、从右到左的文字。只在完美数据下才能工作的设计，算不上可上线。

上线前、进军新市场前，又或者哪天一条 bug 报告以"我们的用户有个特别长的名字，然后……"开头时，用它。首次运行流程、空状态激活和新手引导设计，请改用 `/impeccable onboard`。

## 工作原理

这项技能围绕四个维度的真实场景健壮性展开：

1. **文本与数据极端值**。长文本、短文本、特殊字符、emoji、RTL、以十亿计的数字、1000 项的列表。
2. **错误场景**。网络故障、API 4xx/5xx、校验错误、权限错误、限流、并发操作。
3. **国际化**。更长的译文（德语常比英语长 30%）、RTL 语言、日期与数字格式、货币符号、字符集。
4. **设备与语境**。触控目标、离线行为、慢速网络、低电量模式。

对每个维度，它先定位失败模式，再落实具体修复：溢出处理、有信息量的错误 UI、i18n 安全的布局、复数形式、合理的兜底。

## 试一试

从一页、一个维度开始：

```
/impeccable harden the user profile page for long names
```

预期输出：

- `.user-name` 加上 `text-overflow: ellipsis`，并用 tooltip 展示完整值
- `.bio` 从固定高度改为 `max-height`，配一个"展开更多"的折叠控件
- 为没有简介的用户添加空状态
- 为异步头像请求添加骨架加载
- 在名字长度为 1、20、60、200 字符的情况下测试

按页运行，别一口气全跑。第一次的改动最大；随着模式固化，后续运行会发现的问题越来越少。

## 常见陷阱

- **等 bug 报告上门**。Harden 是预防性的。如果你发现同一类 bug 修到第二遍，就对整个功能跑一遍 `/impeccable harden`。
- **把错误状态和空状态当事后补丁**。加固工作的大头正是错误与空状态 UI。给它们留出时间，而不是只留一个 `catch` 块。
- **以"我们暂时只做英文"为由跳过 i18n**。i18n 安全的布局本来就是更好的布局。弹性容器、正确的文本折行、宽松的行高——没有一样会伤到英文。
