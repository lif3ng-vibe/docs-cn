## 什么时候用

`/impeccable onboard` 处理那些决定新用户去留的时刻：第一屏、空状态、设置流程、产品导览，以及"我现在该干嘛"的空窗。激活率疲软、新用户还没见到价值就流失，或者产品里的空状态只会说"暂无条目"就没了下文——这些时候找它。

## 工作原理

这条命令从一个问题出发：aha 时刻是什么，新用户多快能到达。每一个设计决策都指向那一刻。

它在塑造第一印象的各个界面上发力：

1. **首次运行体验**：注册后的头几分钟。用户该看到导览、空白画布、填好的示例，还是什么都不给。挑与产品匹配的那种。
2. **空状态**：每块零数据界面都给足方位感。我在哪、这里为什么是空的、下一步做什么、填满之后长什么样。
3. **设置与安装**：必填配置压到最少，默认值足够聪明，每一步都解释为什么重要。
4. **渐进式披露**：高级功能先不挡道，时机到了才现身。
5. **激活事件**：用户第一次体验到核心价值的时刻，会被度量并庆祝——安静地。

这条命令抵制两种常见失败模式：一是过度教程化的新手引导，用户得先点完一整轮轮播才能碰任何东西；二是零引导，用户被扔进空应用里自求多福。

## 试一试

```
/impeccable onboard the editor
```

典型输出：

- 首次运行：用一份填好的示例文档替换空编辑器，用户可以直接改。取消按钮丢弃示例，编辑则把内容换成用户自己的东西。
- 文档列表空状态："还没有文档。创建第一篇，或从 Notion、Google Docs、Markdown 导入。"
- 设置：必填字段从 6 个减到 1 个（工作区名称）。其余全有聪明的默认值，之后可以在设置里改。
- 激活：用户第一次保存文档时，一条安静的 toast 说"已保存。你的成果已在云端。"只出现一次，不重复。

## 常见陷阱

- **把产品导览当默认答案**。大多数产品不需要导览，需要一个更好的第一屏。导览是拐杖。
- **没定义 aha 时刻就去设计新手引导**。如果你不能一句话说清用户在头 60 秒该感受到什么，先回去用 `/impeccable shape`。
- **在坏掉的流程上跑 onboard**。先修流程。核心动作都是坏的，新手引导救不了产品。
