tagline: "让设计跨屏幕、设备与情境可用，而不砍掉功能。"

## 什么时候用

`/impeccable adapt` 用于把一个为特定情境打造的设计迁移到另一个情境中正常工作：桌面到移动端、移动端到平板、网页到打印、独立应用到嵌入式、仪表盘到邮件。当源设计本身扎实、却在其他断点、触屏或不同容器里散架时，用它。

它不是用来从零构建响应式的。那要从 `/impeccable` 开始，以响应式优先的方式塑造布局。adapt 解决的是"我们从没考虑过移动端"的补课。

## 工作原理

这项技能从四个维度处理情境适配：

1. **断点与流式布局**：把多栏折叠为单栏，调整 clamp 区间，在设计真正撑不住的地方引入新断点。
2. **触控目标**：最小 44px 的点击区域，相邻目标之间留足间距，必要时让可点区域大于视觉边界。
3. **导航模式**：桌面侧边栏变成移动端底部导航或抽屉菜单，密集的工具栏收进菜单，hover 状态给出触屏等价物。
4. **内容优先级**：决定哪些内容必须可见，哪些可以折叠进展开项，哪些在该情境下可以彻底去掉。

不可妥协的规则：适配，而不是截肢。关键功能不能因为在移动端实现麻烦就消失。想办法装下它、重新设计交互，或者重新审视它在桌面上是否真的关键。

## 试一试

```
/impeccable adapt the settings page for mobile
```

预期变化：

- 三栏网格变为单栏，章节标题作为吸顶分隔线
- 侧边栏导航移到内容上方的横向滚动条里
- 开关增加 8px 垂直内边距，达到 44px 触控目标
- 内联帮助文本改为点按展开，而不是悬停显示
- "危险区域"区块在移动端完整展开而不是折叠，因为它包含不可逆的操作，我们要让用户清楚地看到它们

## 常见陷阱

- **砍掉功能**。如果移动端版本把桌面版能做的事藏了起来，那是退化，不是适配。要为功能争取空间。
- **把移动端当成"缩小版桌面"**。移动端是不同的情境：拇指操作、随时被打断、会话短。要适配情境，而不是适配视口宽度。
- **事后跳过 `/impeccable harden`**。响应式布局会暴露边界情况。adapt 之后跑一次加固，抓住那些只在 320px 宽度下出现的问题。
