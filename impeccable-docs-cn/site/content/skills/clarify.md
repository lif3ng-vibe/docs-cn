## 什么时候用

`/impeccable clarify` 处理那些让人停下来发懵的界面文字。让人困惑的标签、含糊的按钮文案、怪罪用户的错误提示、重复标签的 tooltip、说不出有用信息的空状态。当问题不在布局或颜色、而在文字上时，用它。

典型触发信号："用户看不懂这个字段""错误提示没有帮助""我写不好按钮文案""这个 tooltip 纯属浪费"。

## 工作原理

这项技能在大多数 UX 文案问题所在的界面上重写文字：

1. **标签与字段提示**：直接、具体、说清期望输入什么。
2. **按钮文案**：动词开头，描述结果而非动作。"保存更改"而不是"确定"。
3. **错误信息**：解释出了什么问题、是谁的问题、接下来怎么办。绝不怪罪用户。
4. **空状态**：帮用户定位处境，解释为什么这里是空的，给出下一步。
5. **tooltip 与辅助文本**：补充标签装不下的信息，绝不复述标签。
6. **确认对话框**：点明后果，而不是复述动作。

这项技能从 `PRODUCT.md` 读取受众与心理状态来调整语调。技术受众得到精确的语言，大众受众得到平实的口语。匆忙的用户得到短文本，焦虑的用户（支付、删除）得到安抚。

## 试一试

```
/impeccable clarify the billing form
```

改前改后的典型示例：

- 标签 "账单地址" → "卡面地址"
- 占位符 "请输入 VAT 税号" → "VAT 税号（选填，企业报税用）"
- 错误提示 "输入无效" → "卡号共 15 位，你只输入了 14 位。"
- 按钮 "提交" → "支付 $29 并订阅"
- 空状态 "还没有交易" → "完成首笔订单后，你的第一笔收款会显示在这里。"

## 常见陷阱

- **写得更巧而非更清楚**。clarify 不是用来升级语调的。如果文案已经清楚，就不要用这项技能。想要个性时，改用 `/impeccable delight`。
- **跳过受众问题**。clarify 需要知道读者是谁。如果 `PRODUCT.md` 没有写明受众的技术水平，重写出来的东西就会流于平庸。
- **对营销文案跑 clarify**。clarify 针对功能性的 UX 文本：标签、错误提示、操作说明。营销文案需要另一套打法，而且需要人类写手。
